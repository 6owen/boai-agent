真实供应商评估手动启动；评分、校准校验和数据合同检查离线运行。
题目答案只给评分器；执行成功、目标通过、待评审与证据不足分别保存。

一旦我所属的文件夹有所变化，请更新我。

| 成员 | 地位 | 功能 |
| --- | --- | --- |
| `schema.ts` | 合同 | 数据集/评分器版本、输入/答案、事件、证据和评审结构 |
| `cases.ts` | 场景入口 | 原九题保持输入不变，组合新增业务与留出题 |
| `datasets.ts` | 业务题 | 12项业务开发题、五人问候回归、16项独立业务留出题 |
| `matrix.ts` | 覆盖目录 | 32项要求到实际入口的映射，显式标注缺口，不冒充运行通过 |
| `holdout-manifest.json` | JSON例外文件 | 输入版本化留出定义，输出16题的冻结ID/簇/hash，变更必须建立新版本 |
| `harness.ts` | 执行 | 排除核心助手的普通员工协作场景；隔离AppService/Mastra、素材挂载、途中事件/错误子结果、完整产物hash/时间线/请求与报告 |
| `host.ts` | 凭据桥接 | 只读显式选择的模型连接，系统凭据只经内存IPC传递 |
| `budget.ts` | 预算 | 文件锁原子预留跨批次共享上限，计入连接/失败/judge，不允许扩大已有实验预算 |
| `checks.ts` | 规则评分 | 数值/产物/依赖/审核字节与事件命中，未知用量和运行错误单列 |
| `scorers.ts` | Mastra适配 | 对整组结果的createScorer，无额外模型调用 |
| `calibration.ts` | 校准门禁 | 至少20个不同正负人工标签、固定judge版本、90%一致率、零关键漏判；不生成标签 |
| `report.ts` | 报告 | 分类分母、运行健康、未知用量、四段耗时、证据、可筛选HTML与评审模板 |
| `rescore.ts` | 离线评分 | 保存样本重新评分和比较，损坏样本保留incomplete，不调用供应商 |

| `team-creation.ts` | 团队评估 | 保留 T1-v1，T1-v2 将常规 50 人需求改为 12 人，支持单例通过实际 AppService；保留原始方案/失败/用量与待人工评审状态 |

| `unified-memory.ts` | T2 真实质量 | UM-v1 固定合成私聊/群聊、纠正/限制/临时失效，实际请求/原始结果/用量和人工评审 |
