# BOAI Design

BOAI是面向日常工作和Agent协作的界面。设计语言以中性色、紧凑布局、细边缘、轻高光和就近操作为基础。内容决定层级，组件保持熟悉且稳定的形状。

本指南定义如何沿用BOAI的外观与交互，不代替组件API和Token源码。数值表是2026-10-22源码基线的说明快照；实际默认值从`@boai/tokens`生成，预览中的字号或主题调整不改变这些默认值。公开组件入口与示例见组件索引；包仍为工作区预览，未发布到 npm。

## 1. 视觉原则

**安静。** 大面积使用中性背景，主要操作和状态使用有含义的颜色。正文、控件与说明之间有明确层级，不靠重复卡片、边框和阴影制造强调。

**紧凑。** 标题与动作就近排列，列表采用可读的普通行。更多操作可以在悬停、聚焦或展开时出现，但保留位置并让键盘可达。说明解释用户需要作出的决定，不向产品界面填入实现过程。

**一致。** Card、按钮、输入和浮层使用同一套Soft光源；分割线共享细边缘和高光。页面组合已有组件，不为每个页面重画一套控件。

**稳定。** 异步数据到来前先显示结构与占位，数据在原位置替换。保存、取消、未知结果和失败均有清楚的行为，用户输入不会因等待或失败丢失。

## 2. 颜色与用途

使用语义变量表达用途。默认配色来自`packages/tokens/src/theme.ts`，Soft补充来自`packages/tokens/src/surfaces.ts`。组件继承主题，不在页面中分别写浅色/深色的十六进制常量。

| 角色 | CSS变量 | 默认浅色 | 默认深色 |
| --- | --- | --- | --- |
| 应用外层背景 | `--background` | `#f6f6f6` | `#171717` |
| 卡片/控件表面 | `--card` | `#ffffff` | `#212121` |
| 主要文字 | `--foreground` | `#0d0d0d` | `#ffffff` |
| 次级文字 | `--muted-foreground` | `#5d5d5d` | `#cdcdcd` |
| 主要操作 | `--primary` | `#2563eb` | `#93b8ff` |
| 普通结构边界 | `--border` | `#e5e5e5` | `#3d3d3d` |
| 危险/失败 | `--destructive` | `#a52826` | `#ffb4ac` |
| 成功 | `--success` | `#326a2b` | `#b0dba2` |
| 警示 | `--warning` | `#805817` | `#efce8b` |

还应按用途选用`--surface-list`、`--surface-content`、`--surface-detail`、`--surface-composer`、`--surface-user-message`和`--code-background`。不同表面可能共享默认值，语义仍然不同。

`--accent`是中性hover底色，`--selection`是选中底色；它们不能被误当成品牌主色。主题输入对象的`accent`字段用于派生`--primary`和`--ring`，与CSS变量`--accent`不是同一含义。

主操作前景由解析器根据底色选择。成功、警示、危险和信息背景也由主题计算，不手动拼另一套透明度。颜色必须配合文字、图标或结构表达状态；对比度要针对实际前景/背景配对检查，不能仅凭色值或自动配色函数宣称全部可访问。

## 3. 排版

所有字号来自`packages/tokens/src/typography.ts`的三组偏好与角色比例。默认基准均为13px，这个值属于Token定义，不是让组件各自写死13px。

| 组 | 默认字体 | 适用内容 | 正文角色 | 用户基准范围 |
| --- | --- | --- | --- | --- |
| UI | Geist，回退系统及中文字体 | 导航、按钮、标签、字段 | `--text-ui-body` | 10–22px |
| Content | 跟随UI，可选择独立字体 | 消息、阅读和长文本 | `--text-content-body` | 10–26px |
| Code | 系统等宽字体 | 代码、命令与技术标识 | `--text-code-body` | 10–24px |

UI注释使用`--text-ui-caption`，次级信息使用`--text-ui-secondary`，小节标题使用`--text-ui-heading`；内容标题与代码文字使用各自的角色。字体分别通过`--font-ui-family`、`--font-content-family`、`--font-code-family`选择。

行高使用无单位比例。例如UI正文`--leading-ui-body`默认1.5，内容正文`--leading-content-body`默认1.65。标题、说明与控件随对应字号组共同变化，不能为修补溢出局部缩小字体。

需要测试中文、英文长单词、代码和字号上限。单行标题可以省略，但完整名称应有可访问的获取方式；多行内容优先自然换行，代码和宽表格在自身区域滚动。

## 4. 组件表面

### 按钮与输入

主按钮表达当前明确动作；次级按钮采用中性Soft表面；低强调操作使用ghost；危险按钮只用于相应的危险操作。复用实际Button变体与尺寸，图标按钮必须有可访问名称。

输入框使用中性内侧边缘，表面由`--shadow-input`构成，不额外加底部外阴影。前后缀、步进器和文本输入组成一个外框，内层不重复画框。hover、只读、disabled和错误状态按原组件行为处理；“看起来变灰”不能代替真实禁用。

### Card、边缘和分割

Card用于一个主题的标题、内容、说明和操作。复用`CardHeader`、`CardContent`、`CardAction`、`CardFooter`，不要将每一段正文或每一行列表都装成卡片。

当前`soft-card`使用透明结构边框、Soft表面渐变和`--shadow-control`。细边缘已经存在于阴影中，额外叠加实色border会让同一边界变重。`--shadow-card`是另一项轻表面阴影Token，并不等于当前Card组件最后使用的阴影。

Card页脚、列表分组与表格分割使用`soft-divider-top`、`soft-divide-y`或`Separator`。横向/纵向分别来自`--shadow-divider`和`--shadow-divider-vertical`。普通布局边界可以使用`--border`；每处边界只承担一次分隔职责。

### 浮层和导航

Dialog、Popover、菜单和Tooltip复用已有原语、Soft表面和浮层层次。确认浮层由Popover、清楚的动作说明、取消与确认组成；关闭浮层不能当成确认。Dialog与AlertDialog保留紧凑、明确的操作区。

Tabs按其实际用途选用已有变体和指示层，保持键盘切换、内容关联和减少动态效果。组件样式和交互一起复用，不能只复制静态截图。

### 聊天与组合

Composer保留多行输入、左右操作区域、附件与模型/权限等插槽。展示层接收内容、状态及回调，服务层负责发送、授权和数据持久化。网站例子使用演示数据，发送/停止状态必须能真实切换，不能假装连接了模型。

消息、附件、工具折叠、问题表单和选区操作保持各自语义。需要组合时沿已有结构，不为展示效果改写产品中的业务动作。

## 5. 布局与尺度

现有公共尺寸包括`--control-height: 32px`、`--toolbar-height: 44px`、`--rail-width: 52px`和`--content-width: 768px`。这些是特定布局角色，不是要求所有控件或所有网页固定同一高度/宽度。

优先沿用相邻界面的间距和组件内部布局。标题和对应动作放在同一分区；保存与还原靠近编辑区域。先用留白与标题表达结构，再使用必要的边界，不叠套无用途的容器。

分栏调整和面板显隐分别沿Resizable与PanelResize。隐藏的内容不能继续接收焦点或覆盖其他操作；保留草稿与组件挂载不等于保留可交互状态。

当前源码的部分间距、动效与局部尺寸尚未成为公共Token。遇到重复语义时先收敛到共享定义，再用于页面；不要凭本指南编造一个已经存在的完整间距体系。

## 6. 圆角、层次与动效

| 角色 | Token | 当前默认值 |
| --- | --- | --- |
| 桌面框架 | `--radius-frame` | 12px |
| 按钮/输入 | `--radius-control` | 16px |
| 卡片/表面 | `--radius-card` | 20px |
| 聊天输入容器 | `--radius-composer` | 32px |
| 明确需要圆形/胶囊的元素 | `--radius-pill` | 999px |

支持时使用既有`corner-shape: squircle`，不支持时保留相应回退。胶囊是有意选择的角色，不是所有导航和搜索框的默认形状。公共组件应直接表达语义圆角，避免与Fumadocs等宿主的通用`rounded-lg/xl`刻度互相覆盖。

输入使用`--shadow-input`，按钮和Card使用`--shadow-control`，浮层使用`--shadow-popover`。高光、内侧细边缘和轻阴影来自同一套Soft变量，浅深主题同步。不要把浮层阴影用在普通列表和所有正文分区。

动效服务于按下反馈、Tabs选择、面板显隐和加载状态。沿原组件时长与曲线，避免增加装饰性循环动画。系统减少动态效果时关闭或简化运动，文字状态与操作继续可用；尚未集中管理的动效值要标明来源，不当作稳定公共Token宣称。

## 7. 反馈与交互约束

| 应保持的行为 | 应避免的结果 |
| --- | --- |
| 先显示结构/骨架，数据就位后替换 | 等完所有请求才出现整页DOM，或用加载动效遮挡已有内容 |
| 操作失败统一Sonner，恢复操作留在相关位置 | 额外插入错误Banner/大块红字，或只提示失败却无法继续 |
| 保留未保存内容，退出时提供原有取消/放弃路径 | 保存失败或未知结果时清掉输入，确认退出时偷偷触发保存 |
| pending时真实禁用有关操作，收到确定结果再更新状态 | 重复提交、仅opacity变灰、对未知回执自动重放 |
| 公共组件提供可见键盘焦点、正确标签/说明与焦点返回 | 将桌面全局outline清除规则复制进公共组件库 |
| 状态文字与颜色一起表达含义 | 仅靠红绿颜色或旋转图标表达最终结果 |
| 长内容局部滚动，主要操作可达 | 整个页面横向溢出，或浮层被外框裁掉 |

文档说明块与已保存的业务失败记录可以作为内容呈现；它们不应被混淆为本次操作的额外报错通知。组件目录保留兼容说明时应写明推荐替代项，当前错误反馈使用Sonner。

## 8. 文档站与响应式

Fumadocs负责文档布局、导航、搜索、目录和MDX渲染；正文中的组件、示例与模式使用BOAI共享实现。保留用户选择的Fumadocs默认圆角，同时使BOAI示例使用自己的语义Token。

窄屏采用适合阅读的流式布局，表格/代码可以局部横向滚动。示例需要同时支持浅色、深色、字号变化和长文本；浮层继承所属示例的主题和字体，不能串到相邻预览。网站窄屏可读不等于桌面产品新增了手机端支持。

标题锚点、代码高亮、链接和表格语义应保留。正文排版规则不进入交互示例内部；不为了统一外观将每个Markdown元素替换成Card。

## 9. 给开发者与Agent的使用方式

开发前先找到相应组件的现有实现、Token角色和产品使用场景。优先直接组合公共组件；组件尚在桌面内时，先提取可复用呈现与必要样式，再让两个消费者引用同一份源码。设计示例通过props和回调工作，不依赖应用store、IPC或真实用户数据。

可使用以下任务说明：

> 按BOAI Design实现此界面。复用现有共享组件与语义Token，保持紧凑布局、Soft细边缘和统一排版。先展示稳定结构，再填充数据；操作反馈使用Sonner，保留草稿和真实禁用。对照现有同类界面核对浅深色、字号变化、键盘与长文本，不为新页面另写颜色或字号体系。

修改视觉值应回到Token真源，修改组件样式应回到共享组件/皮肤。文档、示例、CSS与JSON输出同步更新；生成文件不是第二个编辑入口。新展示必须对应真实导出和实际交互，说明尚未支持的范围。
