# BOAI 业务协议使用说明

BOAI 提供版本为 `boai.application.v1` 的应用业务协议。CLI、bobo 的工具与新建员工/群聊界面通过同一入口调用原业务服务，原有页面也继续使用相同服务。业务协议不依赖某次 Agent 运行；owner 可以直接管理对象，bobo 的调用则由宿主绑定实际员工、会话和用户消息身份。

CLI、MCP 和模型工具是调用入口。当前 CLI 使用已有 `boai-1.0` RPC；API模型和本机Agent沿各自现有产品工具桥接入。没有新增一个对任意外部 MCP 客户端开放的通用服务器。

## 1. 发现、调用和核对

在 `pnpm dev` 启动当前开发应用后，使用构建出的 CLI；也可以沿原 CLI 方式连接独立 `serve`。指定其他数据目录时使用原 `--data-dir` 参数。

```sh
pnpm cli app catalog
pnpm cli app catalog employees
pnpm cli app describe employees.create
pnpm cli app call employees.create '{"name":"小研","role":"研究行业动态"}' --request-id create-xiaoyan-001
pnpm cli app receipt create-xiaoyan-001
```

`catalog` 默认只给出名称、说明、副作用、调用资格、可用状态和结果类型。`describe` 返回所选操作的输入 JSON Schema、公共回执 Schema。程序也可请求 `includeSchemas: true` 获取完整目录。当前输出 Schema 校验公共回执信封，`data` 由原领域服务返回，`resultType` 标注对应的 TypeScript DTO；没有声称每个领域结果都已生成独立 JSON Schema。

写操作必须使用调用者保存的 `requestId`，只读操作不要求。一次业务意图保持同一 ID；参数改变必须作为新的明确意图处理。同一 ID、同一参数返回原回执；同一 ID、不同参数返回 `REQUEST_CONFLICT`。重启后仍然有效。

返回结构示意：

```json
{
  "protocolVersion": "boai.application.v1",
  "operation": "employees.create",
  "requestId": "create-xiaoyan-001",
  "receiptId": "由宿主返回的64位标识",
  "status": "succeeded",
  "data": { "id": "实际员工ID", "name": "小研" }
}
```

| 状态 | 含义与处理 |
| --- | --- |
| `succeeded` | 该操作返回了实际领域结果；仍要阅读 `data` 的业务状态。例如安装已受理不等于安装结束 |
| `rejected` | 公共校验、权限、版本或可用条件未通过，尚未派发此操作 |
| `running` | 当前服务内原操作仍在进行，查询原回执 |
| `unknown` | 可能已发生副作用，结果无法确认；读取原回执和目标对象，不换 ID 自动重试 |
| `cleared` | 对应员工或来源会话已清理，回执正文被移除，只保留防重放身份 |

写操作进入原业务服务后发生异常时，公共层保守返回 `unknown`，因为异常可能出现在凭据、文件或数据库写入之后。它不会将任意异常误判为“肯定没写入”。进程重启不会自动重放中断操作。

owner 的请求身份归当前配置目录；bobo 的 `requestId` 归当前员工、会话和用户消息。跨轮核对使用返回的 `receiptId`：

```sh
pnpm cli app receipt-id 实际receiptId
```

同一用户消息内的模型工具重试可用原 `requestId`；后续轮次用原 `receiptId`。员工只能在同一员工、同一会话且当前获准时核对，不能通过传入 `actor` 自报为 owner。CLI 的 run 凭据不能调用 owner 管理通道，应使用其实际授予的员工工具。

## 2. 当前业务域

准确字段与可用状态始终以当前进程目录为准。

| 域 | 已注册的操作范围 |
| --- | --- |
| `employees` | 列表、读取、预设、独立创建、版本化更新、删除、工作区文件与人格读写、profile/configure、state/updateState、behaviorHistory/runBehavior/stopBehavior |
| `groups` | 已有员工组群、读取列表、版本化修改、删除 |
| `connections` | 模型连接列表、创建、修改、删除、模型目录与显式测试 |
| `runtimes` | 本机执行配置列表、状态、保存、显式测试、删除 |
| `sources` | API/MCP/local 数据源列表、详情、创建、修改、删除、显式测试与员工授权 |
| `automations` | 列表、详情、时间预览、创建、修改、暂停、恢复、删除、明确运行、执行历史、执行详情与停止 |
| `sessions` | 会话列表、详情、分页消息、打开员工主私聊、发送本人消息、清空隐藏 |
| `appearance` | 外观读取、主题目录、版本化修改、重置、移除背景 |
| `plugins` | 内置插件清单、版本化启停 |
| `skills` | 本地技能、编辑删除、市场、扫描安装、更新、绑定、分类与操作查询 |
| `knowledge` | 员工知识资料列表、保留、移除、明确共享 |
| `channels` | 员工渠道绑定列表、创建、修改、连接、断开、删除 |
| `runtimePlugins` | 已安装运行时插件列表、版本化启停、卸载 |
| `webSearch` | 独立网页检索服务与偏好配置、测试、删除 |
| `application` | 按主题读取内置产品操作指南 |
| `tasks` | 员工多步任务进度的持久登记、查询、版本化修改与删除；不负责调度或执行 |

这些是显式登记的业务操作，不是开放任意内部 IPC。原生文件选择、凭据回填、宿主私有方法不出现在模型目录。知识保留仍要求实际附件/成果及内容身份，文件上传沿原材料传输入口。

`sessions.send` 仅 owner 可用，不能让 bobo 冒充本人发消息。员工协作沿原委派与公开回复机制。渠道外发继续使用既有明确发布入口，不因新增协议自动发送。

`appearance`、`plugins` 需要当前配置目录连接真实桌面宿主。独立服务没有桌面附着时目录标为不可用，调用返回 `CAPABILITY_UNAVAILABLE`；不会另开一个设置写入器。本机执行配置保持原生工具、登录和权限，不新增 BOAI 目录沙箱。

## 3. bobo 怎么操作软件

bobo 的普通私聊增加三个共用工具：

- `boai_catalog`：先发现业务动作，再查准确参数。
- `boai_call`：调用原业务用例，写入使用稳定请求身份。
- `boai_receipt`：查询实际结果，不执行或重放操作。

产品操作指南通过 `application.guide` 按需读取，现有主题是 overview、employees、groups、sources、automations、connections、skills。它们是内置使用方法，普通可安装技能仍由原技能系统管理。原 `manage_skills`、`manage_data_sources` 等入口保留兼容。

例如“给小研建一个每天九点整理行业信息的定时任务”：bobo 查找实际员工，读取自动化指南与创建 Schema，核对时区、任务、启用意图，并用 `automations.preview` 查看时间，再保存计划、读取回执。未确定的信息简短询问。建计划与立即运行分别调用；如果用户只要保存，不能顺便执行一次。

单独创建员工、组群、保存设置在普通聊天办理，不为行政配置制造 Work。只有用户要求组织成员并立即完成业务目标时，才使用原协作工作流程。实际执行、审批、调度、预算和退出均继续归原服务。

## 4. 人格、简单创建与高级配置

bobo 的默认人格维护在 `src/shared/domain/agent-presets.ts`，初始复制到原 `SOUL.md`；工作规则复制到原 `AGENTS.md`。自然直接、有判断、适度幽默，依据实际记忆和回执说话。后续架构改造已增加独立人格配置、情绪/疲劳/成长/虚拟旅行状态与功能开关驱动的后台活动；实际范围见[架构文档§11](2026-10-19-BOAI独立Agent配置与行为运行架构.md#11-当前实现与验证2026-10-19本次架构改造唯一进度)。完整基础人格的实际模板位于`src/shared/domain/bobo-persona.ts`，新模块位于`agent-prompts.ts`。

已有 bobo 仅在内容与旧出厂默认值完全一致时迁移；自定义人格和规则保留。默认内容是初始化模板，普通员工不实时继承 bobo 的私人记忆、技能绑定或核心权限。

“新建员工”弹窗恢复原完整表单：头像、姓名、职责、模型与权限和工作方式直接展示，用户明确选择模型连接。弹窗没有高级折叠或人格输入。创建后通过原员工配置管理人格、技能、资料、目录、记忆及渠道；工作区、记忆、渠道沿人格与行为页的分区标题、说明Tooltip及卡片布局。业务协议的简单创建仍支持合理默认模型，与弹窗的显式选择互不替代。

发起群聊时只选择已有员工，群名由已选成员姓名自动生成；创建后可在原群资料中改名。高级协作方式、群背景、共享资料等使用原群配置。群成员保留自己的身份、人格和模型，创建群不派发任务。

详细设计与实际测试、失败和未验证范围见[改造方向文档第9节](2026-10-19-BOAI数字员工配置与人格体系改造方向.md#9-当前实施进度2026-10-19唯一进度)。

人格配置独立使用`revision`；源文件继续使用hash及员工`configVersion`。内置活动身份由宿主生成，不授予应用管理；bobo正常聊天的高权限工具保持。`features` 控制情绪/成长/旅行默认触发，`proactive` 配置是否主动联系、low/normal/high频率与本机小时quietStart/quietEnd。`behaviors`仅为只读旧存档，新配置传空数组。`employees.runBehavior`为高级检查入口，类型限personality-heartbeat或builtin-emotion/reflection/travel/greeting，仍受开关/频率/免打扰/新内容条件限制，不必执行，未执行返回null。源消息/活动去重身份独立，内部活动不伪造用户消息。

`employees.files`读取并刷新员工根目录中的受控记忆视图。`employees.readFile`除提示词源文件外，也可读取`IDENTITY.md`、`USER.md`、`MEMORY.md`及实际存在的`memory/YYYY-MM-DD.md`；日期文件呈现该日笔记和反思日记，补写日记使用经历日期。它们是原记忆的只读生成视图，编辑记忆仍使用记忆入口；`employees.writeFile`不会开放生成文件写入或任意路径读取。外部修改文件沿原冲突保护，不静默覆盖。

## 5. 技能与多步任务进度

员工已绑定技能通过`list_skills/read_skill`按需加载；API普通聊天与本机运行共用该能力。技能正文不授予应用管理权限，普通员工不会因绑定一项技能而获得Bobo身份。Bobo当前九项适配技能、实际验证和未覆盖范围见独立Agent架构§11.21。

`tasks`登记可跨轮次恢复的工作进度，与`automations`定时触发及内部执行Work分别持久化。通过现有owner CLI或Bobo的`boai_catalog/boai_call/boai_receipt`操作。先读取实际schema，再调用：

```sh
node dist/cli/index.mjs app catalog tasks --json
node dist/cli/index.mjs app describe tasks.create --json
node dist/cli/index.mjs app call tasks.list '{"agentId":"bobo"}' --json
```

`tasks.create`输入`agentId/title/steps`，每一步为`{title,done}`；返回实际ID及revision。`tasks.update/delete`必须携带读取到的`expectedRevision`，写入使用稳定requestId，未知结果查询原回执。状态是pending/in_progress/blocked/done；默认列表仅返回未完成项，`includeDone:true`包含已完成记录。来源受限或群聊记录不向其他普通私聊开放；owner管理读取沿原身份合同。

保存任务进度不会开始执行、派给其他员工或生成定时计划；重启后记录保留，但不会自动重放未确认操作。删除进度记录也不删除成果、取消运行或移除定时计划。实际操作必须使用各自对应协议。


## 持久依赖计划（plans）

`tasks`登记进度，`planning`表示讨论规划模式，`plans`保存任务/步骤依赖图和审核返工流程。它们都不会自动执行外部工作。

```sh
node dist/cli/index.mjs app catalog plans --json
node dist/cli/index.mjs app describe plans.set --json
node dist/cli/index.mjs app call plans.list '{"agentId":"bobo","conversationId":"实际会话ID"}' --json
```

owner明确员工/会话；员工工具可由宿主补齐当前范围。`set`仅创建一个未归档计划；更新提供实际id/expectedRevision和稳定requestId。`claim`领取单项并返回token，`submit/review/resolve`传为claimToken。领取项itemId不同于计划id。`show`按ref读取完整报告；`block/unblock/reset/archive/delete`按真实版本办理。重置/删除不会撤销真实文件或Work效果。

审核needs_changes→领取feedback→resolve→重新审核；达到次数上限为max_cycles，整图completed_with_unapproved_reviews，表示存在未通过审核。计划记录和给定文字的审核走chat，实际文件/命令/浏览器实施沿原task/Work。重启只恢复记录，不重发业务操作。当前由原Bobo/owner应用权限控制，没有跨员工/会话共享或独立计划卡。
