## 真实交付失败：FR-01

任务只包含两份短材料：订单 O1=100、O2=80（重复一条）、O3=70、O4=50（已取消）；固定退款 20。预期报告为成交 3 笔、成交总额 250、退款 20、净额 230，引用原材料；V2 需增加去重/排除取消单的说明。

实际结果：默认自动思考配置下，模型在首个执行请求中达到 **8192 输出 token** 上限，正文为 0 字符、工具调用为 0，没有产生 `report.md`，后续修订、采用和重启未进入。保留这一失败，不以反复重跑或更换模型掩盖。

| 核验点 | 实际证据 |
| --- | --- |
| 模型/连接 | 已保存的 OpenAI 兼容接口，`deepseek-v4-pro`；连接 ID 见登记，未导出密钥 |
| 判断请求 | HTTP 200；`max_tokens=1200`，显式低思考；正常结束 |
| 执行请求 | HTTP 200；`max_tokens=8192`；自动任务未传 `thinking/reasoning_effort`，沿供应商默认 |
| 结束原因 | `finishReason=length`，输出恰好 8192；执行约 65.85 秒 |
| 工具可用性 | 请求已提供 8 个工具，包括写入和发布；没有发生任何工具调用 |
| 请求预算 | 新实验总上限 24，实际 3；不是总调用额度耗尽 |
| 来源 | 本次隔离库 `real-model/data/material-delivery-v1-1/boai.sqlite` 中的 `traceSpans`；只记录必要指标，不展示思考正文 |

代码对应：[自动思考参数](../packages/runtime/src/adapters/mastra/model-config.ts)、[执行和输出限制](../packages/runtime/src/adapters/mastra/engine.ts)。当前行为符合已实现的默认策略，但本次说明交付效果存在可靠性问题。旧样本相同参数曾成功，因此不能由单样本断言 SDK 或供应商必然错误；也不能归因于尚未执行到的文件发布/修订事务。

后续改进应登记自动任务思考策略与输出预算的对照，例如显式较低思考强度，在原 Work 累计输出限制和本实验剩余 21 次请求内验证；不能静默增加预算，或将改过参数的结果算作原默认配置通过。**本轮未改员工偏好、未改生产模型参数、未发第二个样本。**
