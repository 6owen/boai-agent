# 公共IM消息接收修复

用户已明确：员工收到任何消息，就必须在“会话”页面有对应入口。上轮只为定时任务增加异步补发，遗漏了普通隐藏私聊、群聊和统一消息提交规则。本轮按[第16组03 §18](../../spec/16.数字员工渠道绑定/03-员工主私聊与群聊领域设计.md)纠正，并写入根AGENTS的强制约束。

## 根因与实现

普通消息落库没有统一恢复会话可见性。渠道、定时任务各有局部逻辑，旧群自动化测试甚至要求原群消息为空。结果是消息已经受理，却要依赖特定来源、后续事件或页面路径才能出现在列表。

ProductStore的消息write和transaction.put现在进入同一个提交钩子；conversations/message-reception在原事务内处理新消息身份、可见性和必要的公开投影，提交成功后再更新内存与广播。普通私聊恢复员工入口，群消息恢复原群，渠道来信恢复原渠道和所属员工入口。任务公开消息按实际员工/群归属发布，不等待模型回答；执行上下文、Work、run、turn和预算仍保留在原任务，不重新调用模型或额外向平台发消息。

删除定时专用异步队列与渠道专用隐藏恢复分支。旧任务公开消息ID/清空回执继续兼容；流式增量更新同一条消息，重复事件不唤醒隐藏会话，已清空的旧消息不会因启动扫描复活。没有公开Message的工具日志或私有判断不伪造聊天消息。
