# PPT 员工工具与计量

2026-10-20，承接 `a4e804ac` 保存的阶段。此前是实际进展；完整迁移目标保持，不以 PPT 子阶段替代 371/206/40 与人格效果。

## 已接入

`presentation-tools.ts` 复用原 Alma 设计、布局、图标、模板/材料、编译和视觉审阅核心，提供 13 个真实工具：配置检查、三个目录、模板检查、素材提取、创建、读取、逐页修订、验证、渲染、审阅、导出。API 使用原 task runtime；CLI 调用同一实例；Codex/Claude 从同一工厂取得 schema，再沿原惰性 Work 执行。原生读取配置/目录不创建 Work。

项目和解析缓存放在当前员工×聊天的私有 `.presentations` 中。返回当前项目 ID/revision 和公开来源句柄，不把内部路径当模型文件权限。材料读取复用原逻辑/业务目录、宿主成果字节与当前来源核验；提取分页缓存，图片自动复制为受管资产。后续项目使用会复核原来源权限/hash，跨员工或跨聊天不能拿 ID 复用。通用文件工具不能用 `self:/.presentations` 读取未审阅原件。

逐页修订采用原 CAS 和不可变版本。渲染可在明确的获准输出目录保存 PNG 预览，返回实际路径/hash；不自动注入聊天模型或冒充审阅通过。专用视觉审阅使用原六页/重叠批次和质量门槛；只有当前版本通过后才能导出，渲染/模型选择改变也使旧审阅不能用于新导出。导出为普通获准的新任务文件，再沿原 `publish_artifact` 发布。

专用请求接原追加调用入口，实际视觉连接/模型/路由单列在同一 Run 中。主 SDK 累计与按请求标识保存的附加用量串行合并；重复主回调不重复叠加，未知字段不填零。普通 API 任务沿既有 Work 计数和 profile 请求记录；原生分支不增加 CLI 调用次数或 BOAI token/预算记录。

- API：真实 AppService → 员工工具/CLI 实例 → 编辑 PPTX → LibreOffice PDF/PNG → 独立 Responses SDK → 审阅报告 → 导出 → 原发布。独立读取已发布字节/hash 与审阅文件一致。未审阅拒绝、页面改变后旧批准拒绝；实际 PNG 预览另存并核对 hash。清空会话后私有项目/缓存删除，零请求重放。

视觉 HTTP 回答为确定性夹具。它证明实际传输、工具与文件流程，不证明视觉判断质量。外部模型请求新增 **0**，累计仍 **1338**；没有新的日常人格评测。
