# 图片生成能力接入

Bobo 实际绑定第 29 项 `boai-image-gen`，configVersion 66 / profile revision 16。原 28 项身份与顺序、人格配置保持；29 份技能的源、员工副本和构建副本字节一致，40 份 Alma 研究原件 hash 保持。

`images.settings/configure` 接同一应用协议、稳定写回执和配置 revision，复用已有模型连接与宿主私有凭据。生图模型独立于聊天模型；保存配置不生成图片，不自动选择连接或回退。当前三个连接是聊天模型，本轮没有替用户选择图片提供方或探测这些密钥。

`inspect_image_generation/generate_image` 接 API 任务与普通本机会话的共用工具。检查不创建本机 Work；实际生成仍沿原惰性 Work、目录/材料权限、取消、文件写入和 `publish_artifact`。编辑上传实际原图字节，最多四张/8 MiB。输出最多 20 MiB，PNG/JPEG/WebP，按后缀传显式 JPEG/WebP 格式；实际返回类型必须相符。独占写入不覆盖原文件，同运行同输出路径不重复请求。连接/设置变化取消在途请求并拒绝旧来源写入；凭据读取与连接修改串行，不向旧地址发送新凭据。

当前实现的是 OpenAI Images 协议：JSON generations、multipart edits 和 base64 返回，按官方接口分别处理原生返回与显式兼容 response_format。未实现 Gemini/自动选模型/返回 URL 下载或独立图片设置面板。[生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)、[编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)。

## 实际验证

受控 HTTP＋SQLite＋真实任务工具验证配置/CAS、固定模型/请求、原图编辑上传、取消、错误不重试/不泄露、文件竞争、路径拒绝与原文件交付。原生产品目录检查和惰性生成也通过共用工具验证。最终五文件 242 项通过，加原生会话独立回归 89 通过/2 跳过，合计六文件 331 项不同检查通过、2 跳过（非同一轮全绿报告）；13 项图片检查包含修正后的 native 清理。类型、源码构建和 diff 检查通过。具体日志见 `image-workflow.json`；不把受控像素当成实际生图模型质量，也未跑 E2E 或安装包。

真实 Bobo 一题一次，使用当前 deepseek-flash、当时已绑定的 29 项技能：5 次模型请求，3 个 run 完成，读取 `boai-image-gen` → `inspect_image_generation` → `report_work`。隔离数据库零图片设置、成果、自动化、任务进度和后台活动；一条 delivered Work 交付的是缺少配置的解释，不能说图片已生成。累计模型请求 1009，原 3 次网页检索另计；本轮实际外部生图请求为零。

它准确说出缺少图片连接/模型，没有擅改配置或硬试聊天模型。但答复有四段，暴露 ready 字段，并引导去尚未提供的“图像设置”页面。已在技能中明确当前配置入口是业务协议、连接编辑器只保存连接；这处修订之后没有追加模型样本，不声称已验证消除幻觉。无人工标签、校准 judge 或未见认证。
