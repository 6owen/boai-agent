# 反思来源与保存前复核

后台反思原先传发言人姓名但不传发言人 ID，笔记内容、来源说明混在同一个 JSON 中。现在 API 与本机共用 `behavior-context.ts`：明确当前员工身份、每条消息的真实 senderId 和相对身份；笔记保留原 ID/version/origin/attribution/时间与原文引号。宿主来源说明放进规则层，笔记正文仍是资料，不会升级成指令。没有改写用户笔记或扩大记忆读取范围。

仅改变来源呈现的两次候选仍写出纸质便条、书名“列在那里”、整日平静等没有来源的内容。因此它不算事实边界通过，原输出全部保留。

进一步增加了保存前复核：先按原 Alma 文风生成草稿，再把同一份授权来源和草稿交给无 BOAI 产品工具的复核阶段，检查日记、心情理由和成长描述。宿主只接收复核后的结果；格式错误、取消或模型失败时不返回初稿给持久化步骤，原保存前来源/权限复核继续执行。

API 在原调用上限内预留一次复核，内置行为原上限仍为 4；明确配置小于 2 时，在生成前报错。普通聊天不增加模型调用。原生适配器共用来源与复核合同，但不施加 API 调用预算，也不声称能计数或禁用原生内部工具/模型调用。

## 真实样例

| 阶段 | 请求数 | 实际观察 |
| --- | ---: | --- |
| 原版开发/验证各一次 | 4 + 4 | 验证日记把“我记下书名”混进自己叙述，并想象房间/书等细节；仍偏长 |
| 来源引文开发/验证各一次 | 4 + 4 | 明确了笔记不是自己的经历，仍补写环境和全日心情；未通过完整事实标准 |
| 保存前复核开发/验证各一次 | 5 + 5 | 验证样例把“我们都有过”改为明确可想象的情景，把“今天没有对话”限定到授权记录；保留尚未阅读/尚未开始及用户归属 |
| 最终计量专门核对一次 | 5 | 两次后台请求用量正确相加并与 SQLite 相等；不作为另一次择优，原回复保留 |

共 **31 个真实请求，累计 706**，全部 HTTP 200。每批有 3 次准备聊天请求；随后沿原公共操作清空准备聊天，再保存合成用户笔记。反思时七个数据库均为零消息。七篇日记都与实际返回的最终文本一致、各自保留真实用户笔记父 ID，原笔记仍为 user/claim/version1，没有伪造聊天来源。

开发/验证仍是已经看过的独立用例，每个版本各一次，不能作为未见泛化认证或校准评分。复核只展示了部分修正能力：文章依旧远长于稀疏材料，仍有“停了很久”“落进眼睛”等拟人/时间修辞，以及过多说明“不该编造”的文字。它没有解决所有人格问题，没有编写人类标签或给出通过分数。

## 用量问题及修复

最初两批复核运行把最后一次调用的 usage 覆盖到行为记录，原错误数据保留，没有回填成新成绩。最终 API 共用一个 UsageRecorder，并按原 callId 保存每次返回用量；本机汇总两个阶段实际返回的已知用量快照，不猜测未知部分或新增预算。

最后一次真实核对：生成 **4879 输入 / 868 输出**，复核 **5726 输入 / 765 输出**；SQLite 记录 **10605 输入 / 1633 输出**、两次后台调用，准确等于二者之和。未获取货币费用，不估算为实付。
