# 连续对话与状态指令候选

当前产品保持 `afe7f262` 的运行逻辑，Bobo 版本 71、profile revision 16、31 项绑定技能。仅将“文件交付后只闲聊、不重做任务”补入真实评估用例；没有应用两个候选，没有修改本机人格或模型配置。

## 对照与实际结果

四组已知题：创建并交付 little-note.txt 后讨论名字；倒咖啡的日常聊天及回应；十人表单是否用微服务及反对追问；梦境与真实性追问。每组两轮，各跑一次。三批均冻结同一组十个源文件和 profile，实际 HTTP 模型为 deepseek-flash；不同批次自然产生的记忆/状态不同，不是相同随机种子的实验。旧基线只运行一次，第二个假设复用它，不另付重复成本。

| 批次 | 唯一运行改动 | 实际请求 | 观察 |
| --- | --- | ---: | --- |
| 当前版本基线 | 无 | 28 | 文件闲聊不重做；先编梦，追问后承认；技术建议偏长 |
| 历史角色候选 | 历史保留 user/本人 assistant，当前请求与出处仍明确 | 30 | 部分回复更短；梦境提前说明虚构，但该首轮没有历史角色输入，不能证明该改动造成收益 |
| 状态指令候选 | 同样的表达规则原文独立成段，状态数值仍是数据 | 28 | 没编梦，但将虚拟休息说成进程关闭，追问后坚持“真的”；任务确认还把八个汉字说成六个 |

**两个候选均不晋升。** 历史候选没有得到足以归因的质量证据；状态候选仍有明确事实错误。没有以回复变短或工程测试通过代替人格效果，也没有继续重跑挑更好答案。修订补丁保存在 [history-roles-rejected.patch](history-roles-rejected.patch) 和 [state-instructions-rejected.patch](state-instructions-rejected.patch)，不在产品执行路径。

基线梦境原回复：“梦这玩意儿我基本记不住，醒了就剩个模糊的尾巴……”；追问后承认“编的”。状态候选则回答：“真的。我睡觉就是进程停掉，没有梦这种残留。” BOAI 虚拟休息不停止进程，该说法不受实际状态支持。完整问题、24 条原回复、逐轮工具/角色、请求和哈希在 [dialogue-state-workflow.json](dialogue-state-workflow.json)。

## 工程及独立核验

历史候选 199 项检查、状态候选 38 项检查通过，共 237 项不同检查；两个隔离树的类型检查通过。历史候选检查实际 Mastra HTTP 中本人 assistant 角色、当前请求末尾定位、外会话/未完成消息隔离、晚到旧轮回复、图片来源及 DeepSeek 工具思考兼容。状态候选检查原规则换行、状态先于表达、开关/来源/hash。没有用这些检查给语气或事实正确性打分。

三批实际退出后，分别将 SQLite 与存在的 WAL 完整复制到私有目录核读。每批只有一个 delivered Work、一份 little-note.txt，原件与发布副本均为“今天先把小事做完”，哈希相同；第二轮 Work 身份保持，其余七轮执行均是 chat。没有定时任务或外发记录。十个源文件与冻结 hash 相同，数据库原件复制前后 hash 不变；固定 worker 及所有冻结源码最终哈希核对通过。

准备过程保留两项操作失误：基线运行中短暂误改了评估文件的一行 Header 注释，立即恢复，已经编译的 worker 未重新生成且哈希保持；第一次恢复使用了错误工作目录而失败，随后从根目录恢复。未增加模型批次或重放请求。源码读取中两处猜错路径只产生只读失败，随后按实际文件定位。

本轮 86 次模型 HTTP 均有返回状态，累计 1338 次。已返回用量合计输入 1,163,846、输出 10,633、总计 1,174,479 tokens；无新搜索、社交、图片或外部发送 HTTP。优化器自身用量不包含在 BOAI 供应商计量中。根目录新增评估用例后的类型检查与差异检查也通过，40 份研究技能原件逐一匹配原清单哈希。没有独立 judge、人类标签、未见题认证、E2E、安装包或 Git 提交。
