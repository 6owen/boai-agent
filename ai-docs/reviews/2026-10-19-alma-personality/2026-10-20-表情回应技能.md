# 表情回应技能

`boai-reactions` 已接入当前 Bobo：20 项技能、configVersion52，profile revision16。20 份员工副本逐一与仓库源文件比对一致，40 份 Alma 研究技能原件 hash 均未改变。pnpm dev 已空闲重载到 PID90548 / Electron90556，服务、存储和浏览器就绪；人格开关、主动交流偏好及反思 v3 保持。

## 实际接线

- `list_reaction_messages` 返回本轮实际可见消息 ID、当前回应、支持的表情与目的地；`react_to_message` 以宿主固定的员工身份添加/撤销。不能冒充用户、跨会话操作或在执行结束后继续调用。
- BOAI 本地回应修改原消息，不创建 Work、新消息、定时任务或渠道发送。既有用户回应和消息正文保持，现有 UI 自动显示员工名称。
- 渠道触发时仅回应原绑定、聊天和主题中的实际来信。飞书/Lark、Telegram 使用已安装 SDK 的 addReaction/removeReaction；回执沿原 channelDeliveries、发送队列和重启恢复。未知结果不重试；重放旧 add 回执不会覆盖后来 remove 的显示状态。
- Telegram 原生接口只保留一个机器人回应；BOAI 同步替换员工的旧表情、保留用户回应。飞书类型映射取自安装的厂商适配器。钉钉/Discord 未开放回应工具，不用文本 emoji 冒充。依据：[Chat SDK adapter 访问](https://chat-sdk.dev/docs/api/chat)、[Telegram setMessageReaction](https://core.telegram.org/bots/api#setmessagereaction)。

## 真实模型效果

两组各两轮，25 次真实请求、累计529，全部HTTP200。实际AppService/Mastra、SQLite与原始输入/工具回执见[reactions-workflow.json](reactions-workflow.json)。

| 样例 | 实际结果 |
| --- | --- |
| 给当前消息庆祝，下一轮撤销并换成赞 | 原消息先有🎉，后仅有👍；当前指令消息无表情 |
| 先给感谢，再给下一条点赞 | 上一条🙏保留，新消息有👍；身份均为bobo |

实际读取技能使用 bobo 已有 `manage_skills list/read`，动作使用新增工具；不是假定必经 read_skill。四条用户消息中共三条最终带回应，Work 与渠道发送均为零。当前自然回复示例：

> 修好啦！反复报错的东西最磨人，你愣是把它啃下来了，厉害。今晚可以安心睡了。

第二轮仍出现“换好了：那条消息上的…已撤掉”等操作说明，验证回复也多解释了一句账号身份。能力通过不等于自然交流效果通过；没有独立校准评分器或完整 Alma 对照，未修改反思提示词。
