# 浏览器默认权限、员工命令授权与重新汇报修复

日期：2026-10-17。

## 实现

- BOAI内置浏览器不再按网页来源或每个交互请求人工批准。有效员工任务可直接查看、导航、填写、点击及下载；页面版本、原引用身份、HTTP(S)范围、实际调用开始、取消退出、受管下载和未知结果不重放校验保留。
- BOAI宿主命令审批卡增加“始终允许此类操作”。授权绑定当前员工，独立持久保存，跨任务和重启有效，不修改员工运行配置版本、不打断当前任务。审批消费与授权保存使用同一事务，保存失败时保持待审批。
- 通讯录 → 员工 → 编辑配置 → 命令执行展示“允许，不再询问”，可点“恢复逐次确认”。关闭命令、切换到不适用的运行后端、停用或删除员工会清理授权。本机Agent自己的命令权限模式继续由其原生配置控制。
- 所有重新汇报输入在材料投影入口统一排除员工已忘记的历史消息，原来源有效性验证保持。浏览器资格与任务调度范围沿现行实现，本次没有扩展旧ACP后端或自动化/组织任务的浏览器能力。

## 天气任务失败的根因

只读核对原失败运行 `41d0b924-c5ef-4bbb-bf9a-fe4aa7a90b37`。最初运行上下文正确排除了六条已忘记的历史消息；重新汇报调用 `materialMessages()` 时却再次读入这些消息，因此被原来源校验拒绝，报“重新汇报的实际输入来源已失效，不能读取旧原文”。

修复把遗忘过滤放入共用材料消息投影，覆盖新消息到达触发的汇报和答复证据修正触发的汇报。两条回归路径均断言只执行一次工作、不重新执行副作用，最终正常发布。没有改动用户数据库、覆盖原失败记录或重放原天气任务；本轮未调用真实模型供应商。
