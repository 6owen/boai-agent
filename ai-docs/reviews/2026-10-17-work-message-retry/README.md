# 普通聊天失败工作接续

## 问题与原因

原任务达到 Mastra 单次工具循环上限后标记 failed，提示继续发送消息。新用户消息的模型判断已引用原 Work，但普通聊天路径直接 claim，遗漏重试授权，因此返回“工作当前为 failed，不能重复执行”，第二条执行显示已停止。

用隔离 AppService/FakeEngine 重现完全相同的状态和错误；初始单项回归失败。随后仅只读核对该次 DS 运行的计数/状态：12 次模型调用，47 项已完成工具记录，pendingEffects=0，但 requiresReview=true。已确认操作后因步骤上限退出，没有 settle 清除此标记，形成第二层拦截。未重放用户的 Obsidian 查询，没有真实供应商调用。

## 修改

- 仅当前真实用户的新消息、模型选择继续同一失败 Work、同员工/会话及所见版本匹配时，传递宿主专用重试标记。
- SQLite 同一事务复用原 authorizeRetry 校验并认领；后续认领失败回滚版本和重试计数。
- 保留原 Work、原始消息、预算、累计调用、绝对期限和历史工具；重复消息不重复执行。
- 本人新消息明确接续时，仅当原执行全部已释放且 pendingEffects 明确为 0，才可复用已确认操作；缺失/未知计数、待完成操作仍拒绝。原执行快照/资源失效同样拒绝。普通重试按钮的保守规则保持。
- 已完成操作上下文补入 call_data_source/browser_tool，和原文件/命令操作一起交给模型；不由宿主重放工具。
- 原模型 12 步限制未改动；它与整个 Work 的累计额度是不同限制。原额度耗尽、超时或操作待核对仍拒绝续行。
- 自动唤醒、渠道来源、原自动化、组织/修订等继续沿各自已有授权入口，不取得此普通消息授权。
