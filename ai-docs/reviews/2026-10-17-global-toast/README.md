# 全局错误反馈与旧后台加载

## 原因与现行约束

截图中的“自动化暂不支持命令执行”已不存在于当前源码和dist，但用户开发窗口的Electron 91422 / 运行服务91434仍从03:05启动，早于上一轮修复。`scripts/dev.mjs`只在启动时构建host，前端热更新不会重新加载后台。上一轮隔离新进程通过不能证明旧窗口已生效，本轮明确纠正该交付缺口。

[AGENTS.md](../../../AGENTS.md#全系统错误提示强制)强制全系统操作/请求/加载/校验失败通过现有shadcn Sonner，不允许页面、表单、弹层或工具栏内错误Banner/Alert/红字DOM。错误状态、草稿、锁定和原请求身份保持；重试/核对按钮独立保留。持久业务失败状态和主动查看的执行记录仍可核对，不因浏览历史批量重弹错误。

## 实现

- 共用`useMutation`直接发Sonner，旧`Banner`错误分支/`FieldError`/destructive `Alert`变为无DOM的`ErrorToast`。同文案使用稳定toast身份，受控渲染去重，StrictMode与重渲染不刷屏；明确重试仍可重新通知。
- 搜索、模型列表/连接测试、输入框、附件/图片/文件预览、技能操作和独立浏览器工具栏的局部错误统一Sonner。Toaster继续沿现有shadcn适配和主题，不另造错误外观。
- 原错误组件内的恢复按钮移到原业务位置独立显示。定时任务保存失败不改变表单布局、不丢输入，未知回执的“核对创建结果”保持可用；短暂核对阶段不额外弹出一次“未知”错误。
- ESLint禁止直接在业务DOM使用`role="alert"`，治理文档同步此强制规则；历史执行错误保留在明确展开的详情内。
