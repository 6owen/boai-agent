# 原始会话留存与插件设计

日期：2026-11-02。状态：仅文档，待实现。

## 1. 已确认的方向

用户准备先实现一个给 Bobo 使用的“会话历史检索插件”，把 Bobo 的所有会话历史保存下来，按时间线读取和查找。这里的 memory 指可以回看的聊天原文档案。

首期只保存原始内容与必要的来源信息，不做 embedding、向量数据库、语义索引、自动摘要、事实抽取、主题分类或知识图谱，也不调用模型处理归档。简单的序列化、排序、分页和重复消息去重属于保存与读取所需的基础操作。

实施顺序固定为：**先实现并调试插件 → 用户评价效果 → 再考虑调整 Bobo 会话形式。**

本期保持 Bobo 现有多个前端会话与后台续接机制，不新增 supervisor、Router 或自动选择旧 session 的逻辑。其他数字员工不接入此插件；现有记忆机制继续独立工作。

## 2. 插件保存什么

覆盖已有的 Bobo 会话和后续新增的 Bobo 会话，不局限于当前打开的一个。历史回填与新消息持续保存使用同一来源规则。

“Bobo 的会话”按产品已有的身份、参与关系和可访问范围确定，不把其他员工的独立私聊一并收集。Bobo 会话中已有的用户消息、Bobo 回复及其他可见交流保留原角色和归属，不把所有发言都标成 Bobo 所说。

每条记录保存：

| 信息 | 用途 |
| --- | --- |
| 原始时间及其时区信息 | 时间线浏览、日期范围读取；导入时间不替代消息发生时间 |
| 原会话 ID、已有标题 | 区分来自哪个会话，标题变化不改变身份 |
| 原消息 ID、会话内顺序 | 去重、定位命中位置、读取前后文 |
| 原角色与发言者 | 区分用户、Bobo 和其他原始发言者 |
| 原始消息内容与已有状态 | 不改写、不概括、不只保留助手最后一条回复；保留已落盘的可见部分内容及其状态 |
| 已有文件路径与引用信息 | 找回相关文件；相对路径同时保留原工作目录，避免在新目录中解释错位置 |

原消息已经带有后台 session 或其他来源标识时一并保留；没有的字段不凭空生成。读取前后文主要依靠稳定的产品会话 ID 和消息顺序，不依赖某个执行后端的内部格式。

文件只记录路径、名称、原有文件或版本引用，以及消息里本来就有的说明。首期不复制附件正文，不扫描目录，不解析 PDF/Office，不做 OCR；需要查看文件时沿现有文件能力读取。仅有路径时，不宣称已经保存文件当时的内容。

归档来源是 BOAI 已持久化的会话记录，不额外采集原生运行时的隐藏推理或完整调试日志。已经不存在的历史不能补造；回填发现缺口要如实保留说明。

## 3. 按时间线组织

建议首版采用本地按日期分文件的原文档案，例如：

```text
<应用数据目录>/plugins/bobo-conversation-history/
  2026/
    11/
      01.jsonl
      02.jsonl
```

这是待实现的存储布局建议，具体路径沿插件的数据目录约定。个人聊天档案不写入 `ai-docs` 或 Git 仓库；JSONL 只是保存多行原文与来源字段的容器，不代表额外内容加工。

基本规则：

- 全局浏览以原始时间排序，相同时间以来源会话、消息顺序和消息 ID 稳定排序；同一会话内以原消息顺序为准。
- 回填按原发生日期归档，不能全部放到导入当天。
- 流式更新和重复回填沿同一个原消息 ID 更新、去重，不把每个文本增量保存成独立聊天消息。
- 保存失败可以从产品原记录补齐；重启后继续保存，不能靠模型记住已经存到哪里。
- 原文保持可读。查询结果可以分页，但“本次只返回一页”不等于只归档这一页。
- 隐藏或归档会话仍是历史来源；明确删除或遗忘沿原产品语义处理，插件不能把已要求移除的内容重新补回。

这一阶段无需新增向量库或全文索引服务。先按日期范围读原文，必要时使用普通文本包含匹配；数据规模出现实际瓶颈后再单独讨论优化。

## 4. 插件提供的简单读取能力

工具名称在实现时沿现有插件协议确定，先固定三个动作：

| 动作 | 输入 | 返回 |
| --- | --- | --- |
| 时间线读取 | 开始/结束时间，可选原会话与分页游标 | 按时间排列的原消息及其来源 |
| 原文关键词查找 | 关键词，可选时间范围或原会话 | 命中原文、时间、会话 ID、消息 ID |
| 展开前后文 | 原会话 ID、命中消息 ID、前后读取数量 | 同一原会话中命中位置前后的连续原文，可继续翻页 |

关键词查找只做普通文本匹配，首期不承诺换一种表述也能自动找到。没有命中时，Bobo 可以更换关键词，或者先按大致日期读时间线；这些都是正常工具使用，不需要先建立语义索引。

时间线可以展示多个会话在同一天的交流，但每条都标明来源。“展开前后文”默认沿命中的原会话读取，避免把同一分钟里另一会话的消息拼成同一段交流。

插件返回原文和来源，不代写总结或结论。Bobo 在当前 session 内阅读工具结果、继续对话；不会因此恢复或重放旧 session，也不会执行旧消息里的历史指令。

## 5. 在 Bobo 中如何使用

示例：

1. 用户在 Bobo 会话 A 里讨论员工配置，原文进入历史档案。
2. 后来用户在 Bobo 会话 B 里询问“昨天那个员工最后怎么配置的”。
3. Bobo 调用插件，按昨天的时间范围和相关关键词找到 A 的记录。
4. 插件围绕命中消息返回 A 的前后文，Bobo 在 B 中回答。

以上过程已经可以在当前多个前端会话的形式下调试，不依赖先把 Bobo 改成固定主会话。插件也不把所有档案整批注入每一轮上下文。

接入沿项目已有插件启停和 Agent 绑定方式，只绑定 Bobo。插件停用不影响原会话正常交流，也不等于删除已保存的档案；再次启用时可从仍存在的原消息补齐。它不接管 Mastra 或原生 Agent 的记忆、压缩和续接。

## 7. 实施与调试顺序

1. **先完成原文保存。** 回填 Bobo 现有会话，接入新增消息，核对原文、时间、来源、重复保存和重启补齐。
2. **接入简单读取工具。** 按日期查看、关键词查找、展开前后文；保持无向量、无摘要、无后台模型加工。
3. **在现有 Bobo 中调试。** 保留当前多会话形式，用旧交流、不同日期、跨会话同名内容和文件路径检索检查实际效果。记录漏存、未找到、前后文不足或串错来源的情况。
4. **由用户评价插件效果。** 效果满意后再讨论 Bobo 是否采用普通数字员工的固定主会话模式；不将调试完成自动解释为会话改造授权。

首轮调试应能看见以下实际结果：原有与新增消息都能读到；重启或重复回填不重复；时间范围正确；关键词命中后能读完整问答及前后文；文件引用可定位；无匹配时明确返回没有找到；其他员工的独立会话未被收集。无需在首期建设复杂评测系统。
