# 检索配置与触发策略

2026-11-03。Bobo 的「记忆」页新增「会话历史检索」，直接配置现有 `search_history` 能力。默认仍由模型按需选择；本轮不修改个人数据库、不切换 Bobo 会话形态，也不降低 OM 的 6000/12000 阈值。

## 使用入口与默认值

| 设置 | 行为与边界 |
| --- | --- |
| 模型按需（默认） | 模型决定是否调用 `search_history`。核心指引随能力装载，鼓励相关既往交流的主动查证，不要求每句话都查，也不能保证每次都会查。 |
| 每轮预检 | 回答前用本轮用户文字做本地分词，取至多 3 个字面关键词，调用同一原文查询核心；不使用 Embedding，不让另一个模型决定是否查。没有有效词或没有命中时不注入证据。 |
| 关闭原文检索 | 不提供 `search_history`、不做预检，同时停用这一路 Bobo 的显式官方 `recall`。聊天、Working Memory、OM 不删除，既有自动记忆上下文仍可能存在。 |
| 邻近上下文 | 默认命中前后各 1 条；可分别调整，单侧最多 20 条。切为时间模式时初始前后各 2 分钟，按原始消息时间取同一会话邻居，单侧最多 60 分钟、20 条。 |
| 默认命中数量 | 默认 3 条，可设 1–8；模型单次调用可覆盖默认。 |
| 原文返回上限 | 默认 20000 字符，可设 1000–20000。限制整批证据及其元数据；主命中优先、邻居按距离纳入，不能把窗口视为完整返回保证。 |

每轮预检另有固定的小预算：至多 2 个命中、4000 字符，并服从用户设置中更小的返回上限。排除当前轮及已经提供的可见原文，去重命中与邻居。预检结果作为带来源的历史背景进入第一个回答请求；模型仍可在证据不足时自主补查。普通计算的数字与单字通常没有有效关键词，普通句子仍可能做少量无命中的本地查询。

时间窗口举例：消息原始时间为 10:00，前后各 2 分钟，查询的是同会话 09:58–10:02 的获准消息，而非当前时刻前后 2 分钟。边界包含端点，原会话顺序保持；命中 `from`/`to` 不另外限制邻居范围。两字符中文继续走字面查询，较长关键词走 FTS5 trigram，均为原文匹配，不能承诺同义词召回。

设置保存采用 revision 冲突检查，影响后续轮次。正在执行的轮次沿用其设置快照，但后续查询会重新核对关闭状态及来源授权。关闭不能撤回已经发给模型的内容。数值失焦保存，失败保留草稿并用通知提示；冲突时刷新后重新核对。不会通过本设置改变员工配置版本、Embedding 或 OM 整理阈值。

## 职责与依赖

| 模块 | 单一职责 |
| --- | --- |
| `shared/domain/history-search.ts` | 配置、默认值、硬上限、查询与证据协议，无框架或存储依赖。 |
| `history-settings.ts` | 参数校验和原 ProductStore 中 `historySearchSettings` 的 revision 写入。 |
| `history-search.ts` | 接收获准消息和查询端口，执行默认/覆盖参数、条数或时间窗口、证据裁剪。没有 EngineContext 或 Mastra 类型依赖。 |
| `history-capability.ts` | 同一个 search 端口供工具和预检调用；本地分词和小预算预检，不实现另一套查询。 |
| `history-guidance.ts` | 唯一运行指引，使用当轮实际默认值；官方检索 instructions 与无 OM 记录时的补充系统指引共用。 |
| Mastra `history-tools.ts` / `engine.ts` | 工具挂载与运行前预检适配；保留模型自主工具选择。 |
| AppService 来源解析 | 原始历史与 Mastra 共用来源授权、遗忘和快照失效登记，框架私有身份仅在 Mastra 分支生成。 |
| UI | 读取/编辑宿主配置，不自行拼提示词、猜触发意图或执行 SQL。 |

优先关系是「宿主权限与硬上限 → 单次工具参数 → 员工默认值」。配置中的窗口与命中数是默认值，返回字符预算是宿主约束；工具参数不能提升权限或返回预算。结果 `applied` 返回 revision、实际窗口、limit 和字符上限，`contextTruncated` 标识邻居受限。预检记录 `agent.history.prefetch` 的关键词、命中数、SQL/整体耗时和设置 revision；它不是一次模型工具调用。

原文查询复用现有消息与 SQLite 索引，不另建会话归档或记忆提取库。群聊、渠道、仅此聊天、隐藏/清理中的会话、材料引用、忘记的来源继续沿原规则隔离。其他员工与本机 Agent 的原生循环不接入这套 Bobo 策略。

## 核心指引与 Skill

`boai-history-search/SKILL.md` 随包分发，复杂检索时按需参考。它讲关键词扩展、前后文、纠正核对、原始时间和证据归属，不重复定义设置默认值或强制触发策略。日常查证的核心规则已直接装载，不要求每次先执行 `list_skills → read_skill`。

新建 Bobo 沿原默认技能清单绑定；既有 Bobo 的个人技能副本不会被静默覆盖或追加绑定。已有 Bobo 无需绑定新 Skill 即可得到运行时核心指引；要读取详细 Skill，可沿现有技能库导入/绑定流程。Skill 不负责安装工具或改变访问权限。

“南京现在天气怎么样”本身仍可合理触发实时查询。“每轮预检”能提前提供曾经的天气原文，让模型少依赖用户再次提醒，但历史记录只证明当时的读数。指引要求说明原始记录时间，不能因为几分钟前查过就断言现在完全一致。用户只要旧记录时则可以直接引用旧记录。
