**1. 两个产品的相似处与关键区别**

Todos 以任务和仓库为中心，总管分派，Agent 执行，人在方案与成果环节作决定。它的“项目”明确绑定 Git 仓库；boai 以员工和会话为中心，工作与材料、报告等成果从真实交流产生。因此可以借鉴长任务管理，但不宜要求所有研究、写作、资料工作先建立 Git 仓库。[Todos 概览](https://todos.dev/zh/docs/overview)、[项目](https://todos.dev/zh/docs/projects)

此前 Raft 分析中“缺少完整聊天／任务／文件、全局看板、员工能力概览”的描述已经是历史快照：当前这些入口已有代码。现在需要完成其验证和细节，不应继续计入“尚未开发”。[当前工作视图进度](/Users/wangwenbo/Desktop/demo/boai/boai-agent/ai-docs/spec/8.Agent-IM产品完善/13-工作视图实施与自动验收.md:9)

**3. 最值得转为 boai 产品需求的六项**

下面是本次建议，尚未排入已确认路线，也不代表用户已授权实施。

| 建议顺序 | 用户能做什么 | 复用基础与最小边界 |
| --- | --- | --- |
| 1. 外部应用连接与工具凭据 | 让指定员工读工单、找云端资料、查数据库，而不是反复人工搬材料 | 先选一种真实应用贯通连接、工具发现、员工绑定、授权、撤销和故障说明；模型连接与业务连接分开。MCP 客户端优先，对外 MCP 另排。[连接](https://todos.dev/zh/docs/mcp-servers) |
| 2. 可选的执行前方案 | 复杂任务先给方案，用户修改范围后确认某一版，再开始执行 | 复用 Work、消息回执、来源版本；“修改方案”不能触发原工具执行。简单任务继续直接工作；不把每句话都变成计划审批。[方案](https://todos.dev/zh/docs/plans-and-diffs) |
| 3. 成果差异＋独立审查 | 看到新版具体改了什么，并让另一位员工核对固定版本 | 先做 TXT/Markdown 差异，审查记录绑定两端版本/hash；审查者只读，意见回原聊天。审查通过、成果发布、本人采用三件事分开。[AI 审查](https://todos.dev/zh/docs/ai-review) |
| 4. 指定工作引用＋bobo 查询进展 | 把某张任务卡交给 bobo，询问卡点或比较几项工作 | 引用真实 workId 和当前获准来源，复用现有全局查询；查询不隐式创建任务，也不让 bobo 获得所有员工私聊。多人意见不能改写负责人的交付事实。[总管](https://todos.dev/zh/docs/chief) |
| 5. 长任务上下文与记忆反馈 | 知道员工这轮读了什么、记住什么，长期对话不会仅靠截去旧消息维持 | 先整理已有 Trace/记忆来源，再做版本化摘要与压缩检查点；清理/撤权仍能使摘要失效，摘要不能替代原件证据。[上下文](https://todos.dev/zh/docs/context) |
| 6. 成功工作沉淀为技能 | 从一个已完成且有证据的工作生成可复用方法，审阅后给员工使用 | 复用现有 Skills 导入/更新/绑定，不另造商店；先草稿、再显式发布，不自动覆盖已绑定技能或扩大权限。[技能](https://todos.dev/zh/docs/skills) |

其中第 2、3 项很适合通用员工产品：研究任务可以先确认研究范围、来源与交付格式，报告任务可以比较两版文本，再由核对员工审查事实。无需先做 GitHub、worktree 或代码合并。

如果近期主要目标仍是把“资料交给员工，拿到可用报告”做完整，PDF/Office 正文与引用、实际交付质量、已有工作视图验收应与上述候选一起排序，不能被新目录吸走优先级。

**5. 不宜照搬的设计与明确取舍**

- **不恢复独立待处理主页面。** 当前产品已选择在原员工消息处理补充、审批和采用，右侧只读；可借任务筛选与定位，不另造办理入口。
- **不把看板拖成完成当作交付。** Work 的真实成果证据和本人采用继续独立保存。计划确认是新对象，不能挪用命令审批或成果采用来代替。
- **不直接复制周期取消策略。** Todos 文档规定新周期可取消仍在运行或等待的上一轮；boai 已有 occurrence、原问题、共享预算与工具回执，若改变重叠策略须显式定义，不能静默丢弃旧等待。[定时重跑](https://todos.dev/zh/docs/schedules)
- **不将外部运行时描述为安全沙箱。** Todos 官方说明外部 CLI 以宿主用户权限运行，无逐项审批/沙箱；boai 的宿主命令也明确不是 OS 沙箱。应借能力说明，不取消 boai 现有审批。[外部运行时](https://todos.dev/zh/docs/runtimes)
- **不复制“一个员工取得全部团队业务密钥”的粗粒度开关。** Todos 密钥文档是这种范围；boai 若新增，应优先考虑具体连接/凭据按需授权，避免把模型 key 与业务凭据混在一起。[密钥](https://todos.dev/zh/docs/secrets)
- **不混合员工私有记忆。** 两者都支持独立记忆；共同规则放在明确共享资料/技能或经用户确认的公共事实中。bobo 现有 AGENTS.md/SOUL.md 已具用户规则基础，不需要因为“章程”这个名称再造一套。[B08] [B18]
- **远程机器、托管仓库、手机、多端同步属于单独产品阶段。** 它们需要身份、同步、执行位置、授权和恢复合同，不应作为补完本地视图的附带改动。
- **向量/embedding、重启后盲目续行、独立资料库主导航及旧团队方案表单仍遵循现行排除项。** 不因为竞品目录存在类似名字而恢复。
