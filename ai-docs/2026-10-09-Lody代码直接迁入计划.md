# Lody 代码直接迁入计划

日期：2026-10-09。状态：**计划已建立，生产代码迁入尚未开始。**

执行原则：**以Lody固定源码为实现，不按功能描述重新写一套。能保留的代码原样保留；只修改在BOAI编译、取数、显示和生命周期中不可避免的连接部分。**

用户尚未指定首批模块。本版默认顺序是：冻结来源 → 核对依赖与适配清单 → PDF → DOCX/XLSX/PPTX → 成果diff → 独立审查更大模块。首批是文件预览和只读成果diff；协作核心、批注与视觉预览列为候选批次，不能因计划存在就改写当前Work或恢复暂停的本机兼容开发。用户后续选择范围时调整顺序，不重新设计实现。

研究依据：[Lody源码与BOAI可借鉴方向](2026-10-09-Lody源码与BOAI可借鉴方向.md)。固定上游提交：[52e6eebe908641ea53d5a9aa3530499932f3064f](https://github.com/LodyAI/Lody/commit/52e6eebe908641ea53d5a9aa3530499932f3064f)。本计划补读了预览renderer、读取辅助、diff worker及依赖补丁，但完整递归依赖清单和锁文件核对仍属于M0，不能把入口清单称为已可直接编译的完整包。

## 1. 复制和适配的规则

每个迁入文件登记为以下一类。验收报告必须说明是哪类，不能把重写实现记成原样复制。

| 分类 | 允许操作 | 留证 |
| --- | --- | --- |
| 原样复制 | 保留函数、条件、状态转换、算法、常量、错误条件及生命周期；补项目Header | 上游路径、commit、原文件hash和目标文件 |
| 导入适配 | 改import路径、别名、类型导出和构建资产路径 | 可逐项核对的diff |
| 宿主适配 | 将原输入/回调接到BOAI现有IPC、版本身份、主题、UI控件、日志和翻译接口 | 适配原因、原接口、BOAI对应接口及边界测试 |
| 暂未迁入 | 完整依赖需要改变现有产品或运行体系，尚未确定范围 | 缺失依赖和冲突事实；保留原件，不补自写替代品 |

**允许的必要适配：**

- `@lody/*`和`@/`导入接到复制后的原文件或已有BOAI组件；不创建空壳让编译假通过。
- Button、Select、Spinner等接现有控件，Lucide图标按现行规则换成已有Iconify图标；事件、禁用条件和操作含义保持。
- StyleX布局声明按原值接入当前样式；颜色引用映射现有全局变量。仅做机械映射，不改布局、交互、圆角或增加设计效果。遇到不能机械保留的动态样式，记录差异后再确定该项迁入范围。
- 原主题、翻译和logger调用接现有接口，保持原条件和信息含义。
- 原`bytes`、`oldText/newText`或操作回调接BOAI已核对来源；用户文件身份由现有宿主管理。
- 原worker、WASM和CSS资源接现有Vite构建，携带上游用到的补丁。

**不可擅自修改：**解析算法、缓存/阈值、取消与清理逻辑、重试条件、状态语义、实际测试断言、库选型。不能顺便修上游bug、增加模板/流程/AI判断、调大预算或用自己的简化实现替代原模块。发现上游缺陷时留下原复现，再单列最小补丁；不得把修复混在复制diff里。

宿主既有权限、固定版本/hash、成果采用、明确修订和未知结果规则仍负责BOAI业务。Lody会话执行成功不能直接映射为BOAI业务已交付。

## 3. M1：只接文件来源，不先改renderer

**目标：让上游组件收到真实获准文件，保持BOAI原业务身份。**

BOAI现在的`getArtifactPreview`和`getMaterialPreview`主要返回文本/图片预览，并未提供通用PDF/Office字节输入。此处需要宿主连接代码，不能把路径文本当成授权，也不能把现有文本字段假装成原始二进制。

- [ ] 读取现有`artifact-repository.ts`、材料服务、IPC和预览调用者，确定复用的原件核读入口。
- [ ] 将固定成果ID/hash或材料ID/revision接到受管原件读取。保留当前聊天权限、实际hash、现有大小限制及来源失效处理；renderer不得获得任意路径读取权。
- [ ] 优先采用Lody预览已有的`bytes`输入。上游PDF支持`getDocument({data: bytes.slice()})`，Office支持`readOfficePreviewBytes({bytes,...})`；首批无需另建`lody-resource://`协议或远程文件服务。
- [ ] 保留上游字节上限判断。宿主现有上限较小时以宿主约束为准，不修改上游常量来扩权；记录两层限制。
- [ ] 活跃标签才读取；来源变更、关闭、撤权和清理使旧内容失效，迟到结果不能进入当前版本。

**涉及BOAI文件：**`src/shared/ipc/index.ts`、`src/shared/domain/artifacts.ts`、`materials.ts`、`src/runtime/modules/workspaces/artifact-repository.ts`、实际材料服务、`src/runtime/service.ts`及现有详情调用者。只在实际需要处扩展，具体DTO在读完调用链后登记。

**完成标准：**获准原件能作为字节输入；错误hash、不同会话、清理后的来源及陈旧请求被拒绝；现有文本预览、采用和修订回执行为保持。此阶段不宣称PDF/Office渲染已经完成。

## 7. 更大模块的独立批次

以下先做完整依赖与合同核对，再决定能否原样迁入。不能为了“都有”而改写成代理自创实现。

| 候选 | 原代码 | 进入实现前必须确定 |
| --- | --- | --- |
| 行级评论 | `ui/diff-viewer/session-comment-*`、`use-session-comments.ts`及原共享schema/存储调用 | Loro/共享状态依赖；与BOAI固定成果版本和明确修订的映射。只复制样式不算完成评论功能 |
| 视觉批注 | `shared/src/visual-annotation-*`、preview评论和提交状态、原preview runtime | 原页面运行/注入、浏览器桥和评论持久化；当前应用级浏览器及HTML不执行合同不能被隐式修改 |
| 协作核心 | `apps/cli/src/orchestration/operation-store.ts`、`operation-coordinator.ts`及完整共享/会话依赖 | Lody Session/Delivery/存储/同步与BOAI Work/Wake的实际差异；直接替换会涉及独立运行体系，不能只重命名字段硬接 |

| Role/worktree/远程 | 对应shared、session/worktree和platform原实现 | 持久员工、独立工作区、本机暂停及云能力边界；需要单独确定产品范围 |

## 8. 每一批的固定执行顺序

1. **原件准备：**确定原文件集合、锁定依赖/补丁/资产、保留来源和声明。
2. **原样复制：**以原路径清单拷贝，保持原文件名和内部结构；建议集中在`src/renderer/components/common/lody/`等对应现有职责的局部目录，具体映射由M0冻结，不另建顶级应用。
3. **接线适配：**只应用本计划白名单中的必要diff，复用现有宿主接口；每项注明原始与目标连接。
4. **原测试与适配测试：**沿用适用上游断言，补BOAI实际来源和生命周期边界；不删除失败断言。
5. **运行验收：**通过`pnpm dev`和现有Electron BDD验证可见行为，保存原件、hash、过程截图与失败。
6. **来源审阅：**检查最终差异是否均属于复制/导入/宿主适配；额外算法和产品设计移出该批。
7. **文档收口：**更新目标Header、所属`.folder.md`、需要的索引及本计划结果，再进入下一批。

这些是交付切片，不要求自动Git提交。当前已有修改保留，未经用户指示不提交或推送。

## 9. 验收入口与报告口径

迁入后按改动运行`pnpm typecheck`、`pnpm lint:ui`及相关Vitest；预览/成果适配优先沿用`tests/file-preview.test.ts`、`file-preview-ui.test.ts`、`service-artifacts.test.ts`、`service-materials.test.ts`和新增迁入模块测试。桌面流程扩展现有`tests/e2e/features/artifacts.feature`、`materials.feature`及共享steps/support，不新增平行`.spec.ts`入口。

实际产品验收使用`pnpm dev`；每批记录具体BDD启动配置与命令。不把普通浏览器页面当Electron，不以安装包作为本次前置；资源能在源码Electron构建中正确加载仍须核对。

每批留证至少包含：

| 记录 | 要回答的问题 |
| --- | --- |
| 复制清单 | 来自哪个commit、哪几个原文件、hash是否一致？ |
| 适配diff | 改了什么、为什么接线必须修改、有无改算法？ |
| 依赖/资源 | 哪个实际版本、哪些补丁、worker/WASM/CSS是否实际加载？ |
| 模块结果 | 原断言及BOAI边界是否通过；未运行项有哪些？ |
| Electron结果 | 用户能否实际打开/操作/关闭；原件和截图是否同一场？ |
| 失败与限制 | 哪些功能未完整迁入、哪些上游限制仍存在？ |

若批次涉及真实Agent协作，继续使用原第14组业务场景和第15组真实eval；模型模拟通过不等于内容质量通过。测试数量增加也不证明复制准确，最终还需核对来源diff。
