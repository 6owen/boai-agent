# 定时执行进入员工话题

员工拥有多个工作话题。定时计划负责何时发起工作；每次运行的消息、执行、权限审批和结果属于员工的一个普通话题。后续在这个话题发送消息，沿普通聊天继续，不再创建看板任务或追加定时执行记录。

## 当前实现

- 每次员工定时触发或手动试跑创建独立话题：普通员工为 `personal`，Bobo 为 `core`，均带 `employeeChat: topic`。保留既有调度受理、请求幂等、队列、取消、授权指纹和执行引擎。
- 新定时运行不创建 `agentTasks` 卡片，不写 `taskId/employeeTaskId`，不更新看板状态，不注入看板状态指令，也不发送看板结果事件。API 员工继续由现有 Mastra AgentController / Durable Agent 执行；第三方 Agent 继续用自己的执行内核。本次没有增加循环或调度器。
- 定时页面布局、计划编辑、启停、试跑和执行历史保持。记录和通知通过既有消息定位接口打开原话题，不打开任务 Dialog。
- 员工详情、聊天菜单和工具开始页的任务入口隐藏；残留任务标签自动关闭。保留看板、列表及 Dialog 的前端实现供后续复用。
- 启动时把能确认员工归属的旧定时独立会话原位转换为话题，解除会话/执行记录对卡片的关联。会话 ID、工作目录、消息、执行和原生绑定保持；不重放模型请求。不转换监控、群组、清理中会话或无法确认归属的历史。
- 删除定时执行日志保留会话、原文件和会话执行详情，重启后仍可续聊。删除会话时同步撤销其日志，保留防止原触发重放的最小记录。迁移不删除旧卡片，旧人工任务后台仅保留历史兼容，不参与新定时执行。
