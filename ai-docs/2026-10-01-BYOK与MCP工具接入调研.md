# BYOK 与 MCP 工具接入调研

调研日期：2026-10-01。只读浏览官方来源；未安装或启动 MCP 程序，未调用搜索服务、模型或付费 API。

同日后续方向：用户提出希望先接 Mastra Browser 与 Computer，MCP 将来作为插件。本页保留 BYOK/MCP 的调研与当时推荐；当前接入顺序和默认权限建议见[Browser 与 Computer 员工能力调研](./2026-10-01-Browser与Computer员工能力调研.md)。原生能力可先于 MCP 实施，模型/环境凭据分离与员工授权仍有效。

## 1. 结论

BoAI 可以继续让用户自配模型，同时让用户自配搜索服务或 MCP 工具。两类连接有独立的服务地址、凭据、能力和费用，不要求 BoAI 平台代付。模型 API key 不会自动变成搜索 API key；同一厂商有原生搜索也必须按其模型/端点能力另行接入。

MCP 适合作为可扩展工具通道；如果先接一个实际提供搜索/读取能力的远程 MCP，确实可以减少逐家开发连接适配的工作。但“支持 MCP”不等于已经获得搜索：还需要服务、用户授权、可调用的工具、模型工具调用能力，以及 BoAI 自己的来源/引用展示。

建议最小路线是“用户自配一个远程工具连接 → 检查并选择 search/read 工具 → 绑定具体员工 → 在真实任务中取得资料 → 保留来源并显示引用”。产品验收仍应是研究任务完成，MCP 连接成功只是中间状态。

## 2. 四层配置应分开

| 层 | 用户配置什么 | 向谁发请求 | 提供什么 |
| --- | --- | --- | --- |
| 模型连接 | API 地址、模型、模型 key | 模型服务商 | 判断、撰写、决定工具调用 |
| 搜索/读取服务 | 服务地址、对应 key，或自部署地址 | 搜索/抓取服务 | 搜索结果、网页正文 |
| MCP 连接 | remote URL/认证，或 local command/args/env | MCP 服务；服务内部还可能调用其他 API | 工具目录和调用通道 |
| 员工授权与引用 | 员工可用工具、来源与结果关联 | BoAI 宿主负责执行与记录 | 正确范围内使用、可检查来源 |

MCP 服务可能把搜索服务 key 放在自己的环境变量，也可能向用户要求 remote header/OAuth。用户填写的 MCP key 是否就是底层搜索 key，取决于该具体服务器；不能一概自动复用模型 key。

## 3. Cherry Studio：桌面 BYOK，内置联网和通用 MCP 共存

### 3.1 用户入口

- 模型：模型服务配置填写供应商 key 和 API 地址，管理并启用模型。[官方模型配置](https://github.com/CherryHQ/cherry-studio-docs/blob/main/pre-basic/settings/providers.md)
- 联网：`设置 → 网络搜索` 分“搜索服务商”和“URL 获取服务商”；在聊天输入区点击地球开启。[官方联网模式](https://github.com/CherryHQ/cherry-studio-docs/blob/main/pre-basic/websearch/README.md)
- MCP：`设置 → MCP → MCP 服务器 → 添加`，本地配置 command/args/env，远程配置 URL 和授权；连接后在 `工作 → Agent → 编辑 → MCP` 绑定。[官方 MCP 指南](https://docs.cherryai.com.cn/advanced-basic/extensions/mcp.md)

### 3.2 内置联网与 MCP 的关系

当前官方联网文档列出 API 和 MCP 两类搜索供应商：默认 Exa MCP 使用公开 `mcp.exa.ai` 端点、无需 key，URL 获取默认 Jina；可选 Tavily、博查、Exa 等 API，也可配置 SearXNG 地址；内置 Fetch 提供 URL 获取。多数 API 供应商要求自己的 key。这是应用提供的供应商集成，不是所有 MCP 都自带这些能力。[联网配置与供应商列表](https://github.com/CherryHQ/cherry-studio-docs/blob/main/pre-basic/websearch/README.md#在设置里配置服务)

文档区分“优先使用已配置搜索服务”和“支持原生搜索的模型”，证明独立搜索可与用户原模型组合，而非必须更换为一个特殊模型。公共免 key 端点的实际限额、稳定性和长期政策本次未调用验证，不据此承诺永久免费/无限。

### 3.3 传输与凭据

官方 MCP 指南支持本地标准输入输出、远程 SSE/Streamable HTTP；服务器和 Agent 绑定分开。源码另有 OAuth provider/callback/storage；本次抽查的 [OAuth storage](https://github.com/CherryHQ/cherry-studio/blob/e2f53146eb6944718b091661df0854c75a4d933a/src/main/ai/mcp/oauth/storage.ts#L14)将服务器 URL hash 对应的 token/client 信息写入本地配置目录 JSON。该实现中没有看到存储加密，不能笼统宣称所有凭据进操作系统钥匙串。普通模型 key/搜索 key 的完整持久化和备份路径未做审计。

Cherry 是桌面客户端；上述结论针对官方开源桌面及其文档，不与 Cherry 企业版或官方云服务的权限/存储混用。[官方仓库定位](https://github.com/CherryHQ/cherry-studio)

## 4. LibreChat：自部署 BYOK，内置网页能力与 MCP 独立

### 4.1 模型与网页配置

自部署默认示例可把模型 key 配为 `user_provided`；用户通过端点旁设置按钮，或 `Settings → Data & Privacy → API keys` 填模型 key。部署者也可在服务环境配置共享 key，这两种模式不同。[官方首次使用指南](https://www.librechat.ai/docs/quick_start/first_chat#give-a-model-an-api-key)

内置 Web Search 包含搜索、抓取和可选重排；环境未设凭据时，用户首次联网会被要求输入对应工具 key，可分别选择供应商。当前文档支持 Tavily 同时搜索和抓取，SearXNG 自部署地址及可选 key，也支持 Keenable 免 key 公共搜索/抓取与可选更高限额 key；重排可关闭。这是内置工具栈，不要求通过 MCP。[官方 Web Search](https://www.librechat.ai/docs/features/web_search)

### 4.2 MCP 用户入口、传输与认证

管理员在 `librechat.yaml` 配服务器；用户可在右侧 `MCP Settings` 添加远程服务器、填写 URL/transport/认证并连接，在 Agent Builder 的 `Add tools → MCP` 选择服务器与具体工具。[官方 MCP 使用指南](https://www.librechat.ai/docs/features/mcp)

支持 stdio、SSE、Streamable HTTP 等传输。当前文档明确 command/args/env 等进程型配置只能由部署者在 YAML 管理；浏览器 UI 用户不能任意创建服务器进程。stdio 子程序运行在 LibreChat 宿主/容器侧，不能理解为自动运行在访问页面的用户电脑。[MCP 配置与进程归属](https://www.librechat.ai/docs/configuration/librechat_yaml/object_structure/mcp_servers)

remote 可用 headers、用户 `customUserVars` 或独立 OAuth；UI 的“User provides key”把工具 key 绑定当前目标，URL/认证边界变化要求重新输入，不能把旧 key 发给新目的地。管理员 YAML 可引用服务端 env；UI 创建配置只解析用户变量。凭据由所访问的 LibreChat 部署处理，不是纯浏览器本地配置。[用户工具凭据与 OAuth](https://www.librechat.ai/docs/features/mcp#credential-variables-for-ui-created-servers)

本次没有审计所有数据库、加密和备份实现；不以“每用户连接”推导“管理员看不到所有秘密”。LibreChat 的公开 demo 是评估实例；本段配置结论针对用户自部署，不承诺 demo 有相同权限或允许所有服务。

## 5. Open WebUI：个人模型 BYOK 与服务端联网配置分开

Open WebUI 的用户个人 Direct Connections 可以使用自己的 OpenAI-compatible 地址和模型 key，须由管理员开启；官方仍标为实验功能，模型请求由浏览器直连，受供应商 CORS 限制。[Direct Connections](https://docs.openwebui.com/features/chat-conversations/direct-connections/)

内建搜索配置则归管理员/服务端。当前源码将 Tavily/Brave key、SearXNG 地址与网页加载器分开保存，配置读取/更新要求管理员身份；普通用户模型 BYOK 不会顺带得到搜索凭据，本次没有找到该内建搜索的普通用户个人 key 表单。[搜索配置源码](https://github.com/open-webui/open-webui/blob/main/backend/open_webui/routers/retrieval.py)。SearXNG 可以配置自部署地址和 JSON 输出，无须使用商业搜索 key；仍需用户自己提供实际可访问的服务，官方站教程注明是社区贡献示例。[SearXNG 配置](https://docs.openwebui.com/features/chat-conversations/web-search/providers/searxng/)

当前 MCP 文档说明，自 v0.6.31 起原生支持 Streamable HTTP，由管理员注册并按用户/组授权；个人 OAuth 授权与服务器注册分开。stdio/SSE 通过 mcpo 转成 OpenAPI；普通用户能否添加 OpenAPI 工具另受 Direct Tool Servers 权限控制。[MCP 接入](https://docs.openwebui.com/features/extensibility/mcp/)

这说明 BYOK 产品没有单一固定做法：可以有内置联网供应商，也可以有 MCP，或者同时保留。BoAI 是本地桌面员工产品，不能直接照搬多人服务端的管理员配置和凭据归宿。

## 6. 对 BoAI 的建议实施范围

### 6.1 首批优先 remote MCP，范围限制到真实只读研究

1. 设置中增加工具连接：名称、`Streamable HTTP URL`、认证方式（无认证/API key header）。OAuth 只在首批选定服务确实需要时一起做；不先实现所有协议和市场。
2. 显式测试连接并列出真实工具 schema；显示“连接正常/缺认证/不可用”，不因为配置已保存就宣称能研究。
3. 在员工详情选择连接和具体工具。系统不默认把连接授给全部员工；新团队显示缺少研究工具，并引导绑定。
4. 首批选定一个提供只读 search/read 的服务，固定可支持的返回格式与映射；MCP 工具名/返回正文并不统一，不能只按名称猜“这是搜索”。
5. 模型判断查什么，宿主执行、限时、限定返回量，保存结果来源；员工继续使用本次原 Work/预算，工具服务费用另行记录可知/未知，不伪装成模型 token 用量。

这是在产品已有 Mastra 任务运行时中增加工具接入的建议，本阶段不修改产品代码。推荐的是 **MCP 客户端**：BoAI 连接用户选定工具；把 BoAI 员工暴露为 MCP Server 是另一方向，无须作为前置。

### 6.2 search/read/引用需要明确的产品合同

- search 返回标题、真实 URL、摘要、提供方和取得时间；如果只有摘要，则引用标明依据为摘要。
- read 使用指定来源，返回实际取得正文、最终 URL、时间和有界内容标识；登录墙/失败/超时显性返回。
- 结果入库生成来源身份，消息或成果的引用指向该身份；不要让模型凭空生成“已经读过”标记。
- 引用显示取得的证据，不证明文中所有推断都正确；来源变更、撤权和清理沿既有材料/记忆/成果协议传播。
- 某个 MCP 只返回无 URL 文本时，可作为普通工具结果，不能承诺提供网页引用。

MCP 官方传输规范定义通信和生命周期；它没有替应用供应商付费，也没有自动构建 BoAI 的引用、成员授权或真实交付闭环。[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)

### 6.3 一个具体的 BYOK 配置示例

用户保留已有模型连接，并单独配置“Tavily 研究工具”：远程 URL 为 `https://mcp.tavily.com/mcp`，使用用户自己的 Tavily key 作为 Authorization Bearer 凭据。Tavily 官方 MCP 提供搜索和正文提取，也提供 OAuth 与本地启动方式；第一版只验证搜索/提取即可。[Tavily 官方配置](https://github.com/tavily-ai/tavily-mcp#remote-mcp-server)

连接后，用户在“研究员”详情选择该连接及实际发现的搜索/提取工具；写作者是否获准调用同一工具另行选择。模型 key 仍发给模型商，Tavily key 发给 Tavily；BoAI 负责调用、来源记录和成果关联。界面可提供填写 key 的服务预设，凭据不需要塞进 URL、员工 instructions 或 workspace。这里是配置建议，尚未执行真实连接测试。

Brave 的官方 MCP 同样要求独立 `BRAVE_API_KEY`，可通过本地进程环境传入，进一步说明 MCP 通道与底层服务凭据分别配置。[Brave 官方 MCP](https://github.com/brave/brave-search-mcp-server#installation)

### 6.4 后续扩展

内置搜索 API 适配可作为面向普通用户的快捷入口，背后使用同一工具连接/员工授权/来源合同；不必要求所有用户理解 MCP。stdio 放到后续明确需要本地程序时实现，单独定义程序身份、启动和实际退出边界。官方云托管搜索若以后提供，应单独标记计费与数据目的地，不混到用户自带工具凭据中。

## 7. BoAI 与 Mastra 的实际接入点

当前 [package.json](../package.json) 安装 `@mastra/core 1.71.0`，没有声明 `@mastra/mcp`。core 附带的 [MCPClient 文档](../node_modules/@mastra/core/dist/docs/references/reference-tools-mcp-client.md)说明 command/args/env、remote URL/requestInit、OAuth 和工具发现等配置；对应线上参考是 [MCPClient](https://mastra.ai/reference/tools/mcp-client)。这证明有框架接入路线，不能证明可选包已经安装、版本兼容或本产品已经支持 MCP；落地前须核对所选 `@mastra/mcp` 的实际版本与类型。

- 模型连接保留现有身份；拟新增工具连接与员工绑定，不改员工 ID 或独立 workspace。[当前领域合同](../src/shared/domain/index.ts)
- 工具凭据扩展现有宿主 [CredentialVault](../src/main/vault.ts)，按工具连接独立存储和引用；不把密钥作为普通配置、模型上下文或成果正文。本轮未实现或审计未来工具凭据的完整路径。
- MCP 发现的工具经过当前员工白名单与宿主执行包装后接入 [task-runtime](../src/runtime/adapters/mastra/task-runtime.ts)；decision、普通 chat 和记忆维护继续沿现有无执行工具边界。配置/验证/撤权/取消仍服从原 Work 与实际执行退出协议，不直接把 SDK 自动重试视为可重放业务。
- Skill 是工作指令与资源，MCP 是实际工具通道；绑定 Skill 不自动生成搜索 key、启动服务或授予某个 MCP。新团队默认无工具授权，创建助手可以建议已存在的工具，实际绑定由用户明确选择。

首次退出条件：用户只配置自己的模型和一个工具服务，即可让指定员工完成一次实际搜索/读取，产出可定位来源的结果；未授权员工拿不到工具，取消/撤权/清理和重启不会自动重放调用。来源引用是 BoAI 的产品层职责，不能作为接入 MCP 后自动获得的能力。
