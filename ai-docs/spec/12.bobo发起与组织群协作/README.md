# bobo 发起与组织群协作

更新：2026-10-02。状态：**待实施规格；本次只添加文档，未开发或验收本组功能。**

## 1. 用户确认的主线

> 你找 bobo 讨论需求 → bobo 分析需要哪些员工 → 找到已有员工或创建新员工 → 拉群 → 在群里说明目标、安排分工 → 员工之间交流、配合和交付。

员工 Agent 始终是类似 IM 中的人的独立联系人，拥有自己的身份、配置、workspace 和获准记忆。私聊、群聊、接受工作安排都只是员工参与交流与工作的方式，不决定员工地位，也不使员工归属于 bobo。

群聊只组织参与者。bobo 是更了解用户的关键助手，未来帮助用户找人、补齐缺少的员工并组织一次群协作；群内员工以各自身份沟通和做事。

用户有三条并存的入口：直接找员工、直接在群聊处理事情、先与 bobo 讨论后发起群协作。本组只补第三条入口，复用前两条已有能力。

## 2. 首批固定的产品决定

| 问题 | 本组决定 |
| --- | --- |
| 原 bobo 会话如何处理 | 持续保存原 Conversation 和记录；发起协作不会自动删除、关闭、归档、改为群或迁移历史 |
| 实际协作在哪里 | 首批创建独立普通群，bobo 和选定员工参与；用户依旧按现有本人身份进入群 |
| bobo 在群里做什么 | 以自己的身份说明本次目标、提出分工、参与沟通和跟进；其他成员仍可独立判断和配合 |
| 员工如何选择 | 先匹配已保存且可参与的员工，只为确实缺少的职责创建新员工；明确只要求创建员工时走独立创建支路，不拉群或开工 |
| 用户如何进入 | bobo 原会话显示真实群和员工入口；群正常出现在会话列表，成员可直接私聊 |
| 什么时候执行 | 普通讨论只讨论；用户明确要求组织或处理后，宿主受理对应操作。仅建员工/建群不等于已开始业务工作 |
| 历史和材料如何分享 | 使用本次获准目标摘要和明确材料；不整段复制 bobo 私聊，也不自动开放员工私聊或 workspace |
| 什么时候结束 | 组织操作、群中工作和 Conversation 分别保存状态；工作完成不自动删除会话、移除或删除员工 |
| 已有群如何复用 | BC5 条件扩展，仅按用户明确指向的群身份复用；首批不根据名称或文本相似度自行复用 |

“群内安排工作”是产品行为。已有 `WorkRepository`、`delegate_work` 等是实现群中任务的技术机制；本组不把员工包装成 bobo 私有的后台临时角色，不建立第二套隐藏员工。

## 3. 当前事实与本组新增

| 当前已有基础 | 本组仍需实现 |
| --- | --- |
| 独立员工、普通单聊和群聊、受管工作区与统一记忆 | bobo 分析所需职责并有界查找已有员工 |
| bobo 核心身份、独立核心 Conversation、模型配置及会话历史 | 只补齐缺少员工，并把已有/新员工组织进协作群 |
| 第 9 组 `create_team`：创建新员工、默认群和标签，原子发布及回执 | bobo 作为发起群的成员，发出真实目标消息，接通群内分工与交付 |
| 同会话员工协作、工作记录、预算、结果依赖与取消机制 | 原 bobo 讨论到独立群的来源关联、受理、恢复及导航 |

目前普通群不接纳 bobo，核心会话也不能改成多员工；这是本组实施时必须明确调整的产品约束。此次文档更新保持现有运行规则，不能仅凭新规格声称代码已经支持。

## 6. 首批完成时应当看见什么

用户在 bobo 会话明确要求组织写作：宿主找到已有研究员，补齐缺少的写作员工，建立包含 bobo 和这些员工的群；bobo 在群中说明目标并安排工作，员工交流、执行并交付可检查成果。用户能进入群、私聊任一员工，并在重启后继续打开原 bobo 会话和该群。

任何一环只得到模型描述、假入口或无法核对的结果，都不能把这条流程记为完成。
