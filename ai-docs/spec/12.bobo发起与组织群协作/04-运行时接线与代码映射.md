## 2. 需求判断与工具边界

原 core 普通讨论沿 chat，只有 Message，不创建 Work/员工/群。宿主在工作认领前将本次意图固定为 `Work.organization={requestId,mode,goal}`，组织 Work 只交付员工/组织对象，群业务根承担实际事情。不能先认领完整业务 main 再通过工具搬到群。

`find_employees` 输入 `{search?,cursor?,limit?}`，每页最多20；只读取保存的、启用的、非核心、非 ACP、API连接/模型可用或已验证本机Codex启动项、且不在清理中的员工。返回精确 ID/configVersion 和能力配置事实，不证明绑定技能的外部依赖已验证。

`organize_collaboration` 只接收方案成员/群名/公告；模式、原用户消息、Work/run/配置版本、真实 model/toolCall、request/budget 由宿主提供。普通员工、普通群中的 bobo、chat/decision/memory/report 和自动化没有组织修改工具。

新员工沿 bobo 的实际运行方式与模型；API路径的Mastra浏览器默认可用，兼容配置为 `allowBrowser=true/allowCommands=false/skillIds=[]/knowledgeIds=[]`；本机Codex继承已验证profile，API连接为空且浏览器能力不冒充已接入；已有 false/缺失浏览器字段同样可用，无单独开关。已有员工保留自己的 ID、模型、绑定、根工作区和记忆。

## 3. 三模式的发布对象

| 原 Work 模式 | 新员工 | 独立群+bobo公告 | 群根+启动意图 |
| --- | --- | --- | --- |
| employee_creation | 需要至少一个 | 无 | 无 |
| organize_only | 仅缺员，可为0 | 有 | 无 |
| organize_and_execute | 仅缺员，可为0 | 有 | 同发布事务，绑定原预算 |

群最多12 Agent，计入真实 bobo；用户仍以本人身份交流，不加入 agentIds。所有旧员工复用同一身份；普通手动新群不能添加 bobo，只有受控发布的原协作群后续保存可保留它。

## 4. 发布与真实开场

短 SQLite 事务冻结稳定 request/规范 hash、对象 ID、现员版本及连接指纹、新员工、群与实际公告。长文件处理在 critical 外执行，每文件写入状态在事务保存；完整目录/hash 核对后进入宿主 critical。

最终同事务写入新员工、群、真实 agent/bobo 公告，再调用预算 binder 核实际对象并登记唯一群根/启动意图，提交组织终态、通讯录和阅读完成身份。任一步失败全部回滚；不对外暴露部分员工或半个群。

群目录保留原团队文件机制的 `.team-creation.json` 归属标记供核对、恢复和清理使用。它不属于业务成果，活动列表和启动历史登记均排除该保留文件，不能把内部日志登记到成果 SQL 或检索正文索引。

公告来自实际 bobo 模型工具输入，保存 collaborationSource={operationId,sourceRunId,modelCallId?,toolCallId}。**不把 core runId 放到群消息，不伪造未发生的 group run/turn，不伪造本人 user 消息。** 阅读验证直接读取同事务新群和 committed operation，不依赖提交前尚未安装的内存群。

GroupScheduler 只在已提交启动意图下建立真实事件/轮次并唯一消费；普通群背景保存、打开入口、查看成员都不能再次开工。群内员工各自署名、承担自己的同群 Work/依赖和成果；SDK 实例的创建/释放不改变通讯录员工身份。

## 5. API 与公共投影

| API | 输入 | 返回/副作用 |
| --- | --- | --- |
| listBoboCollaborationOperations | {conversationId} | 最多30条原 core 公共 receipt，只读 |
| getBoboCollaborationOperation | {operationId} | 原 receipt+真实 startStatus，只读 |
| resumeBoboCollaboration | {operationId,expectedVersion} | 原文件审计→原 Work 新 holder→复用冻结日志发布；不调用模型重新规划 |
| abandonBoboCollaboration | {operationId,expectedVersion} | 保存取消 gate、等待实际文件退出、仅清本次 hash-owned 未发布树 |
| resumeBoboCollaborationStart | {operationId,expectedVersion} | 只消费已发布群的原启动意图，不复制预算/重发公告 |

内部 BoboCollaborationService 的 organize(plan,authority,provenance,signal?) 返回真实 receipt；auditOperation 是宿主恢复事务的只读内部接口，不进入 IPC；resume 接受原 Work 新 authority 和取消 signal。公共回执不含私人规则、文件路径或完整 source 内容。

## 6. 恢复、来源与实际退出

重启 recover 只审计归属/hash，未结束组织标 interrupted/needs_attention，不移动文件、不调用模型或自动发布。显式恢复复用原 ready hash，只有原 manifest 未完成文件或已记录写入前缀可以继续；未知外改保留。

恢复当前执行权与公告原生成来源分开，新的恢复 run 不冒充旧模型输出。宿主 validateSource 在受理/claim/resume/最终发布同事务核真实 sourceRun/snapshot、原材料禁入、记忆忘记/失效/expiry；来源失效阻止未发布旧方案。

取消先保存 gate，再 abort/wait 实际文件任务，之后清理本次所有权/hash 匹配文件；已 committed 对象保留。宿主已经持有 critical 的历史清理使用 criticalHeld 标记，不递归认领同一锁；尚有实际运行文件时显性拒绝，不能等候自身排队造成死锁。

首批 core 输入含私有材料时拒绝组织。新群材料须用户在该群独立提供并授权；不把 core MaterialReadRef、私聊、员工根 workspace 或私人记忆复制进新群。

清空/删除原 core 留最小去重、已提交群公告证明和仍被群引用的原预算累计/期限；群/员工保持独立。解散群只沿既有群清理，不删除成员根工作区。未结束组织与备份互斥。
