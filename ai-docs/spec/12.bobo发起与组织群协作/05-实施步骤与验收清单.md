## 2. BC0：冻结现状和规则变更

1. 阅读 [01](./01-产品定位与范围.md)、[03](./03-会话成员与协作合同.md)、[04](./04-运行时接线与代码映射.md)，记录实际源码版本和待改入口。
2. 核对现有第 9 组团队创建、员工记忆、群内工作、材料和成果的真实合同与已验收范围。
3. 明确：核心 Conversation 保持原身份和单独分组；新协作群允许 bobo 成为成员；核心管理权限仍按身份、来源和执行阶段核验。
4. 固定组织请求到群中首次工作受理的合同：一个稳定协作请求、一个共享预算/绝对期限、源组织 Work 和群内唯一业务根两个阶段；不移动旧 Work、不设跨会话父子、不伪造用户发言、不复制预算。
5. 在工作认领前声明源阶段仅交付组织结果；已有 core Work 正在执行完整业务时不能用建群工具暗改范围或迁移到群，沿 03 拒绝隐式转换。
6. 明确用户提出讨论、仅创建对象、组织并完成事情的不同意图。确定性路由、校验、提交和重试由代码负责。

验收：形成源码差异清单和首批测试范围；普通员工单聊、普通群、旧团队创建及核心会话没有被提前重定义。实施中涉及运行规则改变时，再同步 AGENTS、对应 Header/地图和旧专题合同。

## 3. BC1：需求分析与找人

1. 为 bobo 提供有界、可核对的通讯录摘要；先过滤已保存、可用且支持本次能力的员工，再交给模型匹配职责。
2. 给出选中员工的真实身份及选择理由；没有对应职责时，说明需要补齐的员工，而不是为每个需求重新造人。
3. 模型负责理解需求和匹配，宿主负责员工身份、配置版本、可用状态和权限校验；匹配输出不能自行保存联系人。
4. 保留普通讨论路径和后续修改意见；未明确要求组织时，不创建员工、群或业务 Work。

验收：已有合适员工被复用；改名、同名和多标签不导致身份混淆；停用/删除或不支持参与的员工不能被受理；候选输入不含私聊全文、密钥或任意 workspace 内容。

## 4. BC2：补齐缺员与发布独立群

1. 按 [03](./03-会话成员与协作合同.md)冻结原请求、已有员工及配置版本、确实缺少的员工、群身份和必要背景。
   用户明确只创建员工时，使用独立员工创建操作沿原 core Work/预算冻结身份，只发布员工与回执，不制造群、群首条消息或启动意图。
2. 复用既有团队文件准备/所有权/hash/发布机制，只为新员工准备其受管资源；不得复制或重建已选员工的身份与根空间。
3. 一次受控发布新增员工和独立群，保留可核对回执；群包含 bobo 和明确选中员工，用户仍沿本人身份参与。
4. 在原 bobo 会话展示真实群和员工入口，正常列表可进入；保留原会话身份、标题、记录和草稿，不自动导航、关闭、转换或归档。
5. 未知结果保留原请求/key，只读核对；不要因刷新、重启或再次打开页面而重建员工/群。

BC2 可先验收 `organize_only` 和只创建员工的支路。`organize_and_execute` 必须等 BC3 的共享预算绑定、真实群根与启动意图一起接通后才开放，不能创建一个未登记账本的可执行半成品。

验收：全用旧员工、旧员工与缺员混合、全部缺员三类均正确；任一校验/准备失败不暴露半套联系人或假群；重复受理返回原对象；打开/关闭讨论页面不影响已提交群对象。

## 5. BC3：群内说明目标、分工与交付

1. 接通 bobo 在发起群中的普通成员身份、上下文和工作区；成员可见自己的能力与获准材料，不获得核心管理工具。
2. 宿主沿稳定来源受理首次群目标和接续意图；仅明确安排实际处理时开工，群背景编辑、联系人创建和群配置保存不启动工作。
3. bobo 使用自己的身份发表目标与分工；成员按各自身份判断、回复、提问、执行和交付，复用现有群协作机制。
4. 新增宿主事务授权把群内唯一业务根绑定原协作请求的 `budgetId`；源组织 Work 不迁移，不与群根建立跨会话父子。群根与启动意图和发布同事务，组织调用与群判断/执行/分工共用累计额度、未知用量和绝对期限；现有默认 `claim` 不能直接代替这一新入口。
5. 需要用户补充时在群里保留明确问题；用户可直接参与群聊或私聊员工。员工私聊不自动修改另一群中的工作。
6. 成果由实际完成员工发布并保留具体身份、文件/版本/hash；bobo 汇总沿真实证据，不把文字承诺、Span 结束或模型运行成功记为交付。

验收：至少两名员工完成有依赖的真实任务；群中可见各自交流和成果；用户直接介入后继续原工作；bobo 和成员的 workspace、记忆、权限没有合并；同一群目标没有被初始化消息重复触发。

## 6. BC4：恢复清理与完整验收

1. 覆盖发布前停止、发布后停止业务、结果未知、配置变化和执行器退出；取消不重放工具，资源占用直到实际退出。
2. 重启和备份恢复只核对已提交对象、回执和成果；没有显式续行就不重新调用模型或发起工作。
3. 分别验证用户清理 bobo 会话、清空群、解散群、删除普通员工的既有生命周期；会话之间的链接失效不级联删除另一对象。
4. 材料撤权、员工退出、成果外改/缺失使旧来源失效；不能在 bobo 摘要或群上下文里继续使用过期正文。
5. 完成模块、Electron BDD、应用包及受控真实模型场景；分别记录业务证据和人工质量评价。

验收：原 bobo 会话在群创建、业务完成、失败和重启后仍可打开；解散群不删除员工；员工在其他正常会话的身份与可用性遵循既有删除合同；重复/未知请求不复活已清理对象。

## 7. BC5：已有群复用，后续按需

仅在用户明确指向某个已有群后实施。原子核对该群身份、成员版本、bobo 加入资格、背景和材料范围；新的实际请求保留独立身份，旧群的其他工作不被接管或停止。不以群名相似、话题相似或同一批员工推断目标。

首批仅创建独立新群；不得提前在界面展示尚不能执行的“智能复用全部群”能力。本片完成另记证据，不回写为 BC0–BC4 首批已覆盖。
