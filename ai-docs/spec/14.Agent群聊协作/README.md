本组解决普通群聊中的共同目标与接续问题：用户说“大家开始报数”，员工应当理解共同约定，按前置结果接续，最终形成连续结果。现场出现的四个“1”和一个“4”表明，消息可见和多人回复还不足以构成可靠协作。

## 1. 产品目标

Agent 始终是独立员工，具有自己的身份、配置、记忆、工具权限和运行记录。群负责组织共同目标与交流；宿主维护进度、依赖和执行资格，每名员工只产生自己的回复和成果。

| 本轮关系 | 用户例子 | 目标行为 |
| --- | --- | --- |
| 独立参与 | 大家各介绍一下自己 | 成员独立判断，可并行回复或合理沉默 |
| 依次接续 | 依次报数、接龙、每人修改上一人的一句话 | 前一步完整提交后，下一位才基于实际结果生成 |
| 任务分工 | 调研后写稿，再审核修改 | 原Work持久委派、成果版本依赖、负责人接续与交付 |

这些是每次请求的协作语义，不是要求用户设置的三种群类型。报数是暴露缺口的最小例子；验收同时覆盖接龙和真实文件工作，避免只对报数做专用修补。

## 4. 本轮约束

1. 不引入MQ、Redis、新的Agent框架或第二套消息数据库作为前置。
2. 不把所有群聊改成串行，不通过显示顺序伪装执行依赖。
3. 不按“报数”等关键词硬编码路由或替员工生成数字；顺序能力必须能处理新内容接龙。
4. 不以无限轮询、扩大预算或全员反复判断弥补协作协议缺失。
5. 不把运行完成、目标达成、模型自评和人工认可合为一个结论。
6. 旧协议仍约束当前运行；拟调整条款见02第6节，实际接线时同步权威规则与原专题。
