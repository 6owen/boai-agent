**退出条件：**权限显示和重启后的已提交配置一致；最新改版相关业务断言通过，剩余全量回归失败如实分类。D0 中 bobo 证据继续更新第 9 组 08，本表仅回链，不复制完成状态。

## 3. D1：TXT/Markdown 聊天附件

1. 首批仅在已有私聊/群聊开放附件，定义受管身份、导入状态、解析内容与消息关联；不改变空白 bobo 首发受理。
2. 宿主准备文件、校验类型/大小与文本，返回可审阅的就绪/失败状态。
3. 接线选择/拖入、移除、来源预览和共享范围；失败保留草稿，不静默漏掉材料。
4. 带附件发送经事务提交消息与关联，再投影获准内容到对应员工。
5. 补齐重启核对、暂存清理、会话清空、来源撤权、备份往返及旧文本消息兼容。

**退出条件：**两份同名材料身份不混淆、模型获得正确获准内容；失败附件不会在用户不知情时被遗漏；准备/预览不制造 Work。

## 4. D2：成果预览、修订与采用

1. 复用 Artifact 发布身份，扩展独立的成果内容关系；Work.resultVersion 保持工作结果/依赖语义。
2. 实现有界 Markdown 预览与来源/版本选择，复用页面自己的详情标签。
3. 用户针对当前所见版本提交修订；消息与关系原子保存，明确新工作和预算归属。
4. 新版独立发布、旧版保留，审核针对实际字节；迟到结果不能替换正在看的版本。
5. 采用经宿主核对内容并事务提交，返回幂等回执；打开/导出不自动采用。

**退出条件：**用户可预览 V1、针对 V1 修改得到 V2、采用确定 V2；V1 与历史审核/采用不被改写。预览过期或文件外部修改时不能确认未看到的内容。

## 5. D3：第一个完整交付版本

使用隔离数据与真实两份 TXT/Markdown 资料，固定任务、配置、预算和质量要求：

1. 在聊天交材料，员工提炼事实并生成带来源的报告。
2. 根据任务要求核对实际发布版本；需要审核的场景保存可检查证据。
3. 用户在应用内查看，提交一个针对具体版本的修改要求。
4. 新版保留原版关系，用户采用新版。
5. 切换主页面/会话及重启后，从原消息找到原材料、新旧成果与采用记录。
6. 验证停止、撤权、清空、备份恢复；恢复不自动运行模型、重发通知或重放工具。

**退出条件：**整条链路在已登记预算内完成，成果满足内容要求且实际存在。模块、桌面流程、真实质量及用户采用分别留证；未取得人工质量结论时保持对应项待评审，不凭离线 fixture 宣称质量稳定。
