## 当前图片与文件附件范围（2026-10-02）

附件就是当前聊天消息的一部分：私聊发给对方，群聊发给群成员，草稿和已发送消息都不展示“共享给”或员工勾选，不让用户逐个指定接收者。新成员可按本群历史读取规则看到历史附件，离群后不可再读；停用员工不阻塞附件准备/发送。新记录使用 `deliveryScope=conversation`，首次成员记录不是固定访问名单；旧缺省记录保留历史限制，不批量放宽。

已有私聊、bobo 会话与群聊的 composer 支持截图/图片 File 的复制粘贴、系统复制文件的粘贴、文件拖入和原生文件选择。普通文本和网页文本仍按文字粘贴，不把复制的路径字符串当文件。群聊编辑器先接收文件，避免富文本编辑器吞掉拖入事件。

图片草稿以缩略图横向排列在 composer 内部、位于文字输入上方；准备期就使用同一固定尺寸缩略图区域，不先闪通用文件卡或“请等待材料就绪”，读取完成只填充图片，不重复改变高度；悬停或键盘聚焦时右上角出现小型删除按钮，删除保留文字草稿。点击草稿或原消息的图片打开全屏深色 Dialog，以原比例展示，Esc/右上关闭/点击遮罩关闭并恢复焦点；图片不再显示外置文件横条和常驻容量说明。普通文件显示文件名、大小和卡片，TXT/Markdown 可查看原文。流式回复只后台核对图片来源，不反复清空同版本缩略图。原发送按钮继续发送消息和就绪附件，不引入新的任务模式或停止入口。

- 图片/通用文件每份最多 20 MiB，每条最多 3 份，空正文加就绪附件允许发送。文本仍沿 128 KiB / 16,000 字符单份与 32,000 字符合计；二进制不计入文本字符额度。
- 图片类型依据原件字节，支持 PNG/JPEG/GIF/WebP/BMP/AVIF 静态预览；SVG/HTML 作为通用文件，不执行内容。损坏图片不会伪造成功显示。
- 前端不按模型是否支持视觉筛选附件。宿主核对原件/hash/当前聊天成员后，把真实图片作为原生图片部件传给模型；实际模型无法理解或接口拒绝就按原错误链反馈，不捏造图片内容。
- PDF/Office/任意二进制可作为文件保存和展示，本次未增加正文解析、OCR或页码。模型只收到真实文件元信息，不能把元信息当已读取正文。
- 沿原稳定准备/发送请求、当前聊天范围与来源链、清理与备份。无本机路径的 File 先写宿主私有临时来源，准备实际退出后清理；data URI只用于内存预览/模型输入，不写持久消息或Trace。
- 空白 bobo 首发仍先提交工作目标，再在已有会话添加附件；外部 ACP 附件合同未扩展。

下面“首批”保留 TXT/Markdown 的原交付范围；当前文件接收范围以上述增量为准，PDF 正文解析继续单独实施。

## 用户交互

1. 在当前聊天输入框加号选择“添加文件”，或将 TXT / MD 拖入明确落点。
2. 文件条显示文件名、类型、大小与状态；不展示本机完整路径。
3. 宿主导入与解析后，用户可查看真实文本、移除文件或检查失败原因。
4. 附件跟正文一起发到当前聊天；输入区和消息不提供共享成员设置。加入本群后可读取本群历史附件，离群后不可再读。
5. 点击发送时，正文和所有就绪材料关联一并提交；正文可为空，但必须至少有一份就绪材料。
6. 已发送材料保留在原消息里，点击打开本会话自己的详情标签和来源位置。

含导入中、解析中、失败或不支持文件时阻止发送，用户可重试或移除。不能忽略失败文件后启动任务，也不能因为一份文件失败丢掉其余草稿。

切换聊天保留各自草稿与归属；取消选择、空白输入或仅选择材料不创建 Conversation / Work。空白 bobo compose 只有扩展并验证现有原子首发合同后才能开放材料发送，不能绕过正文/具名团队请求互斥规则。

发送回执未知时先按原请求身份查询核对；用户重试沿用同一身份与载荷，不重新创建消息或再次触发工作。

## 状态与失败行为

| 状态 | 可确定的含义 | 用户操作 |
| --- | --- | --- |
| 草稿 | 已选择，未成为已发送材料 | 导入、移除 |
| 导入中 / 解析中 | 正在准备受管原件或派生文本 | 等待、取消；禁止发送 |
| 就绪 | 原件与解析版本已校验，可交给获准处理链 | 预览、发送 |
| 不支持 | 类型、编码或执行对象能力不满足 | 换格式、换对象或移除 |
| 失败 | 文件损坏、超限、无权限或本地处理故障 | 查看原因、明确重试或移除 |
| 不可用 | 来源清理、撤权、丢失或内容校验失效 | 显示原因；禁止继续读取 |

“就绪”不等于员工已经阅读；阅读与引用必须来自真实执行。取消先禁止后续提交，待文件处理器实际退出后清理本次暂存；迟到结果不能复活已取消草稿。

## 宿主、数据与授权边界

- Renderer 负责操作和展示；通过现有桌面通信提交原生选择/拖入授权，不接受任意绝对路径作为读取授权。
- 每份材料至少记录稳定 ID、所属聊天或草稿、原件校验值、受管引用、类型/大小、解析版本、状态和导入请求身份。名称相同不合并，读取范围由所属聊天决定，不因内容相同跨聊天读取。
- 首批按明确支持的文本编码读取；二进制伪装、解码失败及超限显式拒绝。合法空文件展示“无可供处理的文本”，不宣称员工已获取内容。
- 解析保存确定片段位置与原件内容校验；模型每次获得的是获准内容和稳定来源引用。文件变动或授权改变后，旧缓存不能通过校验。
- 发送事务复核归属、就绪状态、当前聊天及请求载荷，新附件不逐个校验首次成员名单；消息、材料关联、必要轮次/投递记录同事务提交，提交后才调度。
- 文件系统与 SQLite 分开处理：先受管暂存与登记，再受理消息；失败和中断以持久记录核对并清理，不能伪装成跨介质原子事务。
- 上传不自动成为员工长期知识，也不自动授予全部员工访问；沿用本会话明确范围，后续知识化另行操作。
- 原件和解析文本放宿主专用受管位置，不能直接放入员工工具可读的群共享工作区。授权检查必须覆盖消息、工具文件读取、成果来源和员工记忆投影，不能只过滤模型提示中的附件正文。
- 材料及派生摘要/回复保留材料来源和本聊天范围；默认员工跨聊天召回不能带走这些内容。每次初始/后续模型调用、工具执行和发布复核实际材料版本及授权，撤权后的旧快照不能继续。
- 外部 ACP 未有专门材料能力合同时显示不支持，不自动复制原件、正文或派生内容到外部工作目录。
- 普通聊天仍不因附件创建 Work；员工判断为任务时沿原用户请求和既有工作预算执行。材料读取后的模型步骤继续计入所属工作账本。

## 来源与后续文本 PDF

TXT / MD 引用采用材料 ID、解析版本、稳定片段位置与可展示文件名；不编造页码。点击引用复核权限，回到正确材料与文本片段。

模型没有实际取得的片段不能显示为已核对引用。找不到原片段时保留明确的“来源无法核对”状态，不能凭相似文本自动替换来源。

文本 PDF 是后续独立切片：验证实际打包环境中的本地解析依赖、普通文本/空白页/损坏/加密/扫描样本，再保留页码与片段映射。没有可提取文本时显示不支持该内容，不以空文本算成功；不混入首批 TXT / MD 完成声明。

## 清理、备份与迁移

草稿在切换聊天时保留；重启不恢复未发送草稿，先在事务中撤权并失效，再按 hash 清理原件，旧准备请求不能重造；外部修改保留且不可再作为有效草稿。处理临时文件有确定回收策略；清理仅限本次拥有的受管文件。清空聊天先失效读取和引用，再处理原件、解析文本、来源映射与预览/搜索缓存，失败沿用持久清理记录。

材料作为记忆或成果来源时保留来源链，撤权/清理须使派生读取失效；不得用旧快照绕过员工记忆屏障。外部修改文件只在 hash 匹配且属于受管投影时清理，保留并显性化用户改动。

备份包含已发送材料、当前聊天范围/旧记录限制和必要解析版本，不包含暂存中间文件或外部凭据。恢复后重新核对受管路径、原件与解析版本，可有界重建纯本地派生内容；不重跑模型任务、不重发通知。

旧纯文本消息保持原样，附件关联缺省为空。迁移须可重复启动且失败保留旧数据，不从正文中的路径猜测历史材料或授权。
