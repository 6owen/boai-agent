## 2. 首批范围

1. 员工技能选择中增加“从本机技能选择”，沿用现有搜索与技能详情。
2. 展示所选技能的实际来源/版本、准备的受管副本和目标员工。
3. 用户提交后，经宿主准备并登记员工可授权 Resource，再保存明确绑定。
4. 显示说明可读、资料未共享、命令未启用、依赖未验证或检查失败；提供相应配置入口。
5. 从一次真实任务验证指定员工可读取获准技能，其他员工没有自动获得权限。

首批目标限于已经保存的员工，每次选择一个技能。新员工先完成现有创建流程；员工配置有未保存修改时先保存，避免把尚未提交的配置混入绑定。准备冻结实际来源身份、内容 hash、目标员工与配置版本；受管 Resource、安装来源、员工绑定/新配置版本和结果回执同 SQLite 事务提交。

首批不自动安装依赖、不将本机目录直接映射为任意员工可读工作区，也不因为技能文字提到浏览器/网络而宣称已接通工具。

## 3. 用户流程

员工配置→添加技能→选择本机条目→查看来源与准备说明→提交→显示已绑定及实际能力状态。

准备或保存失败保留选择与错误；列表不得先显示成功再等待宿主补登记。同名技能显示来源差异，不能按名称合并身份或覆盖旧副本。

团队创建成功可增加“准备第一项工作”入口，打开群聊并填入可编辑示例任务；由用户发送。能力摘要仅在配置、任务准备或用户查看详情时展示，不增加输入框上方的常驻状态条。

这一步复用现有 bobo 极简创建与默认群，不恢复模型/模板/方案表单；群背景及任务草稿不自动创建消息或 Work。

## 4. 身份、文件与授权

| 对象 | 职责 | 首批规则 |
| --- | --- | --- |
| 本机 local 技能 | 发现、安装、收藏与远程来源 | 不因被发现/安装而取得员工权限 |
| 员工 Resource | 获准受管内容与运行引用 | 复用既有校验、版本与授权，明确副本来源 |
| 员工绑定 | 指定员工可使用哪个 Resource | 宿主校验后持久提交，不靠 Renderer 列表推断 |
| 验证回执 | 对确定配置的实际能力检查 | 配置/版本改变后旧回执不代表当前可用 |

技术选择实施前核对现有导入协议：可复用已登记且内容/来源一致的 Resource；新增时按稳定请求身份准备受管副本，返回可核对回执。禁止按名称或相似文本跨来源复用。

文件准备与绑定采用现有暂存/登记/失败清理机制；响应丢失先核对原请求，不重新导入。失败不留下 UI 可用却无文件的半绑定；清理仅操作本次拥有且 hash 匹配的受管文件。

本机技能后续更新不静默改变正在运行员工的副本。使用既有版本检查、活动/等待工作与执行退出保护；撤权后旧快照不能启动调用、工具或发布。

沿用当前授权模型：技能绑定属于员工，在该员工获准参与的聊天中使用，不新增 `sharedSkillIds` 或第二层群技能开关。“资料未共享”专指知识绑定与 `Conversation.sharedKnowledgeIds` 的既有交集；技能安装或收藏本身不会给其他员工增加绑定。

## 5. 能力状态

| 显示状态 | 依据 | 用户可执行的下一步 |
| --- | --- | --- |
| 说明可读 | 当前受管文件和说明校验通过 | 查看说明、用于获准任务 |
| 资料未共享 | 员工绑定与群共享交集不足 | 进入正确员工/群配置 |
| 命令未启用 | 已提交命令权限禁止执行 | 查看权限并明确配置 |
| 依赖未验证 | 没有当前版本的可信执行检查 | 查看所需依赖；显式发起受控检查 |
| 检查失败/版本已变化 | 实际回执失败或配置不再匹配 | 查看原因并修正；旧成功不覆盖新失败 |

仅打开页面/扫描/保存配置不执行外部程序。需要启动程序的验证作为明确动作，经过现有权限、审批、预算/取消和实际退出边界。不能用未执行的推断产生成功回执。
