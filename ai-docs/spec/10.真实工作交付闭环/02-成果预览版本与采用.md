# 成果预览、版本与采用

状态：**待实施 / 待验收**。基线核对日期：2026-10-01。优先级：P0。

目标：用户在应用内检查一份 Markdown 报告，针对明确版本修改一处，再采用新版；原版、来源和采用记录在重启后仍可检查。

## 首批最小范围

- 应用内 Markdown 预览，显示真实作者、发布时间、源消息/工作与内容可用状态。
- 明确成果身份、不可混淆的版本及内容校验；历史版本可切换，原版可检查。
- 围绕指定版本提交用户修订新请求，新版显式关联前版。
- “采用此版本”持久、幂等，并能准确显示当前采用版本及历史记录。

图片、PDF 预览、文本差异、导出增强和在线编辑器分别安排后续切片。首批保留已有外部打开能力，不以外部打开算应用内预览，也不因未做差异视图阻塞版本正确性。

## 预览交互

1. 用户点击消息或“任务与产物”中的已发布 Markdown 文件，打开当前主页面自己的详情标签。
2. 标题显示名称和明确版本；元信息显示作者、发布时间、源消息/工作入口以及本版审核状态。
3. 正文呈现宿主校验后的真实内容；存在材料引用时复用材料 ID/解析版本定位，不用文件名猜来源。
4. “版本”入口展示明确前版、新版和当前采用记录；没有版本链的旧成果正常显示为独立成果。
5. 当前版底部提供“要求修改”“采用此版本”；外部打开、阅读和复制不触发采用。

同一成果复用对应详情标签；切换主页面遵循既有详情作用域。收到新版只提示“有新版本”，不能替换用户正在审阅的旧版，也不能自动改变当前采用对象。

预览不执行任务或工具；Markdown 继续禁原始 HTML、远程图片和隐式外链。格式不支持、文件丢失、撤权或内容被外部修改时明确显示原因，不展示旧缓存冒充当前原件。

## 内容版本与审核合同

| 概念 | 必须表达 | 禁止推断 |
| --- | --- | --- |
| 发布 Artifact | 一次真实已发布文件与作者/run/源消息 | 发布成功等于用户采用 |
| 成果身份与修订关系 | 明确前版、当前版本身份、所属逻辑成果 | 同名、相似文本或更新时间属于同一链 |
| 内容身份 | 发布时保存的 hash 或等价不可变校验，证明所见内容 | 路径和大小足以证明同一内容 |
| 本版审核 | 审核者、确定内容身份、结论、来源和证据 | 上一版审核自动适用于新版 |
| 用户采用 | 用户在明确时间选择的确定内容版本 | 已读、运行完成或员工声明交付自动采用 |

每次发布建立独立内容身份；前版关系必须由宿主获准的修订关联给出，模型不能仅凭文本声称“这是第 2 版”建立关系。

`Work.resultVersion` 继续表示工作结果版本和依赖条件；成果版本只解释文件修订。一个工作发布多个成果或成果有多个修订时，不以两种版本数字相等作为关联依据。

审核必须匹配本版内容身份；无真实证据显示“未记录本版审核”。修改一个字符、外部修改或重新发布后都不能继承旧审核，首批不为补审核自动运行员工。

## 用户修订是新的显式请求

1. 用户在某版点“要求修改”，表单固定显示被修改版本和内容身份，并允许填写修改要求。
2. 默认显示原作者；原作者已移除、停用或不可执行时，由用户明确另选，不暗中改派。
3. 提交携带原版、要求、目标员工、稳定请求身份和预期状态；用户消息与修订关联同事务保存，提交后才调度。
4. 以这条新用户请求进入既有 task 判断与受理流程，并记录明确来源，不重用原运行作为工具重放入口。
5. 新版发布时保存前版关系和真实内容；发送回执未知先核对同一请求，新版发布失败不得留下虚假的可用版本。

原工作已交付结果与原版文件保持其历史事实；修改要求和采用均不回写原交付结果、不重置原预算、不复活人工停止工作。

实施时落实新请求的工作/预算归属：修订任务使用新用户请求的稳定工作身份和现有预算政策，原成果仅作显式来源。原成果来自自动化时，不继承原 occurrence、不隐式解除原等待或追加其额度；用户明确关联自动化补充时仍走原补充合同。

修订可读取获准原版和相关材料，不自动获得全部原任务工具权限；原作者不可用、来源撤权或已有结果不明的外部操作时显式反馈。简单文字修订不自动重跑全部原工具。

## 幂等采用与提交一致性

采用请求至少携带成果 ID、明确版本、所见内容校验、期望状态和稳定请求身份；用户身份使用固定本人身份，不按自动化来源判断。

宿主复核会话权限、版本存在和内容一致性，读取并校验的对象必须与预览声明一致。已外部修改或失效时拒绝陈旧采用，用户重新打开可核对内容后再操作。

SQLite 事务保存采用事件、明确当前采用指向和请求回执；成功提交后才更新界面与待处理投影。响应未知只按原身份核对，不再次制造事件。相同身份不同载荷拒绝，重复点击同版返回原已提交结果。

后续明确采用另一版时保留历史事件，当前采用指向新选择；采用旧版仍按用户选择保存并提示已有新版。新版发布不自动迁移采用记录，首批不提供含糊的撤回开关。

采用只记录用户对本版成果的选择，不触发外部发布、发送消息、部署或重新执行任务；这些业务动作仍需各自明确授权和回执。

## 清理、备份与旧数据

成果、版本关系、审核、修订关联与采用记录随所属会话和成果边界清理；先阻止后续读取/采用，再沿持久文件清理记录处理。只保留现有必要去重身份，不保留能重建被清理正文的缓存或引用。

文件清理沿受管目录和 hash 校验处理；不跟随外部路径，不覆盖/删除用户外部修改。引用对象被删后显示失效，不用另一份同名文件顶替。

备份包括已提交发布文件、内容身份、版本关系与采用/修订回执；恢复先核对引用与内容，失效预览缓存，不重发旧提醒、不执行未完成修订或调用模型补审核。

旧 Artifact 保持原 ID 与文件关联，作为未关联独立成果；无 ID/内容身份的历史文件需宿主核对后登记稳定预览身份，不能从同名自动建立链。无采用记录显示“未记录人工采用”，不倒推历史拒绝或撤销已交付状态。

## 实施落点与关键验收

先读[聊天组件地图](../../../src/renderer/pages/conversations/-components/.folder.md)，让文件行、消息和任务详情共用预览入口；扩展[领域合同](../../../src/shared/domain/.folder.md)与[唯一 IPC](../../../src/shared/ipc/index.ts)，持久提交归既有宿主/存储所有者。文件发布继续沿[工作区地图](../../../src/runtime/modules/workspaces/.folder.md)和现有不可覆盖发布边界。

- [ ] 两份同名独立文件不会串成版本链；每一版能回到准确作者、源消息和工作。
- [ ] 对旧版要求修改产生新用户请求及明确新版关系；原文件、原工作结果和预算不被回写。
- [ ] 审阅旧版期间收到新版不会替换正文；旧版采用/审核不自动继承到新版。
- [ ] 重复采用、回执未知和重启只保留一次同请求提交；相同请求不同版本明确拒绝。
- [ ] 外部修改、缺失或撤权时阻止陈旧采用；清空后预览、引用和搜索不读回原内容。
- [ ] 采用原自动化成果不改变其 occurrence 状态，修订不隐式继承原预算或重放外部工具。
- [ ] 重启/备份恢复后版本和采用记录可检查，但不自动执行未完成修订。
- [ ] Vitest 约束版本身份/事务/采用幂等/迁移，Electron BDD 验证预览、指定旧版修订、新版采用及重启，不新增平行桌面测试入口。
