# 待处理、搜索与阅读位置

日期：2026-10-01。状态：待实施，优先级 P1。D5 与 D6 独立交付；查询和阅读不运行模型，也不处理业务事项。

[自动化历史](../../../src/renderer/pages/schedules/automation-history.tsx)已有自身需处理查询，聊天内有审批和工作详情，但[主 Shell](../../../src/renderer/components/app-shell/index.tsx)缺跨会话统一入口。

[会话列表](../../../src/renderer/pages/conversations/-components/conversation-list.tsx)主要搜索会话名称；[聊天视图](../../../src/renderer/pages/conversations/-components/chat-view.tsx)已有明确消息定位，但新消息/阅读滚动状态主要保存在内存。

## 2. D5：统一待处理

入口遵循现有主页面与各页独立详情标签。先聚合等待用户补充、命令审批、失败/中断；D2 具备明确成果版本与采用后，再纳入待验收成果。

| 类型 | 展示的明确对象 | 主动作 |
| --- | --- | --- |
| 需要补充 | 原工作/问题消息；自动化含 occurrence | 打开问题并向指定工作补充 |
| 需要批准 | 原审批请求、动作、命令与范围 | 查看原请求，允许一次或拒绝 |
| 需要核对/失败 | 原工作原因、已有成果和不明操作 | 查看已有记录与当前允许的后续动作 |
| 待验收成果 | 明确 Artifact/版本/内容身份 | 预览、要求修改或采用此版本 |

事项来自权威业务记录，身份由来源类型/ID/必要版本确定。普通成员交流不制造待办；失败不代表一定可重试；运行成功不自动产生待验收。

### 查询和动作

1. 查询在数据库分页前处理类型、状态和搜索筛选，用稳定游标覆盖所有未解决事项。
2. 列表展示会话、员工、原因/摘要及来源时间；详情携带明确消息/工作/版本导航。
3. 动作回到原业务所有者，事务检查当前身份、授权及期望状态；过期项返回当前状态。
4. 提交成功后更新来源和列表；界面事件只是提示刷新，不拥有第二套解决状态。
5. 隐藏主页面暂停读取轮询；已受理工作、审批/通知回执继续遵循宿主生命周期。

不新增独立“标为完成”来掩盖未批准/未补充的工作。若采用物化缓存，缓存必须可由来源重建，不能拥有独立审批或交付终态。

### 自动化与错误边界

自动化补充仍显式绑定原 occurrence、问题消息、原工作与共享预算，消息和关联同事务提交。普通聊天发送不能解除自动化等待。

已停止工作、旧审批或操作结果不明的项，不提供能绕过既有取消/核对门禁的继续按钮。预算追加、恢复、发送通知均保留原显式动作与持久回执；收件箱点击不隐式执行。

## 3. D6：正文搜索与准确定位

首批搜索消息正文与已登记附件/产物文件名，支持当前会话和全部获准会话。返回会话、发言者、时间、短摘录及稳定消息/文件身份；同文不同消息不合并成一个结果。

点击结果复用已有精确定位，按目标消息载入所需历史页并高亮，不靠相似文本/最近会话猜位置。点击旧版成果保持该版身份，不自动跳最新文件。

先使用 SQLite 的确定性检索能力；采用何种索引由真实 SQLite 能力与性能结果决定。新索引是派生数据，不是消息/授权真源；禁止预先承诺向量或语义检索。

查询有长度/页数/结果上限；排序结合稳定唯一键形成可续游标。十万级数据等更大规模目标按实测扩展，首批至少验证万条历史分页及重复正文定位。

### 授权、清理与备份

索引、摘录和预览只能读取当前获准正文。会话清空/删除、来源撤权和员工权限变更后，旧索引不能成为可读旁路；处理查询与点击时均复核。

备份恢复核对权威数据并失效派生缓存，需要重建时用有界本地步骤显示进度，不调用模型或重发业务。附件/产物失效时保留可见原因，不展示旧缓存冒充可用文件。

## 4. 持久阅读与未读

阅读位置按会话持久保存，遵循稳定完成事件/阅读边界和版本；流式消息起始顺序不足以判断谁最后完成。

1. 用户在底部阅读，记录实际连续已读边界；查看旧历史不越过尚未看到的新内容。
2. 新消息完成后，依据真实完成事件产生未读；一次完成不因重复事件计数多次。
3. 用户查看历史时保持位置，提供“返回未读/最新”操作；新结果不强制滚到底部。
4. 切换页面/会话保持各自草稿和滚动；重启恢复持久阅读边界，优先定位稳定消息，像素位置仅作辅助。
5. 加载/打开搜索结果不自动把后面的历史全部标已读；已读也不表示采用成果或批准请求。

旧数据首次初始化要在实现前固定：使用已知阅读状态或明示的初始化规则；不能将全部历史强行标未读，也不能编造以前已读事实。无可靠位置时给出可解释的默认定位。

“未读”与“待处理”是不同事实。读过审批仍可能待批准；未读普通回复也可能无任何业务动作。
