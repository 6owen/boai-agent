### 明确问题回复与发送

选择问题卡片“回复此问题”，或引用原未回答问题后，进入明确问题关联模式，复用聊天 composer 与引用预览，显示正在回复的原问题及取消问题关联入口；未提交时可取消目标。引用其他普通消息仅做引用，普通发送不隐式成为业务补充。首批补充只支持正文，材料/成员点名须先取消问题关联，作为普通发送仍不能解除原等待。发送将问题 ID、期望版本、原消息及适用 workId/occurrence 交给宿主再次核对，消息、问题关系和稳定回执同事务提交。

普通 chat 问题回答不创建 Work。任务问题回答接续原 Work、最初请求、累计预算与绝对期限，读取已有工具和成果证据，不重放已执行操作。自动化回复必须显式携带原 occurrence，并通过 replyAutomation.question 冻结 expectedVersion/questionMessageId；宿主先在串行临界区的只读事务核对原问题消息确属该 occurrence 的 waiting turn，受理事务再核对原等待版本/预算，inboxReply 问题关系与本人消息/回执同事务保存，不能接给下一次问题。普通聊天发送不解除等待，不改绑原工作来源。当前自动化task问题还沿真实Message→Run→Work→原userQuestion核对owner、origin、固定消息和未回答关系；Work/question版本与occurrence等待版本分别核对，原问题回答与消息/回执同事务保存并接续原Work，仅解除该问题等待，不解除依赖等待或同轮其他员工问题，不新建Work或预算。判断期及真实执行期公开问题共用来源核验；旧completed或同伴失败Turn仅按真实已公开关系只读兼容，不迁移旧Turn，启动中断/取消门禁不放宽。停止、权限、容量、预算及不明副作用门禁保持原合同。

提交前冻结载荷/key。回复未知时跨切会话、关闭与重启保留原目标和请求，只读核对原回执；确认无回执后才允许原请求重试或放弃。已受理返回原消息，不因问题已结束而新建普通回复。迟到结果不能覆盖新草稿或已清理会话。

### 原业务记录与资格

inbox 来源投影/API 保留供准确核对，业务终态仍归原工作/审批/自动化/采用所有者。过期审批、已停止工作、来源失效或不明操作不能被旧卡片绕过；不新增通用“标为完成”或自动恢复按钮。

待验收资格只由本人在原交付消息文件卡明确点击“稍后处理”生成，保存 Artifact/逻辑身份/版本/hash/预期资格 revision 和原请求回执；预览、未采用和运行成功不自动产生。采用与要求修改在原事务结束该版资格，新版不继承。资格不等于人工质量通过。

清理、撤权和备份恢复沿原事务与来源门禁；重启只核对已提交记录，不运行模型或重放工具。原审批卡片和成果版本预览的既有行为必须继续验收。新自动化员工消息保留真实 origin；旧历史消息没有 origin 时，只沿该消息原 turn 的可信来源兼容，不按内容、员工或会话猜测 occurrence。

## 3. D6：统一搜索与准确定位

统一检索会话名称、消息正文、已登记附件/产物文件名及支持的文本正文，支持指定会话和当前可见的全部获准会话。未选择筛选条件时，关键词匹配会话列表当前可见且获准会话中的这三类对象，不默认限制到当前会话或消息类型。返回结果保留类型、所属会话、适用的发言者/时间/短摘录及稳定会话/消息/文件身份；同文不同消息不合并成一个结果。

会话名称结果打开原会话；消息结果复用已有精确定位，按目标消息载入所需历史页并高亮，不靠相似文本/最近会话猜位置。文件结果打开原材料或成果版本，点击旧版成果保持该版身份，不自动跳最新文件。

### D6 首批确定性合同

[个人浏览合同](../../../src/shared/domain/reading.ts)与[检索仓库](../../../src/runtime/modules/conversations/search-repository.ts)独立于运行时 `getConversation` 和模型上下文窗口。会话名称、消息、文件共用固定查询与稳定游标；消息搜索仅匹配 `completed` 正文，文件搜索匹配已发材料和已登记成果名称及已核对的文本正文索引；通用二进制未解析时仍只按名称匹配，不虚构正文。历史消息页可以保留失败、流式等原状态，不能因此给它们生成完成身份。

- 关键词为 1–200 字符；默认每页 40、最多 80。当前/全部会话、员工、时间与类型筛选通过[固定 SQL](../../../src/runtime/modules/conversations/reading-sql.ts)在 `LIMIT` 前求交，首批使用 SQLite `instr`，不建立向量或平行索引真源。
- 搜索按时间、具体 ID、类型稳定倒序；游标绑定规范化查询条件，改变范围或筛选后不能续用旧游标。相同正文、同名文件分别保留自己的具体身份。
- 消息页按 `sequence/ID` 提供 `before/after/around`。`around` 保留所选消息的明确身份；原目标缺失或读取期间被删除，返回携带原 `targetMessageId` 的空页且无翻页游标，不用邻近消息替代，不在聊天页面展示定位错误条或诊断文字。清空/删除同步清除本地锚点、固定消息定位和导航历史里的定位；过期详情请求的成功与失败均不能更新当前页面。
- 查询和点击都复核当前会话/清理门禁、材料版本与授权、成果具体版/hash 及实际原件。可见会话中的文件来源失效返回固定目标与不可用原因，不带旧摘录或正文；隐藏/删除目标显式拒绝，不返回旧条目。旧版点击不改为新版。候选读取期间被删除时，仅有界续页，不能无界扫描或将查询失败冒充无匹配。

原消息/文件查询及来源核对合同已通过首批相关桌面与实际应用包验证；会话名称混合查询及普通 Dialog 初版独立通过80项相关模块、开发4场及本地应用包11场；后续四项修正又独立通过90项相关模块、最终开发4场及实际应用包11场。证据仍回到05，不凭模块检查代替完整桌面或人工质量结论。

### 2026-10-02：Mastra 能力核对与后续扩展

最新顺序见 [01 后续功能路线图](../01-后续功能实施路线图.md)：先本地正文/中文检索 Q1/Q2，再浏览器；不做向量语义检索或 embedding。Q3 员工检索后续按需求确认，不阻塞浏览器。本组 05 保留原 D6 验收，新 Q 阶段详细状态只维护在第 5 组 09。

当前 Q1/Q2 已实施并完成专题验收：查询覆盖 SQLite 全历史，不依赖 Renderer 当前载入消息；空白拆分多词 AND 支持分散词命中并按确定性相关性排序。已发送 TXT/Markdown 材料与支持的文本成果有派生正文索引，显示有界回填及覆盖状态。没有中文语义分词、模糊语义或向量检索；万条历史测试不等于十万级性能验收。

派生正文索引绑定原来源、版本/hash，并在分页与排序前限制获准范围；清理、撤权、外改、恢复及点击核读继续遵循原合同。游标绑定查询条件和索引 revision，不能沿用仅时间/ID/类型的旧游标。实施和证据见[第 5 组 09](../5.Mastra能力扩展/09-检索文件系统与LSP能力核对.md)，不回写 D6 首批历史成绩。

本入口属于本人个人搜索。员工筛选只是查询条件，不能作为员工授权证明；员工跨会话检索需要按可信运行身份、来源授权和使用范围另建受控入口。已有 `search_knowledge` 只检索员工获准知识，不等于可访问本人全部消息与成果。

Mastra Workspace Search 是独立索引；当前每 run 新建并销毁 Workspace，未配置 BM25/vector。不能在 task 中加一个开关就替代个人搜索，也不能先索引全集再依赖 `filter` 隔离。Filesystem 的现有自定义读/写/列表已接入，LSP 面向代码工程。具体差异、安装版约束与待实施清单见 [第 5 组 09](../5.Mastra能力扩展/09-检索文件系统与LSP能力核对.md)。Q3/LSP 尚未实施，Q1/Q2 使用独立增量证据，不与 D6 原通过数字混算。

### 有界浏览与详情入口

会话列表的检索图标与会话标题菜单共用普通 Dialog。结果按当前查询条件续页，点击后由宿主重新核对原会话、消息或文件，再打开原会话、载入明确消息窗口或所选材料/成果版本。界面每次保存最多 80 条历史窗口，并通过“载入更早消息/载入较新消息”接续，浏览范围不改变模型上下文。

成果、活动与 Trace 详情使用 `getConversationMetadata` 获取无正文会话元信息；需要正文时，[详情读取](../../../src/renderer/pages/conversations/detail-reading.ts)仅按明确来源/触发/运行消息 ID 分批请求 `limit=1` 的目标窗口。隐藏标签停止后续批次，原 ID 不可用时显示原因，不回拉整个聊天，也不猜另一条消息。

Trace轮次下拉的来源摘要由宿主按明确来源ID读取，最多80项、每项60字；当前来源失效不返回旧摘要。选择某轮后仍核读其原消息正文，不能以相似内容或其他轮次替代。

活动详情的历史交付证据由宿主核对当前 Work 版本、实际结果消息/来源或登记成果原件；未通过核对不能从 Renderer 旧正文回退为“已交付”，人工待审也不被该检查覆盖。查询发现固定来源失效时，已打开的对应材料/成果详情立即清除旧正文并核对；同名 V2 不能代替已失效的 V1。

### 授权、清理与备份

索引、摘录和预览只能读取当前获准正文。会话清空/删除、来源撤权和员工权限变更后，旧索引不能成为可读旁路；处理查询与点击时均复核。

备份恢复核对权威数据并失效派生缓存，需要重建时用有界本地步骤显示进度，不调用模型或重发业务。附件/产物失效时保留可见原因，不展示旧缓存冒充可用文件。

## 4. 持久阅读与未读

阅读位置按会话持久保存，遵循稳定完成事件/阅读边界和版本；流式消息起始顺序不足以判断谁最后完成。

1. 用户在底部阅读，记录实际连续已读边界；查看旧历史不越过尚未看到的新内容。
2. 新消息完成后，依据真实完成事件产生未读；一次完成不因重复事件计数多次。
3. 用户查看历史时保持位置，通过正常滚动继续阅读；标题栏不展示阅读状态或跳转按钮，新结果不强制滚到底部。
4. 切换页面/会话保持各自草稿和滚动；重启恢复持久阅读边界，优先定位稳定消息，像素位置仅作辅助。
5. 加载/打开搜索结果不自动把后面的历史全部标已读；已读也不表示采用成果或批准请求。

旧数据首次初始化要在实现前固定：使用已知阅读状态或明示的初始化规则；不能将全部历史强行标未读，也不能编造以前已读事实。无可靠位置时给出可解释的默认定位。

“未读”与“待处理”是不同事实。读过审批仍可能待批准；未读普通回复也可能无任何业务动作。

### 完成与阅读持久权威

[阅读仓库](../../../src/runtime/modules/conversations/reading-repository.ts)的 `recordCompletion(tx, message)` 只能在原公开回复事务内、最终消息已经保存后调用。仅固定 `senderType=agent && status=completed` 计数；同消息重复提交幂等，事务回滚不计数，员工完成先后以本会话单调 `ordinal` 为准。用户、系统、失败和流式开始均不累计未读。

页面观测必须携带当时实际看到的 `messageId/ordinal/epoch/contentHash`，不能仅传消息 ID 后由宿主推断其后来完成状态。阅读保存以 `revision/epoch` 作条件更新，在同事务再次核对当前消息与材料来源。连续 `boundary` 只跨越已经看到的连续完成事件；跳转较晚结果放入 `sparseSeen`，保留未见缺口。每次最多观测 80 项、缺口最多 256；达到上限明确拒绝并保留原状态，不丢弃缺口或越界推进。

`firstUnreadMessageId` 在同事务按当前完成 `ordinal/epoch`、连续边界和缺口查询，核对原员工完成消息存在，不能从开始序号猜测。滚动锚点另外保存稳定消息与有界偏移，使用独立 `expectedAnchorRevision`；保存锚点不推进已读，迟到锚点不能覆盖新位置。

界面仅在主页面活跃、文档可见且窗口有焦点时，观测与滚动容器真实相交的完成快照。标题栏不展示阅读状态或跳转按钮；通过正常滚动阅读，历史阅读保持当前消息位置，贴底继续跟随。阅读与锚点分别提交，已读为零不能证明新的滚动锚点已经保存；失联或条件更新冲突先只读核对，不自动重发旧观测。

首次初始化只把确实已有、但没有可信完成事件的旧员工完整回复标记为 `legacyCompletedUnknown`，不给它们补造已读或未读；新空会话不显示旧历史未知。清理在原事务清除完成/阅读私有记录并推进保留的会话 `epoch`，旧页面观测不能复活。备份和重启恢复已提交边界/缺口/锚点，只进行本地核对，不调用模型、创建工作或重放业务。
