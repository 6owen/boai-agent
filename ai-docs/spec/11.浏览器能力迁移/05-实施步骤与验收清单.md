## 2. BRM0：冻结旧源码基线

目标：开发者按清单迁入旧实现，避免先重新设计浏览器或改用第二套 Chromium。

执行步骤：

1. 记录旧 `boai-app` commit、工作树差异和本次迁入文件 hash；源工作树不干净时保存明确文件快照身份，不能只引用 commit。
2. 按 02 标记窗口/CDP/工具 parser/UI/构建文件的直接迁入、必要适配和本批不搬入范围。
3. 记录原 BrowserWindow + 三个 BrowserView 布局、默认尺寸、菜单/加载/空态/遮罩行为和旧 IPC 名称。
4. 核对旧 LICENSE/NOTICE 及实际来源，保留迁入文件所需声明；不因为旧项目在本机就删除版权出处。
5. 标记旧固定 Cookie 分区、always-allowed、批命令、裸脚本/剪贴板/路径上传和乐观移除断言为需要替换的业务边界。
6. 确认当前 Electron API/types 能承载原版 View 路径；若真实兼容问题出现，先保留失败证据和最小修复，不静默换整套 UI 架构。

成功证据：版本/hash 清单和代码去向明确，直接复用与修改项可逐项检查；不将本阶段源码冻结记为浏览器运行通过。

## 3. BRM1：先窗口与 bridge，再接工具

目标：不依赖模型，能够从当前产品受控打开、查看、隐藏和关闭原版专用浏览器。

执行步骤：

1. 迁入 BrowserPaneManager/CDP 及原版 toolbar/empty-state HTML、专用 preload、overlay/layout 代码。
2. 按当前 `vite.config.ts`、`scripts/build.mjs` 接独立 UI 与 preload 构建，替换旧包别名、Jotai/i18n/图标依赖。
3. 主进程管理窗口；utilityProcess/runtime 通过类型化请求桥调用，网站页面拿不到业务 API。
4. 使用稳定员工 × 会话 scope 创建持久 partition，代替全局 `persist:browser-pane`；每个实例固定 scope。
5. 建立运行时租约、单实例动作串行、停止门禁、真实退出和关闭确认；不以移除 Map 或销毁请求已发出证明退出。
6. 主界面接原版徽标与查看入口，状态 revision/tombstone 防迟到事件复活；隐藏和关闭使用不同状态。
7. 使用场景独立 profile 验证 Cookie、弹窗和关闭隔离；不访问或迁移用户已有真实 Cookie。

成功证据：当前 Electron 中三个 View 真实显示，导航/菜单/明暗主题和 preload 路径可用；两个 scope 的测试登录值互不出现；慢操作关闭期间仍持有资源，确认后才释放。

## 4. BRM2：Mastra task 工具与预算

目标：员工在已获准任务中沿原版命令协议使用浏览器，模型和工具不取得全局窗口权限。

执行步骤：

1. 所有启用中的 Mastra 员工含 bobo 默认具备浏览器能力，不提供员工开关；旧 false/缺失字段同样可用；创建或保存员工不启动模型或窗口。
2. 仅在当前 Mastra task 工厂注册 `browser_tool({ command })`，保留旧 parser 和单命令帮助；chat/判断/记忆维护不注入。
3. parser 完整解析后先执行 allowlist/schema 校验；批命令和不在本批开放的 evaluate、系统剪贴板、裸路径 upload 明确拒绝，不能执行第一条后再报错。
4. scope/Work/run/实例/授权版本由宿主校验；`windows` 只返回本任务范围，不能让全局 active 窗口成为模型选择权威。
5. 每次只受理一个动作，保存稳定调用身份和结果回执；重复同请求返回原回执，未知结果只核对，不自动重放网站操作。
6. 将浏览之后的模型调用继续计入原 Work/occurrence 累计预算；不创建浏览器专属第二份预算。
7. 贯通 AbortSignal 与真实动作退出，stage dispose 接租约释放；旧 run 不释放新 run 的容量。
8. 截图返回真实模型图片内容；使用实际支持图像与工具调用的已配置连接验证，路径文本不计为看图成功。

成功证据：真实员工 task 能导航、快照/查找并理解截图；普通 chat 无浏览器调用；多步浏览沿原预算结算，未知模型用量不按零处理；失联调用不会增加第二次网页提交。

旧驱动内部获取页面尺寸/状态可保留固定实现，包括内部 `evaluate`；bridge 只接受固定 query 枚举，不接受模型/renderer 提供的任意表达式或 CDP 命令。

## 5. BRM3：授权、正常浏览、来源与文件

目标：员工能完成受控网页任务，用户正常浏览/登录无需切控制权，结果有可检查来源及真实文件。

执行步骤：

1. 接原任务范围授权与外部副作用审批；点击、按键和导航按实际效果核对，不能统一认定只读。
2. 目标页面、操作对象、提交内容或授权版本改变时旧批准失效；网页文本不能授予新的权限。
3. 工具栏固定48px、X直接关闭；无菜单尺寸扩展/输入遮罩/操作权切换。手工导航沿原scope队列，员工下一步重新核对来源、pageVersion和批准，验证码不触发无入口pause等待。
4. 网站原生权限、重定向和弹窗逐项核对 scope/获准来源；不复制旧定位/媒体/clipboard 自动允许表。
5. 保存实际获取 URL、标题、时间、范围和正文/截图证据；`@eN` 只用于页面操作，不充当来源引用。
6. 网页来源进入记忆/成果时沿现有授权及来源链；退出会话或撤权后，旧内容不能继续调用/发布。
7. 下载进入受管目录，保留来源/hash，经过现有成果发布才算已交付；不向模型开放任意用户路径上传。
8. 清理、删除和重启按实际退出/文件归属/最小去重身份处理；恢复业务备份不导入 profile 或重放浏览器。

成功证据：普通浏览无需切控制权、无无故抖动/刷新，X直接关闭；手工变化后旧ref/批准不复用，模型授权不扩大；报告/下载有实际来源/hash/发布记录，停止和unknown保留真实状态，清理不覆盖外改。

执行步骤：

1. 完成类型、UI 规则和相关 Vitest 测试；更新被修改源码 Header、目录 `.folder.md` 和本组证据入口。
2. 使用 `playwright-bdd` 跑真实 Electron 场景；先构建，再生成步骤绑定，保留失败截图、日志和场景数据身份。
3. 构建发行目录，验证 toolbar/empty-state/preload 和静态资产的打包路径、启动与实际关闭。
4. 在隔离测试网站验证登录、提交、下载、重定向、慢操作；不使用用户私人账号作为自动化测试 fixture。
5. 使用用户已有且明确获准的模型连接执行一项公开网页任务，保存请求、预算、页面来源和成果 hash 证据。
6. 分开登记技术成功与人工评审；模型生成了报告不表示内容质量已经获得用户认可。

成功证据：当前目标桌面平台的打包应用与真实模型闭环通过。其他平台未运行时单独标记未运行，不由某平台通过推导全部平台可用。

## 8. 测试文件位置与旧测试使用方式

模块、parser、bridge、事务/租约及状态 reducer 使用当前 `tests/*.test.ts` 的 Vitest。真实 Electron 场景写入 `tests/e2e/features/`，步骤在 `tests/e2e/steps/`，启动/服务/清理在 `tests/e2e/support/`。

不新增平行 Electron `.spec.ts` 入口，不手工维护 `.features-gen/`。每场景独立资料目录/profile；同场景重启保留数据，结束等待所有窗口/执行器真实退出。

旧 `bun:test` mock 测试仅提供意图和边界参考，按当前 Vitest 重写必要断言。mock BrowserWindow 通过不能证明 Chromium/UI/profile/下载实际行为通过。

旧共享 partition、默认 always-allowed 和乐观删徽标的断言不能原样作为新通过标准。原版 UI 的保留程度通过真实截图/操作证据检查，而不是只检查组件已复制。
