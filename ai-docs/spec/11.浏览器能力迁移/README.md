# 浏览器能力迁移

更新：2026-10-02。状态：**内置浏览器已接入，当前源码完整模块与桌面回归通过；本轮未重验发行包和真实供应商。** 本次实施记录见 [R2 验收](../../2026-10-02-R2浏览器迁移验收.md)，最终详细进度以 05 为准。

实施顺序：本组位于 [01 后续功能路线图](../01-后续功能实施路线图.md)的 R2，在 R1 本地检索升级完成后启动；窗口/CDP复用继续有效；旧员工×会话归属已经撤销，以本组更新后的内置浏览器合同为准。

## 已确定的实现方向

**以旧 `boai-app` 为源，直接迁入窗口、工具栏和 CDP，作为本项目的内置浏览器。** 尽量保留原类名、函数、交互和命令，避免重新写一套浏览器。

- 保留独立 `BrowserWindow` 与 toolbar/page/overlay 三个 `BrowserView` 的组合；首批不改成 IM 内嵌网页或另一种视图架构。
- 保留 `BrowserCDP`、AX snapshot/ref、页面动作实现，以及 `BrowserPaneFns`、命令 parser 和单一 `browser_tool({ command })` 入口。
- 保留地址栏、返回/前进、刷新/停止加载、截图与登录；X直接关闭，用户无需接管/交还，不显示操作权菜单/状态，不锁网页输入。
- 适配旧包别名、日志/主题/导航、IPC、构建和 Pi 工具注册；Mastra 只在获准 task 中挂工具。
- 应用统一保存浏览器登录；工具调用仍逐动作核对授权、实际退出和未知回执。

这一选择取代上一轮分析中“优先将模型入口拆成多个独立工具”的建议：**保留原统一入口，但确定性解析后进行逐动作授权，首批拒绝模型批命令。** 不把整套 browser_tool 当成只读，也不在运行时执行被禁用的子命令。

登录资料由应用浏览器统一持久保存，不按员工或聊天划分，不随聊天/员工清理；登录资料排除业务备份。

首批不安装 `@mastra/agent-browser`，不搬 Pi/远程 WS/MCP 运行框架。当前链路是 **Mastra task → 原版浏览器命令适配 → 宿主桥 → Electron/CDP**。将来需要标准 `Agent.browser` 属性时，可另封装自有 provider；它不是本批前置条件。Computer、MCP 插件和结构化搜索服务后续单独设计。

## 当前产品合同

顶栏浏览器图标直接打开内置浏览器，重复点击显示同一窗口。地址栏、返回/前进、刷新、网站登录与 X 关闭采用普通浏览器交互。窗口和登录资料属于应用，界面不展示员工、聊天归属或成员选择，不新增登录资料设置入口。

切换、清空或删除聊天及员工不改变内置浏览器。应用重启保留登录资料，不自动恢复旧工具动作。旧分区不自动合并不同账号 Cookie，也不擅自删除。

应用中的获准任务可以调用浏览器工具；任务身份只用于原请求、权限、预算和回执。单一实际工具持有者防止并发操作串页，手工导航不扩大工具获准来源，未知副作用不重放，取消等待实际退出。

产品内置浏览器不等同已经接入 MCP、Web Search API 或 Computer；这些仍为后续独立能力。
