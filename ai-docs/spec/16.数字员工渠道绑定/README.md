# 第16组：数字员工渠道绑定

建立日期：2026-10-12。当前状态：**渠道代码已接入，模块与本地协议夹具通过，飞书私聊收发已获用户现场确认**。文档整理后用户已授权生成代码，选择飞书作为真实联调平台。完整验收及其他平台未认证范围以[02 §7](./02-开发计划与验收.md#7-唯一进度与当前待办)为准。

入口：通讯录 → 已保存员工 → 编辑配置 → **渠道**；填写已有飞书机器人的App ID、App Secret与授权用户Open ID，群聊另填授权群ID，保存后连接。飞书后台须选择长连接并订阅应用身份的接收消息事件`im.message.receive_v1`。会话员工详情共用该区域。定位与接收观察见[02 §7.5](./02-开发计划与验收.md#75-手机飞书消息未进入boai的定位与接收观察2026-10-13)，用户私聊确认及暂缓的会话归一方向见[§7.6](./02-开发计划与验收.md#76-飞书私聊收发确认与后续会话归一诉求2026-10-13)。

每名已有数字员工可以绑定自己的飞书、Lark、Telegram或钉钉机器人。外部用户发消息后，同一名BOAI员工使用原执行能力处理，公开回复保存到BOAI原聊天记录，并以该员工绑定的机器人身份回到原平台会话。再次发消息和应用重启后继续同一份聊天记录。

## 实施原则

- 复用顺序：**Mastra现成Provider → Mastra Channels兼容适配器 → Rovai对应渠道源码直接复用与必要适配**。开工时固定实际依赖组合，已有调研版本不自动等于兼容通过。
- 首个交付是已有机器人绑定已有员工、外部消息进入原会话、员工回复返回平台的连续聊天闭环。只补员工关系、外部会话映射和必要受理接线。
- 飞书与Lark分别保存配置、凭据、连接和会话身份，分别验证；一个员工可拥有多个平台身份。不同员工使用各自的机器人身份。
- 平台连接和收发优先交给已有组件；BOAI沿用员工、聊天、Work、材料、成果和权限。API与本机员工分别验证，不因渠道接入新增一轮Mastra模型执行。
- 渠道UI复用BOAI当前组件、主题、字体、间距和图标。外部消息也沿现有聊天及右侧执行/文件入口展示。
- 首版不另建通用渠道框架或机器人开发者后台。机器人创建/发布按现成官方能力或Rovai已有模块接入；多员工群按C5推进。
