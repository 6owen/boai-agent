# 数字员工渠道绑定：开发计划与验收

制定日期：2026-10-12。当前状态：**渠道代码已接入，模块与本地协议夹具验证通过；飞书私聊收发已获用户现场确认，其余真实平台完整验收待续**。文档整理后，用户明确要求“开始执行生成代码”，并选择飞书作为后续真实联调平台；该初始生成授权覆盖此前渠道延期和仅文档范围，不涉及提交/推送或远端机器人创建，随后提交授权见§7.6。

**2026-10-14现行会话合同：** 用户确认并授权按[03 §9](./03-员工主私聊与群聊领域设计.md)分离BOAI主聊天与全部渠道私聊/群。主列表按员工展示，右上角进入员工专属渠道页面；实际来源回发、旧历史与未知不重放保持，当前结果唯一归§7.16。此前本人归一和主列表单列渠道的实施事实按原批次保留，不再作为新消息路由合同。

调研依据见[01](./01-Mastra-Channels与Rovai渠道接入调研.md)。本文沿用其固定快照，不新增“最新版本已兼容”的判断；开工时重新核对实际选用版本与公开接口。

## 1. 目标与完成标准

最小闭环：**选择已保存员工 → 绑定已有机器人 → 平台发消息 → BOAI员工处理并保存公开回复 → 原平台收到回复 → 第二条消息继续原聊天 → 重启后明确新消息继续原聊天**。

普通聊天沿原聊天路径；真实任务沿原Work与成果路径。外部消息不创建另一名员工或第二套工作系统，原生员工仍使用自己的原生会话和执行循环。渠道宿主运行并联网才可收发，关机后的常驻服务属于后续部署能力。

| 必须表达的关系 | 接线要求 |
| --- | --- |
| 平台/账号或租户/机器人安装ID → BOAI员工ID | 引用所选Provider已有安装记录；同一机器人当前只对应一名员工，一个员工可绑定多个平台身份 |
| 平台/机器人身份/外部私聊、群及适用thread → BOAI会话ID | 使用平台稳定ID及明确会话类型，按平台实际线程语义建立映射；同名用户不合并，飞书与Lark不合并 |
| 平台事件ID/来源 → 原消息与受理回执 | 复用BOAI稳定请求身份和事务回执；重复事件核对原受理，不再次执行业务 |
| 已发布员工消息/成果版本 → 平台回复目标与发送结果 | 使用真实作者的机器人回到原会话，业务交付与平台发送成功/失败/未知分别表达 |

这些是必要关系，不预设新表族。先核对Provider安装与存储、BOAI已有记录；确有缺口时只增加所需字段或局部持久映射。

## 2. 员工绑定与用户界面

1. 在现有员工配置/详情增加「渠道」区域。只为已保存员工操作绑定，平台选项将飞书、Lark、Telegram、钉钉分别列出。
2. 首版支持填写或引用已有机器人凭据；展示平台、真实机器人身份、关联员工及实际连接状态。凭据交给Provider可配置的加密能力或BOAI vault，公开查询只返回引用和状态。
3. 「连接/停止连接」管理传输；「解除绑定」移除本地员工关系；删除远端应用必须是明确的独立操作，不能借Provider同名disconnect方法混用。解除绑定保留原聊天与已提交业务记录。
4. 飞书/Lark分别配置区域及App凭据，显式传递domain；Telegram显式选择传输方式，桌面首版优先polling，并展示该bot由当前宿主接收更新的事实。
5. 接收到的聊天进入现有会话列表，保留平台和外部发送者来源；回复、附件、文件及右侧执行复用BOAI原入口。外部成员身份须准确展示，不伪装成本机本人。
6. 全部视觉沿BOAI现有组件和主题。官方扫码创建或Rovai机器人创建/发布模块可在实际调用链可复用时接入，不另造开发者后台自动化。

## 3. 最小业务接线与生命周期

- **来源与授权**：平台稳定发送者身份须经过所选组件的授权流程及BOAI映射，缺口补最小显式授权；不能默认第一个发信人就是本机主人。外部用户消息不得取得本机用户的命令审批、预算追加或管理权限。
- **消息受理**：当前 `service.ts` 的 `sendMessage` 固定使用 `senderId=user`。应复用其消息/请求回执/会话/调度事务，同时增加可信的外部来源入口；不能直接公开转发任意平台载荷到现有本机用户接口。
- **单次执行**：自定义Channel handler进入BOAI原受理与员工执行，关闭或替代会重复调用模型的默认处理。Provider/Channel实例按应用运行期持有，不随每个阶段Agent创建；API、本机Codex和Claude分别走原引擎。
- **公开回发**：只发送原会话已发布且来源有效的员工消息与正式成果，不将私有草稿、Trace或工具结果直接广播。保留平台回复目标；实际SDK回退行为按01所列测试项验证。
- **附件**：下载和准备成功后接原材料入口，保留平台来源与受管原件/hash。失败不能悄悄只执行正文；正式文件交付沿原成果身份，再调用渠道已有上传/发送能力。
- **恢复与退出**：启动恢复安装、绑定与外部会话关系，复用组件既有重连；不因恢复连接重跑已受理业务。停止接收与执行停止分开，解除绑定/换绑须核对在途操作及真实退出，未决原回执不改绑新员工。
- **发送结果未知**：记录并展示真实状态，优先用组件已有查询/幂等能力核对。发送失败不重跑模型或工具；无法证明可安全重试时保留未知，不在BOAI外再叠加盲目重发。
- **清理与备份**：聊天清理沿原受管文件/hash和旧请求去重边界；渠道解除绑定不删除聊天。业务备份保留必要来源与映射，凭据沿现有vault边界，不导出明文；恢复不得自动补发历史回复或抢占另一宿主的bot传输。

## 6. 验收矩阵与结果记录

开发代理执行场景并保留可审阅结果，用户评价效果。按[统一自动化验收](../02-自动化功能验收与结果审阅.md)区分离线协议、真实平台、真实员工执行和人工质量；开发窗口可使用 `pnpm dev`，本计划不要求新增安装包。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| CH01 | 配置、保存与重启 | 绑定指向真实员工/安装，凭据只存加密引用，重启正确恢复；未启动执行或重发历史结果 |
| CH02 | 首条消息与连续私聊 | 原平台与BOAI有同一来源链；第二条继续原会话，公开回复来自同一员工/机器人 |
| CH03 | 事件重复及受理回执失联 | 重复事件不新增同一业务执行；未知先核对原回执，清理后的旧请求不重放 |
| CH04 | 多员工、多用户隔离 | 员工各用各bot，不同私聊按稳定ID隔离，名字相同仍不串聊天 |
| CH05 | 飞书与Lark共存 | 独立域/凭据/安装/会话；同时收发，一侧停止不影响另一侧 |
| CH06 | 外部身份与撤权 | 未授权消息不取得本机主人权；撤权后停止新受理，历史来源仍准确可查 |
| CH07 | 入站图片/文件与失败 | 完整准备后受理，原件/hash可查；下载或准备失败可见，没有只执行正文的假成功 |
| CH08 | 正式成果和明确修订 | 真实任务产生可核对成果；平台回发固定版本，后续修改沿原员工/版本和新请求边界 |
