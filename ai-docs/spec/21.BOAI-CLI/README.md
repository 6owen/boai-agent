源码构建可用示例（应用内安装入口已接入）：

```sh
node dist/cli/index.mjs serve --data-dir /path/to/isolated-profile
node dist/cli/index.mjs run --data-dir /path/to/isolated-profile --employee employee-id --json "整理项目进展"
```

员工须已配置模型或原生运行方式；run复用现有服务，缺服务时使用完整构建自启动。后台交接输出serverId与原requestId，可用receipt查询原任务，可信本人通过server:status/server:shutdown核对和关闭。

会话命令：`session create --employee ID [--name TEXT] --request-id ID`、`session delete ID --request-id ID`、`session receipt REQUEST_ID`。删除沿桌面清空隐藏，重复原请求只返回原结果；bobo尚无会话时先发送原首条消息。

精确停止：`cancel SESSION --run RUN_ID`只停止该运行及原工作范围；同组独立员工继续。省略`--run`仅唯一活动run可自动选择，歧义列出原目标。重复旧run不换挂新任务，实际退出前保持stopping；部分应答未知保留查询身份。

版本与历史：`versions`明确区分当前核验版本、历史验证和未知；`session messages ID --cursor JSON --direction before|after`复用原消息分页。`listen app|session:event --session ID`返回订阅确认并按会话过滤；具体实际与剩余统一见01 §12.28。

执行输出：`send`/`run`支持原文本增量、部分内容废弃和工具结果。`receipt REQUEST_ID --follow`只读续看原执行；待输入/审批返回原动作身份，用户明确响应后可再次续看。长文本按原revision核验，终端脱离不重新发送任务。当前受控验证及完整后续见01 §12.28。

运行凭据：本人通过`invoke auth:issue-run`为正在执行的run明确签发，`auth:revoke-run`撤回。API命令及Codex/Claude/插件自动注入原run环境租约，实际进程退出撤回，不增加本机时间预算；无租约时禁止回退用户连接文件。受限连接通过`employee:context/tools/invoke`调用同一阶段的实际API或本机产品工具，沿原schema、审批和权限。写调用必须携带稳定callId，相同调用核对原结果；缓存仅属于当前存活run，不承诺跨重启恢复。当前实际结果、原失败及完整后续见01 §12.28。

明确来源：`send SESSION --source SOURCE_ID`与`run --employee EMPLOYEE_ID --source SOURCE_ID`支持重复来源ID，沿原Composer授权和版本；不新建源或改变绑定。相同requestId保留原选择，新请求不能选择已停用源。当前单员工路径已验，群及真实供应商等完整矩阵继续。

明确工作位置：`send SESSION --cwd /absolute/project`或`run --employee ID --workspace-dir /absolute/project`。路径属于服务机器，目录须已存在；选择位置不授予访问许可。API相对文件和命令使用该位置，原目录/命令审批继续生效。CLI待审批返回退出码3，本人批准后用`receipt REQUEST_ID --follow`只读续看。原生沿已配置的BOAI或自身权限，完整本机目录隔离仍在实施。

附件：`send SESSION --attachment /absolute/local/file.md "阅读这份资料"`与普通员工`run --employee ID --attachment /absolute/local/file.md`。传输客户端真实字节，沿会话授权；一次最多三份，每份20MiB。重复发送仍需本地文件可读，核对旧结果用receipt。bobo首次附件已接入，准备失败不发布空会话；成功受理后可在桌面核心会话历史打开。

本轮API模型：`send/run --provider NAME --model ID --base-url URL --api-key KEY`只作用于该原请求，默认员工配置不变；凭据仅在服务内存，重启缺失时不能隐式续用。

显式权限：`send/run/session create --mode read-only|ask|allow-all`核对员工已保存权限，省略沿原配置。模式不符先修改员工配置；CLI不会临时改权。群按明确接收员工或当前全部成员核对，原审批和目录授权继续生效。

CLI显示与服务入口：`--verbose/-v`诊断写stderr；`--no-spinner/--disable-spinner`关闭TTY动画；`run --server-entry PATH`仅在需要启动时加载导出serve(options)的本机模块。`--no-cleanup`保留本轮诊断日志，业务会话始终保留。实际与完整剩余见01 §12.28。

命令安装：设置→运行选项→命令行工具，选择命令目录；当前macOS应用自带执行程序，无需系统Node。移动应用后明确更新，卸载保留业务数据。原位置跨发行升级与完整业务仍按01 §12.28验收。

服务验证：`boai validate --json`或`--validate-server`。未指定服务/profile时创建独立临时验证目录；设置安装的启动器绑定当前profile，因此默认只读检查10步。使用`--validation-profile /new/path`明确创建不存在的隔离目录，运行19步文件/回执/清理验证并保留报告、原件及日志。显式模型必须指定新验证目录和完整连接参数；真实审批保持待批，不自动批准。

启动中断：run在服务ready之前也接收Ctrl+C，退出130并保留进程/配置/日志身份，未提交本轮消息；不能确认服务状态时不强杀。真实双终端同请求已核对同一owner/原回执；后续审批/输入交接及当前包增量仍见01 §12.28。
