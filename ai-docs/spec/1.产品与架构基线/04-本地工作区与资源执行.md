## 1. 分别管理能力、资源和执行环境

员工拥有模型、Skills、知识库、工具和权限；资源层管理技能包、知识原件、索引和产物；执行层决定工具在哪里运行。

员工配置绑定资源标识与访问策略，运行时再解析为真实路径。不要让一个目录同时承担员工身份、所有会话、私有资料和群共享文件的职责。

## 2. 本地目录布局（建议）

应用内部数据根使用 Electron 的 userData 路径；实际应用名称及跨平台路径在初始化时确定。下面是逻辑布局，不代表已创建这些运行目录。

```text
<userData>/
  data/
    app.db                 产品配置、会话、消息及运行记录
    mastra.db              框架管理的状态，是否独立文件待原型确定
  skills/                  应用管理的技能包
  knowledge/
    <knowledgeId>/         导入原件、解析结果与索引元数据
  workspaces/
    <workspaceId>/
      inputs/              会话授权使用的输入文件
      shared/              群内共享资料与已发布产物
      runs/<runId>/        单次执行临时文件与待发布结果
  logs/                    应用日志，采用独立保留策略
```

用户也可选择外部工作目录。数据库记录 Workspace 与目录的映射及授权，不要求把已有项目完整复制到应用目录。外部路径失效时展示明确状态，不静默改用其他目录。

技能包和知识库可被多名员工引用，不因多个绑定而默认复制多份原件。

## 3. Skills 生命周期

### 发现与装配

- 支持选择本地技能目录或将技能包导入应用管理区。
- 员工按绑定明确启用 Skills，不默认获得电脑上所有技能。
- 使用 Mastra 文件系统 Skills 的发现与按需读取能力。
- 保存名称、说明、来源、版本或内容指纹，用于展示和运行追踪。
- 首版不建设远程插件市场或自动安装任意依赖的机制。

### 阅读与执行

读取 SKILL.md 是指令加载；执行 scripts 中的文件是工具操作，分别配置能力。

技能包作为可重复使用的源文件，建议默认只读。脚本从技能路径读取依赖或模板，将结果写入 Run 工作目录。模型看到的路径与执行进程实际访问的路径需要一致映射。

### 依赖准备

应用可保存自己的依赖检测记录，不假定任意第三方 SKILL.md 都声明了完整依赖。

识别任务需要的 Node、Python、系统命令、浏览器或库，以及兼容平台和必要凭据。缺少依赖时返回可处理状态，不将其描述为模型使用失败。

Electron 自带 Node 运行能力并不意味着任意 shell 脚本中的 node 命令可用；Python 等也不保证已安装。实际提供方式在安装包原型中确定。

## 4. Workspace 装配

| Mastra 能力 | 项目用途 |
| --- | --- |
| LocalFilesystem | 读写工作文件，按配置读取技能和资料 |
| LocalSandbox | 在本机执行命令和脚本 |
| Filesystem skills | 发现、加载和搜索技能及附属文件 |
| 搜索能力 | 查找获准资料；知识库索引有自己的生命周期 |

会话、员工和 Run 决定本次可访问的路径与工具。静态共享 Workspace 会使多个请求使用同一环境；不能只更换 thread ID 就认为文件已经隔离。

初版可为具体执行装配 Workspace，也可利用所选版本支持的动态解析机制。以路径、权限和生命周期可预测为选择标准，不固定未经安装验证的构造参数。

## 5. 文件归属与并发

- 群共享目录保存明确对该群开放的资料与结果。
- 单聊文件、私有知识和凭据不会因员工进群而自动共享。
- 并行任务先使用各自 Run 目录；完成后登记产物，再发布至共享目录。
- 修改同一文件时，先采用按文件串行写入或冲突检测，避免覆盖其他任务结果。
- 用户选择的外部项目可授权直接修改，并记录实际修改范围和失败状态。
- 临时文件可清理；已关联消息的产物不得随 Run 临时目录清理而丢失。

## 6. 知识库

分别管理知识原件、解析结果、索引和授权。员工绑定知识库是资源关系；能否在某个群里使用并公开结果，由会话授权决定。

检索时先应用员工与会话的访问范围，再返回内容。不能先把全部资料交给模型，再用提示词要求忽略无权资料。

结果保留原件标识、片段位置和文件引用。移除资料或撤销授权后，后续检索不能继续返回旧索引中的内容。

摘要和运行上下文也保留资源来源标识。撤权时一并废弃或重建受影响的派生上下文，防止虽然检索已过滤，旧摘要仍将资料带入后续模型请求。已公开的群消息与资料访问权限是不同对象；撤权不会自动抹除既有历史，历史删除需由独立操作明确处理。

建议先验证 Markdown / 纯文本和实际需要的一种办公文档格式。关键词检索、语义检索及嵌入模型的位置，按真实资料与效果确定。

本地存储不保证全程离线：调用云端嵌入或生成模型时，选入请求的内容仍发送给相应服务。

## 7. 执行边界

LocalSandbox 默认以应用进程权限在宿主机执行。工作目录不是访问边界，Electron 独立运行进程也不是脚本安全沙箱。

应用校验工具和资源访问范围；需要限制 shell 的文件、进程或网络能力时，配合操作系统级隔离或适当执行环境。仅将 LocalFilesystem 设为只读，不能推出 shell 同样只读。

Mastra 文档描述的本地原生隔离使用 macOS Seatbelt 或 Linux Bubblewrap。平台可用性以及 Windows 方案需要实际验证，不承诺等价隔离。

模型文本中的授权声明不是真实权限。凭据只提供给需要的宿主服务或执行边界，不写入群消息、技能包、通用日志及产物。

## 8. 取消与生命周期

为任务提供超时和取消入口。取消除了停止模型输出，还应处理当前工具及子进程；不支持取消的外部操作需显示真实状态。

应用退出时处理受管理进程和未完成运行。重启后标记中断、保留已有结果；涉及发送、提交或覆盖等外部副作用的操作，不自动重放。参见 [03 会话模型](./03-数字员工与会话模型.md)。
