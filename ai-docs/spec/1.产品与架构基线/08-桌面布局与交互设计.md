## 1. 已确认的方向与文档边界

- 应用具有横贯窗口的全局顶部工具栏。
- 左侧为窄导航栏，主要入口是会话、定时任务和资料库，底部保留设置与帮助。
- 会话页内部划分为左侧列表、右侧聊天内容；当前对象的详情在内容区最右侧展开。
- 会话、数字员工和群组的日常设置采用右侧详情面板，保持聊天上下文可见。
- 每位数字员工是完整的独立 Agent，拥有自己的 Workspace、Memory 和 Skills 配置。
- 群聊默认自然协作，成员收到群消息后各自判断是否回应；`@` 是可选点名。
- 删除用户界面中的“@ 模式 / 协调者模式”选项，不要求用户先选择协作模式。
- 定时任务本轮只设计入口、列表和详情页，不实现实际定时执行。

自然群聊、独立员工的运行方式和记忆边界由 09 自然群聊规格定义。本文规定其呈现位置与交互，不重新定义运行调度。

四张用户参考图分别用于借鉴：中性灰白桌面框架、底部锚定菜单、群详情右侧面板、可伸缩的右侧分屏。图片中的插件市场、锁定、社交功能、浏览器标签等，不构成本产品的功能要求。

参考素材已保存在项目内：[01 桌面框架](../../references/v0.2/01-desktop-shell.png)、[02 底部菜单](../../references/v0.2/02-bottom-menu.png)、[03 群详情](../../references/v0.2/03-group-details.png)、[04 内容分屏](../../references/v0.2/04-content-split.png)。

以下像素尺寸、组件命名和具体交互是建议实施基线，可在实际窗口验证后微调；已确认的区域关系与功能边界不随视觉微调改变。

## 2. 当前界面与下一版的对应关系

当前 `src/renderer/App.tsx` 和 `styles.css` 已具有真实会话、员工编辑、群设置、资源管理与任务记录，下一版保留这些能力并重新组织界面。

| 当前实现 | v0.2 目标 |
| --- | --- |
| 247px 左栏同时放联系人、会话和设置 | 拆成全局窄导航与会话页内部列表 |
| 内容区内 100px 顶栏 | 全局 52px 工具栏，加会话内部紧凑标题区 |
| `AgentModal` / `GroupModal` | 内容区右侧员工与群详情面板 |
| `SettingsModal` 混合模型、资源与备份 | 资料库独立入口；全局设置作为内容页 |
| 280px 固定任务栏 | 统一右侧面板容器，承载详情、任务和产物 |
| `mention/coordinator` 选项及必选成员 chips | 自然群聊，可选点名入口 |
| 暖紫色背景、文字和边框 | 中性灰白主体，少量状态色与员工头像色 |

这次调整不应丢失现有模型测试、技能导入、真实流式回复、命令授权、取消、重试、产物打开与备份能力。

## 3. 桌面区域层级

```text
AppShell
├─ GlobalToolbar                         全局窗口工具栏
└─ AppBody
   ├─ NavigationRail                     会话 / 定时任务 / 资料库
   │  └─ BottomEntries                   设置 / 帮助
   └─ ContentFrame                       当前功能内容
      ├─ ConversationList                会话页列表，可折叠
      ├─ ConversationView                聊天标题、消息、输入区
      └─ DetailPanel                     当前对象详情，可关闭与调宽
```

其他导航页复用 `ContentFrame`，拥有各自的列表和内容，不把所有页面硬套成聊天界面。全局工具栏和窄导航不会随着内容滚动。列表、聊天消息和详情面板分别滚动，输入区固定在聊天区域底部。

右侧只维护一个面板容器；打开员工详情、群详情、任务或文件信息时切换其中内容，不连续向右叠加多个栏。文件内容预览不是本轮布局成立的前提，现有产物打开能力继续通过桌面接口提供。

## 4. 尺寸与布局建议

| 区域 | 建议尺寸 / 约束 |
| --- | --- |
| 全局工具栏 | 高 52px，窗口控制区单独保留空间 |
| 窄导航栏 | 宽 64px，不展开为第二份联系人列表 |
| 内容外边距 | 上 0–8px、右与下 8–12px；内部统一边界 |
| 内容框圆角 | 外缘 14px；内部分栏靠 1px 分隔线区分 |
| 会话列表 | 默认 272px，可调范围 232–360px |
| 会话标题区 | 高 56px，标题与功能按钮同一行 |
| 聊天阅读区 | 常规最小宽 420px；消息内容最大宽 860px |
| 右侧详情 | 默认 360px，最小 300px，最大 560px，受剩余窗口宽度约束 |
| 分栏拖动柄 | 视觉线 1px，实际命中宽度 6–8px |
| 导航图标按钮 | 44 × 44px 命中区域，图标 20–22px |
| 列表行 | 通常高 68px，包含头像、标题、预览和辅助状态 |

宽度计算必须先满足可见聊天区域的最小宽度。窗口缩小时，先折叠会话列表，再采用详情占用内容区的窄屏方案，不能把聊天和表单压缩成无法操作的细条。

分隔线支持拖动调整，双击恢复默认宽度。关闭详情后保留该设备上的面板宽度偏好；再次打开使用可用宽度内的最近值，不在不同会话间重置为默认。

## 6. 全局工具栏与窄导航

### 顶部工具栏

- 左侧保留系统窗口按钮与拖动区域，macOS 红黄绿按钮不能覆盖自定义按钮。
- 提供“显示 / 隐藏列表”按钮；功能随当前内容页变化，无列表页面保持隐藏。
- 中间显示当前功能与当前对象的简洁标题，长标题省略，悬停可查看完整文本。
- 右侧提供“显示 / 隐藏详情”入口，打开时有明确选中态；关闭不影响运行中的任务。
- 后退 / 前进作为建议交互，仅针对应用内导航记录；没有可返回页面时禁用，不映射聊天撤销。
- 设置、发送、成员管理等对象操作仍放在对应内容区域，避免全局工具栏堆积全部功能。

空白工具栏区域可拖动窗口，按钮、搜索框、可编辑文本与分栏拖动柄必须排除窗口拖动行为。

### 左侧窄导航

上部依次为“会话”“定时任务”“资料库”；底部固定“设置”和“帮助”，不随内容列表滚走。图标保持常驻位置，当前功能用中性背景和无障碍选中状态标识。

图标使用 Tailwind CSS v4 + Iconify 的 Carbon、Solar 集合，由构建生成本地 CSS，不依赖运行时联网加载。图标悬停与键盘聚焦时显示中文名称，所有按钮有可访问标签。存在等待授权或失败时，可显示带含义的状态标记；不把普通消息计数伪装成真实未读状态。

设置按钮可弹出向右上方展开的紧凑菜单，进入“模型连接”“数据与备份”等已具备能力的设置页。帮助入口可打开使用说明与关于页面。菜单不照搬参考图中的“锁定”“聊天记录管理”等未要求功能。

菜单使用适当的菜单角色，支持方向键、Enter、Escape 与点击外部关闭。菜单关闭后焦点返回触发按钮；危险操作不依赖图标猜测含义。

## 7. 会话页左侧列表

列表标题为“会话”，右侧放新建按钮；其菜单提供“新建员工”和“新建群聊”，二者打开右侧创建表单。搜索范围明确为员工名称、群名称和会话标题，不暗示已经实现全文聊天搜索。

列表默认直接混合展示单聊和群聊，不设置“最近会话”标签或切换页。按真实最新消息时间降序排列，有新消息的会话移到最上方；编辑群名、修改成员或记忆维护不能让旧会话置顶。没有消息的会话排在已有消息之后。数字员工通过独立入口浏览全部联系人、打开单聊和配置员工。

每行包含：

1. 单聊员工头像或群头像；群头像可由少量成员头像组合，仍需明确名称。
2. 会话标题或员工名称，右侧显示最近活动时间。
3. 最近公开消息摘要；员工目录则显示职责简介。
4. 真实的运行中、等待授权、失败或草稿标记，优先级高于装饰信息。

选中会话不因新消息到达而改变；列表可以更新最近活动排序，但不强制滚动离开当前可见位置。默认不截断为只有前 30 条，数据增长后采用分页或虚拟列表。

如果快照接口尚无最近消息摘要、真实未读或运行状态，应补充明确的只读数据投影。界面不能为了预览而逐个拉取全部会话历史，也不能生成虚构摘要填满列表。

首次没有会话时，列表给出轻量创建入口；主内容展示简洁说明与已有员工，不用大型宣传页替代功能区域。没有模型连接的引导可进入设置，返回时保留当前会话选择与输入草稿。

## 8. 聊天内容区

### 标题与成员

单聊标题展示员工名称和简短状态，点击名称或详情按钮打开员工详情。群聊标题展示群名与成员数；点击群名或成员区打开群详情。少量成员可显示头像，成员很多时用数量入口，不让头像挤占标题和操作按钮。

群聊不再显示“@ 指定成员”“协调者模式”等模式标签，也不出现要求选择协作方式的设置字段。

### 消息与任务状态

消息保留实际发送者头像、姓名、正文与时间；流式更新不能改变发送者。任务决定与工具调用可折叠查看，不将后台判断过程伪装成公开聊天消息。

只显示实际执行记录支持的状态，如“研究员正在处理”“写手等待命令授权”。不预设每轮必有固定数量的员工发言，不用中央模型挑选结果制造“大家都同意”的群聊表现。

用户查看上方历史时，新输出不抢夺滚动位置；显示“有新消息 / 返回最新”入口。用户停留在底部时继续跟随流式输出。长代码、表格与文件名在自身区域内换行或横向滚动，不撑破整个内容框。

### 输入区

- 始终可以直接发送普通群消息，不要求先选择员工。
- `@` 是可选点名：可输入触发选择器，也可使用“提及成员”按钮；选中后显示清楚且可删除的成员引用。
- 点名的语义与各成员是否回应由 09 规定；输入区不维护两套发送模式。
- Enter 发送、Shift + Enter 换行，并正确处理中文输入法组合输入。
- 发送按钮在空内容或提交中禁用；员工连接未就绪时给出具体对象的配置入口。
- 工具执行、命令授权、停止本次协作和重试入口保留；停止操作的实际范围采用 09 的定义。
- 任务与产物可从聊天标题或输入区状态入口打开右侧面板，同一信息不堆成多组常驻按钮。

接入状态应依据实际服务配置判断；允许空密钥的兼容服务不能被统一视为未配置。聊天切换、请求失败或后台事件到达，都不能清掉用户尚未发送的新文本。

## 9. 内容区右侧详情面板

### 内容类型与入口

| 入口 | 右侧内容 | 操作边界 |
| --- | --- | --- |
| 单聊标题 / 员工列表编辑 | 员工详情 | 显示并编辑该员工的全局定义 |
| 群标题 / 成员数量 | 群详情 | 管理群名、成员与共享资料 |
| 群内成员头像 | 员工详情 | 标注来自当前群，但编辑仍作用于该员工 |
| 新建员工 / 新建群 | 创建表单 | 成功后进入对应对象，不覆盖原有草稿 |
| 任务状态 / 产物入口 | 任务或产物详情 | 查看真实状态，取消、授权、重试或打开文件 |
| 资料库选中资源 | 资源详情 | 查看来源、路径、绑定关系与可用操作 |

员工详情分为身份与职责、模型、Skills、知识、Workspace、Memory、执行权限和启用状态。长表单按区块或局部标签组织，避免一次铺开所有字段。

Workspace 内增加“系统文件”入口，按 [11](./11-员工系统文件与Mastra适配.md) 展示 AGENTS.md / SOUL.md 等文件的用途、生效版本与可见范围。工作规则和风格可编辑；身份与记忆生成视图跳转各自权威编辑入口。不能把生成视图展示为已实现双向同步的任意文本配置，也不能让保存一段工具说明被误认为已打开执行权限。

Workspace 展示该员工自己的工作区及获准的打开入口；群共享资料与产物另外列出，不把群目录冒充员工独立工作区。Memory 提供独立入口、作用域说明和可用状态；具体内容、编辑与查看权限由 09 定义。没有真实查询能力时明确显示“待接入”，不生成假的记忆条目。

群详情优先展示成员网格、成员名称与状态，支持搜索、添加和移除成员；随后展示群名、共享知识和工作文件入口。无需复制公告、二维码、社交通知等参考图中的社交设置。

编辑员工模型、指令或技能时，应提示“修改会影响该员工后续任务”，避免用户以为只修改当前群中的副本。权限撤销和成员移除的在途影响按运行规格呈现，不能只更新视觉选中态。

### 返回、关闭与未保存修改

- 面板顶部包含标题、必要的返回按钮和关闭按钮；打开详情不会遮罩聊天。
- 从群详情进入某位员工时保留面板内返回路径，例如“群详情 → 研究员”；返回恢复群详情滚动位置。
- 保存按钮固定在面板底部，脏表单显示“有未保存修改”；成功后显示已保存反馈，失败时保留输入并显示具体错误。
- 存在未保存修改时，关闭、切换目标或全局导航先在面板内显示离开确认，可选择保存并继续、放弃修改、继续编辑。
- 离开确认采用面板内提示，不弹出另一张阻断全屏的大表单；只有真正需要系统确认的操作才使用小型确认界面。
- 后台快照刷新不能覆盖脏字段；发现同一对象已有新版本时提示重新核对，不静默用旧表单覆盖新值。
- 未保存表单默认只保留在本次应用会话中；主动退出前提示未保存内容，不能声称其已经持久化。

当前契约没有完整的对象版本冲突提交机制。实现“新版本提示”时需同步补齐必要版本字段或基于保存前读取做最小冲突判断，不能只在界面写一句“已同步”。

## 10. 导航、状态保留与事件边界

建议集中管理：当前一级页面、页面内选中对象、列表筛选、右侧面板目标与返回路径、各分栏宽度。对象表单草稿与聊天草稿独立存放，不能用一个全局 `modal` 状态承载所有导航含义。

| 用户操作 | 必须保留的状态 |
| --- | --- |
| 会话切到资料库再返回 | 选中会话、聊天草稿、历史阅读位置、列表筛选 |
| 会话 A 切到会话 B 再返回 | A 的草稿和点名选择，A/B 消息互不串入 |
| 详情切到任务再返回 | 当前对象、面板内返回路径，经过确认的表单状态 |
| 关闭并重开右侧面板 | 最近宽度和有效目标；不恢复已删除对象 |
| 应用重启 | 持久数据、有效的页面选择和布局偏好；未完成运行采用真实恢复状态 |

页面切换不取消后台任务。切到别的会话后原任务仍可继续更新列表状态；返回时读取该会话真实数据。请求和流式事件继续使用会话标识、请求序号与版本保护，不能因新布局删除现有竞态保护。

布局偏好可本地保存；密钥、完整工具输出、私有记忆与未授权资料不写入一般 UI 偏好存储。删除对象后清理失效的导航目标，并显示空态或可用列表。

## 11. 定时任务、资料库、设置与帮助

### 定时任务：本轮仅页面设计

确定本轮只规划入口、列表和详情页面，不提供实际调度器、后台守护或时间到达后的 Agent 执行。

列表结构预留任务名称、目标员工或群、计划描述、时区、启用状态、最近与下一次执行状态。详情页预留任务内容、执行对象、时间规则、时区和结果去向，但本轮不能把设计稿里的示例当作真实已保存或已启用任务。

在页面真正连接到任务存储与调度能力前，使用诚实的未接入 / 空状态，不提供会让用户误以为已经开始执行的“启用成功”反馈。关闭应用后继续执行、错过任务补跑、夏令时与去重规则留待后续定时执行规格。

### 资料库：公共资源与员工已绑定

资料库包含 Skills 与知识资料。建议提供“公共资源”“员工已绑定”两种视图，并按类型筛选。这里的“公共资源”指本机资源目录中可被选择的资源，不代表自动向所有员工或群授权。

公共资源视图保留导入、来源、路径、格式或类型、描述和可用性；员工已绑定视图先选择员工，再列出其实际 Skills / 知识绑定及相应作用域。员工自己的工作区文件不自动等同于公共知识库。

资源详情显示哪些员工绑定了该资源、哪些群明确共享了相关知识。导入、绑定给员工、共享给群是三个不同动作，不能用一个“添加”按钮暗中同时完成。

移除公共资源前说明实际受影响的绑定关系。入口文案区分解除绑定、移除导入记录与删除源文件，不把它们合并成无法判断后果的“删除”。

### 设置与帮助

设置放全局模型连接、连接测试、数据路径与备份等全局能力；员工自己的模型选择和资源配置留在员工详情。员工详情可跳转创建模型连接，完成后返回原员工草稿并供用户选择新连接。

后续新增「外观」分类，包含模式、Base46 主题、背景图片和图片不透明度，详见 [14](../3.前端重构与功能/14-外观设置与主题系统.md)。该分类是设计项，不属于 12–13 已交付功能；与模型连接、数据与备份并列，不放入员工详情。

帮助先提供实际支持的操作说明、版本与运行环境、日志位置说明。未建立反馈服务时不显示虚假的“反馈已提交”；不因参考菜单含有功能就新增账户、锁定、云同步或消息管理中心。

## 12. 窄窗口与可访问性

宽度断点仅作为建议；实际使用“导航 + 可见列表 + 聊天最小宽度 + 可见详情”的约束计算。

| 窗口条件 | 布局行为 |
| --- | --- |
| 约 1280px 及以上 | 导航、列表、聊天、详情可同时显示，并允许调宽 |
| 约 1100–1279px | 缩小列表与详情到允许范围；不能牺牲聊天最小宽度 |
| 约 900–1099px | 打开详情时优先折叠列表；关闭详情后可恢复之前列表状态 |
| 低于约 900px | 列表、聊天、详情在内容框内采用可返回的单主视图；不叠加全屏遮罩表单 |

窄窗口查看详情时继续显示会话定位与“返回聊天”入口。输入草稿和任务状态不因布局切换消失。宽度恢复后还原用户主动选择的分栏偏好，区分临时自动折叠与用户主动隐藏。

所有主要操作可由键盘完成。分隔线使用可聚焦的 separator，暴露方向与当前值；左右键调整宽度，提供恢复默认入口。窄布局不支持拖动时，隐藏无效拖动柄。

右侧详情是非模态区域，打开后可将焦点移到标题或首个字段，但不锁住焦点；关闭后回到触发位置。Escape 先关闭菜单或退出局部选择，只有无未保存修改时才关闭详情。

焦点可见；状态不只用颜色表达；长名称和图标按钮有完整标签；正常文字对比度至少 4.5:1。流式文本不逐 token 反复播报，运行完成、错误和等待授权通过适当的状态区域提示。支持减少动画偏好和至少 200% 文字缩放。

## 13. 开发拆分与验收

建议顺序：先建立新 Shell 和可伸缩分栏，迁移现有真实功能；再将员工、群和资源表单移入详情；随后接入自然群聊 UI；最后完成窄窗口与键盘验证。不要用静态截图替代真实数据驱动的验收。

| 验收场景 | 通过标准 |
| --- | --- |
| 首次打开应用 | 顶部全局工具栏、窄导航和内容框层级清楚，无旧混合大侧栏 |
| 打开单聊与群聊 | 内容框左列表、右聊天成立，消息和身份来自实际会话 |
| 点击群标题，再点击成员 | 右侧依次展示群与员工详情，返回路径清晰，聊天保持原位 |
| 调整右侧分栏 | 可拖动、可键盘调整、可恢复默认，不把聊天压到不可用宽度 |
| 表单修改后切换对象 | 先处理未保存修改；失败不丢内容；不会悄悄写入错误对象 |
| 后台消息到达且正在编辑员工 | 聊天更新，员工脏表单不被快照覆盖 |
| 普通群消息不带 @ | 可以直接发送；没有协作模式选择或强制点名提示 |
| 查看成员运行状态 | 各员工状态对应真实独立执行，不显示固定发言名额或虚构响应 |
| 员工详情查看 Workspace / Memory | 指向该员工的真实授权范围；未接入能力诚实提示 |
| 资料库切换公共 / 员工视图 | 能区分导入、绑定和群共享，公共不等于自动授权 |
| 点击定时任务 | 出现正确页面设计与能力边界，不声称实际调度已启用 |
| 会话切出与返回 | 保留草稿、点名、选中项与阅读位置，不串消息 |
| 1280 / 1100 / 900 / 760px 宽度 | 无页面级横向溢出，输入、保存、关闭与返回始终可达 |
| 真实取消、授权、失败重试、打开产物 | 新布局保留现有能力，状态与实际执行结果一致 |
| 键盘与 200% 文字缩放 | 主要流程可完成；详情不锁焦点；无被遮挡的关键按钮 |

交付时更新实现记录，分别记录已完成布局、已迁移能力和仍未接入的设计入口。本文状态应在实际实现和上述验收完成后更新。
