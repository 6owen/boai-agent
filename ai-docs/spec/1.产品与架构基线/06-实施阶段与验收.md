## 2. 阶段 A：桌面与本地运行原型

### 交付

- 独立 Electron 应用标识、React 界面和受控 preload 接口。
- Electron 管理的独立 Mastra 运行进程。
- 一个可配置模型连接的测试员工与流式对话。
- 产品数据库与框架存储的最小接入。
- 开发运行和实际安装包两种方式。

### 验收

1. 不启动 boai-app 或远程应用后端，即可打开新应用。
2. 模型请求由运行进程完成，界面正常显示增量内容。
3. 员工能读取指定本地文件并生成一个新文件。
4. 包含脚本的 skill 在依赖就绪时能生成可打开的产物。
5. 取消停止模型与可取消工具；退出后没有遗漏的受管理进程。
6. 安装包中 ESM、数据库驱动、资源路径和子进程入口正常。
7. 重新打开能读取会话与产物；未完成运行标为中断。
8. 确认运行进程终止后，未完成流式消息显示已中断；单纯窗口重连不会误判仍存活的执行。

建议先在当前开发机的 macOS 验证；正式平台支持范围仍待确定。

## 3. 阶段 B：员工与单聊

### 交付

- 员工创建、编辑、停用和模型选择。
- 按员工绑定 Skills、知识库与工具。
- 独立单聊、历史读取、附件和运行详情。
- 必要格式的资料导入、索引与引用。

### 验收

1. 两位员工可使用不同模型和资源。
2. 未获授权资源不会出现在员工检索或工具结果中。
3. 配置改变后新任务使用新配置，既有运行保留实际配置记录。
4. 失败任务说明原因，重试不重复插入原用户消息。
5. 技能目录冲突或失效、依赖缺失、模型连接不可用均有明确反馈。

## 4. 阶段 C：群聊最小闭环

### 交付

- 群创建、成员管理、员工独立群内上下文。
- 明确 @ 与协调者模式。
- 发言归属、运行状态、取消和共享产物。

### 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 同一员工在单聊与两个群中工作 | 身份一致，上下文和授权按会话隔离 |
| 只 @ 研究员 | 研究员执行，其他成员不会无条件启动 |
| 研究员 → 写手 → 审核员 | 依赖顺序成立，每条公开回复显示真实发送者 |
| 员工未参与前几轮 | 参与时获得获准的必要群记录，无重复消息 |
| 同时提交两条群消息 | 确定排队与发言规则，不并发写坏同一上下文 |
| Agent 回复后无人指定下一步 | 不触发无限互相回复 |
| 取消群任务 | 未开始任务停止调度，在途任务按能力取消并显示实际状态 |
| 移除成员或撤销资源权限 | 停止受影响的新调度及排队任务，对在途任务传播取消；后续输入排除撤权资料及受影响的旧摘要 |
| 窗口重连或应用重启 | 历史与产物可查看，中断状态真实，无自动副作用重放 |
| 重开历史、重试、重连后发消息 | 检查实际模型请求，每条公开历史只注入一次，来源与发言者正确 |
| 在等待授权或工具输入时重启 | 保留等待信息，恢复前重验条件，不自动批准或重放工具 |

## 5. 阶段 D：首版体验与分发

完善错误反馈、设置、文件入口、历史加载、备份和必要数据迁移。针对确定的目标平台准备安装与运行验证。

### 验收

- 中文、空格和不同平台路径的工作目录可用。
- 长对话显示和上下文整理不重复消息、不混淆成员。
- 新消息到达、关窗、退出、休眠后的状态都有明确反馈。
- 备份与升级保留知识原件和已发布产物。
- 日志无原始凭据，群上下文不混入未授权私聊资料。
- 在目标平台实际验证安装包，不以开发环境结果替代。

## 6. 待决定与待验证事项

| 事项 | 建议 / 所需证据 |
| --- | --- |
| 正式名称与应用标识 | 目录暂称 boai-agent，初始化时确定 |
| 平台范围 | 先本机验证，正式 macOS / Windows / Linux 范围待定 |
| Mastra 与 Electron 版本 | 核对兼容要求、锁定版本并记录 |
| 运行进程启动 | 优先验证 utilityProcess；若不兼容，以证据选择受管理 Node 子进程 |
| 数据库文件与驱动 | 验证存储、迁移和打包，明确两类数据所有权 |
| 知识库格式 | 用真实资料确定首批格式、解析与检索要求 |
| 模型连接 | 至少验证一个真实连接，服务和模型由用户配置 |
| 群聊默认模式 | @ 和协调者先行，协调者是否可见待交互设计确定 |
| 权限与隔离 | 验证平台实际能力，不能只检查 cwd 或文件工具参数 |
| 技能依赖 | 确定随应用提供、按需准备及用户配置的各自范围 |
| 运行限额 | 选择并发、轮次、超时及费用预算默认值，暂不锁定数值 |
| 退出与后台运行 | 初版建议应用退出时停止执行，常驻后台另行设计 |

## 7. 实现记录

阶段完成时记录代码位置、实际依赖版本、验证环境、通过场景与剩余限制。测试针对身份隔离、消息去重、状态变化、权限和副作用等真实行为。

若 API、运行进程或打包方式与规格不符，更新架构文档并说明依据。首个目标是三个员工的闭环：单聊、共享群聊、本地知识、脚本产物、取消与重启后的真实状态。
