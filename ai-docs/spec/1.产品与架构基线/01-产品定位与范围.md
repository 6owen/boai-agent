## 1. 产品定位（已确认）

boai-agent 是面向用户的 Electron 多 Agent 桌面应用。

用户可以像管理联系人一样创建数字员工，为每位员工配置角色、模型、Skills、知识库和工具。用户既可以与一位员工单独交流，也可以把多位员工加入一个群聊，让他们围绕共同任务讨论、分工和交付结果。

本地文件处理、脚本执行等实际工作能力，与员工配置、知识检索和业务协作同等重要。

### 核心场景

1. 用户创建一位“资料研究员”，绑定模型、检索工具及指定知识库。
2. 用户创建“方案写手”和“内容审核员”，分别绑定适合的 Skills 与资料。
3. 用户可以单独向研究员提问，也可以将三位员工组成“方案讨论群”。
4. 用户在群里指定研究员整理附件，再由写手生成方案，审核员指出问题。
5. 员工以自己的身份发言；产生的文档留在本地，可在群内查看和打开。
6. 关闭后重新打开应用，联系人、群成员、历史消息与已保存的产物仍存在。

## 2. 与已有项目的关系

### boai-app

参考其 Electron 外壳、窗口与生命周期管理、preload 通信、流式内容展示、本地执行进程和桌面打包经验。

boai-agent 使用自己的产品领域和 Mastra 运行层；不会以替换 boai-app 中一个 SDK 的方式继承全部业务逻辑。具体边界见 [05 Electron 外层参考与迁移边界](./05-Electron外层参考与迁移边界.md)。

### 公司数字员工项目

复用“员工由模型、指令、Skills、知识库、连接器装配而成”的概念。新产品的部署环境与交互目标是用户桌面，不直接迁入公司项目的 MinIO、远程数据库、租户治理或发布流程。

公司项目的主管委派是一种任务协作方式；新产品还需要真正的群成员、发言者、群消息和持续会话模型。

## 3. 第一版建议范围

以下是实现规划基线，具体界面与交互细节可在原型阶段调整。

| 能力 | 第一版边界 |
| --- | --- |
| 员工管理 | 创建、编辑、停用员工；配置头像、角色、模型及资源绑定 |
| 模型配置 | 设置模型服务连接与凭据；员工选择已有连接 |
| 单聊 | 与一个员工持续对话；流式回复、工具状态、取消执行、重新打开历史 |
| 群聊 | 创建群、管理员工成员、明确 @、协调者调度；员工保留自己的发言身份 |
| Skills | 导入或绑定本地技能目录，按员工启用，按需读取并执行获准的能力 |
| 知识库 | 导入本地资料、完成基础索引、按员工/会话授权检索、返回出处 |
| 文件工作 | 读取附件、修改授权工作目录、保存并展示产物 |
| 运行记录 | 查看哪个员工执行了什么任务、工具进度、失败原因和已完成产物 |
| 本地持久化 | 保存员工、群、消息、配置和必要运行状态 |

知识库首批文件格式和检索方式需要在原型阶段确定；“知识库”不默认承诺支持所有办公文档格式。

## 4. 群聊体验建议

### 明确指定成员

用户通过 @ 选择员工。指定单个员工时直接调度；指定多个员工时根据用户指定的顺序或协调结果安排执行。

### 协调者模式

用户给出整体任务，由协调者安排成员参与。协调者可以是一位可见员工，也可以是后台调度角色，具体呈现方式待决定。成员公开回复始终标明实际发送者。

### 后续扩展

自由讨论、自动接话、固定业务工作流可以逐步加入。第一版优先保证 @ 和协调者模式可解释、可停止、可恢复查看。

## 5. 本轮不进入实施范围

- 企业多租户后台、组织审批、复杂资源发布治理。
- 多个人类用户通过网络实时群聊及跨设备同步。
- 云端常驻 Agent 集群、应用关闭后的持续执行服务。
- 外部社交平台机器人网关、插件市场、自动更新发布基础设施。
- 通用可视化工作流设计器、所有 Agent 框架的统一接入。
- 不受限制的自动群聊循环。

上述能力可后续讨论，不应成为首个桌面原型的前置依赖。

## 6. 产品语言

| 用户界面概念 | 内部含义 |
| --- | --- |
| 数字员工 / 联系人 | 有持久身份和配置的 AgentDefinition |
| 单聊 / 群聊 | Conversation |
| 正在处理 / 等待操作 / 已完成 | 对任务运行状态的可理解呈现 |
| 工作文件 / 附件 / 成果 | 用户能查看和使用的文件资源 |

避免在日常界面中直接暴露框架 thread ID、resource ID、工具协议或运行进程细节。调试信息放到独立的运行详情中。

## 7. 成功标准

用户可以创建不同能力的员工，理解他们分别做了什么；单聊与群聊上下文保持正确边界；员工能基于获准资料完成本地文件任务；失败和取消有明确反馈；重新打开应用后可以继续查看和开展工作。

完成标准进一步拆分为 [06 实施阶段与验收](./06-实施阶段与验收.md) 中的场景。
