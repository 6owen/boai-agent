# BOAI设计系统

日期：2026-10-22。状态：**共享包与Fumadocs设计站首版已合入main；全量组件、正文样式与Token公开已实施为本地代码候选，云端验收未执行**。BOAI Design、`@boai/tokens`、`@boai/ui`仍为工作名称，尚未正式发布包或迁入独立仓库。实际进度统一见03 §6。

## 建议结论

**共享组件放`packages`，独立运行的设计文档网站放`apps`。** 设计系统本身包含规范、tokens、组件、示例和发布规则，不能全部塞进某个`apps`项目。

| 内容 | 建议位置 | 职责 |
| --- | --- | --- |
| 颜色、排版、圆角、阴影、尺寸等基础定义 | `packages/tokens` | 无React、无Electron依赖，供组件及宿主纯计算使用 |
| BOAI Soft基础组件、皮肤和可复用呈现组合 | `packages/ui` | 浏览器可用的React包，依赖tokens，不依赖BOAI服务 |
| 面向开发者的设计文档与交互示例站 | `apps/design-docs` | 独立启动/构建/部署，实际使用上述两个包 |
| 公开设计指南的Markdown源 | `ai-docs/design-system` | 原则、基础、组件用法、模式、版本说明；已建立 |
| 本次内部调研与迁移计划 | 当前第23组 | 保留决策、实施记录，不整目录发布为公开站点内容 |
| 桌面业务、状态、IPC、主题持久化 | 现有`src/` | 继续负责BOAI产品行为，消费公共包 |

推荐**先在当前仓库孵化并由BOAI真实消费，再将成熟设计系统整体迁入独立`boai-design`仓库**。如果继续同仓维护，网站和npm包也可以独立部署/发布；只有单独的GitHub仓库、议题和版本治理才属于独立仓库项目。将文件放进`apps`不会自动产生这些能力。

当前pnpm workspace已包含根应用、`packages/*`和`apps/*`，保留原补丁/依赖策略。现有桌面应用仍在根目录；是否以后移到`apps/desktop`属于独立工程迁移，不是组件库前提。根`pnpm dev`继续启动桌面，网站使用`pnpm dev:design`。
