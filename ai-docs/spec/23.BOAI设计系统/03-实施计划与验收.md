# 实施计划与验收

## 1. 目标与完成层次

最终目标：BOAI的设计语言和可复用组件拥有明确规范、唯一实现、独立可运行网站与可安装包；BOAI实际使用这些包；如选择独立仓库，迁出后保持单一维护来源。

最初分析批次只要求调查、分支与方案，随后两包一站首版已实施并合入main；逐批事实见§6。当前新增范围是[05 全量组件展示与Token公开规范](./05-全量组件展示与Token公开规范.md)，本轮完成方案与DESIGN指南正文，EX0–EX4产品实施尚未开始。方案存在不表示扩展页面、组件或独立开源发布已完成。

## 4. 验证与交付方式

1. 每个产品PR按当时实际的云端工作流完成原门禁；包/站点检查为新增覆盖，不替代桌面消费者验证。共享包变更要被UI规则/字号扫描/类型检查纳入。
2. 组件行为用针对性模块/浏览器检查；BOAI桌面场景复用已有playwright-bdd入口，不新增平行桌面测试系统。
3. UI迁移先追求现有视觉不变；需要修正焦点等设计时登记差异并逐项审阅候选，不能自动接受基线或降低阈值。
4. 默认不在本机跑自动产品验证、构建或GUI；如用户明确授权本机验证，则按其范围执行。不主动打桌面安装包。
5. 发布包、官网与桌面集成分别报告实际状态。PR/main分别报告对应SHA与Checks，文档轻量结果不能写成产品通过。
6. 本组记录阶段、输入版本、失败、修复与剩余项。历史第22组资格不能充当本组新代码的资格；真实业务评估仍按原专题，不因提取UI虚构模型成绩。
