# 范围与实施计划

## 1. 目标与本轮边界

用户先稳定自己在macOS上的日常使用，日常入口保持`pnpm dev`。目标是：交代的工作能得到可检查的结果；中途等待、失败和停止可理解；回来后能够找到上下文、阻塞和成果，并按真实状态接续。

初始文档已于18a8743a提交；用户随后明确启动完整自用稳定化目标，现进入DU0–DU3实施。个人数据使用只读核对或隔离副本，系统权限不自动开启，发布与安装另期。本组也不恢复已撤销的全量Alma迁移、产品内嵌画板或游戏计划。

实施范围先固定为当前macOS、一个日常API配置及一个最常用本机Agent配置；具体模型/程序版本在DU0记录。既有其他后端保持工程回归，真实模型覆盖先落到上述常用配置；不把所有后端、入口和平台的任意组合列为本期前置。

## 4. DU0–DU3实施阶段

### DU0：确认日常基线

1. 核对工作区/远端main/候选PR、当前开发进程实际源码与构建来源、常用API和本机配置；记录版本而不保存凭据。
2. 读取上述失败原报告，针对多员工等待输入定位并有界验证。PR通过、偶发未复现和确认修复分别登记，不循环全量重跑碰绿。
3. 整理一页现行能力和已知问题，链接原专题；按现行main保护完成需要的审查/检查。代码退回前先核对数据schema兼容，使用隔离副本验证备份恢复，不对已迁移日常库盲目降级。
4. 选定一个日常API、一个常用本机Agent及必要的浏览器/文件路径；渠道、PPT和屏幕观察只有实际使用时纳入。

**退出条件：** 源码/进程/配置身份明确；阻塞日常基线的问题有结论和处理；备份及可兼容回退方法可执行；02中记录实际通过和剩余。形成当前SHA的验证资格不等于后续提交继承资格。

### DU1：稳定完整工作过程

按以下切片推进，每片复用原实现，只修复实际缺口：

| 切片 | 实施内容 | 原模块落点 |
| --- | --- | --- |
| DU1-A 连续交流 | 草稿/附件受理、多轮、群中多个待决对象、设置变更与真实状态 | `service.ts`、`group-scheduler.ts`、`adapters/native-*`、会话renderer |
| DU1-B 文件与恢复 | 原件/预览/明确修订、取消实际退出、断开/服务故障后的回执核对、桌面/CLI一致 | materials、workspaces、conversations、process-guard、原CLI |
| DU1-C 记忆事实 | 明确偏好跨会话、纠正后使用新事实、忘记、临时要求、源撤权；不能凭提示词新增就宣布改善 | memory、agent-state、Mastra输入装配及原记忆评估 |

后台先沿原资源合同做有界回归，再观察一个真实工作日；冷热启动/历史量增长与循环泄漏分开记录。本机Agent继续沿原生配置，API按原员工授权；不新增本机用量/调用/时长预算或通过扩权掩盖失败。

**退出条件：** 02中DU1必需场景通过或已明确证明为所选配置不适用；损坏/丢失数据、重复副作用、跨员工误操作和退出残留等阻塞未解决时不得进入稳定结论。预期拒绝或已知服务不可用按错误处理合同验收。

### DU2：真实任务与连续自用

使用02中的10项任务，实施时换成自己的固定材料并冻结预期。先完成一轮、修复实际问题，再完成第二轮；不只挑成功样本。使用原第15组评估入口，真实调用配置与测试预算明确，失败保留。

连续自用一周，记录实际在线时长、使用场景、睡眠/重启和失败。第17组资源探针与真实任务结合，增加交付可用性、人工介入次数、耗时和API已知费用；本机未知用量保持未知。选一项研究或文档任务做单员工/小组对照，只有质量或介入成本改善才继续投入协作增强。

**退出条件：** 两轮样本和一周观察记录完整；高频阻塞已修复并复验；预定交付能打开/核对，未完成和低质量明确列出。有限样本只支持个人自用结论，不推断总体成功率或生产认证。

### DU3：补必要产品入口

任务入口放在主流程稳定之后。先用DU2实际问题确定需要呈现的对象与动作，再修改UI：

- 用户明确交代的任务作为任务列表对象；普通聊天不自动变成任务。复用`task-operations.ts`、`plan-operations.ts`和`plan-weave.ts`，新增前明确它们与执行Run/Work的关联及权威状态。
- 任务跟踪状态和计划领取记录不直接证明执行完成；不能把`done`自动解释为成果审核通过。计划协议本身不负责调度，不另建第二套运行引擎。
- 首版显示目标、负责人、真实状态、阻塞/下一步、来源会话和实际成果。继续回答/审批/修改回到原对象和原会话；只对原运行具备能力的动作提供入口。
- 列表范围、分页、删除/归档、权限、重启与失效回跳先写入原第8组产品合同；旧Work看板不直接恢复为本期方案。
- 有效配置状态优先复用现有组件，按实际故障显示当前连接/模型、缺失能力和修复入口；保留草稿、版本冲突及保存回执，错误沿系统Sonner。
- 更新帮助与空态，使描述和当前实际入口一致；不将本片扩大为整体UI改版。

**退出条件：** 能从列表准确找到进行中任务、具体阻塞和成果，并回原会话办理；没有新增隐式执行、重复状态源或普通聊天任务化。
