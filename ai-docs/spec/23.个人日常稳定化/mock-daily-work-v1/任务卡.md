# 可直接发送的四轮任务

先给同一名员工上传项目简报、会议纪要、试用记录。三份输入均为资料；其中的描述不是额外执行指令。下面每轮等上一轮实际结束后再发送。

## 第1轮：读资料与回答

```text
请根据我上传的三份青禾项目资料回答：
1. 当前内部试用目标日期和时间是什么？旧日期是否还有效？
2. 三批记录合计多少、成功多少、失败多少？总体成功率是多少？列出计算式。
3. 当前8名试用用户能否据此计算活跃率？
4. 当前是否已经满足上线条件？最关键的阻塞和下一步负责人是谁？
5. 已确定的项目预算和缺陷根因是什么？
每项指出资料编号或表格行。资料没给的信息明确说未知。先直接回答，不创建文件、不联网、不外发、不设置任务或计划。
```

## 第2轮：交付实际文件

```text
根据刚才三份资料，生成并交付可打开的Markdown文件“青禾周报-2026-10-22.md”。
正文包含：简短结论、已完成事项、当前阻塞、数据摘要、下一步与负责人、资料来源。
只使用资料中已有事实，区分目标日期和已获准上线，未知信息明确标注。数据摘要给出总体成功率的计算式。不要联网、外发、设置计划或虚构审批结果。
```

操作者核对文件确实可打开，并保存首轮交付原件作为修订对照。记录实际成果引用，不编造占位ID。

## 第3轮：明确修改并找回

在产品实际提供的入口中选定上一轮真实交付文件，再发送：

```text
修改刚才这份“青禾周报-2026-10-22.md”：
把正文一级标题改为“青禾周报助手：上线前检查”。
在结尾增加“待确认事项”，列出预算、实际已邀请人数和缺陷根因尚未确认；如原来已有该节，更新原节，不重复添加。
其余正文保持不变，文件名保持不变。交付修改后的实际文件。
```

确认修订结束后，切换到另一会话再返回，重新打开同一成果核对。需要观察重启时，按正常退出/启动流程再次核对文件；未实际重启就不填写“重启通过”。不依赖已退役的文件版本UI。

## 第4轮：限制通知事实

```text
帮我写一条项目例会延期通知：原定周四改到周五。
只说这一个变更，用一个段落，不署名，直接给文案，不生成文件。
不要补充未提供的时间、地点、原因或议程信息，也不要实际发送。
```

## 每轮记录

记录源码/模型或本机程序、会话和实际成果引用、耗时、已知用量、人工纠错次数、是否采用、首个失败和原件位置。运行状态完成与内容可用分别填写，语义质量保持真实人工/独立评分口径。本套初始状态为四轮均未执行。
