## 3. 10项真实自用任务

以下是首批题型，尚未选定用户材料。DU0替换为实际常用任务，冻结输入、预期、允许动作与后端。每项先跑一轮，修复后第二轮完整记录；失败样本保留，同题材料更新另登记版本。

| ID | 任务 | 可用结果判定 |
| --- | --- | --- |
| UT01 | 根据两份固定资料回答一组实际问题 | 事实可定位来源；资料没有的内容明确未知 |
| UT02 | 使用已选检索服务补充资料并整理研究结论 | 引用实际读取内容；区分登录限制/提取不全，不补造正文 |
| UT03 | 根据材料生成一份实际需要的文档 | 正式交付文件可打开，满足事先列出的内容要求 |
| UT04 | 对UT03提出明确修改，切换会话/重启后继续 | 修改准确作用于目标文件，原结果和新结果可核对并找回 |
| UT05 | 本机Agent完成隔离目录内的小开发任务并通过终端或预览检查 | 文件变更符合要求；报告实际运行/未运行检查；进程正确收尾 |
| UT06 | 同一项工作跨桌面和CLI交接，过程中回答一个待决问题 | 上下文、目标与结果一致，问题只作用于正确员工/运行 |
| UT07 | 设置一个实际长期偏好，在新会话纠正并忘记 | 当前事实被使用；纠正/忘记生效；临时要求未持久泛化 |
| UT08 | 设置一项实际有用的定时资料整理或提醒 | 正确到期、等待/失败清楚、结果可找回；无重复副作用 |
| UT09 | 给两名员工分工完成研究/文档任务，并做单员工同题对照 | 依赖与最终交付正确；比较结果质量、人工介入和耗时 |
| UT10 | 从一周历史中找回指定结果及待办，并在隔离副本恢复备份 | 具体来源可定位，已保存数据与文件可核对，未重放执行 |

预定交付形式由题目决定：问答不强制生成文件。外发、删除、屏幕观察等动作不因纳入题目就自动获得权限。真实渠道/PPT/日报若成为高频工作，可在开跑前替换一项题型并保留更改原因，不无限扩张样本。

### 每次任务记录

| 字段 | 记录规则 |
| --- | --- |
| 身份 | 任务/输入版本、源码SHA、后端与模型/程序版本、会话/run/成果引用 |
| 结果 | 可用 / 需小改 / 不可用 / 未完成；对应预定要求与实际文件/来源 |
| 介入 | 补充信息、审批、纠错、返工分别计数；正常审批不算故障 |
| 耗时 | 总耗时、等待用户时间、执行时间分别记录，不把等待混作模型耗时 |
| 费用 | API只记录实际已知用量/费用；缺失为未知；不给本机增加BOAI预算 |
| 失败 | 首个阻塞、重试/修复次数、是否恢复、原失败与后续复验引用 |
| 质量 | 人工采用意见与独立judge结果分开；完成状态不代替质量判断 |

业务结果由人工依据预先要求核对，judge可辅助。复用既有eval，不新增自动无限优化循环。模型实验在实际授权后登记配置、请求预算和停止条件；本表数量不构成调用授权。

## 4. 连续自用与资源观察

1. 先复用第17组短期压力合同和门槛，之后记录一个真实工作日的在线小时数、负载及资源变化，再连续自用一周。睡眠、退出和中断如实记入时间线，不写成连续168小时运行。
2. 每日记录实际使用场景、定时触发/失败、卡住位置、是否需重启、恢复方式和数据结果。没有触发的功能标未覆盖，不为补表制造外发或个人数据变更。
3. 分别采样Main/runtime/Renderer堆、工作集、CPU、DOM/监听器及浏览器/终端实例；沿原资源合同单位和口径，区分预热、历史增长、缓存与持续不释放。
4. 长时段不能直接套用短期固定阈值宣布无泄漏。记录相同空闲窗口的趋势；新增单调增长、卡死或无法退出时定位归属，并沿同负载复验。实际配置和使用时长决定结论范围。
5. 修复影响已有结论时，更新SHA并重跑受影响场景；保留其他仍适用的证据和适用依据。出现严重问题期间的观察不计作“无阻塞稳定期”，修复后补足受影响的连续观察窗口。
