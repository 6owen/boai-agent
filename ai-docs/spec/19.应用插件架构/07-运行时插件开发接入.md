# 运行时插件开发接入

当前提供受信本地包接入，Mastra继续运行API员工。新增ACP程序只需声明包；专有协议使用预构建ESM模块。宿主兼容Runtime API 1，并提供带私有模型来源的Runtime API 2；接口仍是候选版，实际类型以`src/shared/plugins/runtime-api.ts`为准，清单以`runtime-catalog.ts`为准。

## 构建与安装

```sh
node scripts/build-runtime-plugins.mjs
```

生成三类产物：

- `dist/runtime-plugin-sdk/`：独立TypeScript接口与`manifest.schema.json`，不依赖`AppService`或BOAI数据库。
- `dist/runtime-plugin-packages/pi/`：Pi RPC模块、清单、许可；可单独安装/更新。
- `dist/runtime-plugin-packages/opencode/`：复用共用ACP驱动的模块包，增加已验证OpenCode模型来源配置。通用ACP声明包仍使用v1。

完整应用构建和Vitest前置也会构建这些产物。设置 → 插件 → 安装或更新插件，选择包含`manifest.json`的文件夹。安装不执行npm脚本。初次内置Pi/OpenCode已可选，无需再安装相同包。

插件页操作受包目录内容hash及列表revision约束。升级保留原启停偏好，且须等待活动执行实际退出；原连接会显示需要重新测试。卸载只删除当前包代码，保留连接、员工、聊天和成果。卸载内置插件的外部覆盖版本后，恢复为停用的内置版本。

使用流程：模型连接 → 扫描本机Agent → 选择程序 → 测试 → 保存 → 员工选择该连接。测试只握手，不调用模型。Pi的原生账号仍由Pi登录系统管理；握手通过不证明供应商凭证可用。

## ACP声明包

文件夹内放以下`manifest.json`和真实`LICENSE`；将命令及参数替换为该程序官方提供的ACP入口：

```json
{
  "id": "example.runtime.my-agent",
  "version": "1.0.0",
  "apiVersion": 2,
  "name": "My Agent",
  "description": "通过ACP接入本机程序。",
  "contributions": [{
    "type": "agent-runtime",
    "providerId": "my-agent",
    "runtimeApiVersion": 1,
    "driver": { "kind": "builtin", "id": "acp" },
    "discovery": { "commands": ["my-agent"] },
    "launch": { "args": ["acp"] },
    "configSchemaVersion": 1,
    "configSchema": { "type": "object", "additionalProperties": false, "properties": {} }
  }]
}
```

发现命令是只读PATH匹配，实际程序由用户选择并固定hash，不通过shell拼接参数。当前每包一个provider。握手读取`agentInfo`、`loadSession`、图片和HTTP MCP能力；未知/未声明能力不按品牌推断。BOAI产品工具通过独立、随机认证的loopback HTTP MCP桥提供；不支持HTTP MCP时可以普通聊天，但不会提供成果发布、委派、自动化或应用浏览器工具。模型设置使用ACP `configOptions`中的model选项，缺少时留空使用原生默认值。

## 专有协议模块

`driver`改为`{ "kind": "module", "entry": "provider.mjs" }`，包内放完整预构建模块及许可。依赖应打包进模块；不依赖BOAI内部路径或运行时联网安装依赖。

模块导出：

```ts
import type { RuntimeFactory } from './runtime-api'
export const runtimeApiVersion = 1
export const createRuntime: RuntimeFactory = services => {
  // 返回probe/openSession/submit/interrupt/inspect/closeSession的实现。
  // 完整可运行参考：src/runtime/adapters/plugins/pi.ts。
  throw new Error('必须实现该程序的原生协议')
}
```

`services.launch`仅含已选择的程序、工作目录、私有会话目录、模型ID和有限配置。`services.tool`/`services.action`回到宿主原业务权限；不提供SecretStore、任意IPC或数据库对象。模块在专用进程中运行，继承当前原生环境（包括自定义配置目录、provider环境引用、PATH和代理/CA），HOME/USERPROFILE按所选登录模式处理，不复制登录文件。该进程具有本机用户权限，不能作为不受信代码安全沙箱。

| 合同 | 插件责任 |
| --- | --- |
| `probe()` | 真实协议/版本核对；不得调用模型 |
| `openSession()` | 只续用当前员工×会话的引用，返回会话ID及可选持久引用 |
| `submit()` | 仅提交一次；有上游证据才emit `input.accepted`，真正结束才emit `session.idle`并返回最终正文 |
| 消息事件 | 正文/思考用稳定块ID；`message.completed`覆盖同一块，工具事件用原callId |
| `services.action()` | 等待用户原生选择；写入答复不等于上游已接续，有后续协议证据才emit `action.resumed` |
| `interrupt()` | 处理本实例所属队列并请求取消；宿主仍等待监督进程树实际退出 |
| `closeSession()` | 释放本次进程/服务/订阅；不删除业务数据或用户登录 |
| 错误/断开 | 不重发submit或工具，不以stdin写入/退出码冒充完成 |

当前每次业务执行一个插件进程，进程退出后保留原生session映射。Pi使用严格LF分帧、prompt回执、`agent_settled`和队列清理；最低验证版本0.85.1。没有自动重连或业务重试。原生运行不受BOAI模型调用/Token/任务时长预算限制；初始化/协议回执/收尾仍有控制超时。

配置schema首版仅支持有限string/number/boolean及enum；全部字段可选，不支持任意React、嵌套表单、密钥字段或迁移脚本。`steer/followUp`属于provider可选方法，目前BOAI普通发送沿宿主队列开启下一轮，不直接调用活动steer；待决action使用独立回调。

```sh
pnpm test:electron --grep '运行时插件'
```

前者使用真实子进程和离线协议，覆盖独立安装、内容变化、停用、会话隔离、交付、审批、委派、自动化、未知及停止；后者沿真实Electron操作。真实已安装Pi探针另有显式开关`BOAI_TEST_INSTALLED_PI=probe`，`live`会产生真实模型请求，默认跳过。详细结果和未验证项见[06](./06-Agent运行时插件实施计划与验收.md)。

发布包必须自行验证目标程序版本，并随附来源/许可和协议合同结果。当前未发布插件市场或稳定公共SDK；OpenCode 1.19.3已新增实际三协议本机HTTP核对，详细结果归第20组02 §6.10；不能把这批请求验证写成OpenCode全业务通过。


## Runtime API 2：明确模型来源

应用插件清单仍为`apiVersion: 2`；本节的`runtimeApiVersion: 2`是独立的运行时协议版本。旧`runtimeApiVersion: 1`模块与通用ACP声明包继续按原初始化结构运行，既不会收到来源字段，也不会获得外部模型能力。

有明确来源能力的模块在贡献中声明：

```json
{
  "runtimeApiVersion": 2,
  "modelSource": { "protocols": ["chat", "responses", "messages"] },
  "driver": { "kind": "module", "entry": "provider.mjs" }
}
```

模块同样导出`runtimeApiVersion = 2`。`probe()`必须根据实际程序版本返回所验证的`modelSource.protocols`，不得仅复制清单。宿主逐次核对固定包hash、声明协议、握手能力与版本；不支持时拒绝明确来源，保留原生来源入口，不静默回退。

员工明确选网关时，宿主通过专用初始化帧把`services.modelSource`交给当前模块：`protocol/baseUrl/modelId/apiKey`及可选目录元信息。`baseUrl`是网关有效的`/v1`地址，模型ID保留供应商前缀。该对象不会进入`launch.config`、持久启动项或公开回执；插件不得写入日志、事件或普通配置。私钥由宿主在事件/答复/错误投影前脱敏，这不是对任意受信模块的安全沙箱保证。模块只能在本次子进程使用凭据。

`openSession()`须先取得原生模型来源确认，返回`modelSource: { protocol, modelId }`。宿主验证后才持久登记session并发送本轮用户消息；错配不得提交。Run只保存连接ID/revision、有效协议和所选model，不冒充原生CLI未暴露的逐请求HTTP头部。来源变化沿原运行指纹使新消息新建session，旧回执不回写，未知不重放。

当前内置Pi/OpenCode包为0.2.0。Pi明确来源固定已核对1.3.0，通过临时扩展注册独立provider，密钥为环境引用；Messages使用Anthropic SDK根地址，其余两协议使用`/v1`。OpenCode明确来源固定1.19.3，通过本次进程内联provider/model配置及环境凭据，继续复用ACP；原生工具和权限不由BOAI另设模型父层。其他版本可以按原生来源合同核对，明确来源必须重新验收版本后扩展。

宿主优先使用当前来源目录，缺少条目时尝试一次绑定取消的有界只读目录请求；失败保留手填模型，不重试推理。Pi优先采用服务声明容量；未知contextWindow使用其1.3.0原生的0语义，避免虚构容量压缩输出，未知输出字段沿Pi自定义模型的16384默认值。0费用仅为原生记账占位，不能作为免费报价。原生非模型配置保持原流程；OpenCode可能自行迁移旧格式配置，例如补`$schema`，这与BOAI注入网关设置分开记录。

新增模块门禁为`tests/plugin-gateway.test.ts`；实际二进制HTTP门禁为`BOAI_PLUGIN_GATEWAY_WIRE=pi|opencode`和新`BOAI_MAGPIE_BATCH`执行`tests/plugin-gateway-wire.test.ts`。真实Magpie文件门禁另用`BOAI_PLUGIN_MAGPIE_REAL=pi|opencode`执行`tests/plugin-magpie-live.test.ts`；每个新批次三条消息、最多30次转发请求，实验上限不进入本机产品预算。实际结果与失败唯一见[第20组02 §6.10](../20.模型网关接入/02-实施计划与验收.md#610-2026-10-17piopencode私有模型来源与实际调用)。


## Runtime API 2：原生配置身份

模块可在贡献中声明`nativeSourceIdentity: true`并提供`inspectSource(): Promise<{ fingerprint: string }>`；仅v2模块可声明，返回固定64位小写SHA-256十六进制。方法只读取已知原生配置和继承环境，不调用模型、执行配置命令、输出路径/配置值或读取登录私有存储。未声明的v1/旧模块保持原生命周期。

沿用原生来源时，宿主先用一个短生命周期模块实例进行只读检查，将不透明指纹加入员工×会话兼容性。正式实例在probe后及openSession后、持久登记/submit前再次检查；不一致则拒绝本轮消息，不自动重试。配置改变只让下一次明确新消息建立新session，保留BOAI历史和原未知请求。明确BOAI连接仍按连接revision和有效协议核源，不混用两种权威。

内置Pi读取PI_CODING_AGENT_DIR（或HOME/.pi/agent）的settings/models与已知项目配置；OpenCode读取XDG_CONFIG_HOME下的全局配置、项目配置和OPENCODE_CONFIG/OPENCODE_CONFIG_DIR。文件读取最多256项、单文件2MiB，非普通文件/不稳定读取拒绝；配置目录层级最多64。环境整体不透明哈希以覆盖自定义provider变量，排除运行传输字段，因此无关环境变化也可能保守重建session。auth、会话状态及任意动态引用不包含在文件扫描中；指纹不是实际流量或所有管理配置覆盖的证明。

原生来源门禁为`tests/native-source.test.ts`、`tests/plugin-gateway.test.ts`及显式`BOAI_NATIVE_GATEWAY_WIRE=codex|claude|pi|opencode`的`tests/native-gateway-wire.test.ts`。真实文件门禁为`BOAI_NATIVE_MAGPIE_REAL`配合新`BOAI_MAGPIE_BATCH`执行`tests/plugin-magpie-live.test.ts`；与G2b批次分开留证。OpenCode原生模式的ACP模型覆盖只针对任务模型，title等轻量调用继续原生small_model；依据[固定1.19.3源码](https://github.com/anomalyco/opencode/blob/v1.19.3/packages/opencode/src/session/prompt.ts)，测试按实际请求分开核对，不改写个人配置来消除这类请求。

实际原生来源批次与失败边界见[第20组02 §6.12](../20.模型网关接入/02-实施计划与验收.md#612-2026-10-17原生来源指纹与四运行时实际文件闭环)。CLI首次配置写入仍需产品准备或重新核对流程，不以预置测试profile成功替代首次使用验收。
