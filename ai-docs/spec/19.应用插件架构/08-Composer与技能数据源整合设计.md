## 2. 模型菜单

点击底部模型名称向上展开，触发器只显示当前模型。菜单顶部弱化展示连接来源，例如「使用 Claude Code · 工作 API」；不把连接名称作为模型名称。

```text
使用 Claude Code · 工作 API
──────────────────────────
模型 A
模型 B                  ✓
模型 C
──────────────────────────
推理强度           中等  ›
──────────────────────────
刷新模型
管理模型…
```

1. 模型项直接选择并保存；成功后更新勾选/触发器并关闭。保存中不重复提交；失败保留原已提交模型，错误不显示为成功。
2. 顶部连接为只读。更改运行方式、连接、地址、密钥或权限从「管理模型」进入原员工设置；composer不再复制完整设置表单。
3. 长列表内部滚动，菜单受视口高度约束。当前已保存模型即使不在目录中也保留可见，不自动选择第一项。
4. 推理强度放二级菜单，使用运行时/模型实际支持值；可用时显示「默认、无思考、低、中等、高、超高、最大」中的适用子集。不得把Craft六档无条件映射给所有模型。
5. API模型目录沿原连接接口；本机模型目录沿本机provider/profile，不按程序品牌猜型号。当前目录仅有字符串的接口需要补充能力元数据，不能从型号文字推断强度。
6. 没有目录时显示当前模型与「管理模型」，允许原设置手动填写。目录读取失败保留当前选择并可刷新。
7. 模型与推理修改仅更新所选字段，必须保留nativeOptions中的原权限、runtime绑定和其他员工字段。
8. 沿现有员工配置版本核对和实际执行锁；生效范围是该员工之后的会话，不声称只影响当前聊天。运行期间不可换模型，仍可查看和编辑消息草稿。
9. 不增加截图中的视觉能力切换和token计数；若以后展示，取实际能力与会话用量，缺失显示未知。

## 3. `/` 命令与 `@` 提及

### `/` 命令

参考Craft的紧凑列表、分组、输入筛选及键盘行为。命令名与说明分行，底部提示「使用 @ 提及技能和文件」。已有功能可先纳入：

| 命令 | 本次可复用行为 |
| --- | --- |
| `/summarize` 总结会话 | 填入现有总结草稿，用户发送后才调用员工 |
| `/todo` 整理待办 | 填入现有待办草稿 |
| `/files` 查看文件 | 打开原文件面板，不发送消息 |
| `/workspace` 打开工作目录 | 沿现有宿主打开目录 |

`/compact` 预留为未来真实上下文压缩命令；只有运行时明确支持且已接回执时才可点击，不能以“请总结”冒充原生压缩。后续native command目录与BOAI命令分组，重名不覆盖、不暗中替换消息。

按用户第3项，先隐藏权限批准控件和截图中的Modes分组；不出现可点但无行为的探索/询问/执行。未来再按不同运行时接入用户批准/全部执行。隐藏入口不改变员工现有权限值和正在等待的真实批准请求。

### `@` 提及

```text
提及技能和文件
  ⚡ research                 技能
  ⚡ writing                  技能
  ▤ 项目简报.md              文件
  ▤ 销售明细.xlsx            文件
```

- 单聊只列当前员工已绑定、仍有效的技能；全局已安装目录不能直接作为员工候选。
- 首版文件复用`queryConversationFiles`，按当前单员工conversationId读取，限定已发送材料与该员工已完成发布的文件；跨该员工多个会话的聚合提及本轮未开放。不递归扫描电脑，不把未完成临时产物当交付文件。
- 群聊保留既有原子成员标签；技能需要明确所属员工，不因为提及技能自动分派给另一成员。首版可先仅在单员工上下文开放技能和文件。
- 插入资源标签后保留草稿、光标和输入法行为，支持整体删除；不在选择时发送消息或调用工具。
- 文件标签携带真实来源身份与hash/版本，技能携带resourceId与绑定版本；同名文件不能仅靠名称定位。发送前重新核对绑定/来源，失效则明确提示重选，不静默读取另一个版本。
- 资源提及用于明确本轮引用，不产生永久绑定，也不绕过员工权限。数据源上线后可加入同一个提及目录；首版标题不承诺尚未接入的数据源。
- 文件与技能目录按打开/搜索读取，离开或关闭停止读取；分页有界、迟到结果不能进入另一员工菜单。

**数据源详情：** 顶部图标、名称、简述、状态、更多操作；正文展示说明、连接配置摘要、可用工具/范围、绑定员工。提供配置、测试连接、绑定员工、停用/移除；未连接、待授权、连接失败和已连接分别显示。测试成功不代表所有业务工具均验证。

**添加数据源：** 同一轻量弹窗选择API/MCP/本地文件夹；按类型显示必需项，不设一张混合大表单。

## 5. 与现有plugins的关系

建议采用「前端统一工作区，后端独立sources模块」。数据源是用户可配置的连接实例；插件可以提供数据源实现/模板，也可以携带技能。两者兼容，无需二选一。**先完成API、MCP、本地文件夹三种内置provider；新增插件`source`贡献作为后续装配方式，不作为首版数据源功能的前置条件。**

```text
插件包 / 内置provider
  ├─ source贡献：API、MCP、本地文件夹
  └─ 可选skill贡献：使用这些来源的工作说明
             ↓
全局数据源实例（配置 / 凭据引用 / 状态）
             ↓ 显式绑定
员工能力（sourceIds / 配置版本）
             ↓
本次运行的获准数据源与工具
```

现状：`src/shared/plugins/types.ts`只声明preview/theme/runtime贡献，不能直接假定已有source注册、凭据管理和员工绑定。首版在sources模块装配三种内置provider；以后需要独立包时，再扩展现有manifest/管理生命周期，沿相同provider接口装配。应用主题/预览/运行时继续在设置管理，不都塞入员工资源列表。

| 计划中的职责边界 | 作用 |
| --- | --- |
| 共享自定义工作区壳 | 左侧两个分类与混合已安装列表；右侧切换原技能内容或数据源内容 |
| 现有Skills模块 | 保留本地、收藏、商城、导入、扫描、更新、导出及绑定；不并入数据源持久化 |
| 新增sources模块 | 数据源实例的增删改查、测试、凭据引用、状态与员工绑定；API/MCP/local共用生命周期 |
| 数据源provider | 迁入Craft连接与请求逻辑，适配BOAI存储、凭据和运行时工具包装 |
| 可选插件source贡献 | 将来注册额外provider或预配置模板；插件卸载与数据源实例解绑由宿主协调 |

全局数据源实例只保存一份，员工以`sourceIds`显式绑定；同一连接可以授予多个员工，无需每个员工重复配置。前端是否共用入口不影响后端模块独立开发，所以无需为了开工临时新增一个孤立的一级页面。

宿主拥有凭据读取、员工绑定、运行快照、撤权与真实进程退出；provider负责连接和工具装配。API/Mastra通过现有工具适配入口装配；本机Agent沿原生MCP或通用产品桥暴露真实支持的能力。适配未完成的组合显示不支持，不能静默改用另一引擎。

### 实际业务与架构

- `shared/domain/sources.ts`：API/MCP/local配置，稳定ID与源revision，绑定时同时核对源revision、原绑定集合和每名员工的configVersion。`DigitalAgent.sourceIds`可选字段兼容旧数据。
- `runtime/modules/sources`：独立业务模块，沿现有ProductStore保存配置；凭据单独进入宿主SecretStore，renderer只得到`hasCredential`，不读取明文。保存配置不触发网络或程序启动。测试结果是真实请求/目录访问结果，不能作为将来始终可用的保证。
- API：Base URL、测试端点、无认证/Bearer/Header/Query/Basic；复用固定Craft `api-auth.ts`完整纯认证逻辑和`api-tools.ts`的请求核心。默认GET，可明确开启POST/PUT/PATCH/DELETE；禁止离开配置地址或跟随重定向，响应上限4MiB、文本输出有截断标记。
- MCP：Streamable HTTP、SSE、本机stdio；支持无认证/Bearer或只写环境变量JSON。真实读取服务器工具目录，按实际schema调用；目录分页/工具数量/结果有界。stdio沿现有Rovai进程监督器及所有权账本，取消/关闭等待实际进程退出，启动只恢复遗留进程而不重放业务。
- 本地文件夹：用户选择明确目录，默认只读；列目录与有界UTF-8文本读取，拒绝越界及符号链接。可开启写入，必须提供读取获得的原hash，新增文件显式使用null；沿现有文件操作串行与版本校验。删除数据源不删除外部文件夹。
- 员工授权：可在数据源详情绑定，也可在员工配置选择。仅当前员工绑定、启用且版本一致的源进入本轮摘要；实际读取/调用只允许执行阶段，写入沿现有Work和副作用记录。配置变更/停用/删除阻止旧调用、取消并等待源租约退出；历史来源/派生记忆继续按原运行身份失效。
- 运行时：Mastra任务工具与本机产品桥共用`inspect_data_source`/`call_data_source`及同一宿主权限回调，不另建Agent执行引擎。API密钥、MCP令牌及环境变量值不发送给模型，返回内容/错误/目录按当前凭据脱敏。
- 备份：副本保留源配置但停用、移除凭据引用和测试状态；外部文件夹和MCP私有进程账本不导出。恢复后需要用户核对并重新启用/配置凭据。
