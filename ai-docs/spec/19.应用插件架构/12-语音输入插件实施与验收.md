# 语音输入插件实施与验收

## 1. 当前任务和交付边界

用户确定先落文档并提交推送，后面再开发。当前独立分支为 `feat/voice-input-plugin`，worktree 为 `/Users/wangwenbo/Desktop/demo/boai/boai-voice-input-plugin`，起点为 `origin/main` 的 `a4f6a3b169ffeda8857ca6b3d818819465994693`。本轮不修改产品代码、依赖或安装包，不下载模型，不申请麦克风权限，也不启动产品测试。

产品合同见[11-语音输入系统插件设计](./11-语音输入系统插件设计.md)。这里的系统级指 BOAI 应用级附加功能：在各会话的输入框使用，共享一份模型；不绑定员工，不进入员工工具或 Skills，不成为系统全局听写。

首版的完成目标：用户主动启用插件、按需下载一个本地模型后，点击录音、停止、得到原输入框中的可编辑草稿，再自行发送。关闭插件后不占用麦克风、不保留识别进程或已加载模型，模型文件可以独立删除。

本期不含云端识别、多个模型切换、自动断句录制、VAD、实时字幕、TTS、语音对话、系统全局快捷键、员工主动录音、通用插件市场。后续功能不能借本规格自动进入本轮。

## 2. 已核实的代码起点与改动地图

以下为准备阶段的源码事实，拟新增项均未存在，不代表实现完成。

- `packages/shared/src/plugins/types.ts`、`catalog.ts`：现有贡献类型为 `preview`、`theme`、`web-search`、`agent-runtime`；内置 catalog 为固定受审清单。拟增加独立 `voice-input` 类型及 manifest 的 `defaultEnabled?: boolean`，默认值为 `true`，语音插件明确为 `false`。
- `apps/electron/src/main/plugin-settings.ts`：当前持久格式为严格的 `schemaVersion: 1`，只保存 `revision` 与 `disabledIds`，由主进程串行 CAS、临时文件和原子替换维护。拟增加 v2 与 `enabledIds`，不能把新字段直接塞进严格 v1；读取 v1 时保留其 revision/disabledIds，内存补空 enabledIds，正常获准写入时保存 v2。
- `apps/electron/src/renderer/stores/plugins.ts`：首个权威快照前全禁用，写入失联后只读复核，启用偏好与实际 usage 分开。语音插件沿此入口，不另建一个同名启停真源。
- `apps/electron/src/renderer/pages/settings/plugins.tsx`：应用插件管理入口。拟挂载语音插件自己的模型管理面板，展示真实模型状态、下载量和磁盘占用，不把模型配置混进运行时插件安装面板。
- `packages/shared/src/ipc/index.ts`、`apps/electron/src/preload/index.ts`、`apps/electron/src/main/main.ts`：现有类型化 Desktop API 和可信窗口通道。拟接有限语音请求、取消和状态事件，不公开任意文件路径、命令执行或模型下载地址。
- `apps/electron/src/main/main.ts`：主窗口启用 `contextIsolation`、禁用 `nodeIntegration`，现有 permission request handler 全拒绝。拟仅为主窗口主 frame 的有效录音请求开放音频；`apps/electron/src/main/browser/browser-pane-manager.ts` 的浏览器页面权限拒绝保持。
- `apps/electron/src/renderer/pages/conversations/-components/prompt-bar.tsx`：现有 scope 为会话身份和单员工身份组合，负责候选、选区与 IME；拟在此提供受 scope/revision 保护的文本插入桥，不让插件直接修改整份 ChatDraft。
- `apps/electron/src/renderer/pages/conversations/-components/mention-input.tsx`、`mention-editor.ts`：原子标签、纯文本插入、撤销及会话切换的编辑器真源。当前 `replace` 仅为标签插入建立独立撤销边界，普通文字没有此保证；语音须补独立编辑器事务，保留 `@` 员工和 `$` 资源/提示词原子，不拼接 HTML 或重建整份草稿。
- `apps/electron/src/renderer/pages/conversations/-components/composer-toolbar.tsx`、`chat-view.tsx`、`core-chat-start.tsx`：共同输入入口、活动页和发送锁定来源。插件只贡献可选录音控件，宿主透传当前可用性；空 Bobo 首发同样可录音，但不得提前创建会话。
- `apps/electron/src/renderer/components/app-shell/index.tsx`：当前草稿按会话保存，Bobo 首发使用独立草稿；隐藏页可能继续保留组件。取消条件必须含页面失活，不能只依赖 React unmount。
- `pnpm-workspace.yaml` 已包含 `packages/*`。拟建 `packages/voice-input-plugin`，分别拥有协议、renderer 和 main/helper 入口。此路径为设计提案，VI0 核实构建分发后冻结；根 package、构建脚本只做依赖与资源装配。
- `package.json` 当前 `asar` 打开、`npmRebuild` 为 `false`，没有语音依赖或麦克风用途声明。原生模块及动态库分发、macOS 用途说明、运行时加载路径必须单独验证，不能因 Node 普通脚本可用就认定 Electron 包可用。

宿主只负责类型化贡献、权限、生命周期和 Composer 桥。录音状态机、PCM 转换、本地识别适配、模型管理及专属 UI 由插件包拥有；不把它们继续堆入 `main.ts`、`app-shell/index.tsx` 或员工运行模块。

## 3. 实施顺序

### VI0：核实本地引擎与分发路径

- 目标：用一个模型验证 Electron 下的可行路线，再冻结依赖和目录；不先扩展通用插件框架。
- 首选候选是 `sherpa-onnx` 的 Node-API 绑定和 SenseVoice INT8。识别只在独立 helper 或 Electron `utilityProcess` 中惰性加载；普通线程不构成原生崩溃隔离。renderer 和 Electron main 均不得直接加载识别原生模块。
- 检查当前 Electron/Node-API、目标架构、原生 `.node` 与动态库、asar 解包、路径中空格/中文、子进程启动和退出。优先验证用户实际使用的 macOS 架构；未验证平台清楚标记不支持或待验证，不能展示虚假可用入口。
- 固定一套可再现的模型 manifest：来源 commit、每个文件的精确字节数、SHA-256、许可证及分发条件。只取 INT8 权重、tokens 和必要许可证，不能整仓下载，也不能自动带上浮点权重。
- 已研究候选模型公开标注约 239 MB，tokens 约 316 kB；这些不是整个插件的磁盘占用。分别记录模型最终大小、引擎与动态库大小、首次下载/升级临时峰值和识别峰值内存。
- 验证 16 kHz 单声道音频输入、中文与中英混读、无声、短句、口头修改和数字。原始识别保留说话内容，不调用聊天模型重写或自动执行识别出的命令。
- 冷启动、重复启动、10/30/120 秒输入分别测停止到结果的时间、主窗口响应和 helper 峰值内存。热态测量指 OS 文件缓存及重复启动观察，不意味着首版常驻模型。先登记设备、版本、样本与基线，再冻结可接受阈值；不能在结果失败后反向放宽阈值。
- 同时冻结单次识别最大墙钟时限、采集与转换后的音频总量上限、单块 IPC 大小及在途块数上限；两端校验，超限取消并释放。限值须与 120 秒录音及实际采样/转换开销相容，不以无限缓冲或无限识别等待掩盖异常。
- 退出条件：原生兼容及隔离方案可复现，真实语音样本可用，许可证与模型 manifest 齐全，依赖/构建路径及性能验收阈值落文档。候选不成立时先记录具体失败，再修订选择；不同时实现多个引擎来掩盖未定路线。

### VI1：插件合同、默认关闭和启停

- 新增 `voice-input` manifest/schema/装配入口；通过类型化 registry 连接宿主，不使用 `agent-runtime` 的会话与执行接口。
- `defaultEnabled` 未声明时沿原行为；默认关闭项只在 `enabledIds` 明确出现时启用，任何 `disabledIds` 记录优先。点击启用/禁用在同一个 CAS 事务中更新对应集合。
- 新装和旧配置升级都保持语音关闭；v1 的其他插件偏好、未知 ID、revision、损坏文件/未来版本只读保护保持。没有权威快照、读写失败或不兼容时不激活。
- 插件启用、模型下载完毕、模型加载和正在录音是独立状态。启用仅开放入口，不自动下载模型、打开麦克风或启动识别 helper。
- 禁用首先撤销录音请求与未完成结果身份，停止采集，再取消识别并等待 helper 退出；超时按受控终止回收。不得保留失效的“正在使用”计数。
- 退出条件：默认关闭和旧配置迁移有针对性覆盖，禁用可确定性释放资源，预览/主题/搜索/运行时既有启停行为保持。

### VI2：按需模型下载和磁盘生命周期

- 模型管理属于插件；同一 BOAI 数据目录中的所有员工共用一份，不在会话或员工目录复制。模型位于应用代码/asar 之外，普通更新不重复下载已有校验通过的版本。
- 展示下载大小、实际已占空间及下载/取消/重试/删除操作。下载使用受审 manifest，renderer 只传模型 ID，主进程不接受任意 URL 或目的路径。
- 每次下载先估算空间；使用任务独立 `.part`/临时目录、精确大小与摘要核验、最后原子发布。中断、取消、断网和摘要失败不产生 ready 模型；不得混用不同版本的权重和 tokens。
- MVP 不强制断点续传；重新下载必须明确为新任务，清理旧片段，不静默积累副本。升级时保留原可用版本直至新版本发布，临时空间不足时不破坏原版本。
- 删除模型先禁止新识别、取消当前识别并确认 helper 卸载退出，再删除精确的受管版本。禁用插件保留已下载模型，删除模型不删除会话草稿，卸载/数据清理职责清楚分开。
- 原始录音优先在内存中转换/传递；确需临时文件时用受管、随机命名目录，成功、取消、错误和退出都清理，启动时清理过期遗留。不写会话材料、记忆、业务备份或含正文的日志。
- 退出条件：下载错误与取消可恢复、大小核验准确、升级不破坏旧模型、删除无正在使用的文件、无孤立临时音频。

### VI3：麦克风权限和单次录音

- 用户点击录音后才申请权限。宿主验证发起 webContents、主 frame、实际可信页面和当前有效请求；只允许 microphone/audio，不放开 camera、desktop capture 或嵌入浏览器页面。
- macOS 补用途声明并走系统麦克风授权。拒绝/受限/缺设备由现有 Sonner 告知；必要的系统设置操作明确指向用户动作，不反复弹授权。
- 权限请求可能长时间没有回复；取消后即使系统迟到批准也不能开始录音，已经得到的 track 必须立刻停止。
- 首版最长单次 120 秒，到限停止采集并转写；显示必要计时，禁止无限 PCM 累积。16 kHz 单声道 PCM16 的 120 秒音频约 3.84 MB，该值不包含采集及转换中间缓冲。
- 采集格式通过明确重采样得到引擎需要的格式，不能只靠 `getUserMedia` 的建议参数推定实际采样率。停止时关闭全部 media tracks、AudioContext/worklet 和事件监听，再进入识别阶段。
- 页面失活、会话/员工切换、窗口隐藏、插件禁用、renderer 销毁或应用退出都会使当前录音会话失效并释放采集。窗口 blur 是否等于离页必须按11合同实现，不能因系统授权弹窗暂时抢焦点误取消；hide 与非活动页面必须覆盖。
- 系统睡眠或锁屏使权限等待、录音、识别及待插入结果失效；通过宿主初始快照和带revision事件校验，唤醒/解锁不自动恢复采集。模型下载在睡眠、停用、退出时取消并清理，重新下载由用户发起。
- 退出条件：真实设备能授权/拒绝/再次使用，取消和迟到批准不会开麦，应用隐藏后系统麦克风指示结束，跨页无后台录音。

### VI4：转写到原 Composer 草稿

- 一次录音请求绑定不可复用的 session ID、原 Composer scope、视图实例 token、草稿代次/修订、插入位置和插件启用代次。同一会话的主视图与侧栏也须区分。全应用只允许一个有效采集/转写会话，重复点击不并发占用设备或模型。
- 停止后创建有限识别任务，返回结果前再次核对当前身份、页面活动、编辑权限和取消状态。请求完成只产生文本，不调用发送方法、创建会话、启动 Agent 或执行 `/` 命令。
- 原 scope 与草稿修订仍匹配时，在原选区通过原子编辑器插入纯文本，并形成独立撤销步骤。转写文本中的 `@`、`$`、路径或命令只是普通文字，不自行变成带权限的资源/员工标签。
- 录音或转写期间用户继续编辑时，不用旧草稿覆盖新内容；保留本次结果供用户明确插入当前合法位置。该结果只在原活动 Composer 的本次插件会话中保留，导航、禁用或取消后失效清理，不偷偷插入其他草稿。
- 保留附件、网页引用、回复/修改目标、资源与提示词快照，以及原发送去重/待核对流程。`draft.submission`、旧渠道只读、明确回复待核对或原输入锁定时，语音不能绕过锁定；普通发送前若录音仍在进行，必须先结束或取消本次输入，不能把迟到结果追加到下一轮。
- Bobo 未有会话时使用当前首发草稿的独立身份和 generation，并给 `core-chat-start` 补显式活动信号；不能只凭 `new:agentId` 判断仍是同一份草稿。识别完成仍不落一条空会话，实际发送才走原创建与消息事务。
- 录音/停止/取消和下载进度是必要交互；说明归就近 Tooltip，失败沿 Sonner，不添加重复标题说明、内联错误 Banner 或“保存成功”常驻 DOM。原 Composer 键盘、焦点与 IME 保持。
- 退出条件：原会话得到可编辑文字，撤销只撤销本次插入，修改中的草稿不丢失，切换目标和迟到任务不会污染其他会话，发送仍由用户主动触发。

## 4. 固定验收场景

每场记录当前 SHA、模型 manifest 版本、运行环境、操作/预期、实际结果及失败原因。没有执行的场景保持“未执行”，不能沿用其他插件或旧提交的测试数量。

- A01 新装/升级：语音默认关闭，无网络下载、授权弹窗、麦克风 track、识别 helper 和模型内存；其他插件原状态保持。
- A02 配置兼容：v1 读入、首次写 v2、未知 ID、未来版本、损坏配置、CAS 冲突及写回执丢失；只读复核不能造成重复启用或清空其他偏好。
- A03 启用但无模型：只显示可下载入口；拒绝下载仍可正常打字；模型未就绪时不能开始录音，不能伪装为已可用。
- A04 下载故障：取消、断网、空间不足、权限不足、长度或摘要不符、应用退出；没有半成品 ready 标记，重试和清理不碰其他文件。
- A05 升级/删除：应用更新复用已有模型，失败升级保留旧版本，识别期间删除先取消卸载；删除后仍能打字并可重新下载。
- A06 设备与授权：首次批准、拒绝、系统受限、没有麦克风、授权请求未响应/迟到返回、设备断开，均有明确结果和完整释放。
- A07 正常输入：短中文、长中文、中英混读、数字/时间/标点；停止后可编辑，再手动发送；收到的 Agent 消息正文来自最终草稿。
- A08 空 Bobo：录音、取消、转写和编辑均不提前创建会话；只有原发送入口建立会话及消息。
- A09 编辑竞争：识别期间打字、删除、选区改变、IME、撤销、追加附件/引用，原内容完整保留，转写不会使用旧快照覆盖新草稿。
- A10 身份竞争：切会话、切员工、进入设置、打开搜索或其他隐藏但未卸载原页的界面、同会话主视图/侧栏、关闭窗口、禁用插件，原任务取消，迟到结果不能进入新目标；Bobo 退回后同名新草稿也不能接收旧结果。
- A11 原子与发送语义：`@`/`$`/提示词原子保留；识别的同形文字不冒认标签；一次插入可单次撤销；回复/修改/发送待核对/只读状态不能被语音绕过。
- A12 有界录音：120 秒到限停止，重复点击不建立多任务；停止/取消后 track、AudioContext、监听器和临时缓冲释放。
- A13 识别故障：helper 启动失败、模型损坏、原生进程崩溃、超时及取消；主窗口和原草稿可继续使用，重试没有旧结果混入。
- A14 离线与隐私：模型已下载时断网完成识别；原音频不成为附件/记忆/业务备份，不出现在日志或遥测，不因识别内容自动发网络请求。
- A15 生命周期：连续录制/取消/转写、插件反复启停、离页再回、应用退出重开；不积累 helper、track、监听器、音频临时文件或重复模型。
- A16 UI 与可访问性：键盘可操作录音/停止/取消，Tooltip/aria-label 与实际状态一致，窄窗/明暗主题和原发送控件正常；错误沿现有 Sonner。
- A17 发行路径：被验证架构下的当前包能找到 helper、原生模块、动态库和模型，麦克风声明有效；代码或数据目录包含空格/中文仍工作。未验证架构和系统单列限制。
- A18 性能与质量：使用 VI0 预先冻结的设备、样本、中文质量、冷/热延迟和内存阈值报告结果；不能用 UI 桩替代真实识别，不能只挑成功短句证明总体可用。

## 5. 完成标准与最小接续顺序

首版完成必须同时满足：可选且默认关闭；一份模型按需下载/删除；真实录音本地识别成功；只写原合法草稿；不自动发送；错误/取消可恢复；禁用后资源完全释放；原编辑和插件行为保持；目标平台源码及实际包的必需场景通过。

任何缺项都保留在唯一进度中，明确属于实现未完成、代码检查未执行、真实设备未验证、性能未达标或平台未支持，不能合写成“基础功能完成”。

接续时先读取11、本文§7、共享开发流程及当前工作树，再核对 main 与本分支变化。首批只做 VI0：冻结原生 helper 路线、单个模型 manifest 和真实测量方法。通过后依次实施 VI1–VI4，再完成 VI5；不先往核心 UI 加常驻麦克风按钮。
