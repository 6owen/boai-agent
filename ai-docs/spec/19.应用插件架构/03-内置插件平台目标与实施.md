# 内置插件平台目标与实施

## 1. 用户确认的目标

将BOAI内置可扩展能力装配为可识别、可管理、可启停、配置可持久恢复的插件，先覆盖文件预览和主题。用户明确选择本轮完成内置平台，第三方包安装、外部代码隔离、商店与自动升级另期。

已有P1只是预览注册表。本轮完成必须让用户在设置中实际管理插件，并证明两类扩展沿同一清单/配置/生命周期工作；不能只移动目录或增加静态列表。

## 2. 完成条件

| 目标 | 交付 | 验收条件 |
| --- | --- | --- |
| G1 统一插件合同 | 稳定id/版本/宿主接口版本、名称/说明、类型化贡献，受审内置目录 | 重复id/非法声明拒绝；不兼容不可启用；预览与主题共用目录及启停配置 |
| G2 宿主配置 | 主进程读写固定插件配置，CAS/串行原子保存及只读错误恢复 | 重启保持启停；陈旧写入不覆盖；损坏/未来版本保留原件、不自动重写；未知插件配置保留供未来版本 |
| G3 管理界面 | 设置中的插件列表、搜索/类型筛选、启停与实际使用/故障状态 | UI操作真实落盘；提交失败显示错误并回读确认状态；不伪造安装/激活成功；沿BOAI现有Card/Switch/Select |
| G4 预览接入 | 原四类查看器消费统一启停快照；独立视图使用计数/故障 | 当前阅读不被停用或后台事件替换；新打开不激活停用项；隐藏/关闭释放引用；原选区/交付切版/来源失效保持 |
| G5 主题接入 | 现有VS Code Plus、Base46配色作为两个数据型插件，BoAI默认配色为宿主保底 | 停用即回退默认，原选择/自定义色/Scenic偏好不被删除；重启仍回退，重新启用恢复；外观选择只列可用配色 |
| G6 验收与开发接入 | 两类扩展接入说明、合同/生命周期测试及Electron实际结果 | 新插件不修改业务预览页；新批次验证管理/重启/主题回退与原预览流程；保留失败、截图和实际构建身份 |

## 3. 职责与行为

- 主进程掌握配置真源，IPC仅接已知插件id、布尔启停和所见revision，无任意路径/模块加载/代码执行。
- shared保存纯数据清单与可验证合同；renderer负责受审组件装配和每个视图的实际使用状态。启用表示可被选择，不等于已经激活。
- 预览停用停止新选择，当前视图固定原provider直到关闭/隐藏；这是正常只读生命周期，不撤销文件权限。清理/撤权仍由业务宿主立即移除正文。
- 主题贡献纯配色数据，不提供全局脚本、任意CSS、远程字体或网络资源。停用不改写保存的主题选择；BoAI默认配色始终可用。
- 插件配置为本机应用偏好，使用独立固定文件，不加入业务备份；换设备恢复业务后使用该设备插件偏好。插件代码随应用发布，不能在管理页卸载内置源码。
- 同renderer的内置插件不是安全沙箱。故障展示只记录插件身份与有界错误类别，不记录文档内容；死循环/OOM和第三方攻击隔离不在本轮保证内。
- 员工/会话、Work、文件权限/hash/版本、原件发布/清理、外部副作用回执、原生Agent循环及本机无BOAI预算规则仍属核心，不迁入插件。

## 4. 实施顺序

1. 冻结本目标及声明/配置合同，建立内置目录，迁移预览声明和主题数据。
2. 接主进程配置存储/初始化/事件与renderer状态；实现启停实际语义和生命周期观测。
3. 接设置插件管理页和外观可用主题，补接入说明。
4. 运行模块、类型、lint、构建和独立Electron；核对画面、构建身份及失败修复，达到全部完成条件再收口goal。

## 7. 范围与后续

内置平台目标完成；外部包签名/安装升级/卸载、插件市场、独立进程或iframe隔离、跨插件依赖和第三方稳定SDK另立目标。不要直接把现有React内部合同公开为第三方安全接口。真正需要新增文件格式或额外业务能力时，先核对宿主有界读取/权限接口，再增加贡献类型。

本轮未新增Git提交或推送，未改用户真实插件偏好；所有启停/坏配置测试使用独立临时数据目录。
