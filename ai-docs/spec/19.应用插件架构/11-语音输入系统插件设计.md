# 语音输入系统插件设计

## 1. 本轮决定与状态

用户确认先在独立 worktree 落实文档，再 `git cp`；产品开发放到后续。本文件固定第一版设计，实施计划与唯一进度见 [12-语音输入插件实施与验收](./12-语音输入插件实施与验收.md)。

“系统级插件”指 BOAI 应用级的可选附加能力：用户启用一次，即可在支持的会话输入框使用；无需给每个员工绑定技能。它不是 BOAI 必需的核心系统功能，也不是操作系统全局输入法或听写服务。

首版只实现一条链路：

1. 用户在插件设置中启用语音输入，明确下载本地识别模型。
2. 在会话输入框点击麦克风，明确授权本次录音。
3. 用户停止录音后，在本机将这一段音频转成文字。
4. 在原输入框安全地插入文字，用户检查、修改后沿原发送流程提交。

当前没有新增插件代码、依赖、模型文件或麦克风权限，没有进行真实录音、识别质量或打包验证。文中的接口名、目录和状态是拟定合同，不能作为现有 API 使用。

## 2. 第一版范围

包含：

- 默认关闭的内置可选插件，独立拥有交互与识别实现。
- 手动开始、停止、取消录音；同一应用同时只允许一个录音/转写会话。
- 本地离线识别，停止后一次性生成草稿文字。
- 模型按需下载、校验、磁盘占用展示与删除；模型供当前应用数据目录下的所有员工共用。
- 支持现有普通单聊、群聊以及空 Bobo 输入框；仍由宿主决定输入框是否可编辑。
- 主窗口可信音频授权、录音和异步结果的生命周期清理。
- 中文输入、夹杂英文与常用产品名的实际质量评估；结果可以人工修正。

首版不包含：

- 云端转写、API Key、自动云端兜底、多个识别引擎同时交付。
- 实时逐字转写、VAD 自动断句、唤醒词、持续监听、语音对话、TTS 播报。
- 系统全局快捷键听写、向其他应用输入、桌面声音录制、会议录音与文件批量转写。
- 员工工具、技能绑定、Agent 自动打开麦克风、语音自动发送或自动执行任务。
- 第三方语音插件市场、任意远程代码安装器、通用不受信插件沙箱。
- 识别后再调用 LLM 自动润色；原文是否修改由用户决定。

已存在的员工语音生成/音频分析技能与本功能各自独立，不能用其先前验证代替输入插件验收。

## 3. 现有源码事实

本次以 `a4f6a3b169ffeda8857ca6b3d818819465994693` 为设计基线，后续实施前重新核对变化：

- `src/shared/plugins/types.ts` 目前包含 `preview`、`theme`、`web-search`、`agent-runtime` 四类贡献，没有录音输入贡献；兼容项只按 `disabledIds` 判断，未被禁用即启用。
- `src/shared/plugins/catalog.ts` 使用严格 schema 校验并冻结受审清单；普通应用插件来自固定目录，不扫描任意外部包。运行时贡献要求 API 2，不能拿它的 Agent 会话协议承载语音输入。
- `src/main/plugin-settings.ts` 的持久格式是 `schemaVersion: 1`、`revision`、`disabledIds`；采用串行 CAS、同目录临时文件与原子 rename。坏文件/未来版本保留原件并只读，未知禁用 id 保留。
- `src/renderer/stores/plugins.ts` 在权威快照到达前禁止激活，启停通过 `expectedRevision` 写入；失联后回读，不重复写入。`PluginUsage` 区分启用与实际使用。
- `src/renderer/pages/settings/plugins.tsx` 已有插件搜索、类型和启停管理，但当前状态文案偏向“预览关闭后生效”，语音不能照搬该停用语义。
- `src/main/main.ts` 的主窗口开启 `contextIsolation`、禁用 `nodeIntegration`、启用 `sandbox`；当前 session 的权限请求全部拒绝。语音输入需要一个窄的音频例外，不能把 `media` 请求整体放开。
- `src/main/browser/browser-pane-manager.ts` 与 `src/main/decode-image.ts` 有独立拒绝权限逻辑，不能因主输入框录音而放宽。
- `src/shared/ipc/index.ts`、`src/shared/ipc/application-host.ts`、`src/main/preload.ts` 提供现有 typed 桌面桥；新增语音方法必须区分桌面 UI 与员工可调用的公共方法。
- `pnpm-workspace.yaml` 已覆盖 `packages/*`，可以容纳独立插件包；现有 workspace 支持不等于语音原生依赖已经能够构建分发。
- 当前 Composer 的 `MentionInputHandle.replace` 仅 member 分支有 `closeHistory`，普通文本插入不能直接宣称具有独立撤销边界；语音写入需要明确的单独 undo 事务。
- `AppShell` 的会话层可能只通过 `display:none` 隐藏，`ChatView` 已有 `pageActive`，空 Bobo 的 `core-chat-start` 尚未获得同等活动信号；同一会话还可能有侧栏输入框，因此只依赖 React unmount 不能完成取消或隔离。

## 4. 插件与宿主的责任

拟定稳定插件 id 为 `boai.voice-input`，贡献类型为 `voice-input`。保持应用插件共同身份与启停协议，给输入能力独立的类型合同。第一版仅接入这一个内置受审实现，不把语音混入 `agent-runtime`、`web-search` 或员工资源绑定。

拟定 `packages/voice-input-plugin/` 作为插件实现所有者，具有明确的纯协议、renderer、main 与识别进程入口；具体 exports 和打包形式由实施第一阶段验证后冻结。它不是当前已存在的包。

插件拥有：

- 录音按钮、录音状态与取消交互，复用宿主 UI 组件和设计 tokens。
- 浏览器音频采集、重采样、音频缓冲与录音会话状态机。
- 模型清单、资源下载/校验/删除、识别引擎适配器及独立识别进程生命周期。
- 插件配置内容、必要的模型状态与错误映射。

宿主只提供：

- 目录注册、兼容检查、持久启停及受约束的设置入口。
- 主窗口音频权限检查与 typed IPC 转发；验证发送方和当前录音租约。
- Composer 的输入扩展位置，以及受 scope/revision 保护的纯文本插入能力。
- 窗口隐藏、导航、输入框卸载、应用退出等生命周期信号。
- 应用数据位置、已有日志与通知通道；不向插件开放整个产品数据库或任意文件操作。

依赖方向是宿主装配插件公开入口，插件通过窄 host adapter 请求能力；插件不得反向 import 会话 store、任务服务或 Main 全局对象。核心不得包含 SenseVoice 模型判断、ONNX 解码或下载实现。禁用插件、模型缺失或识别进程失败时，普通文字输入、附件、技能与来源标签、发送流程仍须可用。

独立包不意味着绝对零安装体积。插件的少量代码与平台识别运行库可能增加发行体积，必须在实施中单列测量；模型权重明确不随 BOAI 安装包分发。是否将原生运行库随受审发行包发布，由兼容性验证冻结，不能借本任务新增远程执行任意二进制的安装平台。

## 5. 默认关闭与启停迁移

当前“没有禁用记录就启用”的逻辑不能满足新功能默认关闭。拟定采用显式 opt-in，而不是首次启动时偷偷写一次禁用项：

- 清单新增 `defaultEnabled?: boolean`；缺省为 `true`，保持原预览、主题等行为。语音插件声明 `false`。
- 快照增加 `enabledIds?: readonly string[]`，只表示明确启用的 opt-in 插件；未提供时视为空数组。
- 兼容检查优先，其次 `disabledIds`；若不兼容或明确禁用，不得激活。
- 对 `defaultEnabled: false`，只有存在于 `enabledIds` 且不在 `disabledIds` 才启用；旧配置、新安装均保持关闭。
- 明确开启语音：移除其禁用记录、加入启用记录。明确关闭：移除其启用记录、加入禁用记录。已有默认开启插件仍沿原启停语义。
- 并发修改、只读状态、持久失败、未知 id 保留、快照 revision 和失联回读规则全部保持；业务备份不替换本机启停偏好。

持久格式升为 `schemaVersion: 2`，不向严格 v1 格式偷加字段。读取 v1 时在内存迁移为 `enabledIds: []`，仅在用户明确修改设置后按原 CAS 原子保存 v2；只读损坏/未来格式不迁移、不覆盖。旧应用遇到 v2 将按原有规则只读保留，不把“降级版本仍可修改插件设置”写成兼容承诺。

启用不等于下载、麦克风授权或正在使用：

- 启用只使入口可用，不能自动下载模型、启动识别进程或请求麦克风。
- 模型下载由用户明确操作；已有可用模型不因重新启用而重下。
- 录音/转写会话持有实际使用引用；停止或失败后释放。
- 停用立即阻止新录音，并取消正在进行的录音/识别、释放音频与进程资源；不能沿用“当前预览关闭后生效”。
- 停用保留已下载模型以便重新使用；删除模型是独立操作，删除后插件可以仍启用但不可开始识别。

## 6. 用户交互

设置入口放在现有“插件”中，增加语音输入类型与本插件配置入口。无需新建核心“语音系统”主导航，也不进入员工配置页。

- 未启用：输入框不出现常驻麦克风按钮，应用不为此启动后台任务。
- 启用但未下载模型：允许通过插件配置进入下载；输入框入口可以引导到同一下载界面，点击不能默默开始下载或录音。
- 下载前展示实际下载大小与模型信息；下载时展示真实进度并能取消；下载后展示实占空间和删除操作。
- 模型可用后，输入框麦克风图标通过 Tooltip 说明操作；录音期间就近显示时长、停止和取消，转写期间可取消。
- 操作反馈沿现有 Sonner；必要的权限/模型缺失说明放在就近可操作提示，不新增装饰性 description 或重复“保存成功”常驻 DOM。
- 权限被拒绝时提供系统设置方向；不循环弹权限、不将拒绝伪装成模型失败。
- 识别为空或失败时保留原草稿，给出可重试的简短反馈；取消不报为插件故障。

第一版不在录音过程中展示猜测文字；录音一旦停止，麦克风立即释放，转写不继续采集音频。用户可以随时检查文字，语音结果永不自动触发发送。

## 7. 录音会话与安全写回

### 7.1 会话身份

每次录音生成独立 `sessionId`，固定宿主 `webContents`/主 frame、输入框 scope、视图实例 token、当前员工/群上下文、草稿 revision 和插入锚点。后续事件必须同时匹配当前会话身份与 generation；同一 Conversation 的主栏/侧栏输入框也不能互相接收结果。

已有会话使用现有 Conversation 身份；空 Bobo 使用独立的未创建会话输入 scope。录音、转写、模型准备均不能提前创建 Conversation、Work、Run 或消息。只有用户按原入口发送时才沿原逻辑创建。

### 7.2 状态与限制

拟定状态为 `idle → requesting-permission → recording → transcribing → completed`，任一活动阶段可进入 `cancelled` 或 `failed`。模型准备属于独立状态，不复用录音状态或构造假进度。

- 全应用只持有一个活动会话；其他输入框展示已有录音状态或拒绝新启动，不静默抢占。
- 首版单次录音上限拟定 120 秒；达到上限自动停止并转写，不能继续后台录音。时长、采样总量及单次 IPC 大小在两端均有界，实施阶段冻结具体常量。
- 采集默认麦克风，向识别器提交符合模型要求的单声道 16 kHz PCM；设备返回实际采样率必须校验，不能只靠 `getUserMedia` constraint 假定已重采样。
- 录音期间不调用 Agent 模型。停止先结束所有 track 和音频处理节点，再开始识别。
- 导航离开、scope/员工失效、输入框卸载或不可编辑、主窗口隐藏、插件停用、应用退出均取消会话；普通窗口失焦不自动重复授权或重启录音。
- 页面活动/可见性由宿主显式传入，空 Bobo 同样维护草稿代际和页面活动状态；`display:none` 隐藏也必须触发清理，不能等待组件卸载。
- 在系统权限弹窗未决时取消，也要使会话失效；迟到拿到 MediaStream 必须立即停止，不能恢复录音。
- 识别取消应实际结束该会话的计算；先尝试协作取消，超时终止独立识别进程，不仅丢弃结果却保留后台计算。

### 7.3 草稿合同

语音返回普通文本，不返回可执行命令、HTML、Markdown 节点或新的资源授权。插入必须经宿主编辑器事务进行，保留 mention、技能、来源标签等原子节点与已有附件。

- 当原 scope 仍有效、输入框可编辑、草稿 revision 与锚点仍匹配，才在保存的锚点插入一次。
- 转写期间用户编辑、清空、发送或替换草稿后，禁止覆盖、回填旧快照或猜测光标位置。
- 同一 scope 仍有效但草稿已变化时，可在当前输入框提供一次性的“插入转写文本”操作；用户明确选择后按当前光标插入，且可以丢弃。待插入文本只保留在当前 UI 内存。
- scope 已变化、原员工/会话被删除或清空、用户导航离开时，取消并丢弃结果；不得写到新会话，也不得导航回来后自动补写。
- 成功插入记录一次性已消费标记；重复事件、延迟 IPC、取消后回包不能二次插入。
- 插入作为独立撤销事务，用户一次撤销只移除本次语音插入；不与之前键入或 mention 操作合并历史。现有普通 `replace` 不足以承诺这一点，需新增受测的宿主插入方法。
- 插入后沿原草稿变更、持久化和发送校验，不绕过既有发送门禁，不清除附件或资源选择。

具体编辑器入口与宿主 scope/revision 适配在 [12](./12-语音输入插件实施与验收.md) 的实施阶段核对；插件不能通过全局 `setDraft` 替换整份编辑器文档。

## 8. 本地识别与进程

首个候选是 `sherpa-onnx-node` 配合 SenseVoice INT8。这是实施验证起点，不是已经验证的 Electron 兼容方案，也不宣称它在 BOAI 中文场景中准确率或速度最佳。

[sherpa-onnx 官方安装说明](https://k2-fsa.github.io/sherpa/onnx/javascript-api/install.html)提供 Node 包和 macOS arm64/x64 等平台支持，并明确原生 addon 需要运行时共享库。实现必须验证实际 Electron 版本、目标 CPU、共享库搜索路径和发行包结构，不能用普通 Node 中 `require()` 成功代替桌面可用。

- renderer 只负责采集和 UI，不加载原生 addon。
- main 只负责验证、调度与生命周期，不在主进程直接执行识别。
- 优先验证 Electron `utilityProcess` 或独立 helper，识别进程按会话需要启动，原生崩溃不会直接发生在 renderer/main 进程；最终方案在第一阶段冻结。
- 普通 `worker_threads` 并不提供独立进程的原生崩溃隔离，不以“用了 worker”替代此边界。
- 首版每次完成、取消或失败后释放识别器并退出辅助进程，不维持常驻模型缓存；后续只有真实冷启动数据证明必要，才另议有界空闲缓存。
- IPC 只传有界音频与识别结果；识别进程不获得会话历史、员工凭据、模型连接 API Key 或任意宿主 RPC。
- 原生库路径由应用确定，不要求用户编辑 shell 环境，不依赖开发机全局 Python、CMake 或额外命令存在。

若候选无法达到兼容性或体验门槛，先记录事实并修订选择。Whisper 等只作为替代评估方向，不同时扩成首版多引擎功能。

## 9. 模型与磁盘管理

候选模型固定到 [SenseVoice ONNX 文件清单的该提交](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/tree/2365baeacb507f821a0c8120fcee3d484dba7a07)：

- `model.int8.onnx`：页面显示约 239 MB。
- `tokens.txt`：页面显示约 316 kB。
- 同库另有约 938 MB 的 `model.onnx`；不能克隆整个约 1.18 GB 模型仓库。
- 仅获取所选版本必需的模型、tokens 和许可证/来源信息；运行库大小、下载暂存空间另计。

以上是页面标示值，不是实际验收结果。实施前必须记录准确字节数、SHA-256、来源 commit、完整许可证与再分发要求；不在本轮下载模型，不用臆造 hash 填入可执行下载清单。

模型属于机器资源，不属于员工资料：

- 拟存于应用数据目录内独立的 `plugins/boai.voice-input/models/<model-id>/<revision>/`，不写入仓库、安装包、会话目录或员工文件夹。
- 同一应用数据目录共享一份，同版本不会按员工、群或会话重复下载。独立测试 profile 可有自己的隔离副本，不能宣称跨 profile 已自动去重。
- 应用更新不得主动重下既有兼容模型；升级模型需要显式下载，旧版本在新版本校验完成前仍保持可用。
- 模型资源、音频和 native 缓存不进入业务备份，不上传、不作为员工知识/记忆材料。
- 设置页分别展示下载预估、实占空间和可删除状态；239 MB 权重不等于总安装/运行内存，也不等于峰值磁盘。

下载/删除合同：

1. 仅使用受审清单中的固定 HTTPS 资源与重定向规则，renderer 不提供任意 URL 或目标路径。
2. 开始前检查可用空间，计入 `.part`、旧模型保留与必要余量；限制单文件与总下载字节数。
3. 每模型版本只能有一个写入事务；下载到临时位置，可取消，失败清理；首版不承诺断点续传。
4. 完整校验字节数和 digest 后原子切换为可用状态。只有两个必需文件与来源/许可信息均就绪才可加载，禁止混用半包、旧 tokens 与新模型。
5. 删除前阻止新识别，取消/释放正在持有它的进程，再清理该版本；不得删除正在加载的文件后假报成功。
6. 启动时清理失效临时文件，核对已登记模型存在性；缺文件或校验失败应回到不可用状态，不自动下载。

## 10. 麦克风权限与数据边界

麦克风属于明确用户操作，插件启用状态本身不授予采集权。BOAI 的现有默认拒绝需收窄为仅可信录音会话的音频例外：

- 请求来自当前主窗口的受信主 frame，origin/开发地址或打包文件身份由宿主已知加载来源核对，不能仅检查 `localhost` 字符串。
- 插件当前启用、输入 scope 有效且存在未过期的用户启动会话；`mediaTypes` 必须只含音频。视频、未知媒体类型和无关请求仍拒绝。
- 权限检查与请求处理均按 Electron 当前版本接口实现；已有系统授权只免除重复弹窗，不取消每次显式启动的要求。
- 不改变浏览器页面、iframe、预览/图片解码窗口的默认拒绝，不授予摄像头、屏幕录制或系统音频。
- macOS 发行包需提供 `NSMicrophoneUsageDescription`，并按 `getMediaAccessStatus` / `askForMediaAccess('microphone')` 处理系统权限。开发进程与打包应用必须分别验证，不能互相代替。[Electron 官方 systemPreferences 文档](https://github.com/electron/electron/blob/main/docs/api/system-preferences.md)
- typed IPC 方法限桌面 UI 使用，不自动加入员工可调用的 public method、CLI、MCP 或技能工具清单；来自员工执行链的请求不能通过持有插件 id 启动采集。

原始音频优先驻内存；若引擎适配必须临时落盘，则使用插件私有临时目录和有界文件，结束/取消/异常后删除，异常退出后的残留在下次启动清理。音频不加入附件列表、ProductStore、历史消息、备份或长期记忆。日志只保留状态类别、时长/大小等必要指标，不记原音频、识别正文或完整用户路径。

用户明确发送后，已经插入的文字沿普通消息流程进入会话；这是既有用户输入，不需要建立第二套语音消息权限或保存整个录音。

## 11. 实施前必须确认的事实

以下属于计划中的技术验证，不代表本轮已执行：

- 选定 sherpa npm 版本、Electron 版本及 native ABI/共享库加载；在 macOS arm64 的真实发行形态启动、退出与故障隔离。
- 固定模型的实际字节数、hash、许可与必要文件集；下载源可达性、慢网/取消/坏文件/低磁盘行为。
- 真实麦克风与 PCM 重采样，中文、英文夹杂、产品名、无声、噪声和长短语音质量；分别记录冷启动耗时、识别耗时、峰值 RSS 与磁盘。
- 原会话、群、空 Bobo、带 mention/来源标签/附件草稿的写回；转写期间编辑、发送、切换、清空、删除与禁用的迟到结果。
- 新旧配置、原预览/主题/检索插件启停、只读配置及降级读取，不用新功能改变原插件默认行为。
- 真实音频权限、隐藏与退出释放，以及普通文字输入不被插件故障拖垮。
