# Agent运行时插件实施计划与验收

## 1. 范围与完成定义

用户随后明确“实现代码”，首版宿主、独立包管理、Pi RPC与通用ACP已接入。验证使用隔离数据目录，未改用户BOAI连接/聊天；真实Pi沿原生登录调用，失败见§7。现行设计见[05](./05-Agent运行时插件协议与接入架构.md)。

实施目标：保留Mastra主线与已有员工产品能力；新增Agent通过稳定provider合同与独立包接入，在接口已覆盖的能力范围内不改核心品牌枚举、聊天页或`AppService`。既要能安装/管理，也要能实际连续聊天；完整成果、协作和自动化能力按矩阵分别验收，不能用“已发现”“已握手”替代。

本增量包含：内置驱动包装、通用ACP驱动、Pi原生RPC插件、OpenCode ACP声明包、受信本地插件包安装/更新/停用、兼容迁移与共用测试。插件市场、自动联网更新、任意不受信代码安全沙箱、远程A2A和替换Mastra另期。原第19组03的G1–G6成绩只属于预览/主题，不能套用于可执行插件。

## 4. 实施落点与新增Agent的流程

具体文件名可按实施时仓库结构调整，职责固定：

| 层 | 预计落点 | 内容 |
| --- | --- | --- |
| 公共合同 | `src/shared/plugins/`及共享schema | 运行时贡献、DTO、版本和能力定义；不暴露应用内部对象 |
| 运行时宿主 | `src/runtime/modules/backends/` | provider解析、连接/session/回执、能力门禁与公共产品桥 |
| 协议驱动 | `src/runtime/adapters/` | 复用Codex/Claude，新增ACP共同驱动；Pi代码后续可独立包交付 |
| 主进程 | 现有插件设置、程序发现与进程监督入口 | 受管安装记录、程序/包hash、进程身份与退出、配置通知 |
| 界面 | 现有设置插件/模型连接/员工及执行面板 | 从贡献与能力生成选择/状态；不逐品牌加组件 |
| 开发包 | 独立插件工程和独立SDK构建产物 | manifest、预构建代码/schema、来源/许可和合同测试；无需把BOAI整体迁为monorepo |

新增程序流程：选择已有驱动或实现provider → 声明发现/配置/能力 → 对固定程序版本跑共用合同 → 生成独立包 → 在插件页安装并启用 → 模型连接扫描/测试 → 绑定员工。使用共用ACP驱动的包只填程序声明；有协议差异时封装在该包内。发现本机未知程序不自动下载适配插件。

首期外部包必须预构建，安装器不执行依赖安装脚本。动态配置schema只能使用宿主支持的标准字段；新增复杂交互先设计扩展合同，不能通过任意React/HTML绕过插件宿主。

## 5. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 插件不存在/停用/不兼容，程序存在或缺失 | 正确状态与操作入口；不把扫描结果伪装成可执行连接 |
| 插件/程序内容变化，陈旧草稿保存 | 原指纹拒绝；重新核对后显式保存；不修改旧历史 |
| 新独立包安装/卸载、配置损坏、安装失联 | 原子回执与只读核对；原件保留，不静默重复安装/激活 |
| 正文/图片/附件、实际流式工具与思考 | 按真实能力交付/呈现；不支持附件不悄悄丢弃；最终答复不重复 |
| 同员工连续多轮、两员工/两渠道并行 | 同记录续用兼容session，不跨员工/渠道串上下文 |
| 运行中发送、steer、follow-up、停止 | 普通输入不取消原轮；停止明确处理本轮队列和子工具，idle/退出可核对 |
| 输入写入后失联、工具/发布结果未知 | 原消息/操作保留unknown，重启及框架重试零业务重放 |
| 原生审批/待决问题、普通已结束回复中的提问 | 按真实action关联回答；普通下一条消息正常续聊，无合成审批 |
| 活动期间停用/升级/卸载/插件崩溃 | 新调用被挡，旧版本租约固定；实际收尾后切换，仅影响所属实例 |
| 文件生成/修订、群依赖、自动化和浏览器 | 由原产品桥产生真实回执，能力缺口明确；不能靠文本“完成”验收 |
| 原Codex/Claude/ACP历史与备份恢复 | 映射/来源不变，缺包仍能阅读历史；不导出登录token/外部个人session |
| Mastra/API与插件互操作 | 原API功能保留；委派使用原身份/回执，不对未知本机任务自动重试 |
| 新ACP程序和Pi插件升级 | 仅新增/更新独立包，业务核心和通用聊天UI没有品牌改动 |
| 空闲/长任务/多会话资源 | 订阅、进程和缓存有归属并可释放；无BOAI本机token/调用/时长预算；单次短测试不冒充长期资源通过 |

Pi特有合同覆盖严格LF分帧、响应关联、受理与完成分开、上游队列清理及abort后的idle。OpenCode覆盖实际ACP握手能力、session恢复、权限/工具事件、停止及已知命令限制；如另选HTTP驱动，还需实例归属、认证、事件session过滤与不误停用户服务。

使用现有Vitest和Electron BDD入口。区分纯合同、协议夹具、真实已安装程序、真实供应商和真实产品界面；每个插件按程序/插件版本记录结果，失败和未运行原样保留。只涉及文档时不运行无关全量产品测试。

## 7. 首版源码实施与实际验收（2026-10-16，当前唯一进度）

用户明确“实现代码”后，新增通用`runtime-plugin`绑定，运行时业务路由不含Pi/OpenCode品牌分支；扫描、模型连接、员工选择与插件设置消费同一贡献声明。Mastra继续负责API路径，Codex/Claude/旧ACP保留原kind、历史和实现。

已接入：

- `runtime-api.ts`独立接口与严格线协议校验；模块通过专用Node进程运行，沿原监督器核对进程树实际退出，不把进程隔离说成权限沙箱。
- Pi原生RPC（0.85.1起）：prompt受理与agent_settled分离、增量session、原生事件/工具、扩展输入/审批、清队列后abort。OpenCode以`opencode acp`声明复用官方ACP SDK 1.5.0；能力由真实握手取源。
- 受信本地包的暂存/内容hash/原子CAS登记、运行租约、启停、更新和卸载；停用不强杀旧执行，更新/卸载等待释放。外部覆盖卸载后立刻恢复停用的内置版本。插件管理刷新实际使用状态，失联只读核对，不自动重放操作。
- 每员工×会话×provider独立原生session、无歧义长度前缀命名空间、来源/程序/配置核对、材料与成果桥、原生待决输入、群委派、自动化、停止与未知恢复。插件私有目录不进业务备份，插件包/偏好不随业务备份复制。
- 独立Pi模块包、OpenCode声明包、TypeScript SDK与JSON Schema由构建产出；开发见[07](./07-运行时插件开发接入.md)。原v1预览/主题继续可用。

首轮联调发现首次pluginRuntime安装标记缺失导致重启重建session，已修复并用真实子进程连续会话验证。检查还修正了本机代理/CA环境继承（回环工具桥强制NO_PROXY）、原生action写入后过早确认、命名空间拼接碰撞、无参数控制帧schema误拒绝，以及运行中更新与获取租约的竞争。当前普通发送仍由宿主排队下一轮，未把Pi steer/follow-up接成新的UI动作。

工程/桌面结果、失败原件与当前限制见[本轮报告](../../reviews/2026-10-16-runtime-plugins/README.md)。真实登录失败不能被离线协议通过覆盖；旧本机及原预览插件成绩按原日期保留。

未完成的认证范围：真实Pi连续多轮/文件/停止/重启，真实OpenCode全部场景，插件渠道收发/完整自动化触发/浏览器/材料图片/备份恢复的新增桌面矩阵，长时间资源与发行包/其他平台。代码复用并不等于这些场景已验收。SDK错误code/acceptance完整信封、跨连接事件游标、旧驱动独立插件包装与稳定公共SDK发布留后续兼容批次；当前无市场、联网更新、不受信代码沙箱、远程A2A。
