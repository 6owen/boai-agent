# Web Search工具接入设计与实施计划

日期：2026-10-18。状态：**已按用户review意见修订，仅文档；未新增搜索实现、配置真实服务或启动goal。**

目标：BOAI已经有内置浏览器，员工继续使用其现有页面访问、登录态和交互能力。在此基础上，让员工能发现并调用绑定的Web Search工具；新增搜索能力可以通过MCP接入，也可以由BOAI已有插件架构提供。员工不需要为了换一种搜索服务而更换模型或执行引擎。

本篇不再把Tavily、Jina、DeepSeek三家全部接入作为首个goal的硬目标。它们是可选提供方；核心交付是“配置一种获准搜索能力→员工实际调用→读取结果/页面→给出可检查引用”，并保持原浏览器可用。

## 1. 已有能力与新增范围

| 内容 | 当前地位 | 本功能职责 |
| --- | --- | --- |
| BOAI内置浏览器 | 已有产品能力 | 保留窗口、登录状态、页面操作及原工具/审批，搜索工具接入后仍可正常使用 |
| 数据源MCP/API连接、员工绑定 | 已有接入基础 | 复用凭据、连接、工具目录、sourceId与员工授权，补搜索/正文能力发现和普通问答调用 |
| BOAI plugins | 已有插件架构及管理/生命周期 | 沿既有架构增加搜索来源的模板或provider贡献；不另建搜索插件系统 |
| 外部Web Search/Fetch | 后续按需接入 | 结构化搜索、摘要和正文读取，作为浏览器以外的可选工具 |

不配置新增搜索服务时，现有浏览器能力保持可用。配置了MCP搜索也不要求所有网页操作都改走MCP；登录、动态页面、点击填写等继续由已有浏览器处理。保存搜索源不重新安装或重建浏览器。

## 2. MCP与plugins的接入关系

MCP是工具调用协议，plugin是能力安装/装配方式，二者可以组合。沿[08第5节](./08-Composer与技能数据源整合设计.md#5-与现有plugins的关系)已有设计：插件可以提供MCP/API连接模板，也可以贡献额外source provider；实际连接实例和员工绑定仍由sources统一管理。

```text
现有BOAI浏览器 ───────────────────────→ 原浏览器工具
配置MCP源 / 插件提供MCP或API模板 → 数据源实例 → 员工绑定 → 搜索/正文工具
插件贡献source provider ──────────────┘
                                    ↓
                         原执行记录、授权与真实引用
```

### 2.1 首个goal的必需路径

先沿已有MCP数据源跑通至少一家同时提供搜索与正文读取的服务。优先从Tavily/Jina等现成服务选取；实施起点SE0根据实际工具目录及任务可用凭据固定一家，记录其工具与版本。其余供应商后续按需配置，不能为了第一家上线重做整个工具平台。

公共实现应按能力、实际schema和来源身份工作，不按员工品牌或供应商名复制调用链。已核对服务的操作语义可以有小型适配定义，员工运行逻辑保持共用。

### 2.2 插件路径

沿现有插件清单、安装/启停、版本和宿主生命周期扩展。**当前插件声明已有preview/theme/runtime，不能据此声称source贡献已经实现。** 首个搜索goal先固定下列接入合同；需要真正交付搜索插件时在同一架构增加贡献类型和实现，不另开注册中心。

- 最小搜索插件可提供MCP/API连接模板、能力说明和使用指引；用户配置凭据并生成原数据源实例，员工仍通过原`sourceIds`获得访问权。
- 直接封装HTTP搜索的插件可贡献source provider，向宿主提供操作schema和结果；凭据、员工授权、审批、取消、运行回执及界面由宿主继续负责。
- 安装或启用插件不自动绑定所有员工；bobo沿原全部启用源规则。插件停用/卸载使所依赖能力不可用，保留源身份/历史并停止新调用；不静默替换provider或误删用户配置。
- 同一服务经MCP和插件出现时沿真实源身份区分，不能两边默认重复调用。本机Agent原生已有的MCP/插件保持原生能力；BOAI新增的搜索源沿公共产品桥或原生工具接线。

插件交付是可单独启用的后续阶段，不阻塞首个MCP搜索闭环；若后续goal明确选择插件交付，须完成真实安装→配置源→员工调用→停用的验收，不能只写模板或清单就宣布插件可用。

### 2.3 候选服务与官方依据

以下为2026-10-18核对的候选接口，不能作为BOAI实测成绩；实施时再次核对真实版本/认证。首版不要求三个服务同时上线。

| 候选 | 可用接入思路 | 官方依据 |
| --- | --- | --- |
| Tavily | 官方MCP，沿远程MCP连接、凭据及工具目录 | [MCP文档](https://docs.tavily.com/documentation/mcp) |
| Jina | 官方MCP搜索/读取，按实际工具目录选择 | [Reader](https://jina.ai/reader/)、[服务元信息](https://mcp.jina.ai/) |
| DeepSeek Search/Fetch | 官方HTTP API；需要时可经原API provider、插件或薄MCP适配接入 | [官方指南](https://api-docs.deepseek.com/zh-cn/guides/search/) |

DeepSeek的`POST /v1/tools/search`、`POST /v1/tools/fetch`是独立搜索/抓取接口，不要求员工使用DeepSeek模型。文档保留这种扩展可能，不把“核心必须直接内置DeepSeek API”写入首个MCP goal。

## 3. 员工如何发现和选择工具

### 3.1 授权与发现

普通员工只使用当前绑定且启用的来源；bobo沿[08第25节](./08-Composer与技能数据源整合设计.md#25-资源连接与员工权限分离结果消息去重2026-10-17)使用全部启用源。服务连接、员工绑定和调用成功是不同事实，不能因为插件已安装或MCP已连接就自动取得全部工具权限。

初始上下文提供简短能力说明，如搜索网页、读取URL；选定后按需读取真实schema，继续复用`inspect_data_source`/`call_data_source`或经同一门禁的能力工具。稳定sourceId和工具身份区分同名服务，配置/目录版本变化时失效旧缓存。不给每轮提示拼入全部MCP工具说明。

### 3.2 选择规则与最小配置

在员工已有数据源配置Card中增加可选“首选检索方式”，沿同一员工草稿保存，默认“自动”。候选为自动、BOAI浏览器以及该员工可用且具备搜索能力的源；bobo候选沿全局启用源。不新增搜索设置主页面。

| 情况 | 行为 |
| --- | --- |
| 用户本轮明确指定浏览器或某个获准源 | 优先遵守，源引用固定sourceId/revision；失效时说明，不能默默替换 |
| 员工选择首选搜索源 | 一般搜索先使用它，读已知链接时按实际读取能力执行；页面交互仍交给浏览器 |
| 员工选择BOAI浏览器 | 沿现有浏览器路径执行；用户明确指定其他源仍可覆盖本轮选择 |
| 自动且只有一个获准搜索源 | 普通搜索优先使用该源，动态/登录交互使用浏览器 |
| 自动且多个获准搜索源 | 结合能力及任务选择一个，记录实际来源，不默认同时调用全部服务 |
| 自动且没有新增搜索源 | 继续使用原BOAI浏览器；当前运行无法使用浏览器时说明实际情况，不伪造搜索结果 |

解绑首选源时同次保存重置为自动；源被全局停用/删除时保留明确的失效状态，普通自动选择可使用现有浏览器或其他获准源并记录回退，不能显示失效源已成功调用。当前用户明确指定来源时仍遵守第一行。新增源不自动夺取已保存的首选，模型/引擎不会随之切换。

本机Agent原生搜索保留；本轮指定BOAI某个源时需验证实际调用了该源，不能以提示词或其他原生搜索结果冒充。未指定时可沿现有原生能力工作，实际使用哪条路径如实记录。

### 3.3 普通问答和原浏览器

新增获准只读搜索/URL读取可用于普通问答和任务，不因为问答用了搜索就制造文件Work。私有判断、记忆维护和已结束运行不因此取得业务外呼权限。群/渠道/自动化按当前执行员工取工具，不经bobo代调用扩权。

BOAI浏览器沿已实现的执行、权限与审批路径使用，本功能不顺带重写其阶段门禁或登录管理。浏览器页面动作、远端写入和本机文件修改继续沿各自原权限；新增只读搜索工具不能成为这些副作用的绕过入口。

## 4. 操作语义、凭据与目录

搜索/抓取可能使用POST，操作分类应依据已核对的服务身份、具体端点/工具、schema及版本。未知工具仍按原保守规则处理，不能把名叫search的工具、GET或`readOnlyHint`单独当权限保证。[MCP官方提示说明](https://kotlin.sdk.modelcontextprotocol.io/kotlin-sdk-core/io.modelcontextprotocol.kotlin.sdk.types/-tool-annotations/index.html)

只读员工可以调用已验证的搜索/抓取；请求审批不因只读POST误触写入批准；真实写工具仍按员工权限。保持连接与员工权限分离，不恢复`allowWrites`、`accessMode`等数据源级读写开关。

凭据由宿主vault注入，优先Authorization，不写入模型参数、guide或公开日志。查询仅使用当前任务所需信息，不自动附带整段私有聊天或知识资料。搜索可能计费；只读不表示允许无限调用或未知后反复重发。

[员工目录授权](../4.数字员工与协作重构/05-员工工作范围与目录权限设计.md)只在实际访问本机文件时核对：已授权可用，其他目录按员工权限申请或自动授权。远程MCP、浏览器或插件进程无需都在coding目录运行；本地MCP、下载/上传和插件文件操作也不能在请求审批模式下先访问再补授权。

## 5. 结果、引用与失败

- 保留真实源/工具/请求身份、查询或URL、调用时间、状态和返回原件。复用原执行视图及同轮同源去重，不新增一串技术聊天消息。
- 向模型提供服务实际返回的标题、URL、摘要/正文、时间与截断信息；缺失保持未知。抓取时间不冒充发布时间，搜索摘要不冒充全文阅读，插件或MCP无法结构化时保留原件及真实限制。
- 答案引用真实返回或读取的URL；工具`isError`、登录页、空正文不得作为成功读取。网页内容不升级为系统指令。
- 资料不会因搜索成功自动加入记忆或知识资料；明确保留文件沿[知识资料功能](../4.数字员工与协作重构/07-员工知识资料设计与实施计划.md)，该功能不构成搜索前置。
- 保存配置不测试或启动进程；沿原AI管理创建源及已有编辑路径。握手/目录成功与实际搜索/正文成功分别记录，状态绑定源revision。API候选的POST接口不以通用GET失败直接判定不可用。
- 超时、401/403、429、额度、无结果、不可提取、取消和未知分别记录。只对明确可重试的只读失败采用有界策略，记录新调用/备用；不重放未知副作用。取消等待实际请求/本地进程退出，迟到结果不发布。前端错误使用Sonner。
