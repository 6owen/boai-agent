
## 3. 贯穿验收

| 编号 | 要证明的行为 |
| --- | --- |
| DA01 | 同一任务不能被两执行器同时领取，两任务修改/暂存不串扰 |
| DA02 | 真实修复在旧实现暴露失败，新实现通过；失败、skip和环境错误可区分 |
| DA03 | 开发—审查—返工—PR形成连续记录，任一提交变化使旧结论失效 |
| DA04 | 新功能允许增加必要源码、测试、资源和`ai-docs`文档，并完成目录同步 |
| DA05 | 取消、超限、进程异常与未知远程结果可恢复核对，不重复副作用 |
| CT01 | T1选中检查真实运行；缺报告、未运行必需项和不完整结果不能通过 |
| CT02 | 基线/候选绑定实际工作树、任务、模型、环境与评分器，不把配置变化当代码收益 |
| CT03 | 真实任务产物、独立评分及人工待评独立呈现，工程检查不替代业务质量 |
| CT04 | GUI和压力测试有资源隔离，启动进程在取消/完成后退出 |
| CT05 | 测试/更新事件重复或中断后，同一运行/PR/失败任务不重复创建 |
| CT06 | 上游、依赖、prompt和技能更新能选择对应检查；必需门槛对应实际交付提交 |
| UI01 | UI宿主与画板逐项引用第19组10结果，原主题/运行时插件成绩不挪用 |
| RL汇总 | 按04的RL01–RL10验证Tag/版本、产物、个人签名形态、数据、回滚和开发模式边界 |

每项记录版本、步骤、输入、原始结果、失败原因和结论范围。平台没有执行时标未运行；成本、重复数和门槛进入实际计划后才执行，不由本文件默认开启模型调用。

## 4. 后续开工顺序

1. 阅读本组README、01/02及第19组10；核对最新AGENTS与相关目录地图。

4. 补任务控制器并用一个真实修复串通，检查失败与中断分支。
5. 用同一流程推进UP宿主和EX完整画板，按原BOAI服务接线，逐项验收。
6. 最后接入周期执行和版本比较，审阅报告后更新基线；不将基线更新等同自动放宽门槛。
