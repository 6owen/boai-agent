# 个人应用更新与发布

适用范围：macOS Apple Silicon，当前本人本机打包自用。应用使用ad-hoc签名，不需要付费Developer ID或公证；更新文件使用独立Ed25519密钥校验。这不是Apple身份签名，私钥留在本机钥匙串，公开Release仅包含公钥、包及校验信息。

## 本地产物位置（2026-11-10）

命令语义保持：`pnpm build`只生成应用编译产物；普通`package`/`dist:mac`输出`dist/releases/`。现行`release:build`将DMG、ZIP和展开应用放到`dist/releases/candidates/<ID>/assets/`；Electron暂存、上一版ZIP和签名更新资产分别在该候选下的`electron-dist/`、`previous/`、`updates/`。下载缓存为`dist/releases/cache/electron/`。

控制记录继续在`.local/release-candidates/<ID>/`，包括`candidate.json`、日志、进程账本及监督器；冒烟参数仍传这个目录。新候选记录`artifactDirectory`，旧候选保持原`.local`资产位置可读，不自动迁移。顶层`dist/releases/`不进入应用包体或应用构建身份哈希；其他应用字节仍校验。`dist/`已在Git忽略范围，旧`release/`忽略项保留。

`.local`内profile、研究原件、归档和恢复记录不属于可统一删除的编译产物。清理时逐项确认使用状态和保留价值；本次只修改输出位置，未清理历史数据、构建安装包或认证发布/安装结果。

## 日常流程

开发Agent统一使用[boai-release](../../../.agents/skills/boai-release/SKILL.md)。可以直接说“用 `$boai-release` 发布一个新版本”或“只准备安装包，先不发布”；技能按请求选择下面的现有入口。

带更新器的自用包使用下面的`release:build`或`release:local`流程；原普通`dist:mac`不注入更新源。

首次配置一次：

```sh
pnpm release:setup
```

配置存于`~/Library/Application Support/BoAI Release/settings.json`，钥匙串账号为`com.boai.agent.updates`。再次执行复用原密钥，已有公钥不一致则拒绝，不自动轮换。丢失原密钥后不能让已有安装版信任新密钥，需要另行迁移或手动安装新基版。

在干净的版本分支中运行：

```sh
pnpm release:version patch
# 也支持 minor、major、明确X.Y.Z；不带参数使用bumpp交互选择
```

bumpp只修改根`package.json.version`与`build.buildVersion`，内部workspace包保留各自版本。只允许递增稳定版本，不在这里提交、打tag或push。版本改动沿正常PR合入main，等待该main提交的GitHub `Test`通过。

在该干净main提交上，本机运行：

```sh
pnpm release:local --publish
```

依次执行：核对当前远程main/同SHA最新Test → 本机构建ad-hoc arm64 DMG+ZIP → 原有ZIP8/DMG2隔离产物冒烟 → 下载并核验上一版ZIP → Sparkle差分及含包签名的appcast → 创建同SHA `vX.Y.Z` tag和draft Release → 上传并回读资产SHA256/大小 → 重核main/Test → 发布为Latest。GitHub不负责打包，无需配置云端Apple凭据。

省略`--publish`只准备候选及更新资产，终端给出`pnpm release:publish 更新目录 冒烟目录`。发布入口重复核验包、冒烟原件、源码及main Test。已存在Release拒绝覆盖；上传/发布中断时保留draft，先核对远程状态，不盲目重发或移动tag。当前更新源要求仓库公开，不向应用嵌入GitHub Token。

候选构建仍可独立运行，允许未合入main的干净功能提交；它不授予发布资格：

```sh
pnpm release:build
pnpm release:smoke --candidate .local/release-candidates/候选ID
```

## 应用行为

- 首次手动安装包含更新器的应用。旧安装版没有更新器，不能自动获得第一版。
- 启动及Sparkle定时检查新版本，后台下载、校验和准备；准备完成不自动重启，不中断运行中的员工任务。
- 普通退出时，先沿现有宿主生命周期关闭/排空员工、终端、浏览器并保存设置，成功后交给Sparkle安装。关闭窗口后仍在托盘运行不算退出。
- 桌面设置中的“应用更新”显示当前/新版本、下载进度与更新说明，可手动检查或“重启并更新”。未保存修改仍沿原确认逻辑；退出清理失败保留已准备更新，稍后可重试。
- 桌面附着到独立CLI服务时暂不启用更新；需先退出CLI服务并重开桌面，避免替换仍被独立服务使用的bundle。
- 差分只用于匹配上一版基包；跨版本或不适用时下载完整ZIP。损坏/不能应用的差分由Sparkle回退完整包，完整包校验失败不安装。
- 安装只替换应用bundle。用户数据不包含在更新资产中；本功能没有实现跨数据库schema降级或自动数据回滚。

## 产物与实现

每个Release包含`BoAI-Agent-X.Y.Z-macos-arm64.dmg`、同版ZIP、适用时的`.delta`、`appcast.xml`、`update-manifest.json`、`SHA256SUMS`。订阅地址为`https://github.com/6owen/boai-agent/releases/latest/download/appcast.xml`。安装包的来源SHA、版本、公钥与feed同时写入包内元数据/Info.plist；本地候选路径与私钥不上传。

Sparkle桥接固定`electron-sparkle-updater@0.5.1`。构建显式重编译本机桥接并包含Sparkle.framework；Electron运行时从锁定版本官方ZIP展开，使用随Electron依赖登记的SHA256核验，保留framework链接，避免pnpm缓存把链接展开后导致签名失败。原有资源、原生助手、协议和asar解包范围保留，Sparkle原始许可随包分发。

Electron下载取消原300秒整段上限：完整缓存继续沿依赖自带SHA256核验；未完成字节位于`dist/releases/cache/electron/partial/<SHA256>.part`。每次独立curl重试和后续构建均从断点继续，连接/持续低速失败最多尝试三次。服务端不支持Range时回退重下，校验失败的完整数据丢弃；构建取消会终止curl并保留部分文件。

`AppUpdates`只开放主窗口专用IPC；员工通用RPC不含安装更新方法。主进程统一管理更新状态与退出交接，前端不决定下载完成或安装资格。

## 验证入口

```sh
pnpm exec vitest run tests/app-updates.test.ts tests/release-check.test.ts tests/release-build.test.ts tests/release-smoke.test.ts tests/release-updates.test.ts
pnpm typecheck
pnpm lint:ui
pnpm build
pnpm exec electron-sparkle-updater rebuild --electron-version 39.2.7 --arch arm64
pnpm exec bddgen
BOAI_TEST_SPARKLE=1 pnpm exec playwright test .features-gen/app-updates.feature.spec.js
```

原生BDD使用独立Electron应用与临时Ed25519密钥，核验真实差分退出安装、损坏差分回退完整包并重启、损坏完整包拒绝安装及数据保留。默认不运行，也不触碰个人应用/正式发布钥匙串。实际通过/失败与产品包、Release发布、个人安装的边界分别记录于[03第5节](03-实施步骤与验收.md#5-唯一实际进度)。
