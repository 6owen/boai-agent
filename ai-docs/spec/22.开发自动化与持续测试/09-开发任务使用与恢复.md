# 开发任务使用与恢复

本机入口为`pnpm dev:task`。首版只执行本地用户登记的固定任务JSON，目标base必须等于本地已存在的目标分支；不提供Issue/webhook/外部PR自动执行入口。检查进程沿原工具及本机权限，环境裁剪和独立进程不等于凭据沙箱；不得据此运行外部不可信任务。外部PR的持续测试使用GitHub独立临时runner和只读权限，发布与远程写权限另行分开。

## 1. 输入与领取

任务冻结`taskId/version/goal/acceptance/source/base/targetBranch/paths/setup/checks/model/maxAttempts/maxCodexCalls/maxTokens/timeoutMs/references`。`model`在真实执行时必须明确，首轮失败任务使用了变化的CLI默认模型，不能把它声明成已冻结的模型。Codex会话使用本机登录，禁用自动子代理、插件、hooks和无限连接重试；不会修改全局Codex配置。

`maxCodexCalls`指CLI会话次数，不是供应商内部请求次数。调用前预留，失败不返还；只有实际完整用量可计入已知token，未知单列并停止本任务请求。每轮总时长受登记期限限制；不能把未知用量或会话失败当零成本。

```bash
pnpm dev:task run --config /明确路径/task.json
pnpm dev:task resume --config /同一个冻结路径/task.json
pnpm dev:task status --task stable-task-id
pnpm dev:task deliver --config /同一个冻结路径/task.json
```

相同任务的状态和原件在仓库共享Git目录`boai-development/tasks/<taskId>`，跨worktree共用SQLite领取锁及进程租约。任务代码工作树在原仓库同级`boai-tasks/<taskId>`，独立分支`dev/<taskId>`。不同输入不得沿用同一个ID，重复完成事件返回原结果。

## 2. 开发与证据

控制器先准备冻结环境并跑原检查，再打开只读Codex开发会话。现有大文件用`beforeSha256`及唯一`oldText/newText`局部替换；新文件可提供完整内容，删除须匹配旧hash。所有文件先核对后写入，拒绝越界、链接、过期输入和UI期望基线修改。目录Header/地图也作为普通受控文件修改。

每轮保存有界实时stdout/stderr、进程回执、完整测试JSON原字节/hash与固定候选提交。规定了`report.requiredTests`的检查，必须每个名称唯一且实际通过；`report.format`可显式为`playwright`，省略时保留原Vitest输入及hash。Playwright按spec标题精确定位，每项只能一次实际结果，预期必须为passed；缺失、跳过、重复、重试、全局错误或完整报告不可读，均标为不可用而非业务失败。基线不可用时不调用开发模型，候选不可用时不调用审查或返工模型；原件仍保存。上轮临时报告先移除，防止复用旧报告。检查后确认HEAD和工作树不变。失败与被拒轮次保留，不缩小原分母。

新无历史Codex会话读取任务、固定diff、完整检查原件作审查；结论绑定base/head和检查证据hash。通过后才允许`deliver`。交付按冻结SHA推送，前后核对实际远程base/head；创建draft PR，不自动合并。写入结果未知时先查询同一分支，禁止重复创建。

## 3. 中断与恢复

原生进程监督器观察owner死亡并负责已捕获子树实际退出。领取锁和工作树隔离不能替代进程退出证据。任务登记在`task.json`与`state.json`之间中断时，状态查询明确报告登记中断；重新领取只核对原输入并补注册态，不重复执行。

执行操作中断且回执不完整时，当前入口返回`needs-reconciliation`，保留pending、文件、租约/监督器记录及日志，不自动重放模型、文件应用或远程写入。`status`不会触发请求。PR待核对可用`deliver`先只读查询，再按实际结果继续；新的base/head必须重新检查及审查。

当前流程版本3使用持久游标及逐步骤检查点。完成回执自身hash先锚定到原pending状态，恢复只推进通过核验的游标，不从回执整份覆盖状态；期限、调用/token与检查/审查资格必须匹配原状态摘要。已完成回执持续登记，恢复、批准和交付前重核全部历史原始日志/结果；每份回执保留实际执行器身份。只有显式`resume`才核对并继续；普通`run`重复事件不会继续未知操作。恢复沿最初绝对期限，不重置尝试/调用/token计数。缺少完整检查点的模型/检查继续停在待核对，不自动重复执行；需要根据原件独立处理或建立新任务修订。

完成回执的原字节与hash同一次状态保存锚定；若中断在锚定后、独立完成标记写入前，显式恢复先核对原字节、所有原始文件及状态摘要，再仅补写同一标记并推进。此路径不重新执行检查、模型或候选提交；字节或期限等被改写仍停止。工作树和索引差异均关闭Git重命名折叠，源删除和目标新增都必须属于日记范围。

补丁应用前保存受控文件的前/后字节及执行位，恢复先核对工作树与Git索引的每个目标只处于前态或后态，再只写未完成项。第三种内容、执行位外改、范围外工作树/暂存修改、未知HEAD、符号链接或原件hash变化均停止；工作树还原不能掩盖纯暂存外改。提交已完成时，核对其唯一父提交、原任务提交说明、完整目标字节与干净工作树，再沿原提交接续，不生成重复提交。

控制器记录实际执行bundle的hash及原字节、Node/平台和Codex版本。兼容流程版本3的新控制器必须显式传入`resume --previous-controller <原SHA256>`，核对旧bundle完整字节并记录from/to迁移；不提供原hash或原件损坏则拒绝。旧控制器生成、没有`workflowVersion:3`的任务缺少兼容检查点，不能由新入口自动升级并重放；过渡流程2因回执格式不兼容也拒绝恢复/交付。原件、已交付PR与已知用量保留，后续使用明确任务修订。任务输入`version:1`保持，不与内部流程版本混淆。恢复能力的确定性/真实SIGKILL证明不冒充一次新的真实Codex业务执行。

## 5. 确定补丁错误与有限返工

在任何文件写入前，若现有文件的局部替换缺少旧片段、旧片段不唯一或没有实际变化，整批拒绝，保存原提案/hash与拒绝原因，经原检查点进入原尝试上限内的返工。不会把前面已准备但未写入的文件当成已应用，不生成空候选提交。已用调用/token不返还、最初期限不变；到限停止。越界、旧hash不符、符号链接、外部修改、I/O失败及未知操作仍停止核对，不被此机制当成普通文案错误继续。开发会话输出前须只读核对旧hash及所有oldText唯一匹配；长目录或进度文件按相关内容读取，不能猜测Header。
