| 身份 | 内容 |
| --- | --- |
| 源码 | commit、未提交差异/新增文件、完整sourceHash、构建版本 |

| 执行 | runId、attemptId、重复编号、时间、状态、用量完整性及停止原因 |

先建立同版本重复基线，分清产品失败、环境失败与采样波动。候选在相同任务/环境/配置下比较；改变题目、模型、judge或依赖影响可比性时，注明变量并重新建组，不把不同设置的两份报告直接相减。

已看过的题只能作为开发或独立验证；最终未见题另外隔离。每轮按任务簇报告样本量、成功数/分母、波动和失败类型。统计区间与自动选优沿第15组原合同，小样本或重复访问验证集不能称总体可靠性认证。

建议首轮冻结关键正确性要求：原文/文件正确、权限拒绝生效、无重复副作用和取消后退出等必需项不能退化。内容质量、耗时和资源的具体阈值在观察基线后登记，不靠放宽阈值使候选通过。

## 5. 工程、业务和性能分别评分

- 确定性事实由代码检查实际消息、文件字节、工具回执与进程；失败和缺证据单列。
- 开放内容沿第15组独立judge与人工校准，评价同一输出两次并记录不一致；未校准的模型建议不能单独放行自动选优。
- `passed`、`failed`、`error`、`cancelled`、`skipped`、`not-run`及`review-needed`在报告中分列。缺少必需样本/报告、截断或评分未知不得被算成通过。
- `eval:score`默认生成报告，不等于严格门槛。接CI时必须显式使用当前支持的严格模式，或补能判断原始报告的适配器；退出码成功不能掩盖待评。
- 产品本机能力不施加BOAI预算；测试运行的模型请求、judge成本与开发Codex成本分别记账。调用未知不补发，不为了挑好结果反复重跑。
- 性能使用固定机器、数据规模、冷/热状态及采样窗口，报告样本、P50/P95（样本足够时）、内存和实际进程。沿第17组已有门槛，短期无增长不能称长期无泄漏。

### 本机自动轮询候选

草稿暂缓使用`mode=deferred/full=false`，不是成功的产品检查。`Required checks`独立重算事件状态、标签、完整差异及确切sha/base/head/mode，验证范围job和明确skipped后仍非零退出；汇总写明`product tests were NOT run / Not merge eligible`。转Ready自动完整验证；`ci:full`影响后续新提交，不把暂缓当通过。移除标签后下一次新提交重新判断，转回Draft立即重新判断；`ci:full`保留期间的新push继续完整执行。草稿要立即验证可从Actions手动执行Offline tests并选择明确分支，手动始终完整；文档PR加标签后的新提交也强制完整。

PR仅监听opened/synchronize/reopened/ready_for_review/converted_to_draft；任何标签增删都不单独创建运行，避免无关元数据生成空workflow或替换同提交上的检查。`Required checks`保持固定名称并always执行。PR有效新运行取消旧运行；main/手动已启动运行不主动取消，待执行队列仍按GitHub并发规则合并。main保护、严格最新base、基准只读和原失败留存保持。

### 代理规范和Hooks边界

`AGENTS.md`指向`.agents/skills/boai-dev-workflow/SKILL.md`，Codex/Claude/Pi共用。hooks仅可做轻量提示，不在commit/push时安装依赖、构建、启动本机产品测试、自动push或派发Actions；不安装客户端专属或用户全局hook。服务端workflow负责实际范围和合并资格，不依赖某个客户端是否执行hook。

新专项诊断默认`workflow_dispatch`，明确目标源码/用例并复用入口；不为逐次试错新增push诊断工作流。只在方案确有持续自动诊断需求时配置明确分支/路径及并发取消。手动工作流须先存在于默认分支后才能按GitHub规则派发；不能假设仅推送临时分支即可手动调用。已有临时诊断由其负责分支后续迁移，不跨工作区覆盖正在开发的文件。专项结果不能替代Required checks。
