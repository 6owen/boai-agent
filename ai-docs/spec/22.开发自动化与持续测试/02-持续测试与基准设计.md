# 持续测试与基准设计

状态：2026-10-20仅文档；本次没有运行测试或调用模型。先测当前实际工作树，再测试功能候选，最后把同一计划接入Actions。用例数量、重复数、运行耗时与阈值由真实基线确定，不预写成绩。

## 1. 已有入口与分层目标

当前`.github/workflows/tests.yml`在macOS单job中串行运行`typecheck`、`lint:ui`、`test`、`eval:dataset`和`test:electron`，25分钟上限，失败上传指定报告目录。`eval:dataset`只输出清单；现有workflow定义不代表近期运行已通过。

| 层次 | 触发 | 计划检查 | 判定 |
| --- | --- | --- | --- |
| T1 PR/提交 | PR新提交、main/master push；文档变更按影响分流 | 类型、规则、必要单测、离线协议、固定核心Electron流程 | 确定性结果作为工程门槛；明确收集缺失、skip和中断 |
| T2 定期/按需 | 后续启用的schedule或手动执行，真实模型使用获准配置 | 真实业务任务、API/原生路径、长流程、重复稳定性、性能与资源 | 工程、业务、环境与评分分别报告；未校准语义评价保持待评 |
| T3 交付候选 | 待合并/发布的明确提交及集成版本 | 风险相关完整回归、关键任务与基线比较 | 必需检查成功且证据对应实际交付版本；基线不可比时不签发通过 |

三层是待实施分类，不是当前已存在的新命令。保留已有工作流触发，在实际迁移完成前不提前替换或删除原检查。

## 2. 运行环境与依赖

- Node、pnpm、依赖、操作系统、架构、Electron和测试执行器版本登记并固定；不让`latest`漂移混入版本收益。
- 离线检查采用受控协议服务，不使用真实供应商凭据。测试数据、数据库、浏览器分区和端口按运行隔离。
- GitHub托管runner优先承接类型、离线协议和可稳定运行的Electron场景。实际系统权限、原生应用及长时间GUI操作若需要专用Mac，单独登记runner、登录会话和权限前提；不把跨平台编译称为原生运行。
- 保持`playwright.config.ts`现有串行桌面语义；后续并行只在独立profile、资源锁与实际环境通过后开放。同机完整桌面/压力测试不互相抢占。
- UI预览图、DOM/业务断言、真实文件和人工体验分别留证。截图存在不等于操作正确；离线夹具通过不等于真实模型可用。
- 日常桌面验收沿用户的`pnpm dev`源码进程，核对主进程和服务实际加载的构建；前端热更新不能代替后台重载证据。

## 4. 基线与更新比较

每个基准包至少保存以下身份：

| 身份 | 内容 |
| --- | --- |
| 源码 | commit、未提交差异/新增文件、完整sourceHash、构建版本 |
| 用例与判定 | suiteVersion、caseId、任务簇、输入与附件hash、评分器版本、基线ID |
| 模型 | 员工后端、连接/模型/effort、提示词和绑定技能版本、路由策略及实际模型身份（可获取时） |
| 环境 | OS/架构、Node/pnpm/Electron、锁文件、CLI/插件/资产版本、隔离profile |
| 执行 | runId、attemptId、重复编号、时间、状态、用量完整性及停止原因 |

先建立同版本重复基线，分清产品失败、环境失败与采样波动。候选在相同任务/环境/配置下比较；改变题目、模型、judge或依赖影响可比性时，注明变量并重新建组，不把不同设置的两份报告直接相减。

已看过的题只能作为开发或独立验证；最终未见题另外隔离。每轮按任务簇报告样本量、成功数/分母、波动和失败类型。统计区间与自动选优沿第15组原合同，小样本或重复访问验证集不能称总体可靠性认证。

建议首轮冻结关键正确性要求：原文/文件正确、权限拒绝生效、无重复副作用和取消后退出等必需项不能退化。内容质量、耗时和资源的具体阈值在观察基线后登记，不靠放宽阈值使候选通过。

## 5. 工程、业务和性能分别评分

- 确定性事实由代码检查实际消息、文件字节、工具回执与进程；失败和缺证据单列。
- 开放内容沿第15组独立judge与人工校准，评价同一输出两次并记录不一致；未校准的模型建议不能单独放行自动选优。
- `passed`、`failed`、`error`、`cancelled`、`skipped`、`not-run`及`review-needed`在报告中分列。缺少必需样本/报告、截断或评分未知不得被算成通过。
- `eval:score`默认生成报告，不等于严格门槛。接CI时必须显式使用当前支持的严格模式，或补能判断原始报告的适配器；退出码成功不能掩盖待评。
- 产品本机能力不施加BOAI预算；测试运行的模型请求、judge成本与开发Codex成本分别记账。调用未知不补发，不为了挑好结果反复重跑。
- 性能使用固定机器、数据规模、冷/热状态及采样窗口，报告样本、P50/P95（样本足够时）、内存和实际进程。沿第17组已有门槛，短期无增长不能称长期无泄漏。

## 6. 更新触发与报告

代码、协议、提示词、默认技能、依赖锁文件、插件或上游参考升级都需要影响分析，选择对应检查；不只监听`src/`。只有文档变更时至少核对链接、引用路径、目录地图与声明，不能把未执行产品测试写成通过。

每次运行输出：版本和输入、执行检查、业务成果、与基线的变化、失败/待评/未运行、原始日志定位、资源与成本、结论适用范围。失败任务回流开发队列时携带同一runId与原件身份；基线只在明确审阅后更新，失败不覆盖旧基线。

证据按项目与用户实际保留策略管理：报告不含凭据、真实登录资料或未授权用户内容；不把大量数据库、录屏和构建产物默认提交Git。历史按要求删除的四目标附件不恢复；本次也不生成新测试原件。
