## 3. 两份固定材料与任务

将以下 UTF-8 原文分别写入隔离数据中的输入目录，经实际 `prepareMaterial` 生成宿主私有原件，再关联同一用户消息；不能直接复制到员工工作区来替代附件链。

`订单记录.txt`：

```text
订单编号,状态,金额
O1,已完成,100
O2,已完成,80
O2,已完成,80
O3,已完成,70
O4,已取消,50
```

`核对口径.md`：

```markdown
# 核对口径
按订单编号去重；已取消订单不计入成交。
固定退款金额为20元，从成交总额扣除。
报告保留成交笔数、成交总额、退款额、净额，并引用两份材料的有效行号。
```

文件末尾保留换行。用户明确要求实际发布 `report.md`，标题“订单核对报告”，正文含唯一四行 `成交笔数：<数值>`、`成交总额：<数值>`、`退款额：<数值>`、`净额：<数值>`，引用两份材料的真实 `material:<ID>:text-v1:L<行号>` 或行区间，禁止无依据扩写，本题不要求员工审核。实际提示词以版本化 case 为准。

评分侧固定答案为 3 / 250 / 20 / 230；这些期望值不投影给员工。员工只获得原始资料、用户目标、质量要求与明确授权。

## 4. 必须执行的交付链

| 步骤 | 实际操作与检查 |
| --- | --- |
| 材料 | 两个稳定准备 key，明确仅该员工授权；预览核对原文/hash/解析版本，准备不创建消息或 Work |
| 首发 | 稳定消息 key 将两份材料当前 revision 与用户消息关联；只读查询发送回执，随后等待真实执行 |
| V1 | 唯一真实发布成果；预览并固定成果 ID/hash，保存原文、来源、源消息/Work/run 和内容第 1 版；修订前保存 `beforeRevision` 快照 |
| 修订 | 对固定 V1 ID/hash、明确员工和稳定新请求 key 调用 `reviseArtifact`；保存本人消息和受理回执 |
| V2 | 唯一明确关联 V1 的修订成果；同一逻辑成果第 2 版，原版保留，新根 Work 与新预算不同于旧工作 |
| 采用 | 携带 V2 ID/hash、预期采用 revision 和稳定 key；固定本人保存 current、历史事件与采用回执 |
| 重启 | 关闭服务，在同一隔离目录重新初始化；只读核对原材料、两版正文、修订、采用和工作预算 |

固定修改要求：“针对所选原版修改：保留原统计和两份来源，新增二级标题‘处理说明’。明确说明重复的 O2 只计算一次、已取消的 O4 排除；不得添加资料外假设。发布修订后的 report.md。”实际传入文本与版本化 case 完全一致。

新根及预算不复用已交付旧 Work 或 occurrence；`Work.resultVersion`、`requiresReview` 不作为成果内容版号。重启前后供应商请求数量与工具事件保持不变，不续行修订或重新生成文件。

## 5. 完整留证与样本身份

- 材料：两份原件原文/hash、解析正文/有效行、材料 ID/revision/parseVersion、聊天范围、授权成员和实际消息关联。
- 版本：V1/V2 的完整实际字节/hash、成果 ID/逻辑 ID/内容版号、前版与修订请求、材料来源和发布身份。
- 受理：首发与修订载荷/key、本人消息、只读消息回执、修订关系、新旧根 Work 和预算。
- 原交付：`beforeRevision` 中原 Work、累计预算和 V1 原文，与修订/采用后的 `beforeRestart` 对照，证明原交付不被覆写或重置。
- 采用：明确 V2 载荷/key、预期 revision、当前指向、本人事件与原采用回执；保留 `adoptionActor=script`、`humanAcceptance=pending`。
- 重启：前后完整聊天、材料预览、成果预览/采用历史、修订记录、请求计数、Work/预算及 run 工具事件快照。
- 运行：阶段耗时、实际请求/错误、已知与未知用量、工作树/事件、启动或中断失败；原 SQLite 与受管文件目录一并保留。

新增 `delivery` 原证据包含 `contractHash`（固定交付合同完整内容的 hash），并与对应评分合同、原始任务、硬检查和语义标准一起纳入既有 `sampleHash`；人工评审绑定该 hash、题目和评分版本。旧样本没有 `delivery` 时保持原 hash 算法结果。原件或证据缺失不能通过补跑业务来修补原样本。摘要截断、超过留证上限或文件不可读取均显式记录为证据不足。

## 6. 评分与人工边界

确定性检查核对两份授权材料、四项数值、有效引用行、真实文件 hash、修订新根/预算、原 Work/累计预算/V1 正文保持完整、本人采用及重启零新增请求/工具。引用行存在并不证明它支持该陈述，V2 出现标题也不证明修改内容正确。

人工分别核对：两版事实与统计完整正确且无无依据扩写；引用的实际行支持对应陈述；V2 准确说明 O2 去重/O4 排除且保留原统计。每项填写 0/1/2、理由和真实材料/成果/消息等证据 ID，绑定完整 `sampleHash` 后离线重评分。

脚本调用“采用”只证明版本/回执技术操作，不代表用户质量认可；技术全通过而人工未完成时仍为 `review-needed`，不得计总通过。辅助模型未经既有至少 20 个独立正负人工标签、同版校准及关键漏判门禁时保持 pending。

传统 `review-lineage` 检查审核员实际读取 `draft.md` 与最终 `report.md` 的同字节及发布先后；它不等于成果每版审核。本题未要求员工审核，V1/V2 均不得继承或虚构审核记录，独立人工评审也不自动写入产品审核状态。
