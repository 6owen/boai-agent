## 审计中修复的缺口

1. 取消逻辑曾提前释放共享模型槽位，未响应取消的适配器仍实际运行。现在调用方可立即退出，槽位持续持有到适配器真正结束；新增回归先复现超过容量，再验证修复。
2. 委派子工作曾受单轮队列串行限制，独立短任务被长任务阻塞。现在不同负责人的定向工作在既有两项任务上限内并行，同负责人仍串行，共享资源互斥和用户新输入优先保留。
3. 补充并行子工作停止与合法相同聊天回复回归，避免只验证正常交付路径。

## 真实模型评估现状

已实现手动 `pnpm eval:collaboration`，9 个固定场景、双版本隔离数据、每场景 5 次、请求上限、原始输出/失败/用量保存和待人工复核字段。当前/基线两种源码均通过本地协议服务的采集链路检查，该检查只证明评估工具能运行，不是模型语义或性能证据。

首次真实试运行标签 `candidate-pilot`，使用现有 `deepseek-flash` 连接。在读取凭据时返回“无法解密模型凭据，请重新填写 API Key。”，尚未发出供应商请求；尝试目录为 `.local/collaboration-evaluation/candidate-pilot-20260928`。该目录保存运行配置，失败来自当次命令输出，早于新增的自动 `startup-error.json` 落盘能力。没有将此次配置失败计作场景样本，也没有重复请求或改写门槛。

随后定位到评估宿主的启动顺序错误：异步读取配置后才设置应用名称，Electron 已经用启动时的名称初始化 macOS 凭据服务。现将名称与隔离目录在首次异步等待前同步设置，与产品宿主一致；没有修改或重存用户凭据。依据为 [Electron 39.2.7 初始化源码](https://github.com/electron/electron/blob/v39.2.7/shell/browser/electron_browser_main_parts.cc#L460)。

修复后的 `candidate-pilot-startup-fixed-1790530186916` 已完成真实正式 @ 场景：只有写手公开答复，失败运行为 0，首次可见回复 4,585 ms。该试运行不计入正式样本，不据此推断整体质量或速度。此前要求重新保存 Key 的判断撤回，原凭据可用。

基线和最终候选各复核 45 个完整样本；前两版候选失败完整保留。最终候选委派 5/5、独立文件 4/5，其余各 5/5，符合 06 的预设门槛。三类简单社交的延迟/判断输入在门槛内；整体已报告总 token 增加约 31.5%，任务首个有效结果更慢，不宣称整体性能收益。独立文件的一次无依据扩写判失败，另一次判断连续截断保留错误。详情见 [08](./08-真实模型评估结果.md)，不把协议正确性等同于任意业务都能完成。
