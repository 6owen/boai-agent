# 实施阶段与验收

日期：2026-09-27。状态：**全部 G 阶段待实施；本文不是测试通过记录。**

本次按 [Paperclip 研究](./05-Paperclip机制与方案修订.md)修订顺序：G2 拆成 G2a/G2b，把原 G3 的最小工作记录、认领和预算前移。G3 继续负责业务协作深化；编号 G0–G4 保留，避免旧引用失效。

## 1. 开始前

先读[当前差距](./02-当前实现与差距.md)和当时源码，记录代码版本、模型/供应商、提示词版本、成员配置和预算。已有未提交改动应保留，避免把 UI 调整或其他能力开发纳入本组。

结构拆分继续遵守 [B3](../4.数字员工与协作重构/03-群组协作与运行生命周期.md)。若 B3 尚未完成，先完成当前阶段真正依赖的最小边界，不以本组为由一次拆出全部目标目录。

## 2. 分阶段交付

| 阶段 | 最小范围 | 前置条件 | 退出条件 |
| --- | --- | --- | --- |
| G0 协作基线 | 整理既有回归，补关键真实模型场景，记录延迟/成本/质量 | 当前可运行版本 | 场景可复现，失败分类明确，无生产行为变化 |
| G1 判断与投递 | 精简 decision 输入、同轮事件合并、连接级容量；可选判断模型实验 | G0，清楚的运行边界 | 不丢首次机会和用户输入；合并/限流不吞事件；成本收益有证据 |
| G2a 最小任务控制 | 稳定工作 ID、负责人、run 执行权、最低交付证据和跨 run 预算 | G1，runs/collaboration 边界清楚，存储条件更新方案 | 同任务仅一有效执行者；旧 run 不释放新锁；重试不清零预算；保持串行执行 |
| G2b 执行与发布 | 有限并行独立 task、草稿与活动分离、发布一致性检查 | G2a；共享资源冲突策略明确 | 慢任务不占用其他独立任务执行；无过期发布、重复副作用或错序 |
| G3 委派与终止 | 父子任务、显式依赖、当前宿主内的定向接续、完成/阻塞证据和根任务预算 | G2b，工作记录及执行权可靠 | 父子不混作依赖，失败不视为成功；无评论自唤醒；子任务不能绕过预算 |
| G4 持久恢复（按需） | 跨重启自动恢复、外部事件/定时唤醒，与自动化衔接 | G3，存在持续执行需求 | 重启、重复事件、暂停、撤权不会漏处理或重放不明副作用 |

G1 不必须同时交付独立判断模型。G2a 不要求完整看板或组织管理，只新增执行确实需要的最小数据；普通聊天不建工作项。G3 可在一次应用运行期处理跨轮次任务；G4 不阻塞这些改进，未交付前重启仍中断、不自动重放。

## 3. 每阶段修改顺序

### G0：先获得证据

复用现有服务、引擎和桌面回归，区分已有覆盖与新增缺口；不把历史测试数量当作本次证据。真实模型场景使用隔离数据，建议每个关键场景至少重复 5 次，保留全部成功和失败记录。供应商调用只有在实际执行评估任务时才发生。

### G1：逐项比较

先调整可核对的事件处理和输入范围，再做模型实验；每次只改变一个主要因素。合并保留事件引用，退避能取消；多会话共享同一连接的调用也要测试。比较后的默认策略写明适用范围，不能仅凭一次成功选择小模型。

### G2a：先固定工作责任与执行权

定义工作创建条件、稳定幂等来源、长期负责人和当前 run 执行权。认领、预算准入和状态变更走同一原子边界；当前 ProductStore 的串行 write 本身不满足条件检查与写入一体化的要求。旧 run 只可释放仍属于自己的执行权。已登记工作结果、已知副作用和待核对操作必须保留。

这一阶段先保持实际执行串行，验证新工作记录与原 turn/run/Contribution 的兼容。不同 run 的重试归入原始工作预算；最低交付证据与“这次运行成功”分别保存。新工作数据需迁移版本和回退读取方案。

### G2b：先解决可见性，再放开执行

先确定草稿/活动/公开消息的差别与序号分配，再引入有限并行。发布检查覆盖工作执行权、新消息、停止、撤权和写入失败。不同工作也可能冲突于相同文件/外部资源，冲突操作保持串行；不能并行后再依赖回复去重补救。

短 chat 保持现有流式；task 已完成操作只生成一次，草稿过时最多重新汇报。补判、失败恢复和丢弃草稿都计入预算与活动记录。

### G3：委派、依赖和业务终止

定义父子工作与执行依赖两个关系，保存目标、所需结果版本和等待周期。子任务成功后只通知真正等待它的员工；失败/取消触发阻塞处理，不自动当作成功结果。负责人仍由任务范围决定，不引入强制 CEO 或全群发言主持者。

工作状态与待通知记录原子提交；同一等待周期只消费一次逻辑就绪状态，新周期不被旧回执拦截。来源 run 自己的评论不唤醒自己，已结束任务不会因感谢而重开。引擎终态与已交付/有进展/等待/阻塞/无进展分开。

扩展 G2a 预算到根任务及全部子任务，分别限制运行重试、无进展继续和发布补判。停止根任务覆盖其子任务与排队唤醒，但不连带取消其他工作共享的依赖。只有这些规则验证后，才按任务范围调整原次数/代数限制。

G3 的未处理接续记录持久保留，但重启不会自动执行；此时显示中断或待明确恢复，避免将 G4 的自动恢复语义提前启用。历史 Contribution 保留原含义，迁移有版本、兼容读取与数据副本验证。

### G4：仅唤醒有明确条件的工作

订阅与事件消费需要处理“事件刚发生、订阅刚建立”的竞争；接纳/送达/业务完成分别记录，重复投递通过幂等准入去重，不宣称外部效果 exactly-once。重启后先对账权限、暂停、预算、依赖和工作状态，并在真正启动前再检查；不能凭超时推断外部操作没发生。时间触发接入原自动化模块，不复制新调度时钟。

## 4. 关键验收矩阵

| 场景 | 必须满足的结果 | 阶段 |
| --- | --- | --- |
| 6/12 位员工收到群体介绍邀请 | 所有有效成员有首次判断机会；不要求强制全员回复 | G0/G1 |
| 旧群再次问候、重试旧请求 | 历史不冒充本轮已回复；重试有新 turn | G0/G1 |
| 明确 @ 与自然语言点名 | 正式 @ 不抢答；自然点名以模型场景评估，不加关键词硬路由 | G0/G1 |
| 全员 pass、某成员模型失败 | 前者合法沉默，后者明确失败，不能互相替换 | 全阶段 |
| 连续多条 agent 事件 | 合并后每条输入仍有处理依据，无等待者丢失 | G1 |
| 多群共享连接遇到限流 | 容量有界、退避不忙循环、取消可退出、输入不丢 | G1 |
| 普通聊天、明确执行请求 | 前者无需工作项，后者有稳定目标/负责人/预算归属 | G2a |
| 两人同时认领同一工作 | 只有一有效 run，冲突方不忙循环争抢 | G2a |
| 同员工旧 run 迟到结束 | 不能清除新 run 执行权或覆盖较新工作状态 | G2a |
| 同一工作不断重试/换 run | 调用与已报告用量仍累计原始预算，不能重置 | G2a |
| A 长调研，B 独立短任务 | B 可独立推进；发布顺序与消息展示一致 | G2b |
| 不同任务修改同一文件 | 仍受共享资源冲突限制，不因不同 workId 放行 | G2b |
| A 先提交，B 草稿基于旧状态 | B 读取新事实后补充或沉默，不重复已完成操作 | G2b |
| 两人相同投票/简短问候 | 合法独立回答不被通用正文去重误伤 | G2b |
| task 已写文件后收到新消息 | 只更新结果汇报；不得重跑写入或命令 | G2b |
| 用户停止、撤权、删除成员 | 在运行任务及队列失效，迟到草稿/工具事件不能复活 | 全阶段 |
| 最终写入失败或发布时发生竞争 | 不确认成功，不提前消费投递；重试不能重复提交 | G2/G3 |
| 有父子关系但没有依赖边 | 不擅自阻塞父工作；父任务不因子任务都终态而自动完成 | G3 |
| 子任务失败/取消 | 通知负责人处理阻塞，不解除成功依赖、不启动依赖其结果的工作 | G3 |
| 依赖完成回调重复、下轮再次等待 | 同一就绪状态不重复唤醒，新 waitRevision 可正常唤醒 | G3 |
| 员工发布自身进度或完成后的感谢 | 不自唤醒或重新开启已结束任务 | G3 |
| 模型正常退出但只说准备开始 | run 可完成，工作不能假完成；按有限无进展策略处理 | G3 |
| 用户只要求计划 | 计划可作为交付，不强制执行额外工具 | G3 |
| 委派很多子任务或循环重建子任务 | 合计受根任务预算、范围与无进展限制 | G3 |
| 停止根工作且依赖被另一工作共享 | 子任务和待处理接续停止，共享依赖不被误取消 | G3 |
| 依赖失败、环依赖、持有者失联 | 失败可见、等待有界，不自动重复未知副作用 | G3 |
| 连续“收到/赞同/继续” | 不被记为真实工作进展；在宿主边界内停止 | G3 |
| 任务有剩余项但成员已各回复一次 | 完成判断依据任务证据；达到预算时如实停止而非假完成 | G3 |
| 重启和重复完成事件 | G4 前中断不重放；G4 后仅恢复明确未消费的合法输入 | G4 |
| 暂停、关闭任务、恢复备份 | 旧唤醒不能重新启动已失效工作 | G4 |

## 5. 评估指标与判定

程序不变量由确定性测试验证；语义质量由真实模型重复试验和人工复核评估。使用相同场景、模型配置和预算比较改动前后，并记录变化项。

| 指标 | 口径 |
| --- | --- |
| 首次有效回复延迟 | 用户输入到首条有用公开回复；样本足够时看 P50/P95 |
| 不必要回复 | 重复事实、无贡献附和占 agent 公开消息的比例；复核规则随场景记录 |
| 漏回复 | 明确需要该员工回应却无人处理的场景比例；与合法 pass 分开 |
| 任务完成 | 预先定义的交付物/步骤完成比例，不能以聊天条数替代 |
| 判断开销 | decision 次数、修复次数、输入/输出 token；未知字段保留未知 |
| 无进展接续 | 连续接续期间无结果、产物或依赖变化的次数 |
| 发布冲突 | 草稿因过期被更新/放弃的次数，以及额外成本 |
| 等待开销 | 队列、模型、审批、依赖分别计时 |
| 有效运行比例 | 成功 run 中具有交付、可核对进展或有效等待的比例 |
| 唤醒开销 | 自触发、重复就绪和无需工作唤醒的次数；与正常群聊判断分开 |
| 根任务总用量 | 原始工作及其全部重试/子任务的合计，不能只统计最后一个 run |

安全与一致性不变量必须全部通过。语义指标先建立基线，再在每阶段开工前写清接受阈值；不能看到结果后临时改通过标准，也不能为追求更少 token 接受明显漏回复。

## 6. 验证、迁移和回退

- 每次实现先运行受影响回归；阶段完成执行类型检查、完整相关测试和生产构建。消息或活动展示变化须验证真实 Electron 流程。
- 涉及持久数据、权限和恢复，使用隔离副本验证；不得清空旧群历史换取通过。
- 有新字段/记录时先定义兼容读取与迁移版本；不要让旧应用误执行新任务状态。
- G2a 新记录必须在保留串行执行时验证；G2b 才开放并行。退回串行策略前先停止新执行，完成执行权与已知状态对账；不能同时让新旧调度器消费同一输入。
- G4 回退先停用新唤醒入口，保留工作历史与未消费证据；不删除用户文件或以重放补齐未知结果。
- 同步实现文件 Header、所属 `.folder.md`、本组阶段状态与第 2 组实际交付记录。代码归属变化再更新更上层地图。
