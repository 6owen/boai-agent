# 思考强度与日常响应延迟

更新：2026-09-28。已实现 composer 二级菜单与真实 SDK 参数传递；尚未进行真实服务的修改前后延迟、语义质量对照评估。

## 故障证据

用户反馈 `deepseek-v4-pro` 回答“今天星期几”约 18 秒，并且看起来没有流式输出。对该轮本地已保存 Trace 只读检查得到：

| 阶段 | 宿主记录耗时 | 模型输出用量 |
| --- | --- | --- |
| 参与判断 | 8.531 秒 | 541 tokens，其中 reasoning 521 |
| 回复与执行（实际 responseKind 为 chat） | 7.198 秒 | 599 tokens，其中 reasoning 595，正文 4 |
| 记忆整理 | 2.082 秒 | 70 tokens，其中 reasoning 63 |

三个阶段的模型排队、退避与限流重试均为零；模型 Span 均标记 `streaming: true`。前置参与判断完成后才进入回复；回复本身的大部分生成用量又是推理，公开正文只有一句，因而逐段输出不明显。记忆整理发生在公开回复之后，不能把总耗时全部归因于等待正文。

当前 Trace 的 `completionStartTime` 可能对应推理 chunk，不能当作首个可见正文时间。当前不保存每个模型 chunk；没有足够证据给出这一轮精确的首字耗时。本记录不复制私有推理正文或凭据。

## 用户配置

唯一入口：**单聊 composer 右侧模型菜单 → 思考强度**。模型连接设置不增加“日常响应”或第二份思考配置。

| 选项 | 生效行为 |
| --- | --- |
| 自动（默认） | 聊天、参与判断、记忆整理使用低强度；任务执行与发布前重新汇报沿用服务默认 |
| 关闭 | 当前员工各阶段发送关闭思考参数 |
| 低 | 当前员工各阶段使用 low |
| 高 | 当前员工各阶段使用 high |
| 最高 | 当前员工各阶段使用 max，可能增加等待和输出预算消耗 |

配置保存为 `DigitalAgent.thinkingLevel`，作用于该员工后续调用，也包括其群聊调用。多个员工共享同一连接时互不修改对方的档位；不是本次消息临时字段。旧员工省略字段等价于自动；旧编辑表单省略该字段时保留已保存值。选择“自动”显式恢复默认策略。

菜单复用 Base UI 子菜单、键盘操作、当前档位展示和已有运行/未保存配置锁定。不切换模型 ID，不把确定性路由交给额外模型判断，不取消参与判断或工作认领，也不更改工具授权与任务发布规则。

## 适配范围和请求映射

本次适配已验证的 **DeepSeek 官方 Chat Completions**：`api.deepseek.com` 下的 `deepseek-v4-pro`、`deepseek-v4-flash`（及四位日期后缀）、`deepseek-pro`、`deepseek-flash`。以员工实际生效模型为准，员工覆盖模型优先于连接默认模型。

其他服务、第三方兼容网关、Responses/Anthropic 协议、旧 reasoner/chat 名称及未知模型暂不发送本次专用参数，也不显示此菜单。它们需要各自协议和模型能力的验证后再扩展，不能只按“兼容 OpenAI”推断都支持。

按照 [DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，服务默认启用思考且强度 high；`thinking.type` 控制开关，`reasoning_effort` 控制强度。安装的 Mastra 1.71.0 显式 URL 路由使用 OpenAI-compatible SDK，命名空间为 `openai`：

- 关闭：`providerOptions.openai.thinking = { type: 'disabled' }`。
- 开启：`providerOptions.openai.thinking = { type: 'enabled' }`，搭配 `reasoningEffort`。
- SDK 将 `reasoningEffort` 转换成请求正文 `reasoning_effort`，`thinking` 原样放入请求正文；不能照搬 Python 示例，把 `extra_body` 当成额外一层请求参数。
- 自动的任务/汇报阶段不传覆盖参数，保留原服务行为；连接测试属于轻量探测，使用低强度并为推理预留输出上限。

实现入口：`src/shared/domain/model-preferences.ts` 定义能力边界与档位；`src/runtime/adapters/mastra/model-config.ts` 映射参数；`engine.ts` 按阶段传入；`composer-toolbar.tsx` 提供入口；`EmployeeService` 校验和保存字段。没有把相同配置写入连接记录或增加环境变量。
