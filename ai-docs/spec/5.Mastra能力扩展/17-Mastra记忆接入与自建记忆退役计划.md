# Mastra记忆接入与自建记忆退役计划

日期：2026-10-30。**用户已授权实施，当前为隔离源码及工程验证阶段。** 目标与归属以[16架构](./16-按执行内核归属的记忆架构.md)为准：API使用Mastra Memory，本机Agent保持原生记忆，BOAI退出重复的记忆引擎职责。

## 1. 实施范围

本次目标是覆盖Bobo和普通API员工的真实记忆链路，接入官方历史、Working Memory、OM和语义回查，并退役对应自建逻辑；本机路径只退出额外BOAI记忆处理，不改变其原生执行循环。

BOAI继续负责员工、产品消息、权限、任务和成果。必要接线必须能对应这些产品职责，不能以“适配器”为名保留自建提取模型、文本打分器或第二套历史压缩器。旧功能有上游缺口时，先核实官方接口、配置或升级路径，明确有限产品适配范围，不默认为继续自研内核。

## 2. 分阶段工作

| 阶段 | 具体工作 | 退出条件 |

| MM2 官方长期与语义能力 | 接Working Memory更新、OM及官方语义回查；配置embedder/向量存储和模型生命周期 | 改写问法与长会话可回查；不靠旧关键词召回兜底冒充官方能力通过 |

## 3. 数据切换与回退

1. 先对隔离副本清点：员工/后端、有效记忆、公开历史、来源范围、纠正与删除记录；保留迁移前备份，不重新执行旧业务。
2. 为有效数据建立稳定映射和幂等迁移回执。短期历史、持续信息、旧经历分别进入合适的Mastra存储；不把所有旧条目拼成无限Working Memory，也不让已删/撤权数据重新参与提取或embedding。
3. 在线切换按员工与后端明确生效点。切换前旧路径负责，切换后Mastra负责；迁移核验可读旧数据，不让两套引擎长期共同学习、更新同一事实。
4. UI和应用操作改接新的真实数据来源。不能继续展示旧MemoryEntry列表，却让运行时使用另一份未同步的Working Memory。
5. 来源修改/遗忘/清理须核对消息、WM、OM和索引的实际结果；涉及异步处理时保留真实状态，完成前阻止旧数据继续注入。已有产品范围与纠正语义不能因换存储消失。
6. 回退必须核对切换后的新写入与版本；不直接覆盖旧库、不自动重放模型调用。原生Agent的私人数据不包含在BOAI记忆迁移或清理范围内。

本机与API切换不自动跨引擎搬运记忆。原生程序配置、登录、系统文件和记忆文件保持原样，BOAI只恢复对应后端自己的会话绑定。
