# 员工与群聊自动化设计与实施计划

日期：2026-10-14。状态：**用户确认方向，文档已复核，运行代码未修改，新验收未运行。** 本次授权是整理未来实现文档；此前其他功能的编码授权不扩大为本增量开工授权。

## 1. 目标与文档优先级

数字员工是执行主体。自动化是本人交给某名员工或某个BOAI员工群的持续工作安排。用户在该员工/群的对话中创建和修改计划，在右侧查看配置、历史和单次执行；sidebar自动化页汇总同一批计划。

本篇更新[07原设计](./07-自动化产品与运行时设计.md)和[旧七项表单规格](../3.前端重构与功能/18-定时任务体验简化/README.md)的**后续归属与交互目标**。现有Mastra时钟、事务受理、执行回执、Work、历史及未知不重放继续复用；旧API/本机混合预算条款按[第13组14最新规则](../13.本机Agent员工运行时/14-本机Agent输入交付与原生信息修复合同.md)阅读，本机执行不施加BOAI用量/时长预算。

自动化与[员工浏览器操作](../11.浏览器能力迁移/06-数字员工浏览器操作设计与实施计划.md)是两个独立闭环。普通员工任务和群内“采集数据→汇总数据”必须能先验收，不依赖浏览器改造、OpenCLI、云端执行或可视化工作流编辑器。自动化浏览网页、主动发飞书作为后续组合场景分别验收。

## 3. 领域关系

### 3.1 计划必须有明确归属

| 概念 | 目标合同 |
| --- | --- |
| 计划归属owner | 一个员工ID，或一个已有BOAI群ID；每个计划只有一个归属 |
| 创建来源 | 本人在哪条BOAI/渠道消息中提出、采用了哪版草稿；用于核对创建意图，不决定执行归属 |
| 执行配置 | 员工计划使用该员工的有效执行配置；群计划保存参与员工、分工、汇总负责人和必要依赖 |
| 执行记录occurrence | 一次定时或手动触发，绑定固定计划版本、实际参与者/配置快照和工作结果 |
| 执行上下文 | 承载本次消息和原生session的内部任务上下文；不创造另一名员工或另一个可管理的BOAI群 |
| 结果目的地 | 应用内归属聊天；外部主动投递是另行配置的能力，不等于创建来源或机器人绑定 |

员工组在本篇指BOAI群聊，不是通讯录标签，也不是单个员工的飞书渠道群会话。第16组当前为“员工×外部来源”独立会话；不能把外部群自动转换为完整BOAI员工群。

计划归属与执行后端分离：员工切换API/Codex/Claude不改变owner。执行前核对实际配置及保存的授权版本；来源或权限变化需要处理时明确说明，不静默换另一个模型或员工。

### 3.2 上下文与展示

新计划默认延续现有`purpose=automation`的独立任务上下文。群计划扩展为带实际参与者的任务上下文，并关联原群owner；不为每次运行在普通会话列表新增一个员工或BOAI群条目。用户从owner右侧的执行记录进入本次详情。

任务结果以有真实来源的摘要、文件引用和执行记录入口回到owner聊天。不能把执行上下文里的私有消息直接改conversationId、伪造成主私聊/群内原始消息；文件跨上下文投影须经现有来源授权和原件校验。

群共享材料按当次授权范围引用；新任务上下文不是读取成员私聊、私人文件或所有历史的捷径。新计划的人工聊天与自动化上下文分开续用原生session，员工及occurrence身份必须参与任务会话映射，跨员工、跨次运行不共用线程。不能因查看详情或重启重新发送任务；旧计划是否已隔离按原执行策略记录，不能补写为已满足新默认值。

旧计划的existing-conversation/new-conversation策略保留实际含义，迁移规则见§7，不借新默认值批量重建旧会话。

## 4. 群内多员工分工

用户确认的代表场景：每天由采集员获取数据，分析员读取这次数据并总结。计划中保存真实成员ID、职责、结果要求和汇总负责人。自然语言是输入方式，宿主核对成员和依赖，不能靠员工姓名文本猜身份。

首版沿现有委派/等待机制执行：汇总负责人承接本次根工作，委派采集工作，等待其真实结果，再继续分析和发布。不引入新DAG执行引擎或让每个员工拥有一份独立定时器。

```mermaid
flowchart LR
    T[一次触发 occurrence] --> B[汇总负责人承接根工作]
    B --> A[采集员执行子工作]
    A --> D[发布本次数据和来源]
    D --> W[核对依赖后唤醒汇总负责人]
    W --> R[发布总结与采集结果引用]
    R --> O[本次整体结果]
```

执行规则：

1. 一个逻辑触发只有一个occurrence；负责人只启动一次。群内普通提示消息不能再次触发全员独立判断/重复采集。
2. 可有多名采集员并行工作；汇总依赖明确列出的结果。依赖ID、结果版本、文件hash及occurrence归属必须可核对。
3. `wait_for_work`等已有机制记录等待并在依赖就绪后唤醒，不轮询聊天中是否出现“完成”二字。
4. 采集失败、取消、来源失效或结果未知时，依赖尚未满足。可以发布明确的失败/部分结果说明，不能冒充完整总结。默认不拿昨天的产物补齐今天的输入。
5. 群成员不是必然参与者。计划只唤醒所需成员；未来动态分工须限定在已授权群成员内，首版以保存的明确分工为准。
6. 非循环依赖才能保存；成员缺失、自依赖和循环依赖在受理前拒绝。无需先建设通用工作流画布。
7. 整体完成要求必需子工作及最终交付均有真实证据。Mastra调度成功、模型结束或采集员先完成，不等于整个计划完成。
8. 暂停计划只停止未来触发；停止本次沿原工作树取消并等待实际执行器退出。停止一个计划不能终止同员工的无关聊天或其他计划。
9. 编辑计划只影响后续触发。当前运行保持其版本和分工；成员移出/权限撤销属于即时权限变化，阻止继续读取或执行失效范围。

## 5. 对话创建、修改与右侧详情

### 5.1 对话入口

- 员工主私聊默认owner为该员工；BOAI群默认owner为该群。跨对象创建必须来自本人明确请求及有权上下文。
- 用户明确“创建/每天执行”，参数完整时，经同一自动化服务直接保存并返回计划ID、时间/时区、负责人、分工和下次执行。只有“帮我设计一个方案”时生成草稿，不启用计划。
- 缺少执行时间、数据范围或汇总负责人等实质信息时在原对话补充；可确定的owner、此设备和时区默认值写入可审阅摘要，不重复询问。
- 草稿和正式计划区分身份/版本；仅生成说明文字不能宣称创建成功。用户编辑后，迟到的模型候选不得覆盖新版本。
- 查询、创建、修改、暂停、恢复、立即运行和删除复用同一组产品服务；语义工具名称实施时确定，不复制业务逻辑。API走现有工具装配，本机沿Codex动态工具/Claude产品MCP桥增量接线，保持原生执行循环。
- 同一用户消息/保存意图使用稳定请求身份；重复工具调用或保存回执失联只核对原结果。不能为“重试创建”产生另一份计划。
- 普通员工只获得当前本人授权范围内的计划管理权；不因被群内其他员工提及而创建长期计划，不在未受信任渠道消息或网页文本中推导管理授权。

### 5.2 员工/群右侧面板

| 阅读层级 | 内容与操作 |
| --- | --- |
| 自动化列表 | 当前owner的计划、下次执行、最近结果；新建/暂停等使用同一保存服务 |
| 计划配置 | 要求、时间/时区、参与员工、分工/依赖、汇总人、结果设置；明确编辑版本和未保存草稿 |
| 执行历史 | 当前计划的分页历史、状态与结果摘要；支持定位某一次执行 |
| 单次执行 | 各员工真实工作、依赖状态、工具/公开进度、问题、成果和适用投递回执 |

沿BOAI当前详情Tabs、执行面板、文件预览和主题实现，不另造一套组件。单次详情复用原Work/执行事件/成果，不用模型生成第二份“执行状态”。等待问题沿原任务问题或原生待决输入身份补充，普通聊天不能隐式解锁错误的occurrence。

sidebar保留全局dashboard：按owner、时间和状态查看计划及执行；所有入口使用相同计划ID/版本和服务。可从总览进入相应详情，不维护另一份配置。跨主页面仍分别保存详情Tabs/草稿，隐藏页面停止主动查询。

### 5.3 频率、运行位置与结果

首版复用每日、每周、工作日/星期多选及明确时区。一次性、每月、自定义cron或外部事件触发不是本篇前置条件；遇到不支持的要求说明真实限制，不擅自改成每天执行。

应用在设备醒着且进程存活时执行，后台常驻沿第17组。休眠、关机、真正退出期间不运行；错过时间如何记录沿现有日历/misfire规则留证，不自动补做所有历史次数。计划本身可有并发/重叠准入规则，这不等于限制本机Agent用量或运行时长。

应用内结果与系统通知先完成闭环。飞书主动投递列为EA4组合扩展：显式选择绑定、本人账号/外部群及内容范围，保存投递意图与回执；禁止沿最近外部联系人推导。来自飞书的计划管理只接受已核对本人的授权，沿原来源回复创建结果；其他渠道授权用户不能因此取得本人长期计划管理权。

## 7. 兼容迁移

- 新定义使用明确版本区分owner和分工。旧定义只在所属员工/BOAI群能从持久关系唯一证明时补owner；核心会话、渠道会话、已删除对象或不明来源保留旧记录并标记待关联，不猜测、不启动迁移任务。
- 旧existing-conversation执行位置和新任务聊天策略保留。关联owner不复制历史、不移动消息/文件、不合并原生session，不隐式新增外部投递。
- 旧existing-conversation若要改为新默认隔离上下文，通过明确编辑产生新的执行版本，保留历史定位；owner补全本身不完成这项转换。
- 迁移不能重新受理历史occurrence、创建新定时器或补发旧结果。默认启停状态和已保存时区不变；仍保留现有启动授权核验。
- 员工删除或群解散后暂停未来计划，保留历史；运行中的来源撤销沿原停止/实际退出机制处理。仅隐藏聊天不等于删除owner。
- 全局页和owner页显示同一计划；旧全局创建入口可以暂时保留为兼容入口，但最终保存仍需明确owner。
