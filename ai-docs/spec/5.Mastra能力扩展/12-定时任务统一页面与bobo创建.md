# 定时任务统一页面与 bobo 创建

本轮用户明确要求直接修改代码。定时任务页统一创建和管理；新建只选择一名通讯录员工，员工组协作不在这次新建入口开放。旧群计划、旧指定会话、历史执行和回执不迁移或删除。第5组11、第3组18中与本页冲突的旧界面合同由本篇替代；原调度、权限、执行、通知和未知不重放继续有效。

## 1. 页面与交互

- 左侧复用会话列表的标题、宽度、分割线和分组样式。原搜索位置为「新建定时任务」按钮，下拉仅「手动创建」「对话创建」。下方「全部定时任务」列出所有计划，包括暂停计划。
- 未选择计划时右侧使用与会话共用的 `IllustratedEmpty`，不展示额外总览卡片或重复创建按钮。
- 手动创建在右侧主内容区显示名称、描述、任务指令、执行员工和日程。员工列表来自通讯录，现有运行资格由前后端核验；不提供群选择。保存后左侧出现同一计划，主区进入该计划详情。
- 员工资料首页和原自动化标签只读展示本人计划。点击通过 `ScheduleNavigationContext` 回到全局定时任务页，不在员工内复制编辑器或启动任务。
- 计划详情保留编辑、暂停/恢复、手动运行、删除和本计划执行记录；全量历史从标题更多菜单进入。历史搜索状态保持，删除计划不删除历史。
- 旧暂停计划编辑后仍暂停，旧通知/时区/指定聊天保持。创建提交与回执同事务；未知提交保留原请求，重启先核对。

## 2. 共用日程 JSON

手动表单与 bobo 的 `manage_automation` 使用同一个 `AutomationInput`、schema 和保存服务。字段增加可选 `description`、`startsOn`（所选时区的 YYYY-MM-DD）和 `dayOfMonth`。工作日继续归一为 `weekly` 加 `[1,2,3,4,5]`，不引入第二份模型专用计划。

| 频率 | 表单配置与实际语义 |
| --- | --- |
| 手动 | 不显示日期/时刻，不注册周期时钟；通过「立即运行一次」执行 |
| 每小时 | 开始日期、每小时的分钟；实际 cron 按分钟重复 |
| 每天 | 开始日期、时间、时区 |
| 工作日 | 周一至周五；不自动排除节假日 |
| 每周 | 选择星期、开始日期、时间、时区 |
| 每月 | 每月日期1–31、开始日期、时间、时区；没有该日期的月份跳过 |

日历预览与真实受理共用 `matchesSchedule`，开始日期之前不能执行业务，改开始日期推进日程代际。继续只用 Mastra 原生时钟；没有新增 renderer 计时器或独立 cron 守护进程。手动计划切换时暂停原有原生日程。

## 3. 真实 bobo 对话

- 从此入口首发沿 `startCoreConversation` 原稳定回执创建 `purpose=core, automationCreation=true` 会话。后续沿同一 `sendMessage` 会话、原API/本机执行配置和历史继续交流，不使用旧 `generateAutomationDraft` 模型选择器。
- bobo询问缺失的员工、指令和时间；明确创建时调用原 `manage_automation`。新保存必须带实际员工ID，宿主只允许一名员工、独立任务聊天，拒绝助手自己、群分工或借此改动普通员工的归属权限。
- 普通bobo会话不因本次增加全局计划工具。普通员工/群对话仍受原owner隔离；专用会话的来源、活动状态、员工和当前配置在保存前核验。
- 模型只负责理解和输出工具JSON。界面卡片来自已经持久化的 `AutomationDefinition.creationSource`，不从回复文本、Markdown或“已创建”措辞推测成功。
- 首发及续聊提交前持久化原请求，未知结果先查原回执；重启不自动重发。对话隐藏停止读取；本页使用有界消息窗口，完整原历史继续在核心会话中保留。

## 9. 定时任务与命令权限独立（2026-10-17）

用户明确指出DS不可选和命令权限没有关系。本节替代此前“自动化不支持开启命令的API员工”限制：

- 命令权限表示员工是否可使用终端命令工具，不决定能否创建或执行定时任务。通讯录选择、保存时的运行配置检查、自动化调用事务均不得按该开关拒绝员工；当前员工启用状态、模型/本机配置与原来源检查继续有效。
- API普通员工创建默认允许申请命令，创建/编辑界面可以独立关闭。保存必须尊重原配置，修改名称或职责不能把关闭状态强行打开。本机Agent继续使用各自运行配置中的权限选项，编辑时保留完整nativeOptions。
