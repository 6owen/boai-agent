## 2. 当前全局检索确实实现了什么

| 对象 | 当前匹配字段 | 当前不覆盖的内容 |
| --- | --- | --- |
| 会话 | `Conversation.title` | 群背景、全部配置、工作目标 |
| 消息 | 已完成消息的 `Message.content` | 未完成流式草稿、私有执行草稿 |
| 材料 | 已发送材料的 `ConversationMaterial.name` | TXT/Markdown 文件正文 |
| 成果 | 已登记成果的 `Artifact.name` | 文件正文、未经登记的工作目录文件 |

消息正文的关键词搜索已经可用，材料和成果当前只按文件名匹配。员工记忆、工作描述和宿主任意文件也不在此全局检索中；记忆继续由员工统一记忆仓库及其授权召回处理。

检索使用固定 SQL 中的 `instr(lower(text), lower(keyword))`，匹配连续子串，按时间、对象 ID 和类型倒序分页。它不是 FTS、BM25、模糊搜索或语义搜索；输入两个词不会自动变成两个独立检索条件。

会话可见性、清理状态、当前/全部范围、员工、时间和类型在 SQL `LIMIT` 前过滤。未选筛选时，覆盖当前会话列表可见范围内的四种类型；搜索不能隐式恢复隐藏会话。

结果携带具体会话/消息身份或材料/成果的版本与 hash。查询及点击均复核来源；失效结果不提供旧正文，不能跳到猜测的最新版。固定消息已消失时，历史定位返回保留原目标身份的空窗口，不回退到其他消息。

## 3. Mastra Search 怎样复用才合适

安装版提供 `Workspace.index()`、`search()` 和 `rebuildSearchIndex()`；`index(id, content)` 索引调用者提供的文本，不读取或创建对应文件。BM25 是不需要外部模型的本地候选；框架另外支持的 vector/hybrid 不在本路线内。依据：[安装版检索文档](../../../node_modules/@mastra/core/dist/docs/references/docs-sandbox-search.md)、[Workspace 类型](../../../node_modules/@mastra/core/dist/workspace/workspace.d.ts)。

它适合员工在一个已经授权的语料集里找内容。本人跨会话检索继续由 SQLite 控制资格、分页和固定来源；不要把全库消息、材料、记忆一次灌入员工 Workspace。

### 必须处理的安装版限制

1. 文件写入、编辑、删除不自动同步索引。删文件后索引可能还保留正文；每次新版本必须重新索引完整内容。
2. `Workspace` 没有公开的单篇删除方法。内部 SearchEngine 的 `remove`/`removeSource` 不是稳定公共接口，不能通过私有字段绕过。需要删除隔离时重建明确语料集，或使用支持删除的应用自有索引。
3. BM25 的获准语料必须由应用先确定；不能假定 `search({ filter })` 对它提供成员授权。`agentId` metadata 也不能充当访问资格。
4. `autoIndexPaths` 需要实际等待 `workspace.init()`，只扫描静态 filesystem/mounts，不支持动态 resolver，也不持续监听变化。重复 init 会清空本地 BM25 后重建，不应放进每次查询。
5. 当前 Workspace 身份是 `run-<runId>`，阶段退出会 destroy；安装版销毁会清掉本地 BM25。不能假设下一次任务或应用重启仍有上次索引。
6. 启用 Search 默认还会产生 index 工具。产品索引由宿主管理；员工只读检索时不要同时授予任意索引写入能力。

这些限制意味着：**先保留 SQLite 权威与应用管理的派生正文，再决定员工侧是否复用 Mastra BM25。** 如采用，每次 topK 前必须确定获准语料，返回摘录前再次核对当前来源；不能先检索全集再在 Renderer 或模型提示中删掉越权结果。

## 4. Q1：先补材料和成果的文本正文

目标示例：员工产出 `调研结果.md`，关键词“苹果浏览器”只出现在文件内容里；本人仍能搜到该成果，并打开命中的确切版本。

首批仅覆盖已发送 TXT/Markdown 材料和已登记、可核读的文本成果。未发送材料、私有草稿、未登记目录文件、二进制文件及外部任意路径不进入全局索引。

### 4.1 数据与来源

- 原材料/成果记录是权威；新增正文索引只是可重建的派生数据，不拥有发布、授权、采用或交付状态。
- 每条索引绑定来源类型、会话 ID、对象 ID、材料 revision 或成果内容版号、原件 hash，以及索引格式版本。分块还需稳定块身份与正文位置。
- 使用宿主原有受控读取，保存同一次 hash 核验得到的字节。不能先验一份内容，再从可变路径读取另一份内容建索引。
- 事务提交前再比较原来源资格和版本。已撤权、已清理、已更换版本的准备结果不能写入可搜索正文。
- 搜索资格通过权威来源关联，在分页前排除隐藏/清理/未发送/未登记对象；查询返回和点击仍沿当前来源 hooks 复核。

### 4.2 更新、回填和清理

1. 新发送材料、新发布或启动时合法登记的成果，将确切来源及待索引资格和原对象提交保持一致；未提交对象不索引。
2. 有界后台处理这些明确对象，复用已有文件/读取限制；设置单文件、单批字节、扫描数量和耗时上限，超限明确记录，不能默默称“全文已覆盖”。
3. 历史回填按稳定游标分页，保存索引版本、成功/失败/跳过数量和继续位置；重启只做确定性文件核读，不调用模型。
4. 清空会话、删除材料/成果、撤权或来源失效时，原事务撤销索引资格并删除相应派生正文。清理竞态中的迟到回填不得复活条目。
5. 外部修改或文件缺失立即阻止旧摘录返回；可以显示既有不可用原因，不能把旧索引正文当当前原件。
6. 备份可省略可重建正文，恢复后先核对已提交本地来源再回填；不能重新读取外部原件、恢复旧授权或重放模型/工具。

### 4.3 接口和界面

保持四类搜索和现有筛选，只在材料/成果结果中增加有界正文摘录及命中位置。结果目标仍携带确切对象、版本/hash；同名文件不合并，不自动跳到新版本。

索引进度与失败覆盖单独可见，不能用“零结果”暗示尚未索引的文件不存在。正文索引不得使每次搜索变成遍历工作目录；读取和查询都保持可取消、有界，隐藏页面不继续检索，迟到响应不更新当前页面。

本人搜索与后台确定性回填不创建 Work，也不调用模型。扩展 schema、IPC 和 UI 时，先遵循现有 repository、错误类型和 `READING_LIMITS`，只增加必要字段。

## 5. Q2：中文、多词与相关性

Q1 解决“正文不可搜”，Q2 解决“输入怎样命中、哪个排在前面”。本阶段只评估本地、确定性的匹配和排序，不使用模型推断近义表达。

当前连续子串对完整中文词可用，但空格、多词、词序变化和近义说法不自动处理。安装版 BM25 默认按空白切词，支持自定义 tokenizer；不能据其英文示例认定中文双字词已经可靠可用。

实施前固定一组真实中文样例，比较原 `instr`、确定性分词/双字候选和 SQLite FTS/BM25 方案。样例至少包含两个汉字、连续长句、空格多词、英文标识符、文件名与正文混合、同词多次出现及零命中。

先明确多词采用 AND/OR 的产品规则，并保留可理解的精确命中行为。候选方案要测召回、误命中、索引体积和查询耗时；可选 FTS 不代表其默认 tokenizer 已满足中文。

相关排序只在实测收益明确后添加。排序键包含稳定得分、时间和对象身份；游标绑定关键词、筛选、排序方式及索引版本，条件改变拒绝复用。分块命中必须按固定来源去重再分页，不能一份大文档占满结果。

索引更新导致排名变化时，声明并校验当前查询版本；不能把不同版本的页拼接为稳定结果。保留已有时间排序是否继续作为选项，按真实使用评估决定，不先堆设置项。

## 6. Q3：员工检索获准消息与产物

规划状态：后续按真实任务需求确认，当前不纳入 Q1/Q2 的验收门槛，也不阻塞浏览器。以下合同保留供明确启动 Q3 时使用。

目标示例：用户交给写作员工一项任务，员工能找自己实际获知且当前获准使用的资料和成果，并给出具体来源引用。

已有 `search_knowledge` 继续负责绑定知识；新增的会话来源检索不替代员工记忆，也不因为群成员身份或相同员工 ID 就自动开放全部历史。

### 6.1 权限与运行边界

- 从宿主可信任务上下文取得员工身份、会话、原 Work/自动化来源和授权版本；不接受模型或 Renderer 传入一个 `agentId` 就授予访问权。
- 获准语料根据实际获知证据、材料成员授权、成果来源、当前使用范围和清理状态确定。查询条件中的员工筛选只是过滤，不是授权。
- 在分页/topK 前限定这个语料集；后验删除全集结果不能提供同等权限保证，也会破坏分页完整性。
- 返回摘录和引用前复核来源，模型后续调用、发布与记忆仍沿现有来源屏障。索引内容是参考数据，不能授权命令或改变员工规则。
- 工具只给已经受理的任务；普通 chat、判断、记忆维护不因新增搜索自动得到 Workspace 工具。接续仍归原 Work 和累计预算。

### 6.2 本地关键词检索与来源引用

若后续启动 Q3，复用 Q1/Q2 的来源、正文读模型和经过验证的本地匹配/排序，提供有界摘录与固定引用；Mastra BM25 仅作为获准语料内的可选实现，不预先选定。不要增加第二套全库消息历史回放。

检索和索引维护本身不调用模型；员工取得摘录后的模型执行仍计入原 Work/occurrence 的既有预算。索引失败不得重试业务工具，原 Work 的已执行或结果未知副作用不得因检索重建被重放。

## 7. Filesystem：补小工具，保留已接合同

当前已创建 `LocalFilesystem({ contained: true })`，自定义 `read_file`、`write_file`、`list_files`、`publish_artifact` 已连接真实任务。Workspace 原生工具总开关仍是 `tools.enabled:false`，Search/LSP 未配置；不能把“安装包含有工具”写成产品已启用。

`self:/` 仅当前员工的当前会话，根目录只暴露 work/runs；共享路径只读，材料任务写入限定本次 run。读、写、列目录和发布均保留来源核对；共享读取使用已核验字节，不再读另一份可变正文。

若员工需要搜索当前文件，后续可增加一个有界、授权目录内的 `grep` 包装：限定来源范围、文件类型、遍历深度、总字节和摘录数，处理符号链接与实际退出。不要把原生读/写/删/任意路径工具一次全部打开。

LocalFilesystem 的路径限制不构成命令或 LSP 进程的操作系统隔离。现有明确审批的宿主命令仍按已声明权限运行，不通过文件工具升级承诺新的硬隔离。依据：[安装版文件系统文档](../../../node_modules/@mastra/core/dist/docs/references/docs-sandbox-filesystem.md)及[现有 S1/S2 规格](03-Sandbox文件系统与Skills.md)。

## 8. LSP：留给编程员工

LSP 的“语义”指代码类型、符号、声明和诊断，不是自然语言消息的语义检索。只有员工需要分析或修改真实代码项目时才启用；写作、一般调研和 IM 搜索不需要它。

安装版前置条件包括静态、支持双向 stdio 的 Sandbox 进程管理器、协议包、语言服务器及其运行时；宿主和进程需在相同绝对路径看到项目文件。现有 LocalFilesystem 配置和宿主单次命令工具不能直接视为已经满足这些条件。

实施时限制可信项目根、服务器启动命令、运行时发现、客户端数量和查询耗时；核对向上寻找项目根是否越出授权目录。LSP 不受 LocalFilesystem containment/allowedPaths 自动约束，也不能依靠它防止进程读其他资料。

保持缺依赖可见，禁止默认启用 `pnpm dlx` 等安装回退。启动、停止、重启和 workspace destroy 要接现有资源占用/取消合同，确认语言服务器及查询实际退出后释放容量；SDK 返回销毁不等于产品已证明退出。依据：[安装版 LSP 文档](../../../node_modules/@mastra/core/dist/docs/references/docs-sandbox-lsp.md)。
