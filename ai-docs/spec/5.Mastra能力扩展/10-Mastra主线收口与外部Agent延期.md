# Mastra 主线收口与外部 Agent 延期

更新：2026-10-08。用户已确认：**保留已有成果，暂停 Claude Code、Codex、Pi 等本机 Agent 路线的后续实现与兼容测试，当前以 Mastra/API 员工的产品闭环收口。A2A 仅作为后续扩展。** 本文维护当前范围与实际验证；本次没有修改个人运行配置或删减模型阶段。首轮离线协议闭环结果见第5节，真实供应商和人工效果仍待验证。

## 1. 保留与暂停的边界

保留 IM、员工、单聊、群聊、任务、文件和自动化已有功能，以及共享持久化、授权、取消、成果版本和未知结果处理。此次调整不回滚群聊或自动化，不删除本机运行时代码、SDK/协议研究、已建测试、旧应用包和成功或失败证据。

暂停的是本机路线的后续开发、CLI/SDK 兼容实验、真实模型复验和专用发行包矩阵；本机缺口冻结在[第13组06 §19](../13.本机Agent员工运行时/06-实施步骤与自动验收.md#19-当前剩余工作清单)，不进入当前 Mastra 待执行清单。恢复该路线需要用户重新明确范围。

不自动禁用用户已保存的本机员工或连接，不把它们改为 API，不迁移个人聊天、原生会话、Work 或成果历史，也不将未知回执改写为成功。当前收口使用隔离数据的 API 员工，不以运行历史迁移作为前置。

## 2. 首批只交付一个员工闭环

沿用现有 IM 和 Mastra 运行入口，核验下面五个顺序相接的目标，发现直接阻塞该闭环的问题才做定向修复。复用已有代码和场景，不建立另一套大规模故障矩阵。

**本轮通过口径是实际Electron源码构建＋真实Mastra SDK＋本地HTTP/SSE协议模型；未调用真实供应商，也未验证发行包或人工效果。** 五项都在同一次新员工、同一私聊的贯穿场景中验证。

| 目标 | 需要看到的产品结果 | 本轮实际状态（离线协议） |
| --- | --- | --- |
| API 创建员工 | 员工绑定明确的API连接/模型，原IM能打开该员工会话 | 通过：UI创建并绑定API连接及同一私聊 |
| 连续聊天 | 同一员工和会话连续处理新消息，历史不被当作新的用户输入重复办理 | 通过：同聊两轮公开回复，第二轮SDK请求含首轮消息和回复；未建立文件Work |

验证仍沿[自动化功能验收与结果审阅](../02-自动化功能验收与结果审阅.md)：模块、离线协议、真实API、实际Electron、发行包分别标明来源；保留失败、原件和截图，技术通过与人工效果评价分开。此处不继承本机路线“完整LR0–LR6/LA”作为首批完成条件。

## 3. 五类阶段先核实，再决定简化

Mastra/API 路径原本也有判断、聊天、执行、汇报和记忆阶段。暂停本机路线不会自动移除这些阶段，本次不声称已经删减它们。

当前先观察同一单员工闭环的实际调用和作用，再评估三个小范围优化：单聊是否可以减少额外判断、执行后的回复是否可以减少独立汇报、自动记忆是否必须在每次交付后执行。只有确认重复工作或额外调用、并保持权限/Work/公开提交/成果版本语义时，才另做定向修改；不同时重构调度器或产品数据模型。

## 4. A2A 延后作为外部任务能力

预期关系是 **BoAI IM → Mastra员工 → 按需委托外部A2A服务 → 返回任务结果和成果**。外部Agent保留自己的工具、上下文与执行循环，不要求它实现BoAI的五类阶段，也不将外部任务自动当成完整自主员工。

前提是对方实际提供A2A服务及可核对的端点与能力。Claude Agent SDK、本机Claude Code或Codex CLI不会因选择A2A就自动成为A2A服务；自建包装器、部署服务和维护SDK仍是独立工程。当前项目尚未完成A2A产品接线，本轮不安装A2A新依赖、不自建Claude/Codex SDK包装服务，也不将A2A作为Mastra首批闭环前置。历史依据与能力限制见[05协议说明](./05-ACP与A2A及MCP连接.md#3-a2a网络-agent-委派双向分开设计)。
