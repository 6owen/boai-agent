# 按执行内核归属的记忆架构

日期：2026-10-30。状态：**用户已授权实施，隔离源码已接入；个人数据/运行版本尚未切换。** 实施步骤、验收与唯一进度见[17](./17-Mastra记忆接入与自建记忆退役计划.md)。

## 1. 已确认的决定

用户明确要求：API接入的员工已经通过Mastra执行，记忆直接使用Mastra Memory，现成能力能用就用，不继续维护一套BOAI记忆引擎；本机Agent自行管理原生会话、上下文和记忆，BOAI不再叠加另一套自动记忆处理。

| 实际执行内核 | 记忆负责人 | 覆盖范围 |
| --- | --- | --- |
| Mastra/API | Mastra Memory | Bobo及普通API员工；私聊、群聊、渠道、自动化中的获准交流与工作上下文 |
| 本机Codex、Claude、Pi及其他原生运行时插件 | 各Agent原生机制 | 保持原生会话恢复、配置、工具、上下文压缩及其实际支持的记忆能力 |

Bobo按其实际选择的执行后端归属，不能因核心助手身份获得第二套记忆引擎。群内每个员工分别按自己的后端执行。API模型品牌或网关不同不改变Mastra的记忆归属。

BOAI继续拥有员工、产品聊天记录、权限、Work、成果和界面。它只维护必要的身份映射、获准数据接入、生命周期同步与管理入口；不自行实现记忆提取、关键词召回、排序、遗忘算法或重复的模型摘要管线。

## 2. 当前实现与目标的差距

本节基于源码基线`397aea3b5ffae29fe22f0fc540efce6b3dbb5360`，描述迁移前事实。

| 环节 | 当前实现 | 目标 |
| --- | --- | --- |
| Bobo的Mastra Memory | 仅核心、非渠道、非任务聊天启用；thread级Working Memory由BOAI每轮覆盖，运行时只读 | 所有Mastra/API公开执行路径共用稳定会话记忆，聊天与任务切换保持上下文 |
| 普通API员工 | BOAI投影聊天历史，自建仓库提取与召回；未接入上述Bobo Memory实例 | 使用同一套Mastra Memory接入方式，按员工隔离 |
| 持久记忆召回 | 中文相邻双字/英文词匹配，优先级排序；所谓2400 token预算实际按UTF-8字节计数 | 使用官方语义检索与上下文预算机制，退出这套自建候选筛选 |
| 长对话维护 | BOAI自建摘要与历史窗口装配 | 由Mastra原生历史和Observational Memory处理重叠职责；产品工作现场与真实回执仍归BOAI |
| 本机路径 | 普通轮后自动提取已跳过，但公共bootstrap仍可能包含BOAI记忆，原生产品桥仍暴露自建记忆工具 | 退出BOAI自动记忆注入及自建记忆工具，不向本机Agent挂载Mastra Memory |

2026-10-30用户提供DS案例：先讨论使用AgentBrowser，下一句让其查询南京天气，DS却用了内置浏览器。只读核对当轮Trace确认，上一轮问答已在模型输入中，插件工具也可用；再次明确指定后才调用插件。**这个案例用于验证连续意图和工具选择，不能据此判定长期记忆缺失，也不能以增加向量索引就宣称解决。** 当前[检索选择规则](../../../packages/runtime/src/modules/sources/search-selection.ts)强调当前消息、排除历史来源选择，需要区分同一用户的连续请求与不可信网页内容。迁移应复用框架会话能力，并校正产品接入规则；不能为每个工具增加永久偏好或特殊关键词补丁。

## 3. 直接使用哪些Mastra能力

| 职责 | 直接复用 | BOAI必要接线 |
| --- | --- | --- |
| 连续对话 | Message history、稳定thread/resource | 输入当前获准消息，保存实际已提交结果；避免完整历史与框架回放重复装入 |
| 跨会话稳定信息 | Working Memory | 员工范围和管理入口；采用框架更新机制，停止每轮用自建召回结果覆盖 |
| 长对话与任务上下文压缩 | Observational Memory（OM） | 绑定已配置的模型、调用生命周期、来源失效与退出清理 |
| 按含义回查历史 | Semantic Recall，或所选OM模式的原生retrieval/vector能力 | 配置明确的embedder和官方向量存储；使用版本实际支持的组合，避免同一材料重复索引与重复注入 |
| 持久化 | Mastra官方存储适配器，优先现有LibSQL | 本地数据位置、备份、稳定标识、迁移回执 |

最终验收必须包含语义召回，不能只实例化`Memory`或接入消息历史就称迁移完成。Working Memory承载精简的持续信息，原始历史和OM承载较长上下文；不能把所有聊天塞进Working Memory。

已安装依赖为`@mastra/core 1.71.0`、`@mastra/memory 1.32.1`、`@mastra/libsql 1.23.3`，见[依赖清单](../../../package.json)。实施时优先核对这些版本的embedded docs、类型与源码；若确需升级，单独记录兼容差异。语义召回需要实际embedder和向量存储；普通聊天模型连接不能自动冒充embedding能力。OM及embedding均沿明确配置，不依赖未说明的环境默认模型，不把本地数据库称为全部推理离线。

官方依据：[Message history](https://mastra.ai/docs/memory/message-history)、[Working Memory](https://mastra.ai/docs/memory/working-memory)、[Semantic Recall](https://mastra.ai/docs/memory/semantic-recall)、[Observational Memory](https://mastra.ai/docs/memory/observational-memory)。线上文档用于对照，具体调用以采用版本为准。

## 4. 身份与生命周期

### 4.1 API记忆

- resource映射到BOAI用户范围内的稳定员工身份；thread映射到员工与产品会话。群会话为每个员工提供独立映射，不能让全体员工共享一个私有resource。
- 同一API员工跨聊天使用其获准的持续信息；同一产品会话的chat/task阶段保持相同上下文归属，不能每轮生成全新的记忆身份。
- 私有判断、未提交输出和临时修复提示不写成公开聊天历史。工具记录保留真实来源与作用域，不据此制造用户发言或公开成果。
- 只输入获准来源。修改、明确遗忘、来源清理和撤权必须作用于框架历史、Working Memory、OM及索引的相关数据；缺少来源级删除能力时，可失效并从仍获准的数据重建受影响范围，不能返回旧结果。
- BOAI可保存来源映射、版本和同步回执供治理，不再维护第二个可独立提取、搜索、更新同一事实的库。产品记录保留在SQLite不意味着自建MemoryRepository必须永久作为记忆引擎。
- 记忆调用的停止、退出、失败和用量纳入现有API运行边界；记忆重建不重放业务工具，不把后台工作未完成记作成功。

### 4.2 本机Agent

- 不实例化Mastra Memory，不使用BOAI的自动提取、召回、Working Memory投影或上下文压缩；公共代码中的这些处理必须在进入原生执行前分流。
- 不默认注入BOAI `search_memory`、`remember_memory`，不自动生成或覆盖供原生Agent使用的BOAI记忆文件。原生Agent本来拥有的同类工具、配置与文件照常可用。
- 保持原生session/resume、原生系统文件发现和原生memory设置。BOAI不因产品聊天清空或后端切换而擅自删除本机Agent自己的记忆文件。
- 员工身份、角色、明确授权的业务输入、产品消息与成果桥仍可传递；这些输入不承载第二套自动记忆机制。不能以退出BOAI记忆为由删掉原生会话恢复或业务连续性。
- 不假定所有本机Agent具有相同的长期记忆能力，也不为填平差异自建通用记忆内核；实际能力由相应原生运行时提供。

### 4.3 后端切换

员工、聊天和成果身份保留，记忆归属随执行后端变化。切到本机时停止API记忆注入；切回API时恢复该员工仍有效的Mastra数据。原生会话和Mastra thread不互相冒充，不默认跨引擎复制私有记忆或双向同步。旧数据保留与删除按各自生命周期处理。

人格配置、笔记、桌面活动、日报和知识资料是现有产品资源，本次不重建这些系统，也不把它们全部自动晋升为长期记忆。资源被实际提供给Agent时，记忆处理遵循其执行内核。

## 5. 自建代码退役边界

| 现有入口 | 迁移后处理 |
| --- | --- |
| `modules/memory/memory-recall.ts`及`memory-policy.ts`中的匹配/排序/字节预算 | 从在线记忆路径退出，以Mastra检索和预算替代；必要来源授权逻辑收敛到产品接入层 |
| `modules/employees/memory-extraction.ts`、`phase-instructions.ts`的记忆提取、`MastraEngine.extractMemory`、`AppService.updateMemories` | 由框架记忆更新取代，不保留第二套轮后模型提炼 |
| `modules/memory/memory-repository.ts`及旧MemoryEntry | 迁移期只读核验/导出兼容；完成切换后退出在线事实写入和召回，不为兼容UI继续双写 |
| `adapters/mastra/conversation-memory.ts` | 改为所有API员工共用的官方Memory接入；移除Bobo专属及仅非任务聊天限制，退出每轮自建Working Memory覆盖 |
| `adapters/mastra/context-maintenance.ts` | 与框架重叠的模型摘要、上下文装配逐步退出；实际输入容量校验、产品Work回执和历史定位按职责保留 |
| `modules/workspaces/workspace-service.ts`、`adapters/native-products.ts`与公共EngineContext | 分离产品bootstrap和API记忆，原生路径不再接BOAI记忆投影及工具 |
| 员工记忆面板与应用记忆操作 | API入口改读写Mastra支持的数据；本机入口不能显示成BOAI可统一管理的长期记忆。旧资料可明确标为历史只读 |

以上是职责级退役清单。用户已授权实施，当前在线分流、兼容代码保留范围和验证结果按[17](./17-Mastra记忆接入与自建记忆退役计划.md) §6读取；不按目录批量删除历史来源与评估夹具。
