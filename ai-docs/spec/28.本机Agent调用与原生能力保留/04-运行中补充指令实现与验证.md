# 运行中补充指令实现与验证

## 1. 本批范围

2026-10-28，独立worktree `boai-native-turn-steering`，分支 `feat/native-turn-steering`，基线 `628b6782`。用户同意先推进运行中追加指令及原生交互核对；本批收口Codex纯文本补充。未恢复其他暂停的稳定化目标，没有替换本机Agent执行循环、配置或工具。

本机安装的Codex `0.164.0`通过 `app-server generate-ts`生成协议，确认 `turn/steer`要求原 `threadId`、`expectedTurnId` 和输入；可携带 `clientUserMessageId`，响应返回实际 `turnId`。这份本机协议是实现依据。

## 2. 实际行为

- 当前聊天只有一个可明确定位的活动Codex执行时，在输入框输入纯文本，点击“添加或更多操作”→“补充到当前执行”。多人群必须能唯一定位到目标员工；多员工点名不提供入口。普通Enter和发送仍沿原调度语义。
- 补充绑定原产品run和原生turn。采用原消息请求ID、去重回执、SQLite事务、材料/记忆来源投影与NativeSessions，不创建新Work、业务轮次或独立输入账本。执行详情指向原run。
- 原生RPC在服务全局串行区之外执行，保留原生事件和批准/提问回调的处理通路。协议回执必须返回同一turn；输入进入原生当前轮次并不承诺模型一定执行全部补充要求。
- 过期turn、错误聊天/员工、取消、配置变更、未回应的原生批准/提问拒绝受理。自动化、Claude/API、材料/网页/资源引用、文件修改、问题关联回复暂不支持此入口。
- 同requestId只投递一次；同ID不同内容拒绝。原生接收不确定时保留unknown并停止原执行，不转为下一轮，不自动重试。重启把未确认accepted转为unknown，只核查原消息回执。
- 发送与录音取消共用原草稿生命周期；接收状态通过消息图标Tooltip及Sonner反馈，不新增常驻状态文案。
