# 本机Agent控制与验收计划

## 1. 目标与调用关系

- 目标：用户在BOAI下达任务，BOAI调用本机指定的Codex、Claude Code等Agent，保留其原生执行能力，并接收真实过程与成果。
- 调用关系：用户 → BOAI员工聊天/执行配置 → 本机Agent原生接口 → Agent执行任务 → 原生事件与结果回到BOAI。
- BOAI负责目标Agent选择、输入传递、会话关联、交互回传及展示；任务推理和工具执行由所选Agent承担。这里是职责目标，逐项实现与可用性仍需对照验证。
- 原生工具、登录、配置、MCP、Skills、hooks、插件及子Agent能力按所选Agent保持。BOAI产品工具沿现有增量入口提供，不为统一界面强制替换原生能力。
- Mastra/API是现有另一条执行路径，本组不将本机Agent嵌入第二套模型决策循环。员工、会话、Work和结果沿原数据合同。
- 远程电脑留待以后；电脑环境、机器节点、VM/容器与桌面键鼠操作不属于本次设计。前端性能另归17组04，语音另由原session推进。

## 2. 本机Agent需要核对的控制能力

- 选择与启动：明确本次选中的实际Agent程序及配置，复用LaunchProfile和现有执行设置；不新增“环境”产品实体。
- 输入与材料：准确传递用户指令、附件和工作目录；BOAI追加的员工/协作指令可追溯，不能默默覆盖原生项目配置。
- 会话接续：将BOAI聊天关联到实际thread/session；区分继续原会话和开始新会话。当前接入不等于已能接管用户在别处打开的任意Agent会话，外部会话导入/附着须另核对原生协议支持与实际需求。
- 运行中交互：原生批准或提问回到用户，回答送回原请求；运行中补充指令按该Agent协议支持情况处理，不能将排队输入误报为已影响当前轮次。
- 取消与结束：区分请求已送达、本轮已结束和进程已退出；取消作用于目标run/turn，保留已经发生的真实结果。
- 过程与结果：呈现原生进展、工具结果、错误及完成状态；原生已经产生的内容不能因BOAI解析或展示而无提示丢失。
- 上述是核对清单，不是已发现的六项故障。先测现有入口，不以清单本身为理由增加抽象层、重试或重构。

## 3. 原生能力对照：先确定差异，再决定修改

### N0：建立可比较基线

- 核对实际运行的BOAI构建、Codex/Claude程序、配置来源、工作目录、权限、MCP/Skills/hooks/插件及模型；只登记非秘密身份。
- 直接原生入口与BOAI入口使用相同材料、等价配置和独立临时副本；项目配置一致，登记不可消除的路径或交互差异。
- 原生执行能力与终端TUI交互分别登记。协议支持而BOAI无入口的记为接入缺口；只由TUI暴露的能力注明边界，不算已透传，也不笼统归为原生引擎失败。
- 复用[原生对照runner](../../../scripts/evaluate-native-parity.mjs)、[执行合同](../../../tests/evaluation/native-parity.ts)及[BDD](../../../tests/e2e/features/native-parity.feature)。现有文件任务不能代表插件、hooks、子Agent或全部控制交互均已验证。

### N1：能力清单与判定

- NP01：普通输入和多轮追问。核对用户原文、实际session与真实工具结果，不只比较回答语气。
- NP02：项目配置与工作目录。实际读取项目说明和固定文件，执行有确定结果的命令，核对cwd与文件字节。
- NP03：原生MCP。使用一个已配置、可确定验证的只读工具；目录中出现工具不算调用成功。
- NP04：Skills/hooks/插件。分别验证发现和实际行为；hooks用独立夹具写标记，未配置项明确不适用，不计入通过分母。
- NP05：权限与用户输入。真实触发原生批准/提问，验证回答到达原请求；聊天里另发追问不替代原请求回传。
- NP06：原生子Agent。验证真实子任务、父子事件和结果回传，不用BOAI员工群替代原生子Agent。
- NP07：附件与视觉。使用同一图片和已知内容附件，核对实际读取；仅出现路径不算读取成功。
- NP08：取消与会话接续。核对原生turn/session、已发生效果及后续继续状态；结果未知先核查，不自动重发任务。
- NP09：过程与结果展示。包括长文本、工具结果、错误和子任务事件；原生有结果时核对BOAI是否正确呈现。
- NP10：运行中补充指令。先确认原生接口支持steer、输入排队还是仅下一轮输入，再核对BOAI的实际投递和生效轮次。原生不支持的标注边界，BOAI未接通但原生支持的记录为缺口。

### N2：证据驱动处置

- 两入口均失败：先定位原生配置或行为，不自动修改BOAI。
- 原生成功而BOAI失败：沿程序/配置/cwd、输入投递、协议交互、结果呈现定位真实断点，每次修一个有证据的机制。
- 两入口结果一致：保持实现。不得仅以稳定化名义叠加截断、复核模型或第二套执行循环。
- 确定性检查验证文件、会话、请求和回执；开放任务效果沿[第15组业务eval](../15.Agent评估与持续优化/11-业务评估与Codex优化主线.md)。模型自报完成不能作为唯一评分。
- 每项记录版本、材料、配置差异、两入口结果、原始证据及未验项；能力支持范围与实际通过分开。现有测试代码不等于本轮已验收。

## 4. 可靠性与日常使用

- 在代表任务对照可复现后，再用重复运行和日常使用记录观察会话接续、请求归属、取消收尾及是否逐步变慢；不靠源码猜测代替实际体验或eval。
- 记录用户真实反馈的触发步骤、运行身份和相关事件；无失败证据时不新增超时、重启或自动重放策略。
- 前端卡顿沿[第17组04](../17.桌面后台运行/04-前端响应性能分析与优化计划.md)单独分析。Agent响应耗时与BOAI界面响应耗时分别测量，避免将模型等待误判为渲染卡顿。
