# 实施阶段与验收

更新：2026-09-28。**本组功能尚未实施，下面的验收项均未执行。**本次完成的是源码核对和规格，不是功能或测试交付记录。

## 1. 阶段安排

### K1：本地管理闭环

目标：现有技能可查内容、收藏分组、批量导入并明确绑定员工；旧知识资料与员工数据不回归。

1. 在现有 Resource 上增加可选管理视图，建立收藏集合和技能详情 IPC；旧数据无需先迁移文件即可打开。
2. 统一 frontmatter 和有界扫描，支持单目录/多 Skill 目录的预览、选择、冲突与逐项结果；保留旧 importResource。
3. 拆分资料库局部组件，完成“已安装/我的”、分组、Markdown/文件详情、来源与员工绑定入口。
4. 覆盖重启持久化、移除收藏不撤权、移除资源会撤权及旧数据兼容。

完成标准：离线即可完成“导入 → 查看 → 收藏分组 → 绑定 → task 读取 → 移除撤权”。不要求接入商店或 S2 命令执行。

### K2：三家商店只读浏览

目标：在同一资料库中浏览技能，并准确体现每个提供商的能力。

1. 提取旧 provider 合同/映射与 fixture，补 schema 校验、能力声明、取消/超时、缺字段处理。
2. 接列表/详情 IPC 与缓存，完成切换、搜索、排序和分页；安装入口在 K3 未就绪时明确不可用。
3. 检查 skills.sh、ClawHub、SkillHub 当前接口，记录日期、列表/详情/分页结果和限制；默认测试只用离线 fixture。

完成标准：三家各有证据，不能只因共享 UI 可打开就宣布全部可用。某家不可用时保持其错误可见，其他商店和本地资料库仍可用。

### K3：安装与更新闭环

目标：商店/受支持的远程来源取得完整技能包，安装到本应用并可维护。

1. 实现有界下载/ZIP/公开 GitHub 来源，所有入口进入同一预览与提交管道；逐项结果、操作查询、取消和幂等。
2. 保存稳定来源和实际内容 hash；提供只读检查更新、单项更新预览、本地修改冲突、活跃工作阻断。
3. 加入文件/DB 一致性日志、失败回滚和启动恢复；扩展卸载、缓存失效、来源记忆失效和备份互斥。
4. 完成商店安装后的本地详情和员工绑定跳转；核对外部 Agent 原目录未被修改。

完成标准：商店安装 → 本地管理 → 显式绑定 → Mastra task 读取贯通；失败更新保留旧包，运行中更新不混读版本。安装不执行 package/技能脚本、不启用命令权限。未获验收的远程来源不显示为支持。

### K4：便携库与旧数据迁移

目标：用户可以迁移旧应用导出的技能内容及可用来源，并保存新应用的集合信息。

1. 准备专用旧格式 ZIP fixture，覆盖 local/vendor/snapshot、缺失来源、重名和无集合信息情况。
2. 实现计划、预览、逐项冲突、离线导入与集合幂等合并；原件只读，不要求旧应用在线运行。
3. 实现选择技能/我的导出、来源与 collection sidecar；拒绝无法无损表示的同名多来源集合，展示拆包选择。
4. 在隔离数据目录完成“旧格式 → 当前应用 → 新导出 → 另一隔离数据目录”的往返验证。

完成标准：内容/hash、来源和受支持的收藏关系保持；没有携带的旧分组明确标为无法恢复；测试不触碰用户真实 skills 目录。

### K5：按需扩展

主闭环交付后，再决定是否加入本应用使用统计、私有/Git 通用来源、外部 Agent 全局管理或技能创作。统计必须先定义采集事件、去重和未知值；外部目录写入必须先明确管理范围。不要为可能需求提前引入全量旧应用依赖。

## 2. 验收矩阵

| 编号 | 场景与必须成立的不变量 | 主要验证层 |
| --- | --- | --- |
| K-01 | 老数据库没有来源/集合字段仍能列出并使用原绑定；知识资料不变 | Vitest 持久化 + 升级 BDD |
| K-02 | 单目录和多目录扫描得到候选；无 SKILL.md、无效 name、多行 description 和不支持字段有准确反馈 | Vitest |
| K-03 | 预览不改受管资源；取消不安装；源内容/目标变化后旧计划被拒绝 | Vitest + BDD |
| K-04 | 批量部分失败逐项反馈；相同 requestId 不重复安装；同内容重复导入按身份和作用域复用 | Vitest + BDD |
| K-05 | 同名不同来源目录都可见；不自动覆盖，同一员工绑定冲突明确拒绝 | Vitest + BDD |
| K-06 | 收藏/分组重启后保留；删除组回到未分组；取消收藏不卸载或撤权；多窗口旧 revision 不覆盖新关系 | Vitest + BDD |
| K-07 | 详情和文件读取不能越出该 resource；无权路径、符号链接、大文件被拒绝；Markdown 不执行代码 | Vitest + BDD |
| K-08 | 提供商 ID、页码/cursor、搜索最短长度和排序能力准确；SkillHub 页内排序不冒充全站排序 | Vitest provider fixture |
| K-09 | 快速切换提供商/搜索时迟到响应不覆盖；下一页失败可重试、无重复项；断网仍可管理本地资源 | Vitest + BDD |
| K-10 | 同名商店项不被误判已安装；provider 标记/下载量缺失保持未知；正文缺失不编造 | Vitest + BDD |
| K-11 | ZIP 穿越、绝对路径、盘符、链接、重复/大小写冲突及解压超限不能写出 staging 边界 | Vitest 恶意 fixture |
| K-12 | 下载超时、取消、中断、重定向至不允许地址和响应超限有明确失败；本地操作不被全局锁阻塞 | Vitest + 受控服务 BDD |
| K-13 | 安装不改外部原件/全局 Agent 目录，不运行 package scripts、Git hooks、meta.ts 或技能脚本 | Vitest 文件快照/执行断言 |
| K-14 | 公共安装不自动授权；只给绑定员工的 task 加载；普通 chat/decision/memory 和 ACP 不越权 | 现有引擎/服务回归 + BDD |
| K-15 | 检查更新只读且失败≠最新；来源不支持可见；本地修改不被无提示覆盖 | Vitest + BDD |
| K-16 | 活跃/等待工作和未退出执行器阻止更新切换；更新保留 resourceId/收藏/绑定，name 变化不原位覆盖 | Vitest + BDD |
| K-17 | 在文件交换前/后、DB 提交前/后注入故障，重启得到一致旧版或新版；不自动重放安装网络请求或业务工具 | Vitest 故障注入 + 重启 BDD |
| K-18 | 移除撤销绑定和来源记忆，迟到运行不能读取/发布旧授权结果；仅删除受管副本，清理失败如实报告 | 现有服务回归 + BDD |
| K-19 | 旧 ZIP 离线恢复实际内容而非上游最新；无分组信息不编造；重复导入不重复建资源或分组 | Vitest + K4 BDD |
| K-20 | 导出/再导入保留文件与来源、已定义集合关系；同名冲突不静默丢失；凭据/机器路径不进入生成元数据 | Vitest + K4 BDD |
| K-21 | 安装提交期间不产生错位备份；新旧备份恢复重定位路径并保留绑定；缓存和 staging 不作为业务数据恢复 | Vitest + 备份 BDD |
| K-22 | 纯说明技能无脚本环境也可读取；有脚本但未验证依赖的技能不显示执行就绪 | 环境计划回归 + BDD |

## 3. 测试与验证方式

模块与持久化测试放 `tests/*.test.ts`，使用本仓库 Vitest；可按实际模块新增 skills-management、skills-marketplace、skills-transfer 等测试文件。复用现有 `environment-plan.test.ts`、`mastra-engine.test.ts`、`service.test.ts`、`agent-homes.test.ts` 的授权与旧数据不变量，不为迁移删掉原断言。

桌面场景统一 `playwright-bdd`：在 `tests/e2e/features/` 写中文业务场景，`steps/` 写操作/断言，`support/` 管理隔离数据、fixture HTTP 服务与进程清理。不新增平行 Electron `.spec.ts`，不手改 `.features-gen/`。

每批按影响运行 `pnpm typecheck`、`pnpm lint:ui`（涉及 UI 时）、相关 Vitest 和 `pnpm test:electron`。功能不依赖真实付费模型，使用受控模型协议证明 task 只取得授权技能。真实商店探测另记结果，不加入默认离线 CI；联网失败不能被 mock 通过掩盖。

建议 BDD 使用业务表述，例如：“安装公共技能后员工仍未启用”“取消收藏不影响员工使用”“任务尚未结束时不能替换技能”“旧技能库重复导入不会覆盖本地修改”。重启使用相同场景目录，跨场景隔离。

## 4. 实施启动检查点

1. 重新读当前目录地图、目标文件 Header、现有导出/调用者和工具库；本规格引用的源文件可能已演进。
2. 记录两仓库版本和当前未提交改动；本次发现的 Trace/本地连接工作不得被迁移覆盖。
3. 明确本批 K 阶段与已支持来源，先落最小合同再接 UI；不要一次搬完整旧 monorepo。
4. 本次将涉及但缺少 Header/.folder.md 的源码位置，在实际触及时补齐；不借此批量修复无关目录。
5. 每批完成实现 → Header → 所属 `.folder.md` 回环；在第 2 组新增真实实现/测试记录，再更新本组状态。只有改变全局结构或规约时才改 AGENTS.md。
6. 对未运行测试、不可用 provider、不支持格式和未完成恢复项明确记录，不把按钮出现视为功能完成。
