### 商店适配不能统一成同一种分页和排序

| 提供商 | 旧适配器行为 | 迁移注意事项 |
| --- | --- | --- |
| skills.sh | 榜单按 page，all-time/trending/hot；搜索至少 2 字符；详情通过搜索精确匹配；安装目标为 Git 来源 | 不给不支持的搜索伪造下一页；详情不保证有 SKILL.md 正文 |
| ClawHub | 榜单按 cursor；recommended/downloads/trending/updated；搜索与列表过滤 suspicious；详情补全 owner | 保留 owner/slug 身份；下载目标走 URL；未知风险状态不能显示成已验证 |
| SkillHub | 列表内部转换为一基页码；搜索单批；可取得中文说明、SKILL.md、安全报告；URL 下载 | 旧适配器 downloads/updated 是对当前返回页本地排序，不能显示为全站排名 |

这些是**旧代码行为**，不是外部服务当前可用性承诺。新适配应显式声明搜索、排序、分页、正文和更新能力。

### 旧导入导出规格与实现有差异

[旧规格](../../../../boai-app/spec/own-skills-directory-import-export.md) 标记“Export implemented / Import pending”。但当前 `InstallSkillDialog` 已有 `import-own` 分支，扫描器也会读 `boai.json`、lock 和来源声明。可参考的是“识别库 → 展示候选 → 安装/复用 → 收藏”的已有链路；不能由此推断已完成该规格中全部只读计划、冲突覆盖、失效计划、原始分类和集合恢复要求。

现有库 manifest 没有收藏分组字段；仅复制技能目录或旧 ZIP，不能自动恢复旧 localStorage 中全部分组关系。新方案对此另行定义，见 [03](./03-架构合同与数据迁移.md)。

## 3. 迁移前当前项目已具备的底座

| 入口 | 当前事实 | 新功能应如何接入 |
| --- | --- | --- |
| [Resource / DigitalAgent](../../../packages/shared/src/domain/index.ts) | `Resource` 包含 id/kind/name/description/path/createdAt/ownerAgentId；员工以 `skillIds` 引用 | 保持 ID 和引用；增加可选管理信息，不另建一套可执行技能实体 |
| [local-resources.ts](../../../packages/runtime/src/modules/resources/local-resources.ts) | Skill 只接单个目录；解析 name/description，标准化目标目录；临时复制后校验并 rename；最多 2000 个文件/目录和 100 MB，拒绝符号链接 | 批量扫描和远程解包最终调用同一受管导入规则；完整 YAML 和预览校验需要补充 |
| [AppService](../../../packages/runtime/src/service.ts) | `importResource` 支持公共/员工专属路径；`removeResource` 取消受影响运行、去绑定、失效来源记忆并删除受管副本 | 新安装/卸载接入该用例，不在 renderer 直接写磁盘或只删卡片 |
| [员工服务](../../../packages/runtime/src/modules/employees/employee-service.ts) | 拒绝同一员工绑定同名 Skill、绑定他人专属 Skill；ACP 本地后端当前拒绝 Skills/知识/命令策略绑定 | 所有入口都经过同样检查；商店不能绕过后端能力限制 |
| [环境计划](../../../packages/runtime/src/modules/workspaces/environment-plan.ts)、[BoundSkillSource](../../../packages/runtime/src/adapters/mastra/bound-skill-source.ts) | 根据员工授权形成文件/hash 清单，读取时核验；普通说明可用不等于执行依赖就绪 | 新来源安装后形成同样资源；安装原件和运行授权仍分开 |
| [资料库](../../../src/renderer/pages/library/index.tsx) | 公共资源/按员工绑定视图、类型搜索、导入、详情、移除 | 原页面拆出局部组件并扩展，不复制旧 AppShell |
| [IPC](../../../packages/shared/src/ipc/index.ts)、[ProductStore](../../../packages/runtime/src/adapters/storage/product-store.ts) | `window.boai.request/subscribe`；SQLite records、事务和备份 | 使用现有跨进程与持久化方式；不引入旧 `electronAPI`、RPC server 或第二个数据库 |

当前导入器对 YAML 只做简单字段提取，多行 description 不会完整保留；新的兼容扫描必须使用同一解析规则贯穿预览和提交，并复用已安装的 `yaml` 包。不能仅因旧应用加载成功就断言该技能符合本项目执行合同。

## 4. 复用决定

| 旧机制 | 决定 | 原因 |
| --- | --- | --- |
| provider 类型、映射函数、可注入请求及适配测试 | 提取迁移，补输入/响应校验和能力声明 | 业务独立度高；先适配现有 HTTP 方式，再核对实时接口 |
| 收藏分组的纯函数与测试意图 | 提取迁移，改用 `resourceId` 和 ProductStore | 保留交互，修正来源重名与持久恢复问题 |
| 缓存 key、请求去重、失效代次 | 复用算法，接当前 API 与状态层 | 避免旧请求覆盖新搜索；不引入平行状态体系 |
| 旧列表、详情和菜单组件 | 按交互重写 | 旧实现依赖 Craft 路由、Info 组件、Jotai、i18n、Lucide、toast；当前使用自身组件/状态/API |
| 全局/项目 `npx skills` 管理 | 不作为默认安装通路 | 写入范围、CLI/网络依赖与当前受管资源模型不同；单为获取目录无需引入全套旧运行时 |
| slug 优先级覆盖 | 不迁移 | 当前按 ID 管理资源，同员工同名必须显式处理；浏览目录不能静默丢失候选 |
| alwaysAllow、requiredSources、外部 Agent placements | 只作兼容信息，不能授予权限 | 旧 Claude/Craft 字段和本项目命令审批、数据授权不是同一合同 |
| ZIP/来源识别与导出模板 | K4 选择性适配 | 保留完整文件和来源；不执行库内 meta.ts、CLI、hooks 或安装脚本 |
| 外部 Agent 日志统计 | K5 再评估 | 当前没有相同会话结构；不将旧日志扫描与主闭环一起搬入 |

旧项目测试可提供 fixture 和断言意图，尤其是 [management.test.ts](../../../../boai-app/packages/shared/src/skills/__tests__/management.test.ts)、[商店测试](../../../../boai-app/packages/server-core/src/services/skill-marketplace.test.ts)、[集合测试](../../../../boai-app/apps/electron/src/renderer/hooks/__tests__/useSkillCollections.test.ts) 和 [导出测试](../../../../boai-app/packages/shared/src/personal-repository/__tests__/export.test.ts)。迁移时改写为本仓库 Vitest / Electron BDD，不能连同旧测试运行器一起复制。
