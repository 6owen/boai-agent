# 项目目录选择与默认执行位置补齐

日期：2026-11-07。状态：**用户已确认列为第7个目标，仅计划，未实施**。源码核对基线为主仓 `5f4437ce`；初次设计基线为`04def162`，本批文档提交前快进到`ce33df56`。实施前重新核对HEAD。实际进度只记录在[04](./04-验收与实际进度.md)。

## 1. 首版要交付的体验

员工可以设置可选的“默认项目目录”；当前聊天和任务明确显示实际使用的“项目目录”，可以选择其他目录或使用BOAI受管目录。发送后，命令默认执行位置、相对文件路径及业务文件默认保存位置一致。

例如员工默认目录为 `/Projects/品牌设计`，新任务A沿用该目录，任务B明确选择 `/Projects/活动海报`。创建A后再改员工默认值，不会改变A的位置；B的选择也不影响A或员工主聊天。普通聊天无需强制选择项目。

这是现有工作目录能力的补齐。没有新项目中心、项目实体/项目权限体系、自动Git/worktree管理、新文件浏览器，也不迁移员工系统workspace或已有业务文件。

## 3. 四类位置与权限各自保留

| 对象 | 职责和生命周期 |
| --- | --- |
| 员工workspace | 员工系统文件、技能、会话和内部状态的受管归属；选项目不搬迁这些内容 |
| 授权目录 | API员工的允许访问范围；选择项目不自动获得更大读写权；native保持自身配置 |
| 项目目录 | 当前工作的默认cwd和业务文件落点；用户明确的其他文件目标仍按原权限处理 |
| 交付副本 | 聊天发布时的受管成果及来源/hash；保存副本不等于移动或接管项目原件 |

项目目录是默认工作位置，不是安全沙盒；绝对路径、工具能力和原生权限仍有效。不能声称选择项目后所有操作都只能在其中，也不能据此额外限制原生Agent。

未选项目时保留各后端原受管默认位置：native会话`workPath`、API命令`runPath`及原逻辑文件路径。不得取授权目录第一项、系统根目录`/`或用户home作为新的隐式兜底。此默认不表示所有临时文件、下载缓存或远端工具数据都迁入项目。

选择时沿原规范路径/现存目录校验，执行前重核当前路径和权限；不存在、离线、已撤权或符号链接目标改变时明确失败，保留用户选择供修正，不静默回退到另一目录。不能通过选目录把BOAI受管数据目录当业务目录。

## 4. 最小数据语义与解析顺序

以下是待实现语义，字段名由W0按现有实体确定；优先扩展现有员工、聊天、任务/assignment记录，不另造项目数据库。

| 保存位置 | 最小内容 |
| --- | --- |
| 员工配置 | 可选默认项目目录；沿原员工配置版本保存，缺字段表示保持既有行为 |
| 聊天/任务设置 | 选择模式：继承员工默认、显式目录、明确使用受管目录；显式目录及选择版本 |
| 执行快照 | 解析后的目录或受管模式、来源和选择版本；绑定原消息/任务/assignment/Work身份 |
| 发送消息 | 继续使用既有`workingDirectory`传递已解析业务目录；受管模式沿原协议，由持久快照避免再次继承新默认 |

新工作的解析顺序为：当前聊天/任务显式选择 → 未覆盖时的员工默认 → 原受管默认。明确“使用受管目录”会覆盖员工默认；模型提到某个材料路径不自动改项目，用户明确指定工作位置时才按实际意图设置。

新聊天/任务创建时复制当时的默认选择，并保存来源；“继承”表示此次取值来源，不是以后每次执行都动态读取员工默认。没有默认项目也保存明确受管模式，防止旧任务因后来设置默认项目而改变位置。首次受理执行时由宿主重核、固定实际目录，再发布运行意图；续聊、再次执行、重启恢复均沿已保存选择。修改员工默认值只影响后续新建工作，已有任务即使未开始也不自动改动。

主聊天首次确定目录后持续使用；新建任务单独解析并保存自己的选择，不从另一个任务或当前打开的文件树猜目录。旧任务缺新字段时保留原Work/消息已有目录或原受管行为，不批量套用今天的员工默认值。

显式切换已有聊天/任务目录，只允许在该目标没有活动执行、在途工具或待决接续时按版本保存。存在并发发送/配置修改时拒绝旧版本；切换不搬移旧文件、重发旧业务或更改其他任务。运行中的补充消息继续使用原执行快照。

native目录变化会改变现有fingerprint，可能新建provider session；必须保留原因与原映射，向用户准确说明续接结果，不承诺厂商私有上下文无损迁移。是否需要持久handoff沿03判断，不把整套H阶段设为选择目录的前置。

## 5. 界面、不同入口与文件交付

员工配置独立显示“默认项目目录”；聊天输入区域/任务详情就近显示当前项目短名及完整路径Tooltip，支持系统目录选择和返回受管目录。复用全局控件与原保存方式，保存失败/冲突沿Sonner及实际回执，不新增常驻操作状态文案。

API授权目录继续单独管理；项目选择本身不修改授权列表，后续访问缺许可时沿原目录申请或已保存执行权限办理。native使用自身目录、工具和审批配置，也应能选择cwd；不能因为native没有BOAI授权列表就隐藏项目选择。

群组沿当前执行员工及其assignment解析目录，不创建群共享目录，也不继承其他员工的许可。定时/自动派生的新任务无显式项目时，在创建该次任务时按同一规则复制默认，首次受理核验并固定；已有occurrence续行使用原快照，重启不重新取默认值或重复执行业务。来源已有显式目录时保留，不能被定时派生覆盖。

API与native统一核验当前员工/会话、真实文件身份、获准来源及hash，再复用`stageBusinessArtifact`或等价原服务把需要交付的文件复制到受管成果区。需消除native“合法项目文件因不在会话workspace而拒绝”的接缝，不能改成发布任意宿主文件。复制失败、原件变化、未知回执均沿原协议处理。

项目中的业务原件继续属于用户；删除员工、聊天、任务或清理交付副本，不删除或回滚项目原件。使用`self:/`、`shared:/`等显式逻辑路径的内部工具保持既有语义。生成图片/文档的可配置本地保存路径应沿同一项目解析；暂不支持选择落点的工具明确说明，不能仅凭设置已保存就声称所有产物均落在项目。
