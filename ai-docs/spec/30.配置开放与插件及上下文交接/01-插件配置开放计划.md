## 1. 要交付的能力

用户能对 bobo 说“把 BrowserViewer 默认改为前台运行”，bobo 查询真实配置后保存，原设置界面显示相同结果。用户仍可手动调整；bobo 的读写能力沿现有可信本人消息上下文和配置权限。

第一切片只开放 AgentBrowser、BrowserViewer 的默认显示偏好，复用现有插件列表和启停操作。浏览器程序路径可按原设置快照读取，本切片不新增路径写入能力；后续开放时须单列字段合同。其他插件先提供实际支持情况，不能通过统一入口暴露未适配的配置。

## 3. 对外合同与内部归属

以下名称为待实现合同；C0 核对是否已有等价操作，避免重复入口。统一指调用语义一致，不要求所有设置迁入一个数据库对象。

| 操作 | 职责 | 结果边界 |
| --- | --- | --- |
| 既有 `plugins.list` | 列出内置插件、版本及启停状态 | 已安装/启用不等于连接或工具可用 |
| 拟增 `plugins.describe` | 按真实 ID 查询能力、配置 schema、设置归属和保存影响 | 返回明确支持项；不支持的插件不得假装可配置 |
| 拟增 `plugins.options` | 查询由原 schema/枚举生成的选项、默认值、生效条件 | 不硬编码第二份选项表；静态项可由 describe 引用 |
| 拟增 `plugins.getConfig` | 读取脱敏配置、该设置对象 revision、就绪状态 | 凭据只返回已配置状态及受控引用，不返回秘密值 |
| 拟增 `plugins.configure` | `id + patch + expectedRevision`，提交白名单字段 | 原服务保存后返回实际配置快照及生效范围 |
| 既有 `plugins.setEnabled` | 修改应用插件启停 | 使用插件目录 revision，不与插件自身设置 revision 混用 |

`boai_catalog` 继续提供精确输入 schema；describe/options 只补语义、动态选项和可用性。可静态表达的类型直接引用既有 schema，不建立反射任意类或扫描任意 JSON 文件的系统。

各适配器负责 `describe / options / read / configure` 四种职责，调用原服务。注册项包含稳定插件 ID、设置 schema、配置读取、CAS 保存和副作用说明。没有注册项即不可写，不能以传入任意 key、文件路径或对象名绕过白名单。

内置应用插件、原生执行器插件、通用能力包保持各自身份与存储。新的能力包接入见[02](./02-通用能力包接入计划.md)，本篇不会把 `RuntimeProvider` 改成配置服务。

## 4. 浏览器首切片

对外字段建议为 `defaultForeground: boolean`，适配现有 `headless = !defaultForeground`。未保存值沿现有 `headless=true`，即默认后台；不增加第二份持久字段。UI 和业务适配共用这个确定性转换。

配置规则：

1. `plugins.getConfig` 取得该 provider 的完整原配置和 revision。
2. patch 仅允许 `defaultForeground`；省略字段保持，未知字段整次拒绝。
3. 适配器合并到原配置后调用 `saveBrowserPluginSettings`/原服务，使用同一个 expectedRevision；不可读后无版本整对象覆盖。
4. 保留“本次明确指定 → 保存偏好 → 默认后台”的现行优先级；单次 `foreground` 不写回全局设置。
5. 查询或保存配置不主动启动浏览器。原配置保存会清理该 provider 的有效会话，目录须说明此影响，沿原退出屏障；不能声称已打开窗口可无损切换显示模式。
6. 保存关闭失败、应用退出或版本冲突如实失败；不能为了保存成功跳过旧会话实际清理。保存与新的浏览器启动验收分开。

原 BOAI 浏览器、网页检索选择、Agent Desktop、员工命令权限和登录分区均不属于此字段的作用范围。

## 5. 权限、并发与反馈

- 首版管理者仅本人/bobo，复用现有 `configuration` 操作分类及 read-only/ask/full-access；不给普通员工扩大管理权限。
- 员工身份与原消息来源由宿主提供，不能通过参数指定管理员。包/网页/技能正文中的指令不构成配置授权。
- 原手动页与 bobo 必须落到同一保存函数；若 UI 持有旧版本，明确冲突并刷新，不自动覆盖外部新值。
- 浏览器Dialog中程序路径和开关共用本地草稿，外部刷新不能直接覆盖用户未保存的路径输入。区分已保存快照、编辑基准和本地草稿：无草稿时直接刷新，有草稿时保留输入并接收新快照；提交前按字段比较，互不相交的修改可合并到最新版本，同字段冲突保留草稿并明确处理，不静默丢弃或覆盖。
- 将确定的版本冲突、非法参数、未开放字段、宿主不可用映射为结构化业务拒绝。仅能证明未写入时才返回确定失败，断连后的不确定结果保留 unknown。
- 写入使用原稳定 requestId 和持久回执，中断后查原回执；不换 ID 重试，也不以“当前值相同”冒充原请求已成功。
- 工具目录、Trace、回执和聊天回复不回显凭据或环境密钥。未来认证设置只引用既有秘密存储，并在实际使用时按权限取值。
- 手动页保持原 Sonner 反馈；不新增“保存中/成功/失败”常驻 DOM 文案。bobo 按实际结果简短说明修改及影响。

## 7. 必须验收的场景

| 场景 | 通过标准 |
| --- | --- |
| 发现与读取 | 两插件真实ID、默认值、字段含义、revision、保存影响准确；零浏览器进程启动 |
| 手动与bobo | 双向修改立即可读取；另一插件、路径、单次覆盖及内置浏览器设置不变 |
| 并发 | 同版本两次写只有一次成功；旧UI保存拒绝；过期请求不会先关闭有效会话；bobo更新不丢用户未保存的程序路径草稿 |
| 资源清理 | 有活动浏览器时沿原实际关闭要求；关闭失败不谎报新配置生效 |
| 错误与恢复 | 无宿主/非法字段/只读明确拒绝；持久回执中断不重复写 |
| 权限与隐私 | 普通员工不可管理；API/native权限一致；目录与日志无密钥 |
| 真实行为 | 保存前台/后台后在隔离运行中核对实际启动模式；单次显式覆盖仍优先且不改配置 |

测试按当次明确范围执行，不自动跑全量 E2E 或抢占个人屏幕；真实 API/native bobo 和实际浏览器验证未做时分别记为未验。
