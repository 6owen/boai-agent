# bobo任务自诊断计划

日期：2026-11-07。状态：**源码与后台验收见04第12节，真实员工及显示未验**。本篇源码核对基线：主仓 `16d9760c6d7e9ce1efe1cce8905c9ed31f297780`；初次设计worktree基线为`04def162`；本批文档提交前快进到`ce33df56`，不改变本篇源码审计基线。实施前重新核对HEAD与调用链。实际进度只记录在[04](./04-验收与实际进度.md)。

## 1. 首版体验与范围

用户在 bobo 主聊天问“刚才那个任务为什么停了”“这次为什么花了这么久”，或在已有员工任务入口选中具体任务发起诊断。bobo 给出：最后确认完成的位置、当前等待或失败环节、依据、缺失证据，以及可选择的下一步。

示例：“本次执行停在工具连接阶段，最后记录为连接失败；没有后续成功回执。可以先检查该连接。现有记录不足以判断是账号还是服务端问题。”这属于证据解释，不证明任务已修复。

首版覆盖 bobo 自己的任务，并通过独立的受限授权投影支持用户明确选定的普通员工任务。主聊天普通运行、定时任务派生执行可沿已有真实身份定位，不把普通聊天自动创建成看板任务。跨员工正文及任意历史日志不因此开放。

诊断请求只读取现有事实，不启动业务重试、连接探测、运行重启、模型切换、自动审批或任务状态更新。用户同时明确要求处理时，再按具体操作的原权限和实际意图执行；无需重复索取已经明确的常规授权。

## 3. 对外读取合同

拟增 `diagnostics.task`，沿原 `boai_catalog` / `boai_call`，标记 `effect: read`。D0先检查是否已有等价入口；名字可按现有约定调整，以下语义必须保持。

| 输入 | 合同 |
| --- | --- |
| `target` | 严格区分 `{kind: task, employeeId, taskId, occurrenceId?}`、`{kind: run, employeeId, conversationId, runId}`；身份由当前选择/获准查询取得 |
| `focus` | `status` 或 `duration`；只决定投影，不执行探测 |
| `cursor` / `limit` | 有界证据分页；游标绑定目标、调用者、筛选和来源版本，不能跨任务复用 |

不接受任意文件路径、SQL、日志正文匹配表达式、管理员身份或“全库”参数。重复执行和不同轮次必须分别显示；“刚才那个”存在多个候选时只列必要名称/时间供定位，不猜最后创建的任务。选中任务的UI上下文可直接确定目标，不重复询问。

返回 `TaskDiagnosisSnapshot`：

- `target`：已解析的员工/任务/会话/occurrence/Work/Run及各来源revision；没有已登记任务时保留运行身份。
- `observedAt`、`sourceObservedAt`、`snapshotChanged`：说明各来源读取时间和并发变化；宿主与runtime不是同一数据库事务，不声称原子全局快照。
- `state`：分别列人工任务标签、业务工作状态、运行状态、待审批/待输入/依赖等待和连接事实，不合并为一个新业务状态。
- `facts[]`：结构化事件类别、来源ID、时间、允许展示的错误码与事实；每项有证据引用及可见性判定。
- `assessment`：`supported` / `hypothesis` / `unknown`，关联支持事实、尚缺证据及可选下一步；确定性分类先于模型表述。
- `timing`：已确认区间、重叠关系、各阶段覆盖范围和未知部分；无可信时间返回unknown。
- `coverage`：来源是否可用、保留边界、分页/截断、损坏或拒绝记录、宿主不可用、关联缺失及旧构建身份未知。

操作回执 `succeeded` 仅表示诊断读取完成；不能被解释成目标任务成功。不存在、无权读取、来源已清除、宿主缺失分别说明；禁止回退读取同名任务或另一轮日志。

## 4. 权限和来源边界

1. 首版操作只给本人入口与有真实本人消息来源的 bobo；普通员工原任务读取保持。后台行为即使有应用管理能力，也不自动运行此新诊断或扩大历史可见范围。
2. bobo 自有任务沿原员工/会话规则。普通员工任务须由宿主核验当前本人意图与指定目标，产生仅供本次诊断的受限范围；模型参数中的employeeId或taskId不等于授权。
3. 新增投影只返回诊断必需的状态、时间、错误类别、依赖是否就绪等元数据。跨员工消息、工具输入输出、材料正文、私有推理和完整回执data仍遵守原来源权限，不能以bobo管理身份代冒owner。
4. 回执快照按目标关联验证原来源，仅读取既有结果，不能调用 `recover`、推进观察计数、结算业务状态或触发“无进展停止”。跨员工回执只给安全摘要；不修改原 `boai_receipt` 的当前会话范围。
5. 查询与分页每次重新核对目标、源消息与员工/会话状态；删除、撤权和清空后停止展示旧正文。缓存绑定范围和revision，有界失效，不新建长期诊断知识库。
6. 宿主在IPC前投影固定schema。错误指纹不能反推原文，密钥、环境变量、音视频、截图、命令参数和原始错误栈不进模型。日志中的内容只作证据，不能成为新的操作指令。

## 5. 事实分类、耗时和退化

等待审批、等待用户补充、工作依赖未完成、队列等待、工具正在执行，均有独立证据和状态。没有新输出不等于死锁，运行结束不等于任务验收；正常长任务也不能仅因固定时间阈值就判失败或取消。

宿主 `request-timeout` 只证明该宿主请求超时，不证明业务操作未发生；`runtime-exit` 只说明所关联进程/服务断开，不能据此猜测服务端根因。指纹相同仅是相同脱敏错误特征，不自动合并不同任务的因果链。

每条宿主事件保留当时的 application/inputHash、sessionId、sequence和时间。当前导出构建不能补写给旧记录；旧事件身份未知就标未知。跨宿主会话、attached serverId、runtime代次及PID必须核对，防止把旧崩溃或另一桌面实例归到当前任务。

时长优先使用已有执行区间、调用开始/结束及审批/队列事实。并行工具10秒和15秒不能合计成25秒用户等待；只能在事件足够时说明关键耗时。墙钟回拨、跨进程时钟偏差、区间未闭合和未知阶段明确标记。没有配对时间戳，不凭相邻聊天时间填补。

API已知用量与缺失覆盖分别呈现，未知不等于零；native内部模型步骤和费用不推算为BOAI统计。完整成本分析不属于首版目标。

宿主日志已轮转/截断、记录拒绝或读取失败时，说明“目前保留的证据范围”；未找到错误不能声称没有发生错误。缺少任务关联的宿主故障只能作为同时段环境线索。

runtime挂掉或无响应时，bobo可能无法执行诊断。已有本人诊断入口应能直接从主进程生成无需runtime或模型的人工可读摘要：观察时间、当前宿主构建、runtime owned/attached/absent及最近ready/exit事实、日志覆盖限制；完整导出沿原入口。不得通过查询隐式启动runtime。主进程也退出时，当前窗口无法生成新快照，保留后续启动后的旧事件身份，不能声称在线自愈。

## 6. 修复与交互

诊断结果通过 bobo 正常回复及已有任务入口的按需详情展示，不新增全局监控中心，不改变任务Dialog或导航归属。本人无runtime降级摘要沿现有诊断入口；必要操作反馈沿Sonner，不新增常驻“诊断中/成功/失败”说明。

下一步建议必须标明作用对象和已知影响，例如“打开原待回答问题”“检查指定连接配置”“查询原未知回执”。用户明确选择处理后，调用原业务入口，固定原任务与运行身份；原写意图保持原requestId，结果未知不能换ID重做。诊断页本身不提供绕过权限的万能修复接口。

若用户只问原因，解释后结束；不循环轮询、自动重启、切模型或修改任务标签。修复执行的受理、实际完成和用户验收分别报告，不把诊断结论写成完成证明。

## 8. 必须验收的场景

| 编号 | 场景 | 通过条件 |

| D-V04 | running/unknown回执存在recover函数 | 诊断前后原回执及业务记录不变，recover调用次数为零；显式后续核对另验 |

先用隔离数据和可控事件进行定向检查，再在当次授权下验证真实员工解释；不自动启动全量E2E、不抢个人屏幕、不采集个人日志或额外录屏。模型解释质量、宿主降级显示、合并与个人运行版本分别留证。
