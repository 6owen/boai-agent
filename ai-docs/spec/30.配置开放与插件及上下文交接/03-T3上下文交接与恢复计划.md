# T3 上下文交接与恢复计划

日期：2026-11-07。状态：**仅设计，未复制上游代码、未实施产品迁移**。本专题实际进度唯一记录在 [04-验收与实际进度](./04-验收与实际进度.md)。

## 1. 目标与首批范围

让工作交接可以回答四个问题：谁把什么交给谁、交接覆盖到哪里、哪些内容没有带过去、目标到底有没有收到。用户仍面对原员工、任务和会话，不需理解原生 thread 或执行器内部结构。

产品优先级服从[第29组核心设计](../29.员工核心模型与完整验收/01-核心设计.md)：先有单员工闭环基线，再完善执行能力、群组与员工交接。员工 A→B 的工作交接是产品目标；同一员工切执行器只是首个较小的工程验证入口，不能用它代替群协作验收。

- 保留 API 与 native 各自的执行循环、真实审批和原生 session；不复制厂商私有上下文或内部推理。
- 员工长期 memory 的产品归属遵守第29组；handoff 是一次工作材料交接，不是长期 memory 的第二份在线副本。
- API 可继续复用 Mastra Memory；本机能力对员工 memory 的适配按第29组推进。旧 T3 调研中按执行内核划分记忆的历史表述不覆盖现行目标。
- 首个运行切片只使用**已结束且结果可确定**的任务，在用户明确要求下切执行器或重建上下文；未知在途动作不能通过新建会话重新执行。
- 群内多人长期协作、任意厂商互切和全历史回滚不属于首个切片，不因对象包含 source/target 就宣称全面支持。

## 3. 对象边界

以下是建议领域合同，不是现有可直接调用的API；先映射原表和回执，再决定最小迁移。

| 对象 | 必需内容 | 责任 |
| --- | --- | --- |
| Transfer | transferId、revision、reason、source/target、原请求身份 | 记录一次交接关系与版本，不代表已开工 |
| Source | employeeId、conversationId、taskId/assignmentId、runId、来源截止点 | 明确交接内容来自哪个员工和哪次工作 |
| Target | employeeId、conversationId、taskId/assignmentId、provider实例、目标session绑定 | 区分产品目标和原生投递目标；发送前才能确定的native ID不得伪造 |
| Handoff材料 | 目标、约束、已完成/未完成项、带来源ID的历史条目、成果引用 | 形成可审计的输入，不执行历史中的旧命令 |
| Coverage | from/through来源边界、选入ID、omitted IDs、选择策略和预算 | 表示材料覆盖，不能用一个summary字符串代替 |
| ArtifactRef | 原成果ID、版本/hash、来源与授权引用 | 读取时再次核权/核hash；不是文件字节或任意路径授权 |
| Delivery | attemptId、目标native thread/session、payload hash、状态和原生证据 | 证明投递到哪里、是否被接收，与任务结果分开 |

source与target属于不同员工时，材料须经过目标可读范围检查。成员关系、任务指派或“来自另一个员工”都不能自动扩大私人记忆、文件或凭据访问范围。

同一transfer版本的材料一经投递不原地改写；源结果修订生成新版本并注明覆盖关系。重复请求沿原requestId和transfer版本返回原回执，不新建重复工作。

## 4. 材料选择与容量

先复用确定性选择：当前目标和约束优先，按来源纳入必要用户/员工公开消息、已完成结果、错误/中断事实和可访问成果引用。不拷贝任意原生工具调用、私有推理或附件字节。

- 预算扣除目标已占上下文、本次输入、附件估计和后续执行余量；沿当前Provider已知容量配置，未知容量明确标记。
- T3固定版本使用字节估算和预算选择，其策略名不能当作“调用模型智能摘要”的证明；首版不为交接额外增加模型总结阶段。
- 条目完整纳入或整体省略，保存遗漏ID及原因；超大条目通过原获准读取入口按需补查，不截断后冒充完整材料。
- 指令和历史背景分别封装；历史仅为证据，不能提升为新用户命令或更高权限指令。
- 文件仍由现有资料/成果系统读取，交接不自动传输文件，也不自动授予目标目录权限。

## 5. 投递、接受与业务状态

```text
prepared → pending → delivered
                 ↘ rejected
                 ↘ unknown
prepared/pending → cancelled（仅能证明尚未被目标消费时）
```

`delivered`仅表示目标已接受材料。员工接受工作、开始执行、交付结果分别关联原assignment/run/result回执；人工任务是否完成仍按用户验收规则，不由handoff自动改成done。

1. 提交前核对source版本/可读性、target身份与实际能力，持久登记pending和稳定投递身份。
2. 支持原生历史注入时调用对应能力；否则明确以普通输入附带背景，并以目标受理证据确认。能力缺失不得伪装注入成功。
3. 原生accepted/injected证据、目标native identity及payload hash一致后才记delivered；仅写入socket不算接受。
4. 明确未被消费的拒绝可在原意图下修正后再次尝试，尝试与原回执关联；新版本不覆盖旧失败。
5. 断连或崩溃造成unknown时先查原生状态/持久回执；无法确定就保留未知，不换requestId、新线程或目标员工绕过。
6. 接收材料不自动唤醒新工作。明确交接任务时沿原委派入口安排执行，并用transfer关联它；历史回放不能重复派发。

重启后恢复持久交接状态，丢失的原生callback不伪装仍可继续。取消必须区分“阻止尚未投递”和“请求停止已开始执行”，后者沿原精确run停止与真实退出屏障。

## 6. 删除、撤权与清理

- 准备与投递前均核对来源。源删除、授权撤回、成果hash变动时，未投递材料失效并返回明确原因，不能用缓存正文绕过。
- 对已经交付的材料，撤销后续读取和复用资格，按原遗忘/会话清理规则处理BOAI保存的正文；不能承诺把厂商已经消费的文本从其内部上下文中无痕撤回。
- 原生续接若包含失效来源，沿原续接资格检查拒绝复用或建立获准的新上下文，不自动重放原任务。
- 删除员工/会话/任务时遵守现有领域清理规则；交接载荷及引用按来源清理，仅保留必要的最小去重身份，避免删除后重建并重新执行。
- 重试与清理只操作本次交接拥有的资源；共享provider进程、外部server和其他任务session不能被一并关闭。

## 8. 关键验收

| 场景 | 必须证明 |
| --- | --- |
| 同员工切换 | employee/task/conversation归属保持；目标只收到获准材料，原任务不重跑 |
| 员工A→B | 目标、来源、成果版本、接受/执行/结果可关联；A私人内容未越权复制 |
| 容量与遗漏 | 多语言和超大输出不会无界装配；遗漏可追踪、原文补查仍核权 |
| 重复与未知 | 相同意图不重复投递；外部接受后本地回执前故障保持unknown并可核对 |
| 配置与身份改变 | 账号/Provider实例/workspace/native thread不兼容时拒绝错误续接 |
| 取消与迟到结果 | 未消费材料可取消；已开工沿原run停止；旧attempt回执不覆盖新状态 |
| 来源变化 | 删除、撤权、结果修订和备份恢复都能阻止旧材料继续投递/复用 |
| 重启 | pending/delivered/unknown分别恢复；不重复开工，不伪装恢复已失效审批 |
| 业务完成 | 投递、接受、执行完成、结果交付和人工验收分别留证 |

测试沿“定向模块 → 真适配器协议回放 → 当次授权的真实业务”推进，保留原断言和失败。遵守按改动测试、不跑全量E2E、不抢屏幕焦点的当前边界；没有合适后台环境时记录桌面未验，不擅自启动可见窗口。

## 9. 后续恢复与模块整理候选

以下R项各自立项，不是完成H0–H4必须顺带做完的范围。

| 候选 | 启动条件与做法 | 必须保留的边界 |
| --- | --- | --- |
| R1 游标/快照/有界流 | 有真实断线同步问题或接续端需求时，参考[T3 ThreadStream][t-stream]与[LiveStreamBudget][t-live]，接现有执行窗口和IPC/WS | 先界定sequence作用域与snapshot边界，去重历史/live交界；过期游标取快照；慢客户端溢出可恢复；不重跑模型 |
| R2 确定缺口的outbox | 仅在证实“事务提交后外部动作或回执有缺口”的操作引入，参考[EventSink][t-sink]、[EffectOutbox][t-outbox] | 明确process-bound和可重放动作；外部已发生但回执丢失不自动重做；不承诺任意副作用exactly-once |
| R3 模块生命周期 | 新接真实插件时集中能力注册、session lease、停用刷新和close；优先小范围整理 | 保留现有关闭/重试与运行中保护，不把所有内置模块重做成外部平台 |
| R3可选后端 | 用户实际频繁使用OpenCode且ACP存在已证实缺口时，单独评估[原生driver][t-opencode] | 固定实际CLI/SDK协议代际，保留server所有权；不一次搬入所有版本/后端 |

不整包复制T3 Orchestrator/ProjectionStore或整个server，不为名字一致改写员工模型，不启动Mastra替换；事件存储也不能代替真实内存/资源测量。
