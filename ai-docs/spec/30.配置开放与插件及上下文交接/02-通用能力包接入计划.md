# 通用能力包接入计划

日期：2026-11-07。状态：**仅设计，未实施**。源码基线：`04def162`。实际进度统一记录在[04-验收与实际进度](./04-验收与实际进度.md)。

## 1. 首版产品目标

把一组技能、MCP工具和配套资源作为一个可管理的能力包导入，明确安装来源、版本及支持范围，再绑定给指定员工使用。后续更新、停用、解绑和卸载能追踪到本包贡献的对象，不影响其他技能、数据源、员工或原生环境。

管理入口沿现有插件/技能界面和 application 业务协议增量接入，由本人/bobo管理；普通员工仅使用显式绑定且获准的能力。手动管理继续保留，首版不建设市场、后台自动更新或新的Agent循环。

范围以[官方包格式](https://developers.openai.com/plugins/build/plugins)为依据，核对日2026-11-07：根 `plugin.json`、`skills/`、可选 `mcp.json`、`assets/`；兼容 `.codex-plugin/plugin.json`。执行前冻结实际支持的规范版本与样本，不以兼容某种清单就宣称兼容全部Codex插件。

## 2. 已有基础与真正新增部分

| 已有基础 | 复用方式 |
| --- | --- |
| `RuntimePlugins` 的独立运行时包、hash/CAS/lease | 借用成熟包管理做法；能力包不冒充 `agent-runtime` 或替换 `RuntimeProvider` |
| `local-skill-catalog.ts:58` 已发现启用Codex插件中的skills | 保留只读发现和现有来源，不把发现项自动转换成BOAI托管安装 |
| 原技能安装/绑定/更新流程 | 保留员工副本、内容hash及用户修改保护；包映射引用真实技能ID |
| `SourceService`、MCP连接和SecretStore | 创建有来源标记的受管源，实际调用、认证、取消与清理沿原服务 |
| 原 application 身份/请求/回执 | 包管理是薄领域操作，持久写意图不另建第二套工具执行协议 |

关键来源：`packages/runtime/src/modules/backends/runtime-plugins.ts`、`modules/resources/local-skill-catalog.ts`、`modules/sources/source-service.ts`、`packages/shared/src/domain/sources.ts`；[第26组外部运行时插件合同](../26.Workspace工程结构重构/04-外部插件开发与接入.md)继续独立有效。

## 3. 支持矩阵与导入原则

| 包内容 | 首版处理 |
| --- | --- |
| portable manifest、skills、普通assets | 解析身份与说明；校验包内资源；通过既有技能服务登记 |
| portable `mcp.json` | 按声明的transport解析，映射现有MCP服务合同 |
| legacy `.codex-plugin/plugin.json` / `.mcp.json` | 独立解析后规范化；portable与legacy的MCP结构不同，不能只改文件名 |
| HTTP/SSE、stdio MCP | 仅承诺现有SourceService实际支持的方式；记录实际映射与不支持字段 |
| 无认证、bearer、stdio所需秘密环境变量 | 复用现有认证与秘密存储；缺秘密时明确待配置，不自动猜测/复制宿主密钥 |
| 依赖尚未支持的OAuth流程、平台私有连接器 | 报告不支持/待接入，不能将已注册的平台ID当通用MCP URL |
| hooks、任意插件UI、自动安装脚本 | 首版不执行；列出不支持项和受影响能力 |

官方说明中的 `extensions.com.openai` 与兼容overlay按所选规范的优先级解析，不能随意合并形成另一种语义。接口只返回必要元数据，清单中的说明/技能正文视为数据，不作为安装权限或操作指令。

默认仅接受用户明确提供的本地目录或已下载包；网络拉取、市场和依赖安装另期。扫描/预检不得启动MCP、运行脚本、安装依赖或联系远端。

预检发现不支持组件时返回完整支持报告。依赖它们的包拒绝激活；只有用户明确选择“仅导入已支持部分”且依赖检查证明可独立运行时，才允许部分导入，并持久标记partial及遗漏项。不能静默半导入后报告全包成功。

## 4. 对象与单一执行归属

| 对象 | 必须保存的事实 | 边界 |
| --- | --- | --- |
| 包来源 | 来源种类/规范格式/规范版本/上游标识及内容hash | 不依赖可变路径作为唯一身份，不保存凭据 |
| 安装记录 | installationId、packageId、version、hash、revision、启用/就绪及支持报告 | 安装存在不代表绑定或已调用；同名不同来源不能静默覆盖 |
| 贡献映射 | 包内skill/server键 → 原技能/源ID、版本与owned/reference关系 | 引用既有对象不获得删除所有权 |
| 员工绑定 | employeeId、installationId、所用版本、获准贡献、绑定revision | 全局安装与员工使用分开；安装不自动绑定全部员工 |
| 加载归属 | 当前会话能力由BOAI托管还是原生Agent提供 | 同一能力不能同时注册和执行两次 |

首版新增安装以BOAI托管贡献为主：API/native通过现有产品工具桥使用相同获准能力，仍保留原生循环。原生环境已加载的插件保持只读发现；检测到同来源能力重复时明确拒绝双重注册，要求使用已有原生来源或由用户明确调整绑定。

必须处理现有bobo默认可访问全部启用数据源的规则：包贡献创建时保持未激活；在原能力发现和实际调用入口，对包托管源共同校验安装状态、启用状态、员工绑定和版本。bobo可管理全部包不等于可执行所有未绑定包的工具，不能只写一份绑定记录而让原全源权限绕过它。普通既有数据源的权限语义保持；这项校验只针对有明确包归属的贡献，并复用同一判定函数，不能仅过滤工具目录。

不能假定所有原生Codex路径都禁用了插件：`packages/runtime/src/adapters/codex/client.ts:130` 的native启动分支与另一分支不同。实施需据实际运行配置核对能力归属；不修改用户全局Codex配置、不卸载原生插件来制造去重成功。无法识别/隔离的组合返回不支持。

## 5. 导入与生命周期合同

操作名称在P0冻结，建议职责为 inspect/install/get/bind/unbind/configure/setEnabled/update/uninstall，统一注册到原 application 协议；精确目录返回本版schema。不要同时创造多个入口管理同一安装事实。

1. **预检**：schema和路径校验、内容hash、贡献列表、支持范围与权限需求。拒绝绝对路径、`..`逃逸、包外符号链接、重复规范路径、超出文件数量/层深/字节限额；固定上限写入共享常量并测试边界。
2. **安装**：复制到独立staging，校验后登记安装与贡献映射；首次默认不向员工暴露工具。文件系统与数据库不能假装一个事务，需可恢复的提交阶段和孤立staging清理；失败保持原活动版本。
3. **绑定/就绪**：显式选择员工和贡献，沿原技能/源授权；缺凭据、命令环境或不支持transport返回准确未就绪原因。绑定不启动MCP，连接测试/实际调用另有明确动作。
4. **调用**：校验绑定、版本和权限；MCP及本地命令沿原目录/命令审批，manifest不赋权。stdio是本地代码执行入口，安装不代表自动允许运行。
5. **停用/解绑**：先阻止新调用并撤回发现，再沿原租约取消/排空本包在途操作。关闭失败保留可追踪句柄和状态，不能报告完全停用或删除在用文件；共享连接按引用归属处理。
6. **更新**：先预检新版本并展示权限/贡献差异；新增权限未经明确授予不激活。旧运行固定旧版本，首版在本包活动租约存在时拒绝切换；失败保留旧版、原配置和绑定。
7. **卸载**：先解绑/停用并确认本包资源实际退出，再删除本包owned副本和映射。共享源、外部原生包、用户修改的技能副本、其他包及凭据引用不得一并删除；有定制内容则保留为独立对象并报告。

所有写操作校验对应安装/绑定revision，使用稳定requestId；确认未写入的错误与未知结果分开，恢复查询原回执而不重新创建安装。多服务提交中断要能检查阶段并收敛，不能因进程重启重复创建技能和MCP源。

## 6. 凭据与配置

包记录和员工绑定只保存秘密引用与就绪状态；秘密由原SecretStore按现有授权使用，不进入目录、日志、Trace、回执或导出包。包内硬编码秘密不得自动迁入或回显，要求通过原安全配置入口重新配置。

读取插件配置沿[01](./01-插件配置开放计划.md)的白名单适配。包提供的任意schema不直接变成任意宿主键写入器；manifest表达需求，BOAI决定支持字段和实际配置服务。环境变量只注入本包受控MCP进程，不合并成全局环境；删除凭据前核对引用，不能影响其他连接。

## 7. P0–P5执行分片

| 阶段 | 工作 | 完成门槛 |
| --- | --- | --- |
| P0 冻结首版合同 | 固定规范/样本、对照现有服务、确定身份与加载归属 | 支持矩阵、源码映射、请求及版本合同可审阅 |
| P1 只读解析预检 | portable/legacy解析、路径限制、hash、支持报告 | 无副作用；非法包及部分支持结果明确 |
| P2 安装与贡献映射 | staging/安装记录、既有技能与MCP源适配、失败恢复 | 同请求幂等；失败无半活动包；独立来源不会互相覆盖 |
| P3 员工绑定与调用 | 权限、配置引用、API/native去重及指南；包贡献统一绑定门禁 | 指定员工能调用，含bobo在内的未绑定员工不能绕过包执行授权；无宿主全局配置改写 |
| P4 更新与退出 | 更新差异、CAS、停用/解绑/卸载、租约与资源归属 | 活动版本固定；失败保旧；真实资源退出且共享对象保持 |
| P5 代表验收 | 三类真实样本和失败场景 | 工程、实际MCP、真实员工路径分别留证并记入04 |

P0/P1可与配置目录设计并行，涉及application注册、技能/源ID分配、数据库集合的修改由协调者指定唯一编辑者；P3依赖已冻结的配置合同和共同单员工基线。

## 8. 验收样本与完成条件

| 样本/场景 | 必须证明 |
| --- | --- |
| 纯Skill包 | 导入→指定员工发现/读取→更新保护定制→解绑/停用撤回；无MCP副作用 |
| Skill＋MCP包 | 从技能找到实际工具并调用；HTTP或stdio按所选样本验证，原生/API不重复注册 |
| 需要认证的MCP包 | 缺凭据不调用；原入口配置后成功；撤销后拒绝；秘密不外泄 |
| legacy与partial | 两种格式的等价字段一致；不支持项明确；未选择partial不半激活 |
| 并发与故障 | 旧revision拒绝；同requestId不重复；阶段中断可恢复；失败更新保旧版本 |
| 生命周期与所有权 | 停用阻止新调用并排空旧资源；卸载只删除owned对象；定制/共享内容保留 |
| 供应内容变化 | 内容hash变化被识别；权限增加未获准不生效；包外路径和静默脚本执行被拒绝 |

至少覆盖一个API员工和一个实际支持的本机Agent路径；普通员工只能消费已绑定能力，管理仍归本人/bobo。纯模块测试、真实MCP传输、真实模型自主使用和桌面界面各自记结果，不相互替代。hooks/UI/私有连接器未支持时保留限制。

## 9. 后续Agent任务文本

> 按本篇执行 P0–P5，首版只实现受支持的Skills/MCP/资源能力包。复用原技能、SourceService、SecretStore及application协议，保持RuntimeProvider和员工模型。先冻结portable/legacy映射、加载归属和三类样本，再实现安装、绑定、更新、停用与卸载。禁止修改全局Codex配置、重复注册原生能力、运行包安装脚本、静默忽略不支持项或删除共享/定制对象。按当次授权执行测试和真实调用，在04记录实际层级、失败与未验范围；不要把目录解析成功宣称完整插件兼容。
