## 2. 实施范围与完成口径

- 当前macOS的API/Mastra、Codex、Claude为必需路径；插件沿原公共合同承接，实际支持表单列，不以重新认证整个插件平台为本功能前提。
- 复用员工、Workspace、原生会话、审批与执行流。增加目录访问授权及接续，不建设独立群沙盒、云容器管理或网络隔离系统。
- 初始持久目录授权、当前运行临时授权与完全访问自动策略是三个来源；实际判定均归当前执行员工，不归会话或群负责人。
- 目录访问批准不重复等同命令/浏览器/远端写审批；保留各自权限，共用待决操作时清楚显示真实范围。
- 知识资料和Web Search不构成前置；本功能接入时负责WS-A10联合检查，其他功能的既有成绩不代替本次授权测试。

## 3. 实施步骤

### WS0：现有能力与批准接续基线

核对已安装Mastra Workspace/filesystem/sandbox、BOAI宿主工具、Codex/Claude及插件原生批准接口。使用隔离目录A、B和哨兵文件建立代表流程：A已授权，B未授权，读取/编辑B先等待，批准后成功，拒绝不访问；改成完全访问后B直接可用。

记录程序版本、有效目录许可、命令cwd、原生请求与批准回执，确定各后端的最小适配。优先用已有Workspace和原生机制；仅设置cwd不能证明权限生效。此阶段不再把“任何时候都不能访问B”作为成功标准，也不要求先证明全机绝对隔离。

产出后端接线表与具体缺口；需要新增限制/批准接口时服务于上述流程。目标后端未跑通授权后继续或完全访问自动授权时，完整goal仍未完成。

### WS1：目录配置、批准与迁移

员工定义/保存IPC增加可见目录列表及读写许可；宿主核对真实路径、员工身份与版本。配置草稿、持久批准、本运行批准及实际回执关联，未知结果按原请求身份只读核对。

保留旧员工缺字段兼容和原执行权限。完全访问不靠写入全盘目录清单实现；新建默认也不自动设为完全访问。持久批准保存目录，本次批准只进入当前运行。

### WS2：公共文件访问与操作判定

复用environment-plan、file-access、WorkspaceService和现有资料/成果来源核验。在实际文件访问前按当前员工判定：已有许可可执行；权限不足请求批准；完全访问自动允许；只读拒绝写入。

覆盖读/列/搜索/写/移动/删除、链接真实目标、发布源及local/MCP/浏览器文件传输。保留原hash冲突、文件副作用与发布事务，不在批准前提前扫描或读取未授权正文。

### WS3：Mastra、本机与批准接续

API接已有Mastra Workspace及文件/命令执行器；Codex/Claude接其原生目录、权限和批准机制，不统一改成Mastra代理。命令、脚本、子进程与本地MCP使用当前员工许可；原生请求与BOAI审批共用真实操作身份，避免双重批准。

待决运行能接受本次目录批准并接续原动作；持久批准更新员工授权版本，避免把合法批准误判成需要取消全部任务的无关配置变更。拒绝、撤回、停止、原生session失效和实际退出沿原生命周期，未知操作不自动重放。

群聊、私聊、渠道、自动化、协作与修订只负责定位执行员工，复用上述链路；不为每个入口再实现一份目录策略。

### WS4：配置和审批UI

在独立工作区Card提供目录列表、权限与增删；执行权限沿现有入口，完全访问准确说明自动授权其他目录。员工系统目录继续独立展示。

目录申请复用原审批卡片，展示真实路径/读写许可/原因，提供允许本次运行、始终允许、拒绝。待决保存/未知核对/取消沿原状态；持久批准回填版本时保留其他配置草稿。错误统一Sonner，打开配置不扫描项目或执行模型。

### WS5：业务验收与交付

按下方矩阵验证批准前、批准后、拒绝后及完全访问四种实际结果。读访问以真实文件门禁、进程观察和返回原件核对；写操作以独立hash/目录核验，不能只依赖模型自述或审批卡出现。

隔离员工与测试文件，覆盖源码桌面及当前目标平台应用包。用户审阅实际效果；成功、失败、未知与未支持组合分别留证，不测试删除个人项目。

## 4. 验收矩阵与完成条件

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| WS-A01 | 配置目录与执行权限 | 路径/读写许可/员工身份正确持久化，cwd及内部状态未被强制迁到该目录 |
| WS-A02 | 请求审批员工访问已授权coding | 按许可创建、读取、编辑、移动和删除，不重复申请相同目录权限 |
| WS-A03 | 请求审批员工读取新目录 | 实际读取前等待；批准后读到目标原件，拒绝/取消不读取 |
| WS-A04 | 请求审批员工编辑新目录 | 实际写入前等待；读写批准后写成功，仅只读批准不能写 |
| WS-A05 | 完全访问员工 | 未预配的两个业务目录均可实际读写，无目录审批弹窗，原审批策略来源可核对 |
| WS-A06 | 只读员工 | 已授权文件可读；额外目录可申请只读；任何目录批准都不能越过员工只读上限 |
| WS-A07 | 临时/持久批准 | 临时只对原运行有效且重启不继承；持久授权在该员工新交流可用并可移除 |
| WS-A08 | 群/多入口归属 | A、B同群各用自己目录；B批准不授予A；私聊、渠道、定时与修订行为一致 |
| WS-A09 | 工作位置与冲突 | 可在批准后的其他位置工作；其他工具保持原运行位置；同目录并发不静默覆盖 |
| WS-A10 | 资料/源/浏览器联合入口 | 知识及附件按原材料权限读取；实际编辑外部目录、本地MCP或上传/下载需要相应目录许可，完全访问自动允许 |
| WS-A11 | 链接及路径替换 | 按真实目标判断；请求审批不借链接绕过，完全访问不误阻止合法目标，删除链接不误删外部目标 |
| WS-A12 | Mastra与命令 | 复用已有Workspace；文件工具、命令/脚本及后代按相同目录策略，批准后可执行 |
| WS-A13 | 原生执行 | Codex/Claude保留循环、模型、工具与session；外部目录申请/接续和完全访问均实际可用 |
| WS-A14 | 活动中批准/撤回 | 本运行能接受合法追加授权；撤回后受影响新操作受阻，旧原生资格不继续使用 |
| WS-A15 | 故障/未知/重启 | 丢失路径、OS拒绝、批准失联如实记录；核对不重复批准，不重放未知文件操作 |
| WS-A16 | 旧配置兼容 | 不改变旧员工/bobo的权限，无关字段保存不隐式新增/收紧目录许可 |
| WS-A17 | 用户文件归属 | 删除员工、清空记录、移除授权不删除或回滚业务目录，受管副本清理保持 |
| WS-A18 | 备份恢复 | 保存持久授权，不递归导出/覆盖业务目录，不恢复临时批准或自动执行 |
| WS-A19 | 配置/审批UI | Card与原审批卡一致，草稿/版本/取消/关闭/未知状态正确，错误只有Sonner |
| WS-A20 | 原能力回归 | 系统文件、知识资料、源绑定、文件交付、浏览器、模型来源及取消/发布事务保持 |

模块用Vitest及隔离SQLite/文件；实际进程验证真实读取和副作用；桌面沿现有playwright-bdd和隔离数据。API/Mastra、Codex、Claude各完成A内操作、B申请批准/拒绝及完全访问流程，至少一场混合群验证A/B目录归属。插件按真实支持表单列，不用模拟结果替代原生实际调用。

执行相关类型/lint/模块/构建与桌面检查，保留构建标识、原失败、复验和输入/回执/原件。记录模型请求与非模型操作，沿原运行用量规则，不新增本机BOAI预算。技术通过、证据完整性和人工评价按[自动验收规约](../02-自动化功能验收与结果审阅.md)分开。

完成条件：WS0–WS5有真实产出，WS-A01–WS-A20覆盖必需路径；目录申请、授权后继续和完全访问自动授权均实际通过。界面已展示或进程能启动不代表授权闭环完成。
