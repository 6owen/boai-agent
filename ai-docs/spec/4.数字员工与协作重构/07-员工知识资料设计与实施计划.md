# 员工知识资料设计与实施计划

日期：2026-10-18。状态：**已按用户纠正修订，等待后续goal；本次知识资料管理增量尚未实施。**

目标：完善现有员工“知识资料”的管理与使用，将主要管理入口放到文件区域。员工配置中的大块选择器收敛为简洁入口；用户可以把会话附件或员工成果明确添加为知识资料，也可以直接添加文件。员工在后续获准交流和任务中查阅这些参考文件。

名称统一使用**知识资料**，沿现有`knowledge`资源及员工`knowledgeIds`。本功能不新增或改名记忆类型，不把知识文件迁入`long_term`记忆；本轮review不包含记忆界面改造。资料可长期保留，是文件的使用方式，不是另一套“长期记忆”功能。

## 1. 产品语义

| 内容 | 用途 | 生效范围 | 例子 |
| --- | --- | --- | --- |
| 会话文件 | 本次交流输入、过程与交付的留存和再次引用 | 原会话/材料/成果授权 | 本月销售表、活动需求、员工报告 |
| 员工知识资料 | 跨任务持续查阅的参考依据 | 目标员工及明确允许使用的上下文 | 品牌规范、产品手册、术语表、项目背景 |
| 员工工作规则 | 规定职责、工作方式、表达与工具使用要求 | 原系统文件和员工配置合同 | AGENTS.md、SOUL.md、工作方式 |

配置给员工的知识资料进入相关资料的候选检索范围，不自动获得更高指令优先级；`.md`扩展名本身不决定权限或用途。若要求“所有文案遵守品牌规范”，在工作规则写明要求并引用相应资料。文件正文、网页摘录、历史聊天和员工成果均不能自行扩大工具或资料权限。

文件已保存不表示模型已读、每轮全文进入上下文或内容被永久记忆。知识资料仍按当前问题检索/读取并保留引用；它与现有记忆条目分别管理。员工产物须由用户明确选为知识资料，不能自动把草稿、错误回答或所有历史附件变成权威依据。

## 2. 界面与操作

### 2.1 主要入口

1. 会话文件沿现有文件列表展示附件和交付。文件更多菜单增加“添加到知识资料”。单员工私聊默认当前员工；群聊需明确选当前有权读取该文件的目标员工，首版不从此操作向无权员工扩散内容。
2. 员工维度的文件区域增加“知识资料”视图，可直接添加、预览、更新和移除。复用现有文件列表、全局预览、员工身份与右侧面板；不恢复已退役的独立资料库主页面。
3. 员工配置与资料概览保留“知识资料 · N份”的简洁入口，点击经原草稿守卫进入该员工文件视图。移除原大块多选列表；新建员工先完成身份保存，再管理资料。
4. 首版不增加聊天顶部常驻知识开关、独立问答系统、文件版本页或一套新的检索界面。来源与更新时间可查看，内部版本/hash用于核验，不恢复已经移除的文件历史/对比UI。

### 2.2 明确操作的含义

- “添加到知识资料”明确表示为该员工独立保留这份内容，供后续获准任务使用；显示文件名、目标员工及来源。操作不发送新聊天消息、不启动模型、不改变原文件内容。
- “直接添加”使用现有文件选择/导入链路，但完成后归该员工知识资料，不要求先制造一条空聊天消息。
- “更新”明确选择新内容，替换该条知识资料的当前引用；普通附件变动或员工后续修订不静默替换它。原聊天里的历史附件/成果保持原内容身份。
- “移除”停止员工后续检索/读取该资料，原会话文件与已交付成果保留；危险操作沿现有红色菜单和Popover确认，失败使用Sonner。
- 配置草稿、资料操作各用真实回执。资料添加/移除若影响员工授权版本，沿现有独立技能绑定的版本回填方式保留其他配置草稿，避免丢失未保存姓名、模型或目录授权。

## 3. 文件保留、来源与授权

### 3.1 独立保留

采用“明确保留的内容＋来源关系”，不能只保存指向会话文件的一条路径。宿主在当前来源/hash验证后取得受管不可变内容；底层可复用同hash受管字节或建立副本，但必须拥有独立生命周期。不能复制整个会话目录或通过文件名认定同一份文件。

来源记录至少能核对原会话、消息、材料/成果身份、内容hash、目标员工、操作者和保留时间。来源会话清理后保留必要来源标记，不为显示来源恢复被清空的消息正文，也不让原链接跳到同名新文件。

只有实际保留成功才显示在知识资料列表。副本准备、员工绑定和操作回执按原事务/持久准备方式衔接；失败仅清理本次归属且hash匹配的临时内容。请求失联先按原请求身份查询，不能重复新增。

### 3.2 使用权限

知识资料归明确员工；bobo的数据源全局访问规则不等于读取所有员工知识资料。群聊仍由各员工分别执行，每人使用自己的获准资料；群负责人不会因此获得全部成员的私有文件。知识共享只控制参考资料可用于哪个会话，不改变任何员工的工作目录。

| 使用场景 | 默认可用资料 | 用户管理与失效规则 |
| --- | --- | --- |
| 本人与员工私聊、本人发起的员工独立任务 | 该员工已绑定且有效的知识资料 | 员工文件区添加/移除，使用原员工身份及配置版本 |
| BOAI群聊、协作与群自动化 | 当前执行员工的`knowledgeIds ∩ 当前群sharedKnowledgeIds` | 文件区“共享到会话”选择明确的群并提交原共享关系；取消共享后该群后续使用失效 |
| 渠道私聊或群 | 当前员工绑定与该具体渠道会话获准集合的交集，并核对原请求者身份 | 文件区选择明确渠道会话授权；现有来源模型不能表达的上下文保持不可用，不做按员工一键开放全部渠道 |
| 其他员工 | 无自动授权 | 需要本人明确添加/绑定给该员工；同一内容可复用受管字节，授权分别保存 |

“共享到会话”沿现有文件操作、会话选择与版本化保存，不建立独立权限管理页面。保留已有群共享入口及旧`sharedKnowledgeIds`语义，迁移完成后仍使用上述交集。群中新加入的员工还需自身绑定该资料才可读；移出群立即失去该群使用资格。共享给某个群表示允许用于该群当前成员可见的答复；群成员变更不把授权复制到其他群。渠道会话的身份/授权变化按原来源门禁使旧快照失效。

把会话文件设为知识资料是明确的保留授权；常规清空来源会话不撤销这项保留。若发生明确材料授权撤回、员工解绑、知识资料移除或接收方权限变化，受影响检索、读取、运行快照和派生记忆必须按当前来源关系失效。实现需区分“清理原会话”与“撤回使用权”，不能让清理误删知识资料，也不能借副本绕过撤权。

员工可查阅不代表自动分享：模型上下文装配、工具读取和最终对外发布均沿原上下文权限核对。任何已经公开的历史回复不会因撤权被伪称从未出现；原生会话兼容性与记忆失效仍须处理后续使用。

### 3.3 与目录授权的关系

知识资料属于宿主明确提供的参考输入，复用现有只读材料投影或受控工具。后续[05目录授权设计](./05-员工工作范围与目录权限设计.md)继续使用这条路径；API员工通过Mastra Workspace/工具读取，本机员工通过其原生执行环境或产品工具读取，群聊不改变当前执行员工的归属。资料授权不自动授予原文件所在文件夹；需要直接访问其他目录时按员工权限申请或自动授权。授权目录中的文件也不会全部自动收录为知识资料。

用户外部原件不受知识资料移除、员工删除或应用清理影响。员工删除只撤销其资料绑定并按受管引用和归属清理；同一内容被其他合法引用使用时不能误删。备份保留知识资料配置、受管内容和必要来源关系，排除任意外部文件夹；恢复不重新读取外部来源或自动运行模型。

## 4. 检索、引用与更新

1. 复用既有本地文本检索、材料读取、成果核源及全局预览。首版至少使Markdown/TXT的添加、相关检索、完整读取、更新与引用形成闭环；不以此功能引入向量库、embedding或OCR工程。
2. 当前可导入/预览的其他格式可按原能力保留，正文检索、原件读取与仅可预览分别表达。PDF/Office复用现有已验证能力；没有正文不能伪造提取或“已读”回执，预览成功不等于模型已理解。
3. 普通有资料需求的问答和任务均能发现获准资料，支持按相关性检索和明确文件引用。不能强制把问答变成文件Work才能查资料，也不把全部知识资料每轮拼入系统提示。
4. 相关结果带资料身份、实际内容版本/hash与可定位片段；答案引用实际读到的文件。目录命中、搜索摘要和全文已读分别记录，无法读取时如实说明。
5. 更新后新请求读取当前版本；已捕获旧内容的受影响运行按现有版本/来源失效规则处理，不把同一次回答中途混成两个版本。与该资料无关的运行不应全部作废。
6. 同名资料、内容冲突、旧版本和本轮用户新材料不能靠“知识资料优先级更高”机械覆盖。按明确工作规则和真实时间/来源处理；无法确定时指出冲突。服务层核对引用与权限，模型负责相关性和内容判断。
