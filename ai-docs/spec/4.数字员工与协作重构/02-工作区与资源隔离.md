# 工作区与资源隔离

2026-10-18现行设计见[05](./05-员工工作范围与目录权限设计.md)及[06实施计划](./06-工作范围实施计划与验收.md)：用户授权业务目录后可正常访问，其他目录可申请，完全访问自动授权。授权目录不是唯一cwd，群中仍由各员工执行；本篇受管存储布局保持。此前目录外一律拒绝的草案已被替代，当前仅文档。

日期：2026-09-27  
任务：B2  
状态：**B2 已实施**。WorkspaceService、近端文件检查、资源导入和记忆模块已落地，数据路径不变；S1 新环境计划见[交付记录](../2.已实现功能与代码现状/15-B1-B2-S1-F1首批重构实现.md)。

本设计把已有 AgentHomes、资源导入、路径检查和产物策略组织到清楚边界，保留 [员工系统文件规范](../1.产品与架构基线/11-员工系统文件与Mastra适配.md)。源码目录迁移不等于用户工作区迁移，也不自动增加更强的系统隔离。

## 1. 当前真实路径

数据根由 Main 选择为 `app.getPath('userData')/v2`；开发/验证可通过已有 `BOAI_DATA_DIR` 指定隔离根。以下 `data/` 表示这个 v2 根，不是另一份新增目录。

```text
data/
  boai.sqlite
  data-version.json
  credentials.enc.json              Main 管理，不进入业务备份
  agents/<agentId>/
    workspace/
      AGENTS.md、SOUL.md             用户可编辑的规则与风格源文件
      IDENTITY.md                   员工资料生成视图
      USER.md、MEMORY.md、memory/    profile 范围生成视图
      skills/<skillName>/            员工专属导入技能
      private/                      已建立目录，不是默认模型工具入口
      sessions/<conversationId>/
        work/                       员工在本会话的持续工作文件
        runs/<runId>/               本次阶段/任务目录，命令默认 cwd
        USER.md、MEMORY.md、memory/  本会话范围生成视图
    state/                          manifest、pending-update、冲突副本
  workspaces/<conversationId>/       当前会话共享目录
    artifacts/                      显式发布的产物
  skills/<resourceId>/<skillName>/   通用导入技能副本
  knowledge/<resourceId>/<file>/     导入的 Markdown/TXT 副本
```

依据：[Main 数据根](../../../src/main/main.ts)、[AgentHomes](../../../src/runtime/modules/workspaces/workspace-service.ts)、[资源导入](../../../src/runtime/modules/resources/local-resources.ts)。同一员工的完整主目录长期存在，但提供给模型文件工具的 `self:/` 是本会话 session，而非整个主目录。

## 2. 当前隔离与限制

| 对象/能力 | 当前约束 | 不能据此推导的能力 |
| --- | --- | --- |
| 普通聊天、参与判断、记忆整理 | 引擎不挂载文件、检索、技能或命令工具 | 不代表模型推理离线，也不代表宿主未准备 session 目录 |
| 员工文件工具 | `self:/work`、`self:/runs`，拒绝系统文件、越界和符号链接 | 不是完整员工主目录的自由访问 |
| 共享文件工具 | `shared:/` 只读；完成文件通过 publish_artifact 显式复制 | 不是所有员工私有草稿自动共享 |
| 技能 | 只加载绑定资源，通过受限 SkillSource 读取；同名冲突拒绝 | 不自动安装 Python/npm/系统命令依赖 |
| 群知识 | 产品层取员工绑定 ∩ 群共享 | 群勾选某资料不等于所有成员都获准使用 |
| 知识检索 | 本地 Markdown/TXT 关键词片段与来源 | 尚无 PDF 解析、embedding 或向量检索 |
| Shell | allowCommands 开关、每次明确审批、固定 cwd、环境白名单、超时/输出上限和取消 | **没有操作系统沙箱、网络隔离或宿主文件系统强制隔离** |

当前命令用宿主用户权限启动 shell；工作目录只指定起始位置，不能限制获批命令读取、写入其他目录或访问网络。Electron renderer 的 sandbox 和 utility process 分离也不构成 Agent 命令沙箱。依据：[命令执行与文件工具](../../../src/runtime/adapters/mastra/engine.ts)。

B2 必须保留并准确说明这一边界。后续接入方案已单列为 [Sandbox 文件系统与 Skills（S1/S2）](../5.Mastra能力扩展/03-Sandbox文件系统与Skills.md)，包含授权映射、依赖、网络和本地执行模式；不能把 WorkspaceService 重命名为 SandboxService 后声称已经隔离。浏览器登录状态与外部 Agent 自带工具还有各自的边界，分别见 [Browser](../5.Mastra能力扩展/04-Browser浏览器能力.md) 和 [执行后端](./04-员工执行后端与能力契约.md)。

## 3. 建议 WorkspaceService 边界

建议放在 `runtime/modules/workspaces`，最初可由现有 AgentHomes 加一层清楚的入口构成；不要求立即写很多类。

| 责任 | WorkspaceService / 产品层 | Mastra adapter |
| --- | --- | --- |
| 路径规划 | 根据员工、会话、run ID 产生固定 session/work/run/shared 路径 | 只消费，不接受模型传入绝对根 |
| 系统文件 | 初始化、检查、hash 冲突、恢复日志、bootstrap 和生成视图 | 使用宿主提供的 bootstrap，不遍历源目录重读 |
| 资源授权 | 计算绑定、所有者和群共享交集，形成运行授权快照 | 挂载获准技能；实际读写前再次做路径检查 |
| 产物发布 | 检查本次运行有效性、归属和登记路径 | 工具入口把一个明确文件复制发布，失败撤回新副本 |
| 文件操作 | 可提取共用的安全路径/复制/读写函数 | 保留 SDK tool schema 和结果转换 |
| Shell | 审批状态、run 有效性与 cwd 归属 | 调用现有受控宿主执行器，传递 abort 与限制 |

不要在 WorkspaceService 再保存第二份员工、资源或记忆数据库。它接收明确的 ID、版本和授权输入，返回路径/bootstrap 或操作结果。`Resource` 的登记、绑定关系与撤权仍由 resources/employees/conversations 用例拥有。

实际操作检查必须留在离 I/O 最近的位置。预先算好授权路径不应替代 `lstat/realpath`、符号链接拒绝、普通文件检查、`O_NOFOLLOW` 等已有检查。不能先验证某目录后，后续直接信任任意模型字符串拼接。

## 4. 系统文件与记忆

AGENTS.md/SOUL.md 是用户源文件；IDENTITY/USER/MEMORY 及每日 memory 文件是产品状态投影。Markdown 的内容不能提升工具权限、覆盖宿主规则或作为另一套记忆真源。

- 源文件保留 hash、configVersion、pending-update 和 manifest，支持文件/SQLite 更新过程中退出后的恢复。
- 生成视图检测到外部修改时继续保留并提示；只有显式重新生成才先保存冲突副本后覆盖。B2 不改变该策略。
- bootstrap 从当前员工身份、规则、风格和有效记忆构成；普通群运行不遍历根 `private/` 或其他 session。
- profile 是用户显式跨会话资料；模型学习记忆只归员工＋会话。记忆源消息/资源、epoch 与删除标记仍在 MemoryRepository 校验。
- 有来源的记忆和上下文随撤权失效；不能因为磁盘上还有 MEMORY.md 投影，就再次把旧事实送给模型。

现有实现见 [AgentHomes](../../../src/runtime/modules/workspaces/workspace-service.ts)、[MemoryRepository](../../../src/runtime/modules/memory/memory-repository.ts)、[上下文与撤权处理](../../../src/runtime/service.ts)。

## 5. 导入、绑定与共享

资源导入是受管理副本，不是直接把用户原目录当可写挂载。Main 保留文件选择器授权；runtime 严格验证资源类型、目录树与技能 frontmatter。

通用技能仍按 `skills/<resourceId>/<frontmatter-name>` 保存，专属技能仍位于所属员工 `workspace/skills/<name>`。name 必须是安全简单目录名，物理目录和声明名称一致。同员工绑定同名技能时明确拒绝，不依靠加载顺序碰运气。

运行时只发现登记并绑定的技能，不能因存在 `workspace/skills` 就自动加载里面所有文件。导入新的技能也不自动向全部员工授权。

工作文件默认留在员工当前 session。发布时只复制一个明确文件到当前会话共享区，分配产物 ID，登记 ownerAgentId/runId/sourcePath，再把产物关联到最终贡献。复制成功但登记失败或运行已取消时，必须清理新复制文件，不能返回虚假的“已共享”。

资源删除/解除绑定/移除成员是用例级动作：取消相关运行、撤销后续授权，排除依赖失效快照的历史上下文，并使派生记忆失效。已有公开消息和历史产物不因重构被物理删除；保留审计事实不等于继续用于新的模型上下文。

## 6. 迁移、备份与打包

本组重构**不改变 v2 数据根、目录布局、资源 ID、工作区相对引用和 SQLite collection 名称**。AgentHomes / ProductStore 的源码移动不触发新的用户数据迁移。

继续保留：

1. v0.1 → v2 的独立一致副本和版本 marker；旧版本后续写入不影响 v2。
2. 导入资源、共享目录、artifact.path/sourcePath 的恢复重定位。
3. 备份包含 SQLite、agents、resources 对应目录和共享 workspaces；不包含模型密钥文件。
4. 有活跃或等待任务时拒绝备份并说明先停止；不为备份默默取消用户任务。空闲时短暂关闭写入入口，生成一致快照与文件副本。
5. 原数据保留，异常中断后不重放命令；恢复需要的 manifest、pending-update 和源文件一同保留。

当前实现见 [数据根迁移](../../../src/main/migration.ts)、[备份与重定位](../../../src/runtime/service.ts)、[SQLite 快照](../../../src/runtime/adapters/storage/product-store.ts)。

打包验证继续覆盖 native SQLite、Mastra 技能文件读取、可写用户目录和 shell 子进程。当前运行依赖宿主环境；B2 不承诺所有平台都内置 Python/Node/第三方库。跨平台发布应记录实际验证的平台和技能依赖，不用单个 macOS 用例代表所有系统通过。

## 7. B2 验收

- 已有员工规则、风格和各会话工作文件原样可读；丢失源文件不被默认值覆盖。
- 同员工两个群、两个员工同群分别测试：self 路径互不混入，共享区只暴露明确发布产物。
- 路径穿越、符号链接、系统文件写入、其他 session、shared 直接写入仍被拒绝；合法当前 session 文件读写正常。
- 未授权技能/知识不能使用；同名技能冲突可解释；Markdown/TXT 检索保留来源。
- 命令批准、拒绝、取消等待、超时、输出限额和环境密钥排除保持原行为；文案不宣称强沙箱。
- 资源撤权后，旧运行与迟到事件不能发布，相关派生记忆和后续上下文失效；历史产物仍可查看。
- 备份恢复到不同数据路径后，员工目录、技能名称、共享文件及来源路径仍正确；退出/升级不重放。
