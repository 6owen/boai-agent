# 员工执行后端与能力契约

2026-10-05 当前入口：受控本机ACP已能真实启动并执行单聊显式任务，仍为fresh session、未知用量，尚非完整员工。进一步的产品交互、具名驱动、连续会话与Work接线转入[第13组](../13.本机Agent员工运行时/README.md)，该组06唯一维护新实施进度，当前已增量接入原生Codex，具体范围与验收以该组06为准。本篇继续拥有通用阶段、权限和完整/任务型/显式混合三路径不变量；下面历史状态不代表当前全部能力。

> 2026-09-27 实施更新：本轮已交付的范围和验证以 [主题、外部 Agent 与自动化实现](../2.已实现功能与代码现状/16-主题外部Agent与自动化实现.md) 为准。下面保留规划时的基线与后续目标；“尚未实现/待实施/当前没有”等描述指规划当时。
日期：2026-09-27。阶段：E1 / E2 / E3。状态：**待实施设计**，不是 B1 的纯结构重构，也不是当前已经可选的执行方式。

目标：数字员工除用户配置模型连接（BYOK）外，也可以选受支持的本地 Agent / ACP 后端；远程 A2A 员工作为可选扩展。产品身份、会话、权限和记忆仍由 BoAI 管理，执行后端按能力接入，不强迫所有外部 Agent 模仿同一个内部实现。

## 1. 当前事实与术语

当前 [MastraEngine](../../../packages/runtime/src/adapters/mastra/engine.ts) 只构造普通 Mastra Agent，使用 [Connection / DigitalAgent](../../../packages/shared/src/domain/index.ts) 中的模型连接和 modelId。OpenAI-compatible 连接允许 localhost 和空 key，因此**本地模型 HTTP 端点**可以沿用这条路径；这不等于支持本地 Agent 进程。

| 选择 | 实际接入对象 | 谁持有 Agent loop / 工具 | 所需配置 |
| --- | --- | --- | --- |
| Mastra + 模型连接 | 云端或本地模型推理 API | 本产品的 Mastra Agent 与宿主工具 | provider、baseURL、模型 ID、必要凭据引用 |
| ACP 本地 Agent | 实现 ACP 的本地可执行程序 | 外部 Agent 自己的 loop，部分能力可通过协议交给客户端 | 已验证的命令/参数、协议/桥接版本、会话和权限策略 |
| 受支持本地 Agent SDK/CLI | 某个有明确适配器的 SDK 或程序 | 外部运行时 | 适配器专用配置；不是任意 shell 文本 |
| A2A Agent | 网络上的 Agent endpoint，可位于本机服务 | 对方服务的 loop、工具、存储 | Agent Card / 执行地址、版本、身份凭据和网络策略 |
| MCP 连接 | 工具、资源、提示词或包装成工具的能力 | 员工仍需自己的执行后端 | MCP server 配置；属于能力连接，不是模型 provider |

“本地”应分别描述进程位置、数据位置和模型推理位置。本地 Agent 可能调用云模型并使用自己的登录态；ACP 不提供免费模型，也不把外部订阅或登录转换成 BoAI 的 BYOK key。

非 ACP 的本地 Agent 也不必一概自行包装 CLI。Mastra 官方另提供 SDK adapter 路线：`@mastra/claude` 的 `ClaudeSDKAgent`、`@mastra/cursor` 的 `CursorSDKAgent`、`@mastra/openai` 的 `OpenAISDKAgent`，由提供方 SDK 继续持有自己的 runtime、工具、权限与 Agent loop。它们可作为 `local-agent` 的具体适配器候选，仍须验证阶段能力，不能当作普通模型连接。当前这些包及其所需 provider SDK 均未在本项目接入，须在选定后核对真实安装情况、peer dependencies、具体 API 和执行模式。[安装 SDK agents 说明](../../../node_modules/@mastra/core/dist/docs/references/docs-connections-sdk-agents.md)、[官方 SDK agents](https://mastra.ai/docs/connections/sdk-agents)。

其中 OpenAI Agents SDK 不等于 Codex CLI；Cursor 的 local 模式需要显式模型配置。本文没有选定任何示例模型或启动命令，也不保证任意非 ACP CLI 都能通用接入。

## 2. 执行方式是判别配置，不是新增 provider 字符串

E1 建议新增带类型标识的 `executionBackend` 配置概念，保留旧字段迁移路径。以下为产品草案，不是已实现类型：

| kind 草案 | 配置引用 | 不应保存的内容 |
| --- | --- | --- |
| `mastra-model` | model connection ID、可选员工 modelId | 明文 key、活跃 SDK 实例 |
| `acp-local` | launch profile ID、adapter/version、会话策略、可选对方 model ID | 任意自动执行的 shell 字符串、整个环境变量、活跃 session 对象 |
| `local-agent` | 已支持 adapter ID、实例配置引用 | 通过猜测 stdout 伪造统一协议 |
| `a2a` | agent-card endpoint ID、协议版本、凭据引用 | 从远端 card 直接获得的本地权限 |

`launch profile` 将 executable、参数数组、版本和运行环境策略与员工身份分开。保存配置不自动安装、运行、登录、发送测试任务或扫描其他项目凭据。外部程序的模型选择使用其会话实际公布的 ID，不把现有 `provider/modelId` 强行拼入 ACP 模型选择。

旧员工没有 backend 字段时，明确迁移为 `mastra-model` 并保留原连接、模型和 ID；配置版本递增、有备份和回退说明。B1 可以先整理现有工厂边界，但不因此假称已经完成 E1。

## 3. 能力协商：声明、核验与本次策略取交集

不能仅以 `stream()` 存在或对方自报“支持工具”判断兼容。适配器记录 `supported / unsupported / unknown`，附协议、程序、适配器版本及核验依据；未知不视为支持。每次连接初始化后比较能力，升级/切换程序、账户、模式或配置后使旧核验失效。

| 能力维度 | 要核验的具体问题 |
| --- | --- |
| 阶段 | 能否分别执行 decision / chat / task / memory；哪些需要单独会话或额外模型 |
| 输入控制 | 能否接收宿主身份规则、署名消息、明确本轮边界；是 system 级设置还是普通 prompt 背景 |
| 私有结构化输出 | 能否稳定遵守 decision JSON / memory candidate schema；是否支持有界纠正；不能仅因 JSON-RPC 传输就认定支持业务 JSON |
| 无工具运行 | decision/chat/memory 能否真正禁用所有外部工具及自动副作用，而不是只在提示词里请求不调用 |
| 工具归属 | 宿主工具、协议介导工具、外部私有工具分别是什么；哪些能逐次批准/拒绝 |
| 工作区和 Skills | 哪些文件操作经过宿主；外部是否自己发现技能/规则；能否限制当前员工×会话范围 |
| 会话隔离 | 能否创建独立 session、恢复、重置和删除；外部全局记忆/缓存能否隔离或明确关闭 |
| 流和终态 | 能否区分回复、活动、思考、工具、产物与最终结果；截断、拒绝、断线分别如何表示 |
| 取消 | 协议取消、外部执行确认、进程终止、远端任务状态查询是否可用 |
| 预算和用量 | 能否限制内部模型请求/步骤；报告的是每次 token、累计费用、上下文大小还是未知 |
| 产物 | 返回内容、文件或 URL 的来源、可访问范围与发布规则是否可校验 |

协商值不是永久授权。有效能力还需与当前成员资格、资源绑定、任务范围、用户批准和执行策略取交集。协议声称可读文件，不代表允许读取员工全部私有目录。

## 4. 按阶段接入，缺能力不能伪装自主 pass

| 阶段 | 本产品要求 | 外部后端不满足时 |
| --- | --- | --- |
| decision | 工具关闭；只决定自己的 reply/pass/wait/ask/handoff；合法 JSON、成员/来源检查；宿主提供观察序号 | 标为不支持自主参与或判断失败；不转换成 pass，不默认 reply，不用中央模型替所有员工选发言者 |
| chat | 无工具、当前用户请求优先；可辨认最终公开回复 | 不启用自动聊天；不能把外部任务执行伪装普通问候 |
| task | 已授权工作；有效权限边界、取消、可追踪结果 | 清楚展示外部边界；不符合任务所需策略则拒绝启动或要求切换后端 |
| memory | 当前轮证据、私有候选、来源/epoch 校验；无工具 | 显示此后端未开启自动记忆整理，保留现有记忆；不保存普通文本或把外部记忆全量导入 |

允许三种**明确配置**的产品用法：

1. **完整员工后端**：适配器通过所需阶段核验，可参加原有自主群聊。纯 ACP 员工可以不需要 BoAI 的模型 key，前提是 ACP 自己具备已验证的阶段能力和登录条件；不是所有 ACP 程序默认满足。
2. **仅任务型外部 Agent**：先接收用户明确交付的任务，或作为获准员工的任务能力。界面明确它不支持群内自主判断/普通聊天；这是 E2 的待实现调用路径，不能把它悄悄塞进现有自动群调度后失败静默。
3. **显式混合后端**：用户为该员工指定一个控制阶段后端，承担 decision/chat/memory，任务交给外部 Agent。仍是该员工独立决定，记录每个阶段实际使用者、费用和数据发送范围；不得未经配置悄悄使用另一把 key 或另一个员工判断。

优先开放仅任务型接入，验证外部边界后再开放完整员工。支持完整后端时不必额外强加一个父 Mastra 模型；`AcpAgent` 可通过适配层直接调用，Mastra supervisor/tool 委派是另一种可选组合。详见 [连接核对](../5.Mastra能力扩展/05-ACP与A2A及MCP连接.md)。

## 5. 状态与输出契约

建议后端输出标准化为：文本消息/活动、工具事件、权限请求、产物候选、已报告用量、终态及外部 session/task 引用。它们进入 runs 的转换层，不直接写产品会话或 MemoryRepository。

运行结果需要区分 `completed`、`failed`、`cancelled`、`interrupted`、`unsupported`、`auth_required`、`input_required`、`budget_exhausted` 等语义；最终产品字段由实现阶段确定。`pass` 只能来自合法的员工 decision，不是连接失败、能力缺失、超时或权限拒绝的替代状态。

- `agent_thought_chunk` 等推理事件不进入公开正文或记忆；工具/计划进展放活动视图。
- 能输出 text delta 不代表每段都是最终答复。当前 Mastra ACP 封装文档会映射 Agent message chunk 为 text-delta；外部程序能否区分中间说明和最终消息必须单独核验。
- 无可靠最终边界时，保留外部运行报告与状态，不拼出一条看似最终的员工回复。需要补充总结模型时必须显式配置并计入预算；不以偷偷补一次 BYOK 来掩盖不兼容。
- 外部产物进入宿主受控校验/复制/登记路径后才发布；路径和 URL 不是跨目录或网络访问的授权。
- request/run/session/task ID 和 generation 关联到本次员工×会话×阶段。旧 session 重播、迟到回复和取消后的事件不得提交到新轮次。

## 6. 会话、进程、凭据与权限

### 会话隔离

ACP session 与产品 Conversation 不等价。建议至少按员工、会话、backend config version、阶段隔离；decision/memory 的私有协议不复用公开 task 的长期 transcript。先采用受控的新会话/进程策略，再有证据地复用任务会话。

进程重开不保证外部全局记忆清空；`cwd` 不保证外部凭据、插件、自动发现文件或用户配置隔离。外部会话数据需要列明保留位置、所有权和删除能力。不支持删除的后端要如实显示限制，不能把删除 BoAI 记忆说成同时清除了外部日志。

### 凭据与进程

本地主进程管理 executable/参数与启动策略；通过参数数组启动，不执行由聊天文本拼接的 shell 命令。限制进程数量、单会话并发、运行时间和输出大小；清理自己启动的进程及其受管子进程，不按进程名终止用户其他任务。

仅注入明确允许的环境项和本后端凭据。ACP 文档的 `env` 是与宿主环境合并，不能假设传空对象就清空继承；具体包尚未安装，实施时必须检查真实 spawn 行为，必要时由隔离的 launcher/执行进程承载。对方使用既有 CLI 登录态时由用户明确选择，不能扫描其他项目的 `.env` 或把全部宿主模型 key 传过去。

### 权限与工具

宿主可控制的是自己实现的 ACP filesystem/terminal/MCP 桥接操作与收到的 permission request；外部进程还可能直接访问主机文件、网络和自己的工具。Mastra Workspace 与 ACP 客户端能力不是操作系统沙箱。

界面应标明工具控制范围：宿主管理、经协议介导、外部自有/不可观察。`allowCommands=false` 只有在适配器确实拦住外部执行时才具有同等语义；否则该后端不满足此策略。需要强隔离时依赖经过验证的 OS/container/沙箱方案，不能仅设置目录或要求对方自觉遵守。

Skills 和知识库不自动跨运行时互通。明确区分“绑定在 BoAI 的技能”与“外部 Agent 自带技能”。移植前先验证格式、发现范围、指令权限、资源引用和实际执行；未适配时显示不支持，不向用户宣称已启用。

### 取消与预算

发送取消、关闭本地流与对方停止执行是三件事。先协议取消并处理待审批请求，等待明确终态；本地受管进程超时后按策略终止。远端任务无法强杀时标为取消待确认/状态未知，继续阻止其迟到结果公开提交。

外部一次 prompt 可含多轮模型与工具调用。记录 `externalInvocations` 等真实调用单位，不把“一次 ACP 调用”冒称“一次 LLM 请求”。未知 usage 保持未知；上下文窗口 used/size 不能当作本次 output token。严格 token/内部步骤限额无法执行的后端不得宣称符合该预算策略，可使用有明示边界的时间、外部请求数和输出限制，或禁用自动运行。

## 7. 实施阶段与退出条件

| 阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| E1 执行后端契约 | 判别配置、能力状态、阶段路由、旧 BYOK 兼容、版本和错误语义 | 原员工无行为变化；本地模型仍走模型 API；未知能力不误判为 pass；配置保存不启动外部程序；能力不满足时可解释 |
| E2 ACP / 受支持本地 Agent | 锁定一个具体适配器/程序版本，先明确任务调用，再评估完整员工 | 握手、隔离、权限拒绝、取消、进程退出、断线、产物和未知 usage 全部通过；实际核验每个开放 phase；混合后端明确配置；重启无自动重放 |
| E3 A2A 远程员工（可选） | Agent Card、认证、协议版本、远端 task 映射与恢复 | 远端状态/取消/认证失效/能力变化可追踪；数据发送范围可见；远端私有工具不伪称宿主可控；不会替换本地群调度 |

E1 的配置与能力契约依赖 B1，可先行确定；E2 的实际运行与隔离接线依赖 B2。受限文件和 Skills 读取依赖 S1，命令/脚本执行依赖 S2，自主群聊接入还依赖 B3 的阶段运行/状态处理；不把 E1/E2 算作 B1 的内部移动文件工作。与 BR1/C1 的浏览器/MCP 扩展协调推进，定时自动化仍是独立路径。

专项验收至少覆盖：

- 相同程序的两个员工、同员工两个群、私聊/群以及 decision/task 的 session 不串；旧历史不会替代当前 turn。
- 非 JSON、缺字段、普通问候、截断、认证失败、能力未知和无控制后端分别落到正确状态；不强制回复或静默 pass。
- 外部直接工具能否绕过策略必须实测；若无法限制，按实际能力降级，而非仅通过“批准回调收到了请求”就认定安全。
- 取消后仍到达的流、session replay、崩溃后重连不会重复公开消息或产生自动副作用。
- 手动和自动记忆仍走产品权威；外部自身记忆不能绕过来源/epoch/撤权。

## 8. 依据和未完成验证
