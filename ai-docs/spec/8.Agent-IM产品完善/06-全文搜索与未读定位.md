## 两种搜索入口

会话列表搜索扩展为可区分“会话名称 / 消息 / 文件”的全局搜索入口；聊天标题菜单提供“搜索本会话”。首批采用确定性文本匹配，不把语义搜索作为前置依赖。

输入关键词后展示类型分组或清晰类型标记。支持会话、员工、日期筛选；查询条件、结果游标和选中项属于当前页面，不能在用户切换后把迟到结果写入另一页。

| 类型 | 搜索范围 | 结果展示 | 点击行为 |
| --- | --- | --- | --- |
| 会话 | 会话标题 | 标题与成员 | 打开会话 |
| 消息 | 已公开的 `completed` 正文 | 发言者、时间、命中片段、会话 | 定位稳定消息身份 |
| 文件 | 已发送材料/已登记成果名称；元数据用于展示及核对，不承诺全部参与关键词匹配 | 文件名、版本、所属会话 | 打开明确文件详情 |
| 文件正文 | 已发 TXT/Markdown 与已登记文本成果 | 有界摘录、正文偏移、覆盖与失败回执 | 打开所选固定版本/hash，失效不展示旧正文 |

## 定位与结果有效性

结果附加稳定实体身份，不以当前列表行号定位。打开时再次核对数据是否仍存在和可访问；不存在则说明“这条内容已被清理或不可用”，不跳到相似文本的另一条消息。

高亮实际命中片段并允许回到结果；新消息到来不覆盖用户主动定位。长消息、折叠内容与附件引用应能定位到正确卡片，不能因为虚拟列表只加载当前区域而宣称不存在。

## 未读语义

持久阅读位置按会话保存。首批建议以消息完成事件/稳定排序为依据；流式消息开始不代表已读，离开后完成仍可成为未读。用户自己的新消息、系统状态更新和 Agent 的完整回复应按明确规则区分，不能把所有事件都计为未读消息。

进入会话本身不把全部标为已读；消息可见且用户正在该会话阅读时推进到连续阅读边界。用户停留在历史位置时保持边界，不因底部新消息到达自动滚动或清零。提供“返回未读”和必要的显式“标为已读”操作；后者只改阅读状态。

| 场景 | 预期 |
| --- | --- |
| 页面隐藏后有员工完成回复 | 保持未读，不主动切页 |
| 用户在历史位置查资料 | 新消息提示但不抢滚动 |
| 同条消息继续流式更新 | 不按每个 token 累加未读 |
| 点击搜索结果 | 定位目标，不隐式把其后的消息全读完 |
| 清空聊天 | 清理阅读位置及索引，保留必要的业务去重边界 |

## 索引与性能

优先复用现有持久层，建立可重建索引；SQLite FTS 或其他具体实现需核对当前运行版本后选定，不在正文承诺已接入。数据库内容是权威，索引失败显性化，不能使消息提交失败后留下可搜索的幽灵记录。

采用有界查询、稳定分页与输入防抖，取消旧请求或按查询身份丢弃迟到结果。索引回补不调用模型、不重放工具；聊天删除后立即禁止搜索读取，物理索引清理允许沿已有可靠清理流程完成。
