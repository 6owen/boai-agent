# 实施阶段与验收矩阵

更新：2026-10-02。首批已实现子集以第 10 组 05 与第 2 组 28 的实际证据为准；本表保留尚未覆盖的通用目标。IM-05 独立待处理页退役，当前聊天入口定向验收完成、原姓名提及基线失败保留，旧页成绩不能代替新入口。

2026-09-30 优先级更新：下一阶段以 [第 9 组 T1 实施清单](../9.团队创建助手/08-实施步骤与交付清单.md)为主。本文件的阶段一至三和 S0–S6 保留为本组内部推进顺序，不要求全部完成后才能创建团队。IM-07 的通用创建部分复用第 9 组，首次真实成果验收仍在本组；两者完成口径分开。

## 1. 实施顺序与阶段门槛

### 阶段一：完成可验收的工作闭环

范围：IM-01 至 IM-04。

先核对现有失败样本和权限真实状态，明确验收任务及预算；再接入材料、成果和必要工具。开发过程持续用同一个场景验证，不等待所有格式、连接器和预览类型完成才集成。

- [ ] [产品定位文档](./00-产品定位与用户旅程.md)中的首个场景从真实材料走到最终成果、修订与用户采用。
- [ ] 来源、产物版本、审核对象、工作身份和预算能相互核对。
- [ ] 停止、撤权、重启、数据清理及备份恢复符合现有边界。
- [ ] 未支持格式、外部后端限制和未知用量明确显示。
- [ ] 相关静态检查、模块测试、Electron BDD 与真实质量验证分别留有结果；未验证项不计通过。

### 阶段二：降低日常管理负担

范围：IM-05 至 IM-08。IM-08 所需的基础观测沿用现有账本，不能等阶段二才开始保存阶段一的必要证据。

- [ ] 用户离开一段时间再回来，能从原聊天问题/审批卡片和成果文件找回阻塞事项与成果。
- [ ] 能通过正文搜索或未读位置找回上下文，完成处理后状态一致。
- [ ] 新用户能通过一个可运行模板完成真实任务。
- [ ] 能查看该任务的用量，并依据同场景评估判断协作效果。

### 阶段三：按真实需求扩展

候选范围：扫描 PDF/OCR、Word/Excel、邮箱/日历/知识库/代码仓库连接、浏览器操作、经过验证的执行隔离，以及群置顶目标/已确认结论等长期上下文入口。

每次选一个高频场景，先写清用户收益、现有能力差距和验收标准，再接入对应工具。涉及发送、提交或发布的动作沿用明确授权与可检查预览；不因接入连接器而获得默认外部写入权。

## 2. 保持的边界与暂不做的事项

- 继续采用本地 Electron 架构和现有 Mastra、SQLite、IPC、工作与预算体系；不另建平行聊天、调度、记忆或预算真源。
- UI 展示层不能替代宿主持久化与授权；跨页面详情隔离、草稿和滚动保持现有规约。
- 附件、产物版本、采用记录等新数据先明确身份、归属、迁移、清理及备份合同，再写界面。
- 普通聊天不产生 Work；运行完成、业务交付、人工采用与通知回执分别保存。
- 已交付、人工停止和操作结果不明的工作保持既有边界；重启不自动恢复模型调用或重放工具。
- 应用退出、设备休眠或关机期间不承诺执行；常驻宿主属于单独部署范围。
- 暂不强制经理角色、多层组织结构、独立讨论串、通用可视化工作流、更多技能市场或音视频会议。
- 多人账号、云同步与移动端在目标用户明确后单独规划；外部分发时另行完成签名、公证、安装升级和恢复验收。

## 3. 测试、证据与完成定义

模块、持久化和模型协议使用现有 Vitest；桌面场景沿用 playwright-bdd 的 features/steps/support，不新增平行桌面测试入口。真实模型评估沿用[评估集方案](../6.Cumora协作重构/09-多Agent测试体系与评估集方案.md)，执行前明确版本、任务、预算和门槛，不借新增功能放宽旧合同。

按变更运行项目规定的类型检查、UI 规则、相关模块测试、构建与 Electron 流程；涉及宿主、资源协议或分发时增加实际应用包验证。真实模型调用和用户试用分别留证，不能由离线测试代替。

每项目标完成需同时满足：

1. 该项目标的首批范围与验收清单通过；部分完成时保留未完成项。
2. 现有业务断言和数据边界未回退，失败、证据不足与待评审如实记录。
3. 实现、文件 Header、所属目录地图及受影响规格同步。
4. 在[已实现功能与代码现状](../2.已实现功能与代码现状/README.md)记录真实改动、验证结果和限制，并回链本文。

产品试用记录首次产出时间、成果采用情况、返工次数、人工介入、已知/未知用量和中断原因。正式门槛在实验前登记；尚未收集的数据不填写示例成绩，不因样本少就宣称稳定。

## 6. 最小交付切片与依赖

| 切片 | 范围 | 退出条件 | 之后才能打开的范围 |
| --- | --- | --- | --- |
| S0 | IM-01 基线与权限真实状态 | 固定失败样本、完成条件、预算与真实权限 | 后续增量依据同一基线比较 |
| S1 | IM-02 的 TXT/MD 与附件消息关联 | 导入、授权、发送、引用、清理/重启通过 | 再增加 PDF/图像解析，沿同一合同 |

| S3 | IM-04 必要工具与依赖检查 | 一个真实网页能力链验证，失败与取消可见 | 不直接宣称全 MCP/浏览器可用 |
| S4 | P0 场景联调 | 材料到报告、审核、修改、采用全链通过 | 可运行模板与扩大用户试用 |
| S5 | IM-05/06 | 多会话事项处理、搜索/未读及清理一致 | 规模化日常使用 |

## 8. 每个切片的交付记录模板

实施时在第 2 组新增或延续对应实现记录，记录：目标/切片编号；改动范围；数据和接口迁移；实际执行的命令与结果；代表场景及证据文件；失败/未验证项；已知限制；下一步。本文进度表只链接这些记录，不复制一份可能过时的测试成绩。

设计提案放在本组 designs，运行截图放在实际实现记录对应证据目录。只有工具真正运行成功且业务断言满足时才勾选功能验收；“图片看起来正确”不能替代真实流程。
