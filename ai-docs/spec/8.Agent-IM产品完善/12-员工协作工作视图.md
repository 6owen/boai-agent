# 员工协作工作视图

更新：2026-10-05。**WV0–WV4完整代码和当前完整源码统一验收已通过；macOS应用包27/27独立通过。模块、源码、应用包及真实供应商/人工层级结果各自在13登记，历史批次不代替当前版本。** 已有聊天卡片、工作记录和文件预览继续按原专题记录。依据见[Raft/OAR源码与桌面调研](../../2026-10-05-Raft与OAR源码及桌面调研.md)，实施结果、场景编号和显性缺口唯一见[13 工作视图实施与自动验收](./13-工作视图实施与自动验收.md)。

目标：进入一个员工私聊或群聊，能自然地交流、看工作、找文件；离开某个聊天后，能从全局任务总览找到需要关注的工作；从通讯录能理解员工的职责、实际能力和当前负责的工作。

## 1. 本次范围与现有基础

| 范围 | 已有基础 | 本次补齐 |
| --- | --- | --- |
| WV-01 会话三视图 | 聊天流；右侧混合任务与产物；原材料/成果卡片；Markdown/Shiki预览 | 同一会话主区域的聊天、任务、文件；有界清单；视图状态保持；精确回原消息 |
| WV-02 全局任务总览 | 持久Work、负责人、父子/依赖、预算、结果和自动化来源 | 独立侧栏入口；跨会话看板/列表；宿主筛选分页；复用会话任务卡 |
| WV-03 员工资料概览 | 通讯录资料/编辑分离；配置、系统文件、工作区、记忆；能力核验 | 先呈现身份职责、实际能力、当前负责工作与发消息入口，再进入已有配置 |

Work是业务工作的唯一权威；Message承载交流和原业务卡片；Material是已发送材料；Artifact是已发布成果。三个视图只是这些对象的不同读法，不建立另一份Task表、员工私有任务库或交付状态。

本次不增加脱离聊天的新建任务表单、拖拽改业务状态、自动派单、经理工作台或通用工作流。OAR的多运行时、恢复与事件适配留作后续独立评估，不是本次视图改造的依赖。内置浏览器继续由[第11组](../11.浏览器能力迁移/README.md)维护，本次不增加浏览器配置入口。

主导航新增“任务”，现有“定时任务”保留。前者回答“现在有哪些工作”，后者管理计划及触发历史。任务总览是Work的浏览和导航入口；问题补充、审批、采用、稍后处理和修订仍在原员工聊天，不恢复独立待处理中心。

## 3. WV-01：会话中的聊天、任务、文件

### 3.1 同一会话的视图状态

已持久化的员工私聊、群聊、核心会话与自动化任务聊天采用同一组三视图，数据只取当前会话获准对象。核心会话的任务只显示本会话真实组织或执行工作，不变成全部员工的管理总览。未创建的空白核心聊天默认停留聊天，查看空页不得创建Conversation、消息或Work。

- 顶部常驻“聊天 / 任务 / 文件”，首次进入默认聊天，之后按会话记住所选视图；原会话标题、成员和已有菜单保留。
- 切换不改变会话身份；聊天草稿、附件草稿、明确问题/成果引用模式、稳定消息锚点及滚动位置保持。业务提交未知时仍保留原载荷/key，不因切视图变成新请求。
- 输入框在聊天视图使用；从任务或文件发起处理先返回聊天，定位原卡片或进入明确引用模式，不另设一套回复表单。
- 任务和文件各自记住筛选、滚动、选中对象；文件选择固定材料身份或成果版本/hash，不自动跳到新版。
- 隐藏视图暂停主动列表读取与聊天可见阅读观测。再次显示时核对当前事实；迟到成功和失败均不得覆盖另一个会话或新选中的文件。
- 打开文件、任务或切换标签不表示聊天已读、任务启动、用户采用或批准。跨主页面右侧标签仍按原作用域隔离，不借用隐藏页面的选择和草稿。

### 3.2 聊天视图

保持现有独立署名、流式回复、引用、附件和业务卡片。原审批卡允许/拒绝，原问题卡明确回复，原成果卡采用/稍后处理；“要求修改”绑定所见原版/hash和执行员工，复用同一输入框。普通发送不取消当前处理，也不因本次改造变成任务创建快捷方式。

原消息文件点击仍直接打开右侧预览。三个标签不取代这个日常入口，也不增加输入框上方常驻状态条或聊天标题栏阅读状态。

### 3.3 任务视图

默认按当前会话的根Work展示，展开真实子工作；结果依赖单独表达，不误作父子归属。每张卡显示工作目标、真实负责人、业务状态、来源时间、等待/失败原因和可核对结果入口。缺负责人、原消息或关系的历史数据明确显示未知，不按员工名、相似文本或最近消息猜测。

查看卡片并展开“工作详情”得到当前只读状态、已登记父子/依赖及结果证据；文件结果沿右侧固定版本预览，“查看原聊天”切到聊天视图并定位明确消息。起始请求、补充问题、审批和交付消息分别保留目标身份，不能把所有入口都定位到最新回复。当前审批固定所见approvalId/runId；员工正式回复尚未发布时定位该等待卡，发布后只定位同Run的明确正式消息。审批结束、运行切换或来源清理使旧审批目标失效，不改绑另一审批。其他目标失效同样明确不可定位，不恢复隐藏会话、不导航到替代消息。

自动化判断阶段task-ask、实际任务执行中WorkOutcome.waiting/userQuestion公开提问，以及没有Work的chat提问分别验证。新执行阶段合法问题须使原Turn进入waiting_user并让本次触发成为可明确补充的等待状态，不能只留下Work等待而让occurrence继续waiting_work。旧已公开执行问题可以沿严格Message/Run/Work关系只读兼容completed或同伴失败的Turn，不迁移原Turn，也不放宽启动中断、取消和当前授权门禁。回复固定原问题消息、所见occurrence版本、原来源和负责人；原Work问题的已回答消息与可接续状态/版本、本人补充消息和回执在同一事务提交。接续始终沿原Work/预算/绝对期限，不能只解除occurrence等待而让Work仍不可认领，也不能因新判断给出另一key而建立替代工作。依赖等待保持独立；一名员工的回答不能解除同轮其他员工尚未回答的问题。事务失败或回执未知沿原请求核对，普通发送不代替这项明确补充。

每次模型调用、工具步骤、Trace Span和AgentRun属于执行过程，不单列成业务任务。普通chat不生成Work；外部ACP记录若只有AgentRun而无可信业务Work，不为了填看板补造工作，该限制在对应详情和验收覆盖中明确。

### 3.4 文件视图

文件清单合并展示两种真实来源，行上区分“输入材料”和“员工交付”。每行提供文件名、类型/大小、发送人或交付员工、时间、原消息入口；成果另外显示明确版号、采用状态和来源。hash可在只读详情核对，不要求普通列表常驻技术字符串。

支持按文件名、来源种类、发送/交付者、类型和时间筛选；条件在宿主分页前应用。文件名筛选不等同于正文搜索；正文搜索继续使用现有检索入口和来源规则。超限、缺失、不支持编码、读取失败分别呈现，不能当“没有文件”。

版本规则固定如下：

1. 只有真实修订关系组成版本组，同名独立材料/成果保持分开。
2. 成果版本组默认展示已发布的最新内容版，同时单独显示本人当前采用版；最新不等于已采用。未采用新版时仍能一眼看到原采用版。
3. 展开可访问历史版本；选择哪个版本，右侧就固定展示哪个版本。新版发布不得替换正在审阅的旧版。
4. 输入材料不套用成果版号；输入原件与交付文件即使同名也不合并。

草稿附件、未事务发布的复制文件、员工私有工作区/系统文件/记忆文件、尚未显式发布的外部运行目录不进入会话文件清单。沿用已有受管历史登记边界，不靠扫描目录填充清单；不恢复已退役的资料库主页面。

右侧继续复用现有预览：Markdown默认排版，可切源码；代码使用本地Shiki JavaScript引擎及明暗主题；普通UTF-8文本保留行号；HTML/SVG只显示源码，不执行远程媒体或脚本。预览上限、原件/hash、材料读取权限和内容失效沿[第10组02](../10.真实工作交付闭环/02-成果预览版本与采用.md)，不通过新清单扩大模型材料或搜索证据范围。

## 4. WV-02：全局任务总览

### 4.1 范围、来源与统计

纳入本人当前获准、可见会话中的真实Work，覆盖私聊、群聊、核心会话及定时触发形成的工作。隐藏/删除会话和已撤销来源在查询与点击时排除，不能照搬Raft仅频道任务的范围。

AutomationDefinition是计划，AutomationOccurrence是一次触发，Work是实际业务工作。一次触发可关联多个Work；没有Work的失败触发留在定时任务历史，不伪装成工作卡。Work有可信origin时显示计划/触发来源并可回查；旧记录来源缺失就显示未知，不按时间接近推断绑定。

未按员工筛选时默认展示、计数根工作，子工作另计并展开；状态等条件匹配该根Work。按员工筛选时，展示该员工真实ownerAgentId拥有的Work，包括子Work，按每个匹配Work自己的状态分列和计数；原根仅作上下文，不计为该员工拥有的工作。所有AND条件必须命中同一Work，不能员工命中一个子工作、状态命中另一对象。结果依赖不算拥有的子工作，不把群成员都算负责人。尚未加载条数不能冒充总数；部分覆盖标注范围。

### 4.2 看板与列表

首次进入默认看板，可切列表并保存本页偏好。两种模式复用同一工作卡字段、筛选和来源解析。筛选包含任务目标关键词、员工、会话、状态、普通/定时触发来源、时间范围。旧来源无法分类时保持未知，不过滤成普通工作。

| 展示分组 | 既有Work状态 | 必须保留的区别 |
| --- | --- | --- |
| 待开始 | ready | 尚未认领不表示模型运行中 |
| 进行中 | running | 实际运行事实和当前持有者沿原记录 |
| 等待或受阻 | waiting、blocked | 按真实记录区分需要补充、结果依赖与失败阻塞；原因缺失显示未知 |
| 已交付 | delivered | 保留原结果消息/文件证据；人工采用和效果认可另外显示 |
| 异常或结束 | failed、cancelled、interrupted | 失败、用户停止和重启中断保留各自文案，不能归作已完成 |

看板不支持拖拽更改业务状态。没有“标为完成”按钮绕过Work事务、结果证据或执行退出。Run成功、Work交付、本人采用、人工效果认可和通知回执分别表达；requiresReview也不作为人工验收结果。

已交付记录的原件后来缺失/外改时，保留历史交付事实，同时显示当前证据不可读取，阻止陈旧预览和采用；读查询不私自改写历史Work状态。点击“查看结果”核对具体结果消息或文件版/hash，不默认选文件夹里的最新文件。

### 4.3 有界读取与动态更新

宿主从现有Work仓库提供会话、全局和员工共用的有界查询；授权、会话可见性、负责人、状态、来源和时间在SQLite分页前完成。稳定排序以明确时间和ID消除同值歧义，游标绑定条件、范围及数据revision；条件或来源代际变化时旧游标失效。

看板各分组必须有自己的有界加载方式和同口径计数，不能先截取一页再由前端分列而漏掉其余状态。Work与文件共用查询合同为**默认每页30项、最多100项**；员工当前工作摘要固定前5项并显示同口径总数。渲染层不得逐个拉所有会话完整详情或聊天历史来拼总览。规模模块验证以一万条预置Work的三次有界查询和全量计数在3秒内完成为当前门槛；不把该数据查询门槛视为界面渲染或无限历史的承诺。

事件仅用于失效当前查询/更新获准最小字段，不替代宿主权威。离开页面暂停主动读取，重新进入核对；筛选、清理、撤权或跨页后的迟到响应不得复活已移除对象。总览读取不能认领Work、重试工具、续预算或恢复执行。

## 5. WV-03：通讯录里的员工资料

员工资料首页按“这个人是谁 → 能做什么 → 正在负责什么 → 找他交流”的顺序组织。保留独立员工身份、头像、名称、职责、workspace和记忆；群只组织参与者，解散群不删除员工。

| 区域 | 展示内容 | 可执行入口 |
| --- | --- | --- |
| 身份职责 | 已提交头像/姓名、角色说明和能力描述；描述是配置声明，非效果证明 | 发消息、编辑资料 |
| 实际能力 | 已绑定Skills、连接/依赖状态及验证范围；分别显示已配置、已授权、说明可读、已验证、不可用/未知 | 查看技能、进入既有配置/检查入口 |
| 当前负责工作 | 用同一Work查询按真实负责人读取ready/running/waiting/blocked等当前工作，保留子工作身份 | 查看工作、查看该员工任务范围、返回原聊天 |
| 深入配置 | 现有配置、系统文件、工作区、记忆及诊断 | 复用现有详情标签和版本化保存 |

工作摘要有界，显示加载范围与“查看全部”入口；查看全部打开全局任务并固定该员工筛选。已交付、失败或中断历史可从全局任务筛选查看，不能暗中重新激活。无当前工作与查询失败是不同状态。

技能安装、员工绑定、当前聊天授权、依赖可执行和真实验证分别核对；不要把Skill存在或模型描述当作已可用。验证只对原配置版本、执行环境和范围有效；配置变化失效旧验证。查看资料不扫描其他外部程序、调用模型或运行验证。

ACP资料通过宿主`getLaunchProfileStatus`只读核对原启动项保存的程序路径/hash及指定登录目录存在性，同次返回配置版本和核对时间。当前程序外改显示验证失效，程序或登录目录缺失显示执行依赖不可用；读取失败独立显示，不能沿用旧握手证明当前可用。刷新只重复这些已配置来源的事实核对，不启动程序、握手或改写原验证记录。程序当前可读仍不表示任务执行能力已验证，原握手只表示当时的连接范围。

不预建尚未接入的MCP、Apps、远程电脑空面板。资料里的工作区继续作为员工私有管理入口，不与已交付文件清单混合。编辑复用现有expectedConfigVersion版本化保存；返回资料后展示已提交配置，失败保留草稿。返回结果不明时先读取已提交配置并明确处理版本冲突，不假设已有配置保存的稳定请求账本/回执接口。原消息、成果和技能绑定的未知回执继续沿各自既有合同。

## 6. 共同完成条件

用户能从三个入口识别同一个工作、同一负责人和同一结果版本；任务/文件切换不妨碍正常聊天；处理动作能回到确切员工消息。右侧预览保持只读，普通读取不产生任何业务突变。
