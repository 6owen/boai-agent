## 1. 唯一权威与模块职责

| 层级 | 负责 | 不负责 |
| --- | --- | --- |
| Renderer | 选择、草稿、预览、筛选、显示和明确操作 | 任意宿主文件访问、权威预算或审批状态 |
| shared/domain 与 IPC | 版本化请求、结果、事件和可序列化合同 | 工具进程与模型实现 |
| 宿主 / runtime 用例 | 授权、输入校验、对象归属、事务受理与提交 | 将 UI 缓存当持久真源 |
| 资源 / 工作 / 自动化模块 | 各自拥有的文件、工作和 occurrence 业务规则 | 互相覆盖状态或推断停止权 |
| adapters | 解析、网页、模型、外部程序与存储实现 | 决定是否已业务交付或用户采用 |

工作认领、预算、持有者比较、结果提交保持 WorkRepository 的 SQLite 事务。问题来源投影、搜索与统计是读模型；需要写入时调用对应业务所有者，不直接改一份平行状态。

会话任务、全局任务和员工当前工作共用既有 WorkItem 真源；会话文件组合已发送材料与事务发布的成果记录。新增视图只增加受控查询和表现层，不建立另一份全局任务库、员工私有任务表或可编辑看板终态。AgentRun、Trace、工具步骤和自动化计划定义不是 Work；外部 ACP 旧记录仅有 AgentRun 而无业务 Work 时，不伪造对应工作或已交付事实。

## 2. 建议新增或扩展的数据

| 概念 | 最小必要信息 | 核心不变量 |
| --- | --- | --- |
| 附件记录 | 稳定 ID、会话/上传来源、受管文件引用、类型/大小/内容校验、导入状态 | 外部路径不是永久身份；名称相同不合并 |
| 解析版本 | 附件 ID、解析器版本、内容校验、页/片段映射、状态 | 派生内容对应确定原件；空解析不假定成功 |
| 消息附件关联 | 消息 ID、附件 ID、顺序、共享授权引用 | 发送与关联同事务，不能产生半条已发送消息 |
| 成果修订关系 | 现有 Artifact ID、逻辑成果身份、明确前版、内容身份 | 不按同名/近似文本推断版本链；不替代工作结果版本 |
| 版本审核记录 | 被审 Artifact/内容身份、审核者、来源 run/消息、结论及证据 | 不把旧版审核继承到新字节 |
| 用户采用记录 | 操作者、成果/版本/内容身份、请求身份、时间 | 已读不生成采用；重复请求幂等 |
| 修改请求 | 明确原版、用户要求、消息、目标员工/工作关联 | 保留原结果；不隐式复活旧工作 |
| 能力验证回执 | 员工/连接/工具/配置版本、验证范围、结果、时间 | 已配置不等于已验证；范围外能力不获授权 |
| 阅读位置 | 会话、稳定完成事件或阅读边界、版本 | 流式起始序号不能决定完成先后 |
| 模板实例来源 | 模板及版本、创建请求、生成对象身份 | 重复创建回执不重复造对象 |

待处理事项优先从来源记录投影。若性能要求物化缓存，其身份至少由“来源类型 + 来源 ID + 必要版本”组成，并保留来源状态版本；它不拥有独立审批/交付终态。通知意图继续按现有事务合同保存。

## 3. 接口职责建议

| 用例 | 输入要点 | 结果与副作用 |
| --- | --- | --- |
| 准备聊天附件 | 原生选取授权、目标会话、请求身份 | 返回受管导入记录与解析状态；不发送消息 |
| 发送带附件消息 | 正文、提及、引用、就绪附件 ID、请求身份 | 校验授权后原子提交消息与关联，再调度 |
| 读取附件/产物预览 | 对象 ID、明确版本、限定预览类型 | 有界读取；不接受任意绝对路径作为授权 |
| 采用产物版本 | 对象/版本/内容身份、期望状态、请求身份 | 原子保存采用事件，返回准确回执 |
| 提交修订 | 原版身份、要求、接收对象、请求身份 | 保存用户请求和修订关联，再按已有工作流程执行 |
| 查询待处理（底层兼容） | 类型、筛选、稳定游标 | 来源核对与原业务投影，不恢复独立UI处理中心；查询不触发模型 |
| 聊天回复问题/原卡片动作 | 明确 question/version/原消息及适用 workId/occurrence；自动化 question 固定 expectedVersion/questionMessageId；审批/成果保持原载荷 | 回到原业务用例校验并事务提交；原问题引用进入明确模式，其他消息引用不自动关联；inboxReply 与本人消息/回执同事务 |
| 搜索 / 阅读位置 | 查询范围/游标；明确连续阅读边界 | 有界结果；阅读更新不处理业务事项 |
| 查询用量 | 工作或员工范围、时间口径 | 从可信账本聚合，返回完整性说明 |
| 查询工作视图（已接线） | 当前会话/全局获准范围/员工身份、状态/来源/时间筛选、稳定游标 | 返回现有 Work 的有界只读投影；无员工筛选默认根工作；按员工筛选返回其实际拥有的Work（含子Work），条件匹配同一对象；不调度或改写终态 |
| 查询会话文件（已接线） | 明确会话、材料/成果类型、版本选择与筛选、稳定游标 | 返回已发送材料与已发布成果的有界元信息及准确来源；正文仍走原受控预览 |
| 核对已配置ACP启动项（已接线） | 明确原启动项ID | 同次返回配置版本、原路径/hash及指定登录目录的只读状态、原因和时间；不执行程序/握手，不写验证记录 |

全部经现有唯一 IPC/桌面通信入口。新增持久突变返回已提交的权威结果，Renderer 再更新；事件只携带获准最小数据。不能为了省事让渲染层直连数据库或启动工具。

### 3.1 工作视图的有界只读合同（已接线，详细结果归13）

1. 范围由宿主按当前可见且获准会话求交，覆盖符合范围的单聊、群聊、核心会话和实际自动化工作；员工身份是筛选条件，不扩大授权。会话/负责人/状态/来源/时间条件在数据库分页前生效，不由 Renderer 遍历所有会话或拉取完整聊天后筛选。
2. 复用共享有界查询合同：Work/文件默认每页30项、最大100项，员工当前工作摘要固定5项并保留同口径总数；其他筛选和展开校验以共享合同为准，不留无上限读取。排序必须有稳定唯一键，游标绑定规范化条件、范围及数据 revision；筛选或范围变化重置游标，失效游标明确拒绝，不混入其他查询页。
3. 工作卡保留 workId、conversationId、明确 sourceMessageId、ownerAgentId、原状态/版本、真实父子关系和适用 origin；结果保留明确消息与成果身份、版号/hash及证据状态。未按员工筛选默认展示/计数根工作并按根状态分组，子工作仅沿真实parentWorkId展开；按员工筛选时展示其实际拥有的Work（含子Work），全部AND条件匹配同一Work，按该Work自身状态分列/计数，根仅为上下文且不算该员工任务；dependsOnWorkIds 不等同父子归属或停止权。运行成功、业务交付、本人采用与人工质量评价分别显示。
4. 文件条目区分输入材料和交付成果，保留 materialId 或 artifactId、原消息/员工、类型/大小、具体版本/hash及实际来源。成果只沿已有显式修订关系折叠，同名文件不合并；选择历史版始终读取该版。私有 workspace、未发布的临时文件及外部运行目录不隐式进入会话文件列表。
5. 列表只读元信息，点击后由宿主重新核对当前范围、清理门禁、原对象与实际来源。详情正文沿原受控预览读取；目录路径、旧摘录或 UI 缓存不能替代受管原件/hash。来源失效即时清除对应旧正文；没有原目标时保留准确不可用原因，不猜邻近消息或最新版本，导航不得恢复隐藏/删除会话。
6. 主视图、会话或员工条件变化后隔离迟到响应。隐藏视图停止列表读取和阅读观测，范围失效清除派生列表/导航焦点，不能覆盖新选中对象。查看、切页、筛选和展开均不产生消息、Work、审批/采用记录、模型调用或执行恢复。
7. 若为性能增加读模型或索引，只能从现有权威记录有界派生，并随清理、权限、版本变化和备份恢复失效；不将其反向写为业务状态。偏好仅保存视图选择、筛选和稳定锚点，不能作为授权、阅读或业务完成证据。

员工ACP资料使用`getLaunchProfileStatus({id})`的同次`profile/status/detail/checkedAt`，不把两次读取的配置版本与依赖事实拼成一个状态。`available`仅说明原已配置来源当前身份核对通过；`changed`及`unavailable`不得借旧`verified`证明当前可用。原配置修改沿版本化保存清除旧验证；查看或刷新只读核对当前原件，不测试连接、运行任务或变更保存配置。失败与尚未配置分别呈现，迟到结果不得覆盖新员工或新版本。

待审批目标保留所见approvalId/runId及适用正式messageId，宿主核对其真实Work、holder/负责人、会话、Run与当前等待钩子。未发布员工回复时只定位原等待卡，不公开私有正文；发布后固定同Run的真实消息。审批结束、运行替换、隐藏/清理或所见关联变化拒绝旧目标，不降级到原请求、邻近消息或另一审批；导航本身不批准或继续执行。

自动化补充读取固定本次触发与原问题消息。新判断阶段和实际执行WorkOutcome产生的task问题都必须使原Turn及occurrence进入明确等待用户补充的状态；旧completed或同伴失败Turn的已公开问题只沿共享`publishedWorkQuestionMatches`真实关系只读核验，不迁移原Turn或放宽中断/取消门禁；task问题从原已公开Message.runId沿真实Run.workId核对原Work.userQuestion、负责人、结果消息、来源和未回答版本；chat只读实际Decision问题，只有旧缺记录才保守兼容原waitingTurn公开消息，不把旧无origin Work转为自动化。精确投影按occurrence和message区分同轮多个问题；提交的occurrence版本、Work版本和question版本分别核对，不能相互代替。本人补充消息、回答关联、原Work可接续版本及稳定回执共用原提交事务，接续沿原负责人、累计预算和绝对期限；不解除独立依赖等待或其他未回答问题，不创建替代Work。源失效和已回答问题拒绝，未知回执只读核对。

业务动作仍回到原员工聊天消息：审批在原请求卡片，采用/稍后处理/未知回执核对在原交付卡片，修订进入同一 composer 的固定版本引用模式。只读查询与导航不能新增独立审批、采用处理中心，也不能通过拖拽看板把运行中或无证据工作改成“已完成”。

## 4. 文件与数据库一致性

1. 文件先写到受管暂存区，校验完成后登记可用身份。
2. 消息提交时事务核对文件状态、会话权限和请求身份；失败不留下可见消息。
3. 不再引用的暂存文件进入确定清理流程；异常中断通过持久记录核对，不猜测是否发送成功。
4. 发布成果继续使用既有不可覆盖发布机制；版本关系和必要通知/待处理变更与业务提交一致。
5. 外部文件被修改时通过内容校验显性化；不得对用户没有看到的内容保存采用记录。

文件系统操作不能伪装成数据库事务；设计必要的暂存/提交/清理日志。已开始的业务事务和已执行工具不自动重放，恢复只核对已提交事实。

## 5. 兼容与迁移

| 旧数据 | 迁移策略 |
| --- | --- |
| 纯文本消息 | 附件关联缺省为空；既有正文、提及和引用不重写 |
| 老 Artifact | 保持原 ID 与发布语义，作为未关联的独立成果；不凭同名建立修订关系 |
| 无人工采用记录 | 显示“未记录人工采用”；不等同于拒绝或业务未交付 |
| 无能力验证 | 显示未验证；禁止用配置存在反推历史可用 |
| 无可信阅读边界 | 首次进入从明确初始化规则开始，不把全部历史强行标未读或假定读完；迁移方案实施前固定 |
| 无调用账本 / 缺用量 | 保留未知；不能用当前模型配置倒推历史价格和请求 |

迁移需有 schema 版本、原子提交、失败保留旧数据和重复启动行为。打开新版本数据的旧应用不得静默覆盖未知字段；具体兼容策略在实现前明确。禁止同时维护两套“暂时”的权威状态。

## 6. 清理、撤权和备份

附件原件、解析文本、页映射、缩略图、搜索索引和相关预览缓存遵循会话清理；来源撤权立即阻止后续读取。新记录须加入现有清理与备份映射，不只删除可见 UI。

用户采用/修订记录随所属会话和成果边界清理，不保留能重建已删正文的旁路。保留既有触发去重身份等必要运行边界，不扩大保留的私有内容。

备份恢复先核对文件与引用，失效预览/搜索/统计缓存；不重新发送旧通知，不重跑解析后的模型任务，也不复制外部凭据。需要重建的纯本地派生索引可以有界重建并暴露状态。
