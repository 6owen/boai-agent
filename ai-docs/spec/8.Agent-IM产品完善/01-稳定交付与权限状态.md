# IM-01：稳定交付与真实权限状态

状态：待实施 / 待验收。优先级：P0。

目标：用户能够区分“正在执行、需要介入、已经交付”，看到的权限与真实执行能力一致。

首批范围：复核代表性任务的研究、写作、审核、最终发布链路；定位预算消耗和重复判断/汇报；校准权限界面的选项与状态。沿用现有工作事务、预算、证据和取消机制。

现有[评估记录](../6.Cumora协作重构/09-多Agent测试体系与评估集方案.md)包含“已生成草稿但预算耗尽，未审核及最终交付”的失败样本，应纳入回归。调研还发现“完全访问权限”仅为本地预览而文案提到沙盒；实施前核对其最新状态并消除误导。

- [ ] 完整报告及其检查证据真实存在；不能以成员均有回复、没有失败 run 或只有草稿作为通过。
- [ ] 审核针对最终发布的实际版本；发生修订后不能沿用旧版审核结论冒充新版本已核对。
- [ ] 保留原预算约束，记录缺失用量；不能通过隐式追加或重置预算让失败变成通过。
- [ ] 权限选项对应真实、可保存的执行状态；不把未实现的预览或应用级路径限制描述成系统沙箱。
- [ ] 停止、撤权、失败和重启边界回归通过；执行器退出前不释放占用，已执行或不明操作不重放。

## 交互入口与展示

复用聊天消息旁的执行过程入口和“任务与产物”详情。任务详情回答目标、负责人、当前业务状态、证据和下一步；Trace 继续承担调用诊断，不能替代交付记录。输入框上方不新增常驻状态条。

| 可见状态 | 显示内容 | 可用操作 |
| --- | --- | --- |
| 正在处理 | 工作目标、负责人、当前可证实进展 | 查看详情、停止此工作树 |
| 等待输入 | 缺少的具体材料/答案及相关问题 | 补充到指定工作 |
| 等待依赖 | 依赖对象及要求的结果版本 | 查看依赖、停止自己的工作树 |
| 需要批准 | 待批准动作、实际范围与所属任务 | 查看请求、允许一次、拒绝 |
| 已交付 | 可检查的回答或产物证据 | 查看成果；需要时进入人工验收 |
| 失败 / 已中断 | 原因、已完成部分、待核对操作 | 查看已有结果；仅提供当前允许的后续动作 |

以上是现有权威数据的展示投影，不用新枚举替换运行、工作、审批与采用各自的状态。

## 完整交付流程

1. 明确请求落到现有工作身份，确定交付对象和预算归属。
2. 成员领取工作，执行前读取获准材料及配置快照。
3. 需要协作时委派有边界的子工作；需要等待时保存明确结果版本与下一步。
4. 汇总实际结果，记录草稿与证据；必要的复核使用实际字节/内容版本。
5. 发布前复核最新输入、证据、权限和停止状态；只在事务成功后呈现最终结果。
6. 人工采用是后续独立动作，不改变已经发生的执行历史。

## 权限交互规则

首批只展示真实支持的执行模式。文件与知识访问、宿主命令、外部 ACP 的权限分别解释；“允许一次”只批准当前明确请求。若继续提供尚未实现的选项，应明确不可用且不可选，不用视觉选中态制造授权已生效的错觉。

权限保存失败保持已提交值，表单仍可修正；运行中配置锁定沿用现有规则。撤权、取消与发布共用已有宿主边界，旧运行回执不能覆盖新权限或新执行权。

## 可靠性改进边界

先分析已有真实失败样本：预算耗在判断、执行、记忆、修复还是无效汇报；通过减少冗余工作改善，不添加新的中央调度器。模型用于判断和内容，重复检测、预算、恢复、通知由确定性代码负责。

未知工具结果进入“待核对”，不得自动重试。预算耗尽明确结束或阻塞；追加沿用用户确认机制。对已完成步骤提出新修改，需要显式新请求与关联，不能自动重跑整个工作树。

## 关键反例

- 研究与写作运行均成功，但最终报告不存在：整个任务未交付。
- 审核的是第 1 版，发布的是第 2 版：不能显示第 2 版已审核。
- 用户停止后旧 run 才返回结果：不能夺回发布权或释放新 run 的资源。
- 模型回复“已获允许”，数据库没有批准记录：不得执行。
