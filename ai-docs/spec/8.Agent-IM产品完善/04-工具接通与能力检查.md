# IM-04：工具接通与能力检查

状态：待实施 / 待验收。优先级：P0。

目标：员工的“能做什么”来自真实工具、依赖和授权，而不只来自角色提示词。

首批范围：研究场景的网页搜索/读取和来源引用；从员工配置显式选取并授权所需技能；检查模型、工具连接、执行依赖与支持范围。优先完成一个必要工具链，通用 MCP 管理和浏览器交互按既有专题逐步接入。

- [ ] 搜索/读取有真实工具结果与来源，失败明确反馈；不把模型记忆中的网页描述当作联网结果。
- [ ] 区分已安装、已绑定、待授权、依赖缺失、未验证、已验证和运行失败；验证记录对应具体配置。
- [ ] 商店安装不会自动授予某员工执行权；配置变化后旧验证不能继续表示当前可用。
- [ ] 工具范围和取消服从原工作、原预算及实际执行器生命周期，撤权即时阻止后续使用。
- [ ] ACP 自有工具与 BoAI 内置工具能力分别说明，不把单聊外部能力默认推广到群协作。
- [ ] 网页等外部内容作为资料处理，不能改变工具权限或覆盖用户目标。

## 能力呈现与入口

复用员工详情的工作区/技能及模型连接设置，在这里解释能力；聊天只显示本次需要用户处理的问题。安装、绑定、授权、依赖和验证是不同维度，应各自可检查，不能压缩成一个容易误导的绿色开关。

2026-10-05 [员工资料概览](./12-员工协作工作视图.md)定义为通讯录内的能力摘要入口，当前未实施，进度归[工作视图实施](./13-工作视图实施与自动验收.md)。摘要使用该员工现有配置、受管来源及真实验证回执，区分已安装/已绑定/获准读取/执行未验证/实际检查结果；缺少证据时明确未知。查看摘要不自动安装、绑定、授权、测试或调用模型，修改和有副作用的检查仍进入现有明确配置流程。

| 维度 | 展示内容 | 改变方式 |
| --- | --- | --- |
| 模型 | 服务是否可用、是否支持当前输入 | 连接测试和真实能力校验 |
| 技能 | 来源、版本、是否被当前员工绑定 | 用户显式选择 |
| 工具 | 已接通能力及支持范围 | 连接配置与验证 |
| 依赖 | 缺失的运行时/程序/配置 | 指向可执行的补全步骤 |
| 权限 | 对谁、哪些资料、什么动作有效 | 明确授权，版本化保存 |
| 验证 | 验证时间、配置版本、测试范围 | 用户触发的有界真实检查 |

“已验证网页读取”不等于“可以发邮件”，读能力通过也不授权写动作。运行中最新错误应保持可见，不能被历史成功测试覆盖。

## 首个网页工具链

1. 用户明确要求研究外部资料，或既定工作范围允许读取相应公开页面。
2. 工具返回查询、时间、来源 URL、标题与有界正文；结果必须来自实际请求。
3. 员工在回答或成果中引用实际使用的来源，区分原文事实与推论。
4. 失败说明是网络、访问限制、解析还是取消；缺资料不当作“没有变化”。

首批采用只读网页搜索/读取，登录网站、下载执行文件、表单提交和浏览器自动操作另行处理。遵循现有网络适配层风格，限制响应体、重定向、超时和目标范围；实现时明确本机/内网地址访问策略，不让一个读取工具获得隐含宿主网络权限。

## 显式绑定与就绪检查流程

员工配置 → 选择本机已安装技能 → 预览实际说明与来源 → 显示工具/依赖缺口 → 用户确认绑定范围 → 保存 → 测试必要能力。

测试必须解释实际会发生什么：扫描与读取元数据不执行外部程序；真实启动、网络或模型验证使用对应授权和预算。不能在页面切换或列表轮询时反复触发付费测试。测试回执绑定配置版本、工具版本和必要环境指纹；配置变更后显示“需要重新验证”。

连接凭据由现有宿主凭据机制保存，Renderer 只接收必要状态；技能正文和页面内容不能读取凭据。工具缓存或结果记录不包含原始密钥。

## 失败、停止与恢复

验证失败保留原配置及明确原因，不把“配置保存成功”显示成“能力可用”。运行失败记录本次原始错误；是否重试由已有工作规则决定，已发生或结果不明的外部动作不能自动重试。

取消必须传递到实际工具/进程，退出前保持资源占用。重启只恢复可检查配置与记录，不自动重新测试、重新登录或续跑业务。

## 实施边界

复用[员工模块](../../../src/runtime/modules/employees/.folder.md)、[资源模块](../../../src/runtime/modules/resources/.folder.md)、[Mastra 任务工具](../../../src/runtime/adapters/mastra/task-runtime.ts)与[能力环境](../../../src/runtime/modules/workspaces/environment-plan.ts)。网页能力是工具，不能伪装成新的员工身份；MCP 与 ACP 的区别保持[执行后端合同](../4.数字员工与协作重构/04-员工执行后端与能力契约.md)。

后续接入邮箱、日历等只扩展明确能力，不以通用连接器一次开放全部权限。
