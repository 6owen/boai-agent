# 自用任务查询与状态来源

## 1. 本批边界

本篇记录已有员工工作数据的有界查询及来源校验。2026-10-26撤销由这些协议推导的独立任务入口规划。数字员工是产品主体，用户沿原私聊和群组交办、查看和调整工作；既有协议不等于新增页面或自动执行的需求。

## 2. 原对象和权威状态

| 对象 | 已有真源 | 本期含义 |
| --- | --- | --- |
| 显式任务 | agentTasks / tasks.* | 用户要求登记的多步工作；agentId为负责跟进的员工，非自动推断的执行人 |
| 计划 | plans.* / Plan Weave | 独立的依赖/领取/报告/审核状态；不自动变任务或启动执行 |
| 实际执行 | 原Run/Work/NativeAction | 只有原记录证明运行、审批、停止及副作用 |
| 成果 | 原已登记Artifact及refs关系 | 关联须明确且当前有权读取；不按同名、最近时间或同会话所有文件猜测 |

任务done只表示登记的进度完成，不证明执行或成果审核通过。note是登记备注，未完成步骤标题是登记的下一步骤，不冒充运行故障或实际工具结果。普通聊天、每次Run、历史Work和自动化不自动成为任务。

## 3. tasks.page只读合同

- 复用原应用协议及可信owner/employee/behavior身份；原tasks.list/get/create/update/delete兼容，稳定写回执不变。
- owner可按员工/来源会话/状态查询，非owner限本人原有可用范围。默认排除done，显式status=done可查询完成记录。
- 每页默认30、最多100；按updatedAt及id降序的固定游标。游标绑定查询条件及调用身份范围，不能跨筛选复用；权限每页重新核对，游标不是授权。
- SQLite在LIMIT前检查员工仍存在、来源仍存在且成员匹配、未隐藏/合并/清理。员工跨单聊读取继续沿原任务范围，不能读取他人、群聊/渠道或会话专属内容。
- 单次SQL只投影列表字段及步数、已完成步数、首个未完成步骤标题；备注摘录最多1000字符并标记截断。完整步骤/备注仍按原tasks.get读取，不把全部记录或全文搬到Renderer后裁切。
- 来源无会话的旧任务保留原范围。删除员工/来源、撤成员、隐藏或清理立即影响下一页；不得为了查询恢复隐藏会话。
- 页面只读，不产生任务/计划领取/Run/Work/消息/授权/回执。重启可继续读取同一查询的游标，不重放业务；任务变更后列表按当前状态读取，游标不承诺冻结历史快照。

## 4. 员工工作记录边界

工作记录归属员工；实际执行与成果仍按原对象和明确引用核验，不能用登记进度推断执行成功。用户在原私聊或群组中继续交流，原请求和来源身份保持。

删除仍沿原tasks.delete+revision，仅删除跟踪记录；不取消Run/Work或删除文件。Plan Weave归档属于原计划动作，不借它自动归档或完成任务。本篇不安排新的布局、导航或自动领取行为。
