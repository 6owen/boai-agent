# IM-08：用量与协作效果可见

状态：待实施 / 待验收。优先级：P1。

目标：用户知道一项工作耗费多少，以及哪些场景值得使用多个员工。

首批范围：按工作和员工展示请求数、已知 token、缺失用量、耗时及预算状态；利用现有评估比较同一任务的单员工与多员工结果。

- [ ] 按唯一调用回执聚合，子工作、修复、记忆和重试不遗漏，不与 run/Trace 汇总重复计数。
- [ ] 未知用量保持未知，部分已知有明确标识；只有可靠价格和对应使用量齐全才提供费用估计。
- [ ] 并行执行、等待和人工处理时间分开解释，不把并行区间简单相加当作用户等待时长。
- [ ] 追加额度保留前后限额、累计用量和确认记录；统计读取不改变权威预算。
- [ ] 同场景比较质量、人工介入、用量和耗时，试运行、失败、待评审均保留，不只展示成功样本。
- [ ] 清空会话及恢复备份后统计按保留证据重建，不出现重复累计或已删内容旁路。

## 面向用户的视图

首批在“任务与产物”的工作详情增加按需展开的用量摘要，展示本工作树累计请求、已知 token、用量完整性、总历时及当前预算。员工层面的汇总作为独立统计入口，避免在聊天输入框上方增加常驻状态条。

不另建覆盖既有个人资料统计的平行报表：与[个人资料待实施方案](../3.前端重构与功能/17-个人资料/README.md)共用权威请求证据和统计定义；本专题优先完成任务视角。

## 指标定义

| 指标 | 计算口径 | 缺证据时 |
| --- | --- | --- |
| 请求数 | 按唯一调用身份计入真实请求，含判断/执行/修复/记忆 | 明确请求记录范围 |
| 已知 token | 累加可信原始使用量，避免账本与 run 双计 | 标记已知部分或未知 |
| 估计费用 | 可信用量匹配有效价格版本并注明估计 | 不显示为零费用 |
| 总历时 | 明确开始到结束的实际用户等待区间 | 显示仍进行或证据不足 |
| 执行 / 等待 | 有证据的执行与依赖/人工等待区间 | 不编造精确拆分 |
| 人工介入 | 明确补充、审批、修订等事件，区分类别 | 不由消息文本猜测 |
| 采用情况 | IM-03 的明确版本采用记录 | 未采用不同于失败 |

多员工并行不能把各自历时简单相加当作总等待；失败和取消仍产生已知用量。费用货币和时间范围必须明确，不能把“输出 token 上限”显示为总费用预算。

## 归属与去重

沿用原始工作和自动化 occurrence 的归属。父工作汇总包含子工作时，列表同时展示子工作不能再汇总一次；修订请求单独列明自己的工作及预算，保留与原成果关系。

仅由可信调用回执结算。重复回执幂等处理；缺少供应商用量时记录未知调用数量。外部 ACP 未提供使用量不得以进程启动次数推算模型 token。

## 单员工与多员工比较

使用相同任务、输入资料、交付要求和预先定义的评审标准。固定模型/工具/版本配置，记录参与人数与运行方式；实验预算覆盖全部批次，不能分批绕过上限。

先判断质量是否合格，再比较耗时、用量和人工介入。展示失败、待评审、证据不足和中断；不能只挑最快的成功样本。正式留出和评审校准沿用现有评估合同，不另造一个更宽松的排行榜。

首批产品不自动推荐“更多员工更好”，也不自动换模型来追求成本指标。可用证据不足时仅展示事实摘要。

## 生命周期和实现

统计从保留的权威记录聚合，缓存只加速读取。清空会话或恢复备份后失效重建，不把恢复前后累计相加。统计失败不能重试业务工具、改变交付状态或中断原任务。

实现复用[工作预算合同](../../../src/shared/domain/work.ts)、[自动化用量展示](../../../src/renderer/pages/schedules/automation-history.tsx)和[评估体系](../6.Cumora协作重构/09-多Agent测试体系与评估集方案.md)。依照 [10](./10-数据契约与迁移边界.md)保持统计读模型与预算写入权威分离。
