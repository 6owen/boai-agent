# IM-05：统一待处理收件箱

状态：待实施 / 待验收。优先级：P1。

目标：用户回来后，直接知道哪些工作需要自己处理。

首批范围：跨会话聚合等待补充、等待批准、失败需处理、产物待验收。复用已有工作与自动化状态，不再建立第二份业务状态真源。

- [ ] 每项关联准确的会话、工作、消息、审批或产物版本；能跳到具体位置。
- [ ] 待处理项有稳定身份，刷新和重启不重复；处理完成后可靠移出待处理列表。
- [ ] 读取或关闭收件箱不等于审批、补充或采用；过期事项不能继续执行旧操作。
- [ ] 同一工作的新进展能够更新对应事项；待处理项不会被大量近期完成记录挤出可见范围。
- [ ] 复用现有通知偏好，只对有意义变化提醒；通知提交不等于送达或已读。

## 页面结构

建议在主导航增加“待处理”入口。左侧为事项列表，右侧复用现有详情标签机制；它拥有自己的选中项和标签状态，不操作会话页隐藏的详情。此入口属于新增设计提案，最终位置可随用户反馈调整。

页头显示当前待处理数量，筛选为“全部 / 待补充 / 待批准 / 待验收 / 需处理”，附轻量搜索。列表每行包含类型、标题、所属会话、责任员工、时间和一句需要用户做什么；首批不增加 KPI 卡片或复杂看板。

点击事项只查看。右侧显示原始问题/动作/产物、相关上下文、准确返回来源的链接及该类型的操作。设计参考：[统一待处理收件箱](./designs/02-统一待处理收件箱.png)。

## 事项来源与操作矩阵

| 类型 | 权威来源 | 详情内容 | 处理动作 | 消失条件 |
| --- | --- | --- | --- | --- |
| 待补充 | 已声明的用户问题/等待记录 | 原问题、目标工作、所缺材料 | 提交明确补充 | 来源问题已被有效处理或取消 |
| 待批准 | 当前有效审批记录 | 完整动作与实际影响范围 | 允许一次 / 拒绝 | 权威审批已终结 |
| 待验收 | 明确要求人工验收的产物版本 | 真实预览、版本、审核证据 | 采用此版 / 要求修改 | 对应版本已被有效处理 |
| 需处理 | 当前未解决的失败/阻塞 | 原因、已交付部分、允许的下一步 | 查看/安全接续/新请求 | 来源状态已解决或关闭 |

不是每条 Agent 问句都形成待补充，也不是所有文件都要求验收。模型草稿或普通建议不直接创建事项；应由明确工作状态或用户开启的验收要求产生。

## 排序与分页

默认按需要处理的时间倒序，提供稳定的时间与身份游标，分页必须覆盖全部未解决事项。置顶等偏好如后续引入只影响排序，不改变业务紧急程度。首批不让模型猜测优先级后隐藏事项。

新事件更新已存在事项，不重复插入。更新后保持当前阅读的详情和列表位置；当前事项已解决时显示结果和返回列表，避免突然跳走导致误操作下一项。

## 操作的一致性

收件箱是跨会话投影，动作必须回到拥有该状态的原业务用例。客户端提交来源身份与期望版本，宿主再次读取权限和业务状态后处理；不可先在收件箱“标完成”，再异步去处理实际工作。

审批已过期、员工已移除、工作已停止、产物已清理时，提示来源变更并刷新，不能继续执行页面上旧按钮。自动化补充仍携带 occurrence 身份，不因从收件箱进入就变成普通聊天回复。

## 通知与安静状态

默认仅突出真正需要用户介入的变化，沿用现有重要更新/每次结果/静音语义。系统通知点击定位同一事项的明确来源；提交失败或未知保持事实，不盲目重发。将列表已读和业务已处理分开，不通过关闭通知批准任何操作。

全空时显示“当前没有需要你处理的事”，保留返回会话入口；筛选为空显示“没有符合条件的事项”。读取失败必须提供重试，不能显示全空伪装正常。

## 实施与验证重点

聚合现有审批、工作等待、自动化待处理及 IM-03 的验收记录；数据方案见 [10](./10-数据契约与迁移边界.md)。页面隐藏时暂停读取轮询，已受理操作的结果仍须正确提交。

桌面验收覆盖：同时存在四类事项、处理后来源与列表一致、旧审批失效、自动化定向补充、清空来源聊天、重启后的分页与重复回执，以及在会话页/待处理页之间切换不混入另一页标签。
