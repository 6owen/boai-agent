# IM-05：聊天内回复、批准与成果处理

更新：2026-10-02。用户已要求撤掉 sidebar 的独立“待处理”页面，把原问题回复关联接回聊天。旧收件箱布局和设计图退役；原工作、审批、问题、自动化 occurrence 与成果资格记录继续保留。当前入口实现与定向验证完成；995模块、本次3场通过，相关Electron14/15，原姓名提及旧基线失败保留，实际应用包未验。实际证据见[第 10 组 05](../10.真实工作交付闭环/05-实施步骤与验收清单.md)和[第 2 组 28](../2.已实现功能与代码现状/28-真实工作交付闭环实施.md)。旧页面通过数字只证明当时快照。

目标：每名 Agent 在原聊天提出问题、申请操作与交付成果，用户在同一消息流处理，同一件事保持原身份和预算。

## 聊天入口

| 类型 | 原聊天中的明确对象 | 处理动作 | 权威终结条件 |
| --- | --- | --- | --- |
| 待补充 | 已公开问题消息及其 question/version；有任务时包含 workId，自动化另含 occurrence | “回复此问题”进入当前聊天输入框，发送明确补充 | 原问题被有效回答或取消 |
| 待批准 | 当前审批消息卡片、完整动作与范围 | 允许一次 / 拒绝 | 原审批终结 |
| 待验收 | 消息文件卡及固定成果版本预览 | 采用此版 / 要求修改；可显式保存稍后验收资格 | 对应版本资格在原采用或修订事务结束 |
| 失败或中断 | 原回复、工作详情、已有成果和可核对证据 | 查看原因与当前允许的后续动作 | 原业务状态更新 |

不再提供独立待处理主页面、事项详情标签或单独回答表单。成果复用已有文件卡和固定版本预览；审批复用已有原聊天申请卡片。底层 inbox 投影/API 只负责来源核对，不成为第二套业务状态。

## 回复此问题

原问题卡片提供“回复此问题”。选择该按钮，或引用原未回答问题，都进入明确问题关联模式，复用现有 composer 和引用预览，显示“正在回复原问题”及“取消问题关联”。用户可取消尚未提交的目标；引用其他普通消息仅保留普通引用，不解除任务等待。首批问题补充仅支持正文，材料或成员点名须先取消问题关联后作为普通消息发送，普通发送仍不解除原等待。

发送携带问题 ID、期望版本、明确原消息、适用的 workId 与 occurrence。宿主再次核对原聊天、获准员工、问题仍有效及当前来源；保存本人消息、问题关系与稳定请求回执后才接续。失效问题不能通过相似文字、最新问题或其他会话替代。

普通 chat 提问的回答不创建 Work。task 补充接续原 Work、原始用户请求、累计预算与绝对期限；已执行工具与已交付证据不会因为回答而重放。普通发送和普通引用不能解除任务或自动化等待。自动化问题必须显式保留原 occurrence，同时冻结所见等待版本与原问题消息。聊天提交使用 replyAutomation 的 question{expectedVersion,questionMessageId}，宿主在串行临界区的只读事务核对原消息确属该 occurrence 的 waiting turn，真正受理事务再以 expectedVersion 核对原等待版本/预算，并与本人消息/稳定回执同事务保存 inboxReply 问题关系；不能在预检后接到该 occurrence 的下一次问题。既有运行详情的普通补充/预算追加入口保持独立，问题回复不能顺便追加额度。仍受共享预算、停止、权限、容量与不明操作门禁。

## 提交与未知回执

发送前冻结原载荷和 requestKey。提交结果不明时保留原 key、目标版本和内容，跨切会话、关闭及重启只读核对原回执；不能变成新的普通聊天消息、生成新 key 或自动重发。确认无回执后才允许用户重试原请求或放弃；已受理返回原消息，当前问题已结束也可核对原提交事实。

迟到回复不能覆盖新的草稿、其他会话或已清理对象。清空/删除沿原业务事务清除私有正文与关系，保留最小去重身份；重启与备份恢复只核对已提交事实，不调用模型、恢复执行或重放工具。

## 原对象的一致性

动作必须回到拥有状态的原业务用例，以来源身份、版本和当前权限进行事务校验。没有独立“标为完成”来掩盖未批准、未补充或未交付的工作。已停止工作、旧审批、来源失效或操作结果不明时，不提供绕过门禁的继续动作。

成果“稍后验收此版本”仍固定本人、Artifact/逻辑身份、内容版号/hash、资格版本及原请求回执。预览、未采用、requiresReview 和运行成功不自动产生资格；新版不继承原资格，也不能把脚本采用当人工质量通过。

通知沿用已有偏好与持久回执；点击只定位明确原消息或 occurrence。提交不证明送达/已读，未知不盲目重发。读过问题或审批也不代表业务已处理。

## 新入口验收

本次应独立证明：sidebar 不出现“待处理”；已公开普通/任务问题可从原卡片进入同一输入框；普通引用不误关联；明确回答保留原 Work/预算/期限和工具证据；自动化回答保持 occurrence/所见等待版本/原问题消息且普通发送不解锁；提交后丢回复、切会话、重启与清理不重复消息或重放业务；原审批拒绝/过期门禁和固定版本资格/修订/采用继续可用。
