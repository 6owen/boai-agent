# IM-07：可运行团队模板

状态：待实施 / 待验收。优先级：P1。

2026-09-30 职责调整：当前优先实施 [第 9 组团队创建助手](../9.团队创建助手/README.md)。本文件保留“可运行场景模板 → 首次真实成果”的目标；通用方案生成、预览编辑、员工/群批量创建及恢复，以第 9 组为唯一合同。将来固定模板也转换成同一种方案，进入同一个创建服务，不另建模板专用创建器。T1 创建功能不依赖本文件的成果验收闭环。

目标：新用户不必编写系统提示词，也能完成第一项真实工作。

首批范围：将已通过验收的“资料研究→写作→核对”场景配置为一个模板，包含角色、工具需求、输入说明、输出格式及检查清单；再按用户需求扩展内容生产或表格分析。

- [ ] 创建前显示将新增的员工/群及必要配置，复用用户选择的模型连接，不复制凭据。
- [ ] 缺工具、缺依赖或待授权时指向具体补全入口，不能一键创建后伪装为全部就绪。
- [ ] 模板不会自动安装执行程序、扩大授权或运行示例任务；实际运行来自明确用户请求。
- [ ] 用户能修改角色、材料与交付要求；模板更新不会覆盖已编辑的员工配置。
- [ ] 新用户以自己的材料完成真实成果闭环，记录首次交付耗时、介入次数和未完成原因。

## 首次使用路径

第 9 组先在通讯录提供“创建团队”，现有“新建员工/创建群聊”入口继续可用。本组后续可增加“从场景开始”，提供已经验证的研究报告模板并进入同一个方案预览；不展示尚不能运行的能力作为已就绪模板。

| 步骤 | 用户看到什么 | 系统做什么 |
| --- | --- | --- |
| 选择场景 | 适合处理的任务、输入示例、最终成果样式 | 加载固定版本模板 |
| 选择模型 | 已有连接与必要能力要求 | 复用连接，不复制凭据 |
| 检查工具 | 所需技能/网页能力/依赖与权限 | 只读检查，缺项解释清楚 |
| 确认创建 | 将创建的员工、群聊及明确绑定范围 | 一次受理创建计划并保存结果 |
| 交材料 | 当前场景的输入提示与附件入口 | 使用普通消息与任务通路 |
| 首次交付 | 实际报告预览与修改/采用 | 使用 IM-03 既有成果流程 |

模板可以给出提示词和检查标准，但不绕过实际授权。创建配置不自动启动示例任务；用户点击发送后才执行，付费用量来自真实任务预算。

## 模板包内容

建议固定版本模板包含：场景身份、名称、适用问题、必要输入、交付格式、成员角色建议、工具/模型能力要求、检查规则与模板版本。系统创建出的员工配置记录来源模板版本，后续由用户独立编辑。

不把用户 Key、个人目录路径、历史聊天或记忆放进模板。首批本地内置模板即可，不建设第二个模板市场，也不将组织层级作为强制配置。

## 创建与失败恢复

用户在最后一步明确确认将创建哪些对象；重复提交同一请求不得重复生成三名员工和两个群。数据库提交前验证全部引用；文件初始化失败应保留可解释的未完成记录并可安全清理，不显示为就绪。

具体状态、冻结载荷、ID 映射、文件准备和原子发布以 [第 9 组批量创建与故障恢复](../9.团队创建助手/04-批量创建与故障恢复.md)为准。本节只保留模板场景的要求，不维护第二份协议。

返回上一步保留草稿；放弃创建不残留半套可见配置。已经创建成功后再打开模板，显示现有结果入口，并允许用户明确创建另一套，不依赖名字相同推断重复工作。

## 模板更新

新模板版本只影响后续创建。已有员工的角色、技能和权限不被覆盖；如果以后支持升级，必须展示实际差异并由用户选择应用。删除模板不应让现有员工无法工作。

## 新用户验收

给未参与开发的人一个真实资料任务，只提供模板入口和材料，不替其手工改配置。记录哪些步骤卡住、是否理解共享范围、是否知道成果在哪、是否成功修改和采用。不能以“员工创建成功”作为首次使用完成。

实施复用[现有角色模板](../../../apps/electron/src/renderer/components/employee/editors.tsx)、[创建弹窗](../../../apps/electron/src/renderer/components/employee/creation-dialogs.tsx)与员工/会话用例；能力检查调用 IM-04，不复制另一套检查逻辑。
