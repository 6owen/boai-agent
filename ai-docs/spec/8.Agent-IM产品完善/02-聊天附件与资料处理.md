# IM-02：聊天附件与资料处理

状态：待实施 / 待验收。优先级：P0。

目标：用户直接在聊天里交材料，不必手工复制整份文档。

首批范围：文件选择/拖入、粘贴图片、TXT/MD、文本型 PDF；显示上传/解析/可用/失败状态。图片必须通过实际支持的模型或解析能力处理；不支持时明确反馈。扫描 PDF 的 OCR、Word 与 Excel 作为后续格式扩展，不混入首批完成声明。

- [ ] 消息保存稳定附件身份及受管文件关联，重启后仍能定位；不能只保存临时路径。
- [ ] 模型实际获得获准且可处理的材料，失败不能静默变成“已读取”；超限与损坏文件有明确反馈。
- [ ] 文本引用能回到原文件及页码或适用的片段位置；无页码的来源不编造页码。
- [ ] 群成员按明确共享范围读取，撤权后不继续获得材料；外部 ACP 不自动继承附件授权。
- [ ] 附件及派生内容参与既有清理、备份与恢复；文件重复名、丢失、取消导入都有可验证行为。

## 用户流程与组件

入口保留输入框加号，增加“添加文件”；支持拖入聊天输入区域及粘贴图片。拖入时显示明确落点，未确认的文件留在当前会话草稿。不要因为光标经过另一会话就改变归属。

附件以紧凑文件条显示名称、类型、大小和状态；图片可显示缩略图。提供移除、查看解析问题和重试解析。点击“发送”提交正文与已就绪附件的稳定关联；首批存在未完成或失败附件时阻止发送，并让用户重试或移除，不能悄悄忽略材料。

已发送附件出现在原消息内。点击进入该会话自己的材料详情，展示预览、解析说明、共享范围及来源定位。附件名称不承载本机完整路径。

## 状态与失败处理

| 状态 | 含义 | 用户操作 / 后续 |
| --- | --- | --- |
| 草稿 | 只选择了文件，还未成为已发送材料 | 移除或开始导入 |
| 导入中 | 复制受管文件并检查格式/大小 | 取消；不发送半成品 |
| 解析中 | 提取文本或准备图片输入 | 等待、取消 |
| 就绪 | 原件与派生内容可供获准处理 | 预览、发送 |
| 不支持 | 类型或成员能力不满足 | 换格式/成员或移除 |
| 失败 | 损坏、超限、权限或解析故障 | 查看原因、显式重试或移除 |
| 不可用 | 已清理、已撤权或文件失效 | 保留非敏感失效提示，不伪装正常 |

附件就绪只说明系统能够交给获准处理链，不意味着每位员工已阅读。发送后的引用和阅读证据要来自实际执行。

## 格式规则

| 格式 | 首批行为 | 引用方式 |
| --- | --- | --- |
| TXT / MD | 有界读取并保存解析版本 | 文件名 + 稳定段落/片段位置 |
| 文本型 PDF | 提取可复制文本，保留页映射 | 文件名 + 页码 + 引文片段 |
| PNG / JPEG / WebP | 校验并提供真实图像输入能力 | 原图 + 可用的区域/说明；不编造页码 |
| 扫描 PDF | 没有 OCR 时明确不支持该内容 | 不用空文本宣称解析成功 |
| DOCX / XLSX | 本轮后续扩展 | 明确章节/工作表等定位后再开放 |

具体单文件、单消息数量和解析资源上限在实施时根据实际模型/解析器能力制定，归统一常量并在界面显示；不在图稿中伪造已支持的容量。PDF 解析器和图片处理依赖须有实际可运行验证。

## 共享、上下文与引用

上传会话材料不自动授予所有员工访问。沿用员工绑定与群共享的授权原则，提交前显示将共享给哪些成员；首批材料仅在本会话指定范围内生效，进入长期知识库需要另外明确操作。

模型输入携带稳定材料身份及已授权内容。正文提到文件名不等于获得文件权限；同名材料按不同身份区分。长文按有界片段提供，模型引用需对应实际提供的内容；不能只把文件路径拼进提示词就算完成接入。

资源版本或授权改变时，旧解析缓存不能绕过新校验。外部 ACP 当前没有相应能力契约时，给出不支持提示，不自动复制到它的工作目录。

## 数据与生命周期

消息和附件关联一并提交；用户因响应丢失重发相同请求不能重复生成两条消息。草稿导入与已发送材料分开记录，取消/遗留草稿有确定清理策略。原件、提取文本、页映射、缩略图、搜索索引均纳入同一清理范围。

清空聊天先失效访问，再删除文件；文件清理失败沿用持久清理记录。备份包括已发送材料及必要解析版本，不包括临时处理中间文件或外部凭据；恢复后校验路径与解析版本，不重放模型任务。

## 验收补充案例

- 两份同名 PDF 保留不同材料身份与来源；重启后引用仍指向正确文件。
- 一份解析失败时发送不能丢掉它而照常开始任务。
- 只获准第一份材料的员工不得获得第二份材料的文本、缩略图或搜索摘要。
- 清空聊天后，预览、缓存、引用、搜索均不能读回原材料。
