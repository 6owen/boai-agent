# IM-03：产物预览、修改与采用

2026-10-03 当前交互：审批与采用/稍后处理均在原员工聊天消息完成，要求修改进入同一composer；右侧只读预览Markdown、Shiki代码与普通文本。宿主按原件/hash核对，预览独立限制1MiB、20万字符、1万行，HTML/SVG只显示源码，预览不改变模型材料解析或正文索引。原侧栏操作说明由本条覆盖，实际验证统一见[第10组实施清单](../10.真实工作交付闭环/05-实施步骤与验收清单.md)。


状态：Markdown/Shiki 只读预览及原聊天版本动作已接入，实际验收以第 10 组记录为准；PDF 预览、差异比较等扩展不因本文列出而视为已实现。优先级：P0。

目标：用户在应用里检查结果，围绕明确版本提出修改，并留下采用记录。

当前范围：Markdown、代码及普通文本的只读预览；图片沿现有图片查看入口；同一成果的明确版本关联；针对指定版本要求修改；原交付消息的“采用此版本/要求修改/稍后处理”。PDF 等格式按实际支持显示，不能把二进制原件登记当成已支持预览。暂不建设完整 Office 在线编辑器。

- [ ] 预览展示真实已发布文件，格式不支持或文件失效时明确说明；不通过预览重新执行任务。
- [ ] 每个版本能定位作者、任务与源消息，保留旧版；文件不能因同名而被静默覆盖。
- [ ] 修改请求携带明确产物版本，避免用户评论旧版却被应用到新版。
- [ ] 用户采用独立于运行完成与工作声明交付；旧版采用记录不会自动继承到新版。
- [ ] 已交付工作保留原结果，返工作为显式修订请求关联；实现前明确工作与预算归属，不能隐式复活人工停止工作或重置耗尽预算。
- [ ] 重复确认不重复写入；确认失败、重启、清理和恢复后状态仍与真实版本一致。

## 界面与主流程

点击消息中的产物或现有“任务与产物”文件行，在本页面的右侧详情标签打开预览；同一成果复用对应标签，切换到其他主页面不暴露这份标签。后续会话“文件”主视图复用同一固定版本预览入口，规格见[员工协作工作视图](./12-员工协作工作视图.md)，该主视图尚未实施。宽度不足时由用户打开/收起详情，保持现有手动宽度规则。

预览标题显示成果名和版本，下方是作者、发布时间、本版实际审核信息与源工作入口。正文使用已支持的受控预览；右侧只承载内容、版本与来源记录，提供返回原交付消息的导航，不放审批、采用或修订表单。用户在原员工交付消息卡片采用、稍后处理或要求修改。打开文件、下载文件、阅读消息都不自动采用。

“版本”入口列出历史版本、关系和采用记录。后续可增加文本可读差异及图片/PDF版本切换，按独立格式/比较切片验收；首批不承诺像素或语义差异分析。没有历史版本时正常预览，无需空的大型版本面板。

## 版本与审核语义

| 对象 | 负责表达 | 不代表 |
| --- | --- | --- |
| 已发布文件 | 一次真实发布的不可静默覆盖文件 | 已被用户采用 |
| 成果版本链 | 哪个新版本修订自哪个已存在版本 | 文件同名就属于同一链 |
| 审核记录 | 哪位员工检查了哪一份确定内容 | 后续修订自动沿用审核 |
| 用户采用记录 | 用户在何时采用哪个确定版本 | 自动执行外部发布 |
| 修改请求 | 针对哪个版本提出什么要求 | 原运行自动重新执行 |

复用现有 Artifact 身份与工作结果版本；新增产物版本关系作为扩展，不用一套新“任务版本”替代原 Work.resultVersion。文件哈希或等价不可变内容身份用于证明审核/预览/采用对象一致，文件名和时间不是充分证据。

## 请求修改

1. 用户在原员工交付消息卡片点“要求修改”，同一聊天 composer 进入明确成果引用模式，绑定该 Artifact、逻辑身份、版号/hash 和执行员工。
2. 引用预览显示所修版本与执行员工；作者已移除或不可用时要求明确另选可执行员工，不暗中改派。
3. 用户在该 composer 填写要求并发送，用户消息、修改请求关系与稳定受理回执同事务持久化。
4. 原版与原交付状态保留；以用户显式修订请求建立对应工作，记录新旧关联与预算归属。
5. 新版发布后提示有新版本，不能静默替换用户正在审阅的旧版，也不能复制旧版采用状态。

重复提交使用稳定请求身份；失败保留草稿。修订涉及新授权、预算追加或结果不明的操作时，遵循现有显式确认与核对边界，不把“改一下文字”扩展成重新执行所有外部工具。

## 采用动作

原员工交付消息卡片的采用按钮携带成果身份、版本、内容校验值和期望采用 revision。宿主复核文件仍存在且内容一致，在事务中保存记录；提交成功后才更新该消息及相关只读投影。重复点击/回执重放应返回同一确认结果。稍后处理固定同一版/hash 与资格 revision；预览和未采用不自动生成资格，采用或修订受理在原事务结束旧版资格。

同一成果可保留多次历史采用事件，但“当前采用版本”是明确指向，不靠最后修改时间猜测。采用旧版时保留用户选择并清楚标注已有新版；不将旧版采用移到新版。撤回采用若后续确有需求应增加显式事件，首批不提供含糊的反复切换开关。

## 异常与可访问性

- 文件消失、来源无权访问或内容被外部修改时，阻止对错误内容进行采用；提供定位真实来源的入口。格式不支持只说明预览不可用，不能将预览格式支持与实际原件交付/hash 核对混为同一条件。
- PDF 或长代码横向滚动只发生在预览区域，不能撑宽聊天和发送控件。
- 键盘可进入版本选择、来源链接、原消息采用/修改和 composer 引用；预览关闭后焦点回到触发按钮。
- Markdown 与 PDF 预览不执行文档脚本；远程图片或链接不得借预览获得任意宿主访问。
