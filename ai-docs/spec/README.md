## 从这里开始

1. 了解现在有什么：[已实现功能全景](./2.已实现功能与代码现状/01-已实现功能全景.md) 与 [代码和运行目录](./2.已实现功能与代码现状/02-代码与运行目录.md)。
2. 决定下一步做什么：[重构总计划](./00-重构总计划.md)。
3. 首批已完成 [第 4 组](./4.数字员工与协作重构/README.md) 员工装配与工作区边界，下一步推进 [Sandbox 与 Skills](./5.Mastra能力扩展/03-Sandbox文件系统与Skills.md)。[第 3 组](./3.前端重构与功能/README.md) 可并行迁移前端；主题不阻塞员工能力。
4. 执行方式看 [员工执行后端](./4.数字员工与协作重构/04-员工执行后端与能力契约.md)，浏览器、ACP / A2A / MCP、自动化和记忆/工作流按 [第 5 组](./5.Mastra能力扩展/README.md) 分阶段接入。
5. 改进多员工自主接话和工作协作，看 [第 6 组 Cumora 协作重构](./6.Cumora协作重构/README.md)，已结合 Paperclip 任务机制修订。先建立行为基线与参与判断，再做 G2a 工作/run 认领和预算、G2b 并行发布，随后推进委派/依赖和按需持久恢复；这些行为变化独立于 B3 结构重构。
6. 迁入旧 boai-app 的技能管理和商店，看 [第 7 组 Skills 管理与商店迁移](./7.Skills管理与商店迁移/README.md)：源码映射、目标流程、数据/IPC 合同与 K1–K5 验收；本次仅文档，尚未实施。

## 阅读与维护规则

- 当前事实先看第 2 组。第 1 组保留旧设计，旧的“尚未开发”“下一版”只代表当时状态。
- 第 3–7 组保留完整方案；以各文档顶部阶段状态和第 2 组实现记录判断已交付范围。
- 本轮将原 `spec/` 的 16 份正文移动到分组目录，并同步项目内 Markdown 链接；参考图仍在 `ai-docs/references/`，验证图仍在 `ai-docs/images/`。
- 每个开发阶段完成后，更新第 2 组的现状与实现记录，再在对应计划勾选验收结果；失败和未验证项如实保留。
- 方案变更先注明理由、影响的契约及数据迁移，不在目录重构时暗改群聊、权限或记忆语义。
- 只建立有实际职责的源码模块；本轮创建的是文档目录，没有预建空的源码层级。
