## 阅读与维护规则

- 当前事实先看第 2 组。第 1 组保留旧设计，旧的“尚未开发”“下一版”只代表当时状态。
- 第 3–5 组保留完整方案；以各文档顶部阶段状态和第 2 组实现记录判断已交付范围。
- 本轮将原 `spec/` 的 16 份正文移动到分组目录，并同步项目内 Markdown 链接；参考图仍在 `ai-docs/references/`，验证图仍在 `ai-docs/images/`。
- 每个开发阶段完成后，更新第 2 组的现状与实现记录，再在对应计划勾选验收结果；失败和未验证项如实保留。
- 方案变更先注明理由、影响的契约及数据迁移，不在目录重构时暗改群聊、权限或记忆语义。
- 只建立有实际职责的源码模块；本轮创建的是文档目录，没有预建空的源码层级。
