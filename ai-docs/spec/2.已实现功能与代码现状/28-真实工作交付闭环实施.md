## D1：TXT/Markdown 材料实施与验收

新增材料模块保存 UTF-8 TXT/Markdown 原件、准备回执、内容 hash 和明确成员授权。上限为每份 128 KiB / 16,000 字符，每条最多 3 份 / 合计 32,000 字符，带材料正文最多 12,000 字符；准备超过五秒先挡提交，容量保留到实际文件执行退出。父级链接、硬链接、伪装二进制、解码失败、空文本和超限均显式失败，不调用模型。

原件位于宿主私有 `materials/<conversation>/<id>/original`。发送将消息、材料关联、轮次与稳定回执同事务提交。未知回复先只读核对，不重建消息；清空保留最小去重回执，旧 key 拒绝重放，新交流使用新 key。清理材料前先传播记忆屏障，hash 外改保留并使该聊天保持清理门禁；恢复返回可见冲突，其他聊天继续可用。

每阶段模型调用、文件工具、回复/产物发布和记忆复核材料授权；派生回复/产物保留材料读取证据，材料记忆限原聊天，员工根记忆文件排除会话/事项限定条目。内建文件访问承接来源门禁，显式获批宿主命令仍有既有主机权限，不能将工作目录当作安全沙箱。

备份导出只复制实际数据库快照中的已发送就绪原件，逐份复核 revision/hash/授权；目标数据库删除未发草稿与清理日志，保留最小准备去重身份。恢复只核对本地原件，不重新读取外部文件或重跑模型/工具。未发送草稿只在当前应用内跨聊天保留；重启先事务撤权/失效，再按 hash 清理，旧准备请求返回原不可用回执，不重造原件。外改原件保留并记录冲突，不再进入模型或预览。

UI 在已有聊天加号和拖入落点提供材料条、失败原因、移除/重试、明确共享与独立原文标签。消息引用以材料 ID、解析版本、revision/hash 和实际行范围核对后定位，不能凭同名或模型声明建立链接。发送载荷冻结并跨聊天保留；回复失联先查原消息回执，后续新草稿不能替换原请求。隐藏标签不继续读取，清理或授权变化立即失效旧文本。

材料专项 31 项真实 SQLite/文件测试、宿主材料专项 16 项、Mastra 文件工具 79 项均通过；文件工具新增 11 项来源门禁断言。最终 D1 回归首次发现一项评估测试把预留的 fetch 尝试当作 HTTP 到达数量（34 次尝试/33 次到达）；仅修正测试，逐项验证真实原 fetch、预算、持久回执及未到达项取消错误，保留原评分/产物/事件和密钥断言，预算及评估 harness 没有改动。

## D2：成果版本、明确修订与本人采用

新增 ArtifactRepository 作为成果内容关系与采用的 SQLite 权威；发布文件保留 UUID，宿主复制时的 hash 必须与登记读取的实际字节相同。逻辑成果、内容版号、明确前版与修订请求独立于 Work.resultVersion / requiresReview；同名发布不推断为同一链。每份最多 20 MiB，首批 Markdown 预览最多 1 MiB / 200,000 字符，修改要求最多 12,000 字符。非 Markdown 仍可凭真实原件证明文件交付，预览和采用明确提示格式不支持。

消息、单聊/群聊任务详情复用成果预览标签。标签固定用户所见 ID/hash，版本在同一逻辑家族内明确选择；新版发布只提示，不替换旧正文或迁移采用。来源按钮按真实材料引用/行范围核对，源消息精确定位；有真实源工作才提供工作入口。本版未记录审核明确显示未记录，不从旧工作或旧版推断。

用户修订是独立的本人新请求：消息、关系、受理回执同事务，执行员工明确选择。WorkRepository 原子建立新根身份与预算，保留旧交付和 occurrence；模型沿用旧 Work 的尝试被宿主纠正为本次新根。只有指定根负责人使用宿主 revisionRequestId 才能发布替换版；子工作和支持资料不能取得替换归属。每阶段与工具前再次核对原版和材料来源，完整要求在用户消息中保留；引擎投影的 16,000 字符原文节选明确注明截取，其余可由获准工具读取。

采用固定 senderType=user / senderId=user，所见 hash 和预期采用 revision 经核对后，同事务保存事件、当前指向和稳定回执。重复同版不增加事件，选择另一版保留历史；打开、复制、外部打开和新版发布不自动采用。未知修订/采用在现有页面作用域和本地草稿中保留原载荷/key，关闭或重启转为 unknown，只读核对原回执；确认无回执才允许原请求重试或明确放弃，后来的版本/字段不覆盖原请求。失败立即清除旧正文，再按固定原版 hash 核对。

受管原件拒绝链接、硬链接、读取中身份/字节变化，读取材料来源需当前授权。新增宿主 readTaskFile 回调让已登记 shared 成果的 read_file 直接使用 hash 校验所得字节，避免 bool 许可后重新打开文件读到另一份正文；确定性外改 canary 验证原已核字节返回、下一次读拒绝。已发布 JSON 监控兼容可信根的系统别名，核对登记 hash，读取前后复核选定材料来源；失效不回退旧 JSON，不推进检查点，不运行模型。

历史目录无登记文件只在启动执行前受控导入为独立成果。活动列表不把复制但尚未发布提交的文件当历史成果，确定性暂停复制→登记测试只得到一次实际发布。清理先持久门禁，再删除关系/历史/正文，只保留最小去重身份；核对时外改保留并使聊天保持门禁，其他聊天继续可用。恢复搬迁路径、版本和采用回执只核对，不续行未完成修订或重放工具。采用和清理是核对时的内容判断，SQLite 不锁定外部进程文件写入；最终核对后并发外改仍可能使已记录版本失效，不能承诺数据库和外部文件跨进程原子。

Renderer只在当前主页面活跃、文档可见、窗口有焦点且消息行与滚动容器实际相交时，提交当时的 `messageId/ordinal/epoch/contentHash` 快照。宿主同事务核对完成身份、当前正文/来源及预期阅读revision；连续boundary仅推进实际见到的连续完成事件，较晚消息记入sparseSeen并保留未见缺口。每次最多80项、缺口最多256；超限显式拒绝，不能删除缺口或把后续历史全部标已读。

首个未读由当前epoch、完成ordinal、连续边界和缺口共同确定，界面提供“返回未读/查看最新消息”。稳定消息锚点和有界offset使用独立anchor revision条件更新，保存位置不推进已读，迟到位置不能覆盖新值。阅读与位置失联先只读核对，重新实际交互才采集新快照，不自动重发旧载荷；本地手动滚动和贴底跟随分别处理。

已有但无可信完成事件的旧员工完整回复只标 `legacyCompletedUnknown`，不给一万条旧历史补造已读/未读；空会话无此提示。清理在原最终事务删私人完成/阅读记录，保留最小clock并提升epoch；旧页面的观测和位置不能复活已清空正文。备份和重启只恢复、核对已提交边界/缺口/锚点，不调用模型、创建Work或重放工具。
