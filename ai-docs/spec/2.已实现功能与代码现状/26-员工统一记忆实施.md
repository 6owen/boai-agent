# 员工统一记忆实施

日期：2026-09-30。本轮实现及验收记录，唯一进度见[第 9 组 08](../9.团队创建助手/08-实施步骤与交付清单.md)。T3 未实施；下文不预填通过成绩。

## T2.1：合同与原子记忆仓库

- 新增独立 memory 领域合同，兼容旧 profile/conversation；新员工记忆另用 employee 范围，来源与使用范围分开。
- MemoryRepository 改为 SQLite 事务读检查写，不再依赖本进程缓存；增加请求回执、员工失效版本、忘记屏障、纠正/派生来源失效与有限维护。
- 新版本启用记录原子且幂等；旧记忆不重写、不自动扩权。旧管理接口仍能读取原命名空间。
- 新增真实 SQLite 多连接、事务失败、幂等、忘记/纠正、派生失效及生命周期的意图测试。
- 实际验证：项目 pnpm 入口尝试联网获取运行器失败，未执行测试。使用已安装 Node 与项目本地入口运行：`node node_modules/typescript/bin/tsc --noEmit` 退出 0；`node node_modules/vitest/vitest.mjs run tests/memory-repository.test.ts tests/agent-homes.test.ts` 两文件 19 项通过（520ms）。原始[模块日志](../9.团队创建助手/evidence/t2-repository.log)与[类型日志](../9.团队创建助手/evidence/t2-types.log)已归档。
- T2.1 存储与兼容边界通过；模型/宿主跨会话接线、界面与完整 T2 验收尚未交付。

## T2.2–T2.3：增量协议与统一召回

- Mastra 候选保留类型/证据/临时范围/到期和明确纠正版本；宿主只接收本轮合法消息，继承员工自身消息的原始来源、资源和最严格范围。候选未授权事项/纠正拒绝，自动化维护仍用原 occurrence。
- 模型各阶段读取同一有界召回；员工私聊和群聊消息获知回执与已发布回复同事务保存。后台整理前可以用合法原文即时接续；旧库启用前消息不自动扩权。
- 硬范围/来源/时间过滤先于相关排序，完整条目携带归属/来源并以 UTF-8 字节保守预算裁选。固定不越权，历史不作为当前事实。
- 实际验证：宿主/工作区/仓库回归三文件 110 项通过；真实 SDK 协议 67 项通过；新纯召回与仓库 17 项通过；新宿主六例通过（双向即时/隔离、迟到发布、纠正/临时、忘记/外部修改、退出源群和备份）。整体质量还需 T2.6。
- 首次真实 UM-v1 12 步完成，22 次调用/4,916 输出 token。原文接续和限制有效，但整理把即时原文误当持久去重背景，导致候选未落库及非法片段纠正；到期项未建立，不能计通过。修复：memory 阶段只把持久条目作为去重/纠正背景，即时片段仅供交流阶段使用。保留首次失败记录，修复后需重验。

## T2.4：生命周期与真实中断

- 到期在读取、工具前和发布时核对；空闲一分钟只执行确定性到期/90 日经历归档，不调用模型。来源撤销/退出/清空传播到记忆、派生来源、获知回执和运行快照。
- 删除/收紧事务同时登记派生文件待清理；启动/恢复再次核对，仅删除 hash 匹配的生成文件。外部修改保留并报告，模型工具不读取这些系统投影。
- 真实 SIGKILL 在整理事务提交前和提交后分别验收：未提交摘要回滚，提交后摘要完整保留；重启将维护运行标为中断，没有模型/工具重放。与新增宿主/仓库/纯召回合计四文件 25 项通过。
- 备份恢复恢复备份时的历史状态，备份之后的忘记操作不跨备份保留；新安装启动重建派生物，明确此恢复语义。

## T2.5：统一管理

- 新 MemoryPane 支持来源、类型、有效/历史、搜索和游标分页；编辑使用范围/事项/有效期/归档，固定/忘记，旧会话条目提升必须明确勾选。版本冲突保留草稿，无常驻查询轮询。
- 群设置和记忆来源聊天均可设置新交流范围及可选事项关联；收紧即失效，放宽不升级旧条目。员工文件导入仍需明确选取片段，不把生成视图当权威。
- 类型检查、UI 规则和完整构建通过；构建原有大 chunk 提示保留。真实 Electron 三场景通过（22.5 秒）：新记忆管理、旧员工 Tabs、群设置。

## T2.6：综合核对与质量记录

本轮实施范围为 T2.1–T2.6。员工 ID、会话/工作区、分类、Work/预算和原 occurrence 归属保留。原生 Mastra Memory、向量数据库、GameSession、主持/投票/胜负均未引入，T3 未实施。

最终团队能力说明与无工具助手提示词升级到 planner v5：如实说明新交流的同员工接续、来源/范围/旧数据边界和 T3 未支持；旧 v4 模型输出与用户认可仍是历史证据，不改写。

### 真实模型 UM-v1

固定 12 步合成数据，模型 deepseek-flash / api.deepseek.com，通过真实 AppService + Mastra chat/extract 执行；参与决策固定为普通聊天，只评记忆与回答，不评路由或正式游戏。每批最多 32 次请求、20,000 输出 token、12 分钟；不自动追加预算。只读现有连接和凭据，凭据仅内存注入；员工/会话/文件均在隔离目录，不修改日常聊天。

| 批次 | 步数/调用 | 输入/输出 token | 判断 |
| --- | --- | --- | --- |
| 首次 | 12 / 22 | 44,045 / 4,916 | 失败：即时片段被当作已持久去重背景，候选未落库/非法纠正 |
| 第二次 | 12 / 22 | 33,471 / 9,787 | 失败：整理提交后误取消自身；临时身份误收窄为来源私聊，群未正确回答 |
| 修复后 | 12 / 22 | 35,086 / 3,180 | 来源/接续/纠正/范围/临时有效性样例通过；到期回答历史表述部分偏差 |

三批全部用量已知，失败不覆盖。修复把持久事实与即时片段分开、提交成功的维护 run 保留成功、提示词区分临时性与“仅此聊天”。最终群答分别使用“同学”“探索者”和“女巫”；仅此聊天 canary 未进入该步实际群 Trace；到期调用无旧身份条目。
