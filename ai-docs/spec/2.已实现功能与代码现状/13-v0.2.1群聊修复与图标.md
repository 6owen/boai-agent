# v0.2.1 群聊修复与图标

日期：2026-09-27。对应用户反馈：群聊问候只有一名员工回复；去掉“最近会话”标签；使用 Carbon / Solar 图标。

本文保留 v0.2.1 的交付记录。完整历史群聊场景的续修及当前 v0.2.2 验证见 [14 历史群聊与本轮边界](./14-v0.2.2历史群聊与本轮边界.md)；下文空白新群验证不能替代已有群完整历史验证。

## 1. 问题与修复

已有群聊记录证实三名员工均已配置模型。研究员把参与判断请求回答成了普通问候，随后 JSON 解析失败；审核员遗漏 `observedThroughSequence` 而校验失败。旧界面仍显示“本轮已完成”，让协议错误看起来像员工正常选择了沉默。

成员判断现使用独立的私有控制请求：员工身份、允许的记忆继续装配，群聊历史按带署名的数据传入，不再把它作为本次待续写的聊天。请求附完整 JSON Schema；宿主根据输入快照填写观察序号。仍由每名员工自己的模型选择 reply、pass、wait、ask 或 handoff，不将自然语言错误输出自动当作 reply。

格式或语义校验失败最多请求同一模型修复一次，额外调用先申请轮次预算，首尝试和修复用量累计记录；取消、超时和用量限制仍生效。鉴权或网络错误不会触发格式修复。

调度保留每名成员针对原始用户消息的首轮投递，较快成员的公开回复不能将其替换。全群问候中，每人都可按自己的身份简短回应；已有其他员工问候并不代表自己已回应，也不强制所有员工开口。新消息到达后，真正需要更新的发言意愿仍重新判断。

有未恢复的判断或执行失败时，轮次显示失败并保留已有回复。后续合法判断可恢复旧判断错误；执行错误必须有后续成功回复才算恢复。错误历史不删除。启动也会修正旧版本的错误聚合状态，不重发历史消息。

## 2. 前端

- 接入 Tailwind CSS 4.3.3、`@egoist/tailwindcss-icons` 1.9.2、Carbon 1.2.28 与 Solar 1.2.13，按指定 Tailwind Iconify 技能配置。
- 用本地静态类映射替换全部 Lucide 图标；31 个图标的 SVG mask 在构建时写入 CSS，无运行时图标网络请求。构建依赖不加入应用运行包。
- 移除“最近会话”标签，默认直接展示消息列表；数字员工保留单独入口。
- 列表按真实 `lastMessageAt` 及实时消息时间排序；编辑设置不能顶置，没有消息的会话排在已有消息之后。
- 当前成员状态按员工汇总，避免一名员工的历史投递重复占多行；详细错误保留在可展开的运行记录中。

## 4. 边界

群聊是成员独立参与，不承诺每条消息所有员工都会回复。选择 pass 与模型协议失败是不同状态。单轮仍遵守调用次数、公开贡献次数、接续代数、时间与用量限制。定时任务执行等 v0.2 未实现范围维持原约定。

框架 API 按项目安装版 Mastra 文档与类型核对；补充参考：[Mastra 结构化输出](https://mastra.ai/docs/agents/structured-output)、[Tailwind Iconify 插件](https://github.com/hyoban/tailwindcss-icons)。本版为兼容自定义模型代理，使用显式 JSON Schema 提示与宿主校验、受控修复，没有增加第二个协调模型。
