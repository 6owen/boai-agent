## 协作基础的已实现范围

- G1：同轮 agent 事件合并保存完整 `eventIds` 和接替投递 ID；不跨用户轮次合并。连接级 FIFO 容量为 3，跨 decision/execution/memory 和会话共用；仅只读阶段对结构化 429 最多退避重试 2 次，任务执行不自动重放。
- 等待、执行阶段与退避分别记时。`executionMs` 包含任务阶段的工具等待，不冒充纯模型推理时间。阶段超时在连接准入后开始，排队仍受轮次取消/时间边界控制。
- G2a 基础：新增 `workItems`、`workExecutions`、`workBudgets` 和 `collaborationSchema/work=1`。工作身份来自会话、原始消息和显式 key，负责人独立于当前运行；旧模型遗漏 work 时按整项请求 `main` 保守认领，不能按员工身份复制任务。
- `ProductStore.transaction` 使用 SQLite `BEGIN IMMEDIATE`，在同一事务检查工作/版本/负责人、预留最低调用和运行额度、取得执行权。旧 run 的迟到释放和提交不能修改后继持有者。
- 原请求的工作共享预算，初始上限 24 次模型阶段/续步、8 次执行、16,000 已报告输出 token 和 5 分钟；用户重试不重置。工具续步经 Mastra `prepareStep` 预留，计数不宣称精确供应商 HTTP 请求数。未知用量保留未知，已知部分作为下界累计。
- 真实副作用前持久记录核对标记；标记失败不执行文件/产物/命令操作。已有副作用的失败工作需要核对，不允许一键重放。重启中断持有中的工作，不自动恢复。
- `report_work` 声明业务 disposition；交付必须引用本次已登记产物或最终答复的实际摘录。未声明结果且没有登记产物的成功 run 记 `no_progress`；有真实登记产物可记 `progress`，两者均不冒充已交付。该结构声明仍需真实模型评估，不代表宿主能判定所有语义真实性。
- 发布记录与工作结果/执行权释放同事务提交，提交后才确认公开事件和投递成功。先通过串行认领回归后接入 G2b：任务草稿私有、完成时分配消息序号、检查权限和新消息，随后与工作结果原子提交。
- G1 输入精简仅省略空 mentions、缺省 turnId 和 false 根标记；可重建成与原表示完全相同的元数据，正文、身份、顺序、时间和引用均保留。确定性测试验证序列化变小；没有宣称真实模型的成本/质量收益。
- G2b 两项独立任务共享进程级准入；同员工会话文件互斥；允许宿主命令的任务与全部任务互斥。任务开始前再检查是否被新用户轮次接替。资源占用等执行适配器实际退出再释放，取消不会让未退出操作与后继任务重叠。
- 过期草稿用无工具的 `private-work-report-v1` 读取实际新消息，最多重述两次；计入原工作调用与用量预算，不重放已完成操作。不支持汇报、主动放弃或达到上限时持久保留草稿及阻塞原因。
- 界面区分“本次运行结束”和工作已交付/进展/等待/阻塞，展示未发布结果与各类等待时间；需要核对副作用的工作不提供直接重放按钮。
- 已就绪回复先获得进入共享模型队列的机会，再补充后续判断，防止其空位被下一批判断占满；6/12 人首次机会和合法 pass 继续覆盖。
- 工作及结果仅在当前员工可见原请求和结果消息时进入模型上下文。备份复制验证保留旧 Contribution 原含义，不把历史 completed 转成业务验收。

### G3 实现与回归检查点（2026-09-28）

- 工作格式升为 `collaborationSchema/work=2`；原 v1 工作补齐依赖字段，预算补齐控制计数，历史 Contribution 原含义保留。隔离 SQLite 副本验证已交付工作可读取、等待/就绪工作和未消费通知在重启后中断；原数据库保持不变。格式 1 的工作读取器拒绝格式 2。回退到不支持工作协议的更老版本时必须恢复升级前副本，不能让旧调度器消费当前数据。
- `delegate_work` 按父工作与显式 key 幂等拆分，保存长期负责人、父/root 身份；同 key 不允许改目标或负责人。拆分关系不隐含等待，子工作交付不自动完成父工作。
- `wait_for_work` 保存显式依赖、最低已交付结果版本、接续目标及等待周期。依赖图校验与登记同事务，拒绝跨会话和环依赖；等待提交后释放执行权，结果不足继续等待，失败/取消/中断使依赖方阻塞。
- 结果、等待状态与 `workWakes` 定向通知同事务写入；通知按工作/等待周期/目标版本/类型幂等。通知接纳和实际运行消费分别持久化，只有原负责人可执行一次；下一等待周期有新身份。阻塞通知进入界面，不自动执行依赖成功路径。
- 定向接续通过已有群聊调度器创建单收件人的内部轮次，复用资源和模型准入，不进行全群判断，不把自身评论或感谢作为工作唤醒。新用户轮次优先；排队的接续真正启动前刷新最新用户上下文。公开结果按提交顺序分配序号。
- 根请求与全部子工作共享 24 次工作模型阶段/续步、8 次运行、16,000 已报告输出 token、5 分钟总期限，并额外限制最多 8 个工作项、3 次显式失败重试、4 次报告刷新及 3 次无进展结算。单次运行最多两次报告刷新仍保留。新 key、子工作和新 run 都不能清零这些计数；运行额度不足会终止待处理通知，避免重新入队循环。
- 文件写入/发布产物/批准后的命令执行先登记效果，再确认已知完成。未确认效果需人工核对；正常等待接续携带同一工作中已完成的工具记录，明确禁止重放。权限变化使对应工作树/通知失效；单独停止只遍历父子树，不取消另一个根工作的共享依赖。
- 活动区显示负责人、父工作、依赖版本、下一步、业务结果和阻塞/重启原因，并提供“停止此工作及子工作”。普通会话停止仍覆盖整个会话。
- 新增 `collaboration.feature` 两个真实 Electron/Mastra 场景：委派检查后负责人汇总（3 次执行、8 个模型步骤、一个根预算）以及等待第二版结果时从 UI 停止并重启；原 13 个迁移场景继续执行。
