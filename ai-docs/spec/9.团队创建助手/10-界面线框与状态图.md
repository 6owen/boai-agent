## 3. 创建中与失败

```text
正在创建你的团队

✓ 已确认成员配置
… 正在准备成员工作区
  保存员工与群聊

暂未完成，成员会在全部创建成功后出现。
[收起]
```

不展示拍脑袋的百分比。阶段状态来自真实日志，不能在前端按计时器推进。收起保持后台操作；放弃创建从明确操作菜单进入。

```text
创建中断，尚未完成
小研的工作区准备失败。已保留本次方案和创建进度。

[继续创建] [放弃并清理] [查看详情]
```

若结果是路径冲突或清理失败，替换为对应文案和动作；不能把所有失败都写成“网络有问题”。详细诊断可包含可定位文件，但主流程不要求用户理解事务、hash 或操作 ID。

## 5. 用户流程图

```mermaid
flowchart TD
  A[通讯录：创建团队] --> B{是否有未结束草稿}
  B -->|有| C[恢复草稿或处理创建中断]
  B -->|无| D[填写需求与模型]
  C --> D
  D --> E[生成并校验方案]
  E -->|需要调整或失败| D
  E -->|成功| F[编辑成员和建群选项]
  F --> G[明确创建]
  G --> H[文件准备与原子发布]
  H -->|未完成| I[继续或放弃清理]
  I -->|继续| H
  H -->|成功| J[查看真实结果]
  J --> K[用户进入群聊或私聊]
  K --> L[用户发送第一条消息]
```

恢复入口若绑定已受理操作，直接进入操作状态页，不回到可编辑表单；图中的“恢复草稿或处理创建中断”包含这两个分支。

## 6. 创建状态图

```mermaid
stateDiagram-v2
  [*] --> accepted: 确认并原子受理
  accepted --> preparing: 领取准备操作
  preparing --> ready_to_commit: 文件全部核对通过
  ready_to_commit --> committed: 全对象与回执同事务提交
  accepted --> interrupted: 退出或中断
  preparing --> interrupted: 退出或中断
  ready_to_commit --> interrupted: 发布前中断
  preparing --> needs_attention: 归属或内容冲突
  interrupted --> preparing: 用户明确继续并领取
  needs_attention --> preparing: 用户处理后重新核对
  accepted --> cancelled: 取消且清理完成
  preparing --> cancelled: 取消且执行器退出并清理完成
  ready_to_commit --> cancelled: 取消先于发布且清理完成
  interrupted --> cancelled: 明确放弃且清理完成
  needs_attention --> cancelled: 冲突处理后清理完成
  committed --> [*]
  cancelled --> [*]
```

取消处理中仍保留当前状态与取消门禁；清理未完成时进入 needs_attention/显示 CLEANUP_REQUIRED，不提前到 cancelled。committed 之后无“继续创建”转换。

## 7. 布局和无障碍

- 复用现有语义颜色、字体、Card/Input/Button/SelectField 和图标；不引入新颜色函数或另一套 UI 主题。
- 列表/详情宽度遵循现有可调分栏；窄宽度下表单单列，成员规则可折叠，底部动作允许换行。
- 标签属于通讯录；跨页面不显示、不操作另一页的创建草稿。
- 生成结果完成后把焦点移到方案标题/摘要；校验失败聚焦首个错误字段。
- 生成/创建状态用可访问状态文本播报，按钮忙态防连点，但宿主仍有幂等保护。
- 停止、放弃、重生成覆盖编辑这几种动作含义不同，不混用“取消”一个词。
