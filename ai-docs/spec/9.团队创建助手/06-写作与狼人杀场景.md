# 写作与狼人杀场景

状态：写作创建属于 T1；跨会话经历属于 T2；正式狼人杀属于 T3。下列样例是验收输入与设计示例，不是已生成的真实员工或游戏成绩。

2026-09-30 修订：用户希望私聊告知同一玩家本局女巫/狼人身份后，玩家回到群里仍然知道，并由主持继续游戏。T2 先交付 [05](./05-员工身份与连续记忆.md)/[13](./13-T2员工统一记忆修改方案.md) 的员工统一记忆；T3 原“无女巫、私聊只允许暂停采访且不影响游戏”的假设不覆盖最新目标，相关旧基线在下文明确降为历史参考。此次不实现或冻结新的完整游戏规则。

## 1. 写作：第一条完整产品路径

输入：“帮我创建一个写科技公众号的四人团队，有人找选题、有人整理资料、有人写文章、有人审稿。”

预期方案示例：

| 成员 | 职责 | 初始规则要点 |
| --- | --- | --- |
| 阿策 | 选题与读者定位 | 先明确受众、角度与提纲，不替所有成员代言 |
| 小研 | 梳理材料与事实 | 区分事实、推测与缺失资料；无网页能力时不假装联网 |
| 阿文 | 撰写与修改 | 根据材料和已确定方向写作，缺事实用待核对标记 |
| 小审 | 审稿与具体建议 | 核对事实、结构和表达，说明修改依据 |

成员名称可以不同，评价分工和规则，不把示例名字写成模型正确答案。用户把“小审”改名并调整规则，创建后必须保存修改后的内容。

默认建群“科技写作组”。群目的和协作建议可见，首次进入没有虚假的历史或自动欢迎词。用户发送“先各自介绍一下”，走普通 chat，不创建 Work。之后用户粘贴一段材料要求生成提纲，按现有 chat/task 判断与工作合同处理，不由团队创建模块发号施令。

首个演示只使用现有文本消息和能力；不依赖尚未完成的 PDF 附件、联网搜索或产物验收。文件任务仍使用真实工具和发布能力，不能为了展示完整流程伪造文件。

## 2. 写作与记忆的阶段差异

| 动作 | T1 | T2 |
| --- | --- | --- |
| 群里点阿文，再私聊 | 同一员工 ID 和规则 | 保持同一身份 |
| 私聊问这个群刚确定的提纲 | 不承诺自动知道；可明确提供材料 | 同一员工可自动召回相关经历；多个同名事项时明确关联消歧 |
| 保存“以后开头简短” | 通过已有基础资料编辑等现有能力使用 | 新交流中的明确偏好自动保留并按需应用，可查看/纠正/忘记 |
| 标为“仅在此聊天使用”的商业秘密 | 保持现有会话隔离 | 宿主阻止进入其他聊天模型请求及派生物；普通私聊来源的披露边界按 05/13 |

演示和发布说明必须如实标注这一差别，不能因为员工名字相同就宣称经历已经连续。

## 3. T1 收到狼人杀需求时

输入：“创建六个性格不同的玩家，我想看他们玩狼人杀，也想私聊其中一个。”

允许生成六名成员及“狼人杀讨论组”：性格可以是谨慎、善辩、善于追问、表达简洁等。不得生成本局隐藏身份；“狼人/预言家”是每局分配的临时角色，不写进永久姓名、员工 role 或 AGENTS.md。

方案页明确说明：“可以创建玩家与群聊；自动发牌、回合控制和胜负判定尚未支持。”用户仍可选择创建角色群，进行普通互动；不显示“开始正式对局”按钮，也不把自然聊天包装成按规则执行的比赛。

## 4. T3：正式游戏的职责拆分

| 系统组件 | 责任 |
| --- | --- |
| 团队创建助手 | 设计玩家性格与名字；不读取后续发牌结果 |
| 游戏服务 | 保存局 ID、规则版本、随机分配、阶段、行动、存活和胜负 |
| 玩家 Agent | 在当前允许视角中发言、推理、提交结构化行动 |
| 主持角色与播报 | 用户可见的主持负责引导和播报已确认事件；规则、秘密收发与结算归宿主，不能靠主持 Agent 猜测；表达可用模板或 Agent |
| 观战界面 | 展示公共过程及用户选择的观战视角；不成为玩家输入来源 |

游戏控制不替换普通群调度，而是只在明确开启的 gameSession 内使用专用调度。锁定局成员和规则版本后，不能在中途通过修改群成员无声改变牌局；需要暂停并结束本局或走明确的规则支持。

## 5. 规则包的旧基线与最新缺口

**以下无女巫版本仅保留为旧设计参考，不再是下一次实施 T3 的默认验收合同。** 原“简化六人局”为 2 狼人、1 预言家、3 村民，无女巫等技能扩展。最新需求必须覆盖主持和女巫；可从“主持 + 六名玩家，2 狼人、1 女巫、1 预言家、2 村民”补充方案，但人数/规则尚未作为正式 T3 合同冻结。

T3 开工前须固定：女巫解药/毒药数量、同夜用药限制、自救、夜间信息展示、行动优先级与死亡结算、失联/超时、私聊能否影响本局以及观战信息边界。规则版本固定在 GameSession，不能由普通记忆或临场 Prompt 决定。以下既有规则要在新规则包中逐项核对或替代：

- 宿主用可复核的随机种子和算法发牌；牌面只写入本局权威状态。
- 夜晚狼人可见同伴及己方私密频道，各提交一个存活非狼人目标；分歧经一次有限讨论后仍不同，则宿主按规则内固定的种子随机打破平票。
- 预言家选择一名其他存活玩家，收到其阵营；夜间行动先按夜开始时存活快照收齐，再结算死亡。若某玩家模型失败，暂停并显示原因，不把失败当成主动弃权。
- 白天按座位顺序各一次发言，再投票；首轮平票只在候选中复投一次，仍平票则本日无人出局。
- 每次死亡结算后检查胜负：狼人全出局则好人胜；存活狼人数量不小于存活好人则狼人胜。
- 出局玩家不再参与行动；死亡角色是否公开固定为“本局结束后统一公开”，不随模型描述改变。
- 设置局总调用/时间预算和单阶段期限，耗尽进入暂停/结束待处理，不无限让模型互相聊下去。

这些历史规则不是当前实现事实。T1/T2 不生成对应引擎；未来规则调整必须升级版本和测试，不修改正在进行的局。

## 6. 玩家视角与信息投影

GameSession 保存全量权威信息；每次调用生成 PlayerView，只包含：自己的身份、当前阶段、公开事件、规则允许获知的私密结果、自己此前的有效行动和推测。狼人可知同伴，村民不可读取发牌全表。观战全知 UI 与 PlayerView 必须使用不同数据投影。

玩家的观点/谎言作为消息保存，不能覆盖 GameSession 的真实身份。任何工具行动都带 gameSessionId、playerId、phaseVersion 和 requestId；宿主校验轮到谁、可选目标、是否存活和是否已行动。旧阶段回包不能在新阶段生效。

同一行动重复请求幂等；夜晚秘密消息不会被普通群 contextWindow 读取。不得把所有秘密先写入普通群消息，再依赖“请勿透露”提示词过滤。

## 7. 局内私聊与可选暂停采访

最新目标要求同一玩家的合法局内私聊能进入随后本局决策：私聊绑定明确 gameSessionId/playerId，宿主校验发言来源及可进入玩家视角的信息。正式身份由游戏服务发放，经私密通道通知；用户随便说“你是狼人”不能覆盖已经冻结的牌面。女巫/狼人回到群里仍知道自己的合法身份，其他玩家不会因此获得该秘密。

“暂停后采访”可保留为另外一种明确标注的不影响游戏模式：在安全阶段边界暂停，等待已开始调用退出并冻结视角，打开绑定本局/玩家的采访会话；不取得主持人的全量状态，也不写回正式行动。不能用这个模式替代用户希望的局内连续私聊。

T3 需把“局内私聊”和“不影响游戏的采访”分别定义并验收：前者哪些信息能影响谁、从哪个阶段版本开始生效；后者如何防止观战全知信息回流。用户提出的统一记忆不等于允许观战者把全量牌面注入任何玩家。

新一局分配新的 gameSessionId、临时身份和局内记忆；员工人格和明确允许的非游戏偏好可保留。旧局秘密不进入新局决策；结束后用户可以查看复盘，但复盘也不能自动升级为永久角色身份。

## 8. T3 上线门槛

- [ ] 所有规则转换在没有真实模型时也可用确定性输入测试。
- [ ] 狼人、女巫、预言家、村民、主持与观战者的实际模型请求/视图各不越权。
- [ ] 过期、重复、不合法目标与出局玩家行动全部由宿主拒绝。
- [ ] 每个阶段有失败/取消/预算耗尽出口，重启不自动补发行动。
- [ ] 女巫资源与行动结算由宿主校验，主持能接收合法私密行动并继续公共流程，不伪造玩家选择。
- [ ] 局内私聊按规则进入同一玩家后续视角；若提供暂停采访，该模式不改写正式状态，恢复不重复行动。
- [ ] 新局不继承旧局秘密，推测不被当成真实身份。
- [ ] 在原定预算内完成整局并能按事件复盘，模型自然发言只是其中一项。
