# 通讯录创建流程与交互

状态：T1 交互合同已接线，实际验收统一见 [08](08-实施步骤与交付清单.md)。布局图见 [10](./10-界面线框与状态图.md)，接口见 [03](./03-数据模型与IPC合同.md)。

## 1. 入口和承载位置

通讯录加号菜单增加“创建团队”，保留“新建员工”“新建群聊”。共享菜单增加可选能力或回调；T1 会话页仍显示原有两项，避免给未接线页面新增失效入口。

点击后在通讯录自己的右侧详情工作区打开“创建团队”标签。已有未完成草稿时聚焦该草稿；第一版同时只允许一个未结束的创建草稿。已完成后可明确“创建另一套”。不创建一个普通聊天用于与系统助手对话，也不增加新的 sidebar 主页面。

切换主页面保留本页标签与草稿；其他主页面不显示它。后台已受理的生成或创建不因页面隐藏而取消，隐藏页暂停查询，返回时重新读取权威状态。

## 2. 描述需求

| 控件 | 行为 |
| --- | --- |
| 需求输入框 | 可见提示每次 1–12 人；必填，1–4,000 字符；允许只输入“写作”，不足细节用可见假设补齐 |
| 示例入口 | “写作团队”“产品讨论组”“角色玩家”；只填入文本，不发起模型调用 |
| 模型连接 | 选择已有 API 连接；首次有且只有一个可用选项时预选，多个时要求选择 |
| 模型 | 默认使用连接默认模型；允许从现有模型配置能力中指定，不能猜测模型名称 |
| 同时创建群聊 | 默认开启；用户可在方案页继续更改 |
| 生成方案 | 显示“生成方案会调用所选模型”；点击后保存草稿并受理生成 |

无连接或缺少有效模型名：按钮不可用，提供“配置模型”导航并保留需求草稿。连接存在但请求认证失败：显示本次失败，不把“有配置”当作验证成功。兼容服务允许无 Key，不用通用的“必须有 Key”前端门禁拒绝它。

仅浏览和填写不调用模型。配置导航返回后恢复原草稿；模型配置变化后重新校验。所选旧连接没有默认模型时仍提供配置入口；模型输入只有空白时按宿主 trim 规则回到连接默认模型，不错误禁用。

## 3. 生成中与取消

展示阶段文字“正在设计成员与分工”，不编造百分比。方案不完整时不展示可点击创建按钮。可收起标签、切换页面，或明确“停止生成”。

停止只终止当前生成；保留输入和上一份有效方案，标明后者对应的需求版本。已经发生的模型用量仍保留。停止后迟到响应不能把草稿改回成功。

生成失败显示可理解原因与“重新生成”；模型原始 JSON/堆栈留在诊断中，不能铺满用户界面。重新生成是明确的新请求，不由返回页面或刷新自动触发。

## 4. 方案预览与修改

上方展示团队名称、用途、假设和由宿主维护的只读能力说明；中间是可展开成员卡；下方是模型配置、建群选项及最终创建动作。

成员卡展示头像、姓名、职责，展开后编辑工作规则/性格。可增加空白成员、删除成员；至少保留一人，最多 12 人。姓名在本方案内不能重复，避免群内称呼歧义；与现有联系人同名给提示，允许作为新身份创建。

用户可以编辑团队名称、目的和协作建议。协作建议是可见的工作背景，不强制改变现有发言调度。取消建群后这些内容保留在草稿/来源记录，不自动写入任何旧群。

T1 新成员统一使用方案中选定的模型配置，成员级不同模型在创建后通过既有编辑器设置。Skills、知识和命令权限不在生成方案中自动授权；缺少的能力以“创建后配置”提示。

生成后直接编辑需求或更换模型连接会使方案待重新生成；仅改成员文本、群选项和协作背景走本地/宿主校验，不再次调用模型。

“重新生成”替换整份方案。若有手工编辑，明确提示会覆盖本次成员调整；保留上一份有效方案直到新方案校验成功。停止或失败时原方案仍可查看，但只有对应当前需求/配置的方案可提交。

## 5. 最后一次确认

按钮使用“创建 4 位员工和群聊”或“创建 4 位员工”，数量实时匹配。旁边说明采用的模型和“创建后由你发送第一条消息”。不额外叠加无意义的确认弹窗。

提交前强制保存所有本地编辑，获取最新草稿版本和内容摘要。宿主再次核对人数、字段、模型引用和方案内容；用户确认的旧版不能被偷偷替换为最新版。

提交期间成员卡只读。失败后根据操作状态给出具体动作，不能统一用一个“重试”按钮重新走全流程。确认按钮连点、IPC 回应丢失、重新打开页面都查询同一个创建操作。

## 6. 创建结果与下一步

| 结果 | 界面动作 |
| --- | --- |
| 有群创建成功 | 按 ID 显示当前成员和群名，改名实时反映；群被移除时显示“群聊已移除”；“进入群聊”“查看成员” |
| 只创建成员成功 | 展示成员列表；点击成员“发消息”才创建/复用单聊；也可进入既有选人建群流程 |
| 等待用户继续初始化 | “创建中断，尚未完成”；“继续创建”“放弃并清理” |
| 需要人工处理文件冲突 | 说明具体成员及冲突，不展示为成功；允许查看诊断和重新核对 |
| 提交已成功但界面超时 | 查询后展示已有结果，不生成第二套 |

创建完成后留在通讯录结果标签，不自动切页。用户点击“进入群聊”再导航；不发送首条消息。可以提供“先各自介绍一下”的文本建议，点击只填入输入框，用户发送后才启动现有聊天。

已完成后关闭标签不会删除成员；“创建另一套”生成新的草稿与请求身份。T1 不提供创建后的“一键撤销全部成员”，避免误删已经参与其他聊天的员工。

## 7. 草稿与放弃

草稿编辑采用短延迟保存并显示保存状态，离开前复用现有未保存守卫。快速连续编辑的保存请求串行，版本冲突时保留本地副本并重新读取，不能覆盖另一份较新状态。

关闭标签：保存草稿后关闭，下次入口恢复。明确“放弃草稿”：未受理创建则删除草稿内容；生成中先取消并等退出。已受理但未发布时走 04 的取消和清理流程。UI 不能直接删除文件。

操作记录在“创建团队”入口可重新找到；不要依赖一条短暂 toast 作为唯一恢复入口。已发布对象后来删除或改名，历史结果按 ID 显示现状，不恢复旧副本。

生成成功后聚焦方案标题；创建成功后聚焦结果标题。显式提交时展开并聚焦第一个无效成员字段；重名提示与姓名字段关联。后台自动保存错误不抢走正在编辑的焦点，其他显式动作失败聚焦可读错误摘要。

## 8. 交互验收

- [ ] 只输入“写作”能得到可调整方案；用户看得见系统补充的假设。
- [ ] 修改成员后，最终按钮数量、预览和实际保存一致。
- [ ] 切页、重开标签、配置模型后返回不丢草稿，不隐式多调用模型。
- [ ] 取消建群确实不新增 Conversation，成功后私聊按需创建。
- [ ] 创建或生成失败时，有明确的下一步且不伪装成功。
- [ ] 键盘可完成编辑与提交，错误关联字段，缩窄窗口仍可操作。
