# 产品目标与范围

状态：产品合同；开工基线核对日期为 2026-09-30。当前完成状态统一见 [08](08-实施步骤与交付清单.md)，不将本节历史差距表当作未实现清单。

## 1. 用户目标

用户不必逐个填写员工 Prompt、建立成员关系和手动配置群聊。描述“想做什么”，即可得到职责清楚、可调整、能够进入现有聊天体系的一组员工。

支持两类意图：工作团队，如写作、研究和内容策划；角色群，如性格不同的玩家或讨论者。角色配置生成与场景实际运行分开交付：生成了狼人杀玩家，不代表已经具备发牌、夜晚行动和胜负判定。

体验承诺：用户在群里和私聊里接触的是同一个员工身份。T1 保证身份、配置和工作区连续；用户已确认后续 T2 采用员工统一记忆，新交流默认按需接续，不要求每次手工共享；来源、仅限本聊天、临时失效与迁移边界见 [05](./05-员工身份与连续记忆.md)和 [13](./13-T2员工统一记忆修改方案.md)。本次修订没有启用 T2。

## 2. 术语

| 术语 | 本组含义 |
| --- | --- |
| 团队创建助手 | 系统内置的方案生成能力，不占员工列表，不加入生成的群 |
| 团队方案 | 尚未创建的配置草稿，可编辑、生成新版本或放弃 |
| 员工 / 成员 | 持久 DigitalAgent，可被多个会话引用 |
| 群聊 | 现有 Conversation，成员列表引用员工 ID |
| 团队 | 本期对“一组员工和可选群聊”的产品称呼；T1 不新增组织/团队管理实体 |
| 通讯录分类 | 已有展示分组，不是团队成员归属或权限边界 |
| 场景 | 写作、角色讨论、狼人杀等用途；不是模型自动安装的程序 |
| 创建完成 | 所有目标员工和可选群已发布、文件已准备、回执已提交 |
| 工作完成 | 后续聊天任务的实际交付，由既有工作体系判定 |

名字相同不表示同一员工；职责相似不触发员工合并。T1 每次明确“创建另一套”都生成新身份，不自动复用或改写旧员工。

## 3. 当前基础与差距

| 当前可复用 | 当前缺口 |
| --- | --- |
| 通讯录、员工编辑、群选人和共同加号菜单 | 一句话入口、生成方案和批量预览 |
| EmployeeService 保存员工与初始化工作区 | 全部成员和群的批量发布与故障恢复 |
| 群持久保存成员 ID，普通单聊复用同一员工 | 创建方案与生成对象的持久回执 |
| Mastra 分阶段 Agent、模型连接与共享容量 | 专用无工具团队设计阶段和结构化输出校验 |
| 员工 profile、员工 × conversation 记忆 | 跨会话经历的受控召回与披露规则 |

记忆当前由 BoAI 的 MemoryRepository/SQLite 管理，模型通过 Mastra 提取候选；不是已经启用原生 Mastra Memory。Workspace 的文件隔离也不等于记忆范围。依据见 [11](./11-决策记录与参考依据.md)。

## 4. T1 必须包含

1. 通讯录加号中的“创建团队”，支持自然语言描述。
2. 用户选择已有 API 模型连接；同一配置默认用于设计助手和新成员。
3. 生成 1–12 名成员；常规无人数要求建议 3 名，按实际分工调整，不强凑人数。
4. 展示名字、职责、工作规则/性格、团队目的、协作建议和能力缺口。
5. 支持手动改名、改职责/规则、增删成员和重新生成方案。
6. 默认同时建一个群，可取消；不提前创建每位员工的私聊。
7. 每名员工独立 ID/workspace，沿用现有 Mastra 模型后端；新员工默认启用，命令权限关闭，Skills/知识默认不绑定。
8. 持久草稿、创建回执、重复请求幂等、文件准备失败和重启中断的可见处理。
9. 创建后能进入群聊或联系任一员工；只有用户发送消息才触发聊天/任务。

T1 不生成头像图片，使用已有头像预设；成员的个性写入初始工作规则，SOUL.md 沿用现有默认初始化，避免新建一套人格文件协议。之后可通过现有系统文件入口修改。

## 5. T1 不扩展的范围

- 不新增模板市场、组织树、经理审批或强制经理角色。
- 不自动安装技能、执行命令、搜索网页、创建自动化或发送外部消息。
- 不让 ACP 本地员工自动参与群聊；T1 新成员只使用当前支持群聊的 Mastra 模型后端。
- 不迁移现有记忆仓库，不自动贯通所有私聊和群聊。
- 不声称角色群能按正式狼人杀规则运行；正式游戏功能见 T3。
- 不要求先交付第 8 组的附件、产物验收、搜索与收件箱。

能力缺口以提示呈现，例如“网页检索尚未接通”；可以创建成员，但不能标为已具备该能力。

## 6. 第一版完成定义

输入“创建一个科技公众号写作团队”，生成四个可区分的角色；用户调整其中一人并确认。重启后四个独立员工及一个群仍在，群引用正确身份，私聊同一员工不会复制身份。取消或未确认时没有新增员工。重复提交和响应丢失不会产生第二套。创建期间不产生公开消息、业务 Work 或新成员模型调用。

验收细节以 [09](./09-验收场景与测试矩阵.md) 为准；“模型返回四个名字”不构成功能完成。

## 7. 与第 8 组的关系

第 8 组 IM-07 保留“经过验证的场景模板帮助用户完成第一次真实工作”的目标；本组提供通用创建通路。将来固定模板也进入同一方案预览与创建服务，不再另写批量保存。

本组 T1 的成功指标是成功建队并开始有效交流；IM-07 的成功指标是完成实际成果闭环。不能混用两个完成标准。
