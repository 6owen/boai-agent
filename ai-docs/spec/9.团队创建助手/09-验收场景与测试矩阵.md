# 验收场景与测试矩阵

状态：验收合同；实际执行结果及差异见 [08](08-实施步骤与交付清单.md) 回链记录。离线协议正确、产品流程可用、真实模型方案质量分别验证，不能互相替代。

## 1. 测试分层

| 层级 | 要验证的意图 | 方式 |
| --- | --- | --- |
| 纯合同 | 字段/人数/枚举/未知字段不越界 | Vitest 直接调用实际校验 |
| 存储和文件 | 幂等、竞争、部分失败与恢复 | 真实 SQLite、独立数据目录、文件断点 |
| 模型协议 | 正确 SDK 输入、结构化输出、取消/迟到与预算 | 真实 Mastra SDK + 本地协议服务 |
| 桌面流程 | 用户可创建、修改、恢复、聊天 | playwright-bdd + 真实 Electron |
| 生成质量 | 分工有用、个性区分、需求遵循 | 明确模型/输入/预算的真实调用与人工评审 |

沿用 tests/*.test.ts 与 tests/e2e/features/steps/support；不新增平行 .spec.ts 桌面入口，不手写 .features-gen。每个场景数据隔离，重启沿用该场景目录。故障注入放测试支撑层，不给生产 UI 增加模拟按钮。

## 3. 中文 BDD 示例

以下场景放入拟新增 team-creation.feature，步骤复用既有生命周期；参数和具体控件可按实现调整，业务断言不能减少。

```gherkin
@team-creation
功能: 在通讯录一句话创建团队

  场景: 调整方案后创建团队并联系同一名成员
    假如 已配置可用的模型连接
    当 我在通讯录描述一个四人写作团队并生成方案
    并且 我修改其中一位成员的名字和工作规则
    并且 我确认创建四位员工和群聊
    那么 通讯录中出现四位独立员工和一个包含他们的群聊
    并且 创建结果保存了我修改后的配置
    并且 创建过程没有发送聊天消息或启动员工任务
    当 我从群成员资料进入该成员的私聊
    那么 私聊引用同一个员工身份

  场景: 文件准备中断后继续同一次创建
    假如 已确认一个团队方案且部分文件准备完成
    当 应用进程中断并重新启动
    那么 通讯录中没有半套可用成员
    并且 我能看到该次创建需要继续处理
    并且 没有自动重发模型请求
    当 我选择继续创建
    那么 系统使用原先分配的员工身份完成整套创建

  场景: 创建成功回应丢失后重新查看
    假如 团队已在数据库中提交但界面未收到成功回应
    当 我重新打开创建结果
    那么 我看到原先创建的成员和群聊
    并且 没有重复的员工或群聊
```

## 4. 真实模型质量评审

2026-09-30 用户确认常规需求最多 12 人：T1-v2 将原“创建50人中文写作团队”替换为明确 12 人的合法上限样例。T1-v1 的原始超限请求和拒绝结果保留为历史负例，0/13 人的宿主拒绝断言继续执行，不截断超限请求。版本变化只补跑受影响样例；提示词变化复跑全部常规样例。

T1.5 前固定至少六类输入：明确四人写作、只说“写作”、单人轻量助手、成员带不同性格的讨论组、狼人杀玩家群、包含越权工具要求的合法团队需求。再加入超人数请求作为拒绝/调整样例。

每类记录原始输入、方案、模型/连接类型（无 Key）、planner/schema 版本、耗时、调用数、已知/未知用量和人工结论。首次响应非法但修复成功要如实计入修复率，不删除失败样本。

| 维度 | 首版通过条件 |
| --- | --- |
| 结构与权限 | 所有有效创建载荷都通过宿主校验；任何越权字段/副作用为阻塞失败 |
| 需求遵循 | 明确人数、主要职责和语言正确；超范围请求不假装完成 |
| 分工质量 | 多成员有可解释分工，不能仅换名字重复角色 |
| 可编辑性 | 用户能理解并修改，没有只能开发者理解的内部字段 |
| 能力诚实 | 工具缺失和正式游戏未支持被明确说明 |

小样本只说明这些版本和案例的结果，不宣称任意模型/主题都稳定。更换模型、提示词或 schema 后重新运行受影响案例；离线门禁仍保留。
