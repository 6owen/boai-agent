# T2 员工统一记忆修改方案

日期：2026-09-30。**本文件为已确认方向下的待实施方案，本次仅修改文档。** T1 已完成；T2 所有切片待实施；T3 不在本轮实现范围。唯一进度表见 [08](./08-实施步骤与交付清单.md)。

## 1. 目标与实施边界

同一员工在私聊与群聊里拥有连续的个人经历，能按需想起相关内容；使用限制、来源和有效期跟随记忆，不能随着换窗口丢失。

本期交付：统一归属、增量提取与纠正、跨会话召回、受控临时记忆、整理/忘记、来源级失效、保守迁移、可管理的员工记忆页。完整产品规则见 [05](./05-员工身份与连续记忆.md)。

本期不交付：全体员工共用记忆、无限历史注入、自动回放旧任务、原生 Mastra Memory 迁移、外部向量数据库、任意项目管理系统、正式狼人杀规则。群、员工、工作区、普通聊天与自动化工作身份继续沿用现有实现。

## 3. 数据合同：归属、使用范围与来源分开

在现有 SQLite 记忆体系中扩展。下列是拟新增语义，具体类型名在 T2.1 固定并同步文档；不提前建立第二套存储。

| 字段或关系 | 合同 |
| --- | --- |
| id / ownerAgentId | 稳定记忆身份与唯一员工归属；改名和模型切换不改变 |
| schemaVersion / policyVersion | 区分旧数据与新默认规则，不靠字段缺失推断更大权限 |
| kind | 长期、经历、临时；与事实/明确偏好/决定/被转述主张/推测的证据类别分开 |
| content / attribution | 内容及实际发言者；别人说的话不变成员工亲历或已验证事实 |
| sources | 来源会话、消息、资料及必要版本；派生记忆保留父条目和根证据，不能丢掉原来源 |
| useScope | employee、conversation 或 context；分别为员工获准会话、仅来源会话、绑定事项 |
| contextRef | 可选稳定关联：先复用现有会话或 Work ID；普通聊天关联群不创建 Work。gameSessionId 由 T3 后续接入，不预建游戏实体 |
| disclosure | 保留私人/群内公开/用户明确可转述等来源语义；不作为硬性防泄漏保证，不替代 useScope |
| status / expiresAt | active、superseded、archived、expired、deleted；到期、撤权读取时立即检查 |
| version / supersedes / pinned | 原子更新、明确替代关系和用户固定；固定不覆盖到期、撤权或删除 |
| createdAt / updatedAt | 原始发生时间和修改时间分开保留；整理不把旧经历伪装成刚发生 |

同一员工使用独立 revision/epoch；已有 profile/conversation epoch 在迁移和兼容期间继续有效。跨范围操作须同时核对相关版本，不能拿一个会话 epoch 保护全部员工记忆。

增加最小的维护回执和忘记记录：维护回执按员工、来源轮次/批次和版本去重；忘记记录只保存阻止重新提取所需的来源身份/版本与必要指纹，不保留被删除正文。新的用户明确陈述或明确重新保存可以形成新记忆，不能由旧维护回包自行恢复。

正式工作完成状态仍由 Work 的交付证据决定；记忆里的“任务已完成”不能替代交付状态。游戏身份/药剂/阶段同理归 GameSession，未来只投影为当前玩家上下文。

## 4. 自动记忆与纠正

### 4.1 新交流的默认规则

1. 只从该员工本轮实际获准接收的已发布消息提取新证据；不能因为员工在群成员列表中就认定他看过全部历史。
2. 普通且值得保留的经历/偏好默认 useScope=employee；来源会话保留，不再等同读取范围。
3. 会话限制和用户结构化选择优先于模型候选。模型可建议缩小范围、分类和有效期，不能自行放宽限制、改归属或授予资料权限。
4. “本次/这个项目/这一局”的信息保留临时性。无法确认所指事项时不升级长期记忆，不猜关联 ID；必要时说明需明确事项。
5. 凭据、私钥、隐藏推理和无依据断言不进入记忆。身份设定文本与真实经历分开。

提取使用现有维护阶段和计量，不另开不受控后台 Agent。每轮候选有固定条数和输出上限；沿用既有共享容量及实际调用预算，自动化来源继续使用原 occurrence 账本。

### 4.2 合并与纠正

- 确定的文本/来源重复由代码去重；语义重复和纠正可由模型提出关联候选，宿主校验目标归属、版本和证据。
- 用户明确纠正可替代旧条目，旧条目标为 superseded 并保留来源关系；召回有效当前事实时排除旧版本。
- 两个互相矛盾的普通消息，不因时间较新就自动宣布一个是真相；保留归属和冲突，回答时说明不确定。
- 模型整理不覆盖用户固定内容或员工人格文件。权限/到期/来源失效由代码决定。
- 条目、替代关系、员工版本、去重回执和索引失效标记在同一 SQLite 事务提交。提交成功回应丢失先查原回执，不再次生成或重复写入。

### 4.3 刚私聊完就去群聊

不能把后台记忆提取完成当作连续交流的唯一条件。统一召回同时支持最近已完成交流的、获准且有来源的原文片段作为短期证据；摘要尚未完成时可直接使用这些片段。

宿主记录员工实际接收的来源边界，只读取已发布内容；未发送草稿、隐藏推理、其他员工的私有执行上下文不在其中。临时片段与持久记忆使用相同范围、忘记、权限和有效期过滤，也占同一上下文预算。若确实没有可用证据，明确说尚无法确认，不能靠猜测补上。

## 5. 统一召回与调用快照

拟在 memory 模块集中提供召回入口；service 提供宿主身份、获准来源、当前会话/事项、当前请求和预算。Workspace 与 Mastra 各阶段消费同一选择结果，不各自发明另一套可见性规则。

固定流程：

1. 根据 ownerAgentId、实际来源授权、useScope、事项与有效期确定可用集合。先过滤，再检索、摘要或重排；记忆标题和索引摘要也遵守同一边界。
2. 在允许集合内选择相关内容：固定且相关的长期条目、当前事项状态、最近交流、相关经历。用户显式指定来源时用于缩小范围；无需每次手动关联才能搜索普通员工经历。
3. 首版采用宿主可解释的事项匹配、关键词/本地文本检索及时间排序，中文输入须有真实召回样例；不把 SQLite 默认英文分词假设为中文已可用。相近问法另做质量评估；不足时再引入索引方案，不默认新增外部向量服务。
4. 按 token 预算选择完整条目和必要原文片段，去重并保留作者、来源、时间、版本。定义单项/总量上限及确定性截断策略，避免按字符串尾部直接裁掉证据含义。
5. 形成只读召回快照，包含所选条目/证据 ID、版本、策略版本和事项有效状态，供 decision/chat/task/report/记忆维护按各阶段用途使用；维护阶段只能以本轮消息产生新事实。
6. 执行和公开发布前重核关键来源、版本与策略。删除、纠正、限制收紧后，旧快照不能绕过发布门禁；需要补判时服从现有次数/预算和不重放工具约束。

普通 chat 仍无文件/命令工具；召回由宿主准备。不得给它整个员工目录或借 task 文件工具跨过范围限制。员工全量管理视图仅用于本机用户界面，不可复用为群模型输入。

私人来源允许跨会话使用时，应在上下文中保留“不主动公开私人细节”的表达约束；这不是硬性信息流保证。需要硬隔离的条目不进入群调用。游戏另由 T3 定义玩家私有决策、可发布信息和结构化行动的边界。

## 6. 生命周期与维护预算

| 触发 | 行为 | 失败与中断 |
| --- | --- | --- |
| 一轮交流完成 | 有界增量提取、去重/纠正候选；原消息不删除 | 失败可见，原对话仍可读；不重做用户任务 |
| 到期或事项结束 | 读取立即排除当前状态；后台补齐状态标记 | 不依赖整理器准时运行；应用休眠后也检查当前时间 |
| 空闲维护 | 分批归并冗长经历、归档低频条目、重建脏索引 | 保存检查点与回执；失败不提交半份摘要 |
| 用户忘记/来源撤权 | 事务设置失效/忘记记录，阻断召回与旧回包，再清理派生物 | 未清理完保持不可召回及待清理状态，不能假称已彻底擦除 |
| 重启或恢复备份 | 校验数据版本、时间与授权，丢弃/重建派生索引 | 不自动重发中断的模型维护或业务工具 |

T2 首版空闲维护先做不调用模型的到期标记、精确去重和索引维护；语义整理复用对话后的有限维护额度，或由用户在记忆页明确执行一次。初版不设置每日自动调用模型的常驻循环，避免无上限消耗。

所有模型维护须有批次 ID、有限输入/输出、调用数和绝对期限，实际退出后才释放容量；用量未知保留未知。普通对话维护用既有轮次预算，不能制造 Work；自动化派生维护仍归原 occurrence，不通过独立维护洗掉预算来源。跨不同预算来源的内容不打包成一次来源不明的付费调用。

长期记忆不按“30 天统一清空”；归档可供用户查看或明确历史查询，已到期/被替代条目不能当作当前事实。固定条目可免于低频归档，但仍受撤权和删除约束。未来增加付费定时语义整理须另补启用方式和总预算。

## 7. 删除、撤权、并发与恢复

### 7.1 失效传播

清除聊天、删除消息、资源撤权、离群、忘记条目和员工删除，都要覆盖根证据、派生记忆/摘要、检索索引、缓存、运行快照与生成文件。仅删除 memory 表的一行不算完成。

来源关系按 ID/版本维护，跨会话召回不改写来源。合并摘要若混入失效来源，先禁用整条摘要，再在有预算和合法证据时重建；不能继续使用旧正文。无法证明派生关系完整的条目保守失效。

“忘记”保留原聊天，但默认召回也不得借原文临时通路恢复同一被忘记证据。清除聊天则按现有合同删除聊天及派生记录，保留最小去重/拒绝迟到身份，不留下可还原正文的墓碑。删除之后新一轮明确重新告知是新证据，须与旧回包区分。

将来源改为“仅在此聊天使用”时，已在其他会话生成的派生摘要同步收紧或失效。已经对用户公开发送的历史消息不能撤回成“从未泄露”，这项限制在 UI 和记录中如实说明。

### 7.2 原子更新与并发

版本检查和提交经过 ProductStore 的 SQLite 事务，不能只依赖当前进程 Map 或 Promise 队列。两个聊天同时更新一个员工时，不得整份覆盖长期记忆；以条目和员工 revision 比较，冲突只重读/重算受影响候选，不重放模型工具。

删除/限制收紧先通过宿主门禁阻止新调用和旧结果发布，再清理文件/缓存。清理失败保留回执，重试只处理派生物。命名空间与运行快照版本都检查，备份与数据迁移互斥。

### 7.3 旧数据与备份

1. 迁移前沿用现有备份/互斥通路；迁移有版本与提交记录，可重复核对，失败保留可恢复的原数据。
2. 旧 profile 保持原含义；旧 conversation 缺少新字段时解释为原会话限制，不默认开放历史私聊。
3. 新规则用于启用后的新交流；原文短期召回也检查启用边界和原会话策略，不能借该通路绕过旧记忆的保守迁移。用户可在记忆页选择旧条目、预览范围变化后纳入连续记忆；保存原来源、原限制和操作回执，不批量导入所有旧聊天。
4. 恢复旧备份按该备份数据及当前兼容策略读取，不扩大范围、不自动补提取。索引是派生数据，恢复后先失效再重建。
5. 恢复备份可能恢复备份中尚未删除的记忆，必须明确说明恢复到历史状态；普通重启不能让已删除记忆复活。不承诺离线旧备份自动继承之后的删除。

## 8. 员工记忆界面与 IPC

复用现有员工详情的记忆入口，默认展示此员工的统一记忆；可按长期/经历/临时、来源会话、有效/归档筛选，按稳定游标分页。隐藏页面暂停列表读取，仍保留该页面的详情草稿。

每条显示内容、来源和发生时间、当前状态，以及“可用于该员工相关聊天 / 仅在此聊天使用 / 仅用于关联事项”等可读范围。支持查看来源、编辑、固定、忘记；临时条目可设置到期或结束使用。原始消息已不存在时显示来源不可用，不能制造替代原文。

会话设置提供“仅在此聊天使用”的结构化限制；条目可更严格，不能越过会话和来源限制。收紧即时影响已有派生记忆；放宽不自动迁移历史条目，避免一次开关把旧私聊全部开放。关联事项是可选消歧入口，普通连续交流不新增必填表单。

沿用 getMemory/saveMemory/deleteMemory/clearMemory 的职责，补充严格校验的查询、分页和版本字段；需要独立生命周期/整理操作时再增加相应 IPC。写入带 requestId 与 expectedRevision；宿主检查员工、来源和范围，渲染层不能指定任意来源 ID 就获得访问权。响应未知查询原请求回执，不盲目重提。

MemoryPane、导入界面与生成文件文案同步更新。T2 实际验收交付时，同步 teamCapabilityNotes 等宿主能力说明中的当前记忆事实；原 T1 评审证据和旧模型输出保持历史原样，不能提前宣称正式游戏已支持。全量管理列表与单次模型召回结果使用不同 DTO，避免把本机用户能看的全部内容传给员工。不要把内部 epoch、来源数据库键作为主要用户文案。

## 9. 实施切片与退出条件

切片执行顺序和状态统一在 [08](./08-实施步骤与交付清单.md)。以下只定义交付物，不是完成记录。

| 切片 | 必须交付 | 退出条件 |
