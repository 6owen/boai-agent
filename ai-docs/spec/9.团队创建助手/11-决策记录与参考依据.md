# 决策记录与参考依据

更新：2026-09-30。本文区分用户已确认方向、当前代码事实和本组实施方案，避免把建议当成已实现功能。

## 1. 用户已确认的方向

- 在通讯录内置“团队创建助手”。
- 一句话生成多名成员，可建立群组。
- 成员拥有独立 workspace，可群聊，也可私聊。
- 期望同一个成员在私聊与群聊之间保持身份和经历连续。
- 写作和观看 Agent 狼人杀是代表场景。
- 单独建立本组详细文档，供后续执行；本轮不实现应用代码。

## 2. 本组采用的实施决策

| 编号 | 决策 | 理由 / 后果 |
| --- | --- | --- |
| D01 | 创建助手为系统能力，不是 DigitalAgent | 不污染通讯录，不需要用户先创建助手或把它加入群 |
| D02 | 模型只产方案，程序创建 | 校验、ID、权限、重复提交与故障处理可以确定执行 |
| D03 | T1 使用现有 API 连接，不接 ACP 群协作 | 尊重当前外部任务后端边界 |
| D04 | T1 不新增 Team 组织实体 | 当前“一组员工 + 可选群”已满足使用，不提前建设组织树 |
| D05 | 默认建群，可只创建成员 | 覆盖直接开始协作与用户稍后组群两种需求 |
| D06 | 同一员工跨聊天引用同一 ID | 私聊不复制“分身”；人格/配置稳定 |
| D07 | 草稿预览后明确创建 | 用户能调整成员与确认实际新增对象，生成本身不产生配置副作用 |
| D08 | 文件先准备，数据库一次发布 | 解决半套可见对象；通过日志处理跨介质中断 |
| D09 | T1 沿用现有记忆，T2 扩展范围 | 创建入口不被记忆迁移阻塞，也不暗中扩大私聊可见范围 |
| D10 | 游戏规则归代码，角色判断归模型 | 能测试行动合法性、轮次、秘密信息和胜负 |
| D11 | 第 8 组保留为基础完善清单 | 附件/产物/收件箱继续有价值，当前开发顺序由本组 T1 负责 |
| D12 | T1 一份未结束草稿、整份重生成 | 先交付简单可恢复流程；多草稿和定向编辑另立需求 |
| D13 | 新成员不自动绑定技能/知识或开启命令 | 创建设计不等于授权，避免生成时夸大可用能力 |
| D14 | 成员个性写入初始 instructions | 复用当前 AGENTS.md 初始化；SOUL.md 仍由既有系统文件入口编辑 |

上述默认值是可执行设计基线，不代表用户已经逐屏确认所有控件，也不代表已经验证生成质量。调整需同步相关合同与验收，不必为了正常实施细节反复追问已确认方向。

## 4. Mastra 依据

本轮沿用用户指定的 Mastra skill 工作方式：先检查安装包文档，再看类型/源码；实现时重新核对版本。当前 package.json 为 core 1.71.0、memory 1.32.1、libsql 1.23.3。

| 主题 | 已核对文档 | 本组使用范围 |
| --- | --- | --- |
| 结构化输出 | [官方 Structured output](https://mastra.ai/docs/agents/structured-output)；本地 node_modules/@mastra/core/dist/docs/references/docs-agents-structured-output.md | 专用设计助手返回 schema 约束对象，仍需产品校验 |
| Working memory | [官方 Working memory](https://mastra.ai/docs/memory/working-memory)；本地 memory 包同名主题文档 | 理解 resource/thread 范围；不等同已接入 |
| Semantic recall | [官方 Semantic recall](https://mastra.ai/docs/memory/semantic-recall)；本地 memory 包同名主题文档 | 未来跨会话召回能力参考，不取代授权 |
| 多人 thread | [官方 Multi-user threads](https://mastra.ai/docs/memory/multi-user-threads)；本地 docs-memory-multi-user-threads.md | 说明单 thread 归属与发言身份；不直接用于共享玩家秘密 |
| Workspace | [官方 Workspace](https://mastra.ai/reference/workspace/workspace-class)；本地 core 包 reference-workspace-workspace-class.md | 文件/执行环境与记忆范围是不同职责 |

官方网页可能领先已安装版本。不能因为新网页提到某字段就不经本地类型和协议测试直接使用；也不因本组新增功能自动升级 Mastra 依赖。

## 5. 不在 T1 开发的候选

多草稿、只重生成某一位成员、从已有员工组队、每成员不同模型的创建页配置、自动选择并绑定技能、团队模板市场、创建后整套删除、任意场景规则生成、交互式可干预狼人杀、Mastra Memory 迁移。

这些不是被否定的方向，只是未进入 T1 验收范围。后续依据实际使用增加，不在第一版预留复杂但无人使用的框架。
