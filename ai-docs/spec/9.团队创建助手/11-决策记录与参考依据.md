# 决策记录与参考依据

更新：2026-09-30。本文区分用户已确认方向、当前代码事实和本组实施方案，避免把建议当成已实现功能。

## 1. 用户已确认的方向

- 在通讯录内置“团队创建助手”。
- 一句话生成多名成员，可建立群组。
- 成员拥有独立 workspace，可群聊，也可私聊。
- 期望同一个成员在私聊与群聊之间保持身份和经历连续。
- 2026-09-30 明确确认“同一员工类似一个人，有统一的记忆”：默认连续经历、按需召回，长期/经历/临时信息分别管理；先生成修改文档，稍后再实施。
- 写作和观看 Agent 狼人杀是代表场景。
- 单独建立本组详细文档，供后续执行；本轮不实现应用代码。

## 2. 本组采用的实施决策

| 编号 | 决策 | 理由 / 后果 |
| --- | --- | --- |
| D01 | 创建助手为系统能力，不是 DigitalAgent | 不污染通讯录，不需要用户先创建助手或把它加入群 |
| D02 | 模型只产方案，程序创建 | 校验、ID、权限、重复提交与故障处理可以确定执行 |
| D03 | T1 使用现有 API 连接，不接 ACP 群协作 | 尊重当前外部任务后端边界 |
| D04 | T1 不新增 Team 组织实体 | 当前“一组员工 + 可选群”已满足使用，不提前建设组织树 |
| D05 | 默认建群，可只创建成员 | 覆盖直接开始协作与用户稍后组群两种需求 |
| D06 | 同一员工跨聊天引用同一 ID | 私聊不复制“分身”；人格/配置稳定 |
| D07 | 草稿预览后明确创建 | 用户能调整成员与确认实际新增对象，生成本身不产生配置副作用 |
| D08 | 文件先准备，数据库一次发布 | 解决半套可见对象；通过日志处理跨介质中断 |
| D09 | T1 沿用现有记忆，T2 扩展范围 | 创建入口不被记忆迁移阻塞，也不暗中扩大私聊可见范围 |
| D10 | 游戏规则归代码，角色判断归模型 | 能测试行动合法性、轮次、秘密信息和胜负 |
| D11 | 第 8 组保留为基础完善清单 | 附件/产物/收件箱继续有价值，当前开发顺序由本组 T1 负责 |
| D12 | T1 一份未结束草稿、整份重生成 | 先交付简单可恢复流程；多草稿和定向编辑另立需求 |
| D13 | 新成员不自动绑定技能/知识或开启命令 | 创建设计不等于授权，避免生成时夸大可用能力 |
| D14 | 成员个性写入初始 instructions | 复用当前 AGENTS.md 初始化；SOUL.md 仍由既有系统文件入口编辑 |
| D15 | T2 新交流默认归该员工的统一记忆 | 替代每次手动共享/关联的旧方案；可选关联负责消歧，硬限制仍由宿主过滤 |
| D16 | 长期、经历、临时记忆有独立生命周期 | 长期内容不按统一天数清空；事项状态读时检查有效期，旧游戏角色不变永久身份 |
| D17 | 记忆归属、使用范围与公开表达分开 | 同一员工可以记得私聊；其他员工不能读取他的私人记忆；提示词保密不是硬隔离保证 |
| D18 | 延续 SQLite 唯一权威并集中召回 | 扩展现有 MemoryRepository；生成文件/索引是派生物，不通过迁移框架跳过来源和删除合同 |
| D19 | 旧记录保守迁移，忘记约束原文回退与再次提取 | 升级不暗中开放历史私聊；忘记不能被旧证据、旧回包或索引重建绕过 |
| D20 | T2.1–T2.6 先实施，T3 另补规则 | 连续记忆不代表可正式玩狼人杀；主持、女巫和局内私聊取代旧版相关假设，规则细节另行冻结 |

上述默认值是可执行设计基线，不代表用户已经逐屏确认所有控件，也不代表已经验证生成质量。调整需同步相关合同与验收，不必为了正常实施细节反复追问已确认方向。

### 4.1 本次统一记忆修订核对的官方依据

核对日期：2026-09-30。以下作为设计参考，不是本项目已接入或实现的证明。

- [Claude Code Memory](https://code.claude.com/docs/en/memory)：自动记忆跨同一仓库会话保存，启动先加载有限索引，详细主题文件按需读取；旧会话记录的保留期清理不清除记忆目录。借鉴索引与按需读取，不照搬仓库归属，也不据此声称应定时清空长期记忆。
- [Mastra Working Memory](https://mastra.ai/docs/memory/working-memory)：resource 范围支持跨 thread 延续，thread 范围隔离。若将来接入，要显式纳入员工身份，不能把全部员工共用用户 ID 当作独立个人记忆。
- [Mastra Semantic Recall](https://mastra.ai/docs/memory/semantic-recall)：支持 resource 范围搜索、数量/上下文范围和 metadata 过滤。过滤与索引更新仍需宿主合同；框架功能不能替代权限和删除传播。

本组据此选择“员工拥有记忆、宿主筛选相关且有效的内容”，T2 首版继续现有仓库，不要求向量库或原生 Mastra Memory 迁移。
