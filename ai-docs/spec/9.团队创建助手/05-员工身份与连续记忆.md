# 员工身份与连续记忆

更新：2026-09-30。状态：**方向已由用户确认；T2 已实现；技术验证和真实样例核对见第 2 组 26，范围外桌面失败单列；新交流按员工统一召回，旧记录保留原范围。** 修改方案、代码落点和验收矩阵见 [13](./13-T2员工统一记忆修改方案.md)，唯一实施进度见 [08](./08-实施步骤与交付清单.md)。

本次修订替代旧版 T2“每次显式关联才可跨会话使用、自动记忆始终留在来源会话”的默认方案。仅在此聊天使用、员工隔离、来源撤权和旧数据保守迁移继续保留。T1 已完成的创建合同不因此改变。

## 1. 产品目标

> 一个员工拥有一份持续存在的个人记忆，私聊和群聊是他经历事情的不同场合。

同一员工在私聊和群聊之间能够自然接续已获准的经历；用户不用为了每次继续讨论都复制材料或操作“共享记忆”。员工改名、换模型、换聊天窗口或应用重启，不创建另一份身份或丢失记忆。

“员工统一记忆”不表示团队所有员工共用一份记忆，也不表示每次调用加载全部历史。员工只拥有自己实际获准接收的信息；记忆不授予新工具权限，不启动旧任务，不改变工作归属。

## 2. 当前实际行为

- DigitalAgent ID 是持久身份，私聊与群聊引用同一员工；WorkspaceService 仍按员工管理根目录，按 conversation 管理 session。
- MemoryRepository 以 SQLite 为唯一权威，新记忆使用 employee 范围，来源与使用范围分开；旧 profile/conversation 保留原语义，MEMORY.md/USER.md 是生成视图。
- service 的各模型阶段、工作区和生成会话文件消费统一获准召回；当前轮增量维护默认写员工记忆，限制/事项/来源由宿主校验。
- WorkspaceService.load 不再独立过滤为当前会话；Mastra 维护只以当前轮为新证据，已持久条目用于去重/纠正。近期获知原文用于即时接续，但不冒充持久事实。
- 当前 Mastra Agent 工厂没有启用原生 Memory；安装依赖不等于接入。

本次修改要解决的是归属、召回和生命周期，不是重新建立一套数据库，也不是把所有条目改成 profile。

## 3. 要保留的三类记忆

| 类型 | 内容示例 | 使用方式 | 生命周期 |
| --- | --- | --- | --- |
| 长期记忆 | 用户偏好、明确约定、稳定项目背景 | 同一员工跨会话按相关性使用 | 保留到纠正、撤权或删除；可固定 |
| 经历记忆 | 群里确定的提纲、私聊交代的安排 | 保留来源、时间、发言者，相关时召回 | 可整理和归档，仍可追溯 |
| 临时记忆 | 某次讨论的临时约定、当前事项状态 | 只在绑定事项及有效期内使用 | 事项结束或到期后不再作为当前状态 |

原始聊天记录是独立的证据来源，不因生成摘要而删除。普通陈述、别人声称的事实和推测要区分；模型不能把“我怀疑 2 号是狼”整理成“2 号是狼”。员工人格配置不被自动记忆覆盖。

游戏身份、药剂、阶段和胜负属于 T3 的 GameSession 权威状态；T2 只预留正确的来源和有效期语义，不用普通记忆条目代替游戏引擎。

## 4. 默认连续体验与例外

T2 启用后，新交流中值得保留的普通偏好、约定和经历默认归入该员工的统一记忆。提取候选由模型判断，归属、来源和使用范围由宿主确定。无需用户逐条点击“设为全局”。

| 信息 | 同一员工的另一会话 | 其他员工 |
| --- | --- | --- |
| 普通偏好与经历 | 来源仍有效且与当前问题相关时可自动召回 | 不读取该员工的个人记忆 |
| 标为“仅在此聊天使用”的信息 | 不进入其他会话的检索、摘要或模型请求 | 不可用 |
| 绑定某事项的临时信息 | 只有当前明确对应该事项且仍有效时可用 | 只按各自获准来源使用 |
| 当前群公开消息 | 员工实际获准接收后可以形成自己的经历 | 其他成员可从同一公开消息形成各自记忆，不复制私有摘要 |
| 已删除、撤权、被替代或到期信息 | 不作为有效当前记忆召回 | 同样不可用 |

私聊来源仍标为私人来源。记忆须分别表达“能否在此场合使用”和“能否公开转述”：允许跨会话使用的私人背景可以帮助该员工理解事情，但不应主动报出私人原文、暗号或无关细节。需要硬性禁止进入群模型上下文的信息，必须使用“仅在此聊天使用”等宿主过滤边界；仅靠不透露的提示词不能保证模型绝不泄漏。

“关联群聊/事项”是限定话题与消歧的可选操作，不再是普通记忆跨会话召回的必经步骤。如果同时存在多个同名项目或对局，应请求选择或说明无法确定，不由模型猜一个 ID。普通事项关联不创建业务 Work。

## 5. 首批验收体验

1. 私聊告诉员工“以后文章开头简短”，到群里请他写作，能应用偏好，不需再次授权每条新记忆。
2. 群里确定提纲，转到同一员工私聊继续讨论，能引用正确结论和来源。刚完成的交流也能接续，不因后台摘要尚未完成而失忆。
3. 同一员工在两个群讨论不同项目，问其中一个时不会串用另一个项目的临时约定。
4. “仅在此聊天使用”的内容不出现在其他会话的实际模型请求、摘要、可搜索标题或生成文件中。
5. 纠正、忘记、来源清除和事项结束能及时生效；重启和恢复备份不扩大范围，也不自动重放任务。
6. 员工详情可查看和管理统一记忆，保留原员工 ID、工作区及原聊天记录。

## 6. 整理、失效与删除

- 读取时检查到期和事项状态，不等待定时整理才让旧状态失效。
- 对话后增量提取；重复内容合并，纠正保留新旧版本和来源，未证实冲突不能简单按最新时间覆盖。
- 空闲时分批整理重复或冗长经历，摘要继承全部必要来源和最严格的使用范围；整理不放宽权限。
- 低频经历可降低优先级或归档；长期记忆不按统一天数清空。原始聊天保留策略单独管理。
- 用户忘记或来源删除后，派生摘要、索引、缓存和生成文件同步失效；旧模型回包不能写回。原始聊天还在时，忘记记录还应阻止同一旧证据被自动再次提取。

整理默认不创建用户的定时任务，不发送群消息，不制造 Work。模型维护调用沿用容量、用量和预算边界；具体触发、限额和中断行为见 13。

## 7. 迁移与兼容

新规则用于 T2 启用后的新交流。旧 conversation 记忆仍维持原范围，旧 profile 保留原语义，不能用一次升级把历史私聊全部开放。员工记忆页可由用户明确选择旧条目纳入连续记忆，保留原来源和升级回执。

同一员工跨会话并行更新，必须在 SQLite 事务内检查版本并提交；冲突后重新读取，不覆盖另一会话刚保存的内容。删除/撤权与发布竞争时由宿主门禁决定，已经送到模型的信息无法撤回，但受影响结果不得继续对外发布。

T1 的创建方案只解释配置来源，不等于员工已经经历过的聊天。团队分类不是记忆权限边界。现有员工和 T1 新建员工均不更换 ID、不复制 workspace。

## 8. 与框架和游戏的关系

T2 优先扩展现有 MemoryRepository，SQLite 保持唯一权威；生成文件和检索索引可重建，不双写另一套权威记忆。Mastra 的 resource/thread 和召回机制是参考，不代替宿主授权。Claude Code 的索引与按需读取是参考，不意味着应定期清空长期记忆。官方依据见 [11](./11-决策记录与参考依据.md)。

狼人杀中“我在本局是女巫”应从同一员工、同一局的合法玩家视角进入群内决策；“其他玩家也知道我是女巫”是另一条公开规则。T2 的通用连续记忆验收不冒充 T3 的发牌、行动、主持和整局验收；最新游戏需求边界见 [06](./06-写作与狼人杀场景.md)。
