## 3. 员工定义仍只有一个写入规则来源

批量创建不能复制 agentSchema 的另一份宽松校验。EmployeeService 导出既有 agentSchema，单个保存和 TeamCreationService 都用它校验。团队用例确定宿主 ID 与冻结定义，WorkspaceService.initialFiles 提供初始化内容；提交后 EmployeeService.installBatch 批量安装，原单员工路径不变。

原 saveAgent 继续走已有单对象用例。团队服务收集全部定义，使用 04 的准备/事务发布；最终内存安装复用注册机制。不能为了共用而把整个 AppService 拆成一次大重构。

## 4. 系统助手与普通员工执行分离

现有 createStageAgent 需要真实员工 EngineContext，包含工作/记忆等上下文。团队设计助手没有 employeeId，不伪造员工记录或虚假 Conversation 来适配它。

使用专用适配器，注入已经解析的模型连接和调用守卫；复用 modelConfig、取消信号、调用容量和用量解析。生成预算归 TeamGeneration，不为配置生成制造 Work/自动化 occurrence，也不改写普通聊天预算。

第一版只支持现有 API 模型配置；若供应商不支持当前结构化策略，报可理解错误或使用文档允许且已测的 JSON schema 兼容方式，不能退回无校验文本直接创建。

## 5. 群背景的接入

teamSetup 在群资料中可读/可编辑，版本变更遵循现有群设置保护。调用装配时加入“用户确认的建群目的与协作建议”背景块，供每名成员自行判断；不得把其内容提升成覆盖应用协议的最高优先级指令。

当前群调度仍自主决定是否发言。创建助手退出流程后不持续当群经理，也不因为 collaborationGuide 写着“先研究后写作”就自动执行工作流。任务需要真实用户消息和既有 Work 合同。

## 6. 兼容清单

- 旧联系人、群、头像、分类/排序、私聊复用继续可用；无新字段的旧记录不变。
- 员工被创建后是普通成员；修改其名字/规则/模型不要求重新运行团队创建。
- 新群支持现有提及、引用、停止、清理和来源检查。
- 模型配置不存在时拒绝提交；配置存在但认证未通过不能在 UI 标为“已验证可运行”。
- 旧数据目录升级只增加新集合/可选字段；创建文件暂存不被普通员工工具列出。
- 现有 API 凭据只由宿主管理；备份、草稿和来源对象都不复制凭据。
