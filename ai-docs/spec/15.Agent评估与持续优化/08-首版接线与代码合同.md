# 首版接线与代码合同

**现行增量：** 真实业务eval、独立judge及Codex候选循环见[11](./11-业务评估与Codex优化主线.md)。本文原手动/描述性合同保留；原测试修复改名`dev:repair`，不能作为业务评分。

## 1. 首版范围

保留`pnpm eval:score`一个命令入口，增加显式`--source service|desktop`，默认仍为service。真实执行继续由原服务runner和Electron BDD负责，本轮不新增产品调度器或另一套桌面测试入口。

| [experiment.ts](../../../tests/evaluation/experiment.ts) | `boai-experiment-v1`尝试投影、来源分组、完整配对及描述性差值 |

旧题库、冻结清单、`EvaluationRecord`和原`SCORER_VERSION`保持；实验投影是评分后的附加结构，不将桌面记录伪造成一次服务执行。服务`compareResults`现在覆盖双方完整配对集合，而不是只遍历候选；仓库调用者已经核对。

## 2. 统一尝试投影

`EvaluationTrial`分别保存题目身份、独立采样编号、retry、任务簇、分集、运行来源、技术状态、最终判定、输入/模型/预算/代码签名、证据hash、调用口径、完整与已知token、耗时和缺口。

服务记录由原评分结果投影，不改变其语义判定。桌面使用最终Playwright尝试状态，不使用fixture清单中的暂存status；原失败即使有达标文件仍为失败。没有实际结果的计划保留为未尝试/不完整。每个retry独立保留，不能用最后成功盖掉先前失败。

桌面技术通过一律保持`review-needed`，没有模型或人工语义认证。某些纯确定性场景未来可以注册专门评分合同后取消语义待评，首版不根据标题猜测。当前所有导入桌面题均为development用途，不自动成为正式留出题。

## 3. 证据边界

- 最终报告的testId、project、retry与清单必须唯一匹配；场景标题、文件和开始时间也核对。
- 逐项验证清单列出的资源及回放bytes/hash；资源限定在本场景目录，拒绝符号链接和路径越界。
- JSON读取上限16 MiB，资源上限128 MiB，回放采用流式hash；不复制巨型Trace或数据库。
- 清单缺失、损坏、重复、孤立或源码核对缺口显式记录，不能生成完整通过。
- 核验只证明清单内资源存在且匹配，不重做原BDD每个业务断言，也不证明清单外内容已采集。内容质量另评。

对第14组编辑部，首版读取已有“独立员工及模型来源”和“结束或失败时实际状态共享预算与调用”证据。其他桌面场景缺这些结构时，用量和配置保持未知，基础失败/原件核验仍可报告；不解析自由文案猜测成本。

活动profile调用数和服务HTTP尝试数分开。已有profile token可作为已知值展示，但Work账本`usageIncomplete`仍为true时，完整总成本保持null。旧桌面证据没有完整的轮次/期限预算签名，因此不凭部分Work上限认定等预算对照。

## 4. 对照与优化判定

比较使用题目＋独立编号＋retry配对，保留双方未匹配项。合同、模型、预算、评分、团队、来源和调用口径不一致，或缺证据、混代码版本时，标为证据不足。服务合同签名还包括实际scenario与交付版本，避免只相信一个沿用的标签。

全部记录可比且判定已确定时，只提供逐尝试和按簇的描述性差值；包含pending时不计算质量提升。尚未实现实验预登记、采样推断、置信区间、单人/多人受控实验和自动保留补丁。`decision: not-assessed`明确表示首版不作优化采用决定。

这补齐E1并提供E4的比较基础，不代表E2–E6已经完成。接下来应补完整实验登记和预算签名、独立题目/基线，再接校准与正式对照，最后才开放E5的有界优化。

## 5. 运行方式

```sh
# 原服务记录的离线评分
pnpm eval:score --input 已保存服务批次 --output 新报告目录 --strict

# 已留证桌面批次；输入是包含最终Playwright JSON与scenarios的run目录
pnpm eval:score --source desktop --input 已保存桌面run目录 --output 新报告目录 --strict

# 同来源的基线与候选；不可比或待评审如实保留
pnpm eval:score --source desktop --input 候选run目录 --baseline 基线run目录 --output 新比较目录 --strict
```

输出目录必须不存在，父目录需已准备。桌面输出`scores.json`、`sources.json`及`index.html`；服务报告保留原输出并增加`experiment`。原资源路径由`sources.json`及逐尝试证据相对路径定位，首版不另复制原件。

严格模式：有失败退出1；无失败但缺证据、待评审或基线不可比退出2；全部适用检查通过退出0。默认模式只生成报告；退出0不表示已通过质量认证。历史结果的实际导入与测试记录见[07](./07-实施阶段与进度.md)。
