# Agent 评估与持续优化

日期：2026-10-09。**本轮只建立设计文档；未实施本组新增能力、未运行新评估、未自动优化产品。** 仓库已有评估代码与历史样本继续保留，不能把“新方案待实施”理解为此前没有evals。后续实施需由用户另行明确启动；实际状态只维护在[07](./07-实施阶段与进度.md)。

本组要建立可持续使用的质量闭环：先把成功标准写清楚，用相同合同测量基线和候选，定位失败，再验证改动是否提高完整任务成功率、降低成本或缩短交付时间。首批聚焦Mastra/API多Agent文件协作，随后扩展到连续IM、材料与修订、记忆、Skills、工具和自动化。

## 1. 要回答的问题

- 当前功能在什么任务上可靠，在哪些条件下失败？
- 一次提示词、模型、工具说明或运行代码改动，改善了什么，又损害了什么？
- 多名员工相对单名员工，是否带来可测量的业务收益？
- 一次技术通过是否具备完整证据，内容质量是否经过适当评审？
- 在既有权限和预算内，能否稳定完成用户目标？

评估单位是一条完整用户任务及其相关会话、工作树和成果。无Work的顺序聊天按完整对话轮次评估；文件任务不能只看最后一条回复或某个子Work的状态。

## 4. 范围与边界

首批复用`tests/evaluation/`、既有脚本和`playwright-bdd`；不预建通用平台、新数据库或产品评估页面。确定性规则使用代码，开放内容使用有证据的模型评审，并由人工校准。

真实桌面验证沿用户已明确的`pnpm dev`方式，无需安装包。真实模型实验后续按批次登记配置和总预算，不自动开启周期任务或付费评估。Codex/Claude/Pi本机开发与兼容测试继续暂停，A2A继续延期，既有配置、代码和证据保持。
