## 2. 数据演进

具体字段名由实现阶段对齐现有仓库，至少保留以下概念：

| 数据 | 必需信息与边界 |
| --- | --- |
| 运行时配置 | 驱动类型、受管启动引用、版本/hash、认证方式引用、验证时间及能力revision；秘密留在原提供方支持的凭据存储 |
| 员工运行绑定 | 稳定employeeId、所选配置及revision；允许共享安装引用，不共享员工会话身份 |
| 会话运行映射 | employeeId + conversationId + phase/用途 + driver/profile revision + generation；原生sessionId只在宿主保存 |
| 执行关联 | 原用户请求/回执key、turn/run、适用Work/occurrence、外部turn/request id、序号与提交状态 |
| 上下文清单 | 已投递材料/成果/技能/记忆的来源、版本/hash、范围和清理代际，用于后续继续前复核 |
| 用量证据 | 供应商实际报告范围、已知量、未知量及可控制限额；无法取得时保持未知 |

优先沿既有SQLite schema版本和事务迁移方式增量演进，不建立第二份JSON权威工作仓库。枚举/IPC/备份版本必须一起检查；未知新驱动不能被老字段的默认分支当成Mastra执行。

## 3. 旧记录与切换

1. 旧 `mastra-model` 保持原连接、模型、工具、记忆和日程；不批量改成员工本机运行方式。
2. 旧 `acp-local` 按原“显式任务、fresh session”的能力打开；只读发现配置不自动升级为完整员工或启动外部程序。
3. 旧外部消息/run/人工文件发布保留事实。没有Work、原生会话ID或用量的历史不推测补造；旧新事件采用明确版本判别。
4. 用户选择新运行方式时，先检查该员工活动执行、未决审批、尚未终结的原Work（含待补充、依赖等待）与未知副作用；原工作须完成，或明确停止并确认实际退出后才可切换。仍未核对的请求不换绑，不因暂无活动run或已杀进程就假定安全。
5. 可切换时保存新配置revision并新建session代际；旧聊天仍可读。向新后端提供哪些历史必须按当前权限与明确策略处理，不能默认全量重播过去工具或复制个人CLI会话。
6. 现有编辑器切到ACP会清空部分API/资源字段；新交互需区分保留的设置与新方式实际启用的设置，迁移不可捏造已删除旧值。要保留备选配置时用显式记录，不能让被隐藏字段暗中生效。
7. 撤销新方式或回API是后续新请求的选择，不重执行旧任务；已经受理的工作仍按原执行身份核对和完成。

活动run的能力快照不可被配置编辑默默扩大。程序或适配器变更导致原验证失效时阻止新的执行；活动请求按原可核对身份处理，不能跳转到新程序重做。

## 4. 备份、重启与故障回退

- 备份包含BoAI业务数据、必要非秘密映射和获准受管文件，不复制本机账户凭据、个人Agent历史或任意安装目录。
- 外部原生session是否可导出、可恢复必须逐驱动验证；不可恢复时标记能力缺口并保留BoAI聊天，不保证“恢复备份即恢复外部模型上下文”。
- 重启先将未结束运行标为中断/待核对。可恢复会话只表示存在可继续的上下文；不表示允许恢复工具执行，也不免除当前权限/来源重验。
- 恢复备份改变数据代际；旧迟到事件不可写入新库。未知操作只读核对，确认无受理回执前不允许原请求重试。
- 回退策略优先停用新驱动并保留记录，继续使用已有API/旧ACP路径；有新数据后不能直接降级二进制并让旧代码静默解析，应校验schema或使用已核验的旧版本备份。
- 清理只删除归属和hash匹配的受管文件。外部已读材料与外部自有历史无法承诺物理抹除；BoAI阻止旧session继续并展示实际清理结果，宿主命令权限不冒充硬沙箱。
