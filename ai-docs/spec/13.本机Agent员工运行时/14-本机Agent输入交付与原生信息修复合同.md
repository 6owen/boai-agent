# 本机Agent输入交付与原生信息修复合同

日期：2026-10-12。用户先要求分析和建立文档，随后明确“员工绑定本机Agent在通信上类似channel入口”，复核文档后授权“开始修改”。**当前已进入实施和测试阶段，工程回归、真实批次、失败及未覆盖范围唯一归[06 §143](./06-实施步骤与自动验收.md#143-输入交付与原生信息修复实施2026-10-12)。** 本文补充[10](./10-员工一等公民与执行能力设计.md)/[11](./11-Rovai对齐与本机执行纠偏.md)，旧实际对照仍归06 §140，文档建立/复核记录归§141–142，不能将历史仅文档状态当作当前限制。

## 2026-10-13补充：本机执行不受BOAI用量预算约束

本机Codex/Claude由原生Agent管理用量与执行。BOAI不展示本机token/费用/预算，不创建以计量完整性为成功前提的规则，不施加输出、调用次数、任务时长或Work接续额度。本机文件交付、协作和自动化沿用身份/来源/成果事务，但不因此继承API预算。混合场景仅API执行计入并受API预算约束；API耗尽不取消正在执行的本机任务。

保留明确停止、进程退出/错误、启动握手和退出收尾的协议期限，以及未知回执不重放；不添加替代执行引擎。历史预算字段和失败证据保留，不自动续跑旧任务。模型/会话/公开能力信息仍可显示；计量和费用不作为本机产品界面内容。评测自身的预登记请求数是开发实验边界，与本机产品预算分开。实际实施和验证归06 §147。

## 1. 固定目标与范围

**员工是绑定的本机Agent在BOAI中带有业务身份的通信入口，消息通信方式类似channel。** 用户发给员工的正文、获准材料和明确回应到达对应本机Agent；Agent使用自己的模型、工具、项目规则、Skills、MCP、插件和内部子Agent，公开回复、执行事件、文件及Agent信息回到该员工的聊天和执行记录。员工还负责BOAI中的协作和成果归属。

绑定引用本机程序/profile及员工执行配置，适配器维护员工×产品会话×运行配置对应的原生session；绑定不要求复制安装一个新Agent，也不接管用户另开的终端交互会话。多位员工可以引用同一程序和登录来源，但保持各自聊天session与业务归属。此处的channel类比描述通信职责，不把`executionBackend`改成第16组外部渠道类型，也不另建第三套执行引擎。

```mermaid
flowchart LR
    U[用户输入] --> E[BOAI员工通信入口]
    E --> B[绑定的执行配置与会话映射]
    B --> A[本机Agent自主执行]
    A --> O[公开回复 / 过程 / 文件 / Agent信息]
    O --> E
```

保留原用户正文和来源，不用摘要或语义改写替代指令；按原生协议封装输入，必要员工/协作上下文作为附加内容。**不逐工具重建原生功能，不额外调用模型翻译每条消息或决定调用哪些工具，不把本机执行改回BOAI规定的模型阶段。** 传输/版本兼容仍由适配器处理，已有原生权限由Agent执行。

本次修复范围是输入接续、材料交付及模型/容量信息取源。保持现有员工身份、会话隔离、Work/成果、普通composer、执行面板和所选原生权限模式。审批历史缺口R2、旧评估入口E1–E3继续按[13](./13-本机Agent接入Review与评估准备.md)登记，不因本文被标为已修；API路线、渠道、A2A及界面重设计不顺带实施。

命令意图作为用户输入交给原生Agent；原生公开命令/Agent目录可以回传，但“回传目录”“执行自然语言命令”和“终端斜杠命令的原生调度”分别核验。不得将普通文字转发或目录存在写成全部终端交互已经等价。

## 3. 当前原生请求的回答接续

先区分两类事实：Agent在普通回复中询问用户且该turn已结束，用户回答是同一session的下一turn；原生协议发出仍待决的`requestUserInput`/`AskUserQuestion`等控制请求，才需要回答该action并继续当前run。不能将所有自然语言问句都改造成阻塞请求或强制同一run接续。

1. 依据原生请求的真实状态和目标绑定路由，唯一有效的公开待决请求可将普通发送作为其补充；正文附材料、只附材料均不能仅因附件降级成普通排队消息。无待决请求的新增输入或协议已明确的新输入沿原steer/队列，不自动停止；不增加关键字分类器或额外模型去猜回答/新任务。
2. 绑定真实员工、conversation、run、原生action及question身份。多个候选按现有@/来源定位或执行面板已有原生交互入口消歧；仍不能唯一确定时，在提交原生回应前给出普通提示，不广播回答、不默认塞入无法推进的队列、不强制新composer模式、不恢复“回复此问题”流程卡片。秘密问题继续走原安全回应入口。
3. 在现有产品事务中核对请求仍待决、材料版本/hash及该员工当前读取资格，保存消息/附件关联、回答绑定和本轮来源。事务失败不能提交原生回答；同一`requestId`重复调用只核对原回执，不能又回应又创建新turn。
4. 将正文及本次实际交付的材料信息回给原请求，继续同一个原生执行。不得仅移除`!materialSelections.length`后仍只发送`message.content`，也不得通过放开调度器并行运行另一轮来掩盖等待。
5. 产品事务和外部协议写入不能宣称原子完成。区分“BOAI已受理”“已尝试投递”和协议实际可确认的接收状态；停止/撤回/断线竞争保留中断或未知。没有确认能力时如实未知，重启不自动重发回答、业务或工具，也不静默改成新任务。
6. 已交付回答及材料立即计入当前run快照、原生session来源与后续成果/记忆来源核验；不能等下一轮才登记。下一次续聊不得重复注入已回答消息，也不能因跳过它而漏查原始内容、材料版本、授权和撤权。清理、撤权和配置变更沿原生命周期处理；不能声称能擦除原生已经读过的上下文。

以上状态用于可靠传输和事实核对，不新增要求用户逐条办理的业务流程；普通消息不需要Work、逐工具批准或额外模型判断才能进入原生Agent。原生确实要求的权限交互仍须准确转接。

## 4. 统一交付获准材料

首次消息和运行中回答复用同一材料交付机制，复用现有材料仓库的原件、版本、hash、成员资格和容量限制，不另造文件解析平台。**本节只约束BOAI持有的材料/产品数据如何交付，不将这些规则升级为Agent原生文件、命令或工具的统一拦截层。** 用户在正文中明确给出的文件路径、命令或项目指令保留原文，由本机Agent按所选配置和权限处理；不能因该文件不是BOAI附件而额外禁止。

- TXT/MD交付已核对的实际文本，保留文件名、材料身份、版本及来源；材料内容保持引用数据，不变成权限或宿主指令。
- 图片在协议支持的用户媒体输入中交付真实图像。原生问题回答目前是字符串，不能把base64或媒体块塞进不支持的答案字段冒充成功；可提供核对原件的受管路径，由实际可用的原生读图工具读取。
- 通用文件交付获准原件的受管路径，让原生文件/命令工具按自身能力处理。预览组件或Lody已经能打开文件，不等于模型已经获得内容；只发送名称、MIME、hash不能记为原件已交付。
- BOAI材料仓库的原件映射/副本限定于对应员工、会话和运行可用的受管输入位置，复制前后核对hash，登记来源和清理归属；材料导出接口不得因此获取任意宿主路径读取权，不导出私有登录或原生日志，不修改原材料。受管输入位置不声明为操作系统沙箱，原生工具无需全部改走宿主文件桥。
- 保持所选原生文件权限。路径可用性、实际工具和媒体协议需验证；运行时确实无法消费时明确说明具体限制，不私自提升权限、不声称已读、不把回答留在不可推进的等待队列。

“交付成功”和“Agent读取并理解成功”分别留证：前者核对真实字节/路径及协议记录，后者用原生读取活动和源文件中才能得到的任务结果检查；文件存在或模型自称读过均不足。

## 5. 原生模型、容量及公开目录

模型信息至少区分员工选择的alias/model、原生初始化实际报告的会话模型和API事件中的模型名。可以复用现有字段并增加必要来源，不强制新建平台或独立目录数据库；历史字段缺失保持未知，不按今天配置回填旧运行。

1. 保留初始化中必要的公开模型信息，以及协议实际返回的命令、Agent目录。账号、token、凭据和私有推理不进入产品展示；目录只证明公开能力声明，不能充当实际加载/执行证明。
   公开目录和容量属于可选信息：未提供、暂无法映射或未知扩展仍如实显示未知/原始公开记录，不阻止已经可用的消息执行；原生握手身份或必须回应的协议请求失败另按具体兼容错误处理。这里不要求逐命令实现菜单、另建目录服务或通过能力清单筛选用户指令。
2. 容量优先依据原生会话模型身份与当前`modelUsage`对应条目匹配。主消息的API模型名单独保留，不能覆盖原生身份后误选辅助模型。alias只在原生握手有明确解析证据时映射；不从displayName/description猜数字、不随意去掉`[1m]`后缀、不取所有模型条目的最大容量。
3. 对容量保存匹配模型、事件来源和所处会话/配置。来源不明确或有冲突时标未知并保留诊断。后续帧未报告容量时，可保留同一会话/模型已核对值及其原来源，明确这不是本轮新报告；配置、模型或来源变化后重新核对。
4. 主运行、辅助模型与缓存用量分别按原始口径处理，不为修容量把计数全部相加。上下文使用量与容量必须有兼容的模型/统计口径，不能把不同来源强行组成百分比；费用沿实际报告，不猜供应商账单。
5. `deepseek-flash[1m]`只是本次缺陷证据，不将这个名字、1M或200k写死成生产规则。按协议事实修通用映射，测试包含普通模型、alias、主/辅助同名、续聊字段缺失与不明确映射。

## 7. 验收矩阵与实施顺序

下表是**验收条件**，不是通过成绩；各项实际覆盖与剩余以06 §143为准。离线夹具检查工程机制，真实CLI/`pnpm dev`任务检查实际能力，两类不能互相替代。评估协议接[第15组12 §8–9](../15.Agent评估与持续优化/12-本机Agent任务稳定性评估方案.md#8-输入交付与原生信息修复的验收登记)。

| 场景 | 必须核对的事实 |
| --- | --- |
| 普通聊天提问后回答 | 前一turn已结束，下一消息沿同一兼容session处理，原用户指令完整；不制造原生待决action、额外模型阶段或Work |
| Codex/Claude原生阻塞请求后正文+TXT/MD | 原action被回应，同一run/原生执行继续；Agent使用新增文本，没有多建或重复执行下一turn |
| 只附材料、图片、通用文件 | 材料确实可消费；结果来自真实原件而非文件名/元数据，等待不悬挂；不支持时明确具体限制 |
| 首发与运行中附件 | 共用来源和交付规则；原hash不变，映射/副本可核对，成果继承实际输入来源 |
| 重复提交、多个待决请求 | 原`requestId`幂等、员工/action绑定准确，不串答、不重复原生投递或成果 |
| 停止/撤回/撤权/成员变化与提交竞争 | 旧请求不被失效输入恢复；拒绝/中断/未知有事实记录，必要运行按原规则收尾 |
| 回答受理前后故障与两次业务重启 | 原件/业务历史保持；重启只读核对，未知不重发；明确新消息按当前获准来源接续 |
| Claude主模型+同名辅助用量 | 原生模型与API模型分别可读；容量匹配主模型条目，不取辅助容量 |
| 续聊缺容量、alias或无法匹配 | 旧值有原来源才可沿同会话保留；不明确显示未知，不猜1M/最大值 |
| 原生公开信息及既有能力 | 已返回的公开目录不丢失，未提供时如实未知；登录/私有内容不展示，原工具/权限、Work、成果及API回归保持 |
| 用户正文中的路径/命令 | 原文到达Agent，其原生工具按所选权限执行/申请批准；不因“不是BOAI附件”追加宿主文件白名单或强制Work |
| 可选目录/容量缺失 | 任务继续执行，信息如实未知；不触发能力禁用、额外模型探测、API回退或自动重试 |

先补R1/I1的双后端红测试，修复输入路由、材料交付和来源/故障边界；M1独立补元信息映射回归并修复。工程检查通过后，以相同任务/获准原件进行小批CLI与`pnpm dev`真实对照，检查实际读取、命令、唯一执行/交付和重启，而不是只看UI恢复。
