## 1. 对照口径

Todos既有内置模型运行时，也可驱动本机成熟Agent；Codex、Claude和部分ACP程序使用不同接入方式。外部路径仍需要平台工具和能力适配，不会自动获得内置运行时的全部功能。[外部运行时](https://todos.dev/zh/docs/runtimes)

其外部运行时不提供团队技能自动加载和平台远程shell；不同CLI对运行中消息、会话回退及用量上报也有差异。Todos采用的配置隔离和无逐项审批方式是其产品选择，BoAI继续沿自身材料授权、宿主审批与实际退出合同实现。[外部运行时的能力差异](https://todos.dev/zh/docs/runtimes)

下表中的“已有基础”表示当前BoAI有对应业务对象或入口，不表示与Todos完全等价，也不表示全部运行时、平台和故障组合已经验收。“待补／待验证”按06继续；“独立扩展”表示当前IM及本机员工规格未包含的完整产品能力。

## 4. Todos中可参考的独立产品扩展

以下完整产品流程尚不属于当前BoAI本机员工方案。若后续选择开发，再建立相应专题；这些项目不作为原IM交付的前置条件。

| Todos栏目 | 参考价值与BoAI当前差异 | 后续规划方式 |
| --- | --- | --- |
| 方案与改动 | Todos保留版本化方案与文件diff。BoAI已有Work草稿／汇报和成果版本预览，但没有等价的项目Git分支与逐文件diff产品流程。[官方说明](https://todos.dev/zh/docs/plans-and-diffs) | 可以先为需要规划的工作增加固定版本方案和明确确认；Git差异预览另按项目能力设计，仍从原消息进入。 |
| AI审查 | Todos可在暂停关口让另一名Agent只读审查方案或diff，意见进入原对话，审查本身不批准。BoAI已有交付判断、群协作和采用／修订，尚无这一完整独立审查关口。[官方说明](https://todos.dev/zh/docs/ai-review) | 未来可借鉴“执行员工与审查员工分开”，绑定原Work／成果版本；意见、采用和人工认可分别保存。 |
| 项目、Todos托管仓库、其他Git服务器、GitHub | 项目仓库绑定、分支构建与合并属于Todos的代码项目工作台。BoAI当前员工workspace和文件成果不等于Git项目管理。[项目](https://todos.dev/zh/docs/projects)、[托管仓库](https://todos.dev/zh/docs/platform-git) | Git仓库连接、worktree、commit／PR／merge与权限建立单独项目专题，避免把任意文件任务强制变成代码任务。 |
| 机器、平台机器、远程shell | Todos有自有／平台执行节点及机器分配；外部运行时与远程shell有能力差异。BoAI当前受管本机程序和命令审批不等于跨机器调度。[机器](https://todos.dev/zh/docs/machines)、[外部运行时差异](https://todos.dev/zh/docs/runtimes) | 远程worker需要独立的机器身份、来源授权、任务归属、断线及取消协议；不能只增加SSH地址。 |
| 手机端 | Todos提供可安装的Web应用，移动端提出任务仍由在线执行机器处理。BoAI现有Electron界面不能直接成为手机端。[官方说明](https://todos.dev/zh/docs/mobile) | 移动端与多端同步需要账号、服务端、消息／成果同步及远程审批范围，另行规划。 |
| CLI、MCP、API key | Todos的CLI负责机器接入，对外MCP让其他客户端访问平台任务。BoAI现有开发脚本和给员工提供的内部工具桥，不等于对外可调用的产品接口。[CLI](https://todos.dev/zh/docs/cli)、[MCP](https://todos.dev/zh/docs/mcp) | 将“员工调用外部工具”“BoAI向外提供工具”“远程worker接入”分开设计；对外接口需要独立凭据、逐工具授权、幂等与撤销。 |

## 5. 继续开发的顺序

1. **先确认现有IM交互**：按[01六项清单](./01-产品范围与前端交互.md#56-保留-im-的前端验收清单)核对员工设置、本机连接、底部、能力概览、原消息及工作／文件视图。复用已接通部分，针对本次选定变更补齐。
2. **再完成本机员工范围**：从[06 §19](./06-实施步骤与自动验收.md#19-当前剩余工作清单)选择明确缺口，沿02–05和07实施。优先保证“新建员工→连续聊天→文件交付→原消息修订→停止及重启核对”的真实链路。
3. **最后扩展产品范围**：完整员工能力稳定后，再选择方案／独立审查、项目Git或远程／移动端专题。参考目录只提供候选，不能自动把所有栏目列入这次开发。

开发代理执行实际场景并提交界面、过程、原件及失败记录，用户审阅效果；离线协议、真实运行时、源码应用及发行包证据分开登记。本文补充参考对照与导航，没有新增产品验收，也不改变06已有的通过、失败和未完成结论。
