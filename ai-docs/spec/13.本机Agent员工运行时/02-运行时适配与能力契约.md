## 1. 开工基线与本组增量

开工基线 `d3ec502` 的 [ExecutionBackend](../../../src/shared/domain/backends.ts) 区分 `mastra-model` 和 `acp-local`。本机 ACP 已通过 [客户端](../../../src/runtime/adapters/acp/client.ts) 真实启动指定程序，执行握手、版本/hash 核对、单次权限请求和进程组取消。工作树后来新增的 `codex-local` 接线见[第2组30](../2.已实现功能与代码现状/30-本机Codex员工运行时实施.md)，能力证据与剩余范围归[06](./06-实施步骤与自动验收.md)；下述旧 ACP 范围不用于描述新 Codex 后端。

现行 ACP 能力为单聊显式 task、新 session、外部自有工具、未知用量；chat/decision/memory、技能/知识和宿主文件/终端桥接均未开放。当前每次运行都有独立目录，并保留显式选择文件发布入口；尚未接入普通员工的完整 Work 流程。新功能不能直接改一个能力布尔值后复用所有入口。

本组扩展为：员工选定一种运行方式后，由对应运行时承担自己的模型与工具循环；BoAI 统一承接身份、消息、阶段路由、审批、Work、资源授权与成果。Mastra API 路径继续存在，调度不依赖额外的“父模型”包装每个本机员工。

## 2. 运行方式与适配器选择

| 产品运行方式 | 接入路线 | 模型/工具循环归属 | 实施条件 |
| --- | --- | --- | --- |
| 模型 API | 现有 MastraEngine | BoAI 的 Mastra Agent | 保持原员工和连接行为 |
| 本机 Codex | 优先核验官方 app-server；保留已验证 codex-acp 路线 | Codex | 锁定程序与协议版本，验证会话、事件、审批、工具约束和取消 |
| 本机 Claude Agent | 核验 Claude Agent SDK，或具体版本的 ACP adapter | Claude 运行时 | 锁定 SDK/程序/适配器组合，分别验证认证与阶段能力 |
| 其他 ACP Agent | 现有 ACP 客户端按能力扩展 | 对方 Agent | 必须真实实现 ACP；不把任意 CLI 当协议服务 |

ACP 是连接协议；Codex/Claude 是具体运行时。SDK 也可复用现成 Agent 循环，不意味着 BoAI 要重写该循环。MCP 是受控能力桥接，不能替代运行方式；远程机器、A2A 与反向暴露 BoAI 服务不属于本组首轮范围。

沿用 [第四组通用契约](../4.数字员工与协作重构/04-员工执行后端与能力契约.md) 的判别配置，扩展具体 adapter/config 引用。实现时先核对现有导出与调用者，再确定新增类型名；不另建第二套员工、模型连接或 Work。员工 ID、聊天和历史身份不因换运行方式而改变。

同一个安装程序可以被多名员工使用；登录账户可在用户明确选择后复用。**程序、账户与员工会话分别建模**，不复用用户在外部产品里已有的个人聊天，也不把“发现程序”解释为获得登录或执行授权。

## 3. 最小适配职责

适配层只承接真正不同的运行时行为，不定义与厂商 SDK 等大的通用框架。至少需要以下职责，其输出交给产品服务核验并持久化：

| 职责 | 必须返回的事实 |
| --- | --- |
| 发现与只读状态检查 | 程序身份、配置 revision、当前可用/改变/缺失；不安装、不登录、不启动模型 |
| 明确连接测试 | 程序/协议/adapter 版本、实际握手与会话能力、失败原因；测试不冒充聊天或 Work |
| 创建或加载受管会话 | 外部 session/thread ID、作用域、配置与授权版本；不暗中导入个人历史 |
| 执行阶段 | 本轮请求身份、增量事件、权限请求、可核对终态、实际用量及其口径 |
| 中断与退出核对 | 取消是否已请求、执行是否真实结束、进程与子进程是否仍占用资源 |
| 只读对账与清理 | 外部可查询的提交/终态、受管存储清理结果、不能确认的部分 |

产品服务继续决定是否可启动、是否已交付、是否发布消息、是否可采用成果。适配器不能直接写 MemoryRepository、创建团队、认领 Work 或把外部完成事件直接变成业务完成。

## 4. 能力必须逐项、逐版本核验

能力状态沿用 `supported / unsupported / unknown`，保存核验依据与日期。有效能力是“程序声明 ∩ 适配器已验证能力 ∩ 本次权限/策略”；未知不能按支持处理。

| 核验维度 | 开放能力前的最低证据 |
| --- | --- |
| chat | 可强制无工具运行、识别最终公开回复、隔离私有事件；仅提示“不要调用工具”不足 |
| decision | 员工本人在无工具阶段返回合法判断协议；无效输出不能转成 pass 或默认发言 |
| task | 权限与工作范围、可靠终态、真实取消、结果来源可核对 |
| memory | 无工具私有候选、可约束 schema，最终仍经来源/epoch 校验入库 |
| 会话 | 创建、加载、隔离、失效和删除各自有证据；支持创建不等于支持恢复 |
| 输入 | 身份指令、当前轮、署名历史和媒体实际支持；普通 prompt 背景不能谎称系统指令 |
| 事件 | 区分公开文本、活动、工具、权限、终态；能流文本不等于有可靠最终答复 |
| 工具 | 原生工具可否禁用/批准，宿主桥接范围、外部自有工具是否可观察 |
| 用量 | 本轮/累计 token、费用、上下文占用、内部调用数分别可否观测与限制 |

程序 hash、adapter/SDK 或协议版本变化必须重新核验；账户、模型、模式、插件和配置变化按受影响维度使旧结果失效。配置校验不自动发送生产请求。界面呈现真实能力见 [01](01-产品范围与前端交互.md)。

保留三种明确用法：通过全部所需阶段的完整员工、仅 task 的受限员工、用户明确配置的混合员工。混合员工的控制阶段和任务阶段分别记录实际运行时、数据发送范围及费用；不得偷偷使用另一名员工或默认 API 连接完成外部员工的判断。仅 task 后端继续走明确任务入口，不能伪装为完整聊天员工。

## 5. 启动、登录与工具边界

延续当前 executable 实路径/hash、参数数组和 `shell:false`。只注入本后端允许的环境项；既有程序扫描、保存与测试分离，不读取其他项目密钥、不复制登录令牌。程序测试失败应保留可修正配置与明确失败状态。

Codex 登录由受支持运行时自身管理。Claude 的实际认证方式必须按所选 SDK/adapter 的官方规则验证；不能因为用户已在 CLI 登录，就承诺第三方产品能使用其订阅额度。产品展示实际账户状态、模型来源与用量可见程度，不把本机进程称为离线模型或免费调用。

`cwd`、私有目录和 MCP 范围是数据组织与桥接边界，不是操作系统沙箱。原生工具可能直接访问宿主；若运行时不能真正满足“禁止命令/无工具”等策略，应拒绝该阶段或显示受限能力，不能以提示词代替约束。

沿用当前受管进程生命周期，不按程序名终止其他用户进程。Windows 当前 ACP 因进程树取消未验证而拒绝；新适配器也须按操作系统独立验证，不能由 macOS 通过推定所有平台可用。进程池仅在会话隔离、逐任务取消和实际退出都可证明后考虑，不作为首轮前提。

宿主桥接仅提供当前获准能力；外部原生工具与 BoAI 工具分开显示。技能、材料、记忆与 MCP 接线见 [04](04-材料技能记忆与工具桥接.md)，不通过共享整个数据目录来省略授权检查。

## 6. 预算、错误与观测

外部一次 prompt/turn 可能包含多次模型调用。保留真实的外部调用次数，内部调用数和 token 不可见时记为未知；累计费用、上下文占用不能直接填成本轮 ModelUsage。适配器若提供累计值，必须固定账户/会话/基线并验证增量语义。

Work 与 occurrence 原账本继续管理预留、结算、绝对期限和追加额度。不能证明可执行的硬性内部调用/token 上限，不宣称符合该预算：先限制为明确授权的交互任务，展示可执行的时间/外部次数/输出限制；要求严格预算的群协作或自动化保持禁用，直到 [05](05-群协作核心助手与自动化.md) 的门禁通过。

认证失败、能力不支持、需补充、额度耗尽、权限拒绝、断线、中断、取消与执行失败分别保留原因。流结束、进程退出、运行 completed 都不是 Work delivered；最终发布由 [03](03-会话工作与恢复协议.md) 管理。

外部事件纳入已有运行观测入口，不伪造 Mastra 内部 span、隐藏模型步骤或精确费用；观测失败不得重试业务工具。阶段验证与上线标准统一见 [06](06-实施步骤与自动验收.md)。

阶段思考强度与预算限制分开。适配器可以对已验证程序/来源/模型的私有判断或记忆设置明确强度，但必须验证实际发出的参数、保留原业务判断和来源校验，并记录实际配置；任务执行、交付汇报及其他模型不能无依据继承该覆盖。强度较低不表示 token 硬上限已受控，不提高原Work额度、不将超额失败计为通过。当前Claude私有阶段实现见[第2组31 §12](../2.已实现功能与代码现状/31-Claude运行时底层接入.md#12-私有判断与记忆的阶段强度)；v8另对宿主已明确认领的组织管理Work验证低档，群内业务工作仍保持原配置，边界见[§14](../2.已实现功能与代码现状/31-Claude运行时底层接入.md#14-组织管理与业务执行的阶段强度)。实际结果仍以06为准。

已受理依赖的私有等待汇报只重新判断当前草稿是否公开，不能执行任务、取消等待或自称已交付。可以对已验证来源/模型单独验证这个阶段的强度，必须以当前Work及本轮非空pendingWait为条件；历史依赖、空依赖、员工身份、文字中的“等待”及用户问题不能隐式取得该配置。普通交付审核仍保留原配置。Claude v9历史边界见[第2组31 §21](../2.已实现功能与代码现状/31-Claude运行时底层接入.md#21-已受理依赖的私有等待汇报强度)，当前v10显式参数见[§22](../2.已实现功能与代码现状/31-Claude运行时底层接入.md#22-私有等待汇报的显式思考参数兼容)，实际效果与未完成范围沿06记录，不以参数回归替代真实协作和应用包验收。

思考关闭与较低强度也要分开核验。固定程序如果只省略thinking字段，不能在默认开启思考的提供方记录为off；必须核对实际传输参数及其来源语义，再验证真实判断和原预算结果。CLI设置名称或同名API参数不构成兼容证明，未验证开关不进入生产。Claude 2.1.214的当前假端点字段检查、真实失败和后续核验范围见[06 §71](./06-实施步骤与自动验收.md#71-claude私有等待汇报分阶段配置2026-10-06)。

当前v10兼容仅用于已验证私有无媒体格式阶段：CLI取得本轮nonce与回环端点，宿主持有原API来源/凭据；鉴权后仅转Messages，明确disabled并移除effort，保持原模型、消息、格式器与响应字节。桥不增加自身重试/重定向或业务权限，错误和原取消沿实际退出结算。其他模型/公开/媒体及混合effort在启动前拒绝；普通业务阶段不继承。实际参数、同输入真实语义与产品回归分开记录，范围及当前缺口见[06 §72](./06-实施步骤与自动验收.md#72-claude私有等待汇报显式关闭思考2026-10-06)。
