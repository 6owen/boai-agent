## 1. 原生会话与产品身份

Conversation 仍是用户看到的聊天，员工 ID 仍是署名和权限主体。外部 thread/session 是员工在特定运行时内的上下文载体，不能代替 Conversation 或 Work。

新增持久映射至少绑定：员工、产品会话、运行方式与配置 revision、阶段隔离域、授权/来源代际、外部会话 ID、最近已提交轮次，以及本次运行 generation。字段落在现有持久化层，由宿主维护；不能只放内存或以工作目录名反推归属。

同一程序的两个员工、同一员工的不同聊天及不同阶段都不能串用上下文。decision/memory 的私有协议使用独立隔离域，不能混入公开 task 的持续 transcript；chat/task 是否复用同一原生会话，须验证每轮工具策略切换和既有上下文符合当前授权，否则分别映射。

阶段边界、后端能力和无工具要求继承 [第四组契约](../4.数字员工与协作重构/04-员工执行后端与能力契约.md)与[02](02-运行时适配与能力契约.md)。缺少安全加载能力时采用受管的新会话与当前获准上下文，不谎称恢复了原生历史。

## 2. 连续聊天与上下文生命周期

普通“发送”仍是 IM 消息，不能自动取消正在执行的工作。宿主在发送事务保存稳定请求身份、原消息和轮次后调度；未获得执行权的后续消息按原会话机制处理，不能直接向同一个外部会话并发追加 turn。

新外部会话首次载入员工身份与当前获准的有界上下文。后续沿已确认的消息边界注入新增信息，保存实际来源；原生持久 transcript 与宿主历史不能每轮重复全量叠加。外部压缩摘要只能是上下文缓存，不能替代 BoAI 的消息原件、来源或长期记忆。

员工换运行方式、程序或配置变化、聊天清空、成员/资源撤权、来源失效时，先使受影响映射不可复用。若外部无法删除特定旧上下文，应新建会话并重新提供当前获准内容，禁止继续用仍持有撤权内容的旧会话生成公开结果。

原生会话中可带入的材料、技能及派生记忆见 [04](04-材料技能记忆与工具桥接.md)。外部程序的全局配置、自动发现技能和日志可能独立保存；未完成验证前不能宣称清空 BoAI 聊天已删除这些副本。

## 3. 阶段路由与 Work 接线

普通 chat 不创建 Work。用户明确任务或员工有效判断产生 task 时，复用原 WorkIntent、稳定原始请求和业务受理事务，不用员工 ID、文本相似度或外部 session ID 推断工作去重。

| 步骤 | 产品宿主负责 | 外部适配器负责 |
| --- | --- | --- |
| 受理 | 消息/回执、原始工作身份、权限快照与必要执行意图同事务保存 | 此时不启动副作用 |
| 认领 | WorkRepository 条件事务认领、容量与预算预留、绝对期限 | 核对程序与已验证能力 |
| 执行 | 固定 run/Work/阶段/代际，持久记录投递状态 | 启动或加载受管会话，发送本轮，返回真实事件 |
| 审批/补充 | 原聊天卡片保存明确问题或权限身份 | 暂停等待正确请求的答复，不自行批准 |
| 结果 | 核对来源、权限、草稿与成果，原事务提交业务结果 | 返回可检查的终态与产物候选，不直接宣告已交付 |

外部 task 的父子 Work、依赖、重试和预算继续沿原实现，不建立“外部任务表”作为另一套业务权威。各个外部执行可以有投递记录，但它只解释 Work 的某次执行。外部 Agent 自己的子 Agent 事件不自动变成 BoAI 员工或子 Work。

当前 [sendExternalTask / executeExternal](../../../src/runtime/service.ts) 保存消息、run 和回执，不创建 Work；显式选文件发布也没有原 Work 归属。该历史路径保留真实标签，旧 run 不回填虚构 Work。新版入口的 Work 绑定须通过迁移与专项验收后启用，旧资料仍可只读核对。

## 4. 流式事件与消息提交

归一化事件至少包含本次 run、外部 turn/session、generation、适配器顺序或事件 ID，以及原始事件类型。处理前复核当前执行权与授权；外部 ID 仅在对应映射内有效，不能拿一个工具 ID 跨轮复用。

| 外部事件 | 产品处理 |
| --- | --- |
| chat 阶段可公开回复增量 | 映射到本轮员工流式消息，最终完成仍需提交核验；task 草稿保持私有 |
| 活动、计划和工具进度 | 进入原运行活动/Trace 入口，不当作最终成果 |
| 私有推理或内部协议 | 不发布到公开正文、搜索或记忆 |
| 权限请求/需要补充 | 创建或更新原聊天中的对应卡片，不另建待处理中心 |
| 文件/URL/产物候选 | 先核验归属、原件/hash 和当前权限，再进入原成果发布机制 |
| 外部终态 | 更新执行事实；业务交付由 Work 结果与证据决定 |

迟到事件、重复事件和恢复时历史重播不得重复创建公开消息或再次登记完成序号。对缺少稳定事件 ID 的协议，不承诺任意重播可安全合并；限制为可证明的活跃流，断线后进入核对。

仍沿用真实公开完成回复的原事务登记、ordinal/epoch/contentHash 阅读身份和历史定位。任务草稿先私有保留；发布前新消息或来源变化只沿原有界汇报修复规则处理，不重放外部工具。成果 adoption、修订、预览与工作 delivered 分开，交互见 [01](01-产品范围与前端交互.md)。

## 5. 审批与用户补充

权限卡片绑定员工、run、外部会话/turn/request、具体操作、所见配置与授权版本。用户允许或拒绝只回答该请求；取消、撤权、会话代际改变后旧答复失效。默认拒绝未知权限类型，不能依据外部文本声称“已获授权”或选项顺序自动放行。

用户审批通过原聊天消息办理，右侧文件详情继续只读。不为不同后端再加一套批准开关或在终端里等待用户操作；确需外部登录时给明确状态和入口，登录完成也不自动重新发送业务任务。

“回复此问题”沿同一 composer 绑定原问题/version/消息及适用 Work/occurrence。普通发送不解除业务等待；补充核验和消息提交共用原事务，不能把新的普通消息偷换成旧审批答案。收到人类输入后先认领原工作和剩余额度，再接续未完成步骤。

## 6. 取消、退出与未知投递

停止先持久化取消门禁，拒绝后续发布；再向受管外部 turn 发取消，等待实际执行终态与资源退出。断开流、cancel 回执、进程退出和远端模型/工具停止是不同事实。只能证明进程退出时如实记录，不能声称已撤销之前的文件或网络副作用。

未确认实际退出前保留占用，不允许旧 run 释放新 run 的容量。进程超时按受支持平台策略终止本应用启动的进程树；清理、删除、应用退出均等待相关执行器实际退出。会话或任务中止不关闭无归属的其他员工/用户进程。

从发送到确认之间丢失回执时，保存原请求载荷、稳定 key、外部引用及“结果未知”。优先调用适配器可证明无副作用的查询接口；不能把重新连接、重新发 prompt 或重新审批当作查询。厂商不支持幂等提交时，不承诺跨崩溃 exactly-once。

普通IM发送在宿主受理前保存原稳定请求和冻结输入；材料只保存id/版本，不能连同媒体或任意路径持久到发送状态。旧ACP未决记录沿原key保留。重启恢复unknown后复用原composer核对入口，不因当前聊天展示了回复就猜测原提交已完成；本地保存失败先拦截新提交，不可读记录不能被空状态覆盖。

只有可靠确认未提交，才允许使用原请求重试。已执行或结果仍未知，保留待核对与可见证据；不能自动换 session、换运行方式或补一次模型调用“试试看”。需要用户另开工作时说明原工作状态，不能悄悄重演旧副作用。

## 7. 重启、恢复、配置切换与清理

启动只读取已提交事实并将未终结执行标为中断或待核对；不自动启动外部程序、接续 prompt 或重放工具。能加载原生会话只表示可取得上下文，不等于有权恢复未完成任务。显式继续也必须先满足无未知副作用、来源有效、原预算与当前容量条件。

配置切换先核对活跃执行、原审批及尚未终结的原Work（含待补充、依赖等待）；原工作完成，或明确停止并确认实际退出后才允许切换。仍有未知副作用时保持待核对，不因暂无活动run而放行。旧 run 固定旧配置，不被新配置覆盖。新工作使用新配置与映射，历史消息、成果、费用和证据保留原来源。切回旧配置不能自动唤醒之前的进程或会话。

本机员工保持同一后端和启动项时，更换来源连接或模型ID同样属于运行绑定变化，必须经过上述检查。检查发生在保存配置和取消原执行之前，拒绝时不得增加配置版本或改写原工作及账本；姓名、职责等普通资料编辑继续沿已有版本和取消合同。实际代码修复与来源换绑的分批证据见[06 §86](./06-实施步骤与自动验收.md#86-本机员工模型绑定切换门禁2026-10-07)。

备份包含 BoAI 已提交的映射与业务事实；外部存储若无法以稳定快照备份，记录其不可恢复范围。恢复后重核本机配置与来源，外部引用默认需要核验；不能凭一个 session ID 承诺在另一台机器继续运行。备份副本必须携带恢复后不可直接续用的持久标记，不能依赖目录变更才识别恢复；同路径回滚同样适用。启动只撤销旧映射的续用资格，保留原执行事实，不启动外部程序；下一次用户消息从当前获准有界上下文建立新会话。正常重启不能反复使恢复后新建的会话失效。受管原生私有运行目录不进入业务备份，同名用户工作文件不按名字误删或排除。

清理删除受管映射和已授权范围内的数据，保留最小去重身份以阻止旧请求重放。原件仅按归属/hash 清理，外部修改保留冲突；外部自有日志清理不支持或失败必须分开报告，不扩大到扫描/删除用户个人 Agent 历史。

## 8. 验收落点

至少覆盖双员工共程序不串会话、同员工跨聊天隔离、消息连续注入不重复、工具关闭证据、重复/迟到事件、权限陈旧版本、断线未知投递、执行中撤权、真实进程退出、重启不重放、旧 ACP 无 Work 历史保留，以及新任务/成果在原聊天和工作视图一致可查。

群协作与 occurrence 的扩展见 [05](05-群协作核心助手与自动化.md)，完整实施、离线与真实运行证据要求见 [06](06-实施步骤与自动验收.md)。这些条款按06逐项验收；既有 ACP 测试或其他后端通过不能替代新运行时证据。

## 9. 当前执行详情与线程选择（2026-10-10）

员工执行清单按原运行ID和当前可见会话/成员、原触发消息及清理门禁读取，稳定时间/ID分页。详情不触发恢复或模型调用；原运行冻结的执行资源、员工配置版本和实际模型回执不随后来换绑改变。聊天仍按员工×会话复用已确认增量线程，任务/私有阶段仍为独立短期线程；Work接续从原业务证据重新构建，不承诺任务线程跨轮复用。Codex实际线程/turn提交引用仅用于核对，不取得重放授权；重启继续原未知不重放规则。明确停止原工作继续等待实际退出；详情不提供本机原运行重试。详见10 §13、06 §119。
