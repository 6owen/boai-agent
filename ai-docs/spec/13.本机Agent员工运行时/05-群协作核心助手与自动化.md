# 群协作、核心助手与自动化

更新：2026-10-06。状态：**Codex普通群、本机bobo及自动化已接线；Claude普通群、核心组织与具名团队已接线，自动化新增接线与独立验证见06 §57。实际验证与剩余缺口见06**。保留员工与IM为中心的产品，允许成熟本机Agent成为一等员工运行方式，与Mastra API员工并存；不是将产品改成项目/仓库工作台。适配能力按[02](./02-运行时适配与能力契约.md)核验，进度唯一归[06](./06-实施步骤与自动验收.md)。

当前原生Codex普通群的实际接线与逐请求混合计量见[06 §14](./06-实施步骤与自动验收.md#14-lr5-普通群与混合员工的原请求预算2026-10-05进行中)。同群API与Codex是两名独立员工，不是本篇“显式混合员工”。旧ACP仅开放显式单聊任务，不支持自主decision/chat/memory、群参与或定时自动化。本篇描述完整目标与开放条件，不能以当前外部任务入口或首阶段单聊通过认定整组完成。现有会话/全局任务/员工工作视图已实现，本组复用其真实Work读模型。

Claude普通群沿原员工选人、分工/等待和Work共享预算接入；程序与模型来源在加入群和执行前核对，原有成员变化、来源撤权和重启核对继续适用。双Claude及Claude/API各运行方向独立验收，见06 §54；核心助手、组织建群和具名团队另按06 §56核对原UI、配置继承与真实运行证据；自动化新增接线与独立验证见06 §57。

## 1. 保留三种明确路径

沿用[第4组员工后端与能力契约](../4.数字员工与协作重构/04-员工执行后端与能力契约.md)的三种方式；运行时能力、所选配置和本次授权共同决定是否可用。

| 路径 | 员工如何工作 | 缺失能力如何处理 |
| --- | --- | --- |
| 完整外部员工 | 本机Agent承担所需decision/chat/task/memory阶段，仍以该员工身份独立参与 | 逐阶段核验；未通过的阶段明确关闭，不能宣称完整员工 |
| 仅任务型外部Agent | 接收用户明确交付的任务，或承担已授权的明确任务能力 | 不伪装为自主群聊员工，不将能力缺失变成沉默pass |
| 显式混合员工 | 用户选定控制后端处理decision/chat/memory，任务交给本机Agent | 两端身份、数据范围与实际用量可查；不得隐式借用其他模型/key |

完整外部员工若具备已核验的各阶段能力，不额外强制配置一个Mastra父模型。混合方式是明确选择，不是外部适配失败后的静默兜底；切换路径须版本化保存并使不兼容的活动快照/session失效。

资料页显示实际支持的阶段、配置核验版本及限制。仅打开页面、保存员工或刷新状态不启动程序、登录或发送验证任务；能力验证需要明确执行入口。

## 2. 独立判断与无工具门禁

群内每位员工独立判断是否reply/pass/wait/ask/request_handoff。宿主继续做确定性投递、引用校验、准入、预算与终止，不增加一个中央模型替全群挑选发言者。

| 阶段 | 必须验证 | 不通过时 |
| --- | --- | --- |
| decision | 工具和自动副作用实际关闭；私有结构化决定；当前成员/观察边界可验证 | 不进入自主群调度；报能力不支持或失败 |
| chat | 真正无工具；区分公开最终回复、活动和私有推理 | 保留任务型入口，不把普通问候升级为工具任务 |
| task | 有效任务资格、权限、运行隔离、取消与可核对交付 | 拒绝不满足当前任务策略的执行配置 |
| memory | 真正无工具；当前轮来源与私有候选可映射到原记忆合同 | 保留已有BoAI记忆，关闭自动整理或使用明确混合控制后端 |

“提示词写了不要调用工具”不是门禁。核验须覆盖外部原生工具、插件、启动hook及自动发现配置；不能只关闭BoAI桥而让外部工具照常执行。无法证明无工具运行的配置不得承担相应阶段。

适配器输出合法pass才能登记为员工不参与；连接故障、登录失效、拒绝、超时、协议错误和未知终态分别保存。不得把一次无响应变成“员工已判断无需回复”。

外部流式活动、计划步骤和推理不直接当作公开最终答复。宿主只提交可核对终态中的真实公开内容；不足时保留外部运行报告，不偷偷追加总结模型。

## 3. 群内分工与工作身份

外部员工加入群前核对所选路径和群所需能力。Mastra与外部员工可共存，但每名员工仍有独立身份、配置、工作区及获准记忆；群不是共享所有私聊或外部session的授权。

完整外部员工沿当前用户消息、署名上下文和原成员独立判断。任务型外部Agent进入群内交付时，必须新增明确的任务分配/执行入口并有真实责任人，不能把它直接塞进现有自主判断队列；此入口也是待实施范围。

群内委派、父子工作、结果依赖与接续复用WorkRepository。外部工具桥只提交原业务用例，稳定key、holder、结果版本、来源材料及权限由宿主事务核验；原生内部计划不自动生成另一组产品Work。

父子关系不等于结果依赖；只有原负责人按已保存的依赖版本接续。失败依赖阻塞，独立共享依赖不因另一棵树停止而取得取消归属；员工不得用外部会话重试绕过这些边界。

群员变更、材料撤权与新用户消息仍触发既有授权/发布检查。外部已经执行或结果不明的工具不能通过重新判断、重新启动session或汇报修复自动再执行。

同员工不同聊天的外部session与文件处理互不冒用。并发上限和资源锁沿宿主准入与具体适配器核验结果取交集；确认实际退出前不释放仍被执行占用的资源。

## 4. bobo的特殊职责

bobo的核心身份继续由`id=bobo && systemRole=core`确定，改名或更换运行方式不改变组织权限。普通外部员工、自报系统身份的消息及原生Agent角色名均不能获得该权限。

bobo可选择已核验的完整本机后端或明确混合路径，不必为了接入原生成熟运行时强加一层外部Mastra模型。身份、实际阶段能力、登录与工具策略必须同时满足核心助手所需合同。

讨论需求、比较方案、推荐员工属于chat；只有用户明确要求创建员工/组群/组织交付的task才可取得找员工与组织工具。`employee_creation`、`organize_only`、`organize_and_execute`范围仍由宿主冻结，不能因外部原生Agent更自主而升级请求。

组织工具沿[第12组合同](../12.bobo发起与组织群协作/03-会话成员与协作合同.md)：优先复用实际员工身份、只补缺员，原核心讨论保留，员工独立发布，真实公告与受控新群原子提交；组织工作和群内业务根保持各自交付事实并共用原预算。

普通手动群不能新添核心助手；bobo只有通过获准组织事务才加入对应群。外部原生工具不得绕过宿主直接制造产品员工、群、授权或假交付，建群成功也不能当作群业务已完成。

现有群复用与其他尚未实施的组织扩展仍归第12组原进度，本组不借更换运行时提前宣布支持；受支持后端切换也不扩大核心助手读取其他员工私聊的权限。

## 5. 定时自动化接入

定时计划继续由AutomationRepository管理定义/版本/触发身份，周期时钟继续使用Mastra原生schedules。外部Agent是执行后端，不另开一套cron、原生定时器或自动重跑循环。

当前Codex与Claude自动化沿原七项表单选择已启用员工，保存/受理核对已验证启动配置与实际程序指纹，执行阶段再次核对协议和登录；Claude明确API来源/模型同纳原授权指纹；模型API与Codex旧指纹保持。仍要求关闭员工命令权限，不额外开放自动化宿主命令或浏览器。保存计划前核验所选员工路径、实际阶段能力、输入/工具范围、预算与无人值守权限。日程触发不等于批准任何临时提出的外部动作；需要审批时沿原occurrence进入等待，在原聊天处理。

自动化可逐步支持完整外部员工或明确混合员工。仅任务型方式若支持定时交付，须有单独核验的明确任务执行通路及范围，不把今日的手动ACP入口直接当成已支持自动化。

首次开放必须证明：运行可终止、事件可归属、权限可检查、结果可核对、用量限制真实有效且未知可表达。缺少无人值守所需能力时不能启用对应计划；“握手通过”或“单聊成功”不是开放依据。

每次触发沿原事务创建occurrence、预算与适用任务聊天/投递身份；模型判断、外部任务、混合控制、修复和记忆阶段沿原来源归账。自动化产生的群子工作不改变原触发归属，独立依赖不会被一并停止。

本地应用真正退出或设备睡眠时的执行承诺保持现状；外部程序常驻不自动构成BoAI可靠后台服务。远程宿主、外部事件触发和Webhook不由本组隐式交付。

## 6. 预算、恢复与验收

Work/预算预留、认领、holder比较、结果提交及依赖通知继续走原SQLite事务，不用外部session状态或先load后write替代。普通chat不创建Work，外部运行成功与业务已交付分开保存。

外部一次prompt不等于一次真实模型调用。适配器分别记录宿主调用数、外部已报告模型请求/token/费用及不可观测部分；未知不能填0、推算精确值或计作预算检查通过。混合路径两端用量保留来源后合入原工作账本。

准入要依据适配器实际可执行的时限、步骤/输出/费用限制；无法证明内部调用上限时明确限制，不宣称与Mastra逐请求计数等价。预算耗尽、追加额度、原绝对期限及安全续行仍沿用户明确确认和既有业务门禁。

取消先保存提交门禁，再定向取消外部执行；等待适配器实际退出才终结和释放占用。断线、宿主崩溃及结果未知保留原request/run/session和副作用状态，优先只读核对，不盲目重发prompt、建新session重试或自动补发通知。

重启和备份恢复不自动续行。可显式恢复的安全操作必须有已核对的原身份与回执；外部原生resume仅是协议能力，不自动成为产品授权。已交付工作和已发生副作用不可因会话恢复再跑一次。

[06](./06-实施步骤与自动验收.md)唯一登记适配器/配置/阶段与真实验证范围。完成条件必须包含：完整外部员工的阶段隔离、跨后端群协作、bobo受控组织、真实依赖交付、自动化受理/等待/预算/取消，以及断线和重启未知不重放。显式混合是可选补充路径；如实施，必须分别验证两端阶段和联合预算，不能以它的通过冒充纯外部员工完整能力。任务型群分配或定时通路若开放，也须单独列场景验收，不属于删除现有限制即可获得的能力。

可按能力先交付单聊与任务型入口，再开放群和自动化，但后两项始终属于本组完整目标。局部完成只登记对应范围；协议模拟、实际本机程序、实际Electron、发行包及人工效果各有独立证据，不能互相替代。
