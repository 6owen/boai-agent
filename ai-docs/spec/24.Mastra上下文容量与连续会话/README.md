# Mastra 上下文容量与连续会话

更新：2026-10-24。状态：用户已启动实施；本地候选已接线，机制与受控SDK验证见02，真实供应商质量和桌面旅程尚未认证。

本组只针对 BOAI 的 Mastra/API 数字员工，实现以下内部链路：

容量检测 → 压缩或换内部 Session → 保留交接与历史定位 → 继续原工作。

用户已经明确的产品设计：

- 员工是独立、持续的数字员工，保留其独立 workspace、人格、技能、配置与装配方式。
- 同一个员工可以在私聊中记得群里的工作，也可以在群里使用私聊形成的记忆；默认跨聊天召回是预期能力。
- 用户继续看见同一个联系人和连续聊天记录；不新增话题入口、模式开关或 Session 管理页面。
- 自动化继续沿现有员工/群会话呈现，内部执行会话和上下文可以独立；保留 occurrence、Work、Run 和交付设计。
- 群共同记忆可以另行添加，作为员工记忆的补充，不是本组容量管理的前置条件。
- Codex、Pi、Claude、OpenCode 等原生运行时不属于本组实现或验收范围。

## 实施原则

复用现有 Mastra 请求循环、模型连接、员工装配、ProductStore、来源校验和执行账本。容量维护是原工作内部的状态转换，不能创建另一名员工、改写业务结果、重置预算或重放未知工具操作。

当前普通 API 历史窗口已有消息数和字符限额，不能笼统称为“完全没处理容量”；缺口是模型窗口感知、逐步请求检查、历史语义压缩、持久上下文分段及可核对的接续。Bobo 的 Mastra Memory 路径也需兼容同一容量合同，不改变其产品会话设计。

本轮已进入代码实施与定向验证。保持第25组为历史参考；其他暂停目标沿其原状态。实际完成范围、失败与剩余只记录在02第5节。
