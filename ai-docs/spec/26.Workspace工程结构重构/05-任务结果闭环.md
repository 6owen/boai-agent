# 任务结果闭环

## 1. 范围和现状

- 本轮任务结果固定为一次真实执行工作 Work 的当前投影，身份是 workId。不会将 tasks.* 手工追踪清单、计划、普通聊天或单个 Run 自动变成 Work。
- ProductStore 继续是 Work、Run、结果消息和成果版本的唯一持久来源；不建结果表、不复制执行状态、不建立新的任务调度器。
- 现有 WorkViewRepository 已负责可见来源及原消息/成果定位；ArtifactRepository 已负责受管文件、原 hash、来源与权限校验；WorkRepository 的继续认领事务保留未知副作用与依赖门禁。
- 当前任务主页面有明确占位，WorkCard 尚无实际页面调用。本轮接入现有聊天执行卡和执行详情，避免仅修改未挂载组件或扩张任务产品。
- Web、远程账号、手机端以及完整任务中心均不在本轮。

## 2. 共享读取合同

- 新增 getTaskResult({ workId })，桌面IPC和owner CLI传输均调用同一AppService投影。
- 返回版本化的工作身份、目标、真实状态、结果版本、原记录总结和下一步；执行状态与文件可读状态分别表达。
- 结果文件仅取此Work明确关联的不可变artifactId，核对conversation/sourceWork与内容hash。通过现有受管文件校验才标为可读取；缺失、外改、撤权和未核旧记录均保留不可用身份及原因，不把发布事件当文件存在。
- 结果消息只取Work明确关联且当前来源合法的原消息；返回有界摘录和截断标记，不输出私有草稿或内部工具参数。
- 关键记录取当前工作有界的最近Run，包括状态、阶段、时间和工具状态计数；失败原因来自原Run.error/Work记录，缺失明确未知，不生成猜测。
- 返回各类total/truncated信息，避免把有界列表冒充全量。点击原文件或原消息继续通过原解析/预览接口复核，不授予永久读取权。
- 查询拒绝隐藏、清理、错会话、失去原来源的工作；不恢复隐藏会话，不创建消息、Run、Work、回执或继续执行。

## 3. 继续入口

- 结果视图只给当前可请求继续、需人工核对、不可继续等读取状态，不保证模型一定续成原工作。
- 普通API工作的资格复用原Work继续检查：状态、执行持有者、未知工具副作用、预算、依赖与父工作；同时核对Run停止投影、当前会话活动、原员工和原来源/后续结果。
- 自动化、组织、修订及本机运行等现有专用流程不被此接口重新解释；需要专用处理时保留原会话/执行入口和明确原因。
- 结果Dialog合格时只提供“返回聊天继续”关闭入口；唯一发送器仍是原聊天卡ContinueRunButton，以其原requestId和锁发送本人真实“继续”消息，仍走原sendMessage回执及Work认领事务。查询本身和CLI task result不发送消息，不自动调用retryRun、不重放工具。
- 读取资格是瞬时投影，实际发送与认领仍由现有事务重新核对；重复点击沿原稳定requestId回执。

## 4. 消费入口

- CLI：task list通过原queryWorkViews发现workId；task result WORK_ID读取共享结果JSON，可配合--json；连接、owner授权、退出和凭据沿原CLI。
- 桌面：聊天终态执行卡及现有执行详情提供按需“任务结果”，展示同一结果文件、摘要、失败与关键记录。面板隐藏停止读取，身份切换和清理事件丢弃旧响应，失败经Sonner；读取不改变聊天历史。
- 结果预览沿getArtifactPreview原hash及当前权限；继续保持原聊天消息入口，执行历史不新增发送/继续操作。
- 不在UI暴露存储路径、原始内部JSON或开发合同；文件显示实际文件名，技术身份仅保留在CLI结构化输出。

## 5. 实施和验证

- 先落本文，再新增shared DTO/schema、runtime只读投影与公开方法，随后接CLI和真实桌面入口。
- 添加定向回归源码：真实文件缺失/外改/撤权、错身份、隐藏/清理、缺少结果、文本结果与交付文件区分、有界截断、未知副作用与已续行阻断、查询零业务写入、传输owner边界。
- 保留现有测试、阈值、UI基线和继续语义。
- 初始仅授权轻量静态检查；后续用户已明确授权隔离副本定向测试、构建和临时profile桌面结果面板，统一由root编排。真实模型、个人数据和正在运行的dev仍不触碰。新增源码测试未执行时明确记录。
