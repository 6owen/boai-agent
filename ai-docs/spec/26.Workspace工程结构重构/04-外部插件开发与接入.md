# 外部插件开发与接入

## 1. 本轮范围

- 外部开发者可以在独立目录或自己的仓库中实现Runtime Provider，不需要导入BOAI宿主源码。
- `@boai/runtime-plugin-sdk`仍是私有工作区包；开发工具从它的真实版本、exports和依赖生成本地tarball，包含JavaScript、TypeScript声明及manifest JSON Schema。此tarball不是npm发布。
- 提供Text Inspector确定性示例：统计输入文本的字符、单词和行数，可选择返回预览。它不调用模型，不读取文件，不支持工具、图片、审批、续聊或运行中追加输入。
- 构建后的插件是目录包，通过现有设置中的运行时插件安装入口安装。安装器不执行npm脚本，不安装依赖。
- 本轮不增加市场、下载器、远端仓库、npm发布、Web端或新运行时协议。

## 2. 现行合同

### 2.1 SDK与版本

- 公共入口仅为`@boai/runtime-plugin-sdk`和`@boai/runtime-plugin-sdk/manifest`；工作区通过development条件读取源码，外部tarball通过types/default读取编译产物。
- 新模板使用`RUNTIME_API_VERSION = 2`。模块必须导出同值的`runtimeApiVersion`和`createRuntime(services)`。
- manifest的`apiVersion: 2`是插件清单版本；贡献中的`runtimeApiVersion: 2`是Provider API版本；`probe().protocolVersion: 1`是现有宿主探测回执版本。这三个字段不能互相替换。
- manifest schema继续接受已存在的v1插件；v2私有模型来源与原生来源身份规则保持。模板不声明这两项能力。
- SDK版本来自`packages/runtime-plugin-sdk/package.json`，zod依赖保持现有精确版本。不复制一套业务类型，不导入`@boai/runtime`或`@boai/shared`。

### 2.2 可安装目录

- 根目录包含`manifest.json`、`LICENSE`或`LICENSE.txt`或`LICENSE.md`；模块入口为manifest指定的包内`.mjs`。
- 同一清单只有一个`agent-runtime`贡献。插件ID与Provider ID是稳定身份，发布新版本应保留身份并修改三段式版本。
- 复用宿主限制：最多128个普通文件、256个节点、8层目录；单文件不超过16 MiB，合计不超过32 MiB，manifest不超过32 KiB；禁止符号链接。
- 示例输出单文件模块，第三方运行依赖须打入模块；Node内置模块可以保留。BOAI安装器不会根据开发项目的package.json安装依赖。
- LICENSE示例仅标注私有开发用途，没有代替作者选择公开分发许可。作者对外分发前应替换为自己的许可及所需第三方声明。

### 2.3 预检与宿主责任

- 预检读取文件、用SDK schema校验manifest、静态解析模块入口与依赖闭包、检查必要导出，不import或执行插件，不联网，不接触profile。
- 预检是模板所支持的自包含模块打包合同，不证明运行行为、能力声明或凭据安全。动态拼接的import/require无法由静态检查证明，应避免使用；现有宿主仍决定实际加载结果。
- 安装仍使用原revision CAS、内容hash、staging原子提交、活动lease与版本固定。过期revision、活动中的更新/卸载、文件篡改仍由原事务拒绝。
- 清单格式/API不兼容沿原schema拒绝；模块导出API与manifest不符沿原runner的“插件Runtime API不兼容”拒绝。不得把预检通过当作已成功握手。
- 外部模块运行在现有插件子进程。它是受信任的本机代码；本轮没有新增隔离沙箱或放宽现有权限。

## 3. 开发流程

### 3.1 从BOAI导出独立项目

在BOAI仓库根目录执行：

```bash
node scripts/runtime-plugin-devkit.mjs sdk
node scripts/runtime-plugin-devkit.mjs create /绝对路径/boai-text-inspector
```

- `sdk`在`.local/plugin-devkit/sdk`生成编译后的SDK，并在`.local/plugin-devkit`生成本地`.tgz`，不进入应用dist分发或构建身份。
- `create`生成同一个SDK tarball，将模板及tarball复制到指定新目录；拒绝已存在目录，不创建Git仓库。目标可在BOAI仓库之外，生成后不需要保留BOAI源目录。
- 生成项目的SDK依赖指向项目内`vendor/`。生成器从BOAI根manifest继承packageManager（当前pnpm@10.13.1）及现有TypeScript/esbuild精确版本，不升级依赖。外部项目使用所声明的pnpm版本，避免全局主版本差异切换store导致离线缓存不可用。
- 两条命令都不自动安装依赖，不启动BOAI，不修改插件登记或真实profile。

### 3.2 独立项目内开发

```bash
cd /绝对路径/boai-text-inspector
pnpm install
pnpm typecheck
pnpm build
pnpm check
```

- 安装依赖需要可用的包管理器缓存或网络；只有后续`check`保证离线且不执行插件。
- 修改`src/index.ts`实现Provider，修改`manifest.json`声明身份/配置；`includePreview`只控制结果中的输入预览。
- `build`先类型检查再打包，输出`package/manifest.json`、`package/plugin.mjs`和`package/LICENSE.txt`，最后调用同一静态预检。
- `check`只读检查`package/`。BOAI侧也可执行`node scripts/runtime-plugin-devkit.mjs check /绝对路径/boai-text-inspector/package`。
- 在BOAI现有设置中安装`package/`目录，再在原本机运行时连接入口选择Text Inspector并测试连接、保存及绑定员工。示例使用本机`node`作为发现入口，不启动新的模型服务。

### 3.3 改造成实际适配器

- 保持`createRuntime`边界。只声明真正支持的capabilities，`unsupported`能力不要靠返回虚假成功代替实现。
- 会话初始化、输入接收、文本事件、终态、interrupt和closeSession必须对应实际Provider状态；不伪造resumeRef。
- 支持模型网关时沿SDK的私有`modelSource`输入及已有manifest握手规则，不把apiKey放进config、事件、日志或回执。
- 如需参考真实协议适配，阅读`packages/runtime-plugins/src/pi.ts`、`opencode.ts`和`acp.ts`。它们仍是工作区内部实现，不能在外部项目中反向导入宿主私有runner/wire。

## 4. 验收

由协调者统一安排执行；本合同和代码写入不等于以下结果已通过。

独立分发验证命令为`node scripts/check-runtime-plugin-distribution.mjs`；已有完整依赖缓存时可追加`--offline`。脚本仅在系统临时目录导出SDK、创建外部项目、安装开发依赖、编译并检查，再用当前源码编译的原安装器/runner验证。它不写应用dist、不启动桌面、不访问个人profile、不调用模型；结束后清理该临时目录。定向回归入口为`pnpm exec vitest run tests/runtime-plugin-devkit.test.ts`。

- SDK真实tarball在仓库外新目录安装，类型只解析声明文件；tarball无workspace依赖或仓库绝对路径。
- 独立项目完成typecheck/build/check；将原BOAI源码路径移出解析条件后仍能消费SDK。
- 已存在目标目录拒绝生成，原文件不变。错误manifest、缺入口/许可、符号链接、包外依赖、裸第三方依赖及缺必要导出被预检拒绝。
- 静态预检遇到含顶层副作用的模块不会执行副作用。
- 在临时registry/空bundled目录用原`RuntimePlugins.install`安装生成包，重开后hash保持；过期revision/篡改仍拒绝，卸载不改其他数据。
- 在隔离profile或临时runner进程执行probe/openSession/submit/closeSession；结果统计与事件一致，API不匹配明确失败。该结果不代替真实模型、Electron UI或长时验证。
