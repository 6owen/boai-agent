# 模块所有权与依赖清单

## 查询实际依赖

在仓库根目录运行下列命令。检查失败时命令以非零状态退出，错误写到 stderr。成功时 stdout 只含 JSON，可用于查调用方、审阅跨层变更或比较两次提交。

```sh
node scripts/check-workspace-boundaries.mjs --graph > /tmp/boai-workspace-graph.json
jq '.runtimeModules' /tmp/boai-workspace-graph.json
jq '.packages[] | select(.name == "@boai/runtime")' /tmp/boai-workspace-graph.json
jq --arg dest 'packages/runtime/src/modules/browser/commands.ts' \
  '.files[] | .path as $caller | .imports[] | select(.target == $dest) | [$caller, .line, .kind, .specifier]' \
  /tmp/boai-workspace-graph.json
```

基于浏览器迁移提交 `144ef0c9` 的产品源码，扫描 16 个 workspace、1,138 个源文件、30 条直接声明的包依赖和 261 个显式公开入口。7,212 处引入中，5,121 处为静态值导入、140 处为值重导出、1,870 处为纯类型、74 处为动态导入、7 处为 CommonJS require。5,544 处解析到仓库文件。一个文件对同一目标可有多条引用。specifier 保留原写法，target 为实际解析到的仓库相对路径。跨包的运行协议、数据库引用、Vite glob 和计算得到的模块名需要通过各自注册表、事件或实际调用另查。

工作区之外另有 tests、scripts、resources、.github、examples、transitions 和项目文档。该提交 Git 跟踪了 tests 下 897 项、scripts 下 120 项、resources 下 200 项和 .github 下 17 项，包含辅助输入及说明文件。设计分发由 scripts/build-design.mjs 及 check-design-distribution.mjs 取证；应用/发布由 scripts/build.mjs、release-* 及 workflow 取证；行为测试按 tests、tests/e2e、tests/evaluation 的实际入口分层。avatar-motion 的发布源来自 .gitmodules 固定的子模块。

## 业务模块之间的环

`runtimeModules.dependencies` 列出每个目录跨到其他目录的直接方向，`cycleGroups` 列出可以相互到达的模块。同目录、仅类型、异步导入及资源文本不计；直接值导入、重导出和字面量 require 均计。用上方逐文件查询可定位实际导入行。普通包及源码初始化方向仍独立检查。

清理协调器迁入 cleanup 后，26 个目录中 12 个仍同属一个强连通组。35 个在环内的直接方向逐项登记在 `scripts/runtime-module-cycle-debt.json`。CI 遇到新的环内方向会列出来源、行号、双方和所属组；迁出后继续保留旧登记也会失败。该文件用于追踪既有耦合。资源包、员工资料与工作区等有明确所有者的反向依赖优先迁移；涉及同一事务的清理、任务交付、群协作调度需先验证真实生命期和故障恢复。

## 治理顺序与状态

1. 已迁移画板 schema 转发和网关目录缓存。工具参数复用插件的原对象；连接退役后会释放刷新状态。
2. 已迁移获准消息原文、轮次与来源记录。跨后端调用直接依赖 conversations，模型消息装配归 Mastra，原生 SQLite 来源摘要与迁移前一致。
3. 已迁移两个 Mastra 导出器及宿主执行事件的持久观测。两个受控 SDK 请求及宿主 SQLite 写入核验了正文遮蔽、布尔值及业务完成。原生互动请求与回执已迁移到相同的结构化文字遮蔽，保留原生字段。
4. 已从 AppService 迁出会话快照投影，消息、运行与轮次各单次扫描；列表偏好仅重排时读取消息时间。继续依业务写入和生命周期逐步切分。工作、原件、来源、预算一起提交的路径须保留原事务。全库 0 个静态初始化环不代表按业务目录聚合后没有双向使用。
5. 业务目录聚合初查为 25 个目录、71 个直接方向，10 对直接双向，15 个目录处于同一强连通分量。应用操作迁移后为 65 个方向、9 对直接双向，memory 离开分量。模型绑定迁移又移除 backends 对团队仓库的依赖，teams 与 backends 两者退出分量。工作区与任务控件共用在途状态后，当时为 63 个方向、7 对直接双向。两个清理协调器及其共享路径核验独立后，26 个目录显式记录 64 个方向，6 对直接双向。会话队列和调度准入改用持久执行顺序后为 63 个方向、5 对直接双向。任务查询迁移后 application 退出强连通分量，当前 27 个目录、64 个方向、3 对直接双向。桌面指南改为按启用状态取实际原件后，desktop-plugin 退出强连通分量，剩 63 个方向、2 对直接双向。员工上下文和动态表达一起归 contexts 后，工作区及 agent-state 退出分量，剩 62 个方向、1 对直接双向。工作规则与预算类型合一后，目录间 61 个方向、0 对直接双向；仍有多目录环。
6. 需要产品决定的范围包括是否退役承诺过的组件旧路径与外部用户可能依赖的包导出。独立的内部所有权迁移可以继续。
