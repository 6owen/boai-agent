# 应用独立开发与构建

## 1. 当前事实与目标

- 现有 Electron、CLI 的应用级 `build` 都委托根全量构建；CLI 修改也会触发设计包、桌面 Swift 与 Renderer。
- 设计站已有独立 `dev/build`，输出 `apps/design-docs/dist`；本轮保留其技术栈与公开内容白名单。
- CLI 客户端只依赖 shared/transport；`serve`、自动启动服务及相关校验通过相邻 `dist/runtime/serve.mjs` 启动共享 runtime。源码边界已经存在，本轮据此拆构建。
- 本轮目标是每个现有应用拥有可执行且闭包完整的开发/构建命令。保持现有 `dist` 布局、业务参数和根全量构建语义，不新增应用或框架。

## 2. 命令合同

- Electron：`pnpm --filter @boai/electron dev`、`build`、`start`；根快捷命令 `pnpm dev:electron`、`build:electron`。`pnpm dev`、`pnpm build` 保持等价兼容。
- 完整 CLI：`pnpm --filter @boai/cli build`；根 `pnpm build:cli`。包含客户端和独立服务所需产物。
- 轻客户端：`pnpm --filter @boai/cli build:client`；根 `pnpm build:cli:client`。仅生成 CLI 客户端、员工工具客户端及来源许可，不编译 runtime、Electron 或设计包。
- CLI 开发：`pnpm --filter @boai/cli dev -- <原CLI参数>` 或 `pnpm dev:cli -- <原CLI参数>`，先构建完整 CLI 再执行命令；无参数显示帮助。执行 `serve` 仍需原命令要求的参数，开发脚本不新增隐式服务或资料目录。
- 轻客户端开发：`pnpm --filter @boai/cli dev:client -- <原CLI参数>` 或 `pnpm dev:cli:client -- <原CLI参数>`，仅构建客户端后执行。需要附着已有宿主时沿用原 CLI 连接参数；需要独立 `serve` 或自动启动服务时使用完整 CLI 命令。
- CLI `start` 保持只运行已构建客户端。开发命令每次先构建再执行；本轮不引入后台 watcher，也不自动重启正在执行任务的服务。
- 设计站：`pnpm --filter @boai/design-docs dev/build` 与根 `pnpm dev:design/build:design` 保持；默认端口5190。
- 所有应用脚本根据脚本自身路径定位当前 worktree 根，根目录、应用目录和 `pnpm --filter` 调用使用同一源码与输出。CLI 开发进程的默认工作目录为当前 worktree 根；具体任务目录仍可用原 CLI 参数显式指定。

## 3. 构建产物闭包

- 轻客户端：`dist/cli/index.mjs`、`employee-tools.mjs`、sourcemap 及 Craft CLI `LICENSE.txt`、`NOTICE.txt`、`source-manifest.json`。客户端不内联服务实现，也不依赖 Electron 才能运行普通命令。
- 完整 CLI：轻客户端全部产物，加 `dist/runtime/serve.mjs`、当前平台的 `dist/native/boai-process-guard` 及许可/来源戳、运行时插件/SDK/插件包、PPT `dist/runtime/alma`、默认技能 `dist/agent-skills`、语音安装器 `dist/capabilities/voice`，以及 Rovai/Hermes 来源许可。
- Electron：完整 CLI 闭包，加 main/preload/browser-toolbar preload、utility worker、当前平台桌面活动及图标辅助程序、应用/托盘图标、Renderer 三个 HTML 入口和原字体/图标/浏览器/配置扫描器许可。开发入口只构建 host，Renderer 由 Vite 提供。
- 本地语音进程闭包为 `dist/voice-input/local-helper.cjs`、`local-recognizers.cjs`、`local-audio.cjs`；随 Electron host 一起构建，模型权重和模型许可继续由显式下载按固定清单安装。多模型实际验证归[第19组12第7节](../19.应用插件架构/12-语音输入插件实施与验收.md#7-唯一实际进度)。
- 设计站：共享 tokens/UI 编译与声明、静态站 `apps/design-docs/dist`，保留白名单文档、Token 下载与预览路由，不生成 Electron/CLI/runtime 产物。
- runtime 继续外置第三方 Node 依赖，从本工作区已安装依赖解析。本轮不承诺将 CLI 目录单独复制到无依赖机器即可运行，也不新增 npm 包发布/独立安装包。

## 4. 源码与身份约束

- 构建继续用 `workspace-packages.mjs` 读取当前 worktree 的公开 exports，将 workspace 源码内联；不从其他 worktree 的链接读取应用源码。
- 编排模块保持导入无构建副作用，CLI 参数在执行前校验；无效目标必须在写产物前失败。
- 每次修改 `dist` 的 host/CLI/全量构建先移除旧 `dist/build-identity.json`。失败也不能留下旧全量通过身份。
- 只有完整 Electron 构建在全部 host、Renderer 和来源许可完成且输入未变化后，登记原全量身份。部分 CLI/host 构建不登记全量身份；设计站独立输出不触碰桌面身份。
- 构建前后继续检查源码指纹；新增编排脚本纳入构建输入。编译期应用版本及输入hash沿用原协议，不改变运行时身份字段。
- Electron 与 CLI 仍共用根 `dist`，不能并发运行会写该目录的构建。独立命令表示可以只构建所选应用，不表示产物目录物理隔离；已有开发进程需在明确验证安排后重建。

## 5. 实施顺序

1. 本文先固定边界和命令；根接入快捷脚本，各应用声明直接指向本 worktree 的编排。
2. 将原全量 `buildHost` 分成 client、runtime、Electron host 三段，保留同名兼容导出；全量默认构建继续登记完整身份。
3. 新增 CLI 开发入口，透传原 CLI 参数和退出状态；Electron/设计站入口统一根目录定位。
4. 补编排回归源码：轻客户端不调用服务/桌面阶段，完整 CLI 资源闭包，Electron 原全量输出，错误目标与构建失败不保留旧身份，应用目录启动参数传递。
5. 先做源码与轻量静态核查；隔离构建、实际 CLI/设计站/Electron验收由本轮协调者在明确授权范围统一执行。

## 6. 验收清单

- 从根和应用目录调用目标一致；未知构建参数不会静默回退为全量构建。
- 干净产物目录执行 CLI 构建不调用 Vite Renderer、UI 声明生成、Electron Swift；完整 CLI 能找到独立服务、插件、技能、PPT、语音和 native guard。
- 轻客户端能够显示帮助并沿原连接协议访问已有宿主；不把未构建独立服务的失败掩盖成完整 CLI 可用。
- 设计站可单独启动/构建，原白名单文档和预览保留。
- Electron `dev/build` 与根原入口一致，旧发布/UI检查仍只接受原全量身份。
- 不修改业务 API、数据库、权限、服务生命周期、默认个人数据或现有运行进程。
