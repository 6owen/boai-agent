## 3. 首批目录归属

- `apps/electron/src/main`：窗口、系统能力与 Electron 宿主适配。
- `apps/electron/src/preload`：主 preload 与浏览器 toolbar preload。
- `apps/electron/src/renderer`：现有桌面页面、路由、状态和静态前端资源。
- `apps/electron/src/worker`：Electron utilityProcess 启动入口及父进程端口装配。
- `apps/cli/src`：命令行解析、输出、附件提交与服务启动命令。
- `apps/design-docs`：现有设计站。
- `packages/shared/src`：领域类型、schema、公开协议；Node辅助只经明确 `node/*` 子入口；不依赖 runtime 或 apps。默认入口为domain/index。
- `packages/transport/src`：现有 RPC client/server、channels、events、discovery、history，通过现有 CliServicePort 接业务，禁止导入 AppService 实现。
- `packages/runtime/src`：AppService、ProductStore、引擎、业务模块、独立服务装配；业务模块不新增 WebSocket 依赖。
- `packages/ui`、`packages/tokens`：沿现有包与公开导出。
- `resources`、`tests`、`scripts`：保留根目录，以清晰的包入口或显式测试源码位置更新引用。

## 4. 依赖合同

- Electron 可使用 runtime、transport、shared、ui、tokens。
- CLI 客户端使用 transport/shared；独立 serve 通过原进程分发启动 runtime，不把 Mastra 内联进轻量 CLI。
- runtime 装配层使用 transport/shared；transport 只使用 shared；shared 不反向导入 runtime 或应用。
- ui 只使用 tokens 与第三方 UI 依赖，不导入宿主、存储或业务 services。
- 包之间使用 `@boai/*` 的公开子入口，不通过相对路径穿越包。测试可直接测试内部实现，仍保留原覆盖范围。
- 公共包的默认导出不混入 Node/Electron 实现。桌面公开方法准入表保持桌面语义，不能视为未来远程授权清单。
- 以轻量静态检查约束相对路径穿包、非法依赖方向、不可解析本地导入和未声明包入口；检查与原类型/UI门禁互补。

## 5. 先解除的依赖

- `runtime/dispatch → main/public-methods`：桌面公开方法策略下移 shared。
- `runtime/material-upload → main/material-sources`：纯 Node 材料来源管理下移 shared/node。
- `shared/ipc/browser → runtime BrowserCommandResult`：结果 DTO 下移 shared，运行实现使用同一定义。
- CLI 与 runtime 共用材料文件读取辅助下移 shared/node，保留原路径校验、限额与文件身份核验。
- `runtime → cli server/events`：抽 transport；客户端命令不再被 runtime 引用。
- Electron parentPort worker 归应用，核心构造与生命周期仍在 runtime。

## 6. 第二批插件整理

- 只提取现有 Runtime API 与 manifest schema 为私有 `runtime-plugin-sdk` 包；不扩大现有 API 承诺。
- Pi/OpenCode/ACP 的独立实现可以收至 `runtime-plugins`；宿主、安装事务、权限、lease与业务回调留 runtime。
- 私有 JSONL wire 校验不自动升级为公共 SDK；预览/主题等内置注册不强行统一为运行时插件。
- 第二批代码已随本轮迁移接线，实际检查与未验范围仍归02；无独立 GitHub 仓库、submodule、npm 发布或协议替换。
