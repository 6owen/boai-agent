## 状态所有权与技术选择

| 状态或契约 | 权威写入者与调用方向 | 派生视图或约束 |
| --- | --- | --- |
| 员工身份、会话、消息与运行 | runtime/service 与 modules/employees、conversations 组织业务操作，经 adapters/storage/product-store 提交 libSQL 事务 | Electron renderer 展示快照和按事件刷新的分页，CLI 经 transport 访问同一宿主 |
| 员工任务、定时执行与交接 | modules/automations、collaboration、contexts 拥有各自业务生命周期 | 手动与定时话题有独立身份及去重合同，不能凭状态名合并 |
| 产品数据与读索引 | ProductStore 持有数据库连接、事务和原始记录，raw-history-index 等维护按来源重建的索引 | 只读取证与运行服务写入模式分离 |
| API 员工与本机运行 | adapters/mastra 使用官方 Controller/Session/Memory，Claude/Codex/插件适配器持有原生会话标识 | 宿主拥有业务授权和账本。原生上下文不迁入 API Memory |
| 系统设置与密钥 | runtime 依赖 contracts.SecretStore；Electron main/vault 与 headless 宿主提供具体实现 | renderer 使用快照和 IPC，来源与员工权限由宿主调用时核对 |
| 指标与诊断 | Mastra metrics 经 DuckDB 投影，运行和会话业务记录仍由 runtime 维护 | 诊断或费用查询不回写业务状态 |
| IPC、远端 RPC 和工具参数 | shared/domain、shared/ipc 与 shared/cli 描述产品协议，runtime/dispatch 分发；transport 承担远端通信 | 主进程另有文件打开、通知、窗口等平台能力 |
| 设计变量与组件 | tokens → ui → Electron renderer / design-docs | 文档预览、源码和分发包需消费真实组件；宿主交互留在应用 |
| 构建与测试 | package.json 命令 → scripts；Vite、esbuild、Vitest 按 workspace 公开入口解析 | PR 的 typecheck 包含 workspace 检查；设计分发和真实桌面走独立验收 |

- 搜索会话工厂、两种 API 提供方、来源服务和测试都直接使用 source-session。该内部模块拥有脱敏顺序、截断上限、会话类型和默认超时。改用依赖注入会把同一策略逐次传入两种适配器；延迟导入仅推迟工厂加载。两种方案都增加调用约定。原工厂没有通过包 exports 发布这三个内部符号。
- 设计页直接根据 hasExample 渲染已有 Preview，删除仅一处调用的 ComponentExample。目录仅负责示例与原文加载，不再依赖页面组件。
- 在改源码前运行新的 CI 检查，真实旧图报告 3 条闭环路径；迁移后在 1,135 个文件上通过。包括边界检查的 typecheck 和两个改动页面文件的 ESLint 均通过。来源、Jina、DeepSeek 共 58 个用例在基线与迁移后分别通过。设计站构建和 12 项 headless 浏览器检查前后通过，基线另验证了仓库外 tarball 消费。
- 扩展 Git 关联测试发现其他失败，已在原提交独立复现 CLI 主聊标题、两项核心改名、两项网关替换断言；其余关联测试的归因仍在核对。构建在基线与迁移后均报告 DESIGN.md 与 design.md 输出大小写冲突，列入设计分发任务。

### 会话阅读、搜索与锚点输入

### CLI 本地观察的中断与超时

- `executeMessage` 和 `executeRunCancellation` 原先分别持有相同的组合信号、计时器、RPC 竞速和监听清理。现在该生命周期归 CLI 的 `observeRpc`。两条命令分别决定超时文案、退出码、原回执查询和是否提交停止。把这一能力放进传输客户端会改变所有普通 RPC 使用者的接口，也会混淆发送与本地停止观察的责任。
- 从真实 owner RPC 选取超时、SIGINT、丢失停止回执、部分取消及原执行退出等 10 项，迁移前后均通过。14 项传输测试通过，其中新增场景直接观察待决调用的监听释放、预先取消时不再发送、宿主只办理一次以及原连接仍可查询。CLI 构建及类型检查通过。

### 会话文件在 SQLite 内选取

- 原资料/成果列表、宿主监控来源、文件失效清理和恢复失败处理会先将整类记录的 JSON 送入 JS 才按会话筛选。ProductStore 的普通读取与原事务内的 list 现在使用同一查询，沿 rowid 保留插入顺序。资料、成果使用现有 conversation_file_scope 部分索引的原谓词，无数据库迁移。回滚、未提交写入、旧缺会话字段的记录、原文件内容和授权检查分别保留。
- 比较过按会话维护内存缓存、新建索引、仅给 load 传入会话条件。前两种增加失效或写入成本；最后一种在 SQLite 上仍按集合扫描，因为参数化集合相等条件无法证明部分索引的谓词。本次复用真实索引，更新完整的产品资料/成果行读取路径。跨会话版本族、全局备份/启动发现和带独立标识校验的清理意图各有语义。
- 使用相同驱动、8,192 条合成成果、512 个会话、7 次热读中位数，原查询传入 12,948,685 字节，结果 16 条，25.11 ms。单加会话条件为 6.47 ms。复用索引后传入 25,277 字节，0.06 ms。这是隔离查询耗时；界面启动、文件系统来源复核和个人数据未测。
- 产品路径两组迁移前共 131 项通过。迁移后扩展组选入监控取消用例，137 项通过，一项在原提交和候选上均返回 queued，而旧断言期待 skipped。单列为队列契约复核。存储定向 5 项及类型检查通过；新增检查在实际驱动执行的 SQL 上用 EXPLAIN QUERY PLAN 核验索引，覆盖两个集合的插入顺序、旧记录隔离、事务内写后读和回滚。

### 会话清理日志的有界恢复

- 原恢复启动时读取全部会话，逐份日志为查子讨论与浏览器屏障重复展开整表。现在先按日志取目标，讨论优先、同组保持写入次序；每个目标从 SQLite 实时读取讨论与浏览器屏障，获准后才按主键取会话。来源清理冲突也只查当前会话。原成功、失败和待恢复回执保持。
- 1,200 个会话、32 份被浏览器阻挡的合成日志，独立原提交的恢复实现与迁移前相同。各跑四遍，空日志原每遍解析 1,200 行标记数据（2,787,690 字节），6.95–9.23 ms；现在为 0 行、0.04–0.23 ms。被阻挡时原每遍解析 2,224 行标记数据（2,860,778 字节），16.08–25.16 ms；现在为 0 行、2.75–3.44 ms。每遍冲突内容与顺序完全相同。这里计量的是恢复阶段，不代表整个应用启动时间。
- 首个普通 JOIN 候选虽减少反序列化，查询计划却扫描全部会话，32 项场景实测 66.99 ms。采用 SQLite 的 CROSS JOIN 从小日志驱动，按 collection + id 主键定位会话；专项断言实际执行计划与子讨论/浏览器屏障优先顺序。原件保留于隔离工作区。PR #246 已合入 main，合并点 8503cf2a。
