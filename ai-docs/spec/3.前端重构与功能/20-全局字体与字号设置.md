# 全局字体与字号设置

日期：2026-10-20

状态：**已实施，持续验收。** 源码接入三组字体与字号、共享角色解析、即时预览、配置迁移、终端及代码预览；仍按本节真实验证范围判断完成度。

## 1. 用户要求与强制原则

用户要求六项设置：**界面字号、内容字号、代码字号，以及界面字体、内容字体、代码字体**。

用户随后明确：

> 不要固定值的字号设置，都统一管理起来

据此，实施必须建立全局统一的排版体系，而不只是增加六个设置控件：

1. **所有 BOAI 自有界面的字号都由统一排版配置管理。** 页面、组件、局部 CSS 和第三方组件初始化不能各自写固定字号。
2. 界面、内容、代码各有独立可调基准。标题、正文、辅助文字、标签、紧凑代码等层级通过统一规则派生，不能留下不随设置变化的例外。
3. 默认值、合法范围、步进、各层级比例、行高及字体回退都集中登记。组件只能引用语义名称，不复制数值、比例或独立默认值。
4. 字号控件支持数值输入及步进调节；不在页面各列一组固定字号档位。控件约束直接来自共享定义。
5. 统一管理保留排版层次，不把全系统所有文字强行改成同一个大小。
6. 不以“特殊组件”“紧凑模式”“第三方默认”作为保留固定字号的理由；代码、diff、终端和弹层同样接入。

建议设置入口为「设置 → 外观 → 字体」。配置作用于当前应用数据配置的全部会话和员工，不按模型或员工复制一套。字体样式按字体家族理解；独立字重/斜体/行距控件未列入本次需求。

## 3. 统一排版体系

### 3.1 单一来源与消费层

建议在 `src/shared/appearance/` 内集中建立排版定义，负责：

| 层 | 统一管理的内容 | 使用方 |
| --- | --- | --- |
| 定义 | 字体ID/字体栈、三类默认基准、范围/步进、字号层级比例、行高和字重语义 | UI、宿主校验及纯解析函数 |
| 用户偏好 | 三类字体ID和基准字号 | 原 AppearanceStore |
| 解析结果 | 每个语义角色的字体、实际字号、行高 | CSS变量、查看器和终端适配器 |
| 展示 | 消费语义变量或解析结果 | 页面、控件、Portal、预览 |

默认数值只在统一定义处存在。CSS、React 和终端不得分别维护默认值；启动首帧与异常回退也使用同一来源。共享定义不依赖 DOM、Electron 或 Renderer。

建议语义角色包括：

- 界面：正文、辅助文字、标签、列表标题、分区标题、页面标题。
- 内容：正文、标题一至六级、表格、引用、说明。
- 代码：正文、行内代码、紧凑代码、行号、终端。

角色名称和最终比例在实施时集中确定。每个角色明确所属基准与派生规则；存在相同样式时复用角色，避免“一组件一token”重新形成散落配置。

### 3.2 字号派生

基本关系为：`角色字号 = 所属分类的用户基准字号 × 统一层级比例`。必要的上下限或特殊相对规则也由统一定义提供，不能散落在调用处。

CSS建议暴露三类字体/字号基准及已解析的语义角色变量，例如：

```css
/* 名称示意；实际值由统一排版解析器生成 */
--font-ui-family;
--font-content-family;
--font-code-family;
--font-ui-size;
--font-content-size;
--font-code-size;
--text-ui-caption;
--text-ui-heading;
--text-content-heading-1;
--text-code-compact;
```

现有 Tailwind `text-*`、`font-sans/mono` 和排版组件映射到这套定义。页面只选用角色，不出现 `font-size: 13px`、`text-[13px]`、`fontSize: 12`、本地字号比例或独立兜底数值。

允许终端等 API 最终接收数值，但该数值必须由共享解析器提供；“API要求number”不等于允许调用点硬编码。

### 3.3 与整体缩放的关系

字号设置调整对应分类文字；现有「界面缩放」继续整体缩放文字、图标和布局。两者独立保存。

显示尺度由语义字号和现有窗口缩放共同决定，不把缩放后的值写回用户字号。界面字号变化不能通过修改根字号意外带动所有 `rem` 图标和间距；布局基准与排版基准分开管理。控件高度可随文字行高适应，避免裁切。

## 4. 设置交互与作用范围

三组设置各包含字体选择、基准字号输入/步进及实际预览，使用现有共享组件：

| 分组 | 建议字体候选 | 预览 |
| --- | --- | --- |
| 界面 | Geist、系统默认 | 会话名称、按钮、辅助文字 |
| 内容 | 跟随界面、Geist、系统默认、系统衬线 | 中英文正文、标题、表格、链接 |
| 代码 | 系统等宽；macOS可加入已确认可用的等宽字体预设 | 缩进、数字、中文注释 |

候选是设计建议；具体默认字号不在各页面另行指定，统一定义需以现有真实画面对照确定。“内容跟随界面”仅跟随字体家族，内容基准字号仍独立。首版使用离线字体和系统回退，完整字体扫描/导入可另行扩展。

交互要求：

1. 调整即时预览，沿现有外观队列合并保存；输入中的暂时空值不立即覆盖已保存值。
2. 每组恢复默认从共享定义读取；「重置字体」只恢复六项，不改变背景、主题、缩放和应用图标。
3. 全部外观重置若包括字体/图标，应在原操作说明中明确范围。
4. 窄窗口允许控件换行，键盘操作与焦点完整；预览使用真实组件与真实语义角色。
5. 错误使用 shadcn Sonner，保留原位置重试与未保存状态；不新增错误Banner。

| 区域 | 归属 |
| --- | --- |
| 导航、会话/员工列表、设置、按钮、菜单、Dialog、Popover、Tooltip、Sonner | 界面体系 |
| 作者、时间、状态、文件路径标签、工具栏、列表摘要 | 界面体系；等宽路径也有统一语义角色 |
| 本人/员工/渠道消息正文、公开思考说明、通知正文 | 内容体系 |
| 聊天输入正文、长文编辑、Markdown/纯文本阅读、笔记/日记、技能说明 | 内容体系；周边控件仍用界面体系 |
| 正文标题、表格、引用、列表 | 内容体系对应层级 |
| 代码块、行内代码、源码预览、diff、结构化JSON/命令输出、终端 | 代码体系对应层级 |
| 图标、头像、图片 | 独立布局尺寸，不随单独字号整体缩放 |
| 外部网页、项目HTML预览、PDF原页、Office原文档 | 保留来源自身排版；BOAI外壳仍受统一设置控制 |
| 导出文件、外部渠道原消息和模型输入 | 不因显示偏好改写内容 |

“统一管理”覆盖 BOAI 自己绘制的文字；系统原生菜单/文件选择器遵循操作系统排版，不能宣称通过 Renderer 字体覆盖。

## 5. 配置与迁移

建议外观 schema 升至2，与 [21 应用图标](./21-macOS应用与Dock图标切换.md) 协调同一升级。仍由主进程配置持久化，Renderer仅镜像和预览。

```ts
// 类型名为设计示意；字体ID、默认值和数值约束来自统一定义
type TypographyPreferences = {
  ui: { family: InterfaceFontId; sizePx: number }
  content: { family: ContentFontId; sizePx: number }
  code: { family: CodeFontId; sizePx: number }
}
```

- v1 `fontFamily`迁至`typography.ui.family`；内容默认跟随界面。新增字号从共享默认定义补齐，原主题/背景/颜色/缩放保持。
- 新版以`typography`为真源。若旧业务协议保留`fontFamily`，仅作界面字体兼容别名；与新版同字段提交矛盾值时拒绝，不维持两份可分歧配置。
- patch按`ui/content/code`逐层合并；改一个字号不得清空字体或其他组。
- UI与主进程用同一数值约束和字体ID登记；不允许任意CSS字符串。内容跟随关系禁止形成循环。
- 已知schema的无效新字段独立回退；未知更高版本保留原文件并沿只读策略处理。
- 字体缺失用集中定义的中文/emoji/系统回退，不改写原选择；新增内置字体须离线分发并保留许可。
- 原revision、事件sequence、启动快照、关闭保护及备份恢复统一扩展。不得新增localStorage权威副本。
- 新字段同步进入shared校验、宿主白名单及现有应用业务协议，不能出现UI可保存而其他入口丢字段。

## 6. 全量接线要求

实施先盘点全部固定字号和局部比例，建立“位置→语义角色→迁移状态”的清单；完成时所有 BOAI 自有排版均有归属。

1. 清理CSS中的固定字号、`font`简写、Tailwind任意字号、内联样式和组件默认字号，统一根变量、全局样式与`text-*`映射。
2. Markdown旧/新排版、Shiki、预览、员工资料、配置表单和门户弹层均覆盖，不能只改设置预览和主聊天。
3. diff通过查看器支持的配置或Shadow DOM样式获取共享解析结果，不假定外层CSS自然生效。
4. xterm更新现有实例的字体、字号和行高，再fit并沿原`terminal.resize`同步PTY尺寸；不因字体切换重建会话、丢失输出或结束shell。
5. 字体变化/加载后重新测量虚拟列表和终端，以消息锚点保留阅读位置；草稿、选区、输入焦点和流式内容连续保留。
6. 第三方库API按仓库锁定版本核对；适配器只做格式转换，不再定义另一套字号体系。
7. 增加静态检查，阻止产品源码新增绕过统一定义的固定字号。检查涵盖CSS/TSX及第三方配置；允许清单仅限统一定义本身和明确不属于BOAI排版的原文档/外部内容，不能按整个业务目录豁免。
