# 前端目录架构与迁移计划

日期：2026-09-27  
状态：**F1 已完成首批目录迁移；未安装新依赖，F2/F3 待实施**。[实现与验证](../2.已实现功能与代码现状/15-B1-B2-S1-F1首批重构实现.md)。

当前代码基线为 [v0.2.2](../2.已实现功能与代码现状/14-v0.2.2历史群聊与本轮边界.md)。本目录以 [F1–F3 开工顺序](./README.md) 组织执行；它们分别对应本文原 A、B、C+D 阶段，不改变既定方案。

目标是在保留 Electron / Mastra 分层和现有桌面交互的前提下，参考 `landing-page/apps/web/src` 的职责划分建立可扩展的前端结构。外观设置的产品与数据合同见 [14 外观设置与主题系统](./14-外观设置与主题系统.md)。

## 2. 参考项目的对应关系

下列路径以 `landing-page/apps/web/src/` 为根，均为本次只读调研依据。

| 参考位置 | 可借鉴点 | 在 boai-agent 的适配 |
| --- | --- | --- |
| `pages/`、`pages/**/-components/` | 页面入口和页面私有组件 | 设置、会话、资料库、定时任务与帮助分开 |
| `components/`、`components/ui/` | 共享组件与 shadcn 基础组件分层 | Shell、详情容器、公共状态组件放共享层 |
| `composables/` | 共享 React hooks | 外观订阅、布局能力等可复用 hooks |
| `setups/theme.ts` | 模式解析、DOM 应用、启动处理 | 建立外观启动入口，接 Electron 快照 |
| `stores/use-theme-store.ts` | Zustand 状态与偏好边界 | 扩展为外观 store，持久化由 Main 负责 |
| `services/api/`、`services/request/` | 类型化服务与传输分离 | 改为现有 preload/IPC 适配，不引入 HTTP 服务 |
| `styles/global.css` | 唯一全局聚合入口 | 从 `main.tsx` 只导入这一个全局入口 |
| `styles/tailwind.css`、`colors.css` | 语义变量与基础色分层 | 增加 Base46 适配，补齐所有浅深表面 token |
| `styles/typeset.css`、`scrollbar.css` | 排版与滚动条集中管理 | 桌面文本、Markdown、代码和滚动条 |
| `config/`、`lib/`、`typings/`、`routers/` | 常量、纯函数、环境声明、导航机制各自独立 | 根据实际职责建立，跨进程类型仍放 `src/shared/` |

不搬入参考项目的 TanStack Start 服务端路由、`src/api/-internal`、Cloudflare、鉴权、SSR hydration 或 Query 客户端架构。boai-agent 是 Electron 中的 Vite SPA，现有 preload 通信已承担本地数据边界。

参考项目的 `data-theme` 表示浅深模式，具体色板另用 `data-theme-id`。参考项目有些 Shell 颜色只有 `:root` 浅色值，没有完整深色覆盖；迁移时必须重新校验，不能因参考项目能切 `.dark` 就认定全部组件支持换肤。

目录逐步建立，有实际职责再拆文件；`App.tsx` 不继续积累全部设置表单，但也不为每个单行组件建立多层目录。

## 4. 依赖方向与状态所有权

```text
pages → components / composables / stores / services / lib
services/api → services/request → preload → Main 或现有 Runtime
stores → shared 合同 / 纯工具；异步保存由统一服务编排
setups → services / stores / lib/theme
styles → CSS 变量合同
shared → 纯类型、校验与常量，不依赖 Renderer、Node 或 Electron
```

- `components/ui` 只提供原语，不读业务快照、外观 store 或 Electron 接口；通过 CSS 变量自然换肤。
- `-components` 仅给所在页面使用；被多个页面引用的员工/资源详情提升到共享目录。
- 组件不可直接导入 `electron`、`node:fs`、Runtime 或 Mastra；需要系统能力时通过 `services`。
- 一个配置字段只能有一个持久化所有者。业务数据库继续拥有员工、消息、运行；Main 拥有外观配置；Zustand 负责界面内存镜像。
- 外观 store 用细粒度 selector，BackgroundLayer 订阅图片与不透明度；拖动滑块不让消息列表、员工表单和全局业务快照跟着重渲染。
- 聊天草稿、表单脏状态、流式消息、导航历史、分栏偏好分别建模。引入 Zustand 不等于立刻把所有业务状态放进一个大 store。
- 退出保护按来源汇总表单脏状态与外观待保存状态，页面卸载只能移除自身登记，不能清空其他来源。
- 沿用现有页面导航策略即可。若以后采用路由库，必须支持打包后的本地文件路径；本轮不要求新增 TanStack Router。

现有布局偏好已用 `boai.*` localStorage 键保存。以后迁入 layout store 时兼容读取旧键，成功迁移后只保留一处写入；不借外观开发重置用户布局或将 UI 数据混进员工配置。

## 5. 样式与 shadcn 接入规则

`main.tsx` 最终只导入 `styles/global.css`。聚合顺序固定为 Tailwind/基础变量 → 排版/滚动条 → Shell/背景与组件样式；`legacy.css` 仅迁移期保留。

Tailwind Preflight 只加载一次。当前 `tailwind.css` 为保留原生表单基线含有 `revert` 规则，当前 `styles.css` 还有未分层的全局按钮/表单样式；引入 shadcn 前必须收窄到旧组件作用域，逐步放进合适的 CSS layer。否则未分层选择器会压过工具类，导致新组件尺寸或颜色失效。

shadcn 配置建议：

- `rsc: false`，TypeScript 组件，`cssVariables: true`。
- `components.json` 的 `tailwind.css` 指向 `src/renderer/styles/tailwind.css`，让 CLI 的样式更新落在该层；`main.tsx` 仍只导入 `styles/global.css` 聚合入口。引入组件时审查生成改动，不再生成一套重复默认主题。
- 别名统一 `@/` → `src/renderer/`、`@shared/` → `src/shared/`；同步 Vite、TypeScript、测试配置与 `components.json` 的 ui/lib/utils/hooks 等位置。
- 保留相对路径的 `base: './'`、当前 Renderer root、构建输出与生产 CSP；不套用普通网站的部署基址。
- 首批按需要引入 Button、Label、RadioGroup、Select/Popover、Slider、Separator、Tooltip 等原语；不为了设置页添加完整 Dashboard 模板。
- 保持 Carbon / Solar 图标。参考项目 `iconLibrary: lucide` 的 CLI 元数据不构成引入另一套图标的要求。

`@config` 与图标插件只保留一条有效加载路径。迁移时核对现有 `tailwind.config.ts` 与 CSS `@plugin` 的职责，不能重复注册插件。新增背景/颜色使用变量，不在大量 `style` 对象中分散维护主题。

## 6. 从现有文件迁移

| 当前文件 | 目标 | 迁移约束 |
| --- | --- | --- |
| `App.tsx` | Shell、页面组合、routers、逐步提取的布局状态 | 保留导航守卫、请求序号、会话 ID 与迟到结果保护 |
| `settings.tsx` | `pages/settings/` 的分类及模型/数据子页 | 先保留真实连接与备份接口，再接入外观 |
| `conversations.tsx` | `pages/conversations/` | 保持草稿、滚动位置、流式输出和运行状态 |
| `activity.ts` | `pages/conversations/-lib/activity.ts` | 保留按创建时间的稳定分组/排序、当前与历史轮次隔离、旧直接会话按触发消息分组；该模块只做展示投影，不接管调度 |
| `employee.tsx`、`editors.tsx` | 共享员工详情、群页面私有组件 | 不破坏脏表单、系统文件和记忆入口 |
| `pages.tsx` | `pages/library/`、`schedules/`、`help/` 及适当共享详情 | 不改变定时任务仍未实现执行的事实 |
| `ui.tsx` | `components/common/`、详情守卫与新基础组件 | 逐个替换，不用新模板覆盖旧交互行为 |
| `icons.tsx` | `components/icons/` | 现有名称与可访问标签可通过重导出过渡 |
| `styles.css`、`tailwind.css` | `styles/` 分层 | 先 token 化，再拆布局；避免一次混改全部样式与业务 |

不要只移动文件而保留错乱依赖；也不要把一次目录迁移扩大为消息、调度、记忆和存储重写。过渡重导出必须有明确清理阶段。

2026-09-27 清理补充：上表中的旧扁平文件已删除，两个仅聚合导出的页面 index 也已删除；调用方直接引用实际模块。`main.tsx` 直接挂载 AppShell，不再添加只包一层 Shell 的 App 组件。承载页面、组件或领域类型实现的 index 继续保留。

迁移会话与活动组件时，以 v0.2.2 行为为基线：默认只展示本轮触发消息与运行，历史错误按轮次折叠；`unresolvedFailureDeliveryIds` 继续由后端权威计算；成员是否已回复以同轮 completed 的公开消息核实，后续 pass 不抹去已有回复。记忆维护失败/中断不提供普通任务重试，历史失败也不混入本轮重试入口。完整回归清单见 [本目录入口](./README.md#v022-必须保留的回归边界)。

## 7. 开发阶段与验证

| 阶段 | 产出 | 完成标准 |
| --- | --- | --- |
| A：目录与样式基线 | 路径别名、global.css、共享组件边界、设置分类骨架 | 现有界面和 IPC 可用；类型检查、构建通过；核心 Electron 导航/表单回归通过 |
| B：语义主题与模式 | Base46 注册表、完整 token、Zustand、Main 配置、启动与系统模式同步 | 至少默认浅/深及额外 Base46 色板可选；切换、重启、Portal 和失败回退通过 |
| C：背景图 | 图片选择、受管复制、受控协议、图片层、滑块 | 导入/取消/替换/移除、透明度、失效图片、快速修改与可读性通过 |
| D：数据与发行验证 | 备份快照/恢复说明、旧数据兼容、清理 legacy | 安装包中系统变色和图片可用；备份恢复及原功能回归通过 |

每阶段先迁移最小闭环；不要一边保持旧全局主题写入，一边再新增独立 shadcn ThemeProvider。首批实现外观 store，其他 UI store 按有必要的模块拆分逐步迁入。

有价值的新增测试：模式解析与主题回退、完整 token 输出、配置校验/原子写入/版本冲突、图片越界与失败保留旧图、备份引用一致性。组件行为重点验证键盘单选、滑块提交和保存失败提示；不为纯文件搬迁或 CSS 常量复制编写镜像测试。

沿用 `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:electron` 与实际打包应用验证。14 的验收表是外观功能完成标准；通过后再新增实际实现记录，不能提前改写 v0.2、v0.2.1、v0.2.2 的历史交付事实。
