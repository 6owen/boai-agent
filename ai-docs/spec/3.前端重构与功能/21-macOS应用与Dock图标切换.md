# macOS 应用、Dock 与托盘图标切换

初稿：2026-10-20；托盘联动方案更新：2026-10-22。

状态：**托盘联动实现已接线，隔离模块与桌面功能验证通过；打包运行和视觉边界分别记录于§7。**

## 1. 目标与设置交互

用户希望将系统里已有的预置头像转为可用的应用图标，并在设置中切换安装应用的 Dock 图标。

现有入口为「设置 → 外观 → 应用图标」，与 [20 字体设置](./20-全局字体与字号设置.md) 同页。复用全部21款预置头像，选择后保存，下次启动恢复。

按以下四个显示目标分别设计和验收：

| 层次 | 用户看到的效果 | 实现边界 |
| --- | --- | --- |
| 运行中的Dock | 选择后立即变化，后台运行/窗口重开仍保持 | Electron运行态Dock API |
| macOS菜单栏托盘（新增，待实施） | 同一选择保存后更新为对应单色简化图，开发版和安装版均适用 | 原Tray实例、模板图与`setImage`，详§8 |
| 安装应用 | Finder中的当前BOAI `.app`同步；退出后固定在Dock的应用仍显示所选图标 | 文件图标与系统缓存，需要原生验证 |
| 分发默认图标 | 首次安装、无个人选择时有正常默认图标 | 构建时的`.icns` |

仅完成运行态切换不能宣称安装图标完整支持。退出后的Dock刷新尚待验证，不能静默缩为临时图标功能。首轮面向macOS，Windows/Linux不展示可用的macOS切换入口。

设置区使用紧凑网格，显示实际转换后的预览、名称和选中状态，复用共享组件、主题及统一排版：

1. 点击后沿原外观队列保存，由宿主应用图标；正常成功仅更新就近状态。
2. 全部21款按头像原顺序展示，窄窗口自动减少列数，支持键盘选择。
3. 「恢复默认图标」只影响图标，并处理运行态与当前安装副本的自定义图标。
4. 保存结果和系统应用结果分开；失败使用Sonner，原位置保留「重试应用」。
5. `pnpm dev`文案明确“开发模式：仅当前进程”，不修改共享`Electron.app`或已安装BOAI。
6. 安装版同一选择覆盖运行态和当前副本；部分失败如实显示“Dock已更新，安装图标未更新”。

应用图标与本人/员工头像独立，互不自动联动。首版不增加用户上传、在线商店或人格自动换图。

## 3. 图标制作与分发

2026-10-21尺寸修正：此前转换脚本将原头像直接拉伸至512px方形，黄色方块等主体几乎顶满Dock图标区域。第一版只缩小透明轮廓，又使Dock整体图标显得过小；第二版加944/1024px（约92%）圆角底板后，用户反馈实际Dock又大了一整圈，合成预览不能代表真实观感。曾生成864px底板/760px主体的中间候选，但用户再次强调当前Dock仍显大，并明确要求白色背景和查GitHub，故未将中间候选作为最终结果。当前资源从原WebP计算可见边界、保留4px源图边缘，头像最长边680/1024px（约66%），纯白`#FFFFFF`圆角底板824/1024px（约80.5%），无额外渐变、描边或投影。21款运行态512px PNG与默认`.icns`由同一布局生成，原头像形象和纹理不变。[LockIME图标设计](https://github.com/oomol-lab/LockIME/blob/main/docs/DESIGN.md#3-app-icon--assetsxcassetsappiconappiconset-full-png-set)以824px主体匹配macOS应用图标网格；[VoiceStudio的Electron图标问题](https://github.com/debpalash/VoiceStudio/issues/2744)记录了960px主体比Dock邻居明显偏大，并指出运行时PNG和安装`.icns`都要修改。这些是开源项目的实现和测量，**Apple官方没有规定此处的固定824px安全边距**；Apple当前指南要求内容居中，并提供1024px画布与模板。[Apple App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons)、[Apple Design Resources](https://developer.apple.com/design/resources/)。

当前分发仍是Electron可用的扁平PNG与传统`.icns`，所以圆角底板绘入资源本身；这不等同于Apple新版Icon Composer的可分层图标。

先制作小老虎、薄荷圆环、小龙三个代表样本，覆盖普通角色、透明孔洞和复杂轮廓，再按统一规则批量制作：

- 统一画布、主体视觉大小和安全留白，保留耳朵、角和装饰，不简单裁成圆形。
- 当前保留纯白底板以避免纯透明版本显小；以用户真实Dock观感审阅最终比例，合成预览只作为批量一致性检查。
- 输出带alpha的无损PNG，避免黑底、白边与毛边；生成多尺寸图像及macOS `.icns`。
- 建议覆盖16/32/64/128/256/512/1024像素，并按iconset点尺寸和1×/2×名称组织；脚本检查尺寸和输出。
- 320px源图放大到1024px不会增加真实细节。大尺寸效果不足时需查找原始高清来源或重新制作，不以文件尺寸冒充画质。

现有离线生成入口为`scripts/generate-app-icons.mjs`，集中清单和资源位于`resources/app-icons/`。后续托盘素材在此映射上补充来源、制作参数及宿主资源，不覆盖原头像；分发要求见§8.2。

Electron官方支持PNG/JPEG，并推荐PNG处理透明图像。因此先转换WebP再交给宿主，不假定跨平台`nativeImage`格式保证包含WebP。[NativeImage官方资料](https://www.electronjs.org/docs/latest/api/native-image)

Renderer的Vite资源URL与主进程本地路径分开解析。主进程只按登记ID读取稳定分发目录，不用开发服务器URL或Renderer哈希文件路径。`scripts/build.mjs`和打包配置需显式包含图标及原生辅助程序，验证开发、dist、asar和安装版。

## 4. macOS接线路线

### 4.1 运行态Dock

主进程在ready后读取选择，解析PNG并检查`nativeImage`非空，再调用`app.dock.setIcon(image)`；每次启动重新恢复，修改时仅应用最新选择。官方API提供Dock图像设置，没有安装文件及退出后持久化保证。[Electron Dock文档](https://www.electronjs.org/docs/latest/api/dock)

图标设置不改变Dock显隐、角标、菜单、后台任务或窗口生命周期。恢复默认显式使用应用默认资源，避免退回Electron框架图标。

### 4.2 安装应用图标

现有macOS原生辅助模块调用`NSWorkspace.setIcon(_:forFile:options:)`，只为当前运行的BOAI安装副本设置文件图标。官方要求目标存在且用户可写，返回成功与否；文档说明该接口生成512×512图标表示，故还须核对大尺寸质量。[Apple NSWorkspace文档](https://developer.apple.com/documentation/appkit/nsworkspace/seticon%28_%3Aforfile%3Aoptions%3A%29)

该API存在不能证明退出后的固定Dock条目会立即刷新。以下按实际安装副本分别验收，已执行范围见§7：

1. 正确定位当前`.app`并核对应用身份，不扫描修改所有同名副本。
2. 设置、替换和恢复默认的Finder、运行中Dock、退出后固定Dock与再启动效果。
3. 可写/不可写目录、只读DMG、移动位置和多个安装副本。
4. 原生返回值、实际图标与保存选择的一致性；系统缓存旧图时不能报完整成功。
5. 包结构、签名校验与个人升级流程影响；不直接改写签名包内`Info.plist`或已封装资源。
6. 不把强制重启Finder/Dock、清空系统缓存作为日常切换步骤。

原生辅助程序编译后随应用分发，不要求用户运行时安装Xcode/Swift。不可写位置不自动提权或改其他副本，准确提示已完成范围并保留重试。

### 4.3 默认包图标与升级

构建已通过electron-builder的mac `icon`项显式配置默认`.icns`，打包与后续升级继续按锁定版本验证。[electron-builder mac配置](https://www.electron.build/mac/)

个人选择存在应用数据目录，不能只依赖`.app`文件属性。新版本首次运行应恢复并核对选择。

升级替换后、第一次启动前的图标恢复需要升级器处理，未运行的新程序不能保证这一阶段。与 [第22组04 本机发布升级](../22.开发自动化与持续测试/04-macOS本机发布与升级方案.md) 联合设计；尚未接线时明确此阶段可能显示包内默认图标，不宣称全生命周期保持完成。

## 5. 配置与失败恢复

与字体共用外观schema v2，已有`appIconId`只接受登记清单ID。旧配置缺字段用默认；不保存图片base64、任意路径或外部URL。托盘联动复用此字段，不增加第二份持久选择，扩展合同见§8。

保存偏好与系统应用不是一个原子事务，建议顺序：

1. 校验ID、资源存在及可解码。
2. 沿原revision队列保存选择。
3. 串行应用运行态Dock；安装版继续执行当前副本的原生更新。
4. 返回两个目标实际结果，不把写盘成功当作全部应用成功。
5. 重试或重启读取最新选择，较早回调不能覆盖较新值。

宿主维护已保存选择、各目标已应用ID、环境能力及待重试原因。安装路径由宿主确定，Renderer/业务协议只提交ID；无桌面宿主的CLI不声称已更新Dock。

Dock资源缺失回退有效默认图标并保留原选择供诊断；托盘的旧图保留与默认回退见§8.4。备份沿原外观快照保存ID，图标随应用分发；跨版本未知ID需回退说明。字体变更不触发无关图标重写，图标原生失败不阻断其他外观字段保存。当前状态对象只覆盖Dock/安装图标，未来托盘结果按§8独立补充。

## 8. 应用图标与托盘联动（2026-10-22合同）

用户先询问外观中的应用图标能否同时修改托盘图标，随后要求“先落实文档”。后续已获实施和本机隔离验收授权；本节保留设计合同，实际进度见§7。托盘在macOS中指顶部菜单栏的应用图标。

### 8.1 用户行为与范围

继续使用「设置 → 外观 → 应用图标」的21款选择，不新增独立托盘选项、单独保存按钮或第二份图标偏好。采用上一轮建议作为设计基线：**Dock保留当前完整彩图，托盘显示同一角色的透明单色简化版。** 具体小图仍需制作和实际菜单栏视觉审阅，本文件不代表21款视觉稿已经确认。

- 点击图标后沿原外观自动保存队列提交；保存成功后更新Dock与托盘，安装版继续更新当前`.app`。界面草稿预览不提前写系统图标，保存失败保持上次已保存图标。
- 「恢复默认图标」沿同一保存路径恢复默认小老虎的Dock图与托盘模板；固定字母B只保留为异常兜底，不作为正常默认选择。
- `pnpm dev`也支持当前进程内即时切换，无需打包、重启或更改共享`Electron.app`。手动/登录启动、窗口关闭后后台运行、重开窗口均读取同一已保存选择。
- 本期联动范围为macOS。Windows/Linux的现有托盘行为不扩展为已支持的应用图标切换；首版也不增加彩图/单色切换、用户上传、远程图片或员工头像自动联动。

### 8.2 托盘素材与视觉

Electron提供[`tray.setImage(image)`](https://www.electronjs.org/docs/latest/api/tray#traysetimageimage)更新现有托盘图片；macOS[模板图](https://www.electronjs.org/docs/latest/api/native-image#template-image-macos)以黑色与alpha描述形状，由系统适配深浅菜单栏。2026-10-22已核对接口文档；实现时仍须在项目锁定的Electron版本中验证实际效果。

1. 每个现有`appIconId`显式对应一组托盘资源，复用现有manifest；新增资源元数据不改变个人偏好schema。素材在构建前离线生成或绘制、审阅并随应用分发，运行时只加载本地图像。
2. 从原头像形象提炼小尺寸轮廓和关键特征，不直接缩小带白色圆角底板的Dock PNG，也不把彩图简单转灰度后当模板。模板主要依靠alpha形状，眼睛、孔洞和装饰须以透明间隙保留，避免角色都变成相似的实心块。
3. 沿现有托盘尺寸提供22×22的1×资源和44×44的2×资源，标明正确scale factor；尺寸是BOAI现有基线，不称为Apple强制标准。统一视觉留白、线宽与主体大小，并实际查看普通/Retina显示、浅深菜单栏和菜单选中状态。
4. 先审阅小老虎、薄荷圆环、小龙三个代表图，再补齐21款。原头像、Dock白底比例和默认`.icns`不因托盘制作而重做。
5. 使用PNG透明模板并显式设置`setTemplateImage(true)`。分发沿`scripts/build.mjs`和现有打包清单覆盖开发、dist和安装包；主进程按登记路径读取，不能依赖Vite URL或名称哈希碰巧符合模板规则。

### 8.3 所有权与生效顺序

| 现有位置 | 后续职责 |
| --- | --- |
| 外观Store与`appIconId` | 唯一持久选择；沿原revision、保存队列和失败处理，不在桌面设置或Renderer另存托盘ID |
| `src/shared/appearance/app-icons.ts`及manifest | 统一21款映射；`AppIconStatus`增加托盘能力、实际应用ID与错误，仍区分保存和系统应用 |
| `src/main/app-icon.ts` | 协调同一选择的Dock、托盘和安装图标结果；复用现有串行/最新选择规则及重试入口 |
| `src/main/background.ts` | 继续唯一持有Tray，提供图片更新和结果；不重建托盘、不复制菜单/点击监听、不接管偏好持久化 |
| `src/main/main.ts` | 连接外观变化与托盘初始化/退出；对齐最新已保存选择和当前Tray生命周期 |
| `src/renderer/pages/settings/appearance.tsx` | 保持原网格、共享字体/组件和自动保存交互；展示逐目标状态及原位置重试 |

当前启动顺序先应用AppIconController，再调用`background.init()`；实现不能仅在前者加入一次`setImage`，否则托盘尚未存在时会漏掉恢复。目标顺序为：

1. Main读取并规范化已保存选择；Tray创建时直接使用该ID的有效模板，失败才走§8.4回退。托盘尚未创建记为等待，不能误报已更新，也不能因Dock先成功而跳过后续托盘应用。
2. 正常保存后，先更新当前进程的Dock与托盘，再执行安装版的原生文件图标更新；三个目标分别捕获结果。安装文件更新保留串行队列，与运行态更新共用最新请求标识；新的Dock/托盘更新不能等待上一轮耗时的安装辅助程序，安装失败或较慢不阻止运行态切换。
3. 快速选择A→B→C时，每次系统调用前核对最新请求，较早结果不得覆盖较新状态；队列完成后以最后已保存的C为准。仅当所有适用目标都已应用当前ID时才能省略重复调用，不能继续只凭Dock成功返回。
4. 字体/主题等无关外观变化不重复写图标。macOS模板明暗由系统处理，不另加主题轮询；窗口隐藏/重开不重复创建Tray或监听器。
5. 退出期间拒绝新的托盘写入，迟到回调不能重建已销毁Tray。无桌面宿主或托盘不可用时返回对应能力状态，不把无操作计为成功；重启重新从已保存ID恢复，不跨进程保存Tray对象或应用成功状态。

### 8.4 部分失败、状态与恢复

三个系统目标不是一个原子事务。保留已保存的用户选择，按目标分别显示成功、等待、不可用或失败，不因托盘失败回滚已成功的Dock或覆盖偏好。

- 运行态换图资源缺失、损坏或更新失败时，优先保留原来可用的托盘图；首次启动无旧图时依次尝试默认小老虎模板、现有内置B。记录实际显示的是旧ID、默认ID或兜底图，不能把兜底B记为已应用用户选择。
- 资源失败不摧毁现有托盘，菜单、重新开窗和真正退出继续可用。若Tray自身初始化失败，沿第17组原有不可用提示与窗口处理，不因本功能修改关闭/后台规则。
- 现有「重试应用」按最新已保存ID重试未成功的适用目标；不得因某个目标成功而跳过失败目标，也不得重放过期选择。系统应用失败不影响其他外观字段保存。
- 提示面向实际结果，例如“Dock已更新，托盘未更新”；正常保存无需成功Toast，错误沿Sonner与就近状态。开发版必须能看见托盘失败和重试，不能被现有仅安装版的状态文案条件隐藏。
- 能力不可用、接口返回成功和实际系统显示是不同证据；宿主状态不代替macOS菜单栏截图或人工视觉审阅。旧Finder、固定Dock缓存和升级未验收范围仍按§7保留。
