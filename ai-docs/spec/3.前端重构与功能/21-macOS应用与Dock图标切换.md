# macOS 应用与 Dock 图标切换

日期：2026-10-20

状态：**已实施，持续验收。** 21款头像已转透明PNG，默认小老虎已生成`.icns`；开发版和隔离安装包均已实际切换。

## 1. 目标与设置交互

用户希望将系统里已有的预置头像转为可用的应用图标，并在设置中切换安装应用的 Dock 图标。

建议入口为「设置 → 外观 → 应用图标」，与 [20 字体设置](./20-全局字体与字号设置.md) 同页。复用全部21款预置头像，选择后保存，下次启动恢复。

按完整使用预期设计三层，分别验收：

| 层次 | 用户看到的效果 | 实现边界 |
| --- | --- | --- |
| 运行中的Dock | 选择后立即变化，后台运行/窗口重开仍保持 | Electron运行态Dock API |
| 安装应用 | Finder中的当前BOAI `.app`同步；退出后固定在Dock的应用仍显示所选图标 | 文件图标与系统缓存，需要原生验证 |
| 分发默认图标 | 首次安装、无个人选择时有正常默认图标 | 构建时的`.icns` |

仅完成运行态切换不能宣称安装图标完整支持。退出后的Dock刷新尚待验证，不能静默缩为临时图标功能。首轮面向macOS，Windows/Linux不展示可用的macOS切换入口。

设置区使用紧凑网格，显示实际转换后的预览、名称和选中状态，复用共享组件、主题及统一排版：

1. 点击后沿原外观队列保存，由宿主应用图标；正常成功仅更新就近状态。
2. 全部21款按头像原顺序展示，窄窗口自动减少列数，支持键盘选择。
3. 「恢复默认图标」只影响图标，并处理运行态与当前安装副本的自定义图标。
4. 保存结果和系统应用结果分开；失败使用Sonner，原位置保留「重试应用」。
5. `pnpm dev`文案明确“开发模式：仅当前进程”，不修改共享`Electron.app`或已安装BOAI。
6. 安装版同一选择覆盖运行态和当前副本；部分失败如实显示“Dock已更新，安装图标未更新”。

应用图标与本人/员工头像独立，互不自动联动。首版不增加用户上传、在线商店或人格自动换图。

## 2. 当前资源与映射

`src/shared/domain/avatars.ts`定义21个稳定预设ID，`src/renderer/assets/avatars/index.ts`映射本地WebP。目录资源说明登记为320×320透明图像；转换时仍须逐张核对像素、alpha和主体边缘。

当前外观无应用图标字段，`src/main/main.ts`无`app.dock.setIcon`接线。`package.json`的mac目标为DMG，未显式指定`mac.icon`，本次仓库检索未发现已登记的`.icns`图标集。

当前依赖是Electron `39.2.7`、electron-builder `26.15.3`；官方最新资料作为设计依据，落地须再按锁定版本验证。

## 3. 图标制作与分发

先制作小老虎、薄荷圆环、小龙三个代表样本，覆盖普通角色、透明孔洞和复杂轮廓，再按统一规则批量制作：

- 统一画布、主体视觉大小和安全留白，保留耳朵、角和装饰，不简单裁成圆形。
- 建议先保留透明轮廓，在真实Dock明暗背景中判断是否需要统一底板；底板样式另作视觉审阅。
- 输出带alpha的无损PNG，避免黑底、白边与毛边；生成多尺寸图像及macOS `.icns`。
- 建议覆盖16/32/64/128/256/512/1024像素，并按iconset点尺寸和1×/2×名称组织；脚本检查尺寸和输出。
- 320px源图放大到1024px不会增加真实细节。大尺寸效果不足时需查找原始高清来源或重新制作，不以文件尺寸冒充画质。

建议增加离线生成脚本、集中清单和资源目录，登记稳定ID、名称、原头像ID、源摘要、制作参数、预览及宿主资源。原头像不覆盖，来源说明保留。

Electron官方支持PNG/JPEG，并推荐PNG处理透明图像。因此先转换WebP再交给宿主，不假定跨平台`nativeImage`格式保证包含WebP。[NativeImage官方资料](https://www.electronjs.org/docs/latest/api/native-image)

Renderer的Vite资源URL与主进程本地路径分开解析。主进程只按登记ID读取稳定分发目录，不用开发服务器URL或Renderer哈希文件路径。`scripts/build.mjs`和打包配置需显式包含图标及原生辅助程序，验证开发、dist、asar和安装版。

## 4. macOS接线路线

### 4.1 运行态Dock

主进程在ready后读取选择，解析PNG并检查`nativeImage`非空，再调用`app.dock.setIcon(image)`；每次启动重新恢复，修改时仅应用最新选择。官方API提供Dock图像设置，没有安装文件及退出后持久化保证。[Electron Dock文档](https://www.electronjs.org/docs/latest/api/dock)

图标设置不改变Dock显隐、角标、菜单、后台任务或窗口生命周期。恢复默认显式使用应用默认资源，避免退回Electron框架图标。

### 4.2 安装应用图标

候选方案是最小macOS原生辅助模块调用`NSWorkspace.setIcon(_:forFile:options:)`，只为当前运行的BOAI安装副本设置文件图标。官方要求目标存在且用户可写，返回成功与否；文档说明该接口生成512×512图标表示，故还须核对大尺寸质量。[Apple NSWorkspace文档](https://developer.apple.com/documentation/appkit/nsworkspace/seticon%28_%3Aforfile%3Aoptions%3A%29)

该API存在不能证明退出后的固定Dock条目会立即刷新。正式接入前用实际安装副本验证：

1. 正确定位当前`.app`并核对应用身份，不扫描修改所有同名副本。
2. 设置、替换和恢复默认的Finder、运行中Dock、退出后固定Dock与再启动效果。
3. 可写/不可写目录、只读DMG、移动位置和多个安装副本。
4. 原生返回值、实际图标与保存选择的一致性；系统缓存旧图时不能报完整成功。
5. 包结构、签名校验与个人升级流程影响；不直接改写签名包内`Info.plist`或已封装资源。
6. 不把强制重启Finder/Dock、清空系统缓存作为日常切换步骤。

原生辅助程序编译后随应用分发，不要求用户运行时安装Xcode/Swift。不可写位置不自动提权或改其他副本，准确提示已完成范围并保留重试。

### 4.3 默认包图标与升级

构建时显式配置默认`.icns`，候选接线为electron-builder的mac `icon`项，实施时按锁定版本确认。[electron-builder mac配置](https://www.electron.build/mac/)

个人选择存在应用数据目录，不能只依赖`.app`文件属性。新版本首次运行应恢复并核对选择。

升级替换后、第一次启动前的图标恢复需要升级器处理，未运行的新程序不能保证这一阶段。与 [第22组04 本机发布升级](../22.开发自动化与持续测试/04-macOS本机发布与升级方案.md) 联合设计；尚未接线时明确此阶段可能显示包内默认图标，不宣称全生命周期保持完成。

## 5. 配置与失败恢复

与字体共用外观schema v2，建议新增`appIconId`，只接受登记清单ID。旧配置缺字段用默认；不保存图片base64、任意路径或外部URL。

保存偏好与系统应用不是一个原子事务，建议顺序：

1. 校验ID、资源存在及可解码。
2. 沿原revision队列保存选择。
3. 串行应用运行态Dock；安装版继续执行当前副本的原生更新。
4. 返回两个目标实际结果，不把写盘成功当作全部应用成功。
5. 重试或重启读取最新选择，较早回调不能覆盖较新值。

宿主维护已保存选择、各目标已应用ID、环境能力及待重试原因。安装路径由宿主确定，Renderer/业务协议只提交ID；无桌面宿主的CLI不声称已更新Dock。

资源缺失回退有效默认图标并保留原选择供诊断。备份沿原外观快照保存ID，图标随应用分发；跨版本未知ID需回退说明。字体变更不触发无关图标重写，图标原生失败不阻断其他外观字段保存。
