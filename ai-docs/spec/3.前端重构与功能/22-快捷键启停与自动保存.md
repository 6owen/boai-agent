# 快捷键启停与自动保存

2026-10-22，状态：**实现已接线，相关模块与编译版桌面路径通过，UI候选已审阅，开发版焦点路径受锁屏阻碍**。设置中的每项快捷键支持独立启停和组合键录入；开关即时保存，组合键在点击录入框外部后自动保存，页面及行内均不设置“保存 / 应用”按钮。

## 1. 用户要求与本轮范围

用户参考图确定三项交互：左侧开关控制是否启用，中间显示动作名称，右侧点击后显示“按下组合键”的录入框；无需再点击保存。颜色、字号、间距和焦点样式沿BOAI现有设置、共享组件及排版变量。

本轮先覆盖当前实际存在的四项动作。截图中的发送消息、后台发送、推理强度、语音聊天、附加文件是交互参考，不在本轮自动扩展为新动作；消息输入框专用按键需要另定作用域。

| 动作 | macOS默认 | Windows / Linux默认 | 作用范围 |
| --- | --- | --- | --- |
| Open Search / 全局搜索 | `⌘ K` | `Ctrl K` | 打开原检索Dialog |
| 切换侧边栏 | `⌘ B` | `Ctrl B` | 会话、通讯录、定时任务的原列表显隐 |
| 后退 | `⌘ [` | `Ctrl [` | 原导航历史可后退时 |
| 前进 | `⌘ ]` | `Ctrl ]` | 原导航历史可前进时 |

四项默认启用。关闭仅停止相应快捷键触发，保留已设置组合；原搜索按钮、侧边栏按钮和历史导航按钮继续可用。范围为BOAI窗口内的应用快捷键，不注册操作系统全局热键。

旧需求和验收来源见[第22组08](../22.开发自动化与持续测试/08-快捷键流程验收任务.md)。其第4节的只读、无配置IPC为历史首版限制；新实施按本文执行，原五场行为回归仍须保留。

## 3. 页面与操作合同

### 3.1 行布局与状态

保留当前设置标题、Card和分隔行。每行按“开关 → 动作名称 → 快捷键”排列；右侧未录入时展示组合键或“无”，点击后进入录入态，显示清晰焦点边框。关闭的项目仍可查看和编辑组合键；修改组合键不会擅自打开开关。

初次载入先渲染稳定行结构和占位，再填入Main快照；未加载或载入失败时不显示可操作的假默认值。开关具有动作名称和开关状态，录入控件可通过键盘聚焦并激活，错误反馈使用现有可访问Sonner。状态文字沿用共享字号，不新增局部固定字号。

保存中在对应行显示状态并防止重复提交；成功后恢复普通行，不为每次修改弹成功Toast。失败统一沿Sonner反馈，原控件保留草稿、未保存状态和重试入口，不新增错误Banner或红字错误块。页面不存在统一保存栏，也不增加每行“保存 / 完成”按钮。

### 3.2 自动保存与取消

| 用户操作 | 必须发生的行为 |
| --- | --- |
| 点击开关 | 自动提交该项启用状态；回执成功后执行器使用新状态。关闭保留原组合 |
| 点击或键盘激活右侧组合键 | 进入录入态并保存原值基线，提示“按下组合键”；仅进入录入不写配置 |
| 按下完整组合键 | 显示本次候选；再次按组合键替换候选。此时不持久化、不改变实际绑定 |
| 点击录入框之外 | 有变化且合法时自动提交一次；点击空白区也算，不依赖目标能否获得焦点 |
| Tab / Shift+Tab离开录入框 | 按相同规则提交并正常移动焦点；不把Tab录成快捷键 |
| 主窗口失焦 | 退出按键捕获；已有完整合法候选按相同规则提交，没有候选则不写入 |
| Esc | 取消当前尚未提交的录入，恢复最近已保存值；不提交、不触发后退或其他动作 |
| 录入态下按无修饰的Backspace / Delete | 将候选清空为“无”，点击外部后保存；不关闭开关。启用但为“无”时没有可触发按键 |
| 未按键或候选与原值相同就离开 | 退出录入，不产生写入或保存提示 |
| 输入非法或冲突组合后离开 | 保留待改候选，通过Sonner报错，实际绑定继续使用原已保存值；不强制抢回焦点 |

Enter不是额外的保存步骤，也不在按键抬起或录入计时结束时提前保存。第一版只支持单组组合键，不支持连续多段按键序列；纯修饰键、组合输入中的半成品及长按重复事件不形成候选。

### 3.3 点击顺序与离页

“点击外部”与随后发生的blur只算一次提交。点击另一行录入框时，先处理当前候选，再进入目标行；不能把同一次按键或失焦重复提交。点击当前行开关时，合法候选和开关目标作为同一行修改提交；候选非法则保留错误、开关不变，避免一半成功一半丢失。其他行操作沿同一写入队列顺序处理。

离开快捷键设置、关闭窗口或退出前，先完成当前合法候选的提交并等待在途回执，再沿原导航/退出流程继续。保存成功的正常离页不弹确认；若有非法候选、失败或结果未知，保留草稿，接入原草稿守卫，允许用户返回修改或明确放弃。用户放弃只清除未提交草稿；已经发出的请求必须先核对结果，不能把未知请求当作已撤销。

失败后仍通过编辑、再次点击外部触发重试，不为异常状态新增“保存”按钮。待保存和失败草稿由页面之外的状态所有者保管，不因组件卸载静默消失。

### 3.4 恢复默认

页标题右侧提供一个低强调的“恢复默认”动作，恢复四项默认组合及启用状态，一次原子提交并自动生效。它不是保存入口；有未解决的录入或在途写入时，先按3.3节处理，再执行恢复。恢复失败保持原已保存配置，不出现部分行恢复的状态。

## 4. 按键、冲突与执行边界

当前四项均为应用级动作，组合键至少包含macOS的Command或其他平台的Ctrl，可附加Shift / Alt；不开放裸字母、数字、空格等会吞普通输入的绑定。Esc、Tab及无修饰删除键为录入操作保留。纯修饰键、无法识别的主键、IME组合输入及多段序列均不能保存。录入、展示、校验和执行共用一套规范化规则，不能用界面显示字符串直接判等；实施时须固定主键的`key` / `code`映射，并覆盖中英文输入法与括号键。

冲突按“规范化组合相同，且启用作用域重叠”判断。当前四项作用域存在重叠，同一组合不能同时启用两项；提示具体占用动作，不能自动覆盖或关闭另一项。关闭项可保留重复组合，重新启用时再次校验；冲突时维持关闭状态和原配置。换绑释放原组合以持久化成功为界，不在候选阶段提前释放。

与应用级作用域重叠的原生菜单组合、复制/粘贴/剪切/全选/撤销等通用编辑组合及已知平台保留组合不可用于这四项。占用表以实际平台菜单和共享规则生成，开发版的重新加载/开发者工具也需考虑；不能只检查四行彼此是否重复。输入控件内部的局部操作仍由上下文保护，例如富文本中的`⌘ B`保留给加粗，不因此废除应用层的默认侧边栏组合。系统或其他应用拦截、BOAI根本收不到的按键不能假装已录入，也不承诺检测所有第三方热键。

录入态暂时阻止本窗口应用动作和相关原生菜单加速键执行，退出录入、窗口失焦、页面卸载及异常路径均释放捕获。只能影响当前受控窗口，不能长期停用菜单或全局键盘。Electron对应用内菜单快捷键、窗口按键事件与系统全局热键有不同入口，实施参考[官方快捷键文档](https://www.electronjs.org/docs/latest/tutorial/keyboard-shortcuts)，不以`globalShortcut`替代本需求。

运行时继续复用原四个动作及原草稿守卫，并保持以下边界：

- 普通输入、富文本、原生select、关闭且聚焦的自定义Select / Combobox保留自身键盘操作。
- IME组合输入、重复按键、已被处理事件以及Dialog / 菜单 / Popover中的操作不触发应用动作。
- 无可用历史时前后导航不改变状态；非会话/通讯录/定时任务页面不切换列表。
- 原有一概拒绝Alt / Shift的判断改为与已保存组合精确匹配，多余修饰键仍不触发。
- 只有启用、有绑定、当前上下文可执行的匹配项才消费事件；关闭项和“无”不能留下隐形快捷键。

## 5. 状态、持久化与接线职责

### 5.1 唯一配置来源

Main拥有本机快捷键偏好；Renderer只持有已保存快照、录入草稿和在途状态。拟新增独立`shortcut-settings.json`，放在现有桌面偏好的受管目录，不写员工配置、业务会话或Renderer的localStorage；不顺带扩大业务备份/同步范围。

共享纯模块定义稳定动作ID、平台默认组合、启用状态、可空绑定、规范化及冲突规则。配置带schema版本和整体`revision`，以动作ID识别记录，不能用中文名称或行序号持久化。缺少文件或新增动作时使用兼容默认；损坏或未知高版本不能静默覆盖原文件，应告知只读回退状态并阻止不安全写入。

新读取/更新方法及变更事件接入原受控IPC、preload与客户端白名单。更新携带目标动作patch、`expectedRevision`和用于关联回执的`requestId`；Main串行校验、原子落盘，再返回规范化快照并发布变更。只有持久化成功后执行器才切换，保证设置显示、实际匹配和重启读取来自同一版本。

### 5.2 失败与并发

| 状态 | 处理要求 |
| --- | --- |
| 正在保存 | 该行锁定重复提交；队列不靠旧全量快照覆盖其他行修改 |
| 校验或写盘明确失败 | 原绑定继续生效，保留草稿及错误；不展示“已保存”，重试仍由退出录入触发 |
| `expectedRevision`冲突 | 读取新快照；不同动作可在重新校验后顺序提交，同一动作被修改则保留用户草稿并提示重新核对，不盲重试覆盖 |
| 回执超时、断开或结果未知 | 回读权威快照确定是否已提交；未核对前不宣称失败回滚或成功，也不让迟到回执覆盖新意图 |
| 当前录入动作收到外部更新 | 更新已保存基线，保留本次草稿并标明变化；Esc回到最新已保存值，提交前重新校验 |
| 已保存后页面重开/应用重启 | 恢复启用状态和组合；不恢复未提交候选或录入捕获状态 |

在途请求由请求身份和版本判断新旧；旧错误/成功回执不得清掉更新的草稿。用户快速改多行、切设置分类或隐藏窗口时仍沿同一队列，不能每次渲染重复注册监听器、复制执行器或放弃保存。

### 5.3 后续实施顺序

先落实共享动作/绑定合同和Main持久化；随后把AppShell硬编码匹配接到已保存快照；再加入设置行的开关、录入、clickoutside和保存状态，接通原导航/退出守卫及录入时原生菜单保护。动作本身、业务历史、搜索状态和员工会话不另建副本。

实施时需要更新源码中“只读/不保存”的旧Header及相关索引；本轮实施候选已同步相应源码Header和目录索引。真实验证以用户日常使用的`pnpm dev`进程为准，不要求用户更换已安装应用来验证本功能。
