# 资源库提示词分组

2026-10-22，状态：**实现已接线，模块和实际开发版主要分组路径通过**。资源库中的“提示词”主列表参考“技能 → 收藏”，增加用户自定义分组、分组折叠与数量，并沿用其分组管理、移动和排序方式。

## 1. 范围与使用方式

进入“资源库 → 提示词”后，列表按“自定义分组 → 未分组”展示。每条提示词最多属于一个分组；新建或尚未分类的提示词位于“未分组”。分组是目录整理方式，不改变提示词正文、版本、使用权限或发送行为，也不要求先收藏提示词。

本轮修改提示词主列表，左侧资源库的技能/数据源/提示词类型导航沿原结构。2026-10-29起，提示词查看、新建和编辑进入Shell右侧详情面板，header复用数据源的标题/AI管理/更多操作；已有提示词默认只读，通过header菜单“编辑”进入名称、描述和正文表单，新建直接进入表单；删除提示词仍需明确确认；聊天中通过`$`引用及发送时展开正文的语义保持。

## 3. 列表与分组管理

### 3.1 分组显示

- 每组沿技能收藏的组头显示名称、数量和折叠箭头；点击组头展开/收起，不打开提示词详情。
- 自定义分组按保存顺序展示，“未分组”固定最后。未分组是系统入口，不可重命名、删除或参与组序拖动。
- 首次使用默认展开，随后记住用户手动折叠状态；这与左侧资源类型默认收起是两个独立状态。新增组展开，删除组清理对应折叠记录。
- 未搜索时保留空组及0计数，便于整理和拖入；空组显示轻量空态。没有任何提示词时仍可管理已建分组，保留“新建提示词”入口。
- 组内沿原提示词行展示名称和描述/正文摘要，不增加一套卡片或颜色体系。字体、尺寸、留白、箭头和动画直接沿共享组件及全局变量。

分组列表沿收藏的自然布局，展开/收起不自动滚动至组首，不因内容卸载让后续组头跳位。只有用户明确定位条目或通过键盘移动焦点时才进行必要的可见区域定位。

### 3.2 新建、重命名与删除分组

在提示词工具栏最右侧放置“提示词分组”图标入口，搜索位于其左侧，Popover布局参考技能收藏。Popover标题旁加号在悬停/键盘聚焦时出现，新建期间保持可见；新建和重命名使用原位输入、同行保存/取消，Esc取消名称编辑。分组名称去除首尾及重复空白，沿收藏的1–40字符、最多100组规则；名称不区分大小写判重，“未分组”保留给系统。

管理浮层显示各组完整成员数，支持拖动及原DragList键盘方式改变组序，不另加上下移动按钮。编辑、删除确认或提交期间沿原忙时锁定，避免同时排序改变目标。

删除使用原Popover确认，明确说明“组内提示词将移到未分组，提示词内容会保留”。一次事务删除组及其成员归属；成员按原组内相对顺序追加到未分组末尾。空组同样允许删除。只有用户选择“删除提示词”并确认时才删除具体提示词，两个操作入口与文案必须区分。

### 3.3 提示词移动与顺序

沿技能收藏的拖拽交互：拖到组头（包括关闭组或空组）即移入该组末尾；拖到提示词行前/后则调整顺序，并跟随目标行所属分组。一次跨组移动同时保存归属和顺序，不能出现复制条目或两个组都显示同一项。

2026-10-29按用户要求移除行内分组和编辑按钮；组序及条目排序保留原DragList键盘操作。更多菜单只提供“删除提示词”，触发器在hover、键盘聚焦、菜单/确认打开时可见，触屏保持可见。点击行打开默认只读的右侧详情，编辑入口仅在header更多菜单中，菜单不能冒泡触发行打开。

新建提示词沿右侧同款表单保存，成功后加入未分组；用户随后移动到需要的组。正文编辑仍按原保存/取消和草稿守卫执行，不引入额外的“正文保存后才能保存分组”步骤。移动、排序和确认删除分组在操作完成时提交，无整页保存按钮；分组名称编辑沿收藏的行内保存/取消。

引入集合顺序后，内容编辑不让条目跳组或重排。首次兼容旧数据时保留当时的更新时间倒序；有序集合建立后，新提示词追加到未分组末尾，人工顺序成为列表顺序来源。

## 4. 搜索、定位与状态

搜索继续匹配提示词名称和描述，先筛选条目，再按原归属显示命中组，暂时展开命中组，组头数量为命中数量；没有命中的组暂时隐藏。清空搜索恢复完整计数、组序及用户原手动折叠状态，搜索不能持久改写折叠偏好。

搜索期间禁用列表拖拽排序，避免按过滤后的相邻项误写全量顺序；“移动到分组”菜单仍可明确设置归属，清空搜索后核对完整列表位置。管理Popover始终显示完整组序和总数，不能用搜索结果改写集合。

从左侧条目或原固定ID入口定位提示词，沿现有focus请求打开对应Dialog，不因所属组折叠或当前搜索隐藏而误报不存在。仅分组变化不关闭当前查看/编辑Dialog，不丢正文草稿；关闭详情后回到原目录状态。

先渲染稳定工具栏和列表占位，再填入提示词及分组快照。提示词/分组任一读取未完成时，不将“尚未读取”当作“没有分组”或空目录；可保留已有快照，尚无完整快照时禁用分组写操作。所有操作/加载/冲突失败统一使用Sonner，草稿和恢复入口留在原控件，不新增错误Banner或红字错误块。

## 5. 数据与一致性

### 5.1 独立集合

沿ProductStore新增提示词集合记录（拟名`promptCollections/library`），保存整体`revision`、有序组列表、提示词顺序及`promptId → groupId`归属。它覆盖全部现存提示词，不设favorite集合；与`skillCollections/library`独立，双方同名分组互不影响。

正文继续使用`PromptTemplate`及其`revision`。仅分组、移位或改组名不改正文版本/更新时间，不改`PromptTemplateReference`已有的正文快照，也不向模型发送分组名。分组ID和提示词ID均为稳定身份，不能用名称或当前行号定位。

Runtime拥有事务和业务校验，Renderer只维护快照、草稿及折叠显示偏好。新集合读取/变更合同接入原共享IPC、运行服务分发和Main公开方法准入，沿全局changed事件更新；不新建独立文件数据库或第二套资源目录服务。可抽取已有分组表现层的公共部分，但不为提示词重写整个技能收藏模块。

### 5.2 原子修改与竞争

| 情况 | 必须处理的结果 |
| --- | --- |
| 创建/改名/删除组、移入组或调整顺序 | 请求携带集合expectedRevision；事务校验组、提示词存在及版本后一次写入，返回完整权威集合 |
| 提示词新建/删除 | 在原正文事务中同步登记顺序或清理归属；保留原删除最小身份，不留下已删条目的计数/空引用 |
| 组删除与正文编辑同时发生 | 编辑只更新正文；删除组只清归属。旧正文保存不能重建已删除分组或覆盖新归属 |
| 移动期间目标组或提示词已被删除 | 拒绝原操作，刷新快照并提示；不擅自重新创建对象或移入别的组 |
| 版本冲突/明确保存失败 | 原已保存组序和归属继续为准，保留名称草稿；不盲目重放旧操作覆盖其他窗口 |
| 回执未知或迟到 | 先回读核对结果，禁止重复创建组/移动；旧读取或旧回执不能覆盖较新快照 |

沿既有收藏Hook的缓存、版本和读取代次隔离；成功回执后更新列表、管理计数和相应目录投影，失效回调不污染新的页面实例。正文表单保留自己的所见版本和草稿守卫，不能因收到集合变化重置表单。

### 5.3 旧数据与恢复

无集合记录时，全部既有提示词投影到未分组，顺序与当前更新时间倒序一致；首次集合写入再持久化这份顺序，不改旧正文。首次初始化、读取和新建/删除必须在一致的事务边界处理，不能因初始化时的旧列表漏掉新条目或复活已删除项。

集合跟随原ProductStore备份/恢复处理，并在实施时核对纳入范围；旧备份没有集合时按未分组兼容。读取残留未知组引用时将仍存在的提示词显示在未分组，已删除提示词不展示；修复元数据不得覆盖正文。损坏集合不能伪装空集合继续覆盖保存，应保留原记录并通过现有错误/恢复入口处理。折叠状态可沿收藏存为本机显示偏好，但业务组名、顺序、归属必须由Runtime持久化。
