### F1：先保持行为，再改变组织

- 保留 `src/renderer` 根、Vite `base: './'`、生产 CSP、Carbon/Solar 静态类及本地构建方式。
- `services/request/desktop-client.ts` 封装现有 `window.boai.request/subscribe`。第一阶段仅迁移调用入口，不更换传输、不再建立第二份订阅或独立业务缓存。
- 拆分 App 时保留请求序号、会话 ID 校验、流式增量合并、取消订阅、脏表单保护、导航历史和焦点归还。保留现有 localStorage 布局键的兼容读取。
- 草稿、表单、流式消息与窗口偏好分别处理；不因为引入 Zustand 就一次性把所有状态放进单个 store。
- 样式先 token 化、限制旧全局规则，再引入新原语。组件移动与业务改写分开，过渡重导出列出清理阶段。
- 阶段验收覆盖现有导航、表单、IPC、窄窗口及下文 v0.2.2 行为；只移动文件不新增镜像式单测。

### F2：完成可保存的主题闭环

- 先冻结共享外观 DTO、默认值、revision、模式解析序号和事件合同，再并行开发 Main 与 Renderer。
- 浅深主题 ID 分别保存；`resolvedMode` 为运行结果，不能覆盖用户的 `system` 偏好。Base46 数据转换为语义变量，不运行主题脚本。
- 先提供完整且可回退的 token，再接模式卡、色板选择、即时预览和保存反馈。变量应用到根元素，使 Portal 也换肤。
- 主进程拥有配置文件与 nativeTheme；Renderer 的 Zustand 只是内存镜像，不再以 localStorage 保存第二份权威外观配置。
- 移除强制浅色首帧假设，保留安全默认外观和启动失败回退。切换主题不得重挂载聊天、取消执行或丢失草稿。

### F3：图片与完整交付一起闭环

- Main 校验并复制图片，按资源 ID 提供读取；Renderer 只引用受管 URL，图片不透明度仅作用于背景层。
- 连续修改、取消导入、失败保留旧图、配置引用提交和旧资源清理遵守同一写入队列。
- 背景图片、复杂聊天和 Portal 组合验证可读性；桌面缩放和键盘滑块行为沿用原验收标准。
- Main 协调已提交外观与业务备份，更新恢复清单；Agent Runtime 不可用不应阻止修改外观。
- 最终在实际安装包验证系统变色、图片协议、重启、备份恢复及原功能。原 D 的回归要求也适用于 F1/F2，不能全部留到最后。

## 与后端重构的共享依赖

| 边界 | 前端所需保证 | 所有权与协作方式 |
| --- | --- | --- |
| 已有 Methods / AppEvent | 方法输入输出、消息 ID/sequence/turnId、错误和取消语义稳定 | 后端可在契约之后拆模块；前端只依赖 `src/shared` 与 IPC 适配，不直接依赖 Runtime 或 Mastra |
| 会话活动投影 | 保留轮次、运行、公开消息及 `unresolvedFailureDeliveryIds` | 失败是否恢复由后端决定，Renderer 只按本轮展示，不重新实现调度策略 |
| 外观配置 | 配置/patch、expectedRevision、规范化快照、保存错误 | 新增到共享纯模块和 Main 白名单；不要复用员工配置或业务数据库字段 |
| 模式和资源事件 | 同 revision 的更新模式仍可被接收；订阅可取消 | 增加事件前把现有消息订阅改为完整的类型分支，不能默认所有其他事件都有 `message` |
| 启动与图片 | 受控启动快照、nativeTheme、资源协议和必要 CSP 来源 | Main/preload 与 Renderer 协作；前端不能导入 Electron、文件系统或直接读用户路径 |
| 退出保护 | 汇总业务表单、外观待提交、保存失败等来源 | 前端用来源登记集合，Main 继续统一处理退出；页面卸载只移除自身来源 |
| 备份 | 业务与外观快照及引用资源全部成功才返回成功 | Main 协调 Runtime 的已有业务导出和外观导出，不由 Renderer 直接拼接文件 |

只要已有契约稳定，F1 不必等待后端内部拆分结束。F2/F3 的 Main 外观目录、preload、共享类型、退出保护和备份接口属于交叉文件，应先确定唯一编辑者或分批合入；前后端不得各自写一套同名设置来源。

## v0.2.2 必须保留的回归边界

1. 当前轮次和历史背景分开；`activity.ts` 的显式时间排序与分组能力不能因拆文件退回到数组末项或简单 reverse。旧直接会话没有 turnId 时仍按触发消息分组。
2. 活动默认只显示本轮，触发消息、时间和阶段可见；旧错误与运行记录保留在历史轮次中，不冒充当前故障。
3. `unresolvedFailureDeliveryIds` 是服务提供的权威投影。后续 pass 不得隐藏未恢复执行失败，已恢复的旧判断错误不能继续作为当前失败。
4. 成员状态核对同轮、同员工、completed 的公开消息。员工已回复后不再补充，显示“已回复，暂无补充”；仍在处理/等待的状态保留，从未回复的 pass 保持不发言语义。
5. 历史轮次和已有后续尝试的旧失败不默认推荐重试。记忆维护的 failed/interrupted 没有普通任务重试按钮，不能重跑原任务；重启也不自动重放外部副作用。
6. 列表按真实 `lastMessageAt` 与实时消息时间排序，普通设置修改不能把会话顶置。保留草稿、滚动位置、审批、取消和迟到结果保护，不恢复“最近会话”标签。
