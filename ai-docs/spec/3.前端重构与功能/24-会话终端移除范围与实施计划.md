# 会话终端移除范围与实施计划

2026-10-22，状态：**终端退役实现已接线，相关模块、编译版及开发版预览生命周期通过**。用户最初要求仅落实文档，随后以“开始执行”授权这轮五项目标。现已修改终端退役候选代码、依赖与随包技能，实际进度归第7节；尚未重启用户进程或修改用户技能绑定。

## 1. 产品决定

移除会话里供用户输入命令、选择/创建/结束shell的“终端”产品能力，以及对员工公开的这套`terminal.*`操作。完成后，不再提供终端菜单、终端标签、终端输入区或隐藏的启用开关。

网页预览保留，并成为独立入口。员工通过原执行工具或所选本机Agent运行命令的能力、执行过程、文件/成果预览、BOAI CLI与桌面活动日报沿原合同。本次移除不改变这些能力的权限、身份和运行语义。

原终端并非所有员工后台命令的自动镜像；移除的是BOAI另行创建的会话交互式shell。用户仍可在执行过程里查看员工通过原工具回传的命令及结果，不新增一套替代终端。

历史接入来源见[独立Agent架构§11.57](../../2026-10-19-BOAI独立Agent配置与行为运行架构.md#1157-侧栏终端预览与桌面活动日报2026-10-20范围收口)。该节原实现与验证保留；2026-10-22后的产品方向以本文为准，不能把本文的计划写成产品已经移除。

## 3. 界面与协议移除范围

### 3.1 界面

会话操作菜单和对应右侧标签统一显示“网页预览”，沿原员工/会话身份、右侧标签复用和已有页面可用范围打开。移除“终端 / 预览”切换栏、终端选择器、新建/结束终端按钮、xterm视图及直接输入命令的入口；保留预览目录、预览启动命令、启动/停止/刷新、真实URL与页面内容。

终端相关轮询、按键写入队列、尺寸观察和字体事件监听一并退出，页面隐藏、关闭及切换不会继续发terminal读写。旧详情目标中的`view: terminal`不再恢复终端，也不静默创建预览或shell；只移除这个失效目标，其他详情标签、聊天草稿和历史定位保持。迟到的旧show事件同样不能重建终端面板。

预览中“到终端查看输出”等提示改为真实可用的状态/诊断入口。失败统一沿Sonner反馈；需要查看开发服务输出时，在预览内提供按preview ID关联的有界只读诊断，保留截断/退出状态，不能重新加入stdin、resize或任意交互shell。

### 3.2 应用协议与旧请求

| 操作 | 移除后的合同 |
| --- | --- |
| `terminal.list/create/read/exec/write/resize/kill` | 新调用不可执行，不再作为可用能力推荐；保留必要的不可用兼容注册，明确返回终端已移除，不创建进程或消费原始输入 |
| `workspace.show` | 新请求只允许网页预览；旧terminal新请求明确拒绝，不能转换成一次新执行 |
| `workspace.close` | 新请求仅关闭明确指定的预览；兼容空terminalIds。携带非空terminalIds的新请求整体拒绝，不先停止部分预览再失败 |
| `preview.detect/list/start/stop` | 保留原能力、目录/命令权限及员工会话隔离，关闭只处理该预览所属资源 |
| 原请求回执查询 | 保留同身份访问、稳定requestId、参数冲突核验和原终态；未知结果不重新执行 |

当前ApplicationService先查注册/schema再查写回执，因此不能直接删掉所有操作注册，导致旧请求失去原回执语义。实施时沿原`available: false`等兼容方式保留旧操作识别和输入合同，旧回执优先返回；目录若保留兼容条目，必须标明不可用及原因。新终端请求被拒绝，原成功回执仍是历史事实，不能据此宣称当前终端可用。

同一退役规则覆盖桌面、`boai.application.v1`、CLI转发及员工工具入口，不允许只隐藏按钮而让默认技能继续创建不可见的用户终端。预览内部调用不经这套退役的公开terminal接口。

## 4. 保留预览与收回进程

### 4.1 预览内部依赖

第一步保留当前开发预览所需的受管进程能力，由PreviewService按preview ID持有创建、读取诊断、结束和退出状态。可以先复用TerminalService内部实现，无须为了去掉产品终端立即重写进程执行器；对外不再提供选择该内部shell进行任意交互的入口。

保留静态目录边界、loopback监听、真实就绪探测、开发命令端口替换、失败收尾和沙箱页面。开始预览不会因为终端退役获得额外目录或命令权限；停止预览必须等其真实监听/子进程退出，不能用隐藏视图代替停止。

`@xterm/xterm`、`@xterm/addon-fit`及专用样式在实施时确认无剩余使用后移除；原生进程守卫、PTY helper或共享进程代码仍被预览/其他执行路径使用的部分保留。依赖和打包调整属于后续代码实施，实施候选已移除独占xterm依赖和对应lock条目，验证状态见第7节。

### 4.2 切换、退出和旧残留

移除公开能力时先停止接收新的终端创建/写入，再处理旧独立终端。按宿主记录的真实会话与进程身份等待退出；预览关联进程由PreviewService管理，不靠标题、进程名或端口猜测归属，不能误杀员工原运行、本机Agent或用户另开的Terminal应用。

前端HMR不足以完成此退役：后台仍可能运行旧注册和旧shell。后续实施必须核对实际`pnpm dev`宿主已加载新服务，并走原正常退出/重启与受管ledger恢复链路。新进程不恢复或重放历史终端命令；普通关闭预览标签仍按原行为暂停显示，不自动结束预览，真正退出则完成原排空。

保留历史聊天、执行记录、命令回执和用户工作文件。旧ledger只用于确认并回收BOAI拥有的残留进程，确认退出后按原生命周期清理，不能先删除ledger使进程失去管理。备份提示及门禁与新可见入口一致：用户可在网页预览中停止其服务；其他已退役终端残留由宿主收尾，不要求用户打开已经移除的面板。

## 5. 技能、历史与实施接续

后续修改`boai-artifact-sidebar`的分发内容、说明及相关生成目录，保留网页预览工作流，撤掉terminal操作指引和“与用户同一终端”承诺。已经绑定的受管副本沿原技能来源hash、绑定版本和回执流程更新；自定义改动按原冲突规则处理，不直接写用户数据库或覆盖其他技能。旧副本若仍请求terminal，由宿主退役规则拒绝，不通过放宽权限迁就旧指引。

Alma研究原件、原接入实验与失败记录保持历史身份。桌面活动日报及其默认关闭、采集授权和来源事实边界不属于此次移除。

实施按以下顺序进行：

1. 固定公开退役/旧回执兼容与内部预览边界，先确保预览生命周期仍有所有者。
2. 同批调整界面、show事件、默认技能及全部公开操作入口，清除终端专属订阅；避免仅前端隐藏的半完成状态。
3. 核对退出/恢复/备份门禁，处理旧残留、必要依赖及构建分发。
4. 按第6节验证，并在第7节记录确切源码、开发宿主、真实结果与剩余。
