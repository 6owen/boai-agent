# 视觉与交互规格

本文是第二版效果图的落地规范，已纳入用户对渐隐、输入框、重复引用、整组右对齐、消息交互卡片以及 Prompt Bar 的后续反馈。像素值为建议实现基线，不是对生成图的逐像素测量；不得把整张位图拉伸后当作界面。

## 1. 四栏与滚动

以 1440×1024、100% 应用缩放核对布局。保留现有原生窗口工具栏和列宽持久化。

| 区域 | 落地基线 | 规则 |
| --- | --- | --- |
| 主导航 | 沿用现有 52px rail | 沿用当前入口与图标，不按设计图省略项删除资料库、帮助等能力 |
| 会话列表 | 初次布局建议约 300px；可调 232–360px | 已有用户宽度优先；复用搜索、置顶、文字 label 分组折叠、拖拽与右键菜单 |
| 群聊主区 | 剩余宽度；上述基线下约 728px，另扣分隔线/外框 | 正文与输入区共享左右对齐线，横向内边距 24px |
| 右侧详情 | 默认 360px；可调 300–560px | 由用户明确打开；保留详情 Tabs、关闭、收起、拖拽排序与草稿保护 |
| 顶部工具栏 | 沿用 44px | 不新增设计图右上角的装饰性日期时钟；保留窗口拖拽区 |
| 群聊标题 | 64px | 沿用悬浮标题，消息滚动容器与标题底部重叠 16px，使用共享 ScrollFade；顶部首条正文留在标题下方 |

列表、消息和详情各自滚动；输入区位于聊天列底部，不横跨右侧详情。正文最多约 768px 宽，详情收起后的宽窗仍保持易读行长。输入区与正文容器整体对齐。

窄窗口遵守现有会话分栏规则：不因窗口缩小偷偷修改用户列宽、自动改成浮层或自动关闭详情。保留列表/详情的显式开关；标题可省略，工具操作允许换行，代码和表格在各自容器横向滚动。固定分栏总宽超过窗口时复用 Shell 原有溢出方式，不在消息内容层另建横向布局系统。

## 2. 色彩、排版与控件

| 用途 | 使用现有语义变量 | 浅色参考 |
| --- | --- | --- |
| 外层/导航背景 | `--surface-app` | `#f6f6f6` |
| 会话列表背景 | `--surface-list` | `#fbfbfb` |
| 正文/详情背景 | `--surface-content` / `--surface-detail` | 白色 |
| 主要/次要文字 | `--foreground` / `--muted-foreground` | `#0d0d0d` / `#5d5d5d` |
| 分隔线 | `--border` | `#e5e5e5` |
| 主操作 | `--primary` | `#2563eb` |
| 选中/悬停 | `--selection` / `--accent` | 跟随主题，不另写一套蓝色色板 |
| 错误/警示/成功 | 现有 destructive / warning / success 语义 | 同时显示文字，不仅靠颜色 |

- 沿用 Geist 与中文系统字体回退；不下载新字体。
- 正文使用全局字号 `1rem`（当前 13px）、行高 1.7，消息小标题约 14px；姓名继承全局 13px，时间 11px；消息头不展示员工职责/描述，职责放入头像资料浮层；时间默认透明占位，悬停或键盘聚焦消息时显示。
- 消息头像 32px；同一员工跨列表、消息和任务行使用现有 Avatar 与相同身份，不创建新的头像系统。
- 发言组之间约 20–24px，同一人的连续消息约 6–8px；正文段间约 8px。
- 文件与审批容器圆角约 10px；输入框完全沿用共享 Soft 皮肤，包括 `--radius-composer`（当前 32px）、squircle、高光、阴影与发送按钮。群聊不覆盖输入皮肤，不改全局 token。
- 图标复用现有本地 Carbon/Solar 入口；主要操作图标约 16px，可点击区域至少沿用 32px 控件。
- 图中的少量蓝底、头像色为示意。主题、深色模式和既有员工头像优先；深色版按相同语义变量派生，本目录没有经选择的独立深色效果图。

## 3. 标题与会话列表

群聊标题左侧只显示群名，移除“你和 N 位 AI 员工”副标题。右侧重叠显示真实成员列表中的前三位头像，头像及点击区域均为 24px、重叠 6px，保留主题背景色的静态分隔边缘；悬停、聚焦和打开资料时都不增加底色、外圈或改变叠放层级；每个头像可点击，向下打开与消息头像共用的只读员工资料 Popover。超过三位时，在最后头像右侧 2px 处显示纯文字 `+N`（剩余真实人数），无按钮底色、边框或悬停下划线；悬停/键盘聚焦只变为主题链接色，点击打开当前群组已有设置详情。保留任务与产物入口和更多菜单，不显示没有真实来源的在线状态。

“任务与产物”打开当前会话既有 activity 详情目标；重复点击复用同一标签。更多菜单保留配置、置顶/取消置顶、执行过程、清空等已有操作。

效果图中的顶部搜索按钮不意味着新增消息搜索：首期不渲染未接入能力的图标。成员旁的 `+N` 只进入已有群配置流程，关闭详情后的焦点恢复沿用现有生命周期。

列表继续展示会话标题、最近公开消息与真实时间；群聊和单聊通过现有头像/拼图识别。保留手动排序、置顶分组和自动化来源提示，不把图中的“最近”字样误解为改用时间强制重排。

## 4. 消息流

### 4.1 结构与连续发言

员工消息使用左侧头像、右侧姓名/时间和正文。姓名悬停或键盘聚焦时变为主题蓝色并显示 @ 前缀，点击加入成员提及并聚焦输入框；点击头像打开只读员工资料 Popover（姓名、职责、启用状态、绑定技能/知识）。用户消息整组镜像：头像最右，其左侧从右到左为昵称、时间，正文和引用靠右；操作栏同样镜像到卡片左侧。系统消息使用轻量说明，不伪装成员工。

连续发言只做视觉分组，不合并消息实体。建议分组条件全部满足：同一会话、同一发送者类型与 ID、同一轮次、相同自动化来源、都已完成、相邻时间不超过 3 分钟，且中间没有其他人消息、系统事件、审批、引用或状态分隔。关联字段缺失或含义不确定时保留完整头部，不猜测。

同组后续消息可省略重复头像，正文保持缩进。每条消息仍有独立 ID、定位、引用、Trace 与操作入口；键盘聚焦或定位到该消息时提供其作者与时间。流式、失败、中断等消息不因压缩头部而丢失状态。

### 4.2 内容与操作

- 正文复用共享 Markdown/Shiki；每条消息复用全局 `soft-card` 表面、背景、边缘、高光、阴影和圆角，不使用选中态灰色背景，引用摘要、蓝色 @、正文、明确关联的文件和表情回应均在同一卡片内；段落不再嵌套额外卡片。
- 宿主会自动把触发消息写入 `replyToMessageId`。群聊中，员工对本轮用户消息的回应不重复显示这段引用（即使判断也选中了该消息）；通过运行/轮次身份确认，原始数据不变。
- 用户手动引用、员工回复同伴或更早的用户消息仍显示真实作者与摘要；没有可核对的运行/轮次则保留原引用。原消息被清理时显示“原消息已不可用”，不按相似文本或最近消息猜测。
- 工具条包含表情回应、引用、复制与员工 Trace，提及统一使用姓名或 composer 入口。短消息放在卡片旁；卡片实测宽度超过 `min(480px, 可用宽度 × 70%)`，或剩余空间放不下工具条时，放到卡片右上角。用户消息镜像到左侧/左上角。工具条复用与消息相同的全局 `soft-card` 与原版 Button ghost，保留按钮圆角；外层裁切防止悬停底色越过容器圆角。悬停、键盘聚焦或表情浮层打开时显示，不渲染未实现的转发/收藏。
- 表情浮层为默认表情网格和本机最常使用区，子区背景按外层圆角统一裁切；回应表情和成员名垂直居中，可点击撤销，重启后保留。提交时保持按钮焦点和亮度并阻止重复点击，不触发滚动；失败保留错误。采用系统 Emoji 图案，未引入参考图中的专有贴图。回应不新建聊天消息、轮次、工作或模型调用，也不改变最近消息预览。
- 文件显示为紧凑一行：图标、名称、真实大小、打开。只有明确关联到该消息的已发布产物才内嵌；关联不足的文件留在右侧“会话全部产物”。
- 当前只有打开文件能力时，操作文案使用“打开”。不把效果图当作已经具备应用内预览、编辑、下载或上传能力的证明。
- 每条消息最大宽度受阅读列约束；长路径、URL 和异常文本换行，代码与表格局部横滚。

### 4.3 流式、定位与异常

| 状态 | 展示与行为 |
| --- | --- |
| 员工正在生成公开回复 | 有内容即逐步显示；空内容可用小型输入动画；状态紧随这条消息 |
| 普通回复完成 | 不固定显示“成功”标签，不等同业务任务已交付 |
| 失败/中断 | 已有正文保留，下方显示原因摘要和执行过程入口；不自动重试 |
| 取消 | 保留内容并显示“已取消”；UI 不提前宣布执行器已经退出 |
| 用户正在阅读旧消息 | 新消息到达不抢滚动；显示“有新消息 · 返回最新” |
| 用户位于底部 | 保留现有跟随逻辑，多位员工并行流式时不重排消息身份 |
| 跳转指定消息 | 按消息 ID 定位并短暂强调；新消息不覆盖定位；目标失效时明确提示 |

空群聊沿用现有伙伴空态和开始交流提示，不凭空制造任务。判断、记忆维护和 Trace span 等内部事件不批量写入聊天正文。

## 5. 审批

效果图的“生成页面预览”是示例标题；实际 `Approval` 没有可信的业务标题字段时使用“{员工名}申请运行命令”，不能用模型猜测命令用途替代真实内容。

审批块展示申请人、实际命令、工作目录和权限范围说明。命令可折行或局部滚动，但在用户决定前可见；设计图的简略说明不能替代这三项信息。主按钮“允许这次执行”或“允许一次”，次按钮“拒绝”。只授权当前请求，不改变长期权限。

通过 runId 确认关联后，审批可排在对应消息后；缺少可靠关联时放在聊天流末尾的待处理区域，并明确员工和请求身份，不挂到“最近一条”消息。当前未解决的审批须容易找到；在旧消息阅读位置之外时沿用新内容提示，不强抢滚动。

提交期间阻止重复操作，成功以宿主回执为准；失败保留审批与反馈。等待人工决定使用静态“待确认”提示，不使用持续旋转的忙碌动画。审批状态位于审批块内部；不复制效果图中输入框上方额外一行“等待你确认…”状态条。

## 6. 输入区

- 两行起步，多行上限、13px 输入字号、圆角、高光、阴影、发送/停止按钮和外层留白均沿用原有 ChatComposer 与全局样式。使用 Beautiful UI Prompt Bar 的输入交互方式增强 @ /，复用全局皮肤。键盘提示只在候选浮层里显示，不在输入区添加常驻页脚。
- 文案：“发消息给 {群名}，@ 提及 · / 命令”。@ 按钮与输入 @ 共用真实成员候选，支持中文姓名/角色筛选；确认后在正文光标处插入复用系统 Soft 次级按钮皮肤的成员标签并保存稳定 ID；不在 composer 上方单独展示提及栏。标签与文字一起选中/替换，通过 Backspace、Delete 或剪切整体删除，删除同步取消对应点名；多个同成员标签只绑定一次，删掉最后一个才解除。群聊以实际不可拆分的行内节点排版文字和标签，标签前后均有原生光标位置；不使用透明 textarea 或视觉覆盖层，不添加额外占位空格，一次退格即可移除相邻标签。单聊保留原生 textarea，composer 外观仍复用既有皮肤。未确认的字面 @ 不冒充成员绑定。
- / 输入或按钮打开快捷命令：`/summarize`、`/todo` 填入可编辑草稿；`/files`、`/workspace` 分别打开现有任务与产物、会话目录。选择命令本身不发送消息，不执行外部命令。
- 菜单支持方向键、Enter/Tab 选择、Esc/外部点击关闭；中文组合输入期间不选择或发送，空结果时 Enter 不误发。候选替换只作用于光标前的当前触发词，保留前后正文；邮箱、URL 不打开菜单。
- 引用预览为 composer 上方单行条：左侧 X、分隔线、回复作者和省略摘要；点击 X 可取消。成员标签在正文中直接删除，无单独移除按钮。群聊不显示模型、权限或思考强度选择器。
- 保留 Enter 发送、Shift+Enter 换行、中文输入法组合输入不误发。空白消息不能发送。
- 运行中沿用“停止本轮”和“停止并发送”的明确语义；不得用设计图只有一个发送按钮为由删除已有停止能力。
- 切换会话保留草稿、引用与已选成员；开关详情不能重建聊天或清空输入。

## 7. 右侧任务与产物

顶部沿用 Shell 的详情 Tabs，不把效果图中简化的一个标题和关闭按钮实现成平行抽屉。标题下依次呈现工作目标、状态、分工、产物；每段通过间距和分隔线组织，不做多层卡片。

| 区块 | 规则 |
| --- | --- |
| 工作目标 | 显示真实 WorkItem 的 deliverable；多个独立根工作分组列出，不合并为虚构“大任务” |
| 状态 | 读取工作状态、交付结果与证据；已回复、运行 completed、Trace 结束都不自动表示已交付 |
| 分工 | 依据真实父子工作与负责人列行；没有子工作时只展示当前负责人，不按群成员名单编造三行任务 |
| 依赖/待处理 | 保留等待输入、依赖、阻塞、失败、中断与待核对信息；独立共享依赖不得冒充子任务 |
| 产物 | 显示已发布文件；任务明确关联的文件与“会话全部产物”区分；缺失时间不伪造时间 |
| 停止 | 保留停止指定工作及其子工作的既有入口和边界；不扩展为停止全部群成员 |

示例的三位员工分工只用于演示布局；图中研究员/文案“已交付”须由实际结果证据支持。暂无任务或文件时分别显示简洁空态。

各主页面保存自己的详情标签和显隐；从会话切到技能/设置不能展示或操作会话详情。返回恢复已有标签、草稿和滚动；关闭后焦点回到原入口。

## 8. 效果图与实施的明确差异

以下是生成图省略或示意之处，不改变已选定的四栏、统一消息流和协作侧栏方向：

1. 保留完整主导航和详情标签；按用户最新要求移除会话来源下拉，恢复置顶/会话文字 label 分组，普通与自动化聊天共同展示，任务来源仅在预览文字标注。
2. 不新增右上角时钟、未实现的消息搜索、附件上传或第二套成员管理。
3. 审批补齐实际命令与工作目录；等待状态静态呈现在审批内。
4. 没有证据的任务状态、文件归属、大小、时间不按样图填充。
5. 单聊保持气泡、权限/模型和外部任务发送边界，共用 / 命令增强；群聊的卡片和右侧用户镜像不扩散到单聊。
6. 图中连续发言仍重复一次姓名可按第 4 节适度收紧，但保持单条消息可访问、可定位。

键盘顺序按导航、列表、标题、消息操作、输入、详情安排。图标操作有名称，聚焦状态清晰，拒绝/允许不只靠颜色辨认。局部焦点样式复用项目已有方式，不为本页改写全局 focus 规则。
