# 渐隐、输入与引用修正

2026-09-29，根据用户实际使用反馈修正。原有统一左对齐消息流、文件与任务面板保留；当前行为以本记录和已同步的视觉规格为准。

## 复现与原因

先在原有“五名独立成员同时流式回复”场景加入断言，运行未修正应用：从输入框发送“大家好”，五条员工消息全部出现引用框；输入框圆角为 14px，阴影为 none。新增断言按预期失败。

运行时 `service.ts` 创建公开消息时使用 `decision.replyToMessageId ?? event.messageId`。即使测试模型只返回普通 chat 意图、没有指定引用，宿主也会记录触发消息。原前端把这个内部关联一律渲染成引用，所以每个员工都重复引用本轮问候。此前代码已有这条关联；本次改造没有区分其展示含义，还用更明显的引用块放大了问题。

上一轮展示的图 2 来自预置历史：研究员没有触发关联，只有写手带有对研究员的引用，未覆盖实际发送的字段形态。上一轮五人并行测试验证了流式和内容，却没有验证引用展示，因此没有发现问题。

渐隐问题包含布局退化：共享 ScrollFade 类仍在，计算样式的 mask 也仍存在，但群聊把标题改成实体固定区域、去掉原有重叠，并加入多余的 `mask-image:none` 覆盖。仅检查 mask 不是 none 无法证明原有阅读效果保留。

## 当前修正

- 恢复悬浮标题与共享 ScrollFade 的 16px 衔接。群聊标题保留两行、64px 高度；首条正文通过顶部留白保持清晰。删除取消 mask 的群聊规则，没有另写一套渐隐实现。
- 删除群聊对 composer、输入字号、发送按钮、阴影、圆角及外层留白的覆盖，删除新增快捷键页脚。复用原有 ChatComposer、全局 Soft 皮肤和响应式布局，保留独立 @ 入口。
- 群聊展示投影按运行或轮次的稳定触发身份判断：员工回应本轮用户消息时不再重复画引用框，包括流式和历史恢复。即使判断也选择了同一本轮用户消息，展示规则相同。
- 用户手动引用、员工回复其他员工、回复更早的用户消息继续显示；无法核对运行/轮次时保留引用，找不到目标仍提示不可用。禁止按“大家好”等文字特判。连续消息分组使用同一投影。
- 投影不改持久消息、模型输入、触发关系或运行时。已存在的历史记录重新渲染即可生效，无数据库迁移。
