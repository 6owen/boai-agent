## 2. 数据映射与降级

| UI 信息 | 当前来源 | 缺失或歧义时 |
| --- | --- | --- |
| 群名/成员 | `ConversationDetail.conversation`、`Snapshot.agents` | 已移除成员采用已有回退身份；不猜头像/在线状态 |
| 消息作者/时间/正文 | `Message.senderType/senderId/senderName/createdAt/content` | 兼容历史记录；已发布正文之外的私有草稿不显示 |
| 引用 | `replyToMessageId`，结合当前运行/轮次的 `triggerMessageId` | 员工回应本轮用户请求时只省略视觉引用，不修改消息；手动/跨消息引用保留，未知关联保留，找不到目标则明确不可用 |
| 表情回应 | `Message.reactions` 的表情、身份和名称 | 旧记录视为无回应；失败保留错误，不用乐观假成功掩盖 |
| 提及 | `Message.mentionIds` 和当前真实成员 | 不按同名文本猜身份；未选择的字面 @ 保持普通文字 |
| 消息 Trace | `Message.runId/turnId/senderId` 和已有 `onTrace(message)` | 无可用过程则明确无记录，不打开另一个人的最近运行 |
| 审批 | `Snapshot.approvals` 的 `conversationId/runId/command/cwd` | 保留真实命令、目录与请求 ID；无法定位消息时放显式待处理区域 |
| 工作 | `ConversationDetail.workItems` | 为空时显示暂无工作，普通 chat 不创建 WorkItem |
| 分工 | `parentWorkId/rootWorkId/ownerAgentId` | 没有父子关系就不生成分工树；依赖关系不等于归属关系 |
| 已交付 | `WorkItem.status/outcome/resultMessageIds/artifactIds` 与可检查证据 | 状态与证据不一致时显示待核对，不能直接绿色通过 |
| 文件 | `ConversationDetail.artifacts` 的 `id/name/path/size/runId/ownerAgentId/publishedAt` | 可选字段未知时省略；保留会话级文件入口 |

### 消息与产物关联

1. 先使用 `WorkItem.resultMessageIds` 和 `artifactIds` 的明确结果关系；仅含唯一结果消息时可直接将对应产物挂到该消息。
2. 其次，若 `Artifact.runId` 对应唯一、明确的发布结果消息，可据此关联；需要核对 Run 的 `messageId`，不能选择同员工最近一次发言。
3. 多条结果消息共享一组文件、ID 缺失、旧数据或关联冲突时，不在消息内猜测归属；文件仍展示在“会话全部产物”。
4. 同一文件可作为消息入口和右栏入口出现，但都读取同一实体；重复渲染不代表复制或再次发布文件。
5. ACP 的文件列表不是已发布产物；继续走显式 `publishExternalArtifact` 后再显示，界面打开不触发发布。

### 审批与状态关联

审批先按当前会话筛选，再通过 runId 对应 Run 的消息定位。缺少消息映射不妨碍用户处理审批。工作行的“待确认”只有其 `activeRunId` 与实际审批对应时显示，不能因同员工其他任务待批准而变色。

提交后等待现有服务返回再更新；失败保持可见。不为纯样式增加轮询、额外模型调用、自动重试、工具重放或自动接续。现有预算、自动化来源、停止与重启边界完全保留。

## 3. 实施顺序

| 阶段 | 具体交付 | 退出条件 |
| --- | --- | --- |
| A：群聊视觉骨架 | 使用现有 Shell 完成标题、用户右/员工左的镜像卡片、输入区和右侧分区；仅在隔离场景使用样例数据 | 1440×1024 浅色实际截图接近选定图；没有断开的按钮或侵入单聊的样式 |
| B：真实状态接线 | 关联审批、文件、任务与真实状态；必要时加入纯展示分组函数 | 无文件/多任务/未知关联/等待/失败/中断均能真实表达 |
| C：交互与回归 | 键盘、引用、滚动、停止、宽度记忆、详情作用域与草稿 | 适用 BDD 与类型/UI 门禁通过，无新增运行语义 |
| D：交付记录 | 更新 Header、目录地图与实现记录，保留独立实际截图 | 将“设计已选定”与“实现已验收”分开记录，所有限制明确 |

先在群聊落实规则，再决定是否单独推广到单聊；共享布局或原语确需改动时，必须核对使用它们的其他页面。

## 4. 可复用的视觉场景

设计示例日期为 2026-09-29，仅用于固定视觉场景；真实 UI 使用真实时间。

| 顺序 | 示例内容 | 场景中必须表达的事实 |
| --- | --- | --- |
| 14:30 用户 | 帮我准备一份新品发布方案，先整理用户需求，再写首版文案。 | 用户头像/昵称/时间/正文整组右对齐，身份清楚 |
| 14:31 林研究 | 三条需求发现和首屏建议 | 可读长回复、列表与段落，卡片右上工具条，不按段落套卡 |
| 14:33 许文案 | 引用研究结论，附发布文案-v1.md | 引用目标明确，文件是真实发布且可打开的测试文件 |
| 14:34 许文案 | 标题建议：让好想法，更快成为团队成果。 | 相邻发言适度合并头部，消息 ID 和引用仍独立 |
| 14:35 陈设计 | 申请运行本地预览命令 | 命令/目录可读，审批只批准本次；拒绝也可用 |

视觉预览数据不得写入用户真实数据库。Electron 场景使用隔离目录和离线可控协议；审批测试使用安全的测试命令。不得为了复刻三行分工而调用真实付费模型或修改用户现有工作记录。

## 5. 验收清单

以下是完整验收标准，不把勾选清单等同于全套测试结果；实际覆盖与未通过项逐项记录在 [实现与验收记录](./03-实现与验收记录.md)。

### 视觉

- [ ] 1440×1024、100% 缩放，四栏层级和选定图一致；右侧显式打开时正文仍可读。
- [ ] 用户整组镜像右对齐、员工左对齐；短消息旁置工具条、长消息角落工具条；连续发言仍可独立操作。
- [ ] 引用、蓝色 @、正文和回应在同一卡片内；默认/常用表情可选择撤销，重启保留且不调用模型。
- [ ] 长 Markdown、中文/英文混排、代码、表格、长文件名不撑破列宽。
- [ ] 输入区沿用原有 Soft 圆角、阴影、字号与按钮，增强 @ /，没有新增常驻快捷键页脚或状态条。
- [ ] 滚动时共享 ScrollFade 实际生效，标题下保留 16px 渐隐衔接，首条正文清晰。
- [ ] 任务、分工、产物通过留白和轻分隔组织，没有大面积嵌套卡片。
- [ ] 深色主题、125% 缩放和 1124×688 / 760px 窄窗无不可达关键操作；列宽不被自动改写。

### 行为与业务意图

- [ ] 单聊既有气泡、模型/权限菜单及配置锁定不被群聊样式影响。
- [ ] 引用、提及、普通发送与输入法保持原语义；composer 无停止按钮，员工处理中仍可发送消息；草稿可恢复。
- [ ] @ / 支持筛选和键盘选择；保留光标后文本，邮箱/URL 不误开；组合输入与无结果 Enter 不误发，选择命令不自动发送。
- [ ] 多员工并行流式不丢字、不按完成顺序重建消息身份；阅读旧消息时不抢滚动。
- [ ] 从界面实际发送“大家好”，流式中和完成后不重复引用；手动引用发送与重启后仍显示，原始触发关联持久数据不变。
- [ ] 指定消息/自动化结果定位有效，失效消息有提示；后来消息不覆盖焦点目标。
- [ ] 允许/拒绝只处理目标审批；重复点击不重复提交；失败可见，实际执行范围可检查。
- [ ] 已回复/运行成功不等于已交付；未知证据、多根工作、共享依赖与历史数据不产生虚假分工。
- [ ] 文件内嵌关联准确；关联不明仍可在会话产物查看，外部未发布文件不冒充交付。
- [ ] 停止单个工作树不取消无归属的共享依赖，重启不自动重放操作。
- [ ] 详情标签跨主页面隔离；重复打开复用；关闭焦点恢复；草稿/滚动/宽度记忆保持。
- [ ] 图标按钮可键盘操作且有名称，聚焦可见；状态有文字而非仅颜色。

### 合适的验证方式

- 实现后执行 `pnpm typecheck`、`pnpm lint:ui`。
- 若新增消息分组或结果关联纯函数，在 `tests/*.test.ts` 用 Vitest 验证关键不变量：来源/轮次不同不分组、关联不明不猜测、视觉分组不破坏独立消息定位。不要为纯圆角/颜色写镜像单测。
- 桌面交互扩展已有 `tests/e2e/features/` 下适用场景，复用 `steps/` 和 `support/`；不新增平行 `.spec.ts`。重点覆盖 `composer`、`history`、`detail-tabs`、`conversation-list`、`collaboration` 及相关审批/产物场景。
- 按仓库流程运行 `pnpm test:electron`（构建、bddgen、Playwright），不手改 `.features-gen/`，不减少原有断言。
- 将实际实现截图与本目录原图按同视口/同状态比较；实际截图单独保存并建立地图，不能覆盖 `group-chat-v2.png` 或把生成图标为测试证据。
