# 消息交互与输入增强

本轮已完成并通过专项验证。用户自己的消息整组镜像到右侧；员工消息在左侧。每条消息使用一个卡片，引用摘要、蓝色提及、正文、明确关联的文件和表情回应放在其中。

## 消息卡片

- 工具条依据实际宽度计算：超过 `min(480px, 可用宽度 × 70%)` 或剩余空间不足时进入角落；员工短消息右侧旁置、长消息右上角，自己的消息对应镜像到左侧/左上角。窗口变化会重新测量。
- 提供表情回应、引用、提及、复制与员工执行过程入口。没有添加空壳转发/收藏按钮。
- 鼠标悬停、键盘聚焦或表情浮层打开时保持工具条可操作。连续发言仍有独立工具条和消息身份。
- 表情面板包含 54 个系统 Emoji 和本机最常使用区；回应显示表情和“我”，可点击撤销。这里只表示当前用户的实际操作，不伪造员工回应。系统 Emoji 图案与参考图中的专有贴图不同。
- 回应通过 `setMessageReaction` 保存到原消息。校验消息所属会话和表情白名单；先写数据库再更新内存，失败保留可见错误。幂等设置状态，重启保留、清空会话一并清除；不改变最近消息、不创建新轮次/工作、不调用模型。
- composer 上方引用预览为单行灰色条：X、分隔线、回复作者、截断摘要。发送后引用与正文在同一卡片。自己的昵称、时间、工具条和引用按右侧布局排列。
- 继续保留上一轮修正的 ScrollFade、Soft composer 和当前轮次重复引用的展示抑制；后端触发消息关联不删除。

## Prompt Bar 的接入方式

来源：[Beautiful UI Prompt Bar registry](https://www.beautifului.dev/r/prompt-bar.json)。已读取源码，并使用 shadcn 的 dry-run 核对安装影响。原版会新增另一套全局 foundation 样式和 `glimm`，同时包含自动演示、假附件、假模型与模拟听写。

本轮将其输入唤起、筛选、方向键和确认交互适配进 `prompt-bar.tsx`，复用现有 ChatComposer、Base UI Popover、Button 和本地 Carbon/Solar 图标；没有安装演示依赖或改写项目颜色体系。保留现有外观、发送/停止、单聊模型/权限设置和 ACP 外部任务边界。

| 入口 | 实际行为 |
| --- | --- |
| 输入 `@` 或点击 @ | 群聊真实活跃成员候选；按中文姓名/角色筛选，选择后保存成员 ID 并展示可撤销标签 |
| `/summarize` | 填入“请总结当前会话的关键结论、分歧和下一步建议。”，由用户编辑和发送 |
| `/todo` | 填入整理待办/负责人/交付/待确认问题的草稿，由用户编辑和发送 |
| `/files` | 打开当前会话已有任务与产物详情 |
| `/workspace` | 打开当前会话工作目录，不执行 shell 命令 |

- 候选浮层与 composer 同宽，位于上方，沿用浅深色语义皮肤；说明与快捷键仅在浮层显示。
- ↑/↓ 切换，Enter/Tab 确认，Esc 收起；按钮与文本触发共用菜单。确认命令本身不发送。
- 只处理当前光标前的独立 `@词` 或 `/词`，保留前文和光标后的文本；邮箱、URL 不误开。未选中的字面 @ 不假装完成成员绑定。
- 中文输入法组合期间不选择/发送；没有候选时 Enter 保留输入。Shift+Enter 保持换行。
- 已选成员去重并保留稳定身份，切换会话继续复用既有草稿。单聊提供 /；群聊才有 @ 成员选择。
