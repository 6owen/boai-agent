宿主执行确定性的协作准入与调度规则；员工仍独立决定自己的参与。

一旦我所属的文件夹有所变化，请更新我。

| 成员 | 地位 | 功能 |
| --- | --- | --- |
| `task-admission.ts` | 资源准入 | 六项独立任务并行、冲突排队不阻塞其他工作区、相同员工会话文件互斥、宿主命令任务全局互斥 |
| `model-capacity.ts` | 模型准入 | 同连接共享六项 FIFO 容量、可取消限流退避、重试前请求预算预留、阶段耗时 |
| `work-protocol.ts` | 协议校验 | 模型阶段输入仅接受组织真实回执/本 run 成果 ID，已声明等待仅 waiting；权威 schema 不被模型输入代替； bobo 组织判断仅 mode/goal，不接受宿主身份；组织交付引用真实 collaboration 回执，由仓库核验；D5 明确用户问题要求 waiting/实际公开引用，禁止混入依赖等待；宿主/模型共用 schema、交付证据与已声明等待检查；预检修复和事务提交复核共用 |
| `work-collaboration.ts` | bobo 工作事务规则 | 真实核心用户/当前 holder 与冻结原公告来源分别核验；组织与独立群根共预算而无跨会话父子；首次启动显式恢复零重放；原文件安全恢复/真实发布后确认副作用；全部真实协作阶段原账本授权与实际组织交付证据 |
| `work-dependencies.ts` | 依赖规则 | 结果版本校验、环检查、失败阻塞和继承目标工作来源的事务内定向通知 |
| `work-repository.ts` | 工作控制 | D6 settle 原结果/消息事务的可组合完成 hook 与失败回滚；D5 公开 task 问题原结果/版本关系、原 Work/budget 安全补充事务；修订权威请求/本人消息/原版/当前目标与唯一新根预算同事务绑定，拒绝旧 Work/occurrence 串用，重试/唤醒与子工作保留新根身份；工作正文继承材料来源、持有者事务追加与授权投影；预算追加/消息/工作接续同事务和用户/预算停止区分；版本 2 父子工作、原子认领/接续、共享预算/自动化请求预留和结算、结果证据、停止树及中断边界；补充沿用最初触发的工作身份、自动化来源不可改绑、停止后的认领/发布门禁 |
| `work-budget.ts` | 预算规则 | 新完整组织初始48/其他24唯一工厂，原保存值不提升；固定共用额度与耗尽判断；自动化 occurrence/非自动化 collaboration 请求的独立授权；共享原始限额/期限、唯一请求原子预留、幂等原始用量结算与未知调用计数；清理的最小调用去重拒绝重放/迟到结算不复活正文；不执行或重试业务 |
| `work-renewal.ts` | 续行规则 | WorkRepository 事务内追加额度/前后回执、只接续安全未完成工作、保留已交付及独立依赖 |
work-repository.ts 的 browserTransaction 将 prepared/start/terminal、原 holder 及 effect 变化合在同一事务；取消后结果只确认原执行，不改新 holder。
work-repository.ts 的组织发布/恢复沿同一 SQLite 事务比较原 Work 和当前执行权；真实文件恢复不制造模型消息，重启仅中断，不能自动开工。
