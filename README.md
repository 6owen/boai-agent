## 开始使用

环境：Node.js 22.13 或以上、pnpm 10。当前验证平台为 macOS Apple Silicon。

```sh
pnpm install
pnpm dev
```

本机运行时的进程树监督复用 Rovai Rust 模块。macOS/Linux 源码开发与构建需安装支持 edition 2024 的 Rust/Cargo；`pnpm dev`、`pnpm build` 与 Vitest 自动构建 `dist/native/boai-process-guard`。用户安装后的应用使用随包二进制，无需本地 Rust。

开发模式支持界面热更新；修改主进程或运行服务后需要重新启动。生产构建和运行：

```sh
pnpm build
pnpm start
```

1. 在左下角「设置」添加模型连接。支持 OpenAI、Anthropic 和 OpenAI Chat Completions / Responses 兼容服务；兼容服务填写完整 API 基础地址，可不填 Key。也可点击「扫描本地 Agent」，预览 Codex / Claude Code 的 API 配置并逐项导入，或选择其他配置目录（JSON、TOML、YAML、dotenv）。缺少模型名时先补填；已导入来源不会重复创建或覆盖已有编辑。扫描不会联网、改写来源或将密钥带入扫描结果；本机 Codex/Claude 可沿用各自 CLI 登录；员工选择“本机 Agent”并绑定实际程序，旧 ACP 配置只作兼容保留。
2. 在「通讯录 → 加号 → 创建团队」的弹窗填写团队名称和团队需求，点击「生成」进入系统核心助手 bobo 的会话；它根据需求安排成员，并默认创建使用该团队名称的群聊。团队入口不需要模型、模板、群开关或草稿配置。也可手工新建员工，并在「编辑配置」选择模型；员工模型 ID 留空时使用连接默认模型。
3. 通讯录按群聊、联系人展示资料；点击「发消息」进入对应会话，也可在会话页新建群聊。`@` 和引用可明确收件人。API员工沿现有Mastra调度，本机员工直接使用自己的持续原生会话；普通本机聊天可以使用其原生工具，遵循所选权限。
4. 在「技能」管理本地技能、收藏和商城，也可导入技能目录或技能库；到已保存员工的配置中明确绑定本机技能。现有知识绑定及群知识共享保留，导入不代表自动授权。
5. 会话右键可“清空聊天记录”或“删除会话”。确认后永久清理聊天/任务记录、会话记忆与专属文件；删除还会移出列表，员工和群配置保留在通讯录。执行中的会话需先停止并等待结束。

通讯录中，群配置和右键菜单可解散群聊；员工右键可删除，清除全部单聊、员工记忆、专属资料与 workspace。所在群聊只移除该员工并保留记录，空群自动解散。加号菜单中的「通讯录管理」打开紧凑双栏弹窗，标签和实际命令权限筛选默认收起；通过关键词及表格多选，勾选即时添加或移除标签并保留其他标签，只更新通讯录，不刷新其他页面；勾选和取消勾选保存时，筛选、搜索、员工列表、选择操作和所有按钮保持正常外观；标签面板搜索仍可用，标签写入、删除和关闭等操作仍串行锁定。底部较高操作栏通过 Motion 滑入，已选人数仅数字使用主题主色，「取消选择」同用主题色，量词「人」和「已选择」使用普通颜色，点击人数可查看紧凑只读名单，危险删除按钮使用冻结选中身份和版本的确认浮层。原分类及其成员关系保留为标签，一个员工可有多个标签；主列表仅群聊和联系人，排序不受标签影响。点击常规「新建标签」按钮后，在列表内输入名称并通过保存/取消图标新建，支持右键重命名和删除；删除标签保留员工及聊天记录。完全访问当前不可用，外部 Agent 权限由自身管理。员工默认启用，配置不再展示启用开关。关联定时任务会暂停，未完成的关联等待会终结；执行或收尾中的任务须先停止并等待实际退出。
6. 员工详情的「工作区」「记忆」「系统文件」对应真实本地数据。工作规则和表达风格可编辑；记忆按员工及会话分开保存、编辑和删除。
6. 任务文件先写入员工在本会话的独立空间，再通过发布操作进入群共享产物。会话“执行”入口查看员工运行历史、公开说明和真实工具参数/结果/文件差异；群聊可按员工筛选。旧Trace只保留为技术/历史详情。会话菜单的「任务与产物」仅展示工作目标、交付状态及文件。

本机 Agent 接入：在“模型连接”扫描并保存本机 Codex 或 Claude，在员工的执行配置中选择该连接和模型/原生选项，再进入原聊天发送消息即可。Codex 使用 app-server，Claude 使用 stream-json，各自管理原生工具与会话。BOAI 的消息、文件发布和协作能力通过增量产品工具接入；CLI 的登录凭据不复制到员工配置中。旧 ACP 历史不自动转换成新任务。

应用首次启动补齐系统核心助手 bobo 和三个可编辑员工，不配置模型凭据，也不生成示例对话。bobo 默认使用首个具有有效默认模型的已配置 API 连接；已经选择的连接会保留。会话列表标题下的名称搜索输入始终保留，下方以核心助手当前头像和名称显示唯一分组标题，即使没有历史也保留；点击标题整行仅展开/收起，右侧更多菜单进入助手设置，新会话图标打开空白聊天。标题右侧图标随悬停、键盘焦点或菜单打开显示；核心历史行以紧凑小缩进显示为分组子级，分组与历史间距收紧，仅显示标题与随悬停、聚焦或菜单打开显示的更多、编辑图标，不展示头像、预览或时间；悬停或选中背景覆盖整行，标题按钮保持透明。通过行内编辑、右键、更多或核心聊天标题菜单都可打开同一个「编辑标题」弹窗，去除首尾空白后须为 1–200 字，只修改该核心会话标题并同步列表与聊天标题，取消不保存，也不调用模型或修改成员、员工配置、记忆和消息。普通会话继续展示原有头像、预览和置顶。会话加号仅保留新建员工和群聊；发送第一条非空消息后才生成核心会话，反复打开不会增加空记录。bobo 显示名称可修改，身份和长期、经历、临时记忆持续归属同一核心助手。没有有效模型时，实际首发不能受理为新会话或团队。需要你自己的模型服务才能得到实际回复。本地保存数据不代表模型推理离线。

首条消息或团队请求响应失败时，应用先核对原请求；已经受理就打开原会话，确认未受理才允许修改后新建，核对未知会保留原输入和请求身份，关闭弹窗或进入设置不会自动重发。已受理但当前会话尚不可用时会提示重启核对；清空或删除后，原请求身份只保留最小去重标记，不能重新建立同一会话。

`~/.agents/skills` 本机技能和旧受管副本均可按记录的远程来源检查更新；兼容原 skills CLI 的 GitHub 来源记录，缺失原始内容时须确认替换。更新保留技能 ID 和收藏，本机更新不创建员工资源；旧受管副本保留绑定。本地修改须预览差异并明确确认替换，受管副本的活动/等待工作或尚未退出的执行器会阻止替换。“检查全部更新”只读取来源，仍需逐项确认更新。文件交换有持久日志和本地恢复；无法判定的一致性问题会保留文件并暂停使用。界面只展示当次操作进度与结果，不再提供安装记录浏览；后台操作账本和恢复边界保留。便携库可通过技能页的“技能操作 → 导入文件夹、ZIP 或链接”选择旧库 ZIP 或根目录离线恢复；“导出技能库”支持选择技能/收藏、检查同名冲突和排除文件后保存 ZIP，保留来源及收藏分组，不恢复员工绑定。旧包未保存的分组不会编造。K1–K4 主闭环与 22 项验收已完成，具体证据见 Skills 实施记录。

Skill 目录必须包含 `SKILL.md`，其 YAML frontmatter 需要有效的 `name`，缺少 `description` 时会提示。导入时复制到应用受管目录；不会直接执行原目录中的内容。可导入 [示例技能](examples/skills/brief-writer/SKILL.md) 所在的 `brief-writer` 目录，以及 [示例资料](examples/knowledge/product-notes.md)。

文件工具的 `self:/` 只对应当前员工在当前会话的空间，`shared:/` 对应会话共享区；系统文件和其他员工目录不可通过普通文件工具读写，技能与知识原件只读。命令执行默认关闭；开启后，每次执行仍需确认完整命令。命令使用当前用户的主机权限，**没有操作系统沙箱**；工作目录、超时和文件工具的路径限制不约束获得批准后的任意 shell 命令。脚本依赖需要在本机准备，当前不提供自动安装依赖。

## 数据与备份

macOS 新版数据位于 `~/Library/Application Support/BoAI Agent/v2/`，可在设置中打开；开发/测试的 `BOAI_DATA_DIR` 指定父目录，新版同样使用其 `v2/` 子目录。首次启动从 v0.1 复制一致副本，校验后启用；原数据保留。旧版后续写入会形成另一份数据，不会自动覆盖或合并到新版。

```text
v2/
  data-version.json                  新版数据版本标记
  boai.sqlite                        配置、消息、轮次、记忆、运行快照及本地 Trace
  credentials.enc.json               主进程加密凭据，不进入普通备份
  agents/<id>/workspace/
    AGENTS.md / SOUL.md               工作规则、表达风格源文件
    IDENTITY.md / USER.md / MEMORY.md 身份和记忆生成视图
    skills/                          已登记的员工专属技能
    sessions/<conversation>/         会话记忆投影、work/ 和 runs/
  workspaces/<conversation>/         共享文件和已发布产物
  materials/<conversation>/<id>/     宿主私有聊天附件原件，按当前聊天接收范围
  skills/<id>/<name>/                 公共技能原件
  knowledge/<id>/<filename>          受管知识资料
```

正在执行或等待审批时不能导出备份，请先完成或停止任务。备份包含数据库、员工系统文件与独立空间、记忆、Skills、知识原件和共享工作区，**不包含 API Key**。恢复方法见备份中的 `RESTORE.txt`：退出应用，保留原数据副本，将备份内容放入目标应用的 `v2/` 数据目录，再启动并重新配置 Key。启动时会重定位受管文件路径。

退出应用会停止执行；重新启动后，未完成任务标记为中断，不自动重放命令。macOS 关闭窗口会保留应用进程，使用「退出」或 Command-Q 才会停止应用。

## 验证与打包

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:electron
pnpm package
```

`pnpm package` 在 `release/` 生成当前平台的应用目录；`pnpm dist:mac` 生成 macOS DMG。打包使用本项目安装的 Electron。正式分发还需要应用图标、签名、公证及目标系统验收。

引擎测试使用真实 Mastra SDK 和本地模型协议服务，覆盖 OpenAI 兼容与 Anthropic 请求、流式输出、技能、知识、产物、命令审批和取消；服务测试使用实际 SQLite。桌面测试启动真实 Electron，验证跨进程调用、群聊、隔离、取消和重启。测试服务只用于自动化测试，应用没有模拟回复模式。

桌面验收使用 `playwright-bdd`：`tests/e2e/features` 保存中文业务场景，`steps` 保存类型化操作与断言，`support` 管理独立数据、Electron 重启和资源清理。原有 13 组桌面流程全部由 BDD 执行，另有五人并行流式、慢判断隔离、委派/定向接续和停止工作树等场景；`tests/*.test.ts` 继续由 Vitest 执行。生成的 `.features-gen` 不提交、不手工编辑。Playwright 报告位于 `playwright-report/index.html`，按业务步骤展示的 Cucumber 报告位于 `cucumber-report/index.html`；二者分目录，避免报告器清理目录时互相覆盖。真实供应商评估单独使用 `pnpm eval:collaboration`，不在默认测试中调用付费模型；场景、预算和门槛见[评估协议](ai-docs/spec/6.Cumora协作重构/06-真实模型评估协议.md)。

评估体系现有38题（10回归、12业务开发、16冻结留出），32项覆盖映射。`pnpm eval:dataset`检查清单与冻结合同，`pnpm eval:score --input 原始目录 --output 新目录`离线生成HTML/JSON报告；不重复调用模型。真实评估支持途中事件、完整产物hash、单人对照和跨批次共享预算；运行结束、任务通过与待评审分别显示。人工校准和正式留出实验尚未完成，见[测试体系实施状态](ai-docs/spec/6.Cumora协作重构/09-多Agent测试体系与评估集方案.md)。`.github/workflows/tests.yml`提供离线类型、UI规则、模块、冻结合同与Electron BDD工作流，真实模型仍手动执行。

协作重构当前能力：连接共享模型容量，同轮事件合并保留来源；任务已有版本化工作记录、事务认领和跨运行预算。业务结果通过独立声明和证据记录，运行成功不自动等于工作完成。员工可同时判断、流式回复与整理各自记忆；普通同伴消息不作废对原始请求的独立聊天意图。默认同连接六项模型调用、六项独立工作区任务并行；任务结果先保存为草稿，过期时仅重新汇报，命令任务和相同员工会话文件保持互斥。新增父子工作、显式结果版本依赖和负责人定向接续；子工作共享原始预算，依赖失败阻塞，支持单独停止工作树。重启中断且不重放；此前固定验收版本的真实模型样本为 44/45，达到预登记门槛，仍存在内容质量限制且整体 token 开销增加；详见[实施记录](ai-docs/spec/2.已实现功能与代码现状/20-Electron-BDD与协作重构.md)。
