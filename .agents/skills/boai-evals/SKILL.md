# BOAI业务评估

你是优化者，BOAI是被测应用，独立评分器负责判断。先读[第15组11](../../../ai-docs/spec/15.Agent评估与持续优化/11-业务评估与Codex优化主线.md)和07最新进度。用户既有授权、模型选择及预算继续有效。

## 建立eval

- 从用户关心的完整任务和已有真实失败出发。优先真实记录/问题，再用明确来源的合成任务补成功、困难和不应触发的情况。核对题目可解、标准均在任务中说明，不只选择当前模型失败的题。
- 复用`tests/evaluation/cases.ts`、真实AppService/Mastra runner及所属功能BDD。新增业务需要扩展对应执行协议；不能用单元测试或固定模型回执代替真实任务。
- 将任务按业务簇分为开发和独立验证，登记目标、可修改文件、模型、重复数、请求预算和停止条件。已有仓库题已可能被看过，只能称独立验证；最终未见题需要另外隔离。
- 用`pnpm eval:build --config PLAN.json --root NEW_DIRECTORY`生成输入/规则/语义标准审阅页。让用户审阅实际样例，已有对具体样例的反馈可复用，不重复请求形式许可。
- 确定性事实由代码检查；内容质量使用独立模型或真实人工。独立judge连续两次评价同一输出，保留差异；模型评审只有通过原校准合同才能参与自动选优。不得代写人类标签或删除语义条款来解除pending。

## 优化

- 使用`pnpm eval:hillclimb --root EXPERIMENT --source .`。它复用业务runner、共享BOAI/judge预算与Codex精确补丁适配；只给优化器开发轨迹，候选在隔离目录运行。
- 先真实基线。pending、样本不足、运行/评分错误、收益小于噪声或任务已饱和时读取报告并处理原因，不扩大原额度或反复重试取最好结果。只有用户另定成本目标后才能改变优化目标。
- 需要独立评审时准备实际原件和理由供审阅。用`eval:experiment review`追加真实标签/校准，再继续同一实验；它不会重跑已经完成的业务。评分不一致需独立纠正评分合同并新建实验。
- 每轮一个因果假设。修复通用机制，不将具体失败题、答案、专名或数值写入生产提示词。开发涨分、验证不涨分或退化时拒绝候选；连续无收益到限停止并分类剩余失败。
- 单元测试与类型检查用于工程回归，不能作为业务选优分数。审阅并在原授权内应用最终补丁，随后完成所属功能的真实API或`pnpm dev`验收。

报告同时给出输入/成果/轨迹、开发与验证分数、样本量/波动/区间限制、BOAI和judge成本及单列Codex用量。保留失败和未执行项；没有真实收益就报告没有收益。程序化置信区间依赖独立采样假设，自适应选优和反复访问验证集不等于最终未见泛化认证。
