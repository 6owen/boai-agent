# BOAI 开发、UI 基准与自动合并

## 默认只做三件事

用户于 2026-10-27 明确：依赖复用缓存；UI 改动审阅并更新受影响基准；没有 UI 改动直接自动合并。每次提交或交付 PR 前重新读取本文件，不沿用旧 Session 缓存的 Draft 例外。以下默认适用于日常开发交付和 `git cp`；用户明确要求仅分析、仅本地、保留草稿或不合并时，以该要求为准。

1. 依赖不变：CI 恢复精确安装缓存并跳过 `pnpm install`。依赖清单、锁文件、配置、补丁或运行环境变化时正常安装。完整缓存由独立任务预热，普通 UI 不等待压缩上传。以真实日志报告耗时，不把“设置了缓存”写成“已经明显提速”。
2. 有 UI 改动：开发 Agent 根据真实差异判断影响，检查场景覆盖，采集官方候选，查看旧图、新图和 diff，只更新需求范围内受影响的基准；完成后将 PR 转 Ready 并设置自动合并。
3. 没有 UI 改动：说明判断依据，直接将 PR 转 Ready 并设置自动合并，不询问是否合并，不额外采集或更新基准。

“自动合并”是交给 GitHub 在必需检查满足后合并，不是跳过检查或强制合并。设置成功并读回回执后结束；只有用户明确要求跟进失败或等到检查通过时，才持续等待。不要为了报告结果重复运行同一套 CI、增加预热实验或另开监控 Agent。

## 开始与提交

- 读取 AGENTS.md、相关规格和目录地图，核对分支、工作区改动、远端和当前 PR。用最新 main 的独立 worktree/功能分支；已有对应分支可继续。保留其他任务的未提交文件和运行进程。
- 只修改当前任务所需内容，按仓库要求同步 Header、`.folder.md` 和相关规格。自查完成后集中提交、推送，只暂存本次文件，不把功能文件复制回 main。
- 云端只执行版本化 UI 合同及 Required checks。本地 Vitest、完整 BDD、T1/T3 和评估入口完整保留，不因云端范围缩减删除测试。不要自行启动本机自动 CI、产品构建或 GUI 测试；轻量差异/配置校验可在本地完成。
- 日常 `git cp` 不再自动解释成“仅 Draft 快照”。只有用户明确说保留草稿、暂不合并或只保存快照时，才停在该阶段。

## 判断 UI 影响

- 检查本次完整 diff 与用户要求。页面结构、样式、图标、文本、主题、控件状态、导航及影响这些内容的数据变化都算 UI 影响，不能只靠文件扩展名判断。
- 交付时用一句话说明：已有场景受影响、新页面尚未覆盖，或没有可见 UI 变化。必要时列出对应 case。修改了 renderer 文件但没有视觉变化，不必硬改基准；新增页面也不能用其他页面的绿灯代替验收。
- 新页面补必要的行为、布局和视觉覆盖；不要扩展成无关功能整治或全产品验收。真实麦克风、模型效果和未覆盖状态须如实区分。

## UI 改动的唯一流程

功能改动 → 同 SHA 官方候选 → 审阅差异 → 受影响的基准随 PR 提交 → 设置自动合并 → GitHub 必需检查通过后合并。

1. 完成实现、自查和集中推送。对当前干净 SHA 触发已有 `ui-baseline-candidate.yml`，复用版本化合同及既有工具，不另造截图通道。
2. 用 `scripts/ui-ci-baseline.mjs import` 导入官方原件，查看 `ui-review` 中的旧图、新图、diff，并核对实际行为、布局和需求。候选采集成功不等于普通 CI 比较通过。
3. 意外变化或实现问题先修代码。有意变化经实际审阅后，沿 `ui-ci-baseline.mjs accept` 明确 run、candidate、case 和 reason，只提交受影响 PNG 与 manifest；没有像素变化则无需改基准。新增场景的新图也必须审阅。
4. 保持零重试、原断言、阈值、mask、来源/hash 和独立核验协议；不得批量接受无关变化、手工覆盖原件、放宽门槛或 force 合并。普通 CI 始终只读比较。
5. 基准提交 push 后设置自动合并并结束，不再次派发候选，不等待普通 CI。明确要求修到通过时，才依据当前失败修复并继续。

当前合同为 24 场（原 20 场及定时任务历史/管理明暗 4 场），两台 macOS runner 并行执行。Required checks 复核当前 SHA、全部场景及原件；缺片、失败、取消、旧提交或缺失材料不能通过。详细协议见 [UI回归基准与PR门禁](../../../ai-docs/spec/22.开发自动化与持续测试/06-UI回归基准与PR门禁.md)。

## 自动合并与交付

1. 核对目标是 `6owen/boai-agent` 的 main、PR head 与本次提交一致，UI 审阅及必要基准已经完成。需要时将 Draft 转 Ready。
2. 执行 `gh pr merge <PR> --repo 6owen/boai-agent --auto --merge --match-head-commit <当前SHA>`，然后读取一次 `state`、`headRefOid`、`autoMergeRequest`、`mergedAt`、`mergeCommit`。
3. 服务端确认自动合并已启用就报告 PR/SHA 并结束；已经合并则报告真实结果。没有确认时说明实际阻塞，不假称已设置，不自动变成轮询、后台监控或强制合并。
4. 不使用 `--admin`、force push 或调整分支保护绕过检查。CI 失败由 GitHub 保持阻断，用户要求跟进时再接续。
5. main 只同步实际已合并的提交；需要同步时确认 main 工作区干净后使用 `git pull --ff-only`。自动合并尚未发生时不提前同步，也不为同步而持续等待。

规则和 CI 改动 push 后用于对应 PR 的新运行，合入 main 后供后续分支同步采用。旧 run 的 Re-run 使用旧版本，不能证明新改动生效。Tag、Release、安装包发布和升级不包含在日常自动合并中。
